# Cisco Quantum Summit 2025 - IonQ

Published: 2025-10-19T23:44:27.706000+09:00

Original Naver post: https://blog.naver.com/4-fire/224046789869

---

아래는 2025년 9월 30일과 10월 1일 2일간 개최된 Cisco Quantum Submit 2025에서 IonQ의 Distributed Quantum Computing & Networking 팀에서 Chief Engineer로 근무중인 **Arun Jagannathan**의 발표 내용을 정리해봤다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTk0/MDAxNzYwODU0MzI4NDcx.x651ZfdHKioWHhhNkGTjVXUZYVaQzpT8zf9sZM9cCoQg.5MpLrKOvoIm_S-t-zPYBvbuR_T2vekxBxpuG8m5GaSQg.PNG/image.png?type=w1)](#)

- - 짧은 거리에서는 트랜스듀서 없이 같은 파장으로 직접 연결
  - 긴 거리에서는 트랜스듀서를 통해 파장을 텔레콤 밴드(1550 nm)로 변환하여 상용 광통신망으로 연결

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTA1/MDAxNzYwODU0MzkyNDUz.aaBzRD9NmbO3bOAv1xraWAiO0SaBwb4np62uFsEK47Mg.pYXBdyj5oGUmXVMWIec8k5alxIDF7hJQEvvkinNiujUg.PNG/image.png?type=w1)](#)

- - QPU 1과 QPU 2에서 각각 광자를 생성해 Bell 상태 분석기로 보낸다.
  - **Bell State Analyzer**를 통해 얽힘을 확인하고, 이로써 두 시스템 간 원격 양자 연결이 성립된다.
  - 검출기가 Bell 쌍을 확인하면 두 시스템 간에 얽힘이 성립되고, 이후 DQC 알고리즘을 실행할 수 있다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMzUg/MDAxNzYwODU0NjY1NzI3.WIqQZwoGBF8iaRmZLHzIDYy8Msr56JiJOaiVQfqfRIUg.rmZvyQqoos-N6T7_WDNytfP2W0ffb_2trF_L_JLgmvcg.PNG/image.png?type=w1)](#)

- - 두 QPU에서 나온 광자를 50:50 빔 스플리터에 결합시켜 경로 정보를 소거하면, 동시 검출로 두 이온이 얽히게 된다.
  - Ba 이온의 경우, 650nm 레이저로 D3/2 상태를 P1/2로 여기시켜 광자를 방출시킨다.
  - 초당 약 1MHz 속도로 반복할 수 있지만, 모든 시도가 얽힘을 만들지는 못한다
  - 자세한 내용은 지난 포스팅 참조

- - 얽힘 생성 확률이 낮기 때문에 **반복 시도 프로토콜**이 필요하다.
  - 시도할 때마다 이온이 가열되므로 냉각 주기가 필수적이다.
  - 바륨 이테르븀, 스트론튬 등 이온 종마다 이 횟수가 다르다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTUw/MDAxNzYwODU0NzkyMDg5.fmVhJLZVHXoshnqOOFXSlUUZ3rPPSYe9Cr-f3-9kZi8g.bZ3DmIfKOBL25UQmKCzE7jJKoo9w1mFjkEns97GTlp0g.PNG/image.png?type=w1)](#)

- - **도플러 쿨링 + EIT(Electromagnetically Induced Transparency) 쿨링**을 반복해 온도를 낮춤

    - 도플러 쿨링과 EIT 쿨링으로 잔열을 제거한 후 사이드밴드 쿨링으로 최종 기저상태로 만듦.
  - 이 과정을 여러 노드(QPU)가 동시에 동기화해야 하므로 고속 제어 스택이 필요함.
  - 냉각은 간단해 보이지만 분산 환경에서는 가장 어려운 동기화 문제 중 하나임

    - 한 노드가 냉각 중일 때 다른 노드가 얽힘을 시도하면 타이밍이 틀어진다.
    - 동시에 얽힘 시도 → 실패 → 냉각 → 재시도” 를 끊임없이 반복
    - 얽힘 시도는 광자 방출 타이밍 수 나노초 단위로 정밀해야 하고,
    - 냉각 루프는 마이크로초 단위로 스케줄링 되어야 하며,
    - 두 QPU가 다른 물리 위치에 있을 때도 **완벽히 동시에** 동작해야 한다
  - OS 없이 구동되는 **bare-metal RPU(Real-time Processing Unit)** 스택을 사용한다.

    - 낮은 레이턴시로 완전 동기화된 제어가 핵심
    - → 양자 시스템을 제어하는 **클래식 컨트롤러(일종의 FPGA 또는 DSP)**사용

      - 레이저 펄스 타이밍, 셔틀링 전압, 냉각 루프, 포토디텍터 트리거 등을 **하드웨어 레벨에서 동기화**함.
      - 실시간 제어 성능이 CPU + OS 환경보다 훨씬 빠름.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTI0/MDAxNzYwODU2NDI3OTIw.z7TBNMvBcaQr73hOWPllngGQOgiHk34BtLtVYeGqwi0g.6LCfTetgSKMFeFdZRQ_AvqdC-dvTFnwHvFOqCdlsHrQg.PNG/image.png?type=w1)](#)

- - **Load / Compute / Interconnect 세 구역 분리 트랩 구조**

    - **열(heating)분리**

      - 얽힘을 시도하는 **Interconnect zone**에서는 레이저 펄스와 광자 방출이 반복되기 때문에 이온이 쉽게 가열됨.
      - 반면 **Compute zone**에서는 정밀한 논리 게이트를 실행해야 하므로 가능한 한 ‘냉각된 상태’를 유지해야 함.
      - 두 영역을 분리하면, **광자 생성으로 생긴 열이 연산 이온까지 전달되지 않음.**
    - **공진 레이저(resonant beams) 영향 차단**

      - Interconnect 구역은 특정 파장의 **공진 레이저**를 사용해 광자를 생성.
      - 이 빔이 Compute 구역까지 새면, 연산 큐빗의 상태를 교란하거나 decoherence를 유발함.
      - 공간 분리 덕분에 이런 간섭이 차단됨.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMjcy/MDAxNzYwODU2NDQ3Nzc5.V9aM5hio-qXTHx988pOTw2xw_yjiN3Iy2lNuXl-V1Ggg.zRVKsBfyKtcCRYxkqVAUyoZpRhMQlXcnHevaN5V5Qasg.PNG/image.png?type=w1)](#)

- - **Load / Compute / Interconnect 세 구역 분리 트랩 구조**

    - Load: 이온 로딩
    - Compute: 논리 연산
    - Interconnect: 얽힘 전송 및 광자 생성

      - Interconnect 구역의 이온은 네트워크 큐빗이며 광자를 생성
      - 이 이온들은 셔틀링으로 Compute 영역과 오가며 위상 정보를 유지
      - 이때 위상 안정성을 모니터링

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfNjQg/MDAxNzYwODU2NTE1ODc5.FZzFsvqdZQQlhE6q20Z93n0ZV6cEMilVvF5ymXMj2acg.46Cw8uAnwDRXzUQv4jyLPHTkrM4nZ3fG8WDwgEnlTzog.PNG/image.png?type=w1)](#)

- - 각 이온의 역할 구분:

    - **Data Ion**: 실제 연산 수행
    - **Coolant Ion**: Sympathetic 냉각

      - 연산 이온은 양자 게이트나 얽힘 조작을 위한 상태에 있을때, 이온을 직접 냉각하려고 레이져를 쏘면 연상 상태가 깨질 수 있다.
      - 이온 체인의 모든 이온은 전기장 속에서 **공동 진동 모드(collective vibrational modes)** 를 공유한다.
      - 따라서 **한 이온의 운동 에너지를 줄이면, 연결된 다른 이온들의 에너지도 같이 낮아지는 효과**가 있다.
      - 이 원리를 이용한 냉각 방식이 바로 sympathetic Cooling임.

        - 냉각은 다른 종 또는 다른 동위원소로 이루어진 ‘냉각 전용 이온’이 대신 수행
        - 연산 이온을 직접 건드리지 않고 냉각할 수 있기 때문에, **게이트 충실도와 coherence time을 유지하면서 열 에너지를 지속적으로 제거**할 수 있음.
    - **Interconnect Ion**: 얽힘 생성용

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTkw/MDAxNzYwODU2NTUwMjgw.33d3u8gAA8RFebfkWJUT-lo51A1VZWu5LBgKv2IEWkgg.HQNeWg5qinmnfEkxBd5p71XCwhFrAish8sA4vwiDGpMg.PNG/image.png?type=w1)](#)

- - **Interconnect Zone에서 광자 방출 시도**

    - 각 Interconnect Ion을 짧은 레이저 펄스로 여기시켜 광자 생성.
    - 약 1 MHz 시도율, 성공 확률은 낮지만 반복 시도 가능.
  - **Bell-state 검출 성공 시 얽힘 확정**

    - 두 QPU의 Interconnect Ion이 원격 얽힘 상태로 연결됨.
  - **Swap to Memory Ion**

    - 광자를 생성하는 네트워크 큐빗은 연산에는 적합하지 않음
    - 따라서 광자를 만든 뒤에는 얽힘을 더 긴 수명의 **Memory 큐빗으로 SWAP**해야 함.

      - Interconnect Ion은 S ↔ P 로 빠르게 전이가 되지만 수명이 짧다. (μs~ms)
      - Memory Ion은 **metastable state** 기반 (S ↔ D)이어서 느리지만 코히스 수명이 초~분 단위로 길다.
    - 이 방식은 Oxford Ionics의 실험(칼슘·스트론튬 병용)과도 유사
  - **Compute Zone으로 이동 / 셔틀링 또는 논리적 전송**

    - Memory Ion의 상태를 연산용 Data Ion으로 전이하여 분산 양자 알고리즘(DQC, BQC 등)을 실행 가능.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMjY4/MDAxNzYwODU2NjkyMTIz.Znccs5ls_-BSI3DWI_IcCRi7GrJ-VJW_yOmcau0M14sg.-GismgLgogfIpXXWPqV3nQxU4LI7vF7o_IkB7wLYBasg.PNG/image.png?type=w1)](#)

**💡****상단: 원격 얽힘(Entanglement Generation)**

1. 1. **QPU-1** 과 **QPU-2** 각각의 **Interconnect Qubit (하늘색)** 이 광자를 방출.
   2. 두 광자가 **Photon State Detection 블록** (중앙 Bell-state analyzer) 에서 간섭 → **얽힘 성공 (heralded event)**.
   - 여기서 검출 신호가 나오면 “두 Interconnect Qubit이 얽힘 상태가 되었다”는 의미.

**💡****하단: 얽힘 전이(Entanglement Transfer)**

1. 1. 얽힘된 두 **Interconnect Qubit (하늘색)** 은 수명이 짧기 때문에, 곧바로 **Memory Qubit (보라색)** 으로 상태를 옮김.

      - 이때 사용하는 게 바로 **SWAP 게이트**.
   2. SWAP 게이트는 두 QPU에서 동시에 실행되어, 원격 얽힘이 **Memory Qubit 쌍** 사이로 이전됨.

**⚙️결과**

- - 두 QPU는 **Memory-Memory 얽힘 상태**를 갖게 되고, 이는 분산 양자 알고리즘(DQC, BQC 등)의 기반 자원이 됨.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMjA3/MDAxNzYwODU2NzkxMzA2.qBLEnSIe5uZXW43IcvZhfCXwal5H9sYnhcyyigzSmPsg.O2mmKEKcU4jgb6wW-WH1R1BVcxgUndUDkGB3TRA0f-0g.PNG/image.png?type=w1)](#)

**💡****상단: Coherent shuttling merges memory qubit with computation qubits**

- - 코히런트 셔틀링(coherent shuttling)이 메모리 큐빗을 연산 큐빗들과 병합한다.

    - 얽힘 상태가 저장된 **Memory Qubit** 을 Compute Zone(연산 영역)으로 이동(shuttling)시킨다.
    - “Coherent”라는 표현은 이동 중에도 **위상 정보(phase coherence)** 가 유지된다는 뜻
    - → 즉, 얽힘이 깨지지 않고 그대로 유지된 채로 옮겨진다는 의미.
    - 이렇게 Memory Qubit이 연산 영역으로 들어오면, **기존의 Computation Qubit(파란색)** 과 동일한 게이트 연산을 수행할 수 있게 된다.
  - IonQ가 **전기장 제어만으로 이온을 미세하게 이동(shuttle)** 시키면서도 얽힘 상태의 위상이 손상되지 않게 한다는 것임.
  - 이는 기술적으로 매우 어려운 부분으로, IonQ의 trap 안정성과 실시간 제어의 정밀도를 보여주는 부분임.

**💡****하단: Memory qubit and entanglement can now be used in arbitrary quantum sub-circuit**

- - 이제 메모리 큐빗과 얽힘 상태를 임의의 양자 서브서킷에서 사용할 수 있다.

    - 이동된 Memory Qubit은 이제 다른 연산 큐빗들과 동일하게 사용 가능.
    - 얽힘이 포함된 상태를 이용해 **원격 얽힘 기반의 연산(sub-circuit)**, 즉 분산 양자 알고리즘을 실행할 수 있다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMTQ1/MDAxNzYwODU2OTIwNDg3.mkmVDWbshgV4sD0qaP0rEk0Rv5uxV0h6Bj6sNHVHFXgg.yeVZTk1SzPutGHxcRHwZiezcMXHa3XDpQHsHvuWkU-Ig.PNG/image.png?type=w1)](#)

- - IonQ는 “단순 연결이 아니라, 네트워크와 컴퓨트를 통합한 스택”을 목표로 한다.
  - 단일 트랩 안에서 두 스택을 모두 실행할 수 있어야 한다.
  - Distributed Quantum Computing (DQC) 실현

> 실험 이미지 (플루오레선스 카메라로 촬영된 Ba⁺ 이온 체인)

- - **왼쪽의 두 개 밝은 점:** → *Network Stack (인터커넥트 구역)*
  - **오른쪽의 여러 개 밝은 점:** → *Compute Stack (연산 구역)*
  - 두 영역은 같은 트랩 내 전기장 안에서 독립 제어되며, 얽힘 생성 및 연산 명령이 동시에 수행된다.

- - BQC에서는 사용자가 **암호화된 양자 상태**를 서버로 전송한다.
  - 서버는 그 내용을 알지 못한 채 계산만 한다.
  - 클라이언트는 작은 QPU, 서버는 대형 QPU 역할을 한다.
  - 서버는 회로의 목적을 모른 채 연산을 수행하고, 결과를 고전적 채널로 돌려준다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfMjYz/MDAxNzYwODU4NzgxMDg5.NOU49XES8EvjcZtDUVZoRISC0-AJTNe1SvcGn0UZILIg.b14f_XN-RNIajk-kTWMluQHVsF0is-GrAcMXtsFb24Yg.PNG/image.png?type=w1)](#)

- - 시나리오 : Alice(클라이언트)는 Bob(서버)에게 자신의 비밀 상태 ρAlice와 Bob의 상태 ρBob을 비교하는 ‘Comparator’를 수행하도록 요청한다.

    - 1️⃣ **Alice와 Bob은 각각 자신의 양자 상태를 준비한다.**

      - Alice → ρAlice
      - Bob → ρBob
    - 2️⃣ **Alice는 자신의 상태를 암호화(encrypt)** 후 Bob에게 전송한다.

[![](https://blogfiles.pstatic.net/MjAyNTEwMTlfNjUg/MDAxNzYwODU4Nzk0NzE5.pOAOrKBGDOd9L_1ZInseidVzeKYnWhckSxJP-e-pBtQg.HLz3swkpnKzRo_nzww93hbKynSHMoIz87OHC7anHKF4g.PNG/image.png?type=w1)](#)

- - Alice의 데이터 프라이버시는 **단일 샷(single-shot)** 수준에서 보장된다.

    - 3️⃣ **Bob은 Blindly**, 즉 상태 내용을 모른 채 Comparator 게이트 U₍cₒₘₚ₎ 을 실행한다.
    - 4️⃣ **Bob은 측정값(Measurement Results)을 Alice에게 보낸다.**
    - 5️⃣ **Alice는 결과를 복호화(Decrypt)** 하여 두 상태의 내적(Inner Product)을 계산한다.

| **단계** | **주체** | **설명** |
| **① Remote Bell Pair Generation** | Client & Server | 클라이언트(Alice)와 서버(Bob)가 원격 얽힘(Bell pair)을 생성. 두 QPU 간 얽힘 채널 확보. |
| **② Individual State Preparation** | Client & Server | 각자 자신의 양자 상태 준비 (ρₐₗᵢcₑ, ρ\_bₒb). |
| **③ Scramble / Encrypt** | Client | Alice가 자신의 상태를 임의의 회전(Rₓ, R\_z 등)으로 암호화 → Bob이 상태를 알아볼 수 없게 만듦. |
| **④ Teleportation** | Client & Server | 얽힘을 이용해 Alice의 상태를 Bob에게 텔레포트. Bob은 실제 상태 내용을 모른 채 수신. |

**💡****BQC Comparator Circuit 실제 타임라인형 회로 다이어그램**

- - Alice와 Bob은 원격 Bell 쌍을 생성하고 각자의 상태를 준비한 뒤, Alice는 상태를 암호화하여 얽힘을 통해 Bob에게 텔레포트한다.
  - Bob은 그 상태를 자신의 데이터와 비교하는 로컬 회로를 실행하지만, 입력의 실질적인 내용을 전혀 알 수 없으며, 측정 결과만이 Alice에게 전달되어 복호화된다.
  - 즉, 이 회로는 **양자 프라이버시를 유지한 채 분산 연산을 수행하는 완전한 BQC 구현도**이다.

- - 얽힘 상태의 중첩(Overlap Function)으로 정확성과 프라이버시를 검증.
  - **결과:**

    - 파란선(복호화 후): 이론값과 일치 → **정확성 확보**
    - 빨간선(복호화 전): 무작위 → **프라이버시 보장**
  - Bob이 악의적으로 Alice의 상태를 추측해도 완전히 실패한다.
  - 심지어 노이즈를 높여도 결과는 변하지 않는다.
  - 즉, 실제 시스템 수준에서도 Blind Quantum Computing이 가능하다는 의미다.

****

**💡** **Photonic Interconnect 4단계별 현황 (IonQ 기준, 2025 Oct)**

- - 현재 IonQ는

    - **이온 ↔ 광자 얽힘 (1단계)**
    - **광자 매개 이온–이온 얽힘 (2단계)** 까지 **실험적으로 완전 성공**,
    - **얽힘 스왑 (3단계)** 은 **단일 QPU 내 프로토타입**까지만 구현,
    - **Cross-QPU 연산 (4단계)** 은 **아직 시뮬레이션 단계**임

**💡****3단계를 완성하기 위한 기술적 걸림돌**

- - **1️⃣ 얽힘 보존 시간 (Coherence Mismatch)**

    - **인터커넥트 큐비트**(보통 6S1/2–6P1/2 전이로 광자 방출):

      - 빠른 광자 생성이 가능하지만,
      - 얽힘 후 **코히런스 타임이 수 ms 수준**에 불과함.
    - 반면 **연산용 큐비트**(예: 5D5/2 or 5D3/2):

      - 초장시간 안정 (수 초 단위 유지 가능).
    - 문제는 얽힘이 “인터커넥트 큐비트”에서 생성된 직후 빠르게 붕괴하기 때문에, **SWAP 게이트를 얽힘 유지 시간 이내에 수행해야 함.**
    - μs 단위 제어 정확도를 요구하는데, 현재의 광자 검출-피드백-게이트 구동까지 걸리는 시간은 아직 수 ms 수준.
  - **2️⃣ Zone 간 전위 불균형과 모션 모드 재정렬**

    - IonQ QPU는 하나의 Ba⁺ 체인 안에 **Compute Zone** (강 RF 포텐셜)과 **Interconnect Zone** (약한 포텐셜)을 동시에 포함.
    - Interconnect Zone → Compute Zone으로 이온을 셔틀링할 때
    - **전기장 경도 · 위상 · 마이크로모션 보정**이 완벽히 맞지 않으면 운동 모드가 교란되어 내부 상태와 얽힘 위상이 틀어짐.
    - Compute Zone에는 이미 여러 연산 큐비트가 체인 형태로 존재하므로, 새 이온이 들어올 때 체인의 **정규 진동 모드(normal mode)** 가 다시 계산되어야 함.

      - → 즉각적인 **게이트 파형 / 펄스 재보정**이 필요하지만,
      - μs 단위로 그걸 실시간 보정하기는 사실상 불가능.
  - **3️⃣ SWAP 게이트 정확도 (Two-qubit Gate Fidelity)**

    - 스왑 연산은 3개의 CNOT 게이트에 해당하는 복합 게이트 체인.
    - 현재 IonQ의 **물리 2-qubit 게이트 fidelity ≈ 99.5 %**,

      - 세 번 누적하면 전체 신뢰도는 약 98.5 % 정도까지 떨어짐.
    - 얽힘 전이를 위해선 > 99.9 %가 필요.
    - 즉, **현재 게이트 정확도**로는 얽힘이 QPU 체인으로 완전하게 전이될 때 노이즈가 누적되어 결과적 fidelity 가 떨어짐.
  - **4️⃣ 광자–이온 동기화 (Photon–Ion Timing Synchronization)**

    - 포토닉 인터커넥트에서 Bell state 성공 확률은 수 Hz 수준.
    - 얽힘 신호가 탐지된 즉시, 두 QPU가 스왑 게이트를 동시에 수행해야 하지만,
    - **레이턴시와 위상 드리프트** 때문에 μs 단위 정밀 동기화가 어렵다.
    - IonQ가 bare-metal RPU 스택을 쓰는 이유가 바로 이 동기화 문제 때문이지만, 아직 **Cross-QPU 레벨에서는 완전 폐루프(feedback loop) 동기화**가 구현 안 된 상태.
