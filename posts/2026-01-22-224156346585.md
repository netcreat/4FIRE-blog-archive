**📌 핵심 구성 요소 설명**

- - **Quantum Repeater + Entanglement Buffer**

    - 각 양자 리피터는:

      - 다수의 **양자 메모리 슬롯**
      - 이들 사이에 **쌍(pairwise) 얽힘 상태**를 저장
      - 얽힘 생성 속도 > 얽힘 붕괴 속도 + 소비 속도
      - 👉 **항상 재고(inventory)가 있는 상태**
    - **즉, 얽힘을 ‘실시간 생성’이 아니라 ‘재고 관리’ 문제로 바꿈**
  - **Programmable Optical Switchboard**

    - 리피터 내부에 **광 스위치보드**가 존재
    - 기능:

      - 어떤 양자 메모리 ↔ 어떤 광 채널도 연결 가능
      - 얽힘을 원하는 방향·노드로 재라우팅 가능
    - 전기적 스위치 ❌ → **광 기반 스위치 ⭕**
    - 양자 상태 보존, 이것이 이 특허의 **기술적 핵심**이다.
  - **Pairwise Entanglement 인스턴스 관리**

    - 얽힘은 “추상적 상태”가 아니라:

      - **관리 가능한 인스턴스**
      - 생성, 저장, 소비, 폐기 대상
    - 시스템은:

      - 어떤 얽힘을 언제 쓰고
      - 어떤 얽힘을 유지할지
      - 어떤 얽힘을 재활용할지
      - **최적화 알고리즘으로 결정**
    - 👉 완전히 **네트워크 자원 관리 문제**로 격상됨

**📌 기존 양자 네트워크와의 차이점**

|  |  |  |
| --- | --- | --- |
| **구분** | **기존 방식** | **이 특허** |
| 얽힘 생성 | 필요 시 생성 | **사전 생성 (Pre-generation)** |
| 얽힘 관리 | 일회성 | **버퍼 기반 재고 관리** |
| 라우팅 | 고정 경로 | **광 스위치로 동적 라우팅** |
| 서비스 모델 | Best-effort | **On-demand (QoS 가능)** |
| 확장성 | 낮음 | **네트워크 규모 확장 가능** |

**📌 이 특허가 겨냥하는 실제 사용 시나리오**

- - **양자 인터넷 (Quantum Internet)**

    - 고객이 요청하면:
    - **즉시 얽힘 제공**
    - 지연(latency) 예측 가능
  - **분산 양자컴퓨팅**

    - 서로 다른 QPU 간:
    - **얽힘 기반 연산**
    - 텔레포테이션 기반 게이트
  - **QKD / Secure Networking**

    - 키 생성 전에:
    - 얽힘을 충분히 확보
    - 네트워크 트래픽 폭증에도 안정적

**📌 왜 “광 스위치보드”가 중요한가**

- - 이 특허에서 가장 **차별적인 포인트**는 바로 이것이다.

    - 전통적 리피터:

      - 메모리 ↔ 채널 매핑이 정적
    - 이 특허:

      - **모든 메모리 ↔ 모든 광 경로 연결 가능**
      - → 얽힘 자원의 **단편화(fragmentation) 방지**
  - 이는 **데이터센터의 SDN이나 클라우드의 리소스 풀링**과 매우 유사한 개념이다.

**📌 이 특허의 숨은 전략적 의미**

- - 이 특허는 단순한 물리 구현이 아니라

    - “양자 얽힘을 네트워크 서비스 자원으로 상품화”하려는 시도다.

      - 얽힘 = 네트워크 패킷
      - 양자 메모리 = 버퍼
      - 광 스위치 = 양자 라우터
      - 고객 = 얽힘 QoS를 요구하는 사용자
  - 👉 **Quantum-as-a-Service (QaaS)** 의 핵심 인프라 특허

  - 방법:

    1. 계산용 qubit → entanglement qubit로 SWAP
    2. Teleportation
    3. 원격 QPU에서 gate 수행

**📌 Modular / Distributed Quantum Computing의 최소 단위**

- - **이 그림의 한 줄 요약**

    - 서로 떨어진 두 QPU를 “얽힘 + 광 인터페이스”로 묶어, 하나의 계산 시스템처럼 쓰는 구조

- - **Quantum Processing Units (QPU 902, 930)**

    - 각 QPU 안에는:

      - **계산용 큐비트** (사선 음영)
      - **얽힘용 큐비트** (빈 원)
    - 로컬 QPU 내부에서는:

      - 기존 양자 게이트(e₁, e₂, e₃, e₄) 수행
    - 👉 여기까지는 “평범한 양자컴퓨터”
  - **Quantum Entanglement Network (932)**

    - QPU와 QPU 사이에 직접 연결 ❌
    - 대신 QPU ↔ 광 트랜스듀서 ↔ 광 스위치 ↔ 양자 메모리 ↔ 네트워크
    - 이 네트워크가 **QPU 간 얽힘을 공급**
    - 👉 QPU는 “네트워크에 붙은 노드”가 됨
  - **Quantum Memories (908, 918)**

    - 앞에서 봤던 **entanglement buffer**
    - 얽힘은 계산 중간중간 필요할 때 여기서 꺼내 씀

**📌 FIG.9에서 실제로 일어나는 계산 개념**

1. 1. QPU 902에서 계산 중
   2. 특정 연산이 원격 큐비트(q₄, q₅ 등)와 얽힘 필요
   3. 네트워크를 통해 **미리 준비된 얽힘 사용**
   4. Teleportation 기반 게이트 수행
   5. 결과는 다시 로컬 QPU로 귀속
   - 📌 **중요**

     - 큐비트를 “이동”시키지 않는다
     - **연산만 이동**시킨다

**📌 대규모 논리 연산이 실제로 어떻게 흐르는가**

- - **🔑 Key를 먼저 보면**

    - 빈 원: **얽힘용 물리 큐비트**
    - 사선 원: **계산용 물리 큐비트**
    - 굵은 선 경로: **하나의 논리 연산(logical operation) 경로**
  - 👉 즉, **한 개의 논리 연산이 여러 QPU와 메모리를 가로지름**

    - Quantum memory pools (1116, 1126)
  - **하단 QPU (1138)**

    - 상단 QPU와 얽힘으로 연결
    - 논리 연산의 나머지 절반 수행

**📌 FIG.11의 핵심 포인트**

- - **논리 큐비트 ≠ 물리 큐비트**

    - 하나의 logical operation이 여러 물리 큐비트를 순회
    - 이는:

      - 오류율 감소
      - 스케일링 필수 조건
  - **Optical switchboard가 “연산 라우터” 역할**

    - 단순 통신 ❌
    - **어떤 큐비트를 언제 얽힐지 결정**
    - 👉 네트워크 장비가 계산에 직접 관여
  - **이 구조는 QEC 친화적**

    - Surface code / lattice surgery
    - Sharded logical qubits
    - Networked stabilizer measurement
    - 👉 **에러 보정과 자연스럽게 결합**

****

**📌 이 두 그림이 왜 “치명적”인가**

- - 이것은 네트워크 특허만이 아닌, 양자컴퓨터 스케일링 특허이기도 하다.

> Quantum entanglement networks are used not only to distribute entanglement, but to enable modular and distributed quantum computation by connecting multiple quantum processing units into a single logical computing system.

- - 큐비트 수 확장 문제
  - 칩 수율 문제
  - 냉각/제어 복잡도 문제
  - 👉 전부 **네트워크로 우회**

**✅ 그럼 2025년 10월 특허(US 12443874 B2)와 뭐가 다른가?**

- - 결론부터 말하면:

> ***10월 특허는 ‘개념과 정당성’을 만들고,***
>
> ***2026년 공개 특허는 ‘운영체계와 최적화’를 장악한다.***

**📌 2025.10 특허 (US 12443874 B2)**

- - **성격**

    - **Quantum Entanglement as a Service (QEaaS)** 개념 특허
    - “이게 왜 가능한가”에 초점
  - **핵심 주장**

    - Trust-free intermediate node
    - Joint measurement (BSM)
    - Superposition을 붕괴시키지 않고 얽힘 확장
    - 서비스 사업자 모델 가능
  - 📌 한마디로:

> ***“얽힘을 서비스로 팔 수 있다”는 권리***

**📌 2026.01 공개 특허 (US 20260005770 A1)**

- - **성격**

    - **운영·스케일·최적화 특허**
    - “이걸 어떻게 대규모로 굴리느냐”
  - **추가된 결정적 요소**

|  |  |  |
| --- | --- | --- |
| **항목** | **US 12443874 B2** | **US 20260005770 A1** |
| Entanglement buffer | 개념적 | **구조·슬롯·관리 로직 명시** |
| Optical switchboard | 언급 수준 | **Any-to-any 라우팅 핵심** |
| Rate inequality | 없음 | **시스템 조건으로 특허화** |
| Multi-customer | 개념 | **실제 시나리오(FIG.5)** |
| Time evolution | 없음 | **FIG.6으로 명시** |
| Distributed QC | 거의 없음 | **후반부 핵심** |

- - 쉽게 말해:

    - 2025: **“양자 인터넷은 가능하다”**
    - 2026: **“이 방식 말고는 대규모 상용화가 어렵다”**

**📌 전략적으로 보면 이게 왜 무섭나**

- - 이 두 특허는 **의도적으로 겹친다**.

    - 앞 특허:

      - 넓은 개념
      - 회피 어려움
    - 뒤 특허:

      - 구현 세부
      - 회피 불가능
  - 👉 **특허 펜스(patent fence)** 구조
  - 경쟁사가:

    - “우리도 얽힘 서비스 할래요” → 2025 특허 걸림
    - “다른 방식으로 운영할게요” → 2026 특허 걸림
