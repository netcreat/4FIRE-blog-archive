**✅ Merchant DSP 이용시 고려사항**

- - 칩 또는 모듈 형태의 DSP를 가져다 꼽는다고 원하는 기능이 전부 구현되는 것은 아니다.
  - ASIC 형태의 칩을 기판에 연결하여 여러 기능들을 구현하는 하드웨어를 구현하거나
  - FPGA를 이용하는 방법이 있다.

    - 현재 상용화 되어 있는 OCT / OISL 단말 대부분은 FPGA를 사용중일 것으로 예상됨.

|  |  |  |
| --- | --- | --- |
| **항목** | **FPGA 기반 DSP** | **ASIC DSP** |
| 구현 | HDL(Hardware Description Language)로 설계 | 고정 하드웨어 |
| 변경 | 가능 | 불가 |
| 전력 효율 | 낮음 | 매우 높음 |
| 성능 | 중간 | 매우 높음 |
| 유연성 | 높음 | 낮음 |

**✅ Tbps급 coherent를 FPGA로 구현 가능할까?**

- - 결론부터 말하면:

    - 이론적으로는 가능
    - 실질적으로는 거의 비현실적
    - 산업적으로는 ASIC이 압도적으로 유리

**1️⃣ Tbps coherent가 요구하는 연산량**

- - 800G coherent (DP-16QAM 기준)만 봐도:

    - Symbol rate: ~130 GBd
    - Dual polarization
    - 2x I/Q
    - 수십 GS/s ADC
    - 실시간 equalization
    - Carrier recovery
    - Phase noise tracking
    - Soft-decision FEC
  - 연산량은:

    - 수백 GS/s급 실시간 DSP 파이프라인 + 고복잡도 LDPC 반복 디코딩을 동시에 처리해야 함

**2️⃣ FPGA의 현실적인 한계**

- - **클럭 속도**

    - FPGA 내부 클럭:

      - 500 MHz ~ 1 GHz 수준
    - Coherent DSP 내부:

      - Deep pipeline
      - GHz 이상 동작
    - Tbps 처리하려면:

      - 엄청난 병렬화 필요
  - **전력**

    - 고급 FPGA (예: Xilinx UltraScale+급):

      - 400G 처리 시 30~60W 가능
    - 고속 병렬화 구조를 구성하면 100W 이상으로 상승할 가능성이 높음

      - 우주에서는 매우 부담.
  - **FEC**

    - Soft-decision FEC는:

      - 수천 비트 블록
      - 반복 연산
      - 높은 병렬도
    - ASIC은 전용 하드웨어 가속 블록 있음.
    - FPGA는 LUT로 구현 → 전력/면적 비효율.

**3️⃣ 산업계 현실**

|  |  |
| --- | --- |
| **속도** | **FPGA 가능성** |
| 100G | 매우 현실적 |
| 200G | 가능 |
| 400G | 가능하지만 빡셈 |
| 800G | 매우 어려움 |
| 1Tbps | 사실상 ASIC 필요 |

- - 그래서:

    - 400ZR 이하 → FPGA 연구 사례 존재
    - 800ZR 이상 → 상용은 사실상 ASIC

**4️⃣ 왜 ASIC이 압도적이냐?**

- - **전력 효율**

    - ASIC은:

      - 필요 회로만 존재
      - 불필요한 LUT 없음
      - 배선 최적화
    - 전력 대비 성능이 2~5배 이상 좋음.
  - **고속 I/O 통합**

    - Marvell Orion 같은 칩은:

      - 고속 ADC/DAC 통합
      - Coherent front-end 최적화
      - DSP 파이프라인 고정 최적화
    - FPGA는 외부 ADC 필요.

**5️⃣ 그럼 우주 OISL은?**

- - 여기서 중요한 점:
  - 우주에서는:

    - 광섬유 CD (Chromatic Dispersion - 색분산) 없음
    - PMD (Polarization Mode Dispersion) 없음
    - CD/PMD 보상 블록은 단순화 가능하지만, 위상/주파수 추적 및 적응 등화는 여전히 필수
  - 즉,

    - 완전한 DCI coherent보다 연산량 감소 가능
  - 그래도 Tbps급이면:

    - FPGA 단독은 현실적으로 매우 힘듦

**6️⃣ 현실적인 아키텍처**

- - **400G 병렬화**

    - 400G FPGA 기반 링크 x 3
    - = 1.2 Tbps aggregate
  - **Coherent-lite ASIC + FPGA**

    - Laser
    - → Coherent-lite ASIC
    - → FPGA
  - **Full coherent ASIC**

    - Laser
    - → 800G ASIC DSP
    - → FPGA

**🔥 최종 결론**

- - Tbps coherent를 FPGA만으로 구현 → 가능은 하지만 비현실적
  - 전력/열/복잡도 때문에 ASIC이 훨씬 유리
  - 우주에서도 Tbps급이면 ASIC 필요 가능성 높음
  - 400G 이하라면 FPGA 충분히 현실적

**📌 우주 OCT 운영시 발생할 수 있는 이슈**

- - 우주에서는 다음과 같은 문제들이 생긴다.

    - 방사선 내성 (rad tolerance)
    - 온도 범위
    - 전력 소모
    - 패키징
    - 진동 내구성

**📌 “상용 DSP 칩”을 우주에서 쓰는 전형적 방법 5가지**

- - 보통 COTS DSP를 그대로 쓰기 어렵고
  1. **COTS + 미션 프로파일로 버틴다 (NewSpace에서 흔함)**

     - LEO / 짧은 수명(예: 3~5년) / 대규모 군집이면 “완전 rad-hard”가 아니라 **rad-tolerant + 운영/교체** 전략을 택하기도 함.
     - NASA도 COTS 사용 시 **리스크를 redundancy, reset/power-cycle, modularization** 등으로 완화한다고 정리해 둠.
  2. **차폐(Shielding) + 레이아웃 최적화**

     - 무게/열 trade-off가 있지만, **차폐로 TID(총이온화선량) 낮추기**는 기본 카드 중 하나.
  3. **오류 내성 설계(EDAC/ECC) + 리셋/복구 루틴**

     - 메모리 ECC, CRC, watchdog, 자동 재부팅, 소프트웨어 복구는 COTS 우주 적용의 핵심 “생존 장치”.
  4. **중복(리던던시) + TMR(삼중화) + 스크러빙**

     - SRAM 기반 로직(특히 FPGA/SoC)은 SEU (single Event Upset)가 나기 쉬워서
     - **TMR + 구성 메모리 스크러빙**(주기적으로 비트플립 복구)을 많이 쓴다.
  5. **Coherent DSP는 COTS ASIC + Space FPGA 분업 구조**

     - 고속 코히어런트 신호 처리(등화, 위상 복구, FEC 등)는 대부분 상용 COTS DSP ASIC이 담당.
     - 우주 등급 FPGA/SoC는 감시, 리셋 제어, 리던던시 관리, 링크 재초기화 등 신뢰성 계층을 담당.
     - 즉, “DSP를 FPGA로 대체”가 아니라 “DSP를 FPGA가 관리”하는 구조가 일반적.
     - AMD Xilinx Space-Grade Versal (XQR Versal)은 space-grade / rad-tolerant 포지션을 명시하며, 고속 트랜시버/ARM 코어를 포함.
     - Microchip RTG4 역시 방사선 허용 FPGA로 우주 미션에 적용 사례 존재.

> ***[용어 정리]***
>
> ***SEU = Single Event Upset***
>
> *방사선 입자 하나가 지나가면서* ***비트가 뒤집히는 현상***
>
> *위험도 중간*
>
> *일시적인 문제, 재부팅하면 복구 가능*
>
> *ECC 메모리, Triple Modular Redundancy (TMR) 사용*
>
> ******
>
> ***ECC 메모리 (Error Correcting Code)***
>
> *메모리에 저장된 데이터가 뒤집혀도 스스로 복구하는 기술*
>
> ***TMR (Triple Modular Redundancy)***
>
> *같은 회로를 3개 만들고, 다수결로 결과를 선택하는 구조*
>
> **
>
> ***SEL = Single Event Latch-up***
>
> *방사선이 내부 구조를 트리거해서* ***전류가 폭주하는 현상***
>
> *위험도 매우 높음*
>
> *재부팅으로 해결 안됨*
>
> *전원 차단 필요*
>
> **
>
> ***TID = Total Ionizing Dose***
>
> *시간이 지나면서 방사선이 반도체를 조금씩 영구적으로 열화시키는 현상*
>
> *TID는 누적되는 값으로, 천천히 망가짐을 의미함.*
>
> **
>
> ***방사선의 영향은 LEO → MEO → GEO 순으로 높아짐***
>
> ***LEO에서는 SEU가 주 이슈***
>
> ***GEO에서는 TID와 SEL 리스크가 크게 증가***
>
> ******
>
> ******

| 성격 | 순간적 | 순간적 | 누적적 |
| 복구 | 가능 | 전원 차단 | 불가 |

**📌 이걸 누가 할 수 있나?**

- - SkyWater 같은 특수 파운드리

    - **터미널 제어 ASIC**

      - 레이저 락(주파수/위상 안정화) 제어
      - PAT(포인팅/획득/추적) 제어
      - 전원/보호/텔레메트리
    - **보안/키관리/암호 모듈**
    - **리던던시 관리, watchdog, fault manager**
    - **인터페이스 브리지/패킷 처리(중저속)**
    - **하지만, 800G coherent DSP 같은 초대형 고속 SerDes DSP는 → 현재 공정 노드상 직접 구현은 매우 어려움**
  - 방산용 보드 설계 업체
  - 위성 페이로드 통합 업체

**📌 “고차 QAM/코히어런트”를 우주에서 하려면 결국 무엇이 핵심인가**

- - 논문/서베이에서도 공통적으로 말하는 건:

    - 우주/FSO 코히어런트는 **DSP + 광학 + 시스템 설계** 공동 최적화가 핵심이라는 점.
  - 그래서 “상용 DSP 칩을 샀다” 해도,

    - 링크가 흔들리는 순간(포인팅 지터/전력 마진 변화)에
    - **adaptive modulation/coding**, 강한 FEC, 링크 제어가 제대로 동작해야 하고
    - 이 제어/복구 체계가 결국 우주 신뢰성의 본체가 된다.
  - [Recommendations on Use of Commercial-Off-The-Shelf (COTS) Electrical, Electronic, and Electromechanical (EEE) Parts for NASA Missions](https://ntrs.nasa.gov/api/citations/20205011579/downloads/20205011579%2002-13-23.pdf)
