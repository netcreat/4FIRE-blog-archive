---

**✅ 암호화용 칩셋의 주요 역할******

1. 1. **암호화/복호화 연산 수행**

      - AES, RSA, ECC 같은 알고리즘을 하드웨어 수준에서 빠르고 안전하게 처리.
      - CPU에서 소프트웨어로 처리하는 것보다 훨씬 빠르고 전력 효율적.
   2. **키 관리**

      - 암호화 키를 안전하게 저장하고 외부에서 접근하지 못하도록 보호.
      - 보통 칩셋 내부에 Secure Element(SE)나 **TPM(Trusted Platform Module)** 같은 영역이 있음.
   3. **난수 생성**

      - 암호화에 필요한 안전한 난수(Random Number)를 생성.
      - 하드웨어 기반 난수 생성기는 소프트웨어보다 예측 불가능성이 높음.
   4. **보안 부팅 및 인증**

      - 시스템이 부팅될 때 펌웨어나 OS가 변조되지 않았는지 검증.
      - 디바이스 인증, 사용자 인증에도 활용.
   5. **물리적 공격 방어**

      - 칩셋은 전력 분석, 타이밍 공격 등 하드웨어 해킹을 어렵게 만드는 설계 포함.

💡 **왜 칩셋이 필요한가?**

- - 소프트웨어 암호화는 CPU 리소스를 많이 쓰고, 공격에 취약할 수 있음.
  - 칩셋은 **전용 하드웨어**로 속도, 보안성, 에너지 효율을 모두 강화.

---

**✅ 암호화 칩셋 내부 주요 구성 요소**

**1️⃣ 공통 요소 — TPM · HSM · SE 모두 갖는 구조**

|  |  |  |
| --- | --- | --- |
| **구성 요소** | **역할** | **TPM / HSM / SE 공통성** |
| **암호화 엔진 (Crypto Engine)** | RSA, ECC, AES, SHA 연산 | 모두 하드웨어 가속 방식. 단, HSM은 속도·처리량이 가장 높고, SE는 저전력·경량에 최적화 |
| **TRNG (난수 발생기)** | 키·Nonce 생성용 고품질 난수 | 세 종류 모두 필수. FIPS 140-3, CC 등 인증 요구 |
| **키 저장소 (Key Vault)** | 루트 키 및 파생 키 저장 | TPM은 SRK, HSM은 Master Key, SE는 Root Secret 구조로 이름만 다름 |
| **보안 로직 (Tamper Protection)** | 물리적·측면채널 공격 방어 | 세 가지 모두 실리콘 수준의 보호 회로 탑재 (전압/온도 이상 감지, 글리치 방지 등) |
| **입출력 인터페이스** | CPU, 네트워크, 호스트와 통신 | TPM·SE는 SPI/I²C/LPC, HSM은 PCIe/Ethernet/USB 등 고대역 인터페이스 |
| **NV 메모리** | 정책·인증·키 메타데이터 저장 | 공통 존재. 다만 TPM은 플랫폼 상태(PCR 등), SE는 결제·ID 토큰 보존 중심 |

**2️⃣ TPM vs HSM vs SE — 구조적·목적별 차이**

|  |  |  |  |
| --- | --- | --- | --- |
| **구분** | **TPM (Trusted Platform Module)** | **HSM (Hardware Security Module)** | **SE (Secure Element)** |
| **주요 용도** | PC·서버 부팅 무결성, OS 인증, 디바이스 신뢰 | 은행·클라우드·CA 등 키 관리/서명 | IoT·모바일 결제·eSIM 등 엣지 보안 |
| **인증 수준** | Common Criteria EAL4+~EAL5+ | FIPS 140-2/3 Level 3~4 | CC EAL5+/EAL6+ |
| **보안 강도** | 중간 | 가장 높음 | 높음 (크기·전력 제한 내) |
| **처리 성능** | 저~중 | 매우 높음 (HW 병렬처리) | 낮음 (저전력 MCU급) |
| **인터페이스** | LPC, SPI (CPU 내장형) | PCIe, USB, Network | I²C, ISO7816 (스마트카드류) |
| **PCR (Platform Config Registers)** | ✅ 부팅 해시 저장 전용 | ❌ 없음 | ❌ 없음 |
| **운영 환경** | PC/서버·임베디드 | 데이터센터·클라우드 | IoT·모바일 |
| **예시 칩** | Infineon SLB9670, Nuvoton NPCT75x | Thales Luna, Utimaco, AWS CloudHSM | NXP SE050, ST STSAFE-A110 |

**3️⃣ 핵심 이해 포인트**

- - **TPM = PC/서버용 보안 루트**

    - → OS 부팅·드라이버·펌웨어 무결성 측정(PCR).
    - 2016년 이후 출시된 PC나 노트북에는 이미 TPM 2.0이 내장되어 있음.
    - 단가가 몇달러 수준으로 매우 낮음
    - PQC 적용은 소프트웨어 업데이트로 적용 가능.
    - IOT 기기들은 PC처럼 표준화가 덜 되어 있어 칩셋 추가가 필수.
    - OS 보안 중심, 고성능 암호화 필요 없음 → 부가가치 낮음
  - **HSM = 키 수명 전체를 관리하는 금고**

    - → 인증서 발급, 서명, 암호화 서비스 제공.
    - HSM(Hardware Security Module)과 같은 고성능 보안 칩셋은 서버, 금융, 인증 시스템에서 계속 수요 증가.
    - 금융, 의료, 정부 분야에서 **하드웨어 기반 보안** 요구사항이 늘어남 (예: FIPS 140-3, GDPR, ISO 27001).
    - 금융·클라우드에서 PQC 전환 필수 → **HSM 수요 폭발적 증가** 예상.
    - **PQC 적용 후**:

      - **하이브리드 인증서 체계** (기존 + PQC) 필요.
      - HSM은 대규모 키 교환·서명 연산을 처리 → PQC 알고리즘은 연산량이 커서 **고성능 하드웨어 필요**.
      - 클라우드 HSM 서비스는 PQC 전환을 위한 API 확장 필수.
  - **SE = IoT/모바일 단말 보안 루트**

    - → 결제, eSIM, 디바이스 인증에 초점.
    - 자율주행차, EV 충전 인프라 등에서 보안 칩셋 필수.
    - PQC 적용 난이도 높음 → 신규 칩셋 설계 필요 → **SE 시장 성장 가속**.
    - **PQC 적용 후**:

      - **IoT 기기에서 저전력 PQC 구현이 최대 과제.**
      - SE 칩셋은 제한된 리소스에서 PQC 연산을 수행해야 하므로 **경량 PQC 알고리즘** 채택 필요.
  - **결론**: 단순한 MCU나 일반 SoC보다 훨씬 높은 수준의 설계·제조·검증이 필요

    - (요즘은 NXP, Infineon 등이 **PQC 내장 SE**로 확장 중)

**✅****인증 체계의 국제 표준**

**1️⃣ Common Criteria (CC) – EAL4+~EAL6+**

- - **공식 명칭:** Common Criteria for Information Technology Security Evaluation
  - **주요 기관:** ISO/IEC 15408 국제 표준
  - **평가 주체:** 독립 인증기관 (e.g. BSI, ANSSI, NIAP 등)
  - **개념**

    - Common Criteria(공통 평가 기준)는 **IT 보안 제품이 어느 수준까지 신뢰할 수 있는지**를 평가하는 국제 인증 체계예요.
    - 평가 대상은 운영체제, 네트워크 장비, IC 칩, 스마트카드, HSM 등 광범위하다.
  - **EAL 등급 구조 (Evaluation Assurance Level)**

|  |  |  |
| --- | --- | --- |
| **등급** | **의미** | **설명** |
| **EAL1** | 기능 시험 | 최소 수준. 단순 테스트만 수행. |
| **EAL2** | 구조적 테스트 | 설계 문서 및 소스코드 일부 검증. |
| **EAL3** | 체계적 테스트 | 보안 개발 프로세스까지 평가. |
| **EAL4** | **설계 및 검증 완료 수준** | 상용 제품에서 흔히 목표로 함. 개발 과정과 테스트 모두 심층 검토. |
| **EAL5** | **반고급 수준 (Semi-formal)** | 하드웨어 기반 공격에도 견딜 수 있음. 보안 아키텍처 정형 검증 포함. |
| **EAL6** | **고급 수준 (Formal)** | 국가급·군수용 등 고위험 환경에 사용. 회로 레벨까지 검증. |
| **EAL7** | 최고 수준 (Formal verified design) | 실험실·이론 수준. 실제 상용 칩에는 드묾. |

> “EAL4+”에서 “+”는 특정 보안 강화 항목(예: 사이드채널 방어, 물리침입 방어 등)을 추가 인증받았다는 의미

- - **예시**

    - **TPM:** 보통 **EAL4+~EAL5+**
    - **보안 스마트카드(SE):** **EAL5+~EAL6+**
    - **정부 ID 칩:** EAL6+ 필수

**2️⃣ FIPS 140-2 / 140-3 – Level 1~4**

- - **공식 명칭:** Federal Information Processing Standard (FIPS) Publication 140
  - **관리 기관:** NIST (미국 국립표준기술연구소)
  - 참고로 PQC관련 표준안도 NIST에서 정립했다. FIPS203~206

[**포스트 양자(PQC) 주요 알고리즘 4종 세트와 QKD**

NIST가 표준화(혹은 초안 단계)로 채택한 PQC 알고리즘 4개를 살펴보도록 하겠다. 알고리즘별로 각...

blog.naver.com](https://blog.naver.com/4-fire/224035914317)

- - **개념**

    - FIPS 140은 암호 모듈(cryptographic module)의 보안 강도를 정의하는 미국 정부 표준이다.
    - 모듈이 **어떤 환경에서 안전하게 작동하는지**를 Level 1~4로 구분다.
    - (즉, “이 칩을 정부 시스템에서 써도 되는가?”를 판단하는 기준)
  - **Level별 구분**

|  |  |  |
| --- | --- | --- |
| **등급** | **의미** | **특징** |
| **Level 1** | 최소 보호 | 소프트웨어적 보안만 있음. 일반 OS 기반 암호 모듈 수준.   |
| **Level 2** | 역할 기반 접근 제어 | 물리적 씰(seal)·탬퍼증거 장치 요구.   |
| **Level 3** | **탬퍼 방지 + 키 보호 강화** | 칩 내부에서 키 추출 불가, 탐침 시 키 자동 삭제. 하드웨어 보안 모듈(HSM) 표준. |
| **Level 4** | **최고 등급 (탐침/전력/온도 공격 방지)** | 환경 이상 감지 시 즉시 키 파괴. 군수·정보기관용. |

- - 예시

    - **클라우드/인증기관 HSM:** **FIPS 140-3 Level 3**
    - **AWS CloudHSM, Thales Luna, Utimaco:** Level 3~4
    - **IoT용 SE/TPM:** 보통 Level 2 수준 (물리적 탬퍼 방어 포함)
