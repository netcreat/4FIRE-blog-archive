# QCCD 의 배선 확장을 위한 접근 방식

Published: 2025-09-05T15:44:43.666000+09:00

Original Naver post: https://blog.naver.com/4-fire/223996526279

---

최근 IEEE에서 개최한 QCE25에서 발표된 논문중 이온트랩과 관련된 흥미로운 내용이 있어서 소개한다.

**✅QCCD의 기본 개념**

**QCCD(Quantum Charge-Coupled Device)** 아키텍처에서는 이온을 **전극에 걸린 전기 포텐셜 차이**를 이용해서 물리적으로 이동(shuttling)시킨다.

**💡****QCCD에서 이온 이동 원리**

QCCD 아키텍처는 **전극 배열** 위에 떠 있는 이온을 **전기 퍼텐셜 차이**로 이동시키는 구조.

**(1) 기본 메커니즘**

- 전극에 전압을 걸면 전기장(E-field)이 형성되고, 양이온과는 서로 밀어내는 성격을 띠게 되어 이온이 **전위가 낮은 쪽**으로 끌려감.
- 따라서 전극에 순차적으로 전압을 가변해 주면, 이온을 원하는 위치로 “미끌어지듯” 이동시킬 수 있다.
- 하지만 단순히 전압을 켜고 끄는 게 아니라, **전압을 부드럽게 램핑(ramping)** 해야 이온의 모션을 안정적으로 제어할 수 있다.

****

**💡****실제 QCCD에서 더 복잡한 이유**

이 단순한 "1번→2번→3번" 패턴보다 실제로는 제어가 더 어렵다.

**(1) 멀티존(Multi-Zone) 구조**

- - QCCD 칩에는 수십~수백 개의 전극 존(zone)이 있고, 각각은 **상태 준비, 게이트 연산, 측정** 기능을 담당.
  - 이온을 원하는 연산 존으로 보낼 때 전극 제어를 조합해야 하므로, 단순한 선형 제어보다 훨씬 많은 전극이 동시에 관여한다.

**(2) 전압 램핑(Ramping)**

- - 전압을 “툭” 바꾸면 이온이 튕기거나 열적 모션이 커져서 게이트 충실도(fidelity)가 떨어진다.
  - 따라서 **수십 ns~수 µs 단위**로 전압을 점진적으로 변경해야 함.
  - 이번 논문에서도 DAC가 최대 **50 Msps**(Mega sample per second) 속도로 동작하는 이유가 이 때문임.

**(3) 3D 전기 퍼텐셜 제어**

- - 실제 이온은 단순히 x축으로만 이동하지 않음.
  - 이온 트랩은 **RF 전극 + DC 전극**으로 구성되어 있고:

    - **RF 전극** → 이온을 z축(수직 방향)으로 띄워놓음.
    - **DC 전극** → x-y 평면 상에서 이온을 이동시킴.
  - 따라서 **3D 전기 퍼텐셜 시뮬레이션**으로 전극별 최적 전압을 계산해 적용해야 한다.

**💡****QCCD에서 전극 수가 많은 이유**

- - 이온 하나를 이동시키는 데도 전극 2~3개가 필요한데, 실제 칩에서는:

    - **큐비트 1개당 약 8~12개의 전극**이 필요.
    - 이온을 "교차점(cross-junction)"에서 회전시키거나 분리/합치는(split/combine) 동작을 할 때는
    - 동시에 **10개 이상의 전극을 정밀 제어**해야 한다.
    - 예: Oxford Ionics의 1,024큐비트 QCCD 칩 → 전극 약 **10,000개** 이상 필요.

---

**✅****배선을 줄일 수 있는 방법**

Oxford Ionics에서 발표한 WISE 배선 방식과 일본의 오사카 대학 및 여러 기관이 협력하여 연구한 고속 DAC 기반 TDM 방식이 있다.

**💡****두 방식의 공통점**

|  |  |
| --- | --- |
| **공통점** | **설명** |
| **배선 수 최소화** | 두 방식 모두 전극 수가 큐비트 수보다 훨씬 많다는 문제를 해결하려고 함 |
| **스위치 네트워크 사용** | DAC 출력 → 스위치를 거쳐 여러 전극에 공유 |
| **샘플-앤-홀드(sample-and-hold)** | 필요한 전압을 설정한 뒤, 전극 채널의 캐패시터에 저장해 일정 시간 유지 |
| **QCCD 아키텍처에 최적화** | 둘 다 트랩 이온 기반 QCCD에서 전극 제어를 간소화하는 것이 핵심 목표 |

**💡****두방식의 차이점**

|  |  |  |
| --- | --- | --- |
| **구분** | **Oxford Ionics – WISE** | **이번 논문 – TDM 고속 DAC 방식** |
| **핵심 아이디어** | 전극 스위치를 **칩 내부**에 집적해 **스마트 전선**처럼 동작 | DAC 1개에서 **전극 N개**에 필요한 전압 파형을 **시간 분할**로 생성 |
| **구현 위치** | **칩 내부**: 전극 근처에 MEMS 기반 스위치 집적 | **칩 외부**: FPGA + 고속 DAC + DEMUX로 제어 |
| **스위칭 속도** | 수십 kHz 수준 → **정적 전극(Shim) + 동적 전극 일부만 커버** | 최대 50 Msps DAC 사용 → **동적 전극 제어에 최적화** |
| **목표 스케일** | 1,000큐비트(≈ 10,000 전극) 기준, DAC 수를 **칩 단위에서 최소화** | 1,000큐비트 제어를 **외부 전자 장치 13 FPGA + 104 DAC**로 실현 |
| **전송 구조** | 칩 내부에서 DAC → 스위치 → 전극 | FPGA → 고속 DAC → DEMUX → 전극 |
| **하드웨어 복잡도** | 칩 내 스위치 집적 → 칩 설계 복잡도 증가 | 칩 단순화, 대신 **FPGA/고속 DAC** 설계 복잡도 증가 |
| **적용 환경** | 상온 및 저온 모두 고려 | 주로 상온, 향후 저온 가능성 연구 계획 |

**💡****해석**

- - **WISE 방식**은 **칩 안에서 전선을 똑똑하게 만드는 것**에 초점이 있음.

    - → 스위치를 전극 근처에 집적해서, "필요할 때만 전원 연결"하는 구조.
  - **논문의 TDM 방식**은 **칩 밖에서 고속 DAC로 시분할 제어**하는 데 초점이 있음.

    - → DAC 하나로 전극 100개를 커버하므로, DAC와 케이블 수를 **100배 절약**.
  - **WISE는 칩 아키텍처 최적화**, **TDM은 제어 전자장치 최적화**라고 보면 이해가 쉽다.

**💡****연구 배경 및 목적**

- - 이 논문은 **QCCD(Quantum Charge-Coupled Device) 아키텍처**를 기반으로 한 **트랩 이온(Trapped-ion) 양자 프로세서**의 **스케일링 문제**를 해결하려고 한다.
  - QCCD 아키텍처에서는 **이온 큐비트를 전극 배열을 따라 이동(shuttling)** 시키면서 상태 준비, 측정, 게이트 연산을 수행한다.
  - 문제는 **전극 수가 큐비트 수보다 훨씬 많다**는 점이다.
  - 예를 들어, **큐비트 1개당 약 10개 전극**이 필요하다. 따라서 **10,000개의 전극 → 1,000개의 큐비트**를 제어하려면 **10,000개의 DAC**가 필요해진다.
  - 현재 방식은 **각 전극마다 DAC를 1:1로 연결**하기 때문에:

    - 하드웨어 복잡도가 매우 높아지고,
    - FPGA I/O 포트 부족,
    - 케이블링 및 배선이 지나치게 복잡해지는 문제가 발생한다.
  - 논문은 **고속 DAC 기반 시분할 다중화(Time-Division Multiplexing, TDM)** 방식을 제안해 **제어 시스템 리소스를 대폭 절감**하는 것을 목표로 한다

**💡****제안한 방법: 고속 DAC 기반 시분할 다중화(TDM) 제어**

- - **핵심 아이디어**

    - 기존 방식: **전극 1개 ↔ DAC 1개**
    - 제안 방식: **고속 DAC 1개 ↔ 전극 N개** (시분할)
    - **하나의** **고속 DAC**에서 전극 전체에 필요한 **완전한 전압 파형을 생성**한 뒤, DEMUX(디멀티플렉서)를 통해 각 전극 채널에 분배하고, 각 채널의 **캐패시터**가 전압을 유지하는 구조를 제안한다.
  - **시스템 아키텍처**

    - **고속 DAC** → **DEMUX 네트워크** → **전극 채널별 캐패시터** → **OP-AMP 증폭기**
    - **FPGA**는 고속 DAC 및 디지털 디코더를 제어하며, 여러 제어 모듈을 동기화하기 위해 **마스터 FPGA**를 둔다.
    - 10GbE를 이용해 각 FPGA 모듈을 공통 클럭으로 동기화한다.
  - **멀티플렉싱 팩터(N)**

    - **멀티플렉싱 팩터(N)** = **DAC 1개가 제어하는 전극 수**.
    - 이상적인 조건에서:

- - - 논문에서는 DAC 샘플링 속도 **50 Msps**, 채널당 0.5 MHz 업데이트 속도를 가정 → **N ≈ 100**을 달성 가능하다고 분석.

**💡****이번 논문에서 전극 제어가 어려운 이유**

- - **(1) DAC 1:1 방식의 한계**

    - 전극 10,000개 → DAC 10,000개 필요 → 불가능.
    - 배선도 너무 많아서 실리콘 패키징 불가 수준.
  - **(2) TDM 방식의 장점**

    - DAC 1개 → 전극 100개 제어 (N=100)
    - FPGA가 DAC 샘플링 타이밍과 DEMUX 스위치를 동기화해
    - 전극 전압을 마치 **개별 제어하는 것처럼 보이게 함**.

**💡****FPGA가 필요한 이유**

|  |  |  |
| --- | --- | --- |
| **FPGA 역할** | **세부 기능** | **없을 경우 문제점** |
| **고속 DAC 컨트롤러** | 14~16비트 데이터 전송, 50 Msps 샘플링 | DAC 출력 지연, 타이밍 깨짐 |
| **DEMUX 및 스위치 제어** | 채널별 샘플-홀드 동기화 | 채널별 전압 갱신 오류 |
| **다중 FPGA 동기화** | 13개 FPGA 간 공통 클럭, 10GbE 통신 | 10,000 전극 제어 불가능 |
| **디지털-아날로그 통합 제어** | 전극 전압 파형 + 디지털 타이밍 모두 담당 | MCU/CPU로 대체 불가 |

**💡****WISE 방식과 비교했을 때 FPGA의 역할**

|  |  |  |
| --- | --- | --- |
| **항목** | **WISE 방식 (Oxford Ionics)** | **이번 논문 방식 (TDM + FPGA)** |
| 스위치 제어 위치 | 칩 내부 MEMS 스위치 자동 제어 | 칩 외부 FPGA가 고속 제어 |
| DAC ↔ 전극 연결 | 내부 네트워크에서 처리 | FPGA가 DEMUX 통해 직접 제어 |
| FPGA 필요성 | 낮음 (칩 내부에서 해결) | 필수 (외부에서 전체 타이밍 제어) |
| 확장성 | 칩 설계 복잡, 외부 단순 | 외부 설계 복잡, 칩 단순 |

> Oxford Ionics의 **WISE 스마트 배선**과 결합하면 **칩 내부+외부 최적화**가 가능하다.
