**✅ 오류정정 코드의 구조와 Walking Cat 아키텍처 분석**

- - IonQ의 양자 오류정정 기술을 이해하려면 단순히 물리 큐비트가 몇 개인지보다 어떤 오류정정 코드를 사용하고, 그 코드를 실제 하드웨어에서 어떻게 실행하는지 살펴봐야 한다.
  - IonQ의 2025년 연구에서는 기존 BB6 코드를 개선한 BB5 코드가 등장했다.

    - 그리고 2026년 10월 1일에는 BB5와 신드롬 추출 최적화 기술을 포함한 미국 특허출원이 공개됐다.
    - 이에 대한 자세한 내용은 이미 다룬 바 있다.

  - 이번 글에서는 오류정정의 기본 개념부터 출발해 각 코드의 구체적인 연산량과 IonQ의 아키텍처 선택 이유까지 분석한다.

**✅ 1. 양자 오류정정의 기본 구조부터 이해하자**

**📌 [[n,k,d]]는 무엇을 의미하는가?**

- - 양자 오류정정 코드는 일반적으로 [[n,k,d]]로 표기한다.
  - n은 논리정보를 인코딩하는 데이터 큐비트 수, k는 논리 큐비트 수, d는 코드 거리(Distance)를 의미한다.
  - 예를 들어 BB5 [[48,4,7]] 코드는 다음과 같다.

|  |  |  |
| --- | --- | --- |
| **항목** | **값** | **의미** |
| 데이터 큐비트 | 48 | 논리정보를 저장하는 물리 큐비트 |
| 논리 큐비트 | 4 | 48개 데이터 큐비트에 인코딩된 정보 |
| Distance | 7 | 최소 비자명 논리 연산자의 Weight |
| Stabilizer Weight | 5 | 안정자 검사 하나가 작용하는 데이터 큐비트 수 |
| 최적 Ancilla | 6 | 해당 연구의 시뮬레이션에서 선택된 보조 큐비트 수 |

- - 이 경우 데이터 큐비트 48개와 Ancilla 6개를 합쳐 총 54개의 물리 큐비트가 필요하다.
  - 단, 54개는 해당 연구의 기본 오류정정 구성에 필요한 숫자이며, **별도의 Cat Factory나 Reservoir까지 포함한 전체 컴퓨터의 물리 큐비트 수를 의미하지는 않는다.**

**📌 안정자는 물리적인 큐비트가 아니다**

- - 안정자(Stabilizer)는 데이터 큐비트에 어떤 Pauli 연산을 적용해 검사할지 정의하는 수학적 연산자다.
  - 따라서 물리적으로 존재하는 데이터 큐비트 및 Ancilla와 구분해야 한다.
  - 예를 들어 S = X1X2X3X4X5라는 안정자를 생각해 보자.
  - 데이터 큐비트 D1부터 D5까지 다섯 개에 X 연산을 적용한다.
  - Ancilla가 해당 안정자의 측정 결과를 읽는다.
  - 정상 코드 상태에서 안정자는 +1 결과를 갖도록 정의된다.
  - 오류가 발생하면 일부 안정자의 측정 결과가 -1로 바뀔 수 있다.
  - 이처럼 여러 안정자의 측정 결과를 조합해 얻는 오류 정보를 Syndrome이라고 한다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDNfMTM5/MDAxNzkxMDI1MTEwMzEx.8yIGXfIJY7TICQihwWtCdmNc52a_UQ4X5M18n_0XDwsg.nrfr8g35ehheLW70jgjuo8IkutalgQLFmZD1Wx8_nw4g.PNG/image.png?type=w800)](#)

**📌 안정자 48개와 Ancilla 6개는 어떻게 다른가?**

- - BB5 [[48,4,7]]에는 X 안정자 검사 행 24개와 Z 안정자 검사 행 24개가 존재한다.
  - 따라서 전체 안정자 검사 행은 48개다.
  - 하지만 이 중 독립적인 안정자 조건은 n-k=48-4=44개다.
  - 나머지 네 개의 검사 행은 논리큐비트이기 때문에 다른 안정자들의 조합으로 표현할 수 있다.
  - 여기서 안정자 검사 48개를 실행한다고 해서 물리적인 Ancilla가 48개 필요한 것은 아니지만, Walking Cat에서는 ancilla와 Data 큐비트의 수를 동일하게 사용한다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDNfMjU0/MDAxNzkxMDI1MTUzMDAy.wvyi1kNxv-R7v9Ji5aoZD1KuliMee0VKQtbRTots-Lgg.OnjegLQQ2shEhFOHM7H1w6ZS_oZhcmQOcej-zukGVTkg.PNG/image.png?type=w800)](#)

- - 기존 BB5 연구에서는 Ancilla 6개를 반복적으로 사용해 48개의 안정자를 측정했다.
  - 첫 번째 측정 배치에서 6개를 측정한다.
  - Ancilla를 재설정한 다음 다른 안정자 6개를 측정한다.
  - 이러한 작업을 8회 수행하면 한 라운드의 안정자 검사가 완료된다.
  - 신드롬 추출 한 라운드를 SEC(Syndrome Extraction Cycle)라고 부른다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDNfMTIx/MDAxNzkxMDI1MjM1OTIy.r2SerZwADwlCz2pjQJDdutQpybyzkf_v9qO3bZhoib8g.97jTDb4iZLUMyFcifPxU6tf3QGw_FzwYTv3bA_cs4fog.PNG/image.png?type=w800)](#)

**📌 Distance 7은 무엇을 보장하는가?**

- - 코드 거리 7은 오류정정 회로를 반드시 일곱 번 실행해야 한다는 의미가 아니다.
  - 이상적인 신드롬 측정과 적절한 디코더를 가정하면 최대 세 개의 임의 물리 큐비트 오류를 정정할 수 있다는 의미다.
  - 일반적인 오류정정 보장 범위는 다음과 같다.

    - **정정 가능한 오류 개수 = ⌊(d-1)/2⌋**

|  |  |
| --- | --- |
| **Distance** | **보장되는 임의 오류 정정 개수** |
| 4 | 1 |
| 5 | 2 |
| 6 | 2 |
| 7 | 3 |
| 9 | 4 |
| 10 | 4 |

- - Distance가 같더라도 실제 논리 오류율이 반드시 같은 것은 아니다.
  - 게이트 오류, 측정 오류, 오류 전파 방식, 안정자 측정 순서, 디코더 성능 등에 따라 실제 성능은 달라진다.

**✅ 2. BB5와 BB6는 무엇이 다른가?**

**📌 안정자 Weight를 6에서 5로 줄였다**

- - BB는 Bivariate Bicycle의 약자로, 두 개의 순환 이동 변수를 사용하는 양자 LDPC 코드 계열이다.
  - 기존의 대표적인 BB 코드는 안정자 Weight가 6이다.
  - Min Ye와 Nicolas Delfosse의 연구에서는 이러한 기존 코드를 BB6라고 부르고, 안정자 Weight가 5인 새로운 변형을 BB5라고 명명했다.

|  |  |  |  |
| --- | --- | --- | --- |
| **항목** | | **BB6** | **BB5** |
| 공통 | 계열 | Bivariate Bicycle | BB 기반 변형 |
| Stabilizer Weight | 6 | 5 |
| 행렬 항의 기본 구성 | 3+3 | 2+3 |
| 30개 데이터 큐비트 | 코드 | [[30,4,4]] | [[30,4,5]] |
| 최적 Ancilla | 3 | 5 |
| 총 물리 큐비트 | 30+3=33 | 30+5=35 |
| Distance | 4 | 5 |
| 보장 정정 오류수 | 1개 | 2개 |
| 48개 데이터 큐비트 | 코드 | [[48,4,6]] | [[48,4,7]] |
| 최적 Ancilla | 6 | 6 |
| 총 물리 큐비트 | 48+6=54 | 48+6=54 |
| Distance | 6 | 7 |
| 보장 정정 오류수 | 2개 | 3개 |

- - BB5는 기존 BB6에서 단순히 검사 대상 큐비트 하나를 제거한 코드가 아니다.
  - 패리티 검사 행렬을 구성하는 순환 행렬의 조합을 변경한 별도의 코드 설계다.
  - 연구진은 각 행렬에 사용하는 순환 이동량의 조합을 탐색해 같은 데이터·논리 큐비트 수에서 더 높은 코드 거리를 얻었다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDNfMTk5/MDAxNzkxMDIzMjIwMjEx.IQ8J5LZXFX7jRn2ANp3p4cGYWP6k5-SeyLBMpjjLCAgg.vD9xRVKH7pwuvbUIa4TzdPzu6h-tMRNia_y_NA4a43Yg.PNG/image.png?type=w800)](#)

**📌 Weight가 낮아졌는데 Distance는 높아졌다**

- - 30개 데이터 큐비트 구성에서는 코드 거리가 4에서 5로 증가했다.
  - 48개 데이터 큐비트 구성에서는 코드 거리가 6에서 7로 증가했다.
  - 안정자 하나가 검사하는 데이터 큐비트 수가 줄었다고 해서 오류정정 능력이 반드시 낮아지는 것은 아니라는 뜻이다.
  - 안정자의 배치와 상호관계가 어떻게 설계됐는지가 중요하다.
  - 연구진의 시뮬레이션에서 물리 오류율이 0.1%일 때 BB5 [[48,4,7]]의 논리 오류율은 비교 대상 BB6 코드 중 가장 낮은 오류율보다 약 4배 낮았다.
  - 다만 이는 특정 이온 체인 모델을 사용한 시뮬레이션 결과이며, 실제 하드웨어에서 동일한 성능이 입증됐다는 의미는 아니다.

**✅ 3. Weight·Ancilla·Distance는 어떤 관계인가?**

**📌 세 변수는 서로 다른 비용에 영향을 미친다**

|  |  |  |
| --- | --- | --- |
| **변수** | **주로 결정하는 요소** | **일반적인 효과** |
| Stabilizer Weight | 안정자당 2Q 게이트 수 | 낮을수록 검사당 게이트 수 감소 |
| Ancilla 수 | 동시 측정 개수 | 많을수록 측정 배치 수 감소 |
| Distance | 오류 보호 수준 | 높을수록 더 많은 오류를 정정할 가능성 |
| 안정자 개수 | 전체 검사량 | 많을수록 총 상호작용 수 증가 |

- - Stabilizer Weight와 Distance 사이에는 일반적인 비례관계가 존재하지 않는다.
  - Ancilla가 많을수록 측정 시간이 줄어들 수 있지만 전체 물리 큐비트 비용은 증가한다.
  - 또한 Ancilla 수는 코드 자체가 결정하는 고정된 값이 아니다.
  - 같은 코드를 사용하더라도 측정 속도, 게이트 병렬화, 하드웨어 연결성에 따라 적합한 Ancilla 수는 달라질 수 있다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDNfNjUg/MDAxNzkxMDI4NTkzNjkw.lRX_ZWQFZPy-P9OFK5ZFqskqD-SedDdHkoq7iGzOIj0g.WcXRpXi83jOSEMFDI7xR1NyiuxwSMsS7p2IhSZDO9bYg.PNG/image.png?type=w800)](#)

**📌 IonQ가 최적 Ancilla를 결정한 방법**

- - 2025년 연구에서는 게이트를 순차적으로 실행하지만 여러 Ancilla는 병렬로 측정할 수 있는 장거리 이온 체인 모델을 사용했다.
  - 측정 시간이 일반 게이트보다 30배 길다고 가정했다.
  - Ancilla를 하나씩 추가하면서 논리 오류율이 얼마나 감소하는지 계산했다.
  - 추가 Ancilla를 사용했을 때 논리 오류율이 충분히 감소하는 동안 Ancilla 수를 늘리는 최적화 절차를 사용했다.
  - 이 연구에서 사용한 주요 조건은 다음과 같다.

    - 물리 오류율: 5×10-4
    - 측정 시간 비율: 30
    - 논리 오류율 개선 기준: 0.9

|  |  |  |  |
| --- | --- | --- | --- |
| **코드** | **Weight** | **Distance** | **최적 Ancilla** |
| BB6 [[30,4,4]] | 6 | 4 | 3 |
| BB5 [[30,4,5]] | 5 | 5 | 5 |
| BB6 [[48,4,6]] | 6 | 6 | 6 |
| BB5 [[48,4,7]] | 5 | 7 | 6 |

- - Weight가 낮은 BB5에서 Ancilla 수가 오히려 증가한 사례가 있다.
  - 따라서 Weight가 낮으면 Ancilla도 적게 필요하다는 단순한 관계는 성립하지 않는다.

**✅ 4. 각 코드의 실제 연산량을 계산해 보자**

**📌 계산 공식**

- - 전체 안정자 검사 행 수를 M, Weight를 w, Ancilla 수를 na라고 정의한다.
  - 모든 안정자의 Weight가 동일하다는 조건에서 SEC 한 라운드에 필요한 기본 연산량은 다음과 같다.

    - **SEC당 2Q 게이트 수 = M × w**
    - **SEC당 측정 배치 수 = ⌈M/nₐ⌉**
  - 이번 연구에서는 비교를 위해 신드롬 추출을 코드 거리와 같은 횟수로 반복했다.
  - 동일한 조건을 적용하면 총 연산량은 다음과 같다.

    - **전체 2Q 게이트 수 = M × w × d**
    - **전체 측정 배치 수 = ⌈M/nₐ⌉ × d**
  - 이 계산은 안정자 검사에 필요한 기본 상호작용을 계산한 것이며, 전체 하드웨어 명령이나 실제 실행 시간을 모두 포함하지 않는다.

**📌 SEC 한 라운드의 연산량**

| --- | --- | --- | --- | --- | --- |

**✅ 5. Walking Cat에서는 오류정정 방법이 달라진다**

**📌 기존 연구와 Walking Cat의 차이**

- - 앞서 살펴본 BB5·BB6 연구에서는 적은 수의 Ancilla를 재사용하는 장거리 이온 체인 모델을 사용했다.
  - 반면 Walking Cat은 이온을 물리적으로 이동시키는 QCCD 아키텍처를 중심으로 설계됐다.
  - 데이터 큐비트와 동일한 개수의 Ancilla를 배치하고, 이온 이동을 통해 필요한 데이터·Ancilla 조합을 만든다.
  - 정렬된 여러 쌍에 2Q 게이트를 병렬로 실행한다.
  - 이 방식에서는 2Q 게이트의 전체 개수와 실제 게이트 계층 수가 크게 달라진다.
  - 따라서 기존 연구의 최적 Ancilla 숫자와 Walking Cat의 Ancilla 배치를 동일한 기준으로 비교해서는 안 된다.

- - Q70은 SEC 한 라운드에서 70×7=490회의 기본 2Q 상호작용이 필요하다.
  - Q54는 54×8=432회가 필요하다.
  - Q102는 102×8=816회가 필요하다.
  - 하지만 데이터 큐비트와 Ancilla가 일대일로 정렬될 수 있으므로 한 계층에서 다수의 2Q 게이트를 병렬로 실행한다.

**✅ 6. BB와 GB는 구조적으로 무엇이 다른가?**

**📌 GB는 BB와 완전히 독립적인 코드가 아니다**

- - BB는 Bivariate Bicycle, GB는 Generalized Bicycle의 약자다.
  - 이번 Walking Cat 논문의 수학적 구성에서는 GB를 BB의 특수한 경우로 표현한다.
  - BB는 두 개의 순환 이동 변수 x, y를 사용한다.
  - GB는 두 번째 순환 이동 차원의 크기를 1로 설정한 형태다.

|  |  |  |
| --- | --- | --- |
| **구분** | **BB** | **GB** |
| 순환 이동 변수 | x, y | 실질적으로 x |
| 행렬 구성 | 두 이동 방향 | 한 이동 방향 |
| 격자 차원 | ℓ, m | ℓ, 1 |
| 설계 자유도 | 상대적으로 넓음 | 제한된 구조 |
| Walking Cat 예시 | Q70 | Q54, Q102 |

- - 두 코드 모두 기본적으로 같은 CSS 패리티 검사 행렬을 사용할 수 있다.

    - H\_X = [A | B]
    - H\_Z = [Bᵀ | Aᵀ]
  - 차이는 A와 B를 구성하는 순환 이동 구조에 있다.

**📌 왜 GB의 단순한 구조가 중요한가?**

- - Walking Cat에서는 이온을 이동시키면서 데이터 큐비트와 Ancilla를 정렬한다.
  - 이 이동 구조를 Three-ring Framework라고 부른다.
  - BB는 두 순환 변수를 사용하므로 긴 Ring, 중간 Ring, 짧은 Ring의 이동 구조를 갖는다.
  - GB는 이 중 한 순환 차원의 크기가 1이어서 해당 Ring 이동이 필요하지 않다.
  - 수학적인 코드 구조가 단순해지는 것뿐 아니라 하드웨어의 이동 경로와 배치 제약을 단순화할 여지도 생기는 것이다.
  - 다만 GB의 구조가 단순하다는 사실이 실제 SEC 시간이 반드시 짧다는 의미는 아니다.
  - Q102의 SEC는 Q70보다 시간이 더 오래 걸린다. 코드 크기와 실제 이동 스케줄까지 고려해야 하기 때문이다.

**✅ 7. 그렇다면 Q70만 BB7을 선택한 이유는?**

**📌 Q70은 논리 연산의 유연성을 추구한다**

- - Q70은 70개 데이터 큐비트를 사용해 논리 큐비트 6개를 인코딩한다.
  - 인코딩 밀도만 보면 Q102보다 낮다.
  - 대신 Q70은 논리 연산을 유연하고 빠르게 처리하는 것을 중요한 목표로 삼았다.
  - 연구진이 선택한 Q70은 6큐비트 Clifford 연산 전체를 Clifford Frame Tracking으로 지원할 수 있다.
  - 이를 통해 논리 Clifford 연산 상당 부분을 직접적인 물리 연산 대신 소프트웨어상의 Frame 변경으로 처리할 수 있다.
  - 또한 논리 Pauli 측정에 필요한 물리 연산자 Weight를 제한하도록 설계했다.
  - 이러한 특징 때문에 Q70은 메모리뿐 아니라 MEK Magic Factory에도 활용할 수 있다.

**📌 더 복잡한 BB 구조가 반드시 나쁜 것은 아니다**

- - BB는 두 개의 독립적인 순환 이동 변수를 사용하므로 코드 설계에서 더 다양한 행렬 조합을 탐색할 수 있다.
  - Q70은 이러한 설계 공간에서 연구진이 요구한 논리 연산 조건을 충족하는 코드로 선택됐다.
  - 하지만 GB로는 동일한 조건을 만족할 수 없다는 사실이 증명된 것은 아니다.
  - 정확히는 연구진이 제시한 후보 탐색과 아키텍처 설계에서 Q70이 요구조건을 만족하는 선택지였다고 이해해야 한다.

**✅ 8. Q54는 왜 GB8을 사용하는가?**

**📌 Q54의 핵심은 Strongly Transversal Hadamard**

- - Q54는 Q70이나 Q102와 설계 목적 자체가 다르다.
  - Q54는 논리 큐비트 2개를 사용하며 주로 CH2 Magic Factory에 활용된다.
  - CH2는 두 개의 논리 H 상태를 생성하고 검증하는 프로토콜이다.
  - 여기에는 물리 큐비트 전체에 Hadamard를 적용하는 연산이 두 논리 큐비트 각각의 Hadamard 연산과 정확하게 일치하는 특별한 성질이 필요하다.
  - 이를 Strongly Transversal Hadamard라고 한다.
  - Q54는 해당 성질을 만족하면서도 비교적 작은 데이터 큐비트 수와 높은 코드 거리를 확보한 코드다.

**📌 GB가 이 조건에 적합했던 이유**

- - 일부 자기직교(Self-orthogonal) BB 및 GB 코드는 물리 Hadamard를 논리 연산으로 사용할 수 있다.
  - 연구진은 이러한 성질을 가진 코드들을 탐색했다.
  - 그 결과 자기직교 GB8 코드 가운데 상대적으로 단순한 구조를 유지하면서 코드 거리 측면에서도 양호한 후보들이 발견됐다.
  - 특히 Q54는 CH2에 필요한 Strongly Transversal Hadamard 조건을 충족한다.
  - GB 전체에 이러한 성질이 자동으로 존재하는 것은 아니다.
  - Q54의 선택은 특정 GB 코드가 CH2의 연산 조건을 충족한 결과다.

**✅ 9. Q102는 왜 GB8을 사용하는가?**

**📌 Q102의 목표는 높은 메모리 밀도다**

- - Q102는 102개 데이터 큐비트에 논리 큐비트 22개를 인코딩한다.
  - 데이터 큐비트 기준 인코딩 비율은 약 21.6%다.
  - Q70의 약 8.6%, Q54의 약 3.7%보다 상당히 높다.

|  |  |  |  |
| --- | --- | --- | --- |
| **코드** | **데이터 큐비트** | **논리 큐비트** | **인코딩 비율** |
| Q70 | 70 | 6 | 8.6% |
| Q54 | 54 | 2 | 3.7% |
| Q102 | 102 | 22 | 21.6% |

- - 따라서 Q102는 대량의 논리정보를 비교적 적은 물리 큐비트에 저장하는 용도에 적합하다.
  - 그러나 높은 인코딩 비율은 논리 연산의 자유도와 반드시 함께 증가하지 않는다.

**📌 GB를 통한 구현상의 이점**

- - 연구진은 인코딩 효율과 논리 오류율을 함께 고려하며 여러 코드를 탐색했다.
  - Q102는 이 조건에서 선택된 GB8 코드다.
  - GB의 단일 순환 구조 덕분에 Walking Cat의 Three-ring Framework에서 짧은 Ring 이동이 자명해진다.
  - 이는 하드웨어 배치 제약을 줄일 수 있는 구조적 이점이다.
  - 그렇다고 GB이기 때문에 높은 인코딩 밀도가 자동으로 발생하는 것은 아니다.
  - 논문에서도 모든 BB 코드와 직접 비교해 GB가 언제나 우월하다는 결과를 제시한 것은 아니다.

**📌 Q102에서 제한되는 부분**

- - Q102는 22개 논리 큐비트에 대한 모든 Clifford 연산을 Q70처럼 자유롭게 Frame Tracking으로 처리하지 않는다.
  - 대신 접근 가능한 논리 Pauli 연산의 범위를 제한해 필요한 Cat State의 크기를 관리한다.
  - Walking Cat은 Q102에서 논리 Weight 3 이하의 Pauli 연산에 접근할 수 있도록 물리 연산자의 최대 Weight를 30으로 설정했다.
  - 이 범위에서 단일 논리 큐비트 Clifford 및 논리 SWAP을 Frame Tracking으로 처리하고, 추가적인 논리 측정을 결합해 보다 일반적인 Clifford 연산을 구현한다.
  - 결과적으로 Q102는 논리 연산의 최대 유연성보다는 메모리 효율을 우선하는 설계다.

**✅ 10. BB5 연구와 Walking Cat을 어떻게 연결해서 봐야 할까?**

**📌 두 연구는 최적화 목표가 다르다**

|  |  |  |
| --- | --- | --- |
| **구분** | **2025년 BB5 연구** | **2026년 Walking Cat** |
| 대상 | 장거리 이온 체인 | 이온 이동 기반 QCCD |
| 주요 목표 | 오류율과 Ancilla 비용의 절충 | 전체 FTQC 아키텍처 구축 |
| 게이트 실행 | 순차 실행 모델 | 대규모 병렬 실행 |
| Ancilla | 필요한 수량 최적화 | 데이터와 일대일 배치 |
| 중심 기술 | BB5·신드롬 추출 최적화 | BB·GB·Cat Factory 통합 |

- - BB5 연구에서 선택된 optimized nₐ는 Walking Cat의 기본 Ancilla 수와 같은 의미가 아니다.
  - 따라서 BB5의 Ancilla가 6개이고 Q70의 Ancilla가 70개라는 사실만으로 BB5가 더 효율적이라고 판단할 수 없다.
  - 두 연구는 서로 다른 하드웨어 모델과 서로 다른 최적화 목표를 갖고 있다.

**📌 코드 하나의 성능만으로 전체 시스템을 평가할 수 없다**

- - 실제 오류정정 컴퓨터에서는 논리 메모리 외에도 논리 측정, Magic State 생산, Cat State 검증, 이온 손실 탐지와 교체가 필요하다.
  - 따라서 전체 시스템의 효율을 비교하려면 코드의 인코딩 비율뿐 아니라 이러한 추가적인 물리 자원과 실행 시간도 함께 고려해야 한다.
  - 특히 Walking Cat에서는 Cat Factory가 각 블록의 논리 연산에 필요한 자원을 공급한다.
  - Q70, Q54, Q102의 선택도 이러한 전체 시스템 관점에서 이루어졌다.

**✅ 11. 최종 결론: 왜 하나의 코드만 사용하지 않는가?**

- - 안정자 Weight가 낮으면 안정자 검사당 게이트 수를 줄일 수 있지만 Distance가 반드시 증가하는 것은 아니다.
  - Ancilla를 늘리면 측정 병렬성을 높일 수 있지만 물리 큐비트 비용도 증가한다.
  - Distance가 높으면 더 많은 오류를 정정할 수 있지만 전체 논리 연산이 반드시 빠르거나 오류율이 무조건 낮은 것은 아니다.
  - GB의 단일 순환 구조는 코드 구성과 이온 이동 배치를 단순화할 여지가 있다.
  - Q70은 BB7 구조에서 6큐비트 Clifford 연산의 유연성과 MEK 프로토콜에 필요한 조건을 확보했다.
  - Q54는 특별한 자기직교 구조와 Strongly Transversal Hadamard를 활용해 CH2 Magic Factory를 구성한다.
  - Q102는 상대적으로 높은 인코딩 비율을 확보하고 GB의 단순한 순환 구조를 활용한다.
  - 다만 GB가 모든 조건에서 BB보다 우월하다는 의미는 아니며, Q54와 Q102가 GB인 이유도 동일하지 않다.
  - 결국 IonQ가 추구하는 방향은 Weight가 가장 낮거나 Distance가 가장 높은 단일 코드를 찾는 것이 아니라, 서로 다른 역할에 적합한 코드를 조합해 전체 오류정정 시스템의 자원과 실행 시간을 최적화하는 것이다.
  - 특히 향후 실제 대규모 하드웨어에서 검증해야 할 핵심은 코드의 수학적 Distance가 아니라, 이온 이동과 측정, 누출과 손실, 실제 논리 연산까지 포함한 종합적인 성능이다.
