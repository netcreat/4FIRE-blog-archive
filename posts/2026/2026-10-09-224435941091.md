# 구름을 뚫지 못하는 레이저로 어떻게 우주 양자통신을 할까? — Capella, Skyloom, Starlink 그리고 IonQ의 QKD 전략

**✅ 1. Capella Space의 새로운 발표 — 위성을 바꾸지 않고 더 빨라졌다**

- - 2026년 10월 8일, IonQ의 자회사 Capella Space가 흥미로운 기술 개선 성과를 공개했다.

    - <https://www.capellaspace.com/resources/optimizing-the-entire-path-from-orbit-to-delivery>
  - 이번 발표는 새로운 SAR 위성을 발사하거나 고성능 레이더를 개발했다는 이야기가 아니다.
  - 기존 위성과 지상 인프라의 통신 설정, 데이터 처리 소프트웨어, 네트워크 운영을 최적화해 영상 전달시간을 줄인 것이 핵심이다.
  - Capella가 최근 30일간 실제 촬영 데이터를 분석한 결과는 다음과 같다.

|  |  |
| --- | --- |
| **영상 촬영 후 고객 전달시간** | **전체 촬영 건 비율** |
| 2시간 이내 | 79% |
| 3시간 이내 | 93% |
| 4시간 이내 | 97% |
| 영상 1건당 평균 지상국 접속 | 1.35회 |
| 평균 촬영 데이터 크기 | 7.9GB |

- - 여기서 지연시간(Latency)은 **SAR 영상이 촬영된 시점부터 고객에게 전달되는 시점까지**를 의미한다. 고객이 촬영을 요청한 시점부터 계산한 시간은 아니다.
  - 특히 인상적인 것은 이러한 성능 개선의 상당 부분이 소프트웨어와 운영 최적화에서 나왔다는 사실이다.

**📌 기존 통신 시스템에서 무엇을 바꿨나?**

- - **MODCOD 최적화:** Modulation and Coding 설정을 변경해 전송속도와 오류율 사이의 균형을 개선했다.
  - **재전송 효율 개선:** 데이터 일부가 유실됐을 경우 전체를 다시 전송하는 대신 누락된 부분만 복구하도록 처리했다.
  - **지상국 운영 최적화:** KSAT(Kongsberg Satellite Services)와 협력하여 무선 전송 설정을 조정하고 데이터 손실을 줄였다.
  - **백홀 개선:** KSATlite는 여러 지상국에서 백홀 처리량을 두 배 이상으로 높였다.
  - **클라우드 아키텍처 개선:** 2GB에서 200GB에 이르는 데이터가 유입돼도 검증·복호화·조립 과정을 3~4분에 처리하도록 수평 확장 구조를 도입했다.
  - **SAR 처리 및 QA:** 영상 처리 알고리즘을 개선하고 품질검사를 자동화했다.
  - 다만 지상국 확장과 네트워크 처리량 증설도 병행하고 있으므로 모든 성과가 소프트웨어 변경만으로 달성됐다고 단정해서는 안 된다.

**📌 왜 재전송 감소가 그렇게 중요한가?**

- - Capella 위성은 평균적으로 궤도 한 바퀴에 약 두 차례 지상국과 통신한다.
  - 첫 번째 지상국 접속에서 데이터를 완전히 내려보내지 못하면 다음 접속을 기다려야 한다.
  - Capella에 따르면 추가 접속이 필요할 때마다 45분 이상의 지연이 발생할 수 있다.
  - 따라서 순간 전송속도를 무조건 높이는 것보다 오류 없는 유효 데이터 전송량(Goodput)을 높이는 편이 전체 전달시간을 줄이는 데 유리할 수 있다.
  - 네트워크 엔지니어 관점에서는 새로운 고속 인터페이스를 도입하지 않고도 패킷 손실과 재전송, 처리 병목을 개선해 애플리케이션 성능을 높이는 것과 유사하다.

**✅ 2. 그런데 Capella의 기존 통신은 마이크로파 아닌가?**

**📌 SAR와 X-band RF 통신**

- - Capella의 SAR(Synthetic Aperture Radar)은 마이크로파 레이더를 이용해 지표면을 관측한다.
  - 광학 카메라와 달리 야간에도 촬영할 수 있으며 구름과 악천후의 영향을 상대적으로 적게 받는다.
  - 촬영한 데이터를 지상으로 내려보낼 때는 별도의 X-band RF 통신을 이용한다.
  - X-band 역시 마이크로파 영역에 속한다.
  - 다만 레이더의 관측 신호와 영상 데이터의 다운링크 신호는 용도와 통신 체계가 서로 다르다.

**📌 문제는 전송속도뿐 아니라 지상국까지의 거리와 시간**

- - 저궤도(LEO) 위성은 초속 약 7.5km로 지구 주위를 이동한다.
  - 위성이 SAR 영상을 촬영한 직후 근처에 이용 가능한 지상국이 없다면 데이터는 위성에 저장된 채 다음 접속 기회를 기다린다.
  - Capella는 기존 지상국 중심 방식에서 이러한 대기시간이 통상 20~60분에 이를 수 있다고 설명한다.
  - 지상국 수를 늘리면 개선할 수 있지만 모든 지역에 지상국을 설치하는 것은 현실적으로 불가능하다.
  - 그래서 등장하는 기술이 OCT(Optical Communications Terminal), 즉 광학통신 단말기다.

---

**✅ 3. Skyloom의 OCT — 레이저로 위성끼리 직접 통신한다**

- - OCT는 RF 대신 레이저를 이용해 데이터를 전송하는 장비다.
  - Capella의 Acadia-10에는 이미 Mynaric의 OCT가 탑재돼 있으며, 2026년 6월 기준 최대 2.5Gbps급 궤도상 통신 시험을 준비하고 있었다.
  - Capella는 2027년부터 차세대 Acadia 위성에 IonQ 계열사 Skyloom의 OCT를 도입할 계획이라고 밝혔다.
  - 여기서 가장 중요한 것은 단순한 전송속도 증가가 아니다.
  - **위성이 지상국을 만날 때까지 기다리는 구조를 우주 중계망으로 바꿀 수 있다는 점**이다.

**📌 기존 RF와 미래 OCT 구조 비교**

|  |  |  |
| --- | --- | --- |
| **구분** | **기존 Capella RF** | **미래 OCT 중계망** |
| 주된 전송 수단 | X-band RF | 위성 간 레이저 |
| 중계 방식 | 위성 → 지상국 | 위성 → 중계 위성 → 지상 |
| 지상국 접속 대기 | 필수 | 중계망 구성에 따라 감소 |
| 대기 구름 영향 | 상대적으로 작음 | 위성 간 구간은 거의 없음 |
| 최종 지상 전송 | RF | RF 또는 광통신 |
| 개발 단계 | 실제 상용 운용 | OCT 시험 및 중계망 통합 확대 |

- - 광학 위성 간 링크가 확보되면 SAR 위성은 지상국 가시권에 들어갈 때까지 기다리지 않고 데이터를 다른 위성에 넘길 수 있다.
  - 그 중계 위성은 다시 다른 위성에 전달하거나 적절한 지상 게이트웨이로 내려보낼 수 있다.
  - 충분한 광학 중계망과 지상 인프라가 구축된다면 기존 수 시간의 전달시간을 수 분 단위로 줄이는 것이 장기적인 목표다.
  - 다만 현재 2.5Gbps급 OCT 시험과 수 분 단위의 상용 SAR 전달 시스템은 구분해야 한다. 후자는 아직 네트워크 구성과 운영 성능의 검증이 필요하다.

**📌 이번 소프트웨어 개선과 OCT를 결합하면?**

- - OCT는 위성에서 지상 네트워크까지 데이터를 보내는 과정에서 대기시간과 전송 병목을 줄이는 역할을 한다.
  - 이번에 개선한 클라우드 데이터 처리와 SAR 영상 생성, 자동화된 QA는 광학 중계망을 도입하더라도 여전히 필요하다.
  - 다만 X-band RF용 MODCOD 설정을 광학 링크에 그대로 적용할 수는 없다. 광학 링크는 자체적인 변조·오류정정·추적 기술을 필요로 한다.
  - 결국 기존 소프트웨어 개선과 새로운 OCT 하드웨어는 상호 보완 관계에 있다.

**✅ 4. 그런데 레이저는 구름을 통과하지 못하지 않나?**

- - 바로 여기서 중요한 의문이 생긴다.
  - 광학통신은 일반적으로 RF보다 높은 데이터 전송률을 지원할 수 있지만, 레이저가 지구 대기를 통과할 때 구름과 안개, 대기 난류의 영향을 크게 받는다.
  - 특히 두꺼운 구름은 광학 링크를 사실상 차단할 수 있다.
  - 하지만 우주 공간은 다르다.

**📌 위성 간 광통신과 위성–지상 광통신은 다르다**

|  |  |  |
| --- | --- | --- |
| **구분** | **위성 ↔ 위성** | **위성 ↔ 지상** |
| 통신 방식 | Optical ISL | Optical Downlink |
| 대기 통과 | 거의 없음 | 필요 |
| 구름 영향 | 거의 없음 | 매우 큼 |
| 주요 문제 | 레이저 정렬·추적 | 구름·안개·대기 난류 |
| 주요 대응책 | 추적 및 경로 최적화 | 지상국 다변화·RF 백업 |

- - 위성 간에는 대기가 거의 없으므로 구름 때문에 레이저가 차단되는 문제가 없다.
  - 반면 지상에 광학 신호를 직접 전송하려면 대기를 통과해야 한다.
  - 따라서 위성 간 링크는 레이저로 구성하고 최종 지상 통신은 RF를 이용하는 혼합형 아키텍처가 매우 실용적이다.

**✅ 5. Starlink는 이미 이 문제를 어떻게 해결했을까?**

- - SpaceX의 Starlink가 좋은 사례다.
  - Starlink는 지구 전역에 수많은 저궤도 위성을 배치하고, 위성 간에는 레이저를 이용해 데이터를 교환한다.
  - 기존에 공개된 Starlink 기술 자료에 따르면 위성 한 기에는 최대 200Gbps를 지원하는 광학 ISL 세 개가 탑재된다.
  - 차세대 V3 위성 설계에는 400Gbps급 광학 링크 여섯 개가 제시됐다. 이는 세대별 설계 사양을 구분해 봐야 하는 수치다.

**📌 Starlink의 핵심은 Optical Mesh Network**

- - 위성 A가 지상 게이트웨이와 직접 통신하기 어려운 위치에 있다고 가정하자.
  - 위성 A는 레이저를 이용해 위성 B에 데이터를 보낸다.
  - 위성 B는 다시 위성 C로 전달할 수 있다.
  - 마지막 위성이 이용 가능한 지상 게이트웨이와 RF로 통신해 데이터를 지상 네트워크에 전달한다.
  - 따라서 우주에서는 레이저의 높은 데이터 전송 능력을 활용하고, 지상에서는 상대적으로 날씨에 강한 RF를 사용한다.
  - 지상 게이트웨이가 악천후의 영향을 받을 때는 다른 이용 가능한 게이트웨이로 우회하는 구조도 가능하다.
  - 단, RF도 폭우와 같은 악천후에서는 감쇠가 발생하므로 날씨 영향을 완전히 제거하는 것은 아니다.

**📌 Capella와 Starlink의 차이**

- - Starlink는 자체적으로 대규모 위성 간 광학 Mesh Network를 운용한다.
  - Capella는 SAR 영상 수집 위성을 보유하고 있으며 광학 중계망을 이용할 수 있는 능력을 확대하는 단계다.
  - Skyloom은 OCT를 공급할 수 있지만, OCT 자체가 대규모 중계 위성망을 의미하지는 않는다.
  - Capella가 Starlink처럼 작동하려면 호환 가능한 위성 중계망, 충분한 중계 용량, 지상 게이트웨이 및 네트워크 운용 체계가 필요하다.

**✅ 6. 그렇다면 위성 QKD는 어떻게 성공했을까?**

- - 여기서 또 하나의 의문이 생긴다.
  - **일반 레이저 통신조차 구름의 영향을 받는다면, 양자 상태가 훨씬 민감한 QKD는 어떻게 지상과 위성 사이에서 성공했을까?**
  - 답은 의외로 단순하다.
  - 구름을 통과하는 기술을 개발한 것이 아니라, 구름이 없을 때 양자광을 전송한 것이다.

**📌 중국의 묵자호(Micius) QKD 실험**

- - 중국은 2016년 묵자호 양자과학위성을 발사했다.
  - 2017년에는 위성에서 지상까지 최대 약 1,200km 거리의 양자키분배(QKD)를 성공적으로 입증했다.
  - 이 실험에서는 약 850nm 파장의 광자를 이용한 Decoy-State BB84 방식이 사용됐다.
  - 연구진은 약 kHz 수준의 보안키 생성률을 달성했다고 Nature에 발표했다.

**📌 실제 실험 과정**

- - **1단계 — 날씨 확인:** 지상 광학관측소의 구름과 기상 조건을 확인하고 실험 가능한 통과 시간을 선정했다.
  - **2단계 — 위성 추적:** 지상 광학망원경과 위성이 서로의 위치를 정밀하게 추적했다.
  - **3단계 — 양자광 전송:** 위성은 편광 상태에 정보를 부호화한 매우 약한 레이저 펄스를 지상으로 전송했다.
  - **4단계 — 광자 검출:** 지상에서는 단일광자 수준의 검출 시스템으로 수신 신호를 측정했다.
  - **5단계 — 키 생성:** 고전 통신 채널을 이용해 필요한 정보를 교환하고 오류정정 및 프라이버시 증폭을 수행했다.
  - 이 과정을 통해 두 장치가 공유하는 비밀 암호키를 생성했다.

**📌 왜 밤에 실험했을까?**

- - 묵자호는 특정 지상국에 대해 야간에 약 5분 정도의 통신 기회를 확보하는 궤도를 활용했다.
  - 야간에는 태양광에 의한 배경 광자 잡음을 줄일 수 있다.
  - 여기에 맑은 하늘과 정밀한 레이저 추적 기술을 결합했다.
  - 중요한 사실은 **묵자호가 24시간 연속으로 QKD를 제공한 것이 아니라 제한된 시간과 날씨 조건에서 성공했다는 점**이다.
  - 따라서 이 실험의 의미는 전천후 상용 운용을 달성했다는 데 있지 않고, 위성–지상 간 양자키분배가 물리적으로 가능하다는 사실을 입증했다는 데 있다.

---

**✅ 7. 구름이 끼면 QKD는 중단되는가?**

- - 해당 지상국과 위성 사이의 양자광 링크가 두꺼운 구름으로 차단되면, 그 링크를 통한 신규 QKD 키 생성은 사실상 중단된다.
  - 이것은 현재의 위성 QKD에서 매우 중요한 제약이다.
  - 하지만 QKD가 중단된다고 기존의 모든 암호화 통신까지 중단되는 것은 아니다.

**📌 방법 1 — 광학 지상국 다변화**

- - 여러 지역에 광학 지상국(Optical Ground Station, OGS)을 설치한다.
  - 지상국 A에 구름이 끼면 맑은 지역에 있는 지상국 B로 전환한다.
  - 단, 지상국 B도 해당 위성의 가시권에 있어야 한다.
  - 단순히 지상국 수를 늘리는 것보다 서로 다른 기상 패턴을 가진 지역에 분산하는 것이 중요하다.

**📌 방법 2 — 암호키 저장(Key Buffering)**

- - 맑은 날 위성이 지상국과 QKD를 수행해 암호키를 생성한다.
  - 생성한 키는 안전하게 저장한다.
  - 이후 구름이 끼더라도 저장한 키를 이용해 일반 데이터 통신을 암호화할 수 있다.
  - 다만 암호키는 무한하지 않으며 키 소비율과 생성률, 보안 정책에 맞춰 관리해야 한다.
  - 특히 One-Time Pad를 사용한다면 암호화할 데이터만큼의 키가 필요하므로 상당한 키 생성 용량이 요구된다.

**📌 방법 3 — RF와 광학통신의 병행**

- - QKD용 양자광은 날씨가 허용하는 순간에 전송한다.
  - 실제 대용량 데이터는 RF 또는 일반 광학통신 네트워크로 전달할 수 있다.
  - QKD로 생성된 키를 이용해 데이터 통신 구간을 암호화하면 된다.
  - 즉, **QKD는 대용량 데이터를 직접 전송하는 기술이 아니라 통신에 사용할 암호키를 안전하게 공유하는 기술**이다.

**📌 방법 4 — 광학 지상국의 대기 보정**

- - NASA는 미국 캘리포니아 Table Mountain과 하와이 Haleakalā 등에 광학 지상국을 운영하며 통신 기술을 실험했다.
  - 이 시설들은 서로 다른 기상 조건을 활용할 수 있도록 배치됐다.
  - 또한 Adaptive Optics를 활용해 대기 난류가 광학 신호에 발생시키는 왜곡을 보정한다.
  - 그러나 Adaptive Optics도 두꺼운 구름을 투과시키는 기술은 아니다.
  - 결국 날씨에 따른 광학 링크 중단을 완전히 없애려면 지상국 다변화, 전송 일정 관리, 키 버퍼링과 다른 통신 수단의 조합이 필요하다.

---

**✅ 8. 일반 OCT와 QKD 장비는 같은 것인가?**

- - 여기서 IonQ의 Skyloom 인수를 해석할 때 주의해야 한다.
  - OCT가 레이저를 사용한다고 해서 곧바로 QKD를 지원하는 것은 아니다.

|  |  |  |
| --- | --- | --- |
| **구분** | **일반 OCT** | **QKD 시스템** |
| 목적 | 대용량 데이터 전송 | 비밀 암호키 생성 |
| 주요 광신호 | 고전 광통신 신호 | 약한 양자광 또는 얽힌 광자 |
| 수신 장비 | 고속 광수신기 | 양자 상태 측정 및 단일광자 검출 장비 등 |
| 대표 성능 지표 | Gbps | Secure Key Rate |
| 위성 간 사용 | 가능 | 추가적인 양자광학 기술 필요 |
| 대기 구름 영향 | 지상 링크에서 큼 | 지상 링크에서 큼 |

- - 두 시스템은 광학 빔 조준, 추적, 광학계, 일부 포토닉스 부품과 위성 플랫폼 기술을 공유할 가능성이 있다.
  - 그러나 QKD에는 별도의 양자광 송신기, 검출기, 프로토콜 및 키 관리 시스템이 필요하다.
  - 따라서 Skyloom의 기존 OCT를 그대로 이용해 위성 QKD가 가능하다고 해석해서는 안 된다.

**📌 Trusted Node 문제도 남아 있다**

- - 묵자호는 위성과 각 지상국 사이에서 별도의 비밀키를 생성하고 이를 이용해 먼 거리의 두 지상국이 키를 공유하도록 하는 Trusted Node 방식도 시연했다.
  - 이 구조에서는 중계 위성을 신뢰해야 한다.
  - 위성 자체를 신뢰하지 않아도 되는 얽힘 기반 QKD는 다른 구조이며 기술적 난도가 높다.
  - 따라서 IonQ가 미래에 구축할 위성 QKD 네트워크가 어떤 보안 모델을 채택할지도 중요한 확인 사항이다.

**✅ 9. IonQ가 Capella와 Skyloom을 인수한 진짜 의미**

- - IonQ는 2025년 7월 Capella Space 인수를 완료했다.
  - 2026년 1월에는 Skyloom Global 인수도 완료했다.
  - 앞서 Qubitekk, Lightsynq 등 양자 네트워킹 기업과 ID Quantique의 관련 기술도 확보했다.
  - 이들 기업의 역량을 하나의 네트워크 아키텍처로 살펴보면 흥미로운 그림이 만들어진다.

|  |  |  |
| --- | --- | --- |
| **기업** | **확보한 핵심 역량** | **미래 네트워크에서 가능한 역할** |
| Capella Space | SAR 위성·우주 플랫폼 | 지구 관측 및 우주 네트워크 플랫폼 |
| Skyloom | 자유공간 광통신·OCT | 위성 간 고속 광학 전송 |
| ID Quantique | 양자 보안·광자 검출 | QKD 장치 및 양자 보안 기술 |
| Qubitekk | 양자 네트워크·얽힘 기술 | 양자 네트워크 구성 |
| Lightsynq | 양자 인터커넥트·반복기 기술 | 장거리 양자 네트워크 확장 연구 |
| IonQ | 양자컴퓨팅 및 시스템 통합 | 양자 네트워크 전체 아키텍처 |

- - 여기서 가장 중요한 것은 개별 기업의 기술을 단순하게 나열하는 데 그치지 않는 것이다.
  - 고전 광통신과 양자통신은 서로 다른 기술이지만 광학 플랫폼, 네트워크 제어, 지상 인프라와 보안 시스템에서 상호 보완적일 수 있다.
  - IonQ가 추구하는 글로벌 양자 네트워크도 궁극적으로는 고전 통신망과 양자 통신망이 결합된 형태가 될 가능성이 높다.

**📌 앞으로 반드시 해결해야 할 문제**

- - **광학 중계망 확보:** Skyloom의 OCT만으로는 글로벌 위성 Mesh Network가 완성되지 않는다.
  - **QKD 광학 지상국:** 구름의 영향을 최소화할 수 있도록 지상국을 분산 배치해야 한다.
  - **양자광학 하드웨어 통합:** OCT와 QKD의 일부 공통 기술을 실제 우주용 하드웨어로 통합해야 한다.
  - **키 관리 시스템:** 제한된 시간에 생성한 QKD 키를 안전하게 저장하고 분배해야 한다.
  - **신뢰 구조:** Trusted Node를 활용할 것인지, 얽힘 기반 방식으로 발전시킬 것인지 결정해야 한다.
  - **기술 검증:** 실제 위성–지상 QKD의 키 생성률, 링크 가용성, 연속 운용 능력을 입증해야 한다.
  - **경제성:** QKD가 기존 암호화 기술이나 PQC(Post-Quantum Cryptography)와 비교해 추가 비용을 정당화할 만큼의 보안 가치를 제공하는지도 중요하다.

**✅ 10. 결론 — 레이저가 구름을 통과할 필요는 없다**

- - Capella의 이번 발표는 기존 하드웨어의 통신 설정과 소프트웨어 구조를 개선해 실질적인 성능 향상을 달성할 수 있음을 보여준다.
  - 앞으로 Skyloom의 OCT가 도입되면 RF 지상국 접속 대기라는 구조적 병목까지 개선할 기회가 생긴다.
  - Starlink는 이미 위성 간 광학 Mesh Network와 지상 RF 통신을 결합하는 방식의 실용성을 보여줬다.
  - 한편 중국 묵자호는 구름 없는 야간 조건에서 위성–지상 QKD가 실제로 가능하다는 사실을 입증했다.
  - 여기서 도출할 수 있는 결론은 명확하다.
  - **위성 간에는 레이저를 이용해 데이터를 효율적으로 이동시키고, 지상과의 연결에서는 RF와 광학통신을 상황에 맞게 활용하며, QKD는 날씨와 궤도 조건이 허용하는 시간에 키를 생성하는 방식이 가능하다.**
  - 물론 이것이 글로벌 QKD 네트워크의 모든 문제를 해결하는 것은 아니다. 광학 지상국, 신뢰 구조, 키 관리, 양자광학 하드웨어와 실제 네트워크 통합이라는 과제가 남아 있다.
  - 그러나 IonQ가 Capella와 Skyloom을 인수하고 Qubitekk, Lightsynq, ID Quantique의 기술까지 확보한 전략은 이러한 과제를 해결하기 위한 기술 기반을 넓히는 움직임으로 해석할 수 있다.
  - 중요한 것은 아직 실제로 완성되지 않은 글로벌 QKD 네트워크를 이미 확보한 것처럼 평가하지 않는 것이다.
  - **Capella는 데이터를 생산하고, Skyloom은 광학 네트워크로 데이터를 운반하며, 양자통신 기술은 그 네트워크에 새로운 보안 기능을 부여할 가능성이 있다.**
  - 앞으로 IonQ가 증명해야 할 것은 이 기술들을 실제 우주 네트워크에서 얼마나 안정적으로 통합할 수 있느냐는 점이다.
