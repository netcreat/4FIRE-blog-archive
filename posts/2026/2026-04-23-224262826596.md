# 이온트랩을 이용한 FTQC: Walking Cat 아키텍처 (1)- Part - Introduction and Overview

Published: 2026-04-23T19:26:08.225000+09:00

Original Naver post: https://blog.naver.com/4-fire/224262826596

---

**✅ 서론**

- - 양자컴퓨팅 산업은 오랜 기간 동안 큐비트 수(qubit count)와 게이트 충실도(fidelity)를 중심으로 발전해왔다. 더 많은 큐비트와 더 낮은 오류율이 곧 성능 향상으로 이어진다는 전제는, 특히 서피스 코드 기반 접근법에서 거의 정설처럼 받아들여져 왔다. 그러나 이러한 접근은 막대한 물리 자원과 복잡한 오류 정정 오버헤드를 요구하며, 실제로 유용한 규모의 논리 큐비트를 확보하기까지 상당한 시간이 필요하다는 한계를 동시에 드러내고 있다.
  - 이러한 배경 속에서 발표된 *Fault-Tolerant Quantum Computing with Trapped Ions: The Walking Cat Architecture*는 기존의 관점을 근본적으로 뒤흔드는 새로운 설계 철학을 제시한다. 이 논문은 양자컴퓨터를 단순히 “큐비트를 얼마나 많이 확보할 수 있는가”의 문제로 보지 않는다. 대신, **논리 연산과 리소스 생성의 분리**, 그리고 특히 **T gate를 위한 magic state 공급 체계**를 중심으로 시스템 전체를 재구성한다.
  - 핵심은 명확하다. 양자컴퓨터의 성능을 제한하는 요소는 더 이상 큐비트 수 자체가 아니라, **비클리포드 연산(T gate)을 얼마나 안정적이고 빠르게 공급할 수 있는가**에 있다는 점이다. 이를 위해 논문은 Q-block(연산)과 MEK/CH(factory)를 분리한 구조를 도입하고, 마치 산업 공정과 유사한 방식으로 리소스를 생산·소비하는 아키텍처를 제안한다. 이 구조는 단순한 최적화가 아니라, 양자컴퓨터의 스케일링 방식 자체를 “큐비트 확장”에서 “리소스 생산 능력 확장”으로 전환시키는 개념적 도약이다.
  - 특히 주목할 점은, 이 아키텍처가 단순한 이론적 제안에 그치지 않고, 트랩 이온 기반 시스템의 높은 충실도와 정밀 제어 능력을 전제로 현실적인 구현 가능성을 함께 논의하고 있다는 점이다. 이는 현재 산업에서 경쟁하고 있는 여러 접근법—포토닉 네트워킹, 마이크로패브릭 기반 QCCD, 그리고 기존 이온트랩 아키텍처—와 직접적으로 연결되며, “누가 먼저 이 구조를 실현할 수 있는가”라는 질문으로 이어진다.
  - 이 글에서는 Walking Cat Architecture가 제시하는 구조적 변화와 성능 해석을 중심으로, 기존 오류 정정 패러다임과의 차이, T gate 병목의 의미, 그리고 실제 구현 관점에서의 산업적 함의를 단계적으로 분석한다.
  - 논문의 양이 매우 방대하여 한 편에 실을 수 없어, 연재의 필요성을 느낀다.
  - 이번 글에서는 전체 내용을 요약한 후, Introduction과 Architecture Principle을 자세히 살펴보겠다.

---

**✅ 무엇을 제안하는 논문인가**

- - 이 논문은 한 줄로 요약하면:

    - **이온트랩 기반에서 실제로 구현 가능한 “실용적 fault-tolerant 아키텍처”를 제시한 설계서**
  - 단순한 코드 제안이 아니라:

    - 아키텍처 (전체 구조)
    - 오류정정 방식 (QEC)
    - 컴파일러
    - 디코더
    - 실제 성능 시뮬레이션
  - 까지 **end-to-end 설계**를 포함한다.

---

**✅ 핵심 개념: “Walking Cat Architecture”**

- - 이 구조의 중심은:

    - **cat state (고양이 상태)를 계속 생성해서 연산에 소비하는 구조**
  - **왜 중요한가?**

    - 기존 fault-tolerant QC:

      - logical gate 실행 = 복잡한 QEC 절차 필요
      - T-gate = 매우 비싼 연산
  - 이 논문:

    - **“cat state factory”를 중앙 자원으로 둠**
    - logical 연산을 **resource consumption 방식**으로 바꿈

> *연산을 직접 수행하는 구조 →미리 준비된 상태를 소비하는 구조*

---

**✅ 기술 핵심: LDPC 기반 QEC**

- - 이 구조는 전통적인 surface code가 아니라:

    - **LDPC (Low-Density Parity-Check) 코드 기반**
  - **특징**

    - 낮은 오버헤드
    - 높은 logical density
    - 빠른 연산 가능
  - 논문에서는 여러 설계 옵션을 제시:

    - 단일 LDPC 기반 (단순 구조)
    - 빠른 구조 (빠른 logical gate)
    - 고밀도 구조 (logical qubit 밀집)

---

**✅ 성능**

- - 논문이 강조하는 포인트:

**📌** **Dense architecture**

- - **110 logical qubits**
  - **~1 million T gates/day**
  - **단 2,514 physical qubits 사용**
  - 이건 굉장히 중요한 숫자
  - 왜냐하면:

    - 기존 surface code:
    - logical 1개 = 수천~수만 physical
    - 여기:
    - 훨씬 높은 효율

**📌** **실제 문제 해결 능력**

- - 예시:

    - Heisenberg model (100-site)
    - **~10,000 physical qubits**
    - **약 1개월 내 계산 가능**
  - 의미:

    - “classically intractable 영역 진입 가능”

---

**✅ 왜 이게 중요한가**

- - 이 논문의 진짜 포인트는 성능 숫자가 아니라:

    - **“현실적인 fault-tolerant roadmap”**
  - 논문이 강조하는 철학:

    - “이론적으로 최고 성능”이 아니라 “지금 기술로 구현 가능한 구조”
  - 즉:

    - 실험적으로 이미 가능한 요소만 사용
    - 과도한 가정 없음
    - 실제 엔지니어링 중심
  - 이건 Ion trap 계열 철학과 매우 유사

---

**✅ 기존 방식과의 차이**

**📌** **Surface code 중심 접근**

- - 안정적
  - 하지만:
  - huge overhead
  - 느린 T-gate

**📌** **Walking Cat 접근**

- - LDPC 사용
  - cat state 기반 연산
  - 높은 density + 빠른 속도
  - 핵심 trade-off:

|  |  |  |
| --- | --- | --- |
| **항목** | **Surface code** | **Walking Cat** |
| 안정성 | 높음 | 중간 |
| 오버헤드 | 매우 큼 | 낮음 |
| 속도 | 느림 | 빠름 |
| 현실성 | 검증됨 | emerging |

---

**✅ 결론**

- - 이 논문을 “한 단계 위에서” 보면:

    - **1) LDPC가 실제 아키텍처로 내려왔다**

      - → 더 이상 이론이 아니라 설계 단계
    - **2) Cat-state 기반 컴퓨팅이 본격화**

      - → resource-driven computation
    - **3) 이온트랩이 여전히 강력한 후보**

      - → high-fidelity + connectivity 활용

> *“이 논문은 fault-tolerant quantum computing을 ‘가능한 설계’ 수준으로 끌어내린 실제 엔지니어링 청사진이다.”*

---

**✅ I.Introduction**

- - 양자컴퓨터는 특정 문제에서 고전 컴퓨터를 능가할 수 있는 잠재력을 가지고 있지만, 이를 실제로 실현하기 위해서는 **오류에 강인한(fault-tolerant) 양자컴퓨팅**이 필수적이다.
  - 현재의 물리적 큐비트는 잡음과 오류에 취약하기 때문에, 신뢰할 수 있는 계산을 수행하려면 오류정정 코드(quantum error correction, QEC)를 통해논리 큐비트를 구성해야 한다.
  - 그러나 기존의 fault-tolerant 접근 방식, 특히 surface code 기반 구조는 높은 오류 임계값(threshold)과 단순한 구조라는 장점이 있지만,

    - 매우 큰 물리 큐비트 오버헤드
    - 느린 논리 연산 속도
    - 특히 T 게이트 구현 비용의 비효율성
  - 이라는 한계를 가지고 있다.

- - 이러한 한계를 극복하기 위해, 최근에는 LDPC codes 기반의 양자 오류정정 코드가 주목받고 있다.
  - LDPC 코드는

    - 낮은 오버헤드
    - 높은 논리 큐비트 밀도
    - 더 효율적인 확장 가능성
  - 을 제공할 수 있는 잠재력이 있다.
  - 하지만 실제 시스템에 적용하기 위해서는

    - 복잡한 디코딩 문제
    - 물리적 구현 제약
    - 연산 및 측정 스케줄링
  - 과 같은 여러 기술적 과제가 존재한다.

- - 본 논문에서는 이러한 문제를 해결하기 위해 “Walking Cat Architecture”라는 새로운 구조를 제안한다.
  - 이 구조의 핵심 아이디어는 다음과 같다:

    - cat state를 지속적으로 생성하는 **factory 구조**를 도입하고 이를 활용하여 논리 연산을 수행하는 방식으로 전체 fault-tolerant 연산을 구성하는 것이다.
  - 이를 통해

    - 논리 연산의 효율성을 높이고 T 게이트와 같은 비용이 큰 연산을 최적화하며 전체 시스템의 자원 사용을 줄일 수 있다.

- - 또한 본 연구는 단순한 개념 제안에 그치지 않고,

    - 실제 하드웨어 제약을 고려한 아키텍처 설계
    - 오류정정 및 디코딩 전략
    - 컴파일 및 실행 스케줄링
    - 구체적인 성능 시뮬레이션
  - 을 포함하는 **종단 간(end-to-end) 분석**을 제공한다.
  - 특히, 이온트랩 기반 시스템과의 높은 호환성을 고려하여 현실적인 구현 가능성을 강조한다.
  - 결론적으로, 이 논문은

> *fault-tolerant 양자컴퓨팅을 단순한 이론적 가능성에서 벗어나* ***실제 구현 가능한 아키텍처 수준으로 구체화하는 것을 목표로 한다.***

**📌 FTQC 아키텍처 스택**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjNfMjgy/MDAxNzc2OTMxMjQxOTQ1.zFtra9JzwrXSBBbJjg_Xhd7AyeA17UCTr-9cxrsEBjkg.ZepjRQq_hHgBqwPgwV38NP332Y0sMJMUVTpPeuiFV5cg.PNG/image.png?type=w800)](#)

- - **Applications**

    - QPE, QFT 같은 실제 알고리즘
    - 여기서는 **문제 정의 레벨**
    - 아직 “양자컴퓨터 내부 구조”와는 무관
  - **Compiler Instruction Set**

    - 알고리즘을 **논리 연산 시퀀스**로 변환
    - 특히 그림에서 강조된 것:

      - **T gate + Clifford gate 분리**
    - **의미**

      - Clifford: 비교적 쉬움
      - T gate: 매우 비쌈 (fault-tolerant의 핵심 병목)
    - 이 논문의 모든 설계는 사실상 **“T gate를 어떻게 처리하느냐”에 집중****됨**
  - **Logical Instruction Set (Logical Architecture)**

    - 오류정정된 logical qubit 레벨
    - 여기서부터 진짜 FTQC 시작
    - 논문에서 정의:

      - logical = “error-corrected qubit”
    - **핵심**

      - LDPC 코드 기반 logical layer
      - cat state가 여기서 사용됨
  - **Physical Instruction Set (Micro-architecture)**

    - logical을 실제 물리 연산으로 변환
    - QEC, 측정, 피드백 포함
    - 👉 여기서 하는 일:

      - syndrome extraction
      - decoding
      - gate scheduling
  - **Device Instruction Set (Device)**

    - 이온트랩 기준으로:
    - **QCCD (Quantum Charge-Coupled Device)**

      - 이온 이동
      - 얽힘 생성
      - 측정
    - 논문 문장 핵심:

      - device instruction = QCCD에서 가능한 물리적 동작

- - **컬럼 의미**

|  |  |
| --- | --- |
| **항목** | **의미** |
| Configuration | 아키텍처 구성 |

| T gates/day | 하루 처리 가능한 T gate |
| Physical qubits | 실제 필요한 물리 큐비트 |

- - **Configuration 해석**

    - 예:

      - 17 × Q70 + 3 × MEK
      - **의미**

        - Q70 → logical block (LDPC 코드 블록), 숫자는 코드 크기 (실제 계산을 수행하는 logical register)
        - MEK → cat state factory (magic state 생성)

          - Meier–Eastin–Knill protocol
          - Magic State Distillation 알고리즘
          - 여러 noisy |T⟩ 사용
          - Clifford 연산 + 측정 수행
          - 오류 확률 제곱으로 감소
        - CH2 → 또 다른 보조 리소스 블록

          - cat state 생성후 이를 이요해 T gate를 간접적으로 구현하는 방식
          - 다수 큐비트 얽힘 상태
          - 안정적 syndrome extraction 가능
          - multi-qubit control 가능
      - 17개 계산 블록과 3개의 T-state factory
    - “연산 블록 + 리소스 생성 블록” 조합
    - **핵심 구조**

      - Walking Cat Architecture의 본질:

        - Q-block = 계산
        - MEK / CH = 리소스 생산 (cat / magic state)
      - **CPU + 메모리 구조가 아니라 Compute + Resource Factory 구조**

> *기존에는 magic state를 개별 처리하여 속도가 느렸지만,*
>
> *Walking Cat 방식은 여러 qubit를 동시 제어함으로써 병렬 T gate처리가 가능함*

- - **성능 해석**

    - **Case 1 (효율 최적)**

      - 5 × Q102 + 1 × CH2

        - Logical: 110
        - T gates/day: 1.0M
        - Physical: 2,514
      - **2,500 physical로 110 logical (**surface code 대비 **10~100배 효율)**
    - **Case 2 (고속 모드)**

      - 17 × Q70 + 24 × MEK

        - Logical: 102
        - T gates/day: 10.4M
        - Physical: 11,847
      - 리소스를 늘리면 T gate throughput 10배 증가
      - **성능은 “큐비트 수 증가”가 아니라 “****factory 증가****”로 속도 증가**
    - **Case 3 (확장형)**

      - 34 × Q70 + 24 × MEK

        - Logical: 204
        - T gates/day: 10.4M
        - Physical: 17,000
      - 핵심:

        - logical qubit 증가 가능
        - throughput 유지 가능
  - **이 테이블이 말하는 진짜 메시지**

    - **병목은 qubit이 아니라 T gate**

      - **qubit은 충분**
      - **T gate 공급이 문제**
    - **구조 전환**

      - **기존: qubit 중심**
      - **여기:** **factory 중심**
    - **scaling 방식 변화**

      - **기존: qubit ↑ → 성능 ↑**
      - **여기:** **factory ↑ → 속도 ↑**
  - **이 논문이 전제하는 것**

    - 높은 fidelity (ion trap OK)
    - 빠른 measurement + feedback
    - cat-state 안정적 생성

**✅ II. Architecture Design Principles**

**📌 기본 설계 철학**

- - 본 아키텍처의 설계는 다음과 같은 목표를 기반으로 한다:

    - **fault-tolerant 양자컴퓨팅을 현실적으로 구현 가능한 수준으로 만드는 것**
    - 물리적 제약 조건을 고려하면서도 높은 성능과 확장성을 동시에 달성하는 것
  - 이를 위해 저자들은 단순히 오류정정 코드만 개선하는 것이 아니라, **전체 시스템 스택을 통합적으로 설계하는 접근 방식**을 취한다.

**📌 핵심 아이디어: 계층 간 일관성**

- - 양자컴퓨터는 여러 계층으로 구성되며,

    - 알고리즘
    - 컴파일러
    - 논리 구조
    - 물리 구현
  - 각 계층이 서로 강하게 연결되어 있다.
  - 따라서 특정 계층만 최적화하는 방식은 비효율적이며, 본 연구에서는 다음을 목표로 한다:

    - 모든 계층에서 일관된 설계 원칙을 유지하여 전체 시스템 효율을 극대화한다

**📌 T 게이트 중심 설계**

- - fault-tolerant 양자컴퓨팅에서 가장 큰 병목은 비-Clifford 연산, 특히 T 게이트이다.

    - Clifford 연산은 비교적 효율적으로 구현 가능하지만 T 게이트는 별도의 리소스 (magic state 등)를 필요로 하며 전체 계산 비용을 지배한다
  - 따라서 본 아키텍처는 다음과 같은 방향을 따른다:

    - **T 게이트의 생성, 정제, 소비를 중심**으로 전체 구조를 설계한다

**📌 리소스 팩토리 개념**

- - 이 설계에서는

    - 계산을 수행하는 영역과 리소스를 생성하는 영역을 분리한다
  - 특히:

    - cat state 및 magic state를 생성하는 **factory 구조**를 도입하여 필요한 시점에 고품질 상태를 공급한다
  - 이 접근 방식은 다음을 가능하게 한다:

    - 연산의 병렬화
    - T 게이트 처리량 증가
    - 전체 시스템 효율 향상

**📌 LDPC 코드 채택**

- - 기존의 surface code 대신 LDPC codes를 사용하는 이유는 다음과 같다:

    - 더 높은 logical qubit 밀도
    - 더 낮은 물리적 오버헤드
    - 더 빠른 연산 가능성
  - 하지만 LDPC 코드는 구조가 복잡하기 때문에 이를 효과적으로 활용하기 위해서는

    - 효율적인 디코딩 알고리즘
    - 안정적인 물리적 구현
    - 적절한 스케줄링 전략
  - 이 필요하다.

**📌 Cat-state 기반 연산**

- - 본 아키텍처는 cat state를 활용하여

    - 다중 큐비트 연산을 효율적으로 수행하고 fault-tolerant 게이트 구현을 단순화한다
  - 이를 통해:

    - T 게이트 구현 비용을 줄이고 병렬 연산을 가능하게 하며 전체 성능을 향상시킨다

**📌 물리적 구현 고려**

- - 이 설계는 특히 이온트랩 시스템을 염두에 두고 있다.
  - 그 이유는:

    - 높은 게이트 fidelity
    - 유연한 qubit 연결성
    - 정밀한 측정 및 제어 가능성
  - 이러한 특성은

    - LDPC 코드
    - cat-state 생성
    - 리소스 팩토리 운영
  - 과 잘 맞는다.

**📌 확장성 (Scalability)**

- - 아키텍처는 다음을 목표로 설계된다:

    - logical qubit 수 확장
    - T 게이트 처리량 확장
    - 물리 큐비트 효율 유지
  - 특히 중요한 점은:

    - 성능 확장이 단순히 qubit 수 증가에 의존하지 않고 리소스 팩토리 확장을 통해 이루어진다

> ***이 섹션은 “양자컴퓨터는 qubit이 아니라 T-gate 공급 시스템으로 설계되어야 한다”는 철학을 공식화한 부분이다.***
