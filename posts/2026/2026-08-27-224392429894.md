[Real-time decoder for a MegaQuOp quantum computer using a single CPU](https://arxiv.org/html/2608.25027v1)

**✅ 이 논문의 핵심은 단순히 decoder가 빨라졌다는 것이 아니다**

**📌 한 문장으로 요약하면**

- - 이 논문은 수백 개 logical qubit과 100만 단위 logical operation을 수행하는 trapped-ion FTQC를 가정하고, 여기서 발생하는 오류 데이터를 시뮬레이션한 뒤 실제 CPU에서 decoder를 돌려 실시간 처리가 가능한지를 검증한 연구다.
  - 가장 큰 결과는 다음과 같다.

    - 최대 408 logical qubits
    - 11,680 physical qubits에 해당하는 시스템
    - 68개 qLDPC memory block
    - 20개 magic-state factory
    - 수십만 개 T gate
    - 100만 회 이상의 logical measurement
  - 이 전체 workload의 decoding을 단일 CPU에서 실시간으로 처리할 수 있음을 보였다.
  - 사용한 장비도 별도의 FPGA, GPU cluster, ASIC 등이 아니라 **2024 MacBook Pro의 Apple M4 Max CPU**였다.

---

**✅ 다만 실제 11,680개의 trapped ion을 돌린 실험은 아니다**

**📌 Quantum hardware는 시뮬레이션이다**

- - 이 논문에서 실제로 11,680개의 physical ion으로 양자컴퓨터를 구성해 실행한 것은 아니다.
  - Quantum workload와 circuit-level noise는 시뮬레이션으로 생성했다.
  - 이 시뮬레이션을 통해 실제 FTQC가 동작할 때 발생할 syndrome과 measurement data를 만들었다.

**📌 Decoder는 실제로 돌렸다**

- - 중요한 점은 decoder 자체까지 시뮬레이션한 것은 아니라는 점이다.
  - Decoder software는 실제로 구현했다.
  - 그리고 시뮬레이션에서 생성된 데이터를 실제 M4 Max CPU에 넣고 처리했다.
  - 논문에서 제시하는 decoding latency 역시 실제 CPU wall-clock time을 측정한 값이다.
  - 따라서 이 논문의 의미는 다음과 같이 구분해야 한다.
  - Quantum hardware scalability를 증명한 연구는 아니다.
  - Classical QEC decoder scalability를 실제 CPU에서 증명한 연구다.

**✅ Walking Cat Architecture와 decoder가 서로 잘 맞는다**

**📌 단순히 decoder가 빨라서 가능한 것이 아니다**

- - 이번 결과를 단순히 Beam Search Decoder의 속도 향상으로만 보면 중요한 부분을 놓치게 된다.
  - Walking Cat Architecture 자체가 classical decoding을 쉽게 만드는 구조를 가지고 있다.

**📌 일반적인 QEC에서는 logical operation이 decoder를 복잡하게 만든다**

- - Logical operation을 실행하면 code block을 변형하거나 merge하거나 lattice surgery를 수행할 수 있다.
  - 이 경우 error model도 계속 바뀐다.
  - Decoder 입장에서는 Tanner graph나 내부 data structure를 계속 변경해야 할 수 있다.
  - 이런 과정은 latency와 memory overhead를 증가시킨다.

**📌 Walking Cat에서는 graph 자체를 유지할 수 있다**

- - Walking Cat에서는 많은 logical operation을 수행하더라도 qLDPC memory block의 기본 구조를 크게 바꾸지 않는다.
  - Walking Cat에서는 logical Pauli measurement를 수행할 때 cat-based measurement(CM)를 기존 syndrome extraction 흐름에 추가하며, 각 CM 뒤에는 ordinary SEC가 이어진다. 저자들은 이 CM+SEC 조합을 이번 논문에서 ‘cat SEC’라고 정의한다.
  - 중요한 점은 CM이 추가되어도 기존 SEC의 Tanner graph topology를 바꿀 필요가 없다는 것이다. CM에서 새로 발생하는 error mechanism이 기존 SEC의 error mechanism과 동일한 detector signature를 가지므로, Tanner graph를 재구성하는 대신 해당 error의 prior probability만 업데이트하면 된다.

**✅ Decoder를 하나가 아니라 두 종류로 나눈 것도 중요하다**

**📌 Error decoder**

- - Error decoder는 전체 syndrome을 계속 처리한다.
  - 주요 역할은 다음과 같다.

    - physical error 추적
    - error correction
    - Pauli frame 유지
  - 이 decoder는 높은 정확도가 중요하다.
  - 따라서 상대적으로 긴 decoding window와 더 강한 Beam Search 설정을 사용한다.

**📌 Outcome decoder**

- - Outcome decoder는 logical measurement가 발생할 때만 사용한다.
  - 목적은 전체 error history를 완벽하게 복원하는 것이 아니다.
  - 당장 필요한 logical measurement 결과를 빠르게 결정하는 것이 목적이다.
  - 다음 quantum operation이 measurement 결과에 따라 달라질 수 있기 때문에 latency가 매우 중요하다.

**📌 모든 decoder가 최고 정확도일 필요는 없다**

- - Cat-state measurement 자체에는 decoder만으로 제거할 수 없는 intrinsic error floor가 존재한다.
  - 따라서 Outcome decoder를 지나치게 정확하게 만들어도 실질적인 이득이 없다.
  - 필요한 수준까지만 정확도를 확보하고 latency를 줄이는 방향을 선택했다.
  - 결과적으로:

    - Error decoder는 정확도 중심
    - Outcome decoder는 latency 중심
  - 으로 역할을 분리했다.

---

**✅ Memory optimization도 이번 연구의 중요한 부분이다**

**📌 기존 방식은 memory 사용량이 컸다**

- - Beam Search Decoder는 여러 candidate를 동시에 유지한다.
  - 기존 구현에서는 각 candidate마다 Tanner graph의 많은 edge message를 저장해야 했다.
  - Decoder 수가 늘어나면 RAM 사용량뿐 아니라 cache와 memory bandwidth 부담도 함께 증가한다.

**📌 이번에는 edge message 저장을 크게 줄였다**

- - 각 edge의 message를 모두 저장하지 않고 error node의 posterior LLR 중심으로 정보를 유지했다.
  - 필요한 edge message는 필요할 때 근사적으로 복원했다.
  - 그 결과 decoder memory footprint를 10배 이상 줄였다.
  - Logical error rate는 기존 구현과 유사한 수준으로 유지했다.
  - 이 최적화가 중요한 이유는 이번 시스템에서는 하나의 decoder만 돌리는 것이 아니라 수십 개 QEC block을 동시에 처리해야 하기 때문이다.

**✅ 정말 CPU 하나로 돌렸나**

**📌 맞다. 다만 single CPU와 single core는 다르다**

- - 사용한 시스템은 2024 MacBook Pro의 Apple M4 Max다.
  - CPU는 총 16 core이며 이 가운데 12 core를 decoding에 사용했다.
  - 대략 다음과 같이 나누었다.

    - 8 cores → error decoder
    - 4 cores → outcome decoder
  - 따라서 정확한 표현은:

    - single CPU
    - 12 CPU cores
  - 이다.
  - Single core 하나로 전체 시스템을 처리했다는 의미는 아니다.

**📌 그래도 인상적인 이유**

- - 별도의 FPGA decoder가 없다.
  - GPU cluster가 없다.
  - ASIC decoder도 없다.
  - 일반 소비자용 CPU 하나에서 실행했다.

---

**✅ Real-time을 단순 평균 latency로 판단하지 않았다**

**📌 실제 FTQC schedule을 따라가며 측정했다**

- - Decoder가 syndrome을 처리하는 시간이 가끔 주어진 시간보다 길어질 수 있다.
  - 이 경우 backlog가 쌓인다.
  - 다음 decoding window가 빨리 끝나면 이 backlog를 다시 따라잡을 수 있다.
  - 하지만 logical measurement 시점까지 backlog를 처리하지 못하면 quantum computer 자체가 기다려야 한다.

**📌 이 지연을 stretch라고 부른다**

- - 예를 들어 원래 계산에 100만 syndrome extraction cycle이 필요했다고 가정한다.
  - Decoder 때문에 2,000 cycle을 추가로 기다렸다면:

    - stretch = 0.2%
  - 가 된다.
  - 즉 stretch는 decoder가 실제 quantum computation 전체 시간을 얼마나 늘리는지를 보여주는 지표다.
  - 단순히 평균 decoding latency만 보는 것보다 훨씬 현실적인 평가 방식이다.

---

**✅ 102 logical qubit에서는 1ms syndrome cycle을 사용했다**

**📌 MIPT 결과**

- - Physical CNOT error가 10⁻⁴일 때 stretch는 약 0.24%다.
  - 2×10-4에서는 약 1.12%다.
  - 3×10-4에서는 약 3.23%다.
  - 4×10-4에서는 약 6.67%다.
  - 5×10-4에서는 약 11.53%다.

**📌 의미**

- - Physical 2-qubit gate error가 약 10-4 수준이라면 decoder 때문에 발생하는 계산 지연은 사실상 매우 작다.
  - 반대로 physical error가 커질수록 decoder workload도 빠르게 늘어난다.

---

**✅** **Physical fidelity가 좋아질수록 decoder도 쉬워진다**

**📌 오류가 많으면 Beam Search가 어려워진다**

- - Physical CNOT error가 증가하면 decoder가 고려해야 하는 error candidate가 늘어난다.
  - 따라서 평균 decoding time뿐 아니라 tail latency가 크게 증가한다.

**📌 평균보다 99.9 percentile이 더 중요하다**

- - QEC는 계속 반복해서 실행된다.
  - 평균 latency가 빠르더라도 가끔 매우 느린 decoding이 발생하면 backlog가 쌓일 수 있다.
  - 따라서 fault-tolerant system에서는 평균보다 worst-case에 가까운 tail latency가 중요하다.
  - 이 부분은 이전 Beam Search Decoder 연구에서도 계속 강조됐던 내용이다.

---

**✅ 408 logical qubit 결과는 더욱 놀라워 보이지만 주의가 필요하다**

**📌 408 logical qubit에서는 stretch가 오히려 더 작다**

- - Heisenberg n266 workload에서는:

    - 10-4 error → 약 0.02%
    - 2×10-4 → 약 0.05%
    - 3×10-4 → 약 0.12%
    - 4×10-4 → 약 0.39%
    - 5×10-4 → 약 0.72%
  - 로 나타난다.

**📌 그렇다고 규모가 커질수록 decoder가 쉬워진다는 뜻은 아니다**

- - 102 logical qubit 실험에서는 syndrome extraction cycle을 1ms로 사용했다.
  - 408 logical qubit 실험에서는 5ms를 사용했다.
  - 즉 CPU가 decoding할 수 있는 시간이 5배 더 주어진다.
  - 논문은:

    - 5ms → near-term trapped-ion timescale
    - 1ms → 장기적인 faster trapped-ion timescale
  - 로 설명한다.
  - 따라서 정확한 해석은:

    - 408 logical qubit / 88 block architecture가 5ms syndrome cycle에서는 single CPU로 충분히 처리 가능했다.
  - 이다.

---

**✅ 이 부분에서 trapped ion의 구조적 장점이 나온다**

**📌 Superconducting에서는 decoder latency가 훨씬 빡빡하다**

- - Superconducting quantum computer는 syndrome cycle이 microsecond 수준으로 매우 빠르다.
  - Classical decoder가 판단할 수 있는 시간도 매우 짧다.
  - 그래서 FPGA, GPU, TPU, ASIC 같은 dedicated hardware가 필요해질 가능성이 높다.

**📌 Trapped ion은 millisecond 단위다**

- - Trapped-ion에서는 syndrome cycle이 대략 1~5ms 수준이다.
  - Classical CPU가 판단할 수 있는 시간이 훨씬 길다.
  - 그 결과 일반 CPU 기반 software decoder가 현실적인 선택지가 될 수 있다.
  - 구조적으로 보면:

|  |
| --- |
| **Superconducting**  **↓**  **μs 수준 syndrome cycle**  **↓**  **CPU가 따라가기 어려움**  **↓**  **FPGA / ASIC 가능성 증가** |

|  |
| --- |
| **Trapped ion**  **↓**  **ms 수준 syndrome cycle**  **↓**  **CPU가 처리할 시간이 충분함**  **↓**  **Software decoder 가능** |

---

**✅ 그래서 FPGA 안녕?이라는 농담이 완전히 틀린 말은 아니다**

**📌 적어도 trapped-ion MegaQuOp 단계에서는 가능성이 보인다**

- - 이번 논문은 Walking Cat + qLDPC + Beam Search Decoder 조합에서는 MegaQuOp 규모까지 dedicated FPGA decoder가 반드시 필요하지 않을 수 있다는 것을 보여준다.
  - 일반 CPU 하나로도 충분히 대응할 수 있다는 것이다.

**📌 다만 FPGA가 완전히 필요 없어졌다는 의미는 아니다**

- - 다음과 같은 경우에는 specialized hardware가 다시 필요할 수 있다.

    - 더 빠른 syndrome cycle
    - 수천 logical qubit 이상
    - 더 큰 qLDPC code
    - 훨씬 낮은 feed-forward latency
    - superconducting architecture
  - 따라서 정확한 표현은 FPGA decoder, maybe not for trapped-ion MegaQuOp. 정도가 적절하다.

---

**✅ Oxford Ionics의 99.99% gate fidelity와도 연결된다**

**📌 논문에서 사용하는 physical error range**

- - 논문에서는 physical CNOT error를 대략 10-4 ~ 5×10-4 범위로 사용한다.
  - Fidelity로 바꾸면 약 99.95% ~ 99.99% 정도다.

**📌 Oxford Ionics의 결과가 바로 이 영역에 들어온다**

- - Oxford Ionics는 electronic qubit control을 사용하면서 99.99% 이상의 2-qubit gate fidelity를 보고한 바 있다.
  - 이번 decoder benchmark에서 가장 낮은 stretch가 나오는 영역과 직접 겹친다.
  - 결국 full-stack 관점에서 보면:

|  |
| --- |
| **Oxford Ionics hardware fidelity**  **↓**  **Physical error ~10⁻⁴**  **↓**  **Walking Cat qLDPC**  **↓**  **Beam Search Decoder**  **↓**  **CPU 기반 real-time decoding** |

- - 이라는 구조가 연결된다.

**✅ 이 논문이 실제로 제거한 리스크는 classical decoding bottleneck이다**

**📌 FTQC에는 아직 해결해야 할 병목이 많다**

|  |
| --- |
| **Physical qubit**  **↓**  **Gate fidelity**  **↓**  **Ion transport**  **↓**  **Syndrome extraction**  **↓**  **QEC code**  **↓**  **Decoder**  **↓**  **Logical operation**  **↓**  **Magic-state factory**  **↓**  **Compiler**  **↓**  **Application** |

**📌 이번 논문은 이 중 decoder 문제를 상당 부분 de-risk했다**

- - 대규모 logical quantum computer가 만들어졌는데 classical decoder가 느려서 quantum computer를 계속 기다리게 하는 문제가 생길 수 있다.
  - 이번 결과는 적어도 Walking Cat 기반 trapped-ion MegaQuOp 시스템에서는 이 문제가 생각보다 크지 않을 가능성을 보여준다.

---

**✅ 이번 논문은 Walking Cat Architecture의 중요한 후속이다**

**📌 Walking Cat은 quantum-side architecture를 만들었다**

- - High-rate qLDPC를 이용해 physical/logical overhead를 낮췄다.
  - Cat measurement를 이용해 logical operation을 수행한다.
  - Clifford frame tracking을 통해 불필요한 physical operation을 줄인다.
  - Trapped-ion의 connectivity와 transport 특성을 활용한다.

**📌 이번 연구는 classical-side architecture를 추가했다**

- - 실제 FTQC를 운영하려면 quantum hardware만 있어서는 안 된다.
  - Syndrome을 실시간으로 읽고 logical error를 추적하는 classical system이 필요하다.
  - 이번 논문은 이 classical QEC layer를 commodity CPU 수준까지 구체화했다.
