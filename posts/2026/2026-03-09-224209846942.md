> 많은 사람들이 **양자 네트워크를 장비 문제**라고 생각한다.

>
> IonQ가 제시한 **Photonic Interconnect 4단계 로드맵** 역시 이러한 발전 과정을 보여준다.
>
> 초기에는 단순한 링크 연결에서 시작하지만, 점차 다수의 노드를 연결하는 **네트워크 구조로 확장**되는 것이 목표다.

**✅ Quantum Routing Protocol이란 무엇인가**

- - 클래식 인터넷에는 **라우팅 프로토콜**이 있다.
  - 대표적인 예

    - Border Gateway Protocol (BGP)
    - Open Shortest Path First (OSPF)
  - 이 프로토콜들은

    - 어떤 경로로 데이터를 보낼지
    - 어떤 링크를 사용할지
  - 결정한다.

**1️⃣ Quantum Network에서도 같은 문제가 존재한다**

- - 예를 들어 다음과 같은 네트워크가 있다고 하자.

A
/ \
B C
\ /
D

- - A와 D 사이에 **entanglement를 생성**하려면 가능한 경로가 있다.

    - A → B → D
    - A → C → D
  - 이때 **어느 경로를 통해 entanglement를 생성할지 결정하는 알고리즘**이 바로 **Quantum Routing Protocol**이다.

**2️⃣ Quantum Routing이 Classical Routing보다 어려운 이유**

- - 인터넷은 **패킷을 전송**하는 네트워크다.
  - 하지만 양자 네트워크는 **entanglement를 생성해야 한다.**
  - 그래서 고려해야 할 요소가 훨씬 많다.
  - 대표적으로 다음 요소들이 동시에 계산되어야 한다.

    - success probability
    - quantum memory lifetime
    - link fidelity
    - swapping cost

**4️⃣ Quantum Routing Protocol이 수행하는 기능**

- - Quantum routing은 **Quantum Network Software의 핵심 기능**이다.
  - 대표 기능
  - **① Entanglement Path Selection**

    - 어떤 노드를 거칠지 결정

      - A → B → D
      - A → C → D
  - **② Entanglement Generation Control**

    - 어떤 링크에서

      - 언제
      - 얼마나
    - entanglement를 생성할지 결정
  - **③ Swapping Orchestration**

    - 언제 **Bell measurement**를 수행할지 결정
  - **④ Resource Management**

    - quantum memory allocation
    - entanglement resource 관리

**5️⃣ Quantum Network Software의 역할**

- - 양자 네트워크 스택은 보통 다음과 같다.

    - Application
    - Quantum routing protocol
    - Network control software
    - Quantum hardware
    - Fiber / free space
  - Quantum Network Software가 수행하는 기능

    - entanglement routing
    - entanglement scheduling
    - repeater control
    - resource allocation
    - network orchestration

**6️⃣ 실제 연구 중인 Quantum Routing 알고리즘**

- - 대표적으로 연구되는 방식들
  - **Entanglement Gradient Routing**

    - **가장 대표적인 알고리즘**
    - 다음 metric을 기반으로 계산하여 max end-to-end entanglement rate를 찾는 알고리즘

      - fidelity
      - success probability
      - decoherence
      - swapping cost
  - **Opportunistic routing**

    - 먼저 성공한 링크를 기반으로 **동적으로 경로 결정**
    - entanglement success rate가 현저히 낮기 때문에 먼저 성공한 링크를 우선으로 고려하는 원리
  - **Fidelity-aware routing**

    - 최종 Bell pair fidelity 최대화
    - QKD network과 distributed quantum computing에서 연구됨
  - **Rate-Optimized Routing**

    - Cisco / IBM 연구에서 많이 등장함
    - entanglement generation rate 최대화
    - Bell pairs / second를 기본 metric을 사용하여 throughput routing을 목적으로 함.

**✅ Quantum Routing이 어려운 물리적 이유**

- - Quantum routing이 기존 인터넷 routing보다 훨씬 어려운 이유는 **물리 법칙 때문**이다.
  - 인터넷은 패킷을 복사하고 재전송할 수 있지만 양자 정보는 그렇지 않다.

**1️⃣ No-Cloning Theorem (복사 불가)**

- - 양자 정보는 **복사할 수 없다.**
  - 관련 개념

    - No-cloning theorem
  - 인터넷에서는 다음이 가능하다.

    - packet copy
    - packet retransmission
    - packet buffering
  - 하지만 양자 네트워크에서는 qubit copy = 불가능

|  |  |
| --- | --- |
| **네트워크** | **특성** |
| 패킷 네트워크 | 복사 가능 |
| 양자 네트워크 | 단 한번의 상태 |

- - 그래서 routing이 실패하면 **데이터 자체가 사라진다.**

****

**2️⃣ Entanglement는 “전송”이 아니라 “생성”**

- - 인터넷 routing

    - packet → 전송
  - 양자 routing

    - entanglement → 생성
  - 예

    - A — B — C
  - A와 C를 연결하려면

    - A-B entanglement 생성
    - B-C entanglement 생성
    - entanglement swapping
  - 을 수행해야 한다.
  - 즉 routing은 경로 선택 + 물리 상태 생성
  - 두 문제를 동시에 해결해야 한다.

**3️⃣ Entanglement는 오래 유지되지 않는다**

- - 얽힘은 **시간 제한**이 있다.
  - 관련 개념

    - Quantum decoherence
  - 예

    - quantum memory lifetime ≈ ms ~ sec
  - 그래서

    - A-B
    - B-C
    - C-D
    - 모든 링크가 **동시에 성공해야 한다.**
  - 이 문제는 기존 인터넷에는 존재하지 않는다.

**4️⃣ 성공 확률이 매우 낮다**

- - entanglement generation 성공률은 10-3 ~ 10-1
  - 즉, 90 ~ 99 % 실패
  - 그래서 routing은 **확률 기반 알고리즘**이 된다.
  - 예

    - 경로 1

      - A-B 0.2
      - B-D 0.3
      - success = 0.06
    - 경로 2

      - A-C 0.4
      - C-D 0.4
      - success = 0.16
  - routing은 이런 확률 계산을 수행해야 한다.

**5️⃣ Classical + Quantum 두 네트워크가 동시에 필요**

- - 양자 네트워크는 항상 quantum channel + classical channel이 동시에 작동한다.
  - 예

    - Bell measurement 결과
    - error correction
    - control signals
  - 이 정보는 **classical network**로 전달된다.
  - 그래서 routing은 classical network latency + quantum memory lifetime 을 동시에 고려해야 한다.

**1️⃣ Quantum Internet은 아직 1985년의 인터넷이다**

- - 양자 네트워크 논의는 종종 **하드웨어 경쟁**으로만 이야기된다.
  - 광자 소스, 양자 메모리, 리피터 같은 장비가 중심이기 때문이다.
  - 하지만 실제로 네트워크를 네트워크로 만드는 것은 **소프트웨어와 프로토콜**이다.
  - 현재 대부분의 양자 네트워크는 여전히 **P2P 링크 수준**에 머물러 있다.
  - 노드가 늘어나고 네트워크가 멀티포인트로 확장되는 순간,
  - 얽힘 경로를 계산하고 리소스를 관리하는 **Quantum Routing 문제**가 등장한다.

**2️⃣ Aliro의 위치**

- - Aliro Technologies 의 **AliroNet**은 이러한 네트워크를 제어하는 **SDN-유사 컨트롤러** 역할을 한다.
  - 장비를 추상화하고 네트워크를 오케스트레이션하는 플랫폼이라는 점에서 중요한 위치에 있다.
  - 하지만 Aliro가 정의하는 것은 **routing 프로토콜 자체가 아니라 그 위에서 동작하는 control layer**다.

**3️⃣ 아직 없는 것: Quantum Routing Protocol**

- - 문제는 아직 **인터넷의 BGP에 해당하는 Quantum Routing Protocol 표준이 존재하지 않는다는 점**이다.
  - Entanglement Gradient Routing, Fidelity-aware routing 같은 연구는 진행되고 있지만
  - 산업 표준으로 자리 잡은 것은 없다.
  - 그래서 지금의 양자 네트워크는
  - 어떤 의미에서는 **1985년 인터넷과 매우 비슷한 단계**에 있다.
  - 장비는 존재하지만 네트워크를 운영할 **공통 프로토콜은 아직 없는 상태**다.

**4️⃣ 앞으로의 경쟁**

- - 결국 Quantum Internet의 핵심 경쟁은 **누가 더 좋은 양자 장비를 만드는가**가 아니라
  - **누가 양자 네트워크의 소프트웨어와 프로토콜을 정의하는가** 가 될 가능성이 높다.
