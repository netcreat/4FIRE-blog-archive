**✅ 1. 비교의 출발점: 같은 연도, 같은 큐비트 종류, 같은 검증 단계**

| 2026년 현재 운영 상태 | Nighthawk r2: **물리 계산 큐비트 120개** 운영 | Tempo 운영. Superion 256은 칩 제작·첫 이온 포획을 확인한 개발 시제품 | 운영 프로세서 vs 시제품의 256을 동등한 가동 큐비트로 계산하지 않음 |

- - **같은 물리 유형:** 2027년 IBM 칩당 520개 또는 연결형 1,040개 목표와 IonQ 물리 10,000개 목표를 볼 수 있다. 다만 연결된 IBM 두 칩이 하나의 균일한 QPU와 같다고 가정해서는 안 된다.
  - **같은 논리 유형:** 2029년 IBM 200개와 IonQ 8,000개는 논리 큐비트 목표끼리 비교할 수 있으나, 동등한 논리 게이트 충실도·연산 시간·오류정정 기준이라는 증거는 없다.
  - IBM Nighthawk r2의 **458개 전체 물리 양자 요소**는 계산용 120개, 연결용 커플러 218개, 고속 리셋 소자 120개를 포함한다. 이를 IonQ의 포획 이온 수와 그대로 대조할 수는 없다. [1][5]
  - IBM Nighthawk r3의 **520개 프로그래밍 가능 큐비트**와 전체 양자 요소 2,034개는 발표된 **2027년 차세대 설계 목표**다. 2026년 11월 현재 520큐비트 시스템이 가동 중인 것은 아니다. [1]
  - 논리 큐비트(오류정정 인코딩), 논리 메모리, 논리 게이트, 내결함성 범용 계산은 서로 다른 성숙도 단계다. **“논리 큐비트 70개를 인코딩했다”와 “70개 범용 FTQC 큐비트가 실시간 오류정정한다”는 같은 뜻이 아니다.**

**✅ 3. 충실도 비교: 99.83%, 99.99%, 94.75%는 같은 숫자가 아니다**

|  |  |  |  |
| --- | --- | --- | --- |
| **측정 대상** | **IBM** | **IonQ** | **비교 판단** |
| 물리 2Q 게이트 | Nighthawk r2 `ibm\_phoenix` CZ 중앙값 99.828% (오류 0.172%) | 2025년 Oxford Ionics 계열 특정 실험 99.99%+ (오류 0.01% 미만) | 실험 조건·측정 방법·규모가 다름 |
| 1Q 게이트 / 초기화 | Nighthawk r2 SX 중앙값 약 99.9789%; 초기화 오류 약 0.0030% | 동등한 전 시스템 중앙값 별도 확인 필요 | 직접 일대일 수치 비교 불가 |
| 칩·모듈 간 상태 전달 | L-coupler 평균 99.00%, 최고 99.3% | 광 인터커넥트에서 광자 얽힘 생성·메모리 연구 | 상태전달 충실도와 얽힘률은 다른 지표 |
| 칩 간 2Q 게이트 | 원격 CZ 평균 94.75% (오류 5.25%) | 동일 프로토콜의 QPU 간 게이트 충실도 동등 수치 미확인 | 원격 연산 충실도를 별도로 확인해야 함 |
| 미래 FTQC 목표 | Starling 로컬 게이트 오류 0.01%대 초반, L-coupler 오류 0.1% 목표 | 로드맵 물리 “fidelity” 99.99%, 논리 오류 상태 <10⁻⁷/10⁻¹² | 목표 또는 다른 지표이므로 실측치로 취급 불가 |

- - IBM r2의 2큐비트 CZ 중앙 오류율은 IBM Quantum Platform의 장비별 보정 수치다. **약 99.83%**는 모든 연결의 최저 성능이나 모든 실행에서 보장되는 시스템 충실도가 아니다. 보정 시각·장비별로 변화한다. [5]
  - IonQ의 **99.99%+**는 2025년 고충실도 2큐비트 게이트 실험에서 발표한 성과다. Superion 256 전체, 향후 10K, 200만 이온이 그 충실도를 일률적으로 유지한다는 실증은 아니다. [9]
  - IBM L-coupler의 **99.0%**는 상태 전달 평균이다. 실제 **원격 CZ의 94.75%**와 구분해야 하며, IonQ의 광 얽힘 생성률과도 직접 비교할 수 없다. [10]
  - 개별 게이트 충실도 이외에도 **측정 오류·누설(leakage)·누화·이온 손실·장기 드리프트**가 오류정정의 성패를 좌우한다. 게이트 오류 임계값은 오류정정 코드와 회로 구조별로 달라진다.

**📌 99.3% 충실도 기준과 현재 원격 게이트 충실도 94.75%를 비교하면?**

- - IBM의 특정 qLDPC/Gross 계열 연구에서는 **약 99.3%의 게이트 충실도에 해당하는 오류정정 임계값(Threshold)** 이 제시됐다. 다만 이는 특정 오류정정 코드와 잡음 모델에서 도출된 기준으로, 모든 모듈 간 연결이나 논리 게이트에 동일하게 적용되는 것은 아니다.
  - 이 기준을 단순 참고하면, IBM Nighthawk r2의 칩 내부 CZ 게이트 중앙 충실도 약 99.83%는 임계값을 웃도는 반면, L-coupler를 이용한 원격 CZ 게이트의 평균 충실도 94.75%는 임계값에 크게 못 미친다. 그러나 모듈 간 연결에는 별도의 오류정정 프로토콜이나 게이트 텔레포테이션 등을 적용할 수 있으므로, 이 수치만으로 Starling의 구현이 불가능하다고 단정할 수는 없다.
  - IBM은 Starling의 **L-coupler 충실도 99.9%에 해당하는 목표**를 제시했지만, 이것이 실제 원격 CZ 게이트 충실도 99.9%를 의미하는지는 확인되지 않았다. **양자 상태 전달 충실도와 최종 원격 게이트 충실도를 구분해 검증해야 한다.****[2][10]**

**✅ 4. 오류정정 경쟁: IBM Starling qLDPC와 IonQ Walking Cat**

|  |  |  |
| --- | --- | --- |
| **비교 요소** | **IBM Starling** | **IonQ Walking Cat** |
| 기본 접근 | qLDPC 논리 메모리 + LPU + 매직 스테이트 + 범용 어댑터 | qLDPC 메모리 + 움직이는 Cat 상태 + Magic/Bell/이온 교체 팩토리 |
| 연결 모델 | C-coupler 비국소 칩내 연결; L-coupler 모듈 연결 | QCCD 기반 이온 이동·2D 배열·광 연결 |
| 코드 자원 | 연결 수 6→5, Josephson junction 5,000→2,000 설계 | 논리 블록·보조 이온·Cat/Beacon/Reservoir 포함 |
| 디코딩 | Relay-BP, 2nm ASIC 개발 | 시뮬레이션·실시간 디코딩 스택 연구 |
| 실증 단계 | 70 논리 인코딩 회로 발표; Starling QEC 모듈 통합 미완료 | 4 논리 qLDPC 메모리 break-even 조건부 실험; 대규모 FTQC 미완료 |
| 추가 검증 | C-coupler 게이트 품질, 매직 상태, 100+ L링크·크라이오 ASIC | 물리 집적 증가, 오류정정 주기, 이온 이동·팩토리 처리량·광 링크 |

- - IBM은 2026년 11월 qLDPC의 큐비트당 연결 수를 **6개에서 5개**로 줄였고, 논리 오류율이 코드/모델 비교에서 20~100배 개선될 수 있다고 제시했다. 하지만 대형 Starling 전체 칩에서 이 개선을 그대로 실측한 것은 아니다. [2]
  - IBM의 Loon은 200µs 수준 T1, 약 0.3% 로컬 게이트 오류 중앙값을 보였으며, Starling용 목표는 밀리초급 T1과 0.01%대 초반 오류다. 2nm Relay-BP 디코더 ASIC은 **개발 중**이며, Starling 전체 시스템이 조립 완료됐다는 뜻이 아니다. [2]
  - IonQ의 Walking Cat은 논리 메모리·Cat factory·Magic factory·Bell factory·Reservoir를 포함하는 전체 FTQC 설계다. 단순히 데이터 큐비트에 물리 큐비트 비율을 곱해서 전체 비용을 예측하면 보조 자원과 처리 시간이 빠진다. [11]
  - IonQ는 qLDPC 실험에서 18개 데이터 이온에 논리 4개를 인코딩했고, 일부 구성에서 물리 이온 수준과 비슷하거나 약간 나은 메모리 수명을 보고했다. 이는 **확장 가능한 실시간 내결함성 논리 회로**가 이미 동작한다는 증명은 아니다. [7]

  - IBM의 100K+ samples/s는 간단한 회로에서 측정한 높은 처리량을 뜻한다. 이를 **7,500게이트 회로를 초당 10만 번 실행한다**는 의미로 해석하면 안 된다. [1][5]
  - IonQ의 99.99% 실험 게이트 충실도를 **향후 8만 논리 큐비트 시스템에서 모든 2큐비트 게이트의 실효 충실도**로 확대 적용해서도 안 된다. [3][9]
  - 기업이 발표한 논리 오류 상태와 물리 게이트 충실도는 다른 지표이며, 논리 큐비트 수에 **오류정정 라운드·매직 스테이트 공장·연결·이온 교체**에 필요한 리소스를 추가해 총비용을 추정해야 한다.

---

**✅ 9. 최종 결론 — 누가 더 많이 만들 것인가보다 누가 먼저 실용적인 논리 연산을 보여주는가**

- - IBM은 **실운영 초전도 QPU의 빠른 처리량, 저손실 커플러, qLDPC 코드 및 디코더, 모듈형 냉각 시스템**을 동시에 발전시키고 있다. 그러나 L-coupler의 원격 CZ 94.75%와 대형 시스템의 배선·극저온 제약은 해결해야 할 과제다.
  - IonQ는 **고충실도 이온 게이트, 유연한 qLDPC 연결, EQC·SkyWater 기반 반복 제조, 광 인터커넥트**를 강점으로 내세운다. 반면 수백 이온 수준의 제품 개발에서 수만·수백만 이온 및 실제 다수 논리 연산으로 확대되는 기술적 간격이 매우 크다.
  - 2027~2028년에는 IBM의 Nighthawk r3·Starling 준비와 IonQ Superion 10K·Walking Cat의 첫 대규모 실증을 주목할 필요가 있다.
  - 2029년 이후에는 **논리 큐비트의 개수 × 오류정정 가능한 회로 깊이 × 실제 초당 논리 연산 × 운용 비용**을 함께 비교해야 한다.
  - **최종 판단:** 현재 공개된 수치만으로 어느 회사가 FTQC의 최종 승자가 될지 결정할 수 없다. IBM은 보다 구체적인 2029년 논리 연산 깊이 목표를, IonQ는 훨씬 큰 논리 큐비트 규모 목표를 제시한다. 두 회사의 경쟁력은 일정표 자체가 아니라 **그 목표의 실제 검증과 비용**에서 갈릴 것이다.

>
> ***이제 초전도의 경쟁력을 단순히 '큐비트를 많이 만들 수 있다'는 논리만으로 설명하기는 어려워 보인다.***
