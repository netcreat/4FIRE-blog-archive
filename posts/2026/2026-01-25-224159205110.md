# Microsoft, 측정 기반의 토폴로지 양자 컴퓨팅 연구를 위한 파트너십 모집

**✅ Microsoft 2026 Quantum Pioneers Program 핵심 요약**

- - **마이크로소프트의 양자 전략**

    - 목표는 *확장 가능하고 오류 허용(fault-tolerant)인 양자컴퓨터* 구축
    - 접근법은 **위상학적(topological) 양자컴퓨팅**
    - 큐비트를 국소 상태가 아닌 *물질의 전역적(topological) 성질*에 저장 → 본질적 오류 내성
  - **왜 Measurement-based Quantum Computing (MBQC)인가**

    - 게이트를 직접 제어하는 방식 대신 **얽힌 리소스 상태를 만들어 놓고 ‘측정’으로 연산 수행**
    - 실시간 제어 복잡도 ↓
    - 잡음·오류에 더 강함
    - 위상 큐비트 기반 **fault tolerance로 가는 속도를 높일 수 있음**
  - **2026 Quantum Research Pioneers Program (QuPP)**

    - 측정 기반(topological + MBQC) 양자컴퓨팅 연구를 가속하기 위한 학계 지원 프로그램
    - 최대 **20만 달러** 연구비 지원
  - **주요 연구 주제**

    - 위상 큐비트 동역학 시뮬레이션
    - MBQC용 측정·판독·제어 기술
    - MBQC에 최적화된 오류 정정 및 컴파일
    - 초기 fault-tolerant / NISQ 실험
    - 측정 기반 QCVV(검증·검증·검증)
  - **일정**

    - 접수: 2025.11.15 ~ 2026.01.31
    - 결과 발표: 2026.03.15
    - 연구 기간: 2026.08 ~ 2027.07 (12개월)
  - **핵심 메시지 한 줄 요약**

> *마이크로소프트는* ***위상 큐비트 + 측정 기반 연산****을 통해*
>
> *게이트 기반을 우회하고 처음부터 fault-tolerant를 전제로 한 양자컴퓨팅을 노린다.***

**✅ 이게 왜 중요한가?**

**📌** **“Measurement-based Topological QC”를 공개적으로 전면화**

- - 지금까지 MS는:

    - Majorana
    - Topological qubit
    - Fault tolerance
  - 이 정도 키워드는 던졌지만, “어떻게 계산하느냐”는 꽤 조심스러웠음.
  - 이번엔 아예 명시함:

    - **Measurement-based quantum computing (MBQC)**
  - 즉,

    - 게이트를 직접 때려서 제어하는 방식 ❌
    - **미리 얽힌 자원 상태 + 측정으로 계산** ⭕
  - → **제어선·펄스·타이밍 지옥을 피하겠다는 선언**

****

**📌** **MS의 현실적 고민이 그대로 드러남**

- - 연구 주제를 보면 의도가 보임:

    - measurement-based **readout & control**
    - measurement-aware **QEC & compilation**
    - **early fault-tolerant experiments**
  - 이건 곧:

    - “NISQ 쇼는 관심 없다. 처음부터 Fault-Tolerant로 가는 실험만 하자”
  - IonQ, IBM, Google이:

    - 중간 성능 경쟁
    - logical qubit 숫자 마케팅
    - 하는 동안
  - MS는 “FT로 가는 계산 패러다임”을 먼저 굳히는 중.

**📌** **위상 큐비트의 약점을 정면 돌파하려는 전략**

- - Topological qubit의 약점은:

    - 만들기 어렵다
    - 제어가 느리다
    - 측정이 까다롭다
  - 그래서 MS의 해법은:

    - “제어를 줄이고, 측정으로 모든 걸 하자”
  - 이건

    - photonic MBQC와 철학적으로 같은 계열이지만, **기반 물질은 topological matter**
  - 즉:

    - **물리적으로 튼튼**
    - **논리적으로 단순**
  - 을 동시에 노림.

**📌** **학계에 주는 메시지 (이게 진짜 핵심)**

- - 이 프로그램은 단순 연구비가 아님.

    - “우리는 이 길로 간다. 같이 갈 사람은 지금 합류해라.”
  - 20만 달러는 크지 않음
  - 대신 **Microsoft Quantum 내부와 정렬(alignment)** 기회 제공
  - → 2~3년 뒤:

    - 이 주제로 논문 쌓인 그룹 = MS 생태계
    - 자연스럽게 **Azure Quantum / MS stack에 흡수**

**✅ Measurement-based QC vs Gate-based QC**

**📌 기본 발상부터 다르다**

- - **Gate-based QC (전통적 방식)**

    - 회로를 실행한다
    - 큐비트에 **게이트 펄스**를 순차적으로 적용
    - X, Y, CNOT, CZ 같은 연산을 시간축 위에서 수행
    - 계산 = **제어의 연속**
    - 고전 컴퓨터의 논리 회로 사고방식과 유사
  - **Measurement-based QC (MBQC)**

    - 이미 계산은 준비돼 있고, 측정만 한다
    - 먼저 **거대한 얽힘 상태 (resource state / cluster state)** 생성
    - 계산은 **측정 순서 + 측정 방향**으로 진행
    - 계산 = **측정의 연속**
    - 계산이 “실행”이 아니라 “소비”되는 개념

**📌 계산 흐름 (시간 구조)**

- - **Gate-based**

    - |ψ⟩ → U1 → U2 → U3 → … → 측정
    - 오류는 매 게이트마다 누적
    - 타이밍·펄스 정확도에 민감
  - **Measurement-based**

    - |Cluster State⟩ → (측정 1) → (측정 2) → (측정 3) → 결과
    - 연산은 **측정 각도**에 인코딩
    - 측정 결과에 따라 다음 측정 보정 (feed-forward)

**📌 물리 제어 복잡도 차이 (이게 제일 큼)**

- - **Gate-based의 현실**

    - 각 큐비트마다:

      - 고속 제어선
      - 정밀 펄스
      - cross-talk 억제
    - 큐비트 ↑ → 배선·전자장치 ↑ → 열·노이즈 ↑
    - 👉 **Scaling wall의 근본 원인**
  - **Measurement-based의 장점**

    - 핵심 제어는:

      - **얽힘 생성 단계 (초기 1회)**
      - 이후는 **측정만 반복**
    - 제어 파라미터 수가 급감
    - 👉 **제어를 “한 번에 몰아서” 처리**

****

**📌 에러 모델 & 오류 보정 (FT 관점)**

- - **Gate-based + Surface Code**

    - 에러 발생 위치:

      - 게이트 중
      - 대기 중
      - 측정 중
    - 오류 보정:

      - 연속적인 syndrome 측정
      - 깊은 회로 필요
    - 📌 논리 큐비트 1개 = 물리 큐비트 수백~수천
  - **MBQC + Topological Codes**

    - 에러가:

      - resource state 품질에 크게 의존
    - 계산 중 추가 오류 유입 ↓
    - **에러 보정과 계산이 구조적으로 결합**
    - 📌 위상적 보호 + 측정 = 자연스러운 FT

**📌 확장성 (100k~1M 큐비트 관점)**

|  |  |  |
| --- | --- | --- |
| **항목** | **Gate-based** | **Measurement-based** |
| 제어선 | 큐비트 수에 비례 | 얽힘 생성 시 집중 |
| 실시간 제어 | 매우 복잡 | 단순 |
| 병렬성 | 제한적 | 매우 높음 |
| 하드웨어 복잡도 | 큐비트↑ → 폭증 | 완만한 증가 |

- - 👉 **초대형 시스템에서는 MBQC가 구조적으로 유리**

****

**📌 어떤 플랫폼이 어디에 잘 맞나?**

- - **Gate-based가 강한 플랫폼**

    - Superconducting (IBM, Google)
    - Trapped Ion (IonQ)
    - 👉 **중소 규모, 높은 게이트 정밀도**
  - **Measurement-based가 강한 플랫폼**

    - Photonic QC (PsiQuantum)
    - Neutral atom (cluster-style)
    - **Topological qubit (Microsoft)**
    - 👉 **FTQC, 초대형 확장**

****

**📌 Microsoft가 MBQC를 택한 이유 (핵심)**

- - Topological qubit의 특성:

    - 생성: 어려움
    - 제어: 느림
    - **측정: 비교적 명확**
  - 그래서 MS의 전략:

    - “게이트로 괴롭히지 말고 측정으로 계산하자”
    - 제어 부담 ↓
    - 위상 보호 극대화
    - FT 진입점 명확

**📌 한 문장 요약**

- - **Gate-based QC**

    - → *정밀 제어의 예술* (하지만 스케일이 고통)
  - **Measurement-based QC**

    - → *구조 설계의 승부* (초대형·FT에 유리)

**✅ 현실적인 가능성**

**📌 방향을 바꾼 이유**

- - Microsoft는 2005년부터 20년동안 Majorana를 연구했지만, 이렇다할 연구성과를 내지 못한채 갑자기 연구의 방향을 바꿨다.
  - **기존 Microsoft topological 접근의 문제**

    - Braiding 기반 연산:

      - 느림
      - 실험적으로 매우 까다로움
      - 대규모 시스템에선 제어 복잡도 ↑↑
  - **Measurement-based 접근의 의미**

    - **braiding을 물리적으로 하지 않아도**

      - 측정 순서 + feedforward로
      - 같은 논리 연산을 구현 가능
    - 즉:

      - “Topological protection은 유지하면서 제어 난이도는 대폭 낮추자”
  - 이건 **방향 전환이 아니라** “같은 물리 기반 위에서 계산 모델을 바꾼 것”

**📌 그럼 실현 가능성은 어느 정도냐?**

|  |  |
| --- | --- |
| **단계** | **가능성** |
| Majorana mode의 실재성 | ✅ **높음** (실험적 증거 누적 중) |
| 안정적 topological qubit | ⚠️ **중간** |
| measurement-only 논리 연산 | ⚠️ **중간~높음** |
| 수백~수천 logical qubit | ❌ **아직 낮음** |
| 2030년대 실용 FTQC | ❌ **불확실** |

- - 👉 **5년 안에 상용? 거의 불가**
  - 👉 **10~15년 스팬의 장기 베팅**임

**📌 그런데도 Microsoft가 이걸 계속 미는 이유**

- - 여기서 핵심은 “이기면 독점”.
  - **성공 시 파급력**

    - Surface code 필요 qubit 수 ↓↓↓
    - 에러율 요구치 ↓
    - 크라이오 배선·제어 폭발 문제 ↓
    - 경쟁사(IBM, Google) **전체 아키텍처 리셋**
  - 그래서:

    - 성공 확률 20~30%라도
    - 성공 시 payoff가 10배 이상
  - Big Tech다운 베팅 구조임.

**📌 투자·산업 관점에서 한 줄 정리**

- - **단기 승자**: IBM, Quantinuum, IonQ, QuEra
  - **장기 리셋 카드**: Microsoft (성공 시 게임 체인저)
  - **Microsoft 양자는**

    - 2020년대: *조용함*
    - 2030년대: *폭발하거나, 완전히 접거나*
