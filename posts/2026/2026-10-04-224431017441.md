# NSA의 국가안보시스템 전환과 새로운 투자 기회

---

**✅ 양자컴퓨터가 등장하기 전에 보안망부터 바꾼다**

- - 2026년 10월 1일, 미국 국가안보국(NSA)이 양자컴퓨터의 위협으로부터 국가안보시스템(NSS)을 보호하기 위한 새로운 발표를 내놓았다.

    - <https://www.nsa.gov/Press-Room/Press-Releases-Statements/Press-Release-View/Article/4615285/nsa-announces-post-quantum-cryptography-measures-to-safeguard-national-security/>
  - 발표의 핵심은 2027년부터 도입되는 신규 상용 국가안보시스템에 양자내성암호(PQC) 지원을 요구하고, 이를 지원하지 못하는 기존 시스템은 2030년까지 단계적으로 퇴출한다는 내용이다.
  - 하지만 이를 새로운 정책이라고 보기는 어렵다. 미국 정부는 이미 2022년부터 NSS의 PQC 전환을 추진했고, 올해 6월에는 행정명령 14412까지 발표했기 때문이다.

**✅ 1. 6월 행정명령이 있었는데 NSA는 왜 다시 발표했을까?**

**📌 미국 정부의 PQC 전환은 두 갈래로 진행된다**

- - 2026년 6월 22일 발표된 행정명령 14412는 미국 정부의 PQC 전환을 가속화하기 위한 정책이다.
  - 다만 미국의 일반 연방정부 시스템과 군사·정보기관에서 사용하는 NSS는 별도의 관리체계로 운영된다.

|  |  |  |
| --- | --- | --- |
| **구분** | **일반 연방정부 시스템** | **NSS** |
| 주요 정책·감독 | OMB 및 국가사이버국장 | CNSS 정책 및 NSA의 기술적 관리 |
| 기술표준 | NIST 중심 | NSA CNSA 2.0 중심 |
| 실행 책임 | 각 시스템 운영기관 | 각 NSS 소유·운영기관 |
| 주요 전환 기준 | OMB M-26-15 | CNSSP-15 |
| 최종 목표 | 2035년까지 단계적 전환 | 2035년까지 양자내성 확보 |

- - 여기서 NSS는 조직이 아니라 특정한 국가안보 임무를 수행하는 정보시스템의 법적 분류다.
  - NSS에 관한 정책을 수립하는 범정부 기구는 CNSS(Committee on National Security Systems)다.
  - NSA 국장은 NSS의 National Manager로서 암호기술에 관한 특별한 권한을 행사한다.
  - 다만 NSA가 미국의 모든 군사·정보 시스템을 직접 운영하거나 교체하는 것은 아니다. 실제 시스템의 소유기관이 구축과 전환을 책임진다.

**✅ 2. NSS는 실제로 무엇인가?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDRfMTIg/MDAxNzkxMDgxOTYxMTMz.J4qcKNmZA2A-gUpYd6XTLcXOppBDSYWGZ6En3vq2c9Ag.D6ABikdHJr7O3hBrWdFgUX9X0ahgKImry9N9qHIbFtYg.PNG/image.png?type=w800)](#)

[**NSA Multi-Site Connectivity Capability Package**](https://www.nsa.gov/Portals/75/documents/CSfC%20CP%20Updates%202026/%28U%29%20Multi-Site%20Connectivity%20Capability%20Package%20v1.3.0.pdf?ver=mJWYHsX8a0wSY6bOPdCrZA==)

**📌 미국 군사·정보기관이 사용하는 국가안보 인프라**

- - NSS(National Security Systems)는 미국의 군사작전, 정보활동, 기밀통신, 무기체계 운용 등을 지원하는 정보시스템이다.
  - 평상시부터 지속적으로 운영되며, 군사적 위기나 실제 작전에서는 지휘통제와 정보 공유를 지원한다.
  - 국방부와 정보기관뿐 아니라 정부를 대신해 이러한 시스템을 운영하는 계약업체의 시스템도 일정한 조건에서 NSS에 포함될 수 있다.

|  |  |
| --- | --- |
| **대표 분야** | **실제 활용** |
| 군사 지휘통제 | 군사작전 계획 및 명령 전달 |
| 정보기관 | 기밀정보 수집·분석·공유 |
| 군사통신 | 시설과 작전부대 간 보안 통신 |
| 무기체계 | 무기체계에 필수적인 정보처리 및 통신 |
| 방위산업 | 정부의 군사·정보 임무를 위한 시스템 개발·운용 |

**📌 SIPRNet, JWICS, NIPRNet은 무엇인가?**

|  |  |  |  |
| --- | --- | --- | --- |
| **네트워크** | **네트워크 공식명** | **보안등급** | **주요 용도** |
| NIPRNet | Non-classified Internet Protocol Router Network | 비기밀 | 군의 비기밀 업무와 정보 교환을 지원하는 네트워크  민감하지만 기밀로 지정되지 않은 정보도 취급할 수 있음 |
| SIPRNet | Secret Internet Protocol Router Network | SECRET | 미 국방부의 기밀 네트워크로, 인가된 사용자가 SECRET 수준의 작전 정보와 문서를 교환 |
| JWICS | Joint Worldwide Intelligence Communications System | TOP SECRET / SCI | 미국 정보공동체에서 고도의 기밀정보와 SCI(Sensitive Compartmented Information)를 처리하고 공유 |

- - SIPRNet과 JWICS는 NSS에 속하는 대표적인 기밀 네트워크를 이해하기 좋은 사례다.
  - 그렇다고 NSS가 반드시 기밀정보만 처리하는 것은 아니다. 기밀로 지정되지 않았더라도 국가안보 임무에 필수적인 시스템이라면 NSS에 해당할 수 있다.
  - 중요한 것은 이러한 네트워크에서 데이터를 어떻게 보호하고 외부 시설까지 안전하게 전달하는가이다.

**✅ 3. RED, GRAY, BLACK 네트워크는 어떻게 다른가?**

**📌 기밀등급이 아니라 암호화 상태에 따른 구분**

- - SIPRNet이나 JWICS를 이해했다고 해서 곧바로 RED, GRAY, BLACK의 차이를 이해한 것은 아니다.
  - SECRET이나 TOP SECRET은 정보의 보안등급을 나타낸다.
  - 반면 RED, GRAY, BLACK은 NSA의 암호화 아키텍처에서 데이터의 보호 상태를 구분하는 개념이다.

|  |  |  |
| --- | --- | --- |
| **구분** | **데이터 상태** | **주요 역할** |
| RED | 암호화되지 않은 기밀 데이터 | 기밀 업무 시스템 |
| GRAY | 한 번 암호화된 기밀 데이터 | 내부·외부 암호화 계층 사이 |
| BLACK | 이중 암호화된 데이터 | 외부 전송 네트워크 |

- - 여기서 GRAY와 BLACK의 설명은 NSA의 CSfC 이중 암호화 아키텍처를 기준으로 한다.
  - SIPRNet이나 JWICS에서 기밀 데이터가 평문으로 존재하는 구간은 RED에 해당할 수 있다.
  - NIPRNet은 비기밀 네트워크이지만, 그 자체가 언제나 BLACK인 것은 아니다. 승인된 암호화 구성에서 전송망으로 활용되는 경우 BLACK 구간의 역할을 수행할 수 있다.
  - RED, BLACK 네트워크는 SDA의 NEBULA를 다루면서 잠깐 언급한적이 있다.

**📌 NSA의 이중 암호화 구조**

- - NSA의 CSfC(Commercial Solutions for Classified)는 검증된 상용 제품을 여러 보안 계층으로 조합해 기밀정보를 보호하는 프로그램이다.
  - 그중 시설 간 통신을 위한 Multi-Site Connectivity 구조는 두 개의 독립된 암호화 터널을 사용한다.
  - 실제 연결을 단순화하면 다음과 같다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDRfNzAg/MDAxNzkxMDgzMDkyNzMy.YpzeoQ1YyCVzRfZyseyZ5hk7tppUKJxUPvDjV1W9TS4g.KCh4b8_SKzrfzoCxpZzEY6eW10NrO2mhhWpp4sqJcCIg.PNG/image.png?type=w800)](#)

- - 실제 구성에서는 방화벽과 암호장비의 배치가 적용되는 CSfC 설계에 따라 달라질 수 있다.
  - Inner 암호화 터널은 시설 A의 Inner 암호장비에서 시작해 시설 B의 Inner 암호장비에서 종료된다.
  - Outer 암호화 터널은 시설 A와 시설 B의 Outer 암호장비 사이에 형성된다.
  - 따라서 BLACK 네트워크를 통과하는 데이터는 두 계층의 보호를 받는다.
  - 모바일 사용자의 경우에는 두 암호화 계층이 사용자 단말에서 시작하도록 구성할 수도 있다.

**📌 여러 보안등급을 하나의 인프라로 연결하는 경우**

- - NSA가 공개한 CSfC 키 관리 설계에는 TOP SECRET, SECRET NOFORN, SECRET Coalition 등 서로 다른 보안영역을 지원하는 사례도 등장한다.
  - 하나의 공통 Outer 암호화 인프라를 사용하면서 각 RED 네트워크에 독립적인 Inner 암호화 계층과 인증기관을 구성할 수 있다.
  - 물론 서로 다른 등급의 네트워크가 자유롭게 정보를 교환한다는 의미는 아니다.
  - 각 등급에 맞는 별도의 인증과 접근통제, 네트워크 분리가 유지돼야 한다.
  - 이러한 구조는 네트워크 장비를 공유하면서도 암호화 계층을 독립적으로 관리할 수 있다는 이점이 있다.

**✅ 4. 그렇다면 PQC는 정확히 어디에 적용되는가?**

**📌 방화벽과 광케이블을 전부 교체하는 것은 아니다**

- - PQC의 핵심은 기존 네트워크의 모든 장비를 새로운 장비로 바꾸는 것이 아니다.
  - 양자컴퓨터에 취약한 공개키 암호를 사용하는 기능을 양자내성 알고리즘으로 전환하는 것이다.
  - 앞서 살펴본 CSfC 구조에서는 Inner 및 Outer 암호화 장비가 대표적인 전환 대상이 된다.
  - 또한 각 암호화 계층의 인증기관(CA), 키 관리 시스템, 원격 사용자 단말 등 관련 구성 요소도 함께 검토해야 한다.

|  |  |
| --- | --- |
| **구성 요소** | **주요 PQC 전환 작업** |
| Inner 암호장비 | 키 설정 및 장비 인증 |
| Outer 암호장비 | 키 설정 및 장비 인증 |
| Inner CA | 양자내성 인증서·전자서명 |
| Outer CA | 양자내성 인증서·전자서명 |
| 사용자 단말 | VPN 및 인증 기능 |
| RED 내부 서버 | TLS·PKI·소프트웨어 서명 등 |
| 일반 전송 라우터 | 암호 기능이 없다면 직접적인 전환 불필요 |
| 광케이블 | PQC 도입만을 위한 교체 불필요 |

**📌 실제로 교체되는 알고리즘**

|  |  |  |
| --- | --- | --- |
| **기능** | **기존 기술의 예** | **CNSA 2.0** |
| 키 설정 | RSA, ECDH | ML-KEM-1024 |
| 전자서명 | RSA, ECDSA | ML-DSA-87 |
| 데이터 암호화 | AES-256 | AES-256 유지 |
| 해시 | SHA-384 등 | SHA-384 등 유지 |

- - ML-KEM은 양측이 안전하게 통신할 수 있도록 공유 비밀을 설정하는 데 사용된다.
  - ML-DSA는 장비와 서버의 신원을 증명하거나 소프트웨어의 무결성을 검증하는 데 사용된다.
  - AES-256처럼 데이터를 실제로 암호화하는 대칭키 알고리즘은 계속 사용할 수 있다.
  - 따라서 기존 IPsec 또는 TLS의 모든 암호화 기능을 폐기해야 하는 것은 아니다.
  - 하지만 키 설정만 교체하고 기존의 RSA·ECDSA 서명 체계를 그대로 방치한다면 완전한 전환이라고 볼 수 없다.

**📌 왜 이렇게 서두르는가?**

- - NSA가 강조하는 첫 번째 위협은 Harvest Now, Decrypt Later다.
  - 적대국이 지금 암호화된 군사통신을 수집하고, 미래에 충분히 강력한 양자컴퓨터를 확보했을 때 이를 복호화할 가능성에 대비하는 것이다.
  - 두 번째는 Trust Now, Exploit Later다. 장기적으로 사용되는 인증서와 디지털 서명에 대한 신뢰가 미래에 무너질 가능성을 고려해야 한다.
  - 따라서 암호장비뿐 아니라 인증기관, 펌웨어 서명, 소프트웨어 공급망까지 함께 전환해야 한다.

- - 일정에는 해당 CSfC 규격이나 평가 기준에서 허용하는 예외 및 승인된 면제가 적용될 수 있다.
  - 특히 2030년은 모든 장비를 무조건 교체해야 하는 날짜라기보다는 지원 불가능한 기존 장비를 퇴출하는 중요한 중간 기한이다.
  - 이미 CNSA 2.0을 지원하는 장비라면 반드시 하드웨어를 교체해야 하는 것은 아니다.

**📌 CSfC의 별도 로드맵**

- - NSA의 CSfC PQC 지침 초안에는 더욱 구체적인 계획이 담겨 있다.
  - 2026년에는 관련 기술 요구사항과 제품 평가 기준을 개정한다.
  - 2027년부터 CNSA 2.0을 지원하는 CSfC 제품의 공급을 확대한다.
  - 2028년에는 관련 제품의 CNSA 2.0 지원을 의무 요구사항으로 확대할 계획이다.
  - 2030년에는 등록된 CSfC 솔루션의 모든 암호화 계층에 CNSA 2.0 또는 승인된 양자내성 완화조치를 적용하는 것을 목표로 한다.
  - 다만 이 세부 일정은 초안에 담긴 계획이므로 공급업체의 준비 상황과 기술적 실현 가능성에 따라 변경될 수 있다.

**✅ 6. NSS의 보안체계를 교체하려면 얼마가 필요할까?**

**📌 추산된 예산은 71억 달러**

- - 미국 정부는 2024년 보고서를 통해 일반 연방기관의 우선순위 정보시스템을 2025~2035년에 PQC로 전환하는 데 약 71억 달러가 필요할 것으로 추산했다.
  - 주목할 사실은 해당 금액에 NSS가 포함되지 않았다는 점이다.
  - 따라서 미국의 전체 PQC 전환 비용을 71억 달러로 해석해서는 안 된다.
  - 더욱이 71억 달러는 확정된 조달 예산이 아니라 불확실성이 큰 초기 추정치다.

|  |  |
| --- | --- |
| **구분** | **비용** |
| 일반 연방기관 우선순위 시스템 | 약 71억 달러 |
| NSS | 공개된 전체 추정액 미확인 |
| 민간 핵심 인프라 | 별도 |
| 동맹국 및 해외 정부 | 별도 |

**📌 실제 비용은 어디에서 발생하는가?**

- - 첫째, 기존 장비를 업그레이드할 수 있는지 확인해야 한다.
  - 펌웨어나 소프트웨어 업데이트만으로 전환할 수 있다면 비용 부담은 상대적으로 작다.
  - 반면 기존 하드웨어가 새로운 알고리즘을 지원하지 못하거나 요구되는 성능을 충족하지 못하면 장비 교체가 필요하다.
  - 둘째, 기존의 인증서 발급 및 관리체계를 전환해야 한다.
  - 셋째, 새로운 암호 알고리즘을 실제 VPN, TLS, 관리 시스템 등에 통합하고 상호운용성을 검증해야 한다.
  - 넷째, 군사·정보 시스템에 요구되는 제품 평가와 운영 승인을 거쳐야 한다.

**📌 가상 네트워크 전환 비용 시나리오**

- - 예를 들어 100개 시설에 독립된 Inner·Outer 암호장비를 각각 이중화해서 설치한다고 가정한다.
  - 시설당 4대의 암호장비가 필요하다면 전체 규모는 400대다.
  - 장비당 가격을 임의로 5만 달러로 가정하면 암호장비 구매비용만 2,000만 달러가 된다.
  - 여기에 시설당 설치·통합 비용 10만 달러와 중앙 공통 시스템 구축비용 1,000만 달러를 가정하면 총 4,000만 달러다.

|  |  |
| --- | --- |
| **가상 산정 항목** | **금액** |
| 암호장비 400대 | $20M |
| 시설 설치·통합 | $10M |
| 중앙 PKI·시험·설계 | $10M |
| 합계 | $40M |

- - 이 수치는 공식 장비 가격이나 실제 사업비가 아니다. 비용이 어떤 구조로 발생하는지 이해하기 위한 임의의 계산이다.
  - 사용자 단말 교체, 유지보수, 장기 운영비, 추가 보안 인증 등은 포함하지 않았다.
  - 개별 시설을 전환하는 프로젝트와 전국적인 군사·정보 시스템을 개편하는 사업의 규모는 비교할 수 없다.
  - NSS 전체를 전환하는 데 필요한 실제 예산은 NSA와 운영기관의 향후 공개 자료를 통해 확인해야 한다.

**✅ 7. 투자자가 주목해야 할 산업은 무엇인가?**

**📌 양자컴퓨터가 등장하기 전에 매출이 발생할 수 있는 시장**

- - PQC는 양자컴퓨터 없이 기존의 컴퓨터와 네트워크 장비에서 실행되는 암호기술이다.
  - 따라서 이번 정책의 직접적인 수혜 가능성은 양자컴퓨터 제조업체보다 기존 보안 인프라를 전환하는 기업에 있다.
  - 특히 미국 정부는 이미 전환 일정을 정했기 때문에 실용적인 암호해독용 양자컴퓨터가 등장하기 전부터 관련 제품과 서비스에 대한 지출이 발생할 수 있다.
  - 투자 대상으로 볼 수 있는 산업을 전환 과정에 따라 나누어 보자.

**📌 ① 암호자산 탐색 및 관리**

- - 대규모 정부기관은 먼저 RSA, ECC 등의 암호 기술이 어디에서 사용되고 있는지 파악해야 한다.
  - 서버와 네트워크 장비뿐 아니라 애플리케이션, 인증서, 코드 서명 및 공급업체의 소프트웨어까지 조사 대상이 될 수 있다.
  - 특히 시스템 간 암호 의존성을 자동으로 탐색하고 전환 우선순위를 결정하는 기술이 중요해질 것으로 예상한다.
  - IBM과 SandboxAQ 같은 기업은 이러한 암호자산 탐색 및 양자내성 전환 분야에서 살펴볼 대상이다.
  - 다만 관련 제품의 존재가 곧 NSS 사업 수주를 의미하지는 않는다.

**📌 ② VPN·방화벽·네트워크 보안**

- - 다음 단계에서는 기존 시스템이 실제로 PQC를 지원해야 한다.
  - Cisco, Fortinet, Palo Alto Networks 등의 네트워크 보안 기업은 기존 기업·정부 고객 기반을 활용할 가능성이 있다.
  - Cisco는 2026년 IOS XE에서 기존 RSA 서명과 ML-DSA-87 서명을 결합하는 소프트웨어 이중 서명 기능을 문서화했다.
  - Fortinet 역시 FortiOS에서 PQC 기반 VPN과 인증 기능을 확대하고 있다.
  - 이러한 기술은 기존 네트워크를 전면 교체하지 않고 단계적으로 전환하려는 기관에 중요할 수 있다.
  - 다만 일반 상용 제품에서 PQC를 지원하는 것과 NSA의 CSfC 관련 요구사항 및 평가 기준을 충족하는 것은 별개의 문제다.

**📌 ③ PKI·HSM·키 관리**

- - 개인적으로 매우 중요하게 보는 부분이다.
  - 네트워크 암호장비에서 새로운 알고리즘을 지원하더라도 인증서를 발급하는 CA와 개인키를 보호하는 HSM이 이를 지원하지 못한다면 전환은 완성되지 않는다.
  - 특히 여러 기관이 사용하는 인증체계는 연결된 시스템이 많을수록 교체 작업이 복잡해진다.
  - 이 분야에서는 Thales, Keyfactor, DigiCert 등 관련 기업의 제품과 사업을 살펴볼 필요가 있다.
  - Thales는 2026년 8월 PQC 지원을 강조한 차세대 Luna 8 HSM을 발표했다.
  - 이러한 기업들은 기존 고객이 사용하는 인증 인프라를 지속적으로 업그레이드해야 한다는 점에서 관심을 가질 만하다.

**📌 ④ 클라우드와 소프트웨어 인프라**

- - PQC는 정부 전용 네트워크에 국한되지 않는다.
  - 클라우드 서비스, 웹서버 및 기업용 소프트웨어에서도 새로운 키 설정과 인증 기능이 필요하다.
  - Microsoft, IBM, Cloudflare 등도 관련 기술을 도입하거나 전환을 지원하는 기업에 해당한다.
  - 다만 이들 기업의 전체 매출에서 PQC가 얼마나 큰 비중을 차지할지는 별도로 판단해야 한다.
  - 기술적 대응 능력과 투자 대상으로서의 매력은 반드시 구분해야 한다.

**📌 투자 관점의 산업별 우선순위**

|  |  |  |
| --- | --- | --- |
| **분야** | **직접적인 관련성** | **주요 관찰 지표** |
| PKI·HSM·키 관리 | 매우 높음 | 인증체계 전환 계약 |
| VPN·네트워크 보안 | 매우 높음 | PQC 지원 제품과 장비 교체 |
| 암호자산 탐색 | 높음 | 전환 컨설팅 및 자동화 계약 |
| 시스템 통합 | 높음 | 대규모 정부 전환 사업 |
| 클라우드 | 높음 | 기존 서비스의 PQC 전환 수익화 |
| 양자컴퓨팅 | 간접적 | 별도의 컴퓨팅 사업 및 기술 성과 |
| QKD·양자통신 | 정책에 따라 상이 | 실제 도입과 정부 승인 여부 |

- - 이 표는 정책과 기술 사이의 직접적인 연관성을 평가한 것이다.
  - 기업의 경쟁력이나 예상 주가 상승률을 평가한 순위는 아니다.
  - NIST의 PQC 전환 프로젝트 참여나 기존 보안제품 인증 역시 해당 기업의 향후 정부 계약을 보장하지 않는다.

**✅ 8. 그렇다면 IonQ에는 어떤 의미가 있을까?**

**📌 PQC와 QKD는 경쟁할 수도, 공존할 수도 있다**

- - 이 부분은 양자컴퓨팅 투자자라면 반드시 구분해야 한다.
  - PQC는 기존 컴퓨터에서 수학적 알고리즘을 이용해 양자 공격에 대응하는 기술이다.
  - 반면 QKD(Quantum Key Distribution)는 양자역학적 특성을 이용해 암호키를 분배하는 기술이다.
  - 양자컴퓨터는 이러한 기술들과 또 다른 시장에 속한다.

**📌 NSA는 QKD보다 PQC를 우선한다**

- - NSA는 현재 NSS의 데이터 전송을 보호하기 위한 수단으로 QKD를 권장하지 않는다.
  - 전용 장비 및 인프라 요구사항, 실제 구현의 취약성, 운영 복잡성 및 서비스 거부 공격 위험 등을 이유로 제시하고 있다.
  - NSA는 이러한 한계가 해결되지 않는 한 NSS용 QKD 보안제품을 승인할 계획이 없다는 입장을 밝히고 있다.
  - 따라서 미국 NSS의 PQC 전환을 QKD 공급업체에 대한 대규모 발주 신호로 해석해서는 안 된다.

**📌 IonQ의 ID Quantique 인수는 어떻게 봐야 할까?**

- - IonQ는 2025년 5월 ID Quantique(IDQ)의 경영권 지분 인수를 완료했다.
  - IDQ는 QKD뿐 아니라 QRNG(양자난수생성기), 키 관리 및 양자내성 보안 기술을 보유하고 있다.
  - 특히 IDQ의 Clarion KX는 QKD와 PQC를 결합하거나 상황에 따라 별도로 사용하는 키 관리 플랫폼이다.
  - 따라서 IDQ를 순수 QKD 공급업체로만 분류하는 것은 적절하지 않다.

  - 다만 NSA 보고서가 대통령에게 제출되는 것이므로 상세 내용이 일반에 공개된다는 보장은 없다.
  - 투자자가 직접 확인할 수 있는 자료는 향후 공개되는 조달 규정, 계약 공고, 제품 인증 목록 및 기업 실적 발표가 될 가능성이 높다.

**📌 실제로 추적할 투자 지표**

- - 정부가 발표하는 PQC 관련 예산과 실제 집행액을 구분해야 한다.
  - 제품의 PQC 지원 발표뿐 아니라 NIST 표준 적합성, 암호모듈 검증 및 관련 NSA 제품 요구사항 충족 여부를 확인해야 한다.
  - 기존 고객에게 소프트웨어 라이선스를 판매하는지, 새로운 하드웨어 판매가 발생하는지 구분해야 한다.
  - 관련 기술을 보유한 기업이 실제로 얼마나 많은 계약을 확보했으며, 그 계약이 전체 매출에서 어느 정도 비중을 차지하는지 확인해야 한다.
  - 특히 정부 전환 사업은 조달 지연과 예산 변경에 영향을 받을 수 있으므로 정책 발표만으로 단기 매출을 추정하는 것은 위험하다.

**✅ 10. 결론 — 먼저 열리는 시장은 양자컴퓨터가 아니라 양자내성 보안일 수 있다**

- - 이번 NSA 발표에서 가장 주목할 점은 새로운 알고리즘이나 새로운 전환 일정이 아니다.
  - 미국은 이미 수립한 PQC 정책을 실제 제품, 보안 인프라 및 조달 절차로 연결하고 있다.
  - NSS의 전환 비용은 아직 공식적으로 공개되지 않았지만, 일반 연방기관의 우선순위 시스템에만 약 71억 달러가 필요할 것으로 추산됐다는 점은 주목할 만하다.
  - 향후 미국의 군사·정보 인프라뿐 아니라 금융, 통신, 에너지, 글로벌 방위산업 및 동맹국의 시스템까지 전환이 확대될 가능성이 있다.
  - 다만 이러한 잠재 시장 전체를 특정 기업의 매출 기회로 환산하는 것은 무리다.
  - 기술적으로는 암호장비 제조업체뿐 아니라 인증, 키 관리, 암호자산 탐색 및 시스템 통합 기업에 수요가 발생할 것으로 예상한다.
  - 반면 양자컴퓨터와 QKD 분야는 이번 정책의 직접적인 수혜 여부를 별도로 검증해야 한다.
  - 앞으로는 새로운 PQC 정책이 발표되는 횟수보다 실제로 인증을 통과한 제품, 정부가 발주한 계약 및 기업의 관련 매출이 훨씬 중요한 지표가 될 것이다.
