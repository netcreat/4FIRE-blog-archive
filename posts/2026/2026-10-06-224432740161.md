# IonQ가 안실라 큐비트를 늘리는 이유

Published: 2026-10-06T13:09:21+11:00

Original Naver post: https://blog.naver.com/4-fire/224432740161?fromRss=true&trackingCode=rss

---

**✅ 안실라는 몇 개가 필요할까? 안정자 웨이트·신드롬·병렬 계층의 관계**

- - 양자 오류정정에서 물리 큐비트를 추가로 확보하면 어디에 써야 할까?
  - 논리 정보를 담는 데이터 큐비트를 늘릴 수도 있지만, 오류를 검사하는 **안실라 큐비트**에 배정할 수도 있다.
  - 큐비트 예산이 작을 때는 소수의 안실라를 측정하고 초기화하며 여러 번 재사용한다. 필요한 검사 결과를 모두 얻을 수 있지만, 그만큼 시간이 걸린다.
  - 더 많은 큐비트를 확보할 수 있다면 여러 안정자 검사를 동시에 진행하도록 안실라를 늘릴 수 있다.
  - Q54·Q70·Q102에서 데이터 큐비트 수만큼 신드롬 추출용 안실라를 배치하는 설계는 이러한 선택을 보여준다.
  - 이 글의 핵심은 **안실라를 늘려, 여러 배치에 나누어 수행하던 검사를 한 배치에서 병렬로 끝내는 것**이다.

---

**✅ 1. 코드의 숫자와 측정 회로의 숫자는 다르다**

- - [[n,k,d]]에서 n은 데이터 큐비트 수, k는 논리 큐비트 수, d는 코드 거리다.
  - n에는 신드롬 추출용 안실라가 포함되지 않는다.
  - 코드 거리가 d이면 이상적인 복구에서 보장하는 임의의 데이터 큐비트 오류 정정 범위는 t=(d-1)/2이다.
  - 안실라를 몇 개 배치하고, 어떤 게이트를 동시에 실행할지는 측정 회로와 하드웨어 설계에서 정한다.

|  |  |
| --- | --- |
| **용어** | **의미** |
| 안정자 검사 | 여러 데이터 큐비트에 걸친 하나의 파울리 연산자 측정 |
| 안정자 웨이트 w | 그 검사에서 항등연산 I가 아닌 연산이 적용되는 데이터 큐비트 수 |
| 신드롬 | 여러 안정자 검사 결과를 모은 비트열 |
| 안실라 | 검사 결과를 얻기 위해 데이터와 상호작용한 뒤 측정하는 보조 큐비트 |
| 2Q 게이트 개수 | 실행해야 하는 2큐비트 게이트의 총량 |
| 2Q 게이트 계층 | 서로 큐비트를 공유하지 않는 게이트들을 동시에 실행하는 한 시간 단계 |
| 측정 배치 | 여기서는 안실라들을 준비하고, 담당 검사들을 수행한 뒤 결과를 읽는 한 묶음 |

- - 예를 들어 S=Z1Z3Z11Z16Z28의 웨이트는 5다.
  - 이는 안정자가 5개라는 뜻도, 안실라가 반드시 5개 필요하다는 뜻도 아니다.
  - 이 안정자 하나를 안실라 하나로 측정하는 기본 회로에서는, 안실라가 데이터 5개와 차례로 상호작용한 뒤 결과 한 비트를 출력한다.

**📌 안실라가 적어도 오류 위치를 알아낼 수 있다. 다만 결과를 모으는 데 시간이 든다**

- - 안정자 검사는 여러 데이터 큐비트의 공동 패리티를 측정한다. 기본적인 단일 안실라 회로에서는 검사 하나가 결과 한 비트를 만든다.
  - 신드롬은 이러한 검사 결과들을 모은 비트열이다. 디코더는 그 패턴을 이용해 복구 연산을 결정한다.
  - 안실라를 한 번 측정하면 결과를 고전 메모리에 저장할 수 있다. 따라서 같은 안실라를 초기화해 다음 검사에 재사용해도 앞서 얻은 결과가 사라지지 않는다.
  - 예를 들어 검사 30개에 안실라 5개를 배정하면, 한 배치에서 5개씩 결과를 얻어 6배치에 걸쳐 30개를 모을 수 있다.
  - 여기서 **측정 배치**는 안실라를 준비하고, 담당 검사에 필요한 상호작용을 마친 뒤, 결과를 읽는 한 묶음이다.
  - SEC(Syndrome Extraction Cycle)는 선택한 검사 목록 전체의 신드롬을 한 차례 추출하는 주기다. 안실라가 적으면 하나의 SEC 안에 여러 측정 배치가 들어간다.

**✅ 2. 같은 Q54에서 안실라만 늘리면 무엇이 달라질까?**

- - 안실라 수의 효과를 보려면 같은 코드와 같은 검사 목록을 유지한 채 비교하는 것이 명확하다.

    - Q54는 데이터 큐비트 54개에 논리 큐비트 2개를 담는 [[54,2,10]] 코드다. 여기서 사용하는 검사 목록은 X형 27개와 Z형 27개이며, 각 검사의 웨이트는 8이다.[2]
    - 웨이트 8은 검사 하나가 데이터 큐비트 8개와 상호작용한다는 뜻이다.
    - 따라서 신드롬을 한 차례 추출하는 데 필요한 데이터–안실라 2Q 게이트는 54×8=432개다.
  - 아래에서는 안실라를 6개, 18개, 54개 배정했을 때를 비교한다. 배치 수가 명확하게 나뉘도록 54의 약수를 골랐다.
  - **6개·18개 구성은 각 배치가 충돌 없이 8계층으로 실행된다고 가정한 설명용 비교다. 54개 구성의 8계층은 논문에 제시된 스케줄이다.** 앞의 두 구성을 실제 장비에서 측정한 결과나 내결함성을 검증한 회로로 해석하지 않는다.

|  |  |  |  |
| --- | --- | --- | --- |
| **항목** | **안실라 6개** | **안실라 18개** | **안실라 54개** |
| 데이터 큐비트 | 54 | 54 | 54 |
| 데이터 + 신드롬 안실라 | 60 | 72 | 108 |
| 한 배치에서 완료하는 검사 | 6 | 18 | 54 |
| SEC당 측정 배치 | **9** | **3** | **1** |
| 배치당 2Q 게이트 계층 | 8 | 8 | 8 |
| SEC당 전체 2Q 게이트 계층 | **72** | **24** | **8** |
| SEC당 데이터–안실라 2Q 게이트 | **432** | **432** | **432** |
| SEC당 읽는 검사 결과 비트 | **54** | **54** | **54** |
| 코드 거리 | 10 | 10 | 10 |

- - - 안실라 6개는 검사 6개를 끝낸 뒤 다음 6개를 맡는다. 이 과정을 9배치 수행한다.
    - 안실라 54개는 검사 54개를 하나씩 맡아 동시에 진행한다. 모두 8번의 상호작용을 마친 뒤 함께 측정한다.
  - 이 비교에서는

    - **데이터와 신드롬 안실라의 합을 60개에서 108개로,** **1.8배 늘려서,**

      - **108/60=1.8**
    - **게이트 계층과 측정 배치를 각각** **9분의 1로 줄인다****.**

      - **SEC당 측정 배치 = 9/1=9**
      - **SEC당 전체 2Q 게이트 계층 = 72/8=9**
  - 검사 수, 게이트 총량, 결과 비트 수는 그대로다. 추가 안실라의 효과는 같은 일을 병렬로 처리하는 데서 나온다.
  - 표의 큐비트 합계에는 비컨이나 예비 큐비트 등 추가 장치 자원이 포함되지 않는다. 또한 계층이 9분의 1이 되었다고 실제 SEC 전체 시간까지 정확히 9분의 1이 된다는 뜻은 아니다.

> ***안실라를 적게 재사용해도, 검사 사이에 추가 오류가 생기지 않는 이상적 조건에서는 같은 패턴을 얻는다.***
>
> ***차이는 그 패턴 전체를 확보하기까지 기다리는 시간이다. 안실라 54개를 배정한 Q54에서는 54개 검사 결과가 한 배치에서 나온다.***
>
> ***실제로는 검사하는 동안에도 오류가 생길 수 있다. 따라서 전체 검사 시간이 짧아지는 것은 대기 중 추가 오류가 누적될 여지를 줄이는 데 도움이 될 수 있다.***

**✅ 3. 왜 하필 데이터 큐비트 수만큼 배정할까?**

- - 이 코드들의 선택된 검사 목록에는 데이터 큐비트 수 n과 같은 수의 검사가 있다.
  - 검사마다 안실라 하나를 배정하면 신드롬 추출용 안실라 수도 n이 된다.
  - **데이터 1개마다 전용 오류 감지기를 붙인다는 뜻이 아니라,** **검사 1개마다 안실라 1개를 배정한다는 뜻이다.**
  - 안실라 하나는 여러 데이터와 상호작용하고, 데이터 하나도 여러 검사에 참여한다.

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **코드** | **데이터 큐비트** | **X형 + Z형 검사** | **독립 안정자 수 n-k** | **배정한 신드롬 안실라** |
| Q54 [[54,2,10]] | 54 | 27 + 27 = 54 | **52** | 54 |
| Q70 [[70,6,9]] | 70 | 35 + 35 = 70 | **64** | 70 |
| Q102 [[102,22,9]] | 102 | 51 + 51 = 102 | **80** | 102 |

- - 독립 안정자 수는 코드가 요구하는 독립적인 제약의 수다. 실제 검사 목록에는 다른 검사들의 곱으로 표현되는 종속 검사가 포함될 수 있다.[1]
  - 따라서 Q54의 **52는 독립 안정자 수**, **54는 여기서 측정하는 검사 수이자 배정한 안실라 수**다. Q70의 64와 70, Q102의 80과 102도 같은 구분이다.
  - 52개의 독립 결과가 필요하다는 말이 물리 안실라 52개를 동시에 보유해야 한다는 뜻은 아니다. 적은 안실라로도 재사용하며 결과를 모을 수 있다.
  - 이 글에서는 병렬화 효과를 비교하기 위해 종속 검사를 포함한 원래 검사 목록을 유지한다.

**✅ 4. 데이터 54개를 한 번씩 만지는 것만으로는 오류 위치를 알 수 없다**

- - Q54의 검사 웨이트는 8이다.
  - 여기서 54÷8을 계산해 “안실라 7개면 전체 오류 검사가 끝난다”고 해석하면 안 된다.

    - 안실라 하나가 데이터 8개와 상호작용해도 얻는 것은 8개 각각의 오류 보고서가 아니라, 그 조합에 대한 공동 패리티 한 비트다.
    - 어떤 Z형 검사에 X 오류가 하나 들어오면 결과가 뒤집힌다. 같은 검사 안에 X 오류가 두 개 들어오면 두 번 뒤집혀 원래 결과로 돌아온다.
    - 따라서 검사 하나의 결과만으로는 어느 데이터에 오류가 났는지, 오류가 정확히 몇 개인지 알 수 없다.
  - 여러 검사가 데이터를 서로 겹치게 포함하도록 만들고, 그 결과의 전체 패턴으로 오류를 추론한다.
  - Q54의 해당 검사 행렬에서는 각 데이터 큐비트가 X형 검사 4개와 Z형 검사 4개에 참여한다.
  - Q54의 안실라 54개는 각기 다른 검사 하나씩을 맡는다. 그중 47개가 남아서 쉬는 구조가 아니다.
  - 안실라 7개를 측정·초기화하며 재사용하는 설계를 택하면, 같은 54개 검사 결과를 모으는 데 최소 54/7=8개의 측정 배치가 필요하다.
  - 이는 결과 개수만으로 계산한 하한이다. 실제 스케줄의 충돌, 이동, 초기화와 측정 시간은 따로 고려해야 한다.

**✅ 5. 웨이트 8이면 왜 8개의 게이트 계층이 필요할까?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMDZfMjc2/MDAxNzkxMjUxMTQ0MzEz.UOhZe89_P666KwwTsc7m8h3wO8Z4gLKriXLRCPR3w4sg.TpQWA4Dm4cyZMcU_GaPJPh8EPoI9TADqtUZR1WRYn3kg.PNG/image.png?type=w800)](#)

- - 한 안실라가 데이터 8개와 각각 2Q 게이트를 수행하는 회로에서는 그 8번의 상호작용을 차례로 진행한다.
  - 서로 다른 안실라들은 같은 시간에 자기 검사를 진행할 수 있다.
  - 따라서 충분한 안실라와 적절한 스케줄이 있으면, 많은 안정자 검사를 병렬로 진행하면서도 각 안실라의 내부 동작은 순차적으로 진행한다.
  - Q54 그림의 A28은 다음 안정자를 담당한다.
  - **S****Z1****=Z****13****Z****18****Z****20****Z****21****Z****39****Z****40****Z****42****Z****47**
  - 그림에 그린 연결선 8개는 한 SEC 동안 방문하는 데이터 전체를 나타낸다.
  - 논문의 스케줄을 그림의 번호 체계로 환산하면 다음과 같다. 다항식 항은 표기 순서대로 번호를 매겼다.[2]

|  |  |
| --- | --- |
| **계층** | **A28이 상호작용하는 데이터** |
| 1 | 21번 |
| 2 | 39번 |
| 3 | 18번 |
| 4 | 42번 |
| 5 | 40번 |
| 6 | 13번 |
| 7 | 47번 |
| 8 | 20번 |
| 마지막 측정 | 8개 데이터의 공동 패리티 한 비트 |

- - A28이 담당하는 안정자 자체는 바뀌지 않는다. 그 안정자 검사를 완성하기 위해 현재 상호작용하는 데이터가 바뀐다.
  - 각 계층에서 데이터나 안실라를 측정하는 것이 아니다. 신드롬 추출용 안실라는 해당 상호작용을 모두 마친 뒤 측정한다.
  - Q54에서는 나머지 안실라 53개도 동시에 각자의 검사를 진행하므로, 한 계층에서 54개의 데이터–안실라 게이트를 실행한다.
  - 따라서 데이터–안실라 2Q 게이트 수는 54×8=432개지만, 병렬 게이트 계층은 8개다.
  - Q70과 Q102도 같은 방식으로 각각 70×7=490개, 102×8=816개를 실행한다.
  - 웨이트와 전체 계층 수가 같은 것은 이 병렬 측정 스케줄의 특성이다. 안실라가 적거나 연결·제어 제약이 있으면 전체 계층 수는 더 커질 수 있다.

**📌 한 배치로 끝낸다는 말은 한 번의 게이트로 끝낸다는 뜻이 아니다**

- - Q54의 안실라 하나는 데이터 8개와 차례로 상호작용한다.
  - 같은 안실라가 동시에 두 개의 2Q 게이트에 참여할 수 없으므로, 이 단일 안실라 측정 방식에서는 검사 하나를 완성하는 데 8개의 게이트 시간 단계가 필요하다.
  - 다른 안실라들은 그동안 각자의 검사를 병렬로 진행한다. 동시에 실행하는 게이트들이 큐비트를 공유하지 않도록 스케줄을 정해야 한다.
  - 예를 들어 앞서 그린 Q54의 A28은 다음 안정자를 측정한다.

    - SZ1=Z13Z18Z20Z21Z39Z40Z42Z47

**📌 안실라 3개로 어떻게 5비트의 신드롬을 얻을까?**

- - 안실라 수는 한 번에 사용 가능한 물리적 보조 큐비트 수다.
  - 측정 결과는 고전 컴퓨터에 저장할 수 있으므로, 안실라를 초기화하고 재사용해 더 많은 신드롬 비트를 모을 수 있다.
  - 고츠만 [[8,3,3]] 코드의 독립 생성자는 8-3=5개다.
  - Gottesman 논문 Table 3.3에 제시된 생성자들은 다음과 같다.[3]

|  |  |  |
| --- | --- | --- |
| **생성자** | **데이터 1번부터 8번까지의 연산** | **웨이트** |
| M\_1 | XXXXXXXX | 8 |
| M\_2 | ZZZZZZZZ | 8 |
| M\_3 | IXIXYZYZ | 6 |
| M\_4 | IXZYIXZY | 6 |
| M\_5 | IYXZXZIY | 6 |

- - 웨이트는 I를 제외한 항의 개수이므로 **8·8·6·6·6**이다.
  - 이 웨이트 목록은 제시된 생성자 선택에 대한 값이다. 코드의 n,k,d만으로 모든 생성자의 표현과 웨이트가 정해지는 것은 아니다.
  - 안실라 3개를 사용하는 예시는 다음과 같다.

|  |  |  |  |
| --- | --- | --- | --- |
| **배치** | **A1** | **A2** | **A3** |
| 첫 번째 | M\_1 | M\_2 | M\_3 |
| 측정 결과 저장·초기화 후 두 번째 | M\_4 | M\_5 | 사용하지 않음 |

- - 이 표는 검사 배정과 결과 수를 보여준다. 배치 내부 게이트가 모두 병렬화된다는 뜻은 아니다. 혼합 X·Y·Z 검사에서는 올바른 게이트 순서를 따로 정해야 한다.
  - 앞서의 설명용 회로처럼 배치 내부 검사들을 차례로 수행해도, 세 결과를 읽고 초기화한 뒤 나머지 두 결과를 얻을 수 있다.
  - 위 생성자 순서에서 2번 데이터에 X 오류가 생기면, 첫 배치 결과는 **010**, 두 번째는 **01**이어서 전체 신드롬은 **01001**이 된다.
  - 단일 큐비트 오류를 가정하면 디코더는 이 패턴을 X**2**로 해석한다.
  - 오류 없음 1가지와 8개 위치의 X·Y·Z 오류 24가지를 합치면 25가지다.
  - 5비트로 표현 가능한 패턴은 25=32가지이며, 이 코드의 24개 단일 큐비트 오류는 실제로 서로 다른 신드롬을 만든다.
  - 다만 d=3이 보장하는 임의 오류 정정 범위는 큐비트 하나다. 두 개 이상의 오류까지 항상 구별된다는 뜻은 아니다.

  - 많은 안실라를 배치하는 목적은 이러한 반복을 더 짧은 주기로 수행할 수 있도록 만드는 데 있다.

**✅ 8. 큐비트를 더 쓰는 만큼 실제 시간도 줄어들도록 설계해야 한다**

- - 안실라 수를 늘려도 같은 코드의 논리 큐비트 수나 코드 거리가 저절로 커지지는 않는다.
  - Q54 비교에서 432개 게이트는 여전히 실행되고, 54개의 측정 결과도 여전히 읽는다. 게이트 오류 기회나 측정 결과의 수가 9분의 1로 줄어드는 것은 아니다.
  - 실제 SEC 시간에는 게이트뿐 아니라 이동, 준비, 측정, 초기화, 손실·누설 검사 등이 포함된다.
  - 따라서 많은 안실라를 효과적으로 사용하려면 병렬 게이트, 이동, 제어와 판독을 함께 지원해야 한다. 논리 오류율이 얼마나 개선되는지는 그 회로와 잡음 조건에서 평가해야 한다.
  - 큐비트 예산이 작을 때는 안실라를 재사용하면서 시간을 더 쓴다. 더 많은 물리 큐비트를 사용할 수 있는 설계에서는 안실라를 넉넉히 배치해 필요한 검사를 동시에 진행한다.
  - **데이터 큐비트만큼 안실라를 배정하는 이유는, 같은 오류정정 정보를 더 짧은 주기로 얻기 위해 물리 큐비트를 병렬 처리에 투자하는 데 있다.**

**📌 계층 수가 곧 실제 실행 시간이나 오류정정 성능은 아니다**

- - 2Q 게이트 계층 수는 순차적으로 필요한 게이트 시간 단계의 수다.
  - 실제 SEC 시간에는 안실라 준비, 이온 이동, 측정, 초기화, 손실·누설 검사 등의 시간이 추가된다.
  - 그러므로 30계층과 8계층이라는 숫자만으로 실제 처리 시간이 정확히 3.75배 차이 난다고 판단할 수는 없다.
  - 표의 ‘d회 SEC 기준 총량’은 비교를 위해 반복 횟수를 그렇게 정한 계산이다. 코드 거리 d가 어떤 상황에서나 반드시 실행해야 하는 SEC 횟수라는 뜻은 아니다.
  - 코드 거리 d와 회로 수준 거리 dcirc도 구분해야 한다. 데이터 오류에 대한 코드의 성질과, 측정 회로의 고장까지 포함한 보호 성능은 같은 지표가 아니다.
  - 웨이트가 커질수록 안실라 하나가 방문해야 하는 데이터가 늘어나지만, 웨이트만으로 코드 거리나 전체 오류정정 성능이 결정되지는 않는다.
  - 안실라를 적게 쓰면 재사용을 통해 필요한 검사 결과를 모을 수 있다. 다만 측정 배치와 대기 시간이 늘어날 수 있다.
  - 안실라를 많이 쓰면 여러 검사를 병렬화할 여지가 커진다. 그 효과는 연결 구조와 제어 능력, 검증된 회로 스케줄에 달려 있다.
  - 따라서 코드를 비교할 때는 **얼마나 많은 큐비트를 쓰는지, 얼마나 많은 게이트를 실행하는지, 몇 계층과 배치로 나누는지**를 함께 확인해야 한다.

**✅ 결론 — 늘어난 큐비트가 확보해 주는 시간**

- - 양자컴퓨터의 규모를 이야기할 때 우리는 물리 큐비트가 몇 개인지 먼저 묻는다. 그러나 그 숫자의 의미를 이해하려면 한 가지 질문이 더 필요하다. **그 큐비트들을 어디에 배정했는가?**
  - 데이터 큐비트는 논리 정보를 담는다. 신드롬 추출용 안실라는 그 정보를 보호하는 데 필요한 검사 결과를 얻는다. 둘 다 물리 큐비트이며, 서로 다른 역할로 하나의 계산을 뒷받침한다.
  - 큐비트 예산이 부족하면 적은 안실라를 여러 번 재사용해야 한다. 검사 결과를 저장하고, 안실라를 초기화하고, 다음 검사를 수행한다. 필요한 정보는 모을 수 있지만, 전체 신드롬을 확보하기까지 여러 배치를 기다려야 한다.
  - 더 많은 물리 큐비트를 사용할 수 있다면 선택의 폭이 넓어진다. 추가 자원을 안실라에 배정해, 차례를 기다리던 검사들을 동시에 진행할 수 있다. **안실라를 늘리는 것은 오류정정에 필요한 시간을 줄이기 위한 투자다.**
  - 앞서의 Q54 비교에서는 배치당 8계층의 병렬 실행을 가정했을 때, 안실라를 6개에서 54개로 늘리면 9배치·72계층이 1배치·8계층으로 줄어든다. 검사 결과 54개와 2Q 게이트 432개는 그대로지만, 전체 결과를 모으는 데 필요한 순차 단계가 크게 줄어든다.
  - 이러한 시간 절약은 양자 오류정정에서 의미가 크다. 검사를 진행하는 동안에도 양자정보는 잡음에 노출되기 때문이다. 검사 주기를 짧게 만들 수 있다면 오류 상태를 더 자주 확인하고, 대기 중 추가 오류가 누적될 여지를 줄일 수 있다. 실제 이득은 이를 뒷받침하는 게이트·이동·측정 성능과 함께 결정된다.
  - 따라서 데이터 큐비트만큼 안실라를 배치했다는 사실은 단순한 자원 증가 이상의 의미를 갖는다. 확보한 물리 큐비트를 이용해 **오류정정의 병렬성을 높이고, 양자정보를 보호하는 주기를 단축하려는 설계 선택**이다.
  - 더 많은 큐비트를 확보하는 일은 출발점이다. 그 자원을 어떻게 나누어 써야 양자정보를 지키고 필요한 계산을 끝까지 이어 갈 수 있는지가 다음 과제다.
  - **안실라에 배정한 큐비트에는 그 목적이 담겨 있다. 양자정보를 지키며 다음 계산으로 나아갈 시간을 확보하는 것이다.**

> *데이터 큐비트 54개에 신드롬 추출용 안실라 54개를 더해 108개를 사용한다고 해서, 연산 능력이**2^{54}**배 향상되는 것은 아니다.*
>
> *이제, 큐비트 하나가 늘 때마다 계산 능력이 두 배가 된다는 단순한 셈법에서 벗어나야 하고, 양자 상태공간의 크기와 실제로 수행할 수 있는 계산의 능력은 구분해야 한다.*
>
> **
>
> ***주목해야 할 것은 늘어난 물리 큐비트를 어디에 사용하는가이다.***
>
> *그중 상당수를 안실라에 배정하면 여러 안정자 검사를 동시에 진행하고, 오류정정에 필요한 정보를 더 짧은 시간에 모을 수 있다. 하드웨어와 회로 설계가 이를 뒷받침할 때, 기다리는 동안 오류가 누적될 기회를 줄이고, 적절한 회로와 하드웨어 조건에서 논리 오류율을 낮추는 데 기여한다.*
>
> ***많은 물리 큐비트를 확보하는 것은 중요하다. 하지만, 더 많은 큐비트를 확보하는 것만큼 중요한 것은, 그 큐비트로 무엇을 가능하게 하느냐이다.***
>
> ***안실라에 배정한 큐비트는 더 빠른 오류정정과 더 신뢰할 수 있는 계산을 위한 투자다. 물리 큐비트의 증가가 짧은 검사 주기와 낮은 논리 오류율로 이어질 때, 그 숫자는 실제로 활용할 수 있는 계산 능력이 된다.***

**📌 Q54는 신드롬으로 어떻게 1·2·3·4번 오류를 찾을까?**

- - Q54의 데이터 1·2·3·4번에 X 오류가 발생했다고 하자.
  - 실제 오류는 E=X**1**X**2**X**3**X**4**이지만, 디코더는 처음부터 이 위치를 알고 있지 않다.
  - 디코더가 받는 것은 안정자 측정 결과와, 어떤 검사가 어떤 데이터에 연결되어 있는지를 나타내는 검사 행렬이다.
  - 여기서는 X 오류만 있으므로 Z형 검사 결과를 살펴본다. X형 검사 결과는 모두 0이다.
  - 각 X 오류 하나가 뒤집는 Z형 검사 번호는 다음과 같다. 이 번호는 데이터 번호가 아니라 검사 번호다.

|  |  |
| --- | --- |
| **단일 오류** | **뒤집히는 Z형 검사 번호** |
| X\_1 | 8, 9, 11, 16 |
| X\_2 | 9, 10, 12, 17 |
| X\_3 | 10, 11, 13, 18 |
| X\_4 | 11, 12, 14, 19 |

- - 네 오류가 동시에 발생하면 검사별 뒤집힘 횟수를 XOR로 합친다.
  - 검사 9에는 오류 1·2가 포함되므로 두 번 뒤집혀 결과가 0이 된다.
  - 검사 11에는 오류 1·3·4가 포함되므로 세 번 뒤집혀 결과가 1이 된다.
  - 따라서 최종적으로 **8·11·13·14·16·17·18·19번 검사**가 1이다.

|  |  |
| --- | --- |
| **신드롬 구간** | **결과** |
| Z1–9 | 000000010 |
| Z10–18 | 010110111 |
| Z19–27 | 100000000 |

- - 신드롬 1은 해당 안정자의 측정값이 -1, 신드롬 0은 +1이라는 표기다.
  - **신드롬 1의 개수는 오류 개수가 아니며, 신드롬 1의 위치는 오류 큐비트 위치가 아니다.**
  - 디코더는 1인 결과뿐 아니라 0인 결과까지 모두 만족하는 오류 후보를 찾는다.
  - 이 그림에서 사용한 최소 웨이트 X 오류 디코더를 계산하면, 0·1·2·3개 오류 조합 중에는 해당 신드롬과 일치하는 후보가 없다.
  - 4개 X 오류 조합 중에서는 **{1,2,3,4}가 유일하게 일치**한다.
  - 따라서 복구 연산으로 C=X**1**X**2**X**3**X**4**를 선택한다.
  - X를 두 번 적용하면 원래대로 돌아오므로 CE=(X**1**X**2**X**3**X**4**)2=I가 되어 복구된다.
  - 일반적인 안정자 코드에서는 실제 오류 위치가 유일하게 결정되지 않아도, 같은 논리적 복구 효과를 내는 후보를 선택하면 정정에 성공할 수 있다. 위 예제는 위치가 유일하게 결정되는 경우다.[1]

**📌 비교표는 실행 조건을 맞춰서 읽어야 한다**
