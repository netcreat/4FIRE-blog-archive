# NIST PQC 전환 지침 최종 확정

Published: 2026-10-28T22:12:16+11:00

Original Naver post: https://blog.naver.com/4-fire/224457006220?fromRss=true&trackingCode=rss

---

**✅ 2030·2031·2035년의 의미**

- - **2026년 10월 27일 NIST는 IR 8547 최종본을 발표했다.** 새로운 양자내성암호 알고리즘을 추가한 발표가 아니라, 기존 공개키 암호를 어떤 일정과 우선순위로 교체할 것인지 정리한 전환 로드맵이다.
  - 핵심 질문은 두 가지다. **2024년 표준 및 전환 초안과 무엇이 달라졌는가?** 그리고 **PQC 전환 수요의 확대가 IonQ의 QSPM 매출로 곧바로 이어진다고 볼 수 있는가?**
  - 두 번째 질문에 대한 현재 판단은 신중해야 한다. IonQ가 QSPM 제공을 공개적으로 설명한 것은 사실이지만, 독립적으로 검증할 수 있는 제품 구현과 구축 실적은 별도로 확인해야 한다.

---

**✅ 2024년 PQC 표준화와 2026년 전환 지침은 역할이 다르다**

- - 2024년 8월의 FIPS 203·204·205는 **무엇으로 교체할 것인가**를 규정했다.
  - 2024년 11월 NIST IR 8547 초안은 **언제 기존 알고리즘을 퇴출할 것인가**를 제안했다.
  - 2026년 10월의 IR 8547 최종본은 전환 일정을 확정하고 연방정부 정책, 기술별 우선순위, 사용 가능한 전환 방식 등을 연결했다.

|  |  |  |
| --- | --- | --- |
| **시점** | **문서** | **핵심 의미** |
| 2024년 8월 | FIPS 203·204·205 | ML-KEM·ML-DSA·SLH-DSA 표준 확정 |
| 2024년 11월 | NIST IR 8547 Draft | 양자 취약 암호 퇴출 일정 제안 |
| 2026년 10월 27일 | NIST IR 8547 Final | 전환 지침 최종 확정, 연방정부 조기 전환 일정 반영 |

**📌 표준화된 주요 알고리즘**

|  |  |  |  |
| --- | --- | --- | --- |
| **표준** | **알고리즘** | **용도** | **기존 방식 예시** |
| FIPS 203 | ML-KEM | 양자내성 키 설정 | ECDH, FFDH, RSA 기반 키 설정 |
| FIPS 204 | ML-DSA | 양자내성 디지털 서명 | RSA, ECDSA, EdDSA 서명 |
| FIPS 205 | SLH-DSA | 해시 기반 양자내성 서명 | 기존 공개키 디지털 서명의 대안 |

|  |  |  |
| --- | --- | --- |
| **기준** | **시점** | **대상과 의미** |

|  |  |  |

| 2035년 Disallowed | 양자 취약 공개키 알고리즘 퇴출 제시 | 기본 퇴출 방향 유지 |
| 연방정부 우선순위 | 일반 전환 시나리오·일정 중심 | 행정명령·OMB의 중요 시스템 조기 전환 정책 반영 |
| 문서 지위 | 의견수렴용 초안 | 최종 확정 보고서 |

- - 가장 중요한 변경점은 **기존 RSA-3072 또는 ECDSA P-256처럼 클래식 보안강도가 128비트 이상인 구성도 2030년 이후 Deprecated 대상이 된 점**이다.
  - 2024년 초안에서는 112비트 보안강도의 매개변수와 128비트 이상 매개변수의 2030년 처리 방식에 차이가 있었다. 2026년 최종본은 이 경계를 없애는 방향이다.
  - 즉 더 긴 RSA 키나 더 강한 ECC 곡선을 쓰는 것만으로 양자 취약 공개키 암호의 퇴출 일정을 피할 수 없다는 의미다.

**✅ 왜 키 설정 전환이 디지털 서명보다 우선인가?**

- - 기업의 TLS 통신은 키 설정과 데이터 암호화가 서로 다른 역할을 맡는다. 일반적인 기존 구성은 **ECDHE로 공유 비밀을 설정하고 AES-GCM으로 실제 데이터를 암호화**하는 구조다.
  - PQC 전환에서는 키 설정을 **ML-KEM**으로 교체하거나, 전환기에 **ECDHE + ML-KEM** 결합 방식을 사용할 수 있다. 이후의 대칭 암호화는 기존 AES를 계속 활용할 수 있다.
  - 공개키 디지털 서명은 키 설정과 다른 문제다. 인증서, 코드 서명, 장비 및 사용자 인증에 쓰는 RSA/ECDSA/EdDSA는 ML-DSA 또는 적절한 PQC 서명으로 전환할 수 있다.
  - **Harvest Now, Decrypt Later(HNDL)** 때문에 장기 기밀성이 필요한 트래픽의 키 설정 교체가 특히 시급하다. 오늘 기록한 암호문이 미래에 복호화될 가능성을 줄이려는 것이다.
  - NIST는 고전 암호와 PQC를 병행하는 Hybrid 전환을 허용하지만, 무조건 의무화하지는 않는다. 결합 방식의 안전성, 운영 복잡성, 계산 자원 증가 등을 검증해야 한다.

**📌 살펴볼 대상**

- - VPN/IPsec/IKE 및 TLS가 어떤 키 교환 알고리즘과 암호 스위트를 사용하는지 확인한다.
  - SSH, PKI, 디바이스 인증서, HSM, 애플리케이션 라이브러리까지 함께 조사한다.
  - PQC 도입 시 핸드셰이크 크기, 인증서 크기, CPU 사용률, MTU·단편화 가능성, 벤더 간 호환성을 시험한다.
  - TLS 1.3 지원 자체가 PQC 지원을 뜻하지는 않는다. 실제 ML-KEM/서명 지원 여부는 별도로 확인해야 한다.

**📌 그렇다고 IonQ의 다른 보안 실적까지 부정할 수는 없다**

- - IonQ는 2026년 9월 Congruity360과 **818만 달러 규모**의 양자보안 협약을 발표했다. 회사가 명시한 구축 대상은 **PQC 및 QKD 장비를 사용하는 양자안전 네트워크**다.
  - 2026년 10월 26일에는 제네바와 서울 사이에서 PQC 및 QKD를 결합한 내부 통신망을 운영한다고 발표했다.
  - 이 두 발표는 **PQC/QKD 통신 인프라 및 구축 역량의 근거**다. 그러나 그 자체로 **QSPM의 암호자산 탐지 엔진과 상용 제품 검증을 입증하는 자료는 아니다.**

**✅ Elisity IdentityGraph와 Dynamic Policy Engine이 QSPM의 빈칸을 채울 수 있는가?**

- - Elisity의 IdentityGraph는 장비·사용자·워크로드의 신원과 보안 상태, 통신·접근 관계를 연결하는 기반이다.
  - Elisity의 정책 엔진은 해당 신원과 관계 정보를 바탕으로 접근제어와 마이크로세그멘테이션 정책을 실행하도록 설계된 영역이다.
  - 그러나 **IdentityGraph 자체가 TLS 핸드셰이크, SSH 키, 인증서, 애플리케이션 암호 라이브러리까지 자동으로 찾아내는 전문 Cryptographic Discovery Engine이라는 뜻은 아니다.**
  - 2026년 10월 12일 Elisity는 암호자산 목록과 위험 정보를 IdentityGraph에 추가하는 방향을 **인수 후 개발할 다음 단계**로 설명했다. 이미 완성되어 판매 중인 통합 기능으로 발표한 것이 아니다.
  - 따라서 IonQ가 QSPM을 완성하려면 **① 암호자산의 실제 탐지 → ② 신원·네트워크 관계에 위험정보 결합 → ③ 전환 우선순위 판단 → ④ 정책 및 보완조치 연계**의 과정이 제품 수준에서 검증되어야 한다.

| IonQ | QSPM | 제공 발표와 목표 기능 설명. 고유 탐지 구현·QSPM 특정 고객 실적의 공개 검증은 제한적 |

- - SandboxAQ와 Keyfactor는 **무엇을 어디서 수집하고 분석하는지**를 기술 문서로 공개하고 있다. 이는 독립적인 기술 실체를 검토할 출발점을 제공한다.
  - 이는 해당 경쟁사 제품이 모든 환경에서 완벽하게 작동한다는 뜻은 아니다. 제품 설명과 실제 고객별 탐지 범위·정확도·상용 매출은 별개의 검증 사항이다.
  - 현재 비교에서 중요한 것은 마케팅 문구의 우열이 아니라, **실제 탐지·분석·개선 작업을 고객 환경에서 반복 수행할 수 있음을 얼마나 구체적으로 보여주었는가**다.

**✅ NIST 발표가 IonQ 매출로 연결되려면 필요한 이정표**

- - 첫째, 제품의 기술적 실체 공개

    - 암호자산 수집·탐지 방식과 센서·커넥터 지원 범위를 문서화한다.
    - 서버, 네트워크 장비, 클라우드, 애플리케이션 내 암호 사용의 식별 정확도를 검증한다.
  - 둘째, Elisity와의 실제 통합 증명

    - IdentityGraph와 암호위험 데이터를 연결하는 구현 및 정책 적용 사례를 제시한다.
    - 정적 목록 제공을 넘어 지속적인 위험 평가와 대응 우선순위 설정이 작동함을 보여준다.
  - 셋째, QSPM 자체의 유료 고객 및 실적 확인

    - PQC/QKD 장비 구축 계약과 구분되는 QSPM 라이선스·서비스 계약을 확인한다.
    - 재현 가능한 구축 사례, 운영 환경, 제품 매출을 구체적으로 제시한다.
  - **분석:** NIST IR 8547 최종화는 기업의 암호자산 탐지, 암호 민첩성(Crypto Agility), 위험 우선순위 관리에 대한 필요성을 높일 수 있다.
  - **확인된 사실:** NIST는 특정 QSPM 상용 제품의 구매를 의무화하거나 IonQ 제품의 상용화를 인증하지 않았다.
  - **투자 관점의 결론:** 산업 전체의 PQC 전환 수요 확대와 IonQ QSPM의 제품 경쟁력·매출화는 별도의 가설이다. IonQ의 현재 보안 실적은 QKD/PQC 구축과 QSPM 제품 실적을 구분해 평가해야 한다.

---

**✅ 결론: 전환 일정은 구체화됐지만, QSPM의 경쟁력은 이제 입증해야 한다**

- - **2026년 IR 8547의 변화는 새로운 PQC 알고리즘이 아니라 기존 공개키 암호의 퇴출 단계와 전환 책임을 더 분명하게 만든 데 있다.**
  - 가장 중요한 세부 변경은 2024년 초안과 달리 128비트 이상 강도의 양자 취약 공개키 암호도 2030년 이후 Deprecated 범위에 포함한 것이다.
  - QSPM 분야에는 우호적인 시장 환경이 형성될 수 있지만, IonQ의 QSPM에 대해서는 아직 제품 구현·Elisity 통합·유료 고객 실적을 확인해야 한다.
  - **정리하면, NIST 발표는 PQC 전환 산업의 필요성을 뒷받침한다. 그러나 그것만으로 IonQ QSPM이 이미 완성된 상용 제품이거나 경쟁사보다 앞선다고 결론 내릴 수는 없다.**
