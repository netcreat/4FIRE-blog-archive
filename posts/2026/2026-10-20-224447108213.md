# Quantinuum의 논리 오류율 10배 개선의 의미?

Original Naver post: https://blog.naver.com/4-fire/224447108213?fromRss=true&trackingCode=rss

**✅ IonQ의 고충실도·대량생산 전략과 비교하면?**

- - 2026년 10월 19일 Quantinuum은 Helios 양자컴퓨터에서 **99.9995%의 논리 메모리 충실도(Logical Memory Fidelity)**를 달성했다고 발표했다.
  - 지난 9월 Helix Code로 세운 자사의 기록보다 오류율을 약 10배 낮췄으며, Code Distance가 증가할 때 논리 오류가 평균 12분의 1로 감소하는 결과도 제시했다.
  - 이 발표를 보고 몇 가지 의문이 생겼다.

    - Quantinuum은 왜 부호화 효율이 높은 BB 계열 qLDPC 대신 Color Code를 사용했을까?
    - 발표에 등장하는 Λ=12는 어떤 의미이며, IonQ에도 이에 대응하는 실험 결과가 있을까?
    - Quantinuum의 99.9995%와 IonQ의 99.99% 또는 99.995%를 직접 비교할 수 있을까?
    - 물리 큐비트 수를 크게 늘리지 않은 상태에서 높은 논리 정확도를 검증하는 전략과, 고충실도 물리 큐비트를 대량 생산하는 전략 중 무엇이 유틸리티 스케일에 더 유리할까?
  - 이번 발표는 상당히 중요한 성과다. 그러나 FTQC(Fault-Tolerant Quantum Computing)의 완성도를 판단하려면 논리 오류율 외에도 물리 큐비트 수, 부호화 효율, 논리 연산 속도, 병렬성, Magic State 처리량, 오류 정정 지연시간 등을 함께 살펴봐야 한다.
  - 이번 글에서는 Quantinuum의 실험을 분석하고 IonQ의 기존 발표와 비교하면서, **실제 검증된 기술과 아직 검증해야 하는 기술을 구분**해 보려고 한다.

---

**✅ 1. Quantinuum은 무엇을 달성했나?**

**📌 Helios에서 달성한 논리 메모리 오류율**

- - Quantinuum은 98개 물리 큐비트를 갖춘 Helios 양자컴퓨터에서 Distance 3, 5, 7의 Color Code를 실험했다.
  - 가장 높은 보호 수준인 Distance 7에서 측정된 논리 메모리 오류율은 약 5×10-6이다.
  - 이는 한 번의 오류 증후군 추출 주기(Syndrome Extraction Cycle)당 약 20만 번에 한 번의 논리 오류가 발생하는 수준이다.

|  |  |
| --- | --- |
| **항목** | **결과** |
| 양자컴퓨터 | Quantinuum Helios |
| 전체 물리 큐비트 | 98개 |
| 오류 정정 코드 | 2D Color Code |
| 실험 코드 거리 | 3, 5, 7 |
| Distance 7 코드 | [[37,1,7]] |
| 논리 메모리 충실도 | 99.9995% |
| 논리 메모리 오류율 | 약 5×10⁻⁶ / QEC Cycle |
| 메모리 오류 억제 계수 | Λ≈12 |
| 논리 2Q Clifford 오류 억제 | Λ≈9, Distance 3→5 |

- - 여기서 중요한 점은 **99.9995%가 논리 2큐비트 게이트 충실도를 의미하지 않는다는 사실**이다.
  - 이번에 보고된 최고 수치는 논리 큐비트의 정보를 오류 정정 주기 동안 보존하는 성능이다.
  - 논리 2Q Clifford 게이트에 대해서도 코드 거리 증가에 따른 오류 억제를 확인했지만, 최고 메모리 충실도를 그대로 논리 게이트 충실도로 해석해서는 안 된다.

**📌 실제 오류 발생은 3건이었다**

- - Quantinuum은 다음과 같은 실험 결과를 공개했다.

|  |  |
| --- | --- |
| **구분** | **측정값** |
| 반복 실험 | 29,000회 |
| 반복당 QEC 주기 | 20회 |
| 총 QEC 주기 | 580,000회 |
| 관측된 논리 오류 | 3건 |
| 추정 오류율 | 5.17×10⁻⁶ |

- - 실제 관측된 오류율은 다음과 같다.

    - **3 ÷ 580,000 ≈ 5.17×10****-6**
  - 매우 우수한 결과지만, 실제 오류가 3건에 불과하기 때문에 통계적 불확실성도 존재한다.
  - 또한 이번 실험에는 새로운 Leakage Repump 기술과 Decoder 개선도 포함됐다. 따라서 단순히 소프트웨어에서 코드 이름만 변경해 10배 개선했다고 설명하는 것은 정확하지 않다.
  - 같은 세대의 Helios 하드웨어를 활용하면서 오류 정정 코드와 제어·복구 방법을 개선한 결과로 이해하는 것이 적절하다.

**✅ 2. Color Code는 무엇인가? qLDPC인가?**

**📌 먼저 qLDPC의 정의를 구분해야 한다**

- - 엄밀하게 말하면 2D Color Code 역시 넓은 수학적 정의에서는 qLDPC에 포함된다.
  - qLDPC(Quantum Low-Density Parity-Check)는 각 Stabilizer Check가 관여하는 큐비트 수와 각 큐비트가 참여하는 Check 수가 코드의 크기가 커져도 일정한 상한을 유지하는 코드 계열이다.
  - 2D Color Code 역시 이러한 조건을 충족한다.
  - 그러나 최근 양자컴퓨터 기업들이 강조하는 qLDPC는 대체로 **높은 부호화율(High Encoding Rate)을 갖는 BB Code, Hypergraph Product Code 등**을 의미한다.
  - 따라서 두 개념을 구별할 필요가 있다.

|  |  |  |
| --- | --- | --- |
| **구분** | **2D Color Code** | **고부호화율 BB/qLDPC** |
| 넓은 의미의 qLDPC | 포함 | 포함 |
| 대표 구조 | 2D Topological Code | 비국소 연결 기반 Block Code |
| 논리 큐비트 부호화 | 일반적으로 패치당 소수 | 블록당 여러 개 |
| 부호화율 확장 | 규모 증가 시 낮아짐 | 높은 부호화율 가능 |
| 연결 요구 | 국소적 연결 중심 | 비국소 연결 필요 |
| Clifford 연산 | Transversal 구현에 장점 | 코드별 연산 방식 필요 |
| IonQ의 중장기 전략 | 보조적으로 활용 가능 | 핵심 전략 |

- - 핵심은 Color Code가 qLDPC인지 아닌지의 명칭보다는 **대규모 시스템에서 논리 큐비트당 필요한 물리 큐비트가 얼마나 증가하는가**에 있다.

**📌 Quantinuum이 Color Code를 선택한 이유**

- - 첫째, Color Code는 이미 잘 연구된 코드이기 때문에 실제 하드웨어에서 오류 정정의 성능을 측정하고 비교하기에 적합하다.
  - 둘째, 2D Color Code는 Clifford 연산을 Transversal 방식으로 구현할 수 있다는 강점이 있다. 실제로 Quantinuum은 이번에 논리 2Q Clifford 게이트에서도 오류 억제 현상을 확인했다.
  - 셋째, 코드 거리를 3→5→7로 증가시키면서 논리 오류율을 측정하면 하드웨어가 오류 정정 임계값(Threshold) 아래에서 작동하는지 검증할 수 있다.
  - 넷째, Helios의 QCCD 아키텍처는 이온을 재배치하고 다양한 큐비트 연결 관계를 구현할 수 있어 서로 다른 QEC 코드를 시험하는 데 유리하다.
  - 다시 말해 Quantinuum은 이번 실험에서 **최대한 많은 논리 큐비트를 만들어내는 것보다 오류 정정 성능의 확장 법칙을 실증하는 데 집중한 것**으로 볼 수 있다.
  - 다만 이것이 Quantinuum이 고부호화율 코드를 포기했다는 의미는 아니다.
  - 지난 9월에는 [[20,2,6]] Helix Code를 통해 논리 큐비트당 약 10개의 물리 큐비트를 사용하는 구조를 선보였다.
  - 이번 Color Code는 논리 큐비트당 최대 37개의 데이터 큐비트를 사용하면서도 더 낮은 논리 메모리 오류율을 달성했다.
  - 즉, Quantinuum은 **부호화 효율과 오류 억제 성능 사이에서 서로 다른 선택지를 확보하려는 전략**을 취하고 있다.

**✅ 3. Λ=12는 무엇을 의미할까?**

- - 그리스 문자 대문자 Λ는 '람다'라고 읽는다.
  - 이번 실험에서는 오류 억제 계수(Error Suppression Factor)를 의미한다.
  - 오류 정정 코드의 Distance가 증가할 때 논리 오류율이 얼마나 빠르게 감소하는지 나타내는 값이다.
  - 이번 실험처럼 Code Distance가 2씩 증가하는 경우 다음과 같이 근사할 수 있다.
  - **pL(d+2) ≈ pL(d) / Λ**
  - 만약 Λ=12라면 Code Distance가 두 단계 증가할 때마다 논리 오류율이 약 12분의 1로 감소한다는 의미다.

|  |  |  |
| --- | --- | --- |
| **Code Distance** | **논리 오류율** | **구분** |
| 7 | 약 5×10⁻⁶ | 실측 |
| 9 | 약 4.17×10⁻⁷ | 예측 |
| 11 | 약 3.47×10⁻⁸ | 예측 |
| 13 | 약 2.89×10⁻⁹ | 예측 |
| 15 | 약 2.41×10⁻¹⁰ | 예측 |
| 17 | 약 2.01×10⁻¹¹ | 예측 |
| 19 | 약 1.67×10⁻¹² | 예측 |
| 21 | 약 1.40×10⁻¹³ | 예측 |

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjEwMTlfMTUz/MDAxNzkyNDE4NzAyMDU3.-d8QwwBw_hFAYBcWpPLcuu8k1P3nMcO-m-xLveMgkEog.jklVocsbUfsLx2vlBfS4WSPgAex44U9zw_rFBgMsthUg.PNG/image.png?type=w800)](#)

- - 이 표에서 Distance 7까지는 실제 실험이지만, Distance 9부터는 Λ=12가 그대로 유지된다고 가정한 계산이다.
  - Quantinuum은 이 결과를 토대로 Distance 21에서 논리 오류율 10-12 이하를 실현할 수 있다고 주장한다.
  - **이번 실험의 진정한 의미는 99.9995%라는 수치뿐 아니라, 물리 큐비트를 추가해 보호 수준을 높였을 때 실제로 오류가 크게 감소했다는 사실이다.**
  - 이것은 FTQC에 반드시 필요한 조건 중 하나다.
  - 다만 Λ는 하드웨어에 영구적으로 고정된 상수가 아니다. 코드 구조, 물리 오류 모델, Syndrome 회로, Decoder 및 시스템 규모에 따라 달라질 수 있다.
  - 앞으로 Distance 9, 11 이상의 코드에서도 동일한 오류 억제 계수가 유지되는지를 확인해야 한다.

**✅ 4. IonQ에서도 Λ=12와 같은 결과를 얻었을까?**

**📌 동일한 조건의 Λ 값은 아직 확인되지 않는다**

- - IonQ도 오류 정정을 오랫동안 연구해 왔으며, 2026년에는 실제 qLDPC 메모리 실험을 발표했다.
  - 그러나 이번 Quantinuum처럼 여러 Code Distance를 증가시키면서 논리 메모리 오류율의 감소를 측정하고, 그 결과로 Λ≈12와 같은 억제 계수를 보고한 동등한 실험 결과는 확인되지 않는다.
  - 그렇다고 IonQ가 아직 2큐비트 게이트만 실험했다고 생각하면 안 된다.
  - IonQ는 이미 실제 다중 큐비트 QEC 실험을 수행했다.

**📌 IonQ의 40이온 qLDPC Breakeven 실험**

- - 2026년 6월 발표되고 9월 14일 수정된 논문 *Breakeven demonstration of quantum low-density parity-check codes*에서는 40개의 바륨 이온을 사용해 여덟 종류의 오류 정정 코드를 시험했다.
  - BB5, Generalized Bicycle, Toric, Concatenated Code를 하나의 하드웨어에서 구현했다.
  - 대표적으로 다음과 같은 BB5 코드가 사용됐다.

    - [[18,4,3]]
    - [[24,4,4]]
    - [[30,4,5]]
  - [[18,4,3]]은 18개 데이터 큐비트로 4개의 논리 큐비트를 부호화한다.
  - 단순 데이터 큐비트 기준 부호화율은 다음과 같다.

    - **4 / 18 ≈ 22.2%**
  - 이에 비해 Quantinuum의 Distance 7 Color Code는 다음과 같다.

    - **1 / 37 ≈ 2.7%**
  - 두 수치는 데이터 큐비트만 고려했으며, 실제 장비에서 필요한 측정용 Ancilla 및 기타 자원까지 모두 포함한 효율은 아니다.
  - 그래도 부호화 효율이라는 측면에서는 BB 계열 코드의 장점이 분명하다.

**📌 IonQ의 실측 오류율은?**

- - 2026년 9월 수정 논문에 따르면 IonQ의 실제 BB5 메모리 오류율은 다음과 같다.

|  |  |  |
| --- | --- | --- |
| **코드** | **X 상태 메모리 오류율 / 주기** | **Z 상태 메모리 오류율 / 주기** |
| BB [[18,4,3]] | 1.95% | 1.10% |
| BB [[24,4,4]] | 2.19% | 1.28% |
| BB [[30,4,5]] | 3.52% | 1.70% |
| GB [[26,2,5]] | 1.91% | 0.91% |

- - 이 실험에서는 일부 논리 메모리 수명이 물리 큐비트와 비슷하거나 약간 길게 측정됐다.
  - 특히 GB [[26,2,5]] 코드의 메모리 수명은 3.95±0.71초로, 비교 대상 물리 큐비트의 3.84±0.48초와 유사한 수준이었다.
  - 다만 두 결과의 오차 범위가 상당히 겹치므로 물리 큐비트보다 통계적으로 확실하게 우수하다고 단정하기는 어렵다.
  - 또한 이 실험에서는 Leakage가 감지된 일부 실행 결과를 제외하는 Post-selection을 사용했다.
  - 이 부분은 앞으로 실제 FTQC에서 중요한 검증 대상이다.
  - 정리하면 IonQ는 실제 하드웨어에서 qLDPC를 구현했고, Breakeven 부근의 메모리 성능을 보였지만, **이번 Quantinuum 수준의 낮은 논리 메모리 오류율과 강한 Distance Scaling을 같은 조건으로 실증한 단계는 아니다.**

**✅ 5. IonQ의 99.995%와 Quantinuum의 99.9995%는 비교할 수 있을까?**

**📌 먼저 IonQ의 숫자부터 구분해야 한다**

- - IonQ 자료에서 등장하는 99.995%에는 주의가 필요하다.
  - IonQ의 BB5 코드 연구에서 제시된 99.995%는 실제 물리 2큐비트 게이트 실험값이 아니다.
  - 이는 물리 오류율 10-3을 가정한 시뮬레이션에서 [[48,4,7]] BB5 Code의 논리 메모리 오류율이 5×10-5에 도달했다는 결과다.
  - 반면 IonQ가 2025년 10월 공개한 Oxford Ionics의 실제 물리 2큐비트 게이트 실험은 게이트 오류율 약 8.4×10-5를 보고했다.
  - 이를 충실도로 환산하면 약 99.9916%다.
  - 서로 다른 결과가 비슷한 숫자로 표현되기 때문에 혼동하기 쉽다.

| --- | --- | --- | --- |
| **발표** | **수치** | **무엇을 측정했나?** | **검증 유형** |
| Quantinuum 2026.10 | 99.9995% | 논리 메모리 / QEC 주기 | 실제 실험 |
| IonQ BB5 연구 | 99.995% | 가정한 물리 오류 모델에서 논리 메모리 | 시뮬레이션 |
| IonQ/Oxford Ionics | 약 99.9916% | 물리 2Q 게이트 | 실제 실험 |
| IonQ 2026 qLDPC | 약 0.91~3.52% 오류율 | 코드·기저별 논리 메모리 / QEC 주기 | 실제 실험 |

- - 이 표의 수치들은 각각 의미가 다르다.
  - **Quantinuum의 실제 논리 메모리 99.9995%와 IonQ의 시뮬레이션 논리 메모리 99.995%를 마치 동일한 실험에서 얻은 결과처럼 비교하면 안 된다.**
  - 마찬가지로 IonQ의 물리 2Q 게이트 Fidelity와 Quantinuum의 논리 메모리 Fidelity도 직접적인 우열 비교가 불가능하다.

**✅ 6. 비교 가능한 것과 비교할 수 없는 것을 구분하자**

**📌 기술적 비교 기준**

|  |  |  |
| --- | --- | --- |
| **비교 항목** | **직접 비교** | **판단** |
| 물리 2Q 게이트 충실도 | 조건부 가능 | 동일한 측정 방식·하드웨어 범위 필요 |
| 논리 메모리 오류율 | 조건부 가능 | 코드, 사이클 시간, 오류 모델, Post-selection 확인 |
| Code Distance Scaling | 조건부 가능 | 같은 의미의 거리와 오류율 측정 필요 |

| 논리 큐비트 숫자 | 조건부 가능 | QEC/QED, 동시 사용성, 오류율 구분 |
| 데이터 큐비트 부호화율 | 가능 | k/n 비교 가능, 총 오버헤드는 별도 |
| Decoder 속도 | 조건부 가능 | 데이터 규모, 지연, 하드웨어/시뮬레이션 구분 |
| 논리 게이트 처리량 | 현재 제한적 | 동일 작업에 대한 실측 비교 부족 |
| 대량 생산 가능성 | 정성 비교 가능 | 양산 수율·운용 성능은 미검증 |
| 2029년 FTQC 로드맵 | 목표 비교 가능 | 달성한 성과와는 구별 |

- - 특히 논리 오류율을 비교하려면 오류율에 시간 정보를 함께 표시해야 한다.
  - 예를 들어 어떤 시스템의 오류율이 QEC Cycle당 10-5이고 사이클이 1ms라면, 다른 시스템의 사이클당 10-6이지만 사이클이 100ms인 경우보다 반드시 우수하다고 말할 수 없다.
  - 논리 메모리의 오류 발생률을 실제 시간 기준으로 비교하거나, 동일한 논리 연산을 완료하는 데 필요한 시간과 오류 확률을 함께 측정해야 하기 때문이다.

**📌 동등하게 비교할 수 있는 핵심 실험은 무엇인가?**

- - 가장 이상적인 비교는 양사가 동일한 목표 오류율 아래에서 동일한 논리 알고리즘을 실행하는 것이다.
  - 예를 들어 다음을 고정할 수 있다.

    - 같은 논리 큐비트 수
    - 같은 Clifford/T 또는 Toffoli 게이트 수
    - 같은 최종 성공 확률
    - 같은 Shot 수
    - 동일한 오류 검출·폐기 기준
  - 이 상태에서 소요 시간, 물리 큐비트 수, 소비 전력, Decoder 부하 및 비용을 비교한다면 훨씬 의미 있는 결론을 얻을 수 있다.
  - 그런데 현재 공개된 결과만으로는 이러한 End-to-End 비교를 완성하기 어렵다.

**✅ 7. 유틸리티 스케일에서 논리 큐비트 수보다 중요한 것은 무엇인가?**

- - 나는 이 부분이 양자컴퓨터의 발전을 평가할 때 가장 중요하다고 생각한다.
  - 논리 큐비트가 아무리 많아도 실제 유용한 알고리즘을 충분히 빠르고 안정적으로 실행할 수 없다면 그 가치는 제한적이다.
  - 유틸리티 스케일(Utility Scale)은 논리 큐비트 숫자 하나로 정의되는 고정된 기준이 아니라, 유용한 문제를 요구 정확도와 실용적인 시간·비용 안에서 해결할 수 있는 단계로 이해해야 한다.

**📌 ① 논리 오류율과 회로 깊이**

- - 깊은 논리 회로를 실행하려면 오류율을 극단적으로 낮춰야 한다.
  - 단순한 독립 오류 모델에서 성공 확률은 다음과 같이 계산할 수 있다.
  - **P(success) ≈ (1-p)^N**
  - 여기서 p는 연산당 오류 확률이고 N은 연산 횟수다.
  - 예를 들어 p=10-5라면 100만 번의 연산을 모두 오류 없이 수행할 확률은 매우 낮다.
  - 반면 p=10-12라면 같은 단순 모델에서 성공 확률은 약 99.9999%에 달한다.
  - 하지만 여기서 p는 반드시 **실제 실행하는 논리 연산의 오류 확률**이어야 한다.
  - 메모리 오류율을 그대로 논리 T 게이트의 오류율로 대입할 수는 없다.

**📌 ② 논리 게이트 처리량(Logical Gate Throughput)**

- - 논리 큐비트가 많다는 것은 동시에 저장할 수 있는 양자 정보가 많다는 의미다.
  - 그러나 그 정보를 얼마나 빠르게 처리할 수 있는지는 별개의 문제다.
  - 중요한 것은 다음과 같다.

    - Logical Clock Speed
    - Syndrome Extraction Cycle Time
    - Clifford/T Gate 처리량
    - 병렬 실행 가능한 논리 연산 수
    - Decoder 및 Classical Feed-forward 지연
  - 예를 들어 800개 논리 큐비트를 확보하더라도, 실제 연산을 수행할 때마다 긴 이동·측정·복구 과정이 발생한다면 전체 알고리즘 실행 시간은 상당히 길어질 수 있다.

**📌 ③ Magic State 생산 능력**

- - 대부분의 범용 FTQC 설계에서는 T 게이트를 수행하기 위해 Magic State가 필요하다.
  - 따라서 논리 큐비트 수만큼 중요한 것이 Magic State Factory의 처리량이다.
  - 논리 큐비트를 1,000개 확보했어도 Magic State 생산 속도가 부족하면 실제 알고리즘은 필요한 자원을 기다리면서 지연될 수 있다.
  - IonQ가 Walking Cat Architecture에 Magic State Factory와 Cat State 이동 구조를 포함한 이유도 여기에 있다.
  - Quantinuum 역시 이번 기술 블로그에서 Magic State Preparation의 Below-Threshold Scaling이 아직 실증되지 않았다는 한계를 인정했다.

**📌 ④ 실시간 Decoder**

- - 오류 정정에는 양자 하드웨어뿐 아니라 고속 Classical Processing이 필수다.
  - Quantinuum은 이번에 1ms 미만의 Decoder 지연시간을 보고했다.
  - IonQ도 2026년 9월 실시간 Decoder 연구에서 최대 408개 논리 큐비트와 3,150만 회 이상의 연산을 포함하는 시뮬레이션 기반 Benchmark를 사용해 CPU 기반 처리 가능성을 검증했다.
  - IonQ는 특정 조건에서 Decoder가 추가한 실행 지연을 약 0.02%로 보고했다.
  - 하지만 **이는** **실제 408개 논리 큐비트를 물리 양자컴퓨터에서 실행했다는 의미가 아니다.**
  - Quantinuum의 하드웨어 QEC 실험과 IonQ의 대규모 Decoder 시뮬레이션은 서로 다른 기술 계층을 검증한 결과다.

**📌 ⑤ 물리 큐비트 확장성 및 제조 수율**

- - 물리 큐비트 수는 여전히 결정적으로 중요하다.
  - 고품질 논리 큐비트를 만들려면 데이터 큐비트뿐 아니라 Ancilla, 측정, 냉각, 통신 및 연산 자원도 필요하기 때문이다.
  - 따라서 다음 항목들을 함께 고려해야 한다.

    - 실제 동작하는 물리 큐비트의 수
    - 물리 큐비트 전체의 Fidelity 분포
    - 제조 수율 및 불량 큐비트 대응
    - 제어 회로의 복잡성
    - 이온 이동과 냉각 오버헤드
    - QPU 간 Interconnect 성능
    - 시스템 전체 비용과 전력 소비
  - 결국 유틸리티 스케일에서는 단순히 큐비트 수가 많거나 Fidelity가 높은 것만으로 충분하지 않다.
  - **논리 연산의 신뢰성, 처리량, 확장성, 비용을 동시에 충족해야 한다.**

**✅ 8. Quantinuum은 큐비트 수를 크게 늘리지 않고도 이러한 기록을 달성했다**

**📌 이것이 장점이면서 한계이기도 하다**

- - 이번 연구는 이미 운영 중인 Helios를 이용해 오류 정정 성능을 크게 개선했다.
  - 하드웨어 큐비트 수를 확장하지 않고도 실제 논리 오류율을 낮출 수 있다는 것은 분명한 장점이다.
  - 동일한 물리 하드웨어에서 더 복잡한 코드와 Decoder를 적용하는 것만으로 성능이 향상된다면 향후 시스템의 자원 효율을 개선할 수 있기 때문이다.
  - 그러나 그 반대편에는 중요한 질문이 남아 있다.

    - **현재 98개 물리 큐비트에서 입증한 성능을 수천~수만 개 물리 큐비트에서도 유지할 수 있는가?**
  - Quantinuum은 2027년 Sol에서 2D Grid Trap을 도입하고, 2029년 Apollo로 이어지는 확장 계획을 갖고 있다.
  - 따라서 물리 큐비트를 늘리지 못하는 기술이라고 단정할 수는 없다.
  - 실제로 새로운 Grid Trap과 제어 신호 공유 기술을 개발해 왔으며, 이온 이동과 제어 확장에 필요한 실험도 진행했다.
  - 다만 이번 99.9995% 실험이 대규모 Grid Trap의 성능까지 검증한 것은 아니다.
  - 수천 개 큐비트로 확대할 때는 다음과 같은 문제가 발생할 수 있다.

    - 이온 이동 횟수 증가
    - 이동과 냉각으로 인한 지연
    - Trap Junction 통과 오류
    - 동시 연산에 따른 Crosstalk
    - 제어 및 Calibration 복잡성
    - 대규모 논리 블록 간 자원 경쟁
  - 이 문제들을 해결하지 못한다면 작은 장비에서 높은 Fidelity를 달성한 것이 대규모 FTQC 성능으로 그대로 이어지지 않을 수 있다.

- - Quantinuum은 Λ=12라는 결과를 예측해 논리 오류율 10-12를 목표로 다음과 같은 자원 추정치를 제시했다.

**✅ 9. IonQ는 오류 정정 성능을 더 높이기 전에 물리 큐비트의 확장성을 확보하려 한다**

**📌 Superion 256과 SkyWater의 역할**

- - IonQ는 2025년 Oxford Ionics를 인수하면서 전자식 큐비트 제어(Electronic Qubit Control) 기술을 확보했다.
  - 이 기술은 큐비트 제어를 반도체 제조 공정과 결합해 확장하는 데 중요한 역할을 한다.
  - 2026년 9월 Investor Day에서는 SkyWater에서 제작한 Superion 256 칩과 초기 이온 포획 성공을 발표했다.
  - 또한 10K 시스템용 Cryo-CMOS 시험 칩도 공개했다.
  - 여기서 구분해야 할 부분은 다음과 같다.

    - 256큐비트 칩 제작: 실제 진행
    - 프로토타입 이온 포획: 실제 성공
    - 256개 큐비트 전체의 99.99% 게이트 성능: 아직 별도 검증 필요
    - 10,000개 큐비트의 FTQC 성능: 로드맵 목표
  - IonQ의 전략은 반도체 제조 기반으로 물리 큐비트를 빠르게 확장하면서, 높은 물리 게이트 Fidelity와 qLDPC를 결합해 낮은 오류율과 높은 부호화율을 동시에 달성하는 것이다.

**📌 IonQ의 qLDPC 부호화 효율이 중요한 이유**

- - IonQ는 2027년 10,000개 물리 큐비트로 800개 논리 큐비트를 구현한다는 목표를 제시하고 있다.
  - 이 목표를 단순 비율로 계산하면 다음과 같다.

    - **10,000 ÷ 800 = 12.5 물리 큐비트 / 논리 큐비트**
  - 물론 이는 전체 시스템 로드맵 목표를 기반으로 계산한 것이며, 현재 실측된 물리·논리 큐비트 전환율은 아니다.
  - Quantinuum의 앞선 30,000개 물리 큐비트로 100개 논리 큐비트를 구현한다는 예측 추정과 직접 비교해서는 안 된다.
  - 서로 가정한 논리 오류율과 시스템 구조가 다르기 때문이다.
  - 그럼에도 IonQ가 고부호화율 qLDPC에 집중하는 이유는 명확하다.
  - 동일한 물리 큐비트 수에서 더 많은 논리 큐비트를 확보하고, 그 자원을 데이터 저장뿐 아니라 Magic State Factory 및 실제 논리 연산에 배분하려는 것이다.

**📌 하지만 물리 2Q Fidelity를 대규모로 유지할 수 있을까?**

- - Oxford Ionics의 99.99% 물리 2Q Fidelity는 중요한 실험 성과다.
  - 그러나 2개의 이온 사이에서 초고정밀 게이트를 구현하는 것과, 수백~수천 개 이온을 가진 시스템에서 수많은 게이트 쌍의 충실도를 동일하게 유지하는 것은 서로 다른 문제다.

    - 대규모 시스템에서는 다음을 검증해야 한다.
    - 모든 게이트 영역에서 동일한 Fidelity를 유지하는가?
    - 동시에 여러 2Q 게이트를 실행할 수 있는가?
    - 이온 이동과 냉각 과정에서도 오류율을 유지하는가?
    - QEC Syndrome 추출에 필요한 반복 연산의 오류율은 얼마인가?
    - 칩마다 제조 편차가 발생하면 어떤 영향을 받는가?
    - 물리 2Q 게이트 99.99% 자체가 10,000큐비트 FTQC를 보장하지는 않는다.
  - 그리고 IonQ의 실제 40이온 qLDPC 실험은 고부호화율 코드의 구현 가능성을 확인했지만, 대규모 시스템에서 매우 낮은 논리 오류율을 유지할 수 있다는 사실까지 입증한 것은 아니다.

**✅ 10. 둘 중 어느 전략이 유틸리티 스케일에 유리할까?**

**📌 현재 실험 성과를 기준으로 보면**

- - Quantinuum의 강점은 매우 분명하다.

    - 실제 하드웨어에서 낮은 논리 메모리 오류율 실증
    - Distance Scaling에 따른 강한 오류 억제 확인
    - 논리 Clifford 게이트 오류 억제 실험
    - Leakage 복구와 Decoder까지 결합한 QEC 개선
    - 같은 하드웨어에서 다양한 코드 검증
  - 이것은 **오류 정정이 실제로 작동하고 보호 수준을 높이면 논리 오류를 더 낮출 수 있다는 점에 대한 강력한 실험적 증거**다.
  - 반면 IonQ는 높은 물리 게이트 Fidelity와 고부호화율 qLDPC를 결합하는 아키텍처를 연구하고, 이를 실제 물리 큐비트 대량생산으로 확대하려 한다.
  - IonQ의 강점은 다음과 같다.

    - 고충실도 물리 2Q 게이트 실험
    - 실제 40이온 qLDPC 구현
    - BB 계열의 높은 부호화 효율
    - 전자식 제어와 반도체 제조 공정 통합
    - Magic State와 논리 연산을 고려한 Walking Cat Architecture
    - 실시간 Decoder 연구와 광자 Interconnect 개발
  - 그렇다면 어느 쪽이 더 유리한가?
  - 나는 평가 시점을 구분해야 한다고 생각한다.

**📌 현재의 QEC 기술적 검증에서는 Quantinuum이 앞선다**

- - 지금까지 측정된 논리 메모리 오류율과 Distance Scaling을 기준으로 한다면 Quantinuum이 더 강한 실험적 증거를 확보했다.
  - IonQ는 실제 qLDPC Breakeven 실험을 수행했지만, 아직 Quantinuum의 이번 Color Code 결과에 상응하는 강한 오류 억제 특성을 실제 하드웨어에서 검증하지 못했다.
  - 이 부분에서는 Quantinuum의 성과를 인정해야 한다.

**📌 수천~수만 큐비트 규모의 확장 전략에서는 판단이 달라진다**

- - 반면 IonQ가 계획대로 Superion 256에서 10K로 물리 큐비트를 확장하고, 고충실도 게이트 성능을 유지하면서 qLDPC 기반 FTQC를 구현한다면 이야기가 달라질 수 있다.
  - 특히 높은 부호화율과 제조 효율이 함께 실현된다면 동일한 규모의 물리 큐비트에서 더 많은 유효 논리 연산 자원을 확보할 가능성이 있다.
  - 하지만 이는 아직 조건부 가능성이다.
  - Superion 10K가 실제로 제작되고, 수천 큐비트에서 높은 Fidelity와 오류 정정 성능을 유지한다는 실험 결과가 필요하다.
  - 반대로 Quantinuum도 Sol과 Apollo의 대규모 Trap 구조에서 Helios의 오류 억제 성능을 유지한다면, 더 적은 물리 큐비트로 높은 신뢰도를 달성하는 전략이 매우 경쟁력 있을 수 있다.

**✅ 11. 앞으로 두 기업에서 확인해야 할 결정적인 지표**

**📌 Quantinuum에서 확인할 것**

- - **① Distance 9 이상의 Color Code 실험**

    - Λ≈12가 큰 코드에서도 유지되는지를 확인해야 한다.
  - **② Sol에서의 QEC 성능**

    - 2D Grid Trap으로 확대하면서 Helios 수준의 낮은 오류율을 유지할 수 있는지가 중요하다.
  - **③ 대규모 논리 연산 및 Magic State**

    - 메모리 오류율뿐 아니라 실제 논리 T 게이트와 충분히 깊은 범용 회로의 실행 결과가 필요하다.
  - **④ 논리 연산 처리량**

    - 높은 정확도를 확보하더라도 알고리즘 실행 시간이 지나치게 길어진다면 실용성이 제한된다.

**📌 IonQ에서 확인할 것**

- - **① Superion 256 전체 시스템의 실제 Fidelity**

    - 99.99%급 물리 2Q 게이트 Fidelity가 소규모 프로토타입뿐 아니라 확장된 시스템에서 유지되는지를 확인해야 한다.
  - **② 대규모 qLDPC Distance Scaling**

    - 40이온 qLDPC 실험을 넘어, 더 큰 코드에서 오류 정정 성능이 지속적으로 개선되는지를 입증해야 한다.
  - **③ qLDPC 논리 게이트 성능**

    - 고부호화율이 실제 Clifford 및 Non-Clifford 게이트 처리량으로 연결되는지가 중요하다.
  - **④ 10K 시스템의 제조 및 통합**

    - SkyWater에서 제작한 칩이 실제로 수천 개 이온을 안정적으로 제어하고, FTQC에 필요한 QEC 회로를 실행할 수 있는지를 검증해야 한다.
  - **⑤ 광자 Interconnect의 실질적인 처리량**

    - IonQ가 2026년 10월 발표한 이온–SiV 메모리 간 1kHz급 얽힘 연결 성과는 의미가 크다.
    - 그러나 FTQC 확장을 위해서는 얽힘 생성률뿐 아니라 최종 Fidelity, 반복 사용 안정성, 병렬 채널 수, 정제 비용, 원격 논리 게이트 지연을 함께 개선해야 한다.

**✅ 12. 결론 — 높은 Fidelity를 가진 작은 양자컴퓨터와 vs 대량생산 가능한 양자컴퓨터**

- - 이번 Quantinuum의 발표를 단순히 논리 오류율이 10배 개선됐다는 사실로만 평가해서는 안 된다.
  - 가장 중요한 성과는 실제 양자 하드웨어에서 오류 정정 코드의 Distance를 증가시킬수록 논리 오류가 크게 감소한다는 점을 검증했다는 것이다.
  - 이는 향후 FTQC 구현 가능성을 높여주는 중요한 실험 결과다.
  - 그러나 이번에 측정한 높은 논리 메모리 Fidelity가 대규모 논리 회로, Magic State Factory, 긴 연산 시간 및 수만 개 물리 큐비트를 가진 시스템에서도 유지될지는 아직 확인되지 않았다.
  - IonQ 역시 고충실도 물리 2Q 게이트와 반도체 기반 확장 전략을 확보했지만, 이를 결합한 대규모 QEC 시스템의 실제 성능을 증명해야 한다.
  - 따라서 두 기업의 차이는 단순히 정확도를 선택했느냐, 큐비트 수를 선택했느냐의 문제가 아니다.

    - **Quantinuum은 이미 존재하는 하드웨어에서 QEC의 효과를 반복 검증하며 높은 정확도에 접근하고 있고,**
    - **IonQ는 높은 물리 Fidelity와 제조 확장성을 확보한 뒤 고부호화율 QEC를 통합하려는 경로를 추진하고 있다.**
  - 현재 공개된 실험으로 판단하면 논리 오류 정정의 정확도와 거리 확장에 대한 증거에서는 Quantinuum이 앞서 있다.
  - 반면 IonQ의 반도체 기반 제조와 qLDPC 전략이 계획대로 구현된다면, 향후 더 큰 시스템에서 논리 큐비트 수와 처리량을 빠르게 확장할 잠재력이 있다.
  - 나는 두 전략이 결국 같은 지점에서 만나야 한다고 생각한다.
  - 물리 큐비트가 늘어나도 Fidelity가 유지되어야 하고, 논리 큐비트가 늘어나도 오류율이 충분히 낮아야 한다. 또한 Magic State 공급, Decoder, 논리 게이트 병렬 처리 및 Interconnect가 전체 알고리즘을 지연시키지 않아야 한다.

    - **FTQC의 진정한 경쟁은 누가 더 많은 큐비트를 만들었는가, 또는 누가 더 높은 단일 Fidelity 기록을 세웠는가가 아니다.**
    - **누가 충분히 많은 논리 연산을 요구된 정확도와 실용적인 시간·비용 안에서 실행할 수 있는가에 달려 있다.**
  - 이번 Quantinuum의 연구는 그 목표를 달성하기 위한 중요한 한 단계를 실제 하드웨어에서 검증했다.
  - 다음 경쟁은 높은 논리 정확도를 유지하면서 얼마나 빠르고 크게 확장할 수 있는가가 될 것이다.
