# 라우터 한 대가 아니라 장애 격리 실패가 남긴 질문

Published: 2026-11-16T21:46:16+11:00

Original Naver post: https://blog.naver.com/4-fire/224479524660?fromRss=true&trackingCode=rss

---

**✅ FAA 전국 항공 운항 중단**

- - **2026년 11월 16일 기준 분석.** 11월 13일 미국 FAA는 전국 출발 항공편의 운항을 일시 중단했다. 통신망의 이상이 여러 항로관제센터에 영향을 주었기 때문이다.
  - 핵심은 “광케이블 전환 작업 중 신형 라우터를 연결했다”라는 사건 자체보다, **원격 시설의 비정상적인 동작이 국가 공통 통신 기반에 어떻게 전파됐고 왜 충분히 격리되지 않았는가**라는 질문이다.
  - 이번 글은 **확인된 사실, 기술적 가설, 제안 가능한 해결책**을 분리한다. IonQ의 Elisity를 비롯한 보안·통신 기술도 실제 지원 범위 안에서 평가한다.
  - 이 글은 FAA·미 교통부·장비사·사업자 공식 자료와 언론 보도에 기반한 독립 분석이며, **FAA 공식 사고 원인 보고서(RCA)나 IonQ의 실제 납품 제안서가 아니다.**

---

**✅ 1. 무엇이 실제로 일어났는가**

**📌 확인된 사건 개요**

|  |  |  |
| --- | --- | --- |
| **항목** | **확인된 사실** | **의미** |
| 사고 시점 | 2026년 11월 13일 오후 약 3시 30분(미 동부시간) | 전국 Ground Stop 발령 |
| 운항 재개 | 같은 날 오후 8시 15분 | 약 4시간 45분 후 운항 재개 |
| 네트워크 현상 | 4~5초마다 약 1,000건의 연결 시도 | 초당 약 200~250건의 시도. 패킷 종류는 미공개 |
| 영향 | 22개 ARTCC 중 17개, 일부 TRACON | 음성통신과 레이더 피드의 간헐적 불안정 |
| 항공기 대응 | 당시 운항 중이던 약 3,500대 안전하게 착륙 | 전면 통신 두절이 아니라 안전을 위한 예방 조치 |
| 초기 조사 지점 | El Dorado(Arkansas), Amarillo(Texas) | 두 시설 격리 후 통신망 안정 |

- - FAA는 모든 무전기·레이더가 동시에 중단된 것은 아니라고 밝혔다. 일부 주파수와 레이더 피드는 유지됐지만, 통신 신뢰성이 떨어진 상황에서 신규 출발을 계속 허용하지 않은 것이다. 자료: [FAA 공식 Q&A](https://www.faa.gov/newsroom/nationwide-ground-stop-questions-and-answers).
  - 항공 관제사가 경험한 직접적 문제는 **불안정한 항공기 음성통신과 레이더 데이터**다. 반면 특정 인터페이스에서 링크가 내려갔는지, CPU가 포화됐는지, 라우팅 테이블이 요동쳤는지는 공식 자료에 공개되지 않았다.

**📌 증상이 시작된 두 원격 시설**

- - **El Dorado:** 항공 무선통신 시설. L3Harris가 구리 회선을 광 기반 서비스로 전환하면서 새로운 라우터를 설치하는 작업을 진행했다.
  - **Amarillo:** 레이더 시설. Duffy 장관은 약 3주 전에 교체한 장비도 El Dorado 쪽 신규 장비가 활성화될 무렵 비정상적인 데이터 전파에 관여했다고 설명했다.
  - FAA는 두 시설의 통신을 차단하고 문제 기능을 비활성화한 뒤 안정화를 확인했다. 이는 **장애 발생 지점과의 강한 연관성**을 보여주지만, 직접적인 근본 원인까지 입증한 것은 아니다. 자료: [Duffy 인터뷰](https://abcnews.com/US/live-updates/faa-ground-stop-live-updates-hundreds-flights-canceled/?entryId=138160582&id=138125140), [FAA Q&A](https://www.faa.gov/newsroom/nationwide-ground-stop-questions-and-answers).

**✅ 2. 라우터 교체만으로 전국 장애가 생겼다는 설명은 충분한가**

**📌 Broadcast라는 단어의 함정**

- - 일반적인 Layer3 라우터는 Ethernet Layer2 Broadcast를 다른 IP 서브넷으로 그대로 포워딩하지 않는다. 따라서 정부 관계자의 “Broadcast” 표현을 곧바로 **Layer2 Broadcast Storm**이라고 해석해서는 안 된다.
  - OSPF는 224.0.0.5/6과 같은 링크 로컬 멀티캐스트를 쓰지만 Hello 패킷이 전국 WAN으로 전달되는 구조는 아니다. OSPF LSA는 인접 관계를 통해 Flooding될 수 있어도, 이번 메시지가 OSPF였다는 증거는 없다.
  - BGP는 보통 TCP Unicast로 동작한다. RIP v2는 멀티캐스트를 사용한다. FAA가 언급한 “connection attempts”가 라우팅 프로토콜, 접속 재시도, 서비스 제어 메시지 또는 특정 애플리케이션 세션인지는 미공개다.
  - 초당 200~250회의 시도는 현대 라우터의 순수 Forwarding 성능만으로는 큰 부하라고 보기 어렵다. 다만 구형 서비스 장비의 CPU 처리, 세션 생성, 재인증 또는 반복적인 복구 절차에 집중된다면 심각한 문제가 될 수 있다. **이는 기술적 가능성이지 사건의 확정 원인은 아니다.**

**📌 왜 69대 중 두 시설만 문제가 되었나**

- - Duffy는 관련 라우터가 69대이며 Broadcast 기능을 비활성화했다고 밝혔다. FAA 공식 Q&A는 유사 장비 **약 60대**에 예방 조치를 적용했다고 표현한다. 두 숫자는 발표 범위가 서로 다를 수 있으므로 일치하는 수량이라고 단정하지 않는다.
  - 69대가 모두 같은 Juniper 모델인지, 동일한 구성으로 설치됐는지, 혹은 동일한 시기에 교체됐는지는 확인되지 않았다. 따라서 “69대 전부가 신규 설치됐는데 67대는 멀쩡했다”는 전제도 확정 사실은 아니다.
  - 나머지 장비들과 차이가 있었을 수 있는 요인은 **장비 설정, 연결된 서비스, 상대방 장비의 응답 방식, 원격 시설의 토폴로지, 기능 활성화 시점** 등이다.
  - 특히 Amarillo 장비가 3주 동안 운영되다가 El Dorado 변경 직후 같은 유형의 문제에 관여했다면, **두 지점 간 공통 서비스·설정·연결 조건**을 조사할 이유가 있다. 직접 연결됐다고 증명된 것은 아니다.

**📌 Cisco 600, Juniper 모델, 외부 4G 연결은 확인됐나**

|  |  |
| --- | --- |
| **질문** | **현재 확인 가능한 답** |
| 신규 Juniper 모델 | Juniper 제품으로 보도됐지만 정확한 모델명·Junos 버전은 미공개. SRX·ACX·MX 추정은 확인된 사실이 아님 |
| 기존 Cisco 600 계열 | 2001년경 장비라는 발언과 Cisco 600/6000이라는 보도가 있으나 정확한 SKU가 특정되지 않음. 소형 DSL Cisco 600이라고 확정할 수 없음 |
| 두 지점의 4G·위성·외부망 포트 | 해당 라우터의 인터페이스 구성과 4G/LTE 연결 여부 미공개. Radio Site라는 명칭이 4G 기지국을 뜻하지는 않음 |
| 제조사 주장 | HPE는 라우터가 설치자의 설정대로 작동했다는 입장. 최종 조사로 검증되기 전까지 하드웨어 결함 또는 작업자 과실을 확정할 수 없음 |

- - 자료: [HPE/Juniper 입장](https://abc7ny.com/live-updates/faa-ground-stop-live-updates-what-know-nationwide-flights-are-grounded/20038887/entry/20042608/), [장비 조사 보도](https://www.wsj.com/business/airlines/the-single-router-in-southern-arkansas-that-ground-air-travel-to-a-halt-eedc326c). 이번 사건의 원인을 Cisco 라우터의 낮은 CPU 성능이나 Juniper의 특정 버그로 단정하지 않는 이유다.

**✅ 3. 진짜 구조적 문제: 이중화와 장애 격리는 다르다**

- - **링크 이중화**는 케이블이나 라우터 하나의 고장을 우회할 수 있게 해 준다. 그러나 **공통 제어 경로, 서비스 세션, 관리 시스템, 전송 구간**이 동일하게 영향을 받으면 백업 장비도 장애를 공유할 수 있다.
  - 예를 들어 두 회선이 서로 다른 Carrier 명의로 제공되도 실제로는 같은 관로, 같은 건물의 장비실, 같은 광전송 장비나 같은 코어 라우터를 경유할 수 있다.
  - 따라서 통신망 복원력은 회선 개수보다 **물리 경로 분리, 장비 및 Control Plane의 독립성, 서비스별 Failure Domain 제한, 자동 장애 전환의 안정성**으로 평가해야 한다.
  - 특히 이번 사고가 기존 장비와 백업 경로에까지 영향을 주었다면 단순한 Dual-Homing으로 충분했는지 검토해야 한다. 실제 전파 과정은 여전히 조사 중이다.

**📌 변경 관리가 왜 중요했나**

- - FAA는 주요 관제시설의 정비를 주로 야간에 수행하지만 원격 사이트의 통상적인 장비 교체는 낮에도 진행해 왔다고 밝혔다. 사고 이후 원격 사이트 정비 시간도 재평가하겠다고 했다. 자료: [FAA 공식 Q&A](https://www.faa.gov/newsroom/nationwide-ground-stop-questions-and-answers).
  - 하지만 야간 작업으로 옮기는 것만으로는 문제가 해결되지 않는다. 중요한 것은 **사전 영향 범위 검증, 단계별 활성화, 관측 가능한 테스트, 빠른 롤백과 자동 격리 경로**다.
  - 문제 발생 지점의 정확한 추적 절차는 공개되지 않았다. 어떤 로그·NetFlow/IPFIX·패킷 캡처·유지보수 기록을 근거로 두 사이트를 특정했는지까지는 아직 알 수 없다.

**✅ 4. FTI, FENS, BNATCS와 통신사업자 역할**

**📌 기존망과 미래망은 다른 계약이다**

|  |  |  |  |
| --- | --- | --- | --- |
| **구분** | **계약·조직** | **담당 역할** | **이번 사고와의 관계** |
| FAA | 미 연방항공청 | 관제 서비스 운영·안전감독·발주 | Ground Stop 결정·조사 |
| FTI | L3Harris | 현재 FAA 전국 통신망의 통합 서비스 공급·운영 | 사고 당시 진행한 원격 사이트 작업 |
| Carrier | 지역별 통신사업자 | 실제 Copper/Fiber 등 지역·장거리 회선 공급 | 두 현장의 사업자 명칭은 미확인 |
| FENS | AT&T 주도, Verizon 지원 | FTI를 대체할 신규 엔터프라이즈 통신망의 설계·구축·전환 | 이번 사고가 발생한 망은 아님 |
| BNATCS | Peraton 총괄 통합 | 통신·레이더·관제 소프트웨어 등을 포함한 항공관제 현대화 총괄 | 차세대 개선 사업의 통합 책임 |
| 장비 제조사 | Juniper/HPE, Cisco 등 | 라우터 공급 및 기술 지원 | 장비 결함·설정·호환성 조사 대상 |

- - 즉 계약의 순서는 “Harris → AT&T → Verizon”이 아니다. **기존 FTI는 L3Harris가 운영**하고, FENS는 당초 Verizon이 주계약자였다가 2026년 AT&T가 주도하는 형태로 전환됐다. Verizon은 새 네트워크의 핵심 기능 지원 역할로 보도됐다.
  - AT&T는 단순한 회선 판매자만이 아니라 **FENS의 엔드투엔드 사업을 책임질 주계약자**다. 자사망과 타 통신사업자망을 조합할 수 있다. 그러나 El Dorado 현장의 실제 Fiber 공급사가 AT&T였다는 근거는 없다.
  - 2026년 8월 AT&T에 부여된 약 7,430만 달러는 FENS 초기 개발·계획 작업과 관련된 계약으로 확인된다. 이후 전체 장기 계약의 확정 범위와 동일시해서는 안 된다. 자료: [미국 정부 계약 기록](https://www.usaspending.gov/award/CONT_AWD_693KA826F00278_6920_693KA826D00016_6920/), [FENS 사업자 역할 보도](https://www.nextgov.com/modernization/2026/08/faa-brings-t-network-modernization-program/415417/).
  - Peraton은 해당 사고의 원인 장비를 운영한 회사라기보다 **BNATCS 현대화 사업 총괄 통합업체**다. 자료: [FAA 발표](https://www.faa.gov/newsroom/trumps-transportation-secretary-duffy-faa-administrator-bedford-announce-prime-integrator).

**✅ 5. 현대화 압력: 트럼프의 신속 추진 요구와 예산 문제**

**📌 사건 이전부터 확인된 노후화 위험**

- - 미 회계감사원(GAO)의 2024년 공식 감사에 따르면 FAA 항공관제 주요 시스템 138개 가운데 **51개는 지속 운영이 어렵고, 54개는 잠재적으로 지속 운영이 어렵다**고 평가됐다. 즉 105개(약 76%)에 노후화·유지관리 위험이 있었다. 모든 시스템이 즉시 작동 불가능하다는 뜻은 아니다. 자료: [GAO 공식 감사](https://www.gao.gov/products/gao-24-107001).
  - FAA는 2025년 12월 BNATCS 계획에서 2028년 말까지 전면적인 현대화를 추진한다는 목표를 제시했다. 이는 계획상의 목표일 뿐, 현재 달성된 일정을 의미하지 않는다. 자료: [BNATCS 사실자료](https://www.faa.gov/newsroom/brand-new-air-traffic-control-system-bnatcs-fact-sheet).

**✅ 8. 파일럿은 ARTCC 한 곳부터, 그러나 WAN 경계까지 포함해야 한다**

- - 하나의 ARTCC를 시작점으로 삼는 것은 합리적이다. 다만 시설 내부 스위치만 측정하면 이번 사고처럼 **원격 Radio/Radar Site에서 발생한 문제가 공통 백본으로 확산되는 현상**을 검증하지 못한다.
  - 따라서 초기 파일럿의 범위는 **ARTCC 1개 + 연결된 대표 원격 시설 + FTI/FENS 연결 경계 + 격리된 시험환경**으로 구성하는 것이 바람직하다. 실제 운영망에서 고장·폭주를 재현해서는 안 된다.
  - Elisity 정책은 Passive Visibility → Policy Simulation → 사전 승인된 제한적 Enforcement → 장애 및 복구 검증 순서로 도입한다. 핵심 관제 트래픽은 테스트 중에도 필수 허용 목록으로 보호해야 한다.

|  |  |  |
| --- | --- | --- |
| **단계** | **검증 목적** | **측정 지표·합격 기준 예시** |
| 1. Passive Monitoring | 기본 통신 맵과 장비 식별 | 자산 식별률, 흐름 분류 정확도, 기존 서비스에 추가된 지연·손실 |
| 2. Policy Simulation | 차단 정책의 영향 예측 | 관제 필수 트래픽 오차단 여부, 예상 Deny Flow, 정책 오류율 |
| 3. Controlled Enforcement | 의심 단말·흐름 선택 차단 | 탐지 시간 MTTD, 차단 시간 MTTC, 허용 서비스 가용성 |
| 4. Failure Drill | 격리·전환·복구 절차 검증 | 복구 시간 MTTR, 백업 경로 독립성, 자동/수동 롤백 성공률 |
| 5. 운영 통합 | NOC/SOC 및 FAA 절차 연동 | 알람 상관분석 정확도, 승인 절차, 변경 감사·로그 무결성 |

- - MTTD(Mean Time to Detect), MTTC(Mean Time to Contain), MTTR(Mean Time to Recover)는 제안되는 평가 지표다. FAA나 IonQ가 달성한 기존 성능 수치는 아니다.
  - 자동 복원은 탐지만큼 중요하지만, 항공관제망에서는 이상이 사라졌다는 이유만으로 즉시 전체 정책을 해제해서는 안 된다. **정상 상태 검증, 운영자 승인, 단계적 서비스 복원, 재발 감시**가 필요하다.
  - 성공 조건의 최우선 항목은 **보호 솔루션이 새로운 장애 원인이 되지 않는다는 것**이다. 별도의 Management Path, Fail-Safe 동작 및 안전성 검증이 필수다.

**✅ 10. 결론: 광케이블 교체보다 중요한 것은** **장애가 전파되지 않는 설계****다**

- - 이번 사고는 “오래된 Cisco가 나빴다” 또는 “새 Juniper가 잘못됐다”로 단순화할 수 없다. **새로운 연결이 만들어낸 비정상 동작을 공통 FAA 통신망이 왜 견디거나 격리하지 못했는가**가 핵심이다.
  - 원인이 장비 결함이든, 설정 오류든, 사이버 공격이든 핵심은 동일하다. 특정 장비나 네트워크 구간에서 발생한 문제가 전체 시스템으로 확산되지 않도록 차단하고, 정상적인 서비스는 최대한 유지해야 한다.
  - 전국적인 항공 운항을 약 4시간 동안 중단시키는 대신, **문제가 발생한 구간만 신속하고 선택적으로 격리하고 안전하게 복구할 수 있는 자동화된 장애 탐지·격리·복구 솔루션**이야말로 FAA가 가장 우선적으로 확보해야 할 역량이라고 판단한다.
  - PQC/QKD, 정밀 시각, 광 통신, 신뢰 가능한 반도체 제조, 양자컴퓨팅은 각각 가치가 있지만 즉시 필요한 네트워크 장애 대응과 혼동해서는 안 된다.
  - 가장 설득력 있는 제안은 **“FAA 통신망을 IonQ가 대체한다”가 아니라 “기존 계약자들과 협력하여 장애의 조기 탐지, 확산 방지, 안전한 복구, 핵심 서비스 연속성을 정량적으로 개선한다”**는 것이다.
  - 현재 공개된 자료에서 FAA가 IonQ 또는 Elisity를 이번 장애의 공식 해결책으로 선정했다는 사실은 확인되지 않는다. 이 글의 적용 방안은 기술적 분석과 사업 가설이다.
