**✅ VII. LOGICAL INSTRUCTION SET**

- - 앞 Section VI에서는

    - 어떤 Pauli가 측정 가능한지
    - 어떤 Clifford가 frame-tracking 가능한지
  - “가능한 연산의 범위”를 정의했다
  - 이제 여기서는 한 단계 더 나간다:

    - “그럼 실제로 어떤 명령어로 계산을 구성할 것인가?”
  - 즉, 가능한 연산 정의 → 실제 instruction set 구성
  - 그리고 중요한 선언:

    - 이 아키텍처는 gate-based가 아니라 Pauli measurement 기반 instruction system

**📌 Logical Instruction Set 구성**

- - 논문이 정의하는 instruction은 다음 6가지다
  - **(1) LZ — Logical zero preparation**

    - |0⟩ 상태로 초기화

      - 블록 전체 logical qubit reset
  - **(2) LP — Logical plus preparation**

    - |+⟩ 상태로 초기화

      - 역시 블록 전체 reset
  - **(3) LT — Logical magic state preparation**

    - |H⟩ 상태 생성 (magic factory에서)

      - T gate 구현을 위한 핵심 리소스
  - **(4) LM1 — In-block measurement**

    - 같은 block 내부에서 logical Pauli 측정
  - **(5) LM2 — Inter-block measurement**

    - 서로 다른 block 간 joint measurement
    - 여기서 Bell + cat stitching 등장
  - **(6) CLIF — Logical Clifford**

    - frame-tracking으로 수행 (실제 gate 없음)

**📌 중요한 구조적 특징**

- - **📌 핵심 1 —** **“모든 연산은 measurement 중심”**

    - 이 아키텍처에서는:

      - gate 실행 ❌
      - measurement 실행 ⭕
    - 즉:

      - 계산 = 측정 sequence
      - gate = measurement + classical update
  - **📌 핵심 2 —** **Block 단위 실행**

    - 모든 instruction은 **block 기준으로 수행**
    - 특히:

      - LM2 → 두 block 필요 나머지 → single block
    - 즉, 연산 단위 = qubit ❌ 연산 단위 = block ⭕
  - **📌 핵심 3 —** **Magic factory는 특별한 존재**

    - LT는 memory block에서 실행 불가
    - 반드시 **magic factory 필요**
    - 구조:

      - Memory → 계산 Magic → T resource 공급

**📌 Destructive Measurements (새로운 instruction)**

- - 논문은 추가로 2개를 정의한다:

    - **DMX — Destructive X measurement**
    - **DMZ — Destructive Z measurement**
  - 특징:

    - 측정하면서 상태를 “파괴”
  - 장점:

    - 빠름
    - 한 번에 많은 측정 가능
    - decoder와 바로 연결됨
  - 조건:

    - Clifford frame에 따라 측정 대상이 바뀜

**📌 실제 연산 방식**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjVfMTYg/MDAxNzc3MTExMTYzMjE4.xFnZbj3aIX_BntTN8n7RcnoEGmaaCFlt9xHO3peCv9kg.pM9BEXuPzJdyeCPKlXO9ZkzD7JxfUCNxogiI-Dq7TfQg.PNG/image.png?type=w800)](#)

- - 모든 logical measurement는 cat state 사용
  - 흐름:

|  |
| --- |
| cat state 생성  → 데이터 큐비트와 결합  → 측정  → 결과 decoder로 전달 |

- - 핵심 특징:

    - cat state는 measurement 후 사라짐
    - 여러 개 소비됨
    - 오류 줄이기 위해 반복 측정
  - **3가지 측정 방식**

    - **논리 → 물리로 변환**
    1. **EDM (Error-detected measurement)**

       - 불일치 나오면 실패
       - → 보수적, 안정적
    2. **ECM (Error-corrected measurement)**

       - 여러 번 측정 → majority vote
       - → 더 강한 오류 내성
    3. **Viterbi-based (adaptive)**

       - decoder가 실시간 판단
       - → 효율 + 빠름

- - T gate는 직접 수행 안 함:

    - magic state + measurement + 보정
  - 두 방식 존재:

    - CH2 factory → Clifford 조건 만족 (빠름)
    - MEK factory → 더 일반적 (하지만 2-step)

**📌 Logical connectivity & Parallelism (아키텍처 핵심)**

- - 이 구조의 가장 중요한 특징:

    - **Full connectivity**

      - 어떤 block이든 서로 연산 가능
      - → 거리 제한 없음
    - **Full parallelism**

      - 여러 block에서 동시에 실행 가능
      - 결과:

        - 성능 = 병렬 처리 능력
    - **어떻게 가능하냐?**

      - cat factory pipeline
      - Bell state routing
      - 즉, resource 공급 속도가 병렬성을 결정

> *Walking Cat에서 계산은 “gate 실행”이 아니라,*
>
> *“measurement instruction들의 스케줄링과 resource 소비”로 이루어진다*.

**✅ VIII. INSTANCES OF THE WALKING CAT ARCHITECTURE**

- - 앞에서:

    - 구조 정의함 (Memory, Magic, Cat, Bell, Qubit)
    - 연산 정의함 (measurement 기반)
  - 이제 여기서 하는 일:

    - “그래서 이걸 실제로 구성하면 규모 / 비용 / 성능이 어떻게 되냐?”
    - 즉, 이론 → 실제 시스템 사이즈 & 성능 추정

**📌 기본 가정 (중요)**

- - 이 섹션의 모든 숫자는 아래 기준:

    - physical error rate: p = 10-4
    - leakage: p\_leak = 10-5
    - loss: p\_loss = 10-7
    - 시간 단위:

      - 1 POC ≈ 200 μs
      - transport ≈ 10 μs
  - 핵심:

    - 현실적인 trapped-ion 수준 가정

**📌 Architecture Configuration (구성 정의)**

- - **아키텍처는 이렇게 정의됨**

|  |
| --- |
| 몇 개의 memory block  +  몇 개의 magic factory  +  어떤 코드 (Q54 / Q70 / Q102) |

- - **표기법**

|  |
| --- |
| N\_M × Memory + N\_T × Magic factory |

- - - 예:

      - N\_M × Q102 + N\_T × CH2
    - 의미:

      - Q102 → 메모리 코드
      - CH2 / MEK → magic factory 종류
    - **코드 선택 (핵심)**

      - 논문은 3개 사용:

        - Q54
        - Q70
        - Q102
      - 특징:

|  |  |
| --- | --- |
| **코드** | **특징** |
| Q54 | 작은 블록 |
| Q70 | 중간 |
| Q102 | 밀도 높음 (가장 중요) |

- - - 결과:

      - SEC ≈ 30 POC ≈ 6ms
  - **중요한 설계 선택**

    - memory는 같은 코드로 통일
    - magic factory도 동일 구조
    - 이유:

      - 복잡도 줄이기

**📌 Component Allocation (구성 배치)**

- - **기본 규칙**

    - memory block 하나당 cat factory 1개
    - magic factory 하나당 cat factory 1개
    - 이유:

      - measurement 병렬성 최대화
  - **width 설정**

    - Q70 → logical width = 6
    - Q102 → logical width = 3
    - 의미:

      - 한 번에 측정 가능한 Pauli 크기
  - **magic factory 특징**

    - MEK → Q70 기반
    - CH2 → Q54 기반 (더 큰 cat 필요)
  - **Bell factory 개수**

    - ≈ N / 3
    - 이유:

      - stitching (cat 연결)
  - **Reservoir (버퍼)**

    - ≈ 200 qubits
    - 역할:

      - qubit loss 대응
      - 공급 안정화

**📌 Transport Overhead (이동 비용)**

- - **문제**

    - cat state는:

      - 만들고 → 보내고 → 쓰고 → 다시 돌아감
    - 그래서:

      - 칩 전체를 도는 outer loop 필요
  - **결과**

    - 추가 qubit 필요:

      - ≈ t / f

        - t = 이동 시간
        - f = 생산 속도
    - 의미:

      - transport 자체도 리소스 먹는다
  - **중요한 판단**

    - 논문 선택:

      - 복잡한 최적 경로 ❌
      - 단순 outer loop ⭕
    - 이유:

      - transport qubit 비중은 전체에서 작음

**📌 Qubit Allocation (전체 자원)**

- - 이 부분이 핵심이다.
  - **실제 규모**

    - **예:**

      - 200 logical qubits
      - 1M ~ 10M T gates/day
    - 결과:
    - 물리 큐비트 수: 수천 ~ 수만
  - **중요한 관찰**

    - **1) Q102 강력**

      - 높은 density → qubit 효율 좋음
    - **2) T gate 늘어나면**

      - magic factory ↑ → 전체 qubit ↑
    - **3) CH2 vs MEK**

      - CH2 = qubit 더 적게 씀
    - 이유:

      - 더 효율적인 magic 생산

**📌 Logical Instruction Set 영향**

- - 이 구조에서:

    - instruction set = 코드 + width에 따라 결정
  - **실행 시간 계산**

    - 시간은 SEC 기준으로 계산 → 이후 ms로 변환
  - **LM2 (블록 간 연산)**

    - 문제:

      - 다른 코드끼리 속도 다름
    - 해결:

      - 느린 쪽 기준으로 동기화

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjVfMjky/MDAxNzc3MTEzMTc5Mjcy.06Ee6uJly_KXuMkkkymIgOe50LMg80V6cPJTnm8Z9b4g.6gj_K1o1MhJlAq48kTMF5XO4IB0UdSoQxkzLhUbsl4Mg.PNG/image.png?type=w800)](#)

- - **(a) 1M T gates/day (저속 구성)**

    - **구조 3개 비교**

|  |  |  |
| --- | --- | --- |
| **구성** | **물리 qubit** | **특징** |
| 34×Q70 + 3×MEK | 10,625 | MEK 적음 |
| 34×Q70 + 1×CH2 | 10,239 | 효율형 |
| 10×Q102 + 1×CH2 | **4,540** | 초고밀도 |

- - - **핵심 해석**
    - 같은 logical (~200)인데:

      - Q102 사용 → **물리 qubit 절반 이하**
      - Q70 → 안정적, 대신 비효율
  - **(b) 10M T gates/day (고속 구성)**

    - 같은 logical (~200)인데:

|  |  |
| --- | --- |
| **구성** | **물리 qubit** |
| 34×Q70 + 24×MEK | **17,000** |
| 34×Q70 + 9×CH2 | 13,264 |
| 10×Q102 + 10×CH2 | 7,559 |

- - - **핵심 변화**

      - Magic (보라색) 급증
    - **의미**

      - 속도 ↑ = T factory (Magic) 증가

**📌 Single-Code Architecture**

- - **단순화 버전**

    - 전부 같은 코드만 사용
    - 예:

      - N\_T × MEK
  - **특징**

    - magic factory가 memory 역할도 가능
    - 의미:

      - 역할 전환 가능 (flexible)
  - **tradeoff (Fig. 11 핵심)**

    - logical qubit ↑ → T 생산 ↓ T 생산 ↑ → logical qubit ↓
    - 핵심:

      - compute vs resource tradeoff

> *이 섹션은 “이 아키텍처를 실제로 만들면 몇 개의 큐비트가 필요하고 얼마나 빠르게 계산할 수 있는지”를 정량적으로 보여주는 파트다.*
