# Fast logical operations in quantum LDPC codes using simple resource states

Published: 2026-07-21T16:21:07.620000+09:00

Original Naver post: https://blog.naver.com/4-fire/224353334531

---

**✅ 서론: qLDPC는 이제 ‘오류를 고치는 것’을 넘어 ‘빠르게 계산하는 것’으로**

- - IonQ의 양자 오류정정(QEC) 연구가 또 한 단계 앞으로 나아갔다.
  - 지난 몇 년간 IonQ와 그 연구진이 발표해온 qLDPC 관련 연구의 흐름을 따라가 보면, 각각의 논문이 서로 독립된 결과라기보다 하나의 명확한 로드맵을 따라 차례대로 쌓이고 있다는 점이 흥미롭다.

    - 2025년 발표된 ***Quantum Error Correction for Long Chains of Trapped Ions***에서는 이온트랩 시스템의 긴 이온 체인에 적합한 qLDPC 코드와 syndrome extraction 방법을 연구하며, 적은 물리 큐비트로 높은 수준의 오류정정을 구현할 가능성을 제시했다.
    - 이어 2026년 4월 발표된 ***Walking Cat Architecture***에서는 이를 한 단계 확장해 Q70 [[70,6,9]], Q102 [[102,22,9]]와 같은 고밀도 qLDPC 코드를 기반으로 syndrome extraction, decoder, cat-state factory, logical operation, compiler까지 연결한 본격적인 fault-tolerant quantum computing 아키텍처를 제시했다.
    - 그리고 2026년 6월의 ***Breakeven Demonstration of qLDPC Codes***에서는 이러한 아이디어가 단순한 이론이나 시뮬레이션에 머무르지 않고 실제 이온트 하드웨어에서도 작동할 수 있음을 보여주었다. 여러 종류의 QEC 코드를 실제 장비에서 구현하고, 일부 qLDPC 실험에서 논리 큐비트의 수명이 물리 큐비트 수준을 넘어서는 breakeven 영역에 도달하며 qLDPC의 실질적인 가능성을 입증했다.
  - 그렇다면 자연스럽게 다음 질문이 생긴다.

    - **오류를 정정해 논리 큐비트를 안정적으로 만들 수 있다면, 이제 그 논리 큐비트로 실제 계산을 얼마나 빠르게 수행할 수 있을까?**
  - 이번에 발표된 ***Fast Logical Operations in Quantum LDPC Codes Using Simple Resource States***는 바로 이 질문에 답하려는 연구다.
  - qLDPC의 가장 큰 장점은 하나의 코드 블록 안에 여러 논리 큐비트를 매우 높은 밀도로 인코딩할 수 있다는 점이다. 그러나 이 장점은 동시에 약점이 되기도 한다. 여러 논리 큐비트가 하나의 물리적 코드 블록을 공유하기 때문에, 개별 논리 큐비트를 읽고 조작하거나 복잡한 논리 연산을 수행하는 과정이 오히려 느려질 수 있기 때문이다.
  - 이번 연구는 이 병목을 해결하기 위해 복잡한 resource state 대신 비교적 단순한 **cat state**, 여러 logical Pauli measurement를 하나로 묶어 처리하는 **scheduler code**, 그리고 Clifford Noise Reduction(CliNR)을 결합하는 새로운 방법을 제안한다.
  - 그 결과 상세 시뮬레이션 기준으로, Q70에서는 5개의 계산용 논리 큐비트에 대한 random Clifford 연산의 cat-based measurement 비용을 약 **17.6배**, Q102에서는 21개의 계산용 논리 큐비트에 대해 무려 **63.4배** 줄이는 결과를 보여준다. 이는 QEC 자체의 오류정정 성능을 63배 높였다는 의미는 아니다. 복잡한 logical Clifford 연산을 기존처럼 수많은 작은 gate와 measurement로 순차 실행하는 대신, 연산 전체를 resource state preparation과 joint measurement 문제로 바꾸면서 필요한 cat-based measurement 수를 극적으로 줄였다는 의미다.
  - 특히 주목할 점은 이번 논문의 두 저자다.

    - **Mark Webster**는 양자 오류정정과 stabilizer code를 전문으로 연구해온 연구자로, University of Sydney에서 Stephen Bartlett 교수의 지도로 박사학위를 수행하며 XP stabilizer formalism과 transversal logical operator를 연구했다. 이후 UCL의 Dan Browne QEC 그룹에서 연구했으며, 2026년 Oxford Ionics에 QEC Researcher로 합류했다. 특이하게도 연구자가 되기 전에는 전략 컨설팅과 기업 경영 분야에서 오랜 경력을 쌓은 인물로, 이론적 QEC뿐 아니라 실제 시스템에서 사용할 수 있는 효율적인 오류정정 구조를 찾는 데 강점을 가진 연구자다.
    - 공동 저자인 **Nicolas Delfosse**는 IonQ의 QEC 연구를 이끌고 있는 핵심 연구자 중 한 명이다. 수학과 양자 오류정정을 배경으로 오랫동안 quantum code, decoding, fault-tolerant architecture를 연구해왔으며, IonQ가 최근 추진하고 있는 qLDPC 기반 QEC 전략의 중심에서 연속적으로 중요한 연구 결과를 내놓고 있다. 그의 연구에서 반복적으로 나타나는 특징은 단순히 더 좋은 코드를 만드는 데 그치지 않고, **syndrome extraction, decoder, logical operation, hardware architecture를 하나의 시스템으로 연결하면서 실제 계산 비용을 줄이는 것**에 집중한다는 점이다.
  - 이번 논문 역시 그 연장선에 있다.

    - **“그렇게 보호된 논리 큐비트로 실제 양자 계산을 어떻게 더 빠르게 수행할 것인가?”**
  - 이번 논문은 qLDPC를 단순히 정보를 오래 보존하는 ‘좋은 양자 메모리’에서 실제 유용한 계산을 빠르게 수행하는 ‘양자 컴퓨터’로 발전시키기 위해 반드시 해결해야 할 문제를 다룬다.
  - 특히 Q102처럼 하나의 코드 블록에 22개의 논리 큐비트를 담을 수 있는 고밀도 qLDPC에서는 논리 큐비트 수가 많아질수록 기존 gate-by-gate 방식의 연산 비용이 급격히 증가한다. 반면 이번 연구가 제안하는 resource-state 기반 방식은 문제 크기가 커질수록 상대적인 이점이 더욱 커질 가능성이 있다.
  - 따라서 이번 논문의 진정한 의미는 단순히 “cat-based measurement를 수십 배 줄였다”는 숫자에만 있지 않다.
  - **qLDPC가 가진 높은 인코딩 효율을 실제 계산 속도의 이점으로까지 연결할 수 있는 새로운 길을 제시했다는 것.**
  - 이것이 이번 연구에서 가장 주목해야 할 부분이다.

**✅ 출발점: qLDPC의 가장 큰 장점은 높은 encoding rate다**

- - 저자들은 QEC가 fault-tolerant quantum computer의 핵심이라고 전제하면서, 최근 qLDPC가 이론·시뮬레이션·아키텍처·실험 측면에서 빠르게 주목받고 있다고 설명한다.
  - Surface code와 비교했을 때 qLDPC의 가장 중요한 장점은 **하나의 코드 블록에 여러 logical qubit을 동시에 encode할 수 있기 때문에 physical-qubit overhead를 크게 줄일 수 있다는 것**이다.
  - 예를 들어 Walking Cat의:

    - Q70 = [[70,6,9]]
    - Q102 = [[102,22,9]]
  - 처럼 하나의 블록 안에 여러 logical qubit을 넣을 수 있다.
  - 그런데 바로 이 장점이 동시에 새로운 문제를 만든다.

---

**✅ qLDPC의 역설: 저장 효율은 좋은데 logical qubit을 조작하기 어렵다**

- - Surface code에서는 logical qubit들이 비교적 개별적인 패치 형태로 존재한다.
  - 반면 qLDPC에서는 **여러 logical qubit이 같은 physical-qubit block 안에 서로 얽혀 encoding**되어 있다.
  - 그래서 저자들이 지적하는 핵심 병목은 **여러 logical qubit을 한꺼번에 조작하려 하면 logical access가 어려워지고, 그 결과 logical operation이 느려질 수 있다**.는 것이다.
  - 즉 qLDPC에는 이런 trade-off가 있다.

|  |
| --- |
| 높은 encoding rate  ↓  적은 physical qubits로 많은 logical qubits 저장  ↓  하지만 여러 logical qubits가 한 block을 공유  ↓  **logical operation / measurement가 복잡해짐**  ↓  **연산 속도 병목** |

- - 이번 논문은 바로 **마지막 두 단계의 병목을 해결하려는 논문**이다.
  - 즉 새로운 qLDPC 코드를 만드는 논문이라기보다, **이미 qLDPC 안에 encode된 여러 logical qubit을 어떻게 더 빠르게 읽고 조작할 것인가**를 다룬다.

---

**✅ 기존 해결책: 복잡한 graph-based resource state**

- - qLDPC에서 빠른 logical measurement를 하기 위해 기존 연구들은 주로 **graph-based resource state**를 사용해왔다.
  - 그런데 저자들은 이 접근에 세 가지 현실적인 문제를 지적한다.

**📌** **첫째, resource state가 너무 복잡하다**

- - logical measurement를 할 때마다 memory code와 resource state를 결합해 **새로운 merged code**를 형성해야 한다.
  - 즉 단순한 ancillary state 하나를 잠깐 붙이는 정도가 아니라:

|  |
| --- |
| Memory qLDPC block  +  Complex resource state  ↓  새로운 merged code 형성  ↓  logical measurement |

- - 같은 구조다.
  - 그래서 하드웨어가 이런 다양한 merged code 구조를 수용해야 하는 부담이 커진다.

**📌** **둘째, 수학적 형식이 복잡하다**

- - 기존 방식은 주로 **homological algebra**로 기술된다.
  - 이론적으로 매우 우아하지만, 실제 하드웨어 엔지니어링이나 QEC 시스템 관점에서는 접근성이 떨어질 수 있다고 저자들은 지적한다.
  - 이번 프로토콜은 **회로 그림만 보아도 무엇을 하는지 비교적 직접 이해할 수 있다**는 점을 강조한다.

**📌** **셋째, 실제 practical performance 검증이 부족하다**

- - 기존 연구는 대체로 **"asymptotically fault tolerant하다"**는 이론적 증명에 집중한다.
  - 하지만 실제 finite-size code에서

    - 몇 번 measurement가 필요한가?
    - 얼마나 빠른가?
    - 실제 물리 오류율에서 overhead가 얼마인가?
  - 같은 실용적인 성능은 더 연구할 필요가 있다는 것이다.

---

**✅ 이번 논문의 철학: 복잡한 resource state 대신 cat state만 쓰자**

- - 저자들의 해법은 의외로 단순하다.
  - **Shor-style measurement**를 사용한다.
  - 필요한 ancillary resource는 ∣00⋯0⟩+∣11⋯1⟩ 형태의 **cat state**뿐이다.
  - cat state는 memory qubit들과 **한 time step 동안만 상호작용한 뒤 바로 측정**된다.
  - 따라서 기존 방식처럼 memory와 auxiliary를 장시간 결합해 새로운 merged code를 만들 필요가 없다.
  - 구조적으로 비교하면:
  - **기존 graph-resource 방식**

|  |
| --- |
| Memory  +  Complex resource state  ↓  Merged code 형성  ↓  logical measurement |

- - **이번 방식**

|  |
| --- |
| Cat state 준비  ↓  측정할 physical qubits 옆으로 이동  ↓  한 번 interaction  ↓  Cat state 측정  ↓  끝 |

- - - 훨씬 단순하다.

---

**✅ 왜 이온트랩과 특히 잘 맞는가**

- - 여기서 IonQ와 직접 연결되는 부분이 있다.
  - 이 방법은 cat state를 **측정하려는 qubit 근처로 가져와야 한다.**
  - 따라서 저자들은 이 방식이 **qubit 자체를 이동시킬 수 있는 플랫폼**에 특히 적합하다고 말한다.
  - 논문이 직접 언급하는 플랫폼은:

    - trapped ions
    - neutral atoms
    - spin qubits
    - electrons on helium
  - 이다.
  - 특히 Walking Cat은 이온트 QCCD의 **ion transport** 능력을 전제로 설계되었기 때문에 이 접근과 자연스럽게 연결된다.
  - 즉 cat state를 필요한 위치로 보내:

|  |
| --- |
| Cat-state factory  ↓  ion transport  ↓  필요한 data qubits 주변  ↓  logical Pauli measurement |

- - 를 수행하는 것이다.

---

**✅ 아주 중요한 철학적 문장: “모든 연산이 strict fault-tolerant일 필요는 없다”**

- - Introduction에서 내가 가장 중요하게 보는 문장 중 하나다.
  - 저자들은 자신들이 **practical regime**에 집중한다고 말하면서, **특정 quantum algorithm이 요구하는 target logical error rate를 달성하는 데 반드시 모든 operation이 엄격한 의미에서 fault-tolerant일 필요는 없다는 점을 활용한다.**고 명시한다.

> ***“we leverage the fact that fault-tolerance is not required to achieve the target logical error rate required for a specific quantum algorithm.”***

- - 즉, **“QEC의 목적은 모든 동작을 완벽하게 만드는 것이 아니라, 실제 알고리즘이 요구하는 오류 수준을 최소 비용으로 달성하는 것”**이라는 실용적인 접근이다.
  - 이 철학이 뒤에서 **MEDM + CliNR**로 이어진다.

    - **첫째, MEDM도 “오류를 다 고치는 것”보다 “발견하면 restart”를 선택할 수 있다**

      - MEDM은 Multi-Pauli Error Detected Measurement다.
      - Scheduler code로 여러 Pauli 측정에 redundancy를 넣은 뒤 오류를 발견하면 복잡한 correction 대신 restart를 한다.
    - **둘째, Resource State를 “오류정정”하지 않고 “오류검출 후 버린다”**

      - 이게 가장 직접적인 사례다.
      - 저자들은 Logical CliNR의 가속 원인 첫 번째로 명시적으로 **resource state를 error correction 대신 error detection으로 준비할 수 있다**고 쓴다.
      - 전통적으로 엄격하게 하려면, 아래처럼 오류를 정정하여 FT 상태를 유지해야 한다.

|  |
| --- |
| Resource state 준비  ↓  계속 syndrome 측정  ↓  오류 위치 추정  ↓  decoder  ↓  오류 correction  ↓  FT 상태 유지 |

- - - - 하지만, resource state는 실제 계산 데이터 자체가 아니라 offline에서 미리 만드는 보조 자원이기 때문에 문제가 있으면 고쳐서 살려야 할 이유가 없다.
    - **셋째, CliNR 자체가 ‘Full QEC’가 아니라 Partial Error Correction이다**

      - 이번 논문은 CliNR를 명시적으로 **partial error correction scheme**이라고 부른다.
      - 그리고 더 흥미로운 것은 logical level과 physical level을 섞는다.

|  |
| --- |
| Resource state 준비·검증  → logical level    State injection  → physical transversal CNOT  → physical destructive measurement |

- - - - 즉 모든 것을 logical fault-tolerant gate로 구현하지 않는다.
      - 저자들은 이를 가속의 세 번째 원인으로 직접 지목한다. RSI를 physical transversal CNOT과 destructive measurement로 구현함으로써 기존 CliNR의 시간 패널티를 피한다는 것이다.

  - 하지만 logical operator 하나를 측정할 때 **Viterbi measurement**를 사용한다.
  - 쉽게 말하면:

|  |
| --- |
| Logical Pauli P1  ↓  cat measurement  ↓  아직 신뢰도 부족?  ↓  다시 measurement  ↓  충분한 confidence가 생길 때 종료 |

- - 그리고 P2를 측정하면 다시 처음부터 한다.
  - 즉:

|  |
| --- |
| P1 → 반복  P2 → 반복  P3 → 반복  P4 → 반복  ... |

- - 이다.
  - Viterbi 방식 자체는 single-Pauli measurement로서는 효율적이지만, **여러 commuting logical operators를 동시에 처리할 때 각자 따로 측정한다는 점이 비효율적**이다.

---

**✅ 이번 논문의 첫 번째 핵심 혁신:** **여러 logical Pauli를 한꺼번에 측정****한다**

- - 이번 논문에서는 (ℓ)개의 **commuting logical operators**를 하나씩 따로 측정하지 않는다.
  - 여러 operator들의 조합을 측정한다.
  - 예를 들어:

|  |
| --- |
| 원래 알고 싶은 것  P1  P2  P3  P4 |

- - 를 직접 각각 반복하는 대신:

|  |
| --- |
| P1 × P2  P2 × P3  P1 × P3 × P4  P2 × P4  ... |

- - 같은 조합을 측정한다.
  - 그리고 이 측정 순서를 결정하는 것이 이번 논문의 핵심 개념인 **Scheduler Code**다.
  - Scheduler code는 **quantum code가 아니라 classical binary linear code**다.
  - 역할은 **어떤 Pauli product들을 측정해야 최소한의 measurement로 원래 logical outcomes를 신뢰성 있게 복원할 수 있는가?**를 결정하는 것이다.
  - 따라서 일종의 **logical measurement용 error-correcting checksum**이라고 이해하면 쉽다.

**📌 MEDM / MECM**

- - **MEDM** = **Multi-Pauli Error Detected Measurement**
  - **MECM** = **Multi-Pauli Error Corrected Measurement**
  - 기존 Walking Cat의 단일 logical Pauli 측정 방식인:

    - **EDM** = Error Detected Measurement
    - **ECM** = Error Corrected Measurement
  - 을 이번 논문에서 **여러 개의 commuting Pauli를 동시에 다루도록 확장한 버전**이라고 보면 된다. 논문도 Section III에서 MEDM/MECM을 새 multi-Pauli protocol로 소개하고, 각각 기존 EDM과 ECM을 여러 commuting Pauli로 일반화한다고 설명한다.
  - Scheduler Code는 MEDM과 MECM을 가능하게 하기 위해 새로 도입한 핵심이 바로 scheduler code다.

|  |
| --- |
| 기존 single-Pauli 방식  EDM / ECM / Viterbi  ↓  여러 commuting Pauli를 동시에 측정하고 싶음  ↓  어떤 Pauli 조합을 어떤 순서로 측정할지 설계해야 함  ↓  Scheduler Matrix G  ↓  그 G가 생성하는 binary linear code  = Scheduler Code  ↓  MEDM / MECM 구현 |

---

**✅ 첫 번째 결과: logical measurement당 cat state 수를 크게 줄인다**

- - 논문은 Walking Cat의 Q70과 Q102를 대상으로 시뮬레이션한다.
  - 그 결과

    - **10개의 commuting logical operators**

      - 평균 2.1 cat states per logical measurement
    - **20개의 commuting logical operators**

      - 평균 1.7 cat states per logical measurement
  - 까지 줄인다.
  - **20개를 동시에 처리할수록 더 효율적이라는 게 중요하다.**
  - 기존 Viterbi와 비교하면 20개 simultaneous logical measurement에서 거의 **3× 수준의 measurement efficiency 개선**을 얻는다.
  - 즉:

|  |
| --- |
| Single measurement 최적화  ↓  Viterbi    Multiple measurements 공동 최적화  ↓  Scheduler code  ↓  MEDM / MECM  ↓  약 3× 감소 |

- - 이다.

---

**✅ 그런데 저자들은 여기서 멈추지 않았다**

- - 이 아이디어는 단순히 logical operator를 빨리 읽는 데서 끝나지 않는다.
  - 저자들은 중요한 점을 발견한다.

    - **Stabilizer도 결국 commuting Pauli operators다.**
  - 따라서 여러 stabilizer generator를 빠르게 측정할 수 있다면 **stabilizer state를 빠르게 준비할 수 있다.**
  - 이것이 다음 단계의 결정적인 연결고리다.
  - 왜냐하면 Clifford operation을 **resource stabilizer state**로 바꿔 수행할 수 있기 때문이다.
  - 즉:

|  |
| --- |
| Fast multi-Pauli measurement  ↓  Fast stabilizer-state preparation  ↓  Fast Clifford resource-state preparation  ↓  CliNR  ↓  Fast logical Clifford operation |

- - 이라는 연결이 생긴다.

---

**✅ 두 번째 핵심 혁신:** **CliNR를 logical level로 재설계**

- - CliNR는 원래 **Clifford Noise Reduction**, 즉 partial error correction 기법이다.
  - 그런데 원래 CliNR는 noise를 줄일 수는 있어도 **execution time은 오히려 늘어나는 방식**이었다.
  - 이번 논문은 CliNR를 변형한다.
  - 핵심은 세 가지다.

    - **① Clifford circuit을 직접 실행하지 않는다**

      - 큰 Clifford circuit 대신 **그 Clifford가 이미 반영된 resource state를 offline에서 준비**한다.
    - **② Resource State Preparation과 Verification을 합친다**

      - 기존에는 RSP → RSV 로 따로 했지만,
      - 이번에는 fast multi-Pauli measurement, 특히 MEDM을 이용해 **RSP + RSV** 를 함께 처리한다.
    - **③ Resource State Injection(RSI)은 physical operation으로 한다**

      - logical operation으로 천천히 하지 않고

        - transversal physical CNOT
        - destructive measurement
      - 를 사용한다.
    - 즉 가장 비싼 부분은 logical level에서 최적화하고, 빠르게 할 수 있는 부분은 physical level로 내린다.
    - 이것이 나중에 **17.6× / 63.4×** 같은 큰 차이를 만드는 핵심 구조다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA3MjBfMTk0/MDAxNzg0NTU1NDEzNzM4.OrwmLJh9wI0I8e9TyqQizQY0cgCnH_TMpY0Q383J8xQg.H975co2Pg4g-JOkbLgRj630_Qc3KqBtRlOoCeL0jgj0g.PNG/image.png?type=w800)](#)

- - **왼쪽 Physical CliNR는 resource state를 먼저 만든 뒤(RSP), 다시 검사하고(RSV), 마지막에 data에 주입한다(RSI).**
  - **오른쪽 Logical CliNR는 원하는 resource state를 logical stabilizer measurement로 직접 만들어내면서 동시에 검증하기 때문에 RSP와 RSV가 하나로 합쳐진다.**
  - 이후 RSI는 느린 logical gate가 아니라 **physical transversal CNOT + destructive measurement**로 수행한다. 이것이 큰 속도 향상의 핵심이다.

**✅ 가장 중요한 포인트 3개**

**📌** **첫째, 이번 논문은 “QEC 성능을 더 높인 논문”이라기보다 QEC 위의 computation layer를 빠르게 만든다.**

- - 이번에는 **“보호된 logical qubit으로 계산할 때 발생하는 속도 병목”**으로 넘어갔다.

**📌** **둘째, 63배의 출발점은 scheduler code만이 아니다.**

- - Scheduler code의 multi-Pauli measurement 자체는 약 **3배** 개선이다.
  - 수십 배 수준의 개선은:

    - Fast multi-Pauli measurement
    - fast stabilizer-state preparation
    - logical CliNR
    - Clifford circuit을 resource state로 압축
    - physical-level injection
  - 이 모두 결합되면서 생긴다.

**📌** **셋째, “모든 것을 완전한 FT로 만들 필요는 없다”는 현실적인 철학이 매우 중요하다.**

- - 이번 연구는 full QEC를 포기한 것이 아니다.
  - 오히려 **qLDPC라는 full QEC 기반 위에서, 오류정정·오류검출·partial error correction을 각 단계의 필요에 맞게 조합해 시간과 자원을 최소화한다.**는 방식이다.

> ***qLDPC는 많은 logical qubit을 적은 physical qubit으로 저장할 수 있지만, 같은 block 안의 여러 logical qubit을 동시에 조작하기 어렵다는 병목이 있다. 이 논문은 복잡한 resource state 대신 이동 가능한 단순 cat state와 classical scheduler code를 이용해 여러 commuting logical measurements를 공동 처리하고, 이를 logical CliNR와 결합함으로써 qLDPC의 logical-operation overhead를 크게 줄이려 한다.***
>
> ******
>
> ***이번 논문의 핵심은 QEC의 정확도를 높인 것이 아니라, 동일한 목표 logical error rate를 유지하면서 logical computation에 필요한 measurement와 fault-tolerant operation overhead를 대폭 줄인 것이다. 이 때문에 실제 quantum processor의 실행 시간도 크게 단축될 가능성이 높지만, 논문이 직접 입증한 63.4×라는 수치는 wall-clock speed가 아니라 cat-based measurement 수의 감소율이다.***

**✅** **IonQ의 QEC 어디까지 왔나?**

- - 놀랍게도 **큰 퍼즐 조각들은 상당히 많이 맞춰지고 있다.**
  - Delfosse 팀의 연구를 “QEC를 실제 컴퓨터로 만들 때 생기는 병목” 기준으로 보면 아주 재미있다.

**📌** **병목 1. 물리 큐비트가 너무 많이 필요하다**

- - → **qLDPC**
  - Surface code보다 높은 encoding rate로 physical-qubit overhead를 줄인다.

    - Q70:

      - 70→6 logical
    - Q102:

      - 102→22 logical
  - Walking Cat에서는 2,514 physical qubits로 110 logical qubits를 구성하는 dense architecture를 설계했다.
  - **공간 비용 문제에 대한 해법이다.**

****

**📌** **병목 2. Syndrome은 계속 쏟아지는데 decoder가 너무 느리다**

- - → **Beam Search Decoder**
  - 이것은 고전 컴퓨팅 병목이다.
  - QEC는 끊임없이

|  |
| --- |
| syndrome 측정  ↓  CPU/decoder로 전달  ↓  어디서 오류가 났는지 추론  ↓  correction/frame update |

- - 해야 한다.
  - Decoder가 quantum hardware보다 느리면 QEC 시스템 전체가 막힌다.

[**Beam search decoder for quantum LDPC codes**

IonQ의 Nicolas Delfosse팀이 또다시 일을 냈다. FPGA가 필요없는 알고리즘을 소개했으니 소화해보...

blog.naver.com](https://blog.naver.com/4-fire/224104049196)

- - 2025년 Beam Search 논문에서는 BB [[144,12,12]]에 대해 beam-width 32 설정이 물리 오류율 5×10−4에서 syndrome-extraction round당 99.9-percentile decoding latency를 1 ms 아래로 낮췄다. 그것도 단일 CPU core의 소프트웨어 실행이었고, 저자들은 이를 바탕으로 1,000 logical-qubit 이온트랩 시스템에 약 세 대의 32-core CPU면 가능할 수 있다고 추정했다.
  - 즉 **QEC classical decoding 때문에 대규모 FPGA/ASIC 농장이 반드시 필요한가?**라는 문제에 대해 **이온트랩의 비교적 느린 SEC cycle에서는 일반 CPU로도 충분할 가능성이 있다.**는 답을 준 것이다.
  - **고전 계산 부하 문제에 대한 강력한 후보 해법이다.**

****

**📌** **병목 3. QEC는 되는데 logical operation이 너무 느리다**

- - → **이번 MEDM/MECM + Logical CliNR**
  - 이게 이번 논문이다.
  - qLDPC는 저장 효율은 좋지만, 한 block 안에 logical qubits가 많이 들어가니 실제 계산이 느려지는 문제가 있다.
  - 그걸 아래 방법으로 줄인다.

|  |
| --- |
| Scheduler Code  ↓  MEDM / MECM  ↓  여러 logical measurements 공동 처리    +    Logical CliNR  ↓  gate-by-gate 실행을  offline resource-state preparation으로 전환 |

- - 저자들은 이 가속을 resource-state offline preparation, MEDM을 이용한 RSP+RSV 통합, physical-level RSI의 조합으로 설명한다.
  - **시간 비용 문제에 대한 해법이다.**

****

**📌** **병목 4. qLDPC가 실제 하드웨어에서도 정말 작동하나?**

- - → **2026년 Breakeven 실험**
  - 실제 이온트랩 장비에서 9종의 QEC code를 구현했고, 18 physical qubits로 4 logical qubits를 encoding한 qLDPC 사례를 포함해 일부 조건에서 logical lifetime이 physical qubit과 비슷하거나 조금 넘어서는 breakeven을 보였다.

    - **“이론만 되는 것 아닌가?”라는 문제에 대한 초기 실험적 답**이다.
  - 그래서 큰 그림을 그리면 정말 이렇다.

|  |
| --- |
| QEC의 주요 병목    1. Qubit overhead  ↓  qLDPC / Q70 / Q102  ✓ 후보 해법    2. Syndrome extraction  ↓  Walking Cat + cat states  ✓ architecture    3. Decoder computational load  ↓  Beam Search  ✓ CPU-level 후보 해법    4. Logical measurement latency  ↓  Scheduler Code + MEDM/MECM  ✓ 약 2~3× 개선    5. Logical gate execution overhead  ↓  Logical CliNR  ✓ Q102에서 약 24× 구조적 감소    6. 실제 hardware QEC  ↓  Breakeven demonstration  ✓ 초기 실증 |

> ***“QEC는 너무 많은 큐비트가 필요하고, decoder도 너무 무겁고, logical operation도 너무 느리다”라는 세 가지 대표적인 효율성 문제에는 이제 각각 꽤 구체적인 답이 생겼다.***

**📌 하지만 “거의 다 해결됐다”고 하기 어려운 이유**

- - 핵심 병목에 대한 **해법은 상당 부분 제시됐지만, 이를 대규모 시스템에서 통합 검증한 단계는 아니다.**
  - Q70/Q102 기반의 Walking Cat 전체 구조, 실시간 decoder, cat factory, MEDM, Logical CliNR, compiler와 실제 알고리즘을 하나의 시스템으로 동시에 구동한 실증은 아직 없다. 이번 63.4× 역시 **cat-based measurement 수의 감소**를 보여준 시뮬레이션 결과이지, 전체 wall-clock time이 그대로 63.4배 단축됐다는 의미는 아니다.
  - Beam Search 역시 대규모 시스템에서 CPU만으로 충분하다는 가능성을 강하게 보여줬지만, 실제 1,000 logical-qubit 시스템에서 end-to-end로 검증된 것은 아니다. 또한 T gate·Toffoli·magic-state factory 같은 non-Clifford 연산의 throughput, 그리고 correlated error·leakage·ion loss·crosstalk 등 실제 하드웨어의 복합 noise 문제도 남아 있다.
  - 따라서 현재 단계는 **QEC의 주요 성능 병목마다 구체적인 해결책이 거의 갖춰지고 있지만, 이제 가장 중요한 과제는 이 모든 요소를 실제 대규모 하드웨어에서 통합해 성능을 검증하는 것**이라고 보는 것이 정확하다.

- - 따라서 나는 “QEC의 성능 문제를 거의 다 해결했다”보다는 “QEC가 느리고 비싸다는 문제를 구성하는 주요 병목마다 이제 구체적인 해결책이 등장했고, 남은 가장 큰 문제는 이들을 실제 대규모 하드웨어에서 하나의 시스템으로 통합해 검증하는 것”이라고 표현하는 게 가장 정확하다고 본다.
  - 특히 이번 논문의 *practical regime* 철학은 이 흐름을 잘 보여준다.
  - **최고의 QEC란 가장 엄격한 오류정정 프로토콜이 아니라, 알고리즘이 요구하는 신뢰도를 만족하면서 실제 자본·큐비트·시간·고전 연산을 가장 적게 쓰는 시스템**이라는 방향으로 연구의 초점이 이동하고 있는 것이다.
