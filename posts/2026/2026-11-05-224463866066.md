  - 이번 편에서는 암호화와 별도로 **Zero Trust·마이크로세그멘테이션·EDR·NDR** 등이 필요한 이유를 실제 네트워크 동작 관점에서 살펴보겠다.

---

**✅ 1. 공격자는 암호를 풀지 않고도 데이터를 훔칠 수 있다**

- - **병원 네트워크를 예로 들어 보겠다.** 모든 통신을 ML-KEM과 AES-256으로 보호했더라도 직원 계정이 탈취되거나 애플리케이션 서버가 감염되면 공격자는 합법적인 권한을 흉내 내 평문 환자정보를 요청할 수 있다.
  - **이때 공격자는 Shor도 Grover도 필요하지 않는다.** 정상적인 복호화 과정과 허용된 애플리케이션 API를 악용하면 되기 때문이다. 데이터가 암호화되어 있다는 사실만으로 이 공격을 막을 수 없다.
  - 여기서 암호화와 실제 사이버보안의 가장 큰 차이가 나타난다.

**📌 공격자는 반드시 암호를 해독할 필요가 없다**

- - 한 병원의 모든 주요 시스템이 ML-KEM과 AES-256을 사용한다고 가정해 보겠다.
  - 공격자가 병원 직원의 계정을 탈취하거나 한 대의 서버에 악성코드를 설치하면 어떻게 될까?
  - 공격자는 다음과 같은 행동을 할 수 있다.

    - 탈취한 계정으로 정상적인 애플리케이션에 로그인한다.
    - 감염된 서버에서 복호화된 환자정보를 읽다.
    - 서버에 저장되거나 메모리에 존재하는 비밀키를 탈취한다.
    - 허용된 네트워크 경로를 이용해 다른 시스템에 접근한다.
    - 추가 서버의 취약점을 공격해 권한을 확대한다.
    - 백업 서버와 관리 시스템까지 침해한다.
  - 이 과정에서 PQC나 AES-256의 수학적 구조를 깨뜨릴 필요는 없다.
  - 암호화는 통신 중이거나 저장 중인 데이터의 기밀성을 보호할 수 있지만, 정당한 계정이나 감염된 애플리케이션을 통해 평문에 접근하는 공격까지 자동으로 막아주지는 않는다.
  - 이 때문에 암호화와 별도로 접근 통제, 엔드포인트 보호, 네트워크 보안이 필요한다.

---

**✅ 2. 마이크로세그멘테이션과 Zero Trust는 왜 더 중요해질까?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjExMDNfODYg/MDAxNzkzNzAzMDE2Nzkx.KkNkQM_ACWLct3s85wAyHmUO8_zjOZeHuqcyV5FKDl0g.XMrs1EYhbB864ZRB5KgDnwWmA23yuJp5kfgMJTohzgAg.PNG/image.png?type=w800)](#)

- - **여기서 마이크로세그멘테이션이 필요한 이유가 분명해진다.**

    - 키가 유출되거나 한 대의 서버가 침해됐다는 사실 자체는 되돌릴 수 없어도, 공격자가 그 서버에서 데이터베이스·백업·관리 네트워크로 자유롭게 이동할 수 없도록 통신 경로를 제한할 수 있다.
  - **예를 들어 웹 서버가 감염되더라도 데이터베이스 포트와 백업 서버로의 직접 접속을 기본 차단할 수 있다.**

    - 필요한 애플리케이션 간 통신만 허용하고 관리 트래픽을 별도 경로로 제한하면 공격자의 횡적 이동(Lateral Movement)을 어렵게 만듭니다.
  - **하지만 마이크로세그멘테이션도 만능은 아니다.**

    - 이미 허용된 애플리케이션 경로로 평문을 읽는 공격이나 감염된 엔드포인트의 키 탈취는 다른 통제가 필요한다. 그래서 ID 관리, EDR/NDR, 키 보호, 데이터 접근 감사와 결합해야 한다.

**📌 네트워크 내부라고 해서 신뢰할 수는 없다**

- - 과거의 네트워크 보안은 외부와 내부를 구분하는 방화벽 중심으로 설계되는 경우가 많았다.
  - 일단 내부 네트워크에 들어온 장치라면 비교적 넓은 접근 권한이 허용되기도 했다.
  - 하지만 이런 구조에서는 단 한 대의 서버가 침해되더라도 공격자가 다른 서버로 이동하기 쉬워진다.
  - 이를 Lateral Movement, 즉 내부 횡적 이동이라고 한다.
  - 마이크로세그멘테이션은 개별 워크로드, 애플리케이션, 장치 또는 서비스 수준에서 접근 정책을 세분화한다.
  - 예를 들어 다음과 같은 정책을 만들 수 있다.

    - 웹 서버는 지정된 애플리케이션 서버에만 접근 가능
    - 애플리케이션 서버는 필요한 데이터베이스 서비스에만 접근 가능
    - 사용자 PC는 데이터베이스 서버에 직접 접근 불가
    - 백업 서버에는 지정된 백업 워크로드만 접근 가능
    - 관리 서버는 승인된 관리자 계정과 장치에서만 접근 가능
  - 이렇게 하면 한 서버가 침해되더라도 공격자가 다른 시스템으로 확산할 수 있는 경로를 줄일 수 있다.
  - 호주 ASD는 2026년 9월 발표한 네트워크 세그멘테이션 지침에서 마이크로세그멘테이션을 개별 워크로드·애플리케이션·장치·서비스 수준의 세밀한 정책 집행 방식으로 설명한다.

**📌 기존 VLAN 기반 분리와 무엇이 다를까?**

- - VLAN과 ACL도 중요한 보안 통제 수단이다.
  - 하지만 동일 VLAN이나 동일 신뢰 영역에 있는 서버 사이의 통신이 광범위하게 허용되어 있다면 내부 이동을 충분히 통제하지 못할 수 있다.
  - 마이크로세그멘테이션은 단순히 IP 주소와 VLAN만 사용하는 것이 아니라, 시스템의 역할과 애플리케이션·워크로드의 식별 정보를 활용해 훨씬 세밀한 정책을 구현할 수 있다.

|  |  |  |
| --- | --- | --- |
| **구분** | **전통적 네트워크 분리** | **동적 마이크로세그멘테이션** |
| 주요 식별 기준 | VLAN, 서브넷, IP 주소 | 자산·워크로드·애플리케이션·Identity |
| 정책 범위 | 네트워크·보안 구역 중심 | 개별 서비스·워크로드 수준 |
| 정책 변경 | 수동 ACL·방화벽 변경이 많음 | 정책 자동화 가능 |
| 서버 이동 | IP·구성 변경에 영향받을 수 있음 | 제품에 따라 Identity 중심 정책 유지 가능 |
| 내부 이동 통제 | 구역 간 통제 중심 | 동일 구역 내부까지 세분화 가능 |

- - 물론 마이크로세그멘테이션이라고 해서 모든 제품이 이러한 기능을 동일한 수준으로 제공하는 것은 아니다.
  - 정책을 실제로 어디에서 집행하는지도 중요한다.

    - 스위치나 네트워크 장비에서 집행하는가?
    - 방화벽을 경유해야 하는가?
    - 엔드포인트 에이전트가 필요한가?
    - 가상화 플랫폼이나 클라우드 정책을 활용하는가?
    - 기존 네트워크를 크게 변경하지 않고 배포할 수 있는가?
  - 정책 엔진이 아무리 뛰어나도 실제 데이터플레인에서 정책을 안정적으로 집행하지 못하면 효과가 제한된다.

**📌 Zero Trust는 단순한 네트워크 분리가 아니다**

- - NIST SP 800-207의 Zero Trust 원칙은 자원이 내부 네트워크에 있다는 이유만으로 신뢰하지 않는 것이다.
  - 접근 요청마다 사용자, 장치, 애플리케이션, 권한, 환경 등을 고려해야 한다.
  - 마이크로세그멘테이션은 이러한 Zero Trust 정책을 구현하는 핵심 수단 중 하나가 될 수 있다.
  - 하지만 Zero Trust 자체가 마이크로세그멘테이션 하나만으로 완성되는 것은 아니다.
  - 강력한 인증, 권한 관리, 장치 보안, 지속적인 모니터링이 함께 필요한다.

**✅ 3. PQC와 마이크로세그멘테이션이 서로 보완하는 지점**

- - **양자 시대의 보안은 세 가지 실패 지점을 따로 관리해야 한다.**

    - 첫째, 키 설정 알고리즘이 미래에 해독되는 위험이다.
    - 둘째, 현재 키·계정·엔드포인트가 탈취되는 위험이다.
    - 셋째, 침해 이후 내부 네트워크로 공격이 확산되는 위험이다.
  - **각각에 맞는 답이 다르다.**

    - 첫 번째는 PQC·Hybrid 키 설정과 암호 민첩성,
    - 두 번째는 KMS·HSM·최소권한·MFA·EDR,
    - 세 번째는 마이크로세그멘테이션·방화벽·Zero Trust 정책 집행이 주로 대응한다.
  - 두 기술은 서로 다른 공격 단계를 방어한다.

|  |  |  |
| --- | --- | --- |
| **공격 시나리오** | **PQC** | **Microsegmentation** |
| 미래 양자컴퓨터로 과거 키 교환 해독 | 직접 대응 | 직접 대응 불가 |
| 서버 계정 탈취 | 직접 대응 불가 | 접근 범위 제한 가능 |
| 감염된 서버의 내부 이동 | 직접 대응 불가 | 핵심 방어 수단 |
| 정상 권한으로 평문 데이터 탈취 | 직접 대응 불가 | 일부 경로 제한 가능 |
| 공개 네트워크의 통신 도청 | 기밀성 보호에 기여 | 일반적으로 직접 방어 불가 |
| 침해된 서버에서 다른 시스템으로 확산 | 직접 대응 불가 | 피해 범위 축소 |
| 암호 알고리즘의 미래 취약점 | 새로운 알고리즘으로 전환 필요 | 취약 암호 자체를 해결하지 못함 |

- - 여기서 중요한 점은 마이크로세그멘테이션이 HNDL을 직접 해결하는 기술은 아니라는 것이다.
  - 외부 네트워크에서 합법적인 암호화 통신을 수동으로 녹화하는 공격자는 내부 서버 간 접근 권한이 없어도 데이터를 수집할 수 있다.
  - 반대로 PQC로 암호화된 통신을 사용하더라도 공격자가 서버 내부의 평문 데이터를 훔치는 것을 막지는 못한다.
  - 따라서 미래의 보안 아키텍처는 다음과 같은 역할 분담이 필요한다.

    - **PQC:** 미래 양자 공격에 대한 암호학적 대응
    - **AES-256:** 실제 데이터의 기밀성 보호
    - **QKD:** 특정 환경에서 계산적 보안에 의존하지 않는 키 분배
    - **KMS/HSM:** 키 수명주기 및 비밀키 보호
    - **Zero Trust:** 모든 접근 요청에 대한 명시적 검증
    - **Microsegmentation:** 불필요한 통신과 내부 확산 제한
    - **EDR (****Endpoint Detection and Response)** **/ XDR (****Extended Detection and Response)****:** 엔드포인트 위협 탐지 및 대응

      - EDR은 PC 또는 서버에 설치된 보안 센서나 운영체제 보안 기능을 통해 장비 내부의 활동을 수집한다.
      - XDR은 여러 시스템에서 발생한 사건을 연결해 전체 공격 경로를 재구성한다.
    - **NDR (****Network Detection and Response)** **/ IDS (****Intrusion Detection System)****:** 네트워크 기반 이상 행위 탐지

      - NDR은 개별 PC나 서버 내부보다 네트워크에서 발생하는 통신 패턴을 분석한다.
      - IDS는 패킷에서 알려진 공격 시그니처를 찾거나 사전에 정의된 이상 조건을 탐지하는 데 중점을 둔다.
      - IPS(Intrusion Prevention System)는 트래픽 경로에 배치되어 실제 차단을 수행할 수 있다.
    - **DLP (****Data Loss Prevention)****:** 민감 데이터 유출 위험 통제

      - DLP는 보호해야 할 데이터가 무엇이고, 그 데이터가 어디로 이동하려 하는지에 집중한다.
    - **QSPM/Crypto Discovery:** 암호화 자산 및 양자 취약성 파악
  - 모든 제품을 단순히 많이 도입한다고 안전해지는 것은 아니다.
  - 각 기술이 어떤 공격을 방어하고 무엇을 방어하지 못하는지 명확히 이해해야 한다.

**📌 보안장비가 실제로 중요한 지점: 정책 집행**

- - 방화벽·NAC·EDR·NDR·마이크로세그멘테이션은 같은 기능이 아니다. 각각 접근 제어, 식별·인증, 감염 탐지, 네트워크 이상 분석, 내부 이동 제한이라는 서로 다른 역할을 맡다.
  - 예를 들어 감염된 의료 장비 한 대에서 백업 서버로 연결할 필요가 없다면, Identity 기반 마이크로세그멘테이션으로 그 경로 자체를 제한할 수 있다. 그러나 정상적으로 허용된 애플리케이션의 평문 탈취는 별도의 계정·데이터 보안이 필요한다.
  - **실행 우선순위:** 핵심 데이터베이스, 백업, 관리자 네트워크부터 통신 관계를 파악하고 정책을 시뮬레이션한 뒤 단계적으로 적용하는 편이 안전한다.

**📌 지난글에서 기업이 점검할 네가지 실천 과제를 살펴봤다.**

- - **1. 보호해야 할 데이터를 분류한다**
  - **2. 실제 암호 사용 현황을 확인한다**
  - **3. 키 관리 체계를 강화한다**
  - **4. PQC 및 Hybrid 전환을 시작한다**
  - 여기에 5번째 내용이 추가된다.

****

**📌 우선순위 5. Zero Trust와 마이크로세그멘테이션을 강화한다**

- - 중요 서버 간 통신 관계 파악
  - 불필요한 East-West 통신 제한
  - 관리 시스템과 백업 시스템의 접근 격리
  - 중요 데이터베이스 접근 통제
  - EDR/NDR과 보안 정책의 연계
  - 정책 시뮬레이션 및 단계적 적용
  - 세그멘테이션은 암호가 깨지는 것을 막지 못하지만, 공격자의 이동과 피해 확산을 줄이는 데 기여한다.
