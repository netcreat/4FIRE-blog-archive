**출처 : 카이스트 테라랩**

- - **Twin-HBM-NMC Logic Die**

    - 스택 아래에 **큰 로직 다이**가 위치
    - 이 다이 안에:

      - **NMC(Near Memory Compute) Logic**
      - **PHY(물리 Layer for I/O)**
      - **HBM controller**
      - 등이 포함됨
    - → 즉 단순한 버퍼링이 아니라 **연산을 메모리 근처에서 수행**(processing-in/near-memory)
  - **NMC Blocks**

    - NMC = Near Memory Computing
    - 역할:

      - 메모리 접근을 줄이는 데이터 pre/post-processing
      - 필터링
      - 압축/풀기
      - AI 연산 일부
      - Reduce/Scatter 같은 memory-bound 작업 처리
    - GPU에서 부담해야 할 메모리 병목 연산을 미리 처리해서 **데이터 이동량을 감소**
  - **2048 External I/O Channels**

    - Twin-Tower 로직 다이에서 GPU로 연결되는 채널 수

      - GPU ↔ HBM PHY
      - 목적 : 패키지 인터커넥트
    - 일반 HBM 대비 **대폭 확장된 인터페이스**
    - 이를 위해 **Silicon Interposer**가 사용됨
  - **4096 Internal I/O Channels**

    - DRAM 내부 I/O

      - HBM PHY ↔ DRAM arrays
      - 목적 : DRAM bank 접근
  - **Silicon Interposer**

    - HBM ↔ GPU 연결을 위한 기판
    - 매우 fine pitch routing 가능
    - 2.5D integration의 일반적인 구성

**출처 : 카이스트 테라랩**

- - **Interposer의 reticle size 한계**

    - 핵심 제약은 **EUV/DUV 리소그래피의 최대 reticle 크기**다.
    - 현재 TSMC CoWoS의 reticle 최대 크기:

      - **~858 mm****2** **(약 26×33 mm)**
    - 즉 인터포저는 그보다 크게 못 만든다.
    - 따라서 GPU + N개의 HBM을 붙이려 하면:

      - 더 많은 HBM을 배치할 수 없음
      - 더 긴 인터커넥트 배선 필요
      - 병렬 BW scaling 한계 도달
  - **KAIST의 제안 : Hybrid Interposer**

    - Silicon 인터포저 + Glass 인터포저를 결합해서 reticle을 넘어서는 초대형 인터포저 구성
    - 전기 인터커넥트 + Power Delivery + Thermal Path를 Glass가 담당
  - **Glass가 주목받는 이유**

    1. **Panel-scale size 가능**

       - 반도체 reticle 한계 없음 → 수십 cm까지 가능
    2. **Low CTE (열팽창 계수)**

       - 실리콘과 유사 → warp 최소화
    3. **Low dielectric**

       - 신호 integrity 우수 → SerDes + HBM 모두 수용 가능
    4. **Via density**

       - TSV 대신 **μ-Through-glass-Via (μTGV)** 사용 가능
  - **Hybrid여야만 하는 이유**

    - **Glass는 기본적으로 패시브 substrate**라는 점

      1. TSV density가 실리콘만큼 높지 않음

         - TSV pitch 필요: **3~10 µm 수준**
         - Glass는 현실적으로 **시간당 μTGV 형성** 수준이 낮음
      2. Active routing 불가 (Transistor 없음)

         - 다음 기능 불가:

           - SerDes PHY
           - Retimer / Equalizer
           - Clock recovery
           - DLL/PLL
           - Power gating
           - Redriver
           - CXL/HBI link layer
           - Cache coherence fabric
      3. **Power Delivery Network (PDN) 한계**

         - HBM + GPU는 매우 높은 PDN 요구:

           - 고전류 (A급)
           - low impedance
           - decoupling 필요
           - non-uniform power domain
         - Glass는 전력망을 처리하기에 구조적 한계
      4. **Thermal constraints**

         - Glass는:

           - 열전도율 낮음
           - 열확산(diffusion)에 불리함
      5. Alignment + Via Reliability

         - HBM은 수천~수만 개의 micro-bump alignment 필요
         - Glass는 이 부분에서 아직:

           - 재현성
           - warpage
           - stress
           - via reliability
         - 모두 개선 필요

**출처 : 카이스트 테라랩**

- - HBM이 단순 DRAM 역할을 넘어서 계산·캐시·열·네트워크까지 포함하는 메모리 중심 컴퓨팅 구조로 확장
  - Top view

    - H = Heat path
    - Yellow = Data/Interconnect path
    - 네 가지를 Interposer 위에서 모두 수행

      - **NMC-HBM**: compute가 DRAM에 바로 접근
      - **HBM-HBM**: cross-memory data exchange (rare in GPU today)
      - **NMC-NMC**: near-memory compute cluster
      - **Cache-cache**: coherence or sharing 가능
      - **Heatsink connection**: 열 배출 경로 공유
  - NMC를 HBM 위에 얹는 순간 가장 큰 문제는 발열 + DRAM retention + refresh rate 증가되므로 다음이 필요함

    - 상부로 heat extraction
    - Interposer로 lateral spreading
    - TSV로 minimal hotspot
