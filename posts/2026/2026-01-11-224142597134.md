**📌 전송 속도(Bandwidth)**

- - 전체 대역폭(Bandwidth) : 22TB/s
  - Stack 개수 : 8
  - Stack 당 대역폭 : 22/8=2.75TB/s
  - I/O 개수 : 2048
  - Data rate : 2.75TB/s × 8(Byte → bit) / 2048 = 10.74Gb/s

    - 기존 규격은 8Gbps였음

**📌 용량(Capacity)**

- - 전체 용량 : 288 GB
  - Stack 개수 : 8
  - 스택당 용량 : 288/8=36GB
  - die 개수 : 12
  - die 당 용량 = 36/12=3GB=24Gb

**✅** **HBM4의 특징**

**📌 메모리 컨트롤러 아키텍처 변화**

- - HBM3까지:

    - **MC는 GPU 안에 있었음**
  - HBM4 이후:

    - **MC가 HBM base die로 이동하는 흐름**
  - 장점:

    - ✔ routing 간소화
    - ✔ signal integrity 개선
    - ✔ SerDes placement 쉬움
    - ✔ packaging 부담 감소
  - 결국:

    - HBM base die가 logic die화
  - 즉 메모리 → “active chiplet”

**📌 패키징/전기 특성 변화**

- - HBM4는 사실 기술적으로 **패키징 방식 전환**이 진짜 핵심임
  - **Parallel → SerDes(D2D) 전환 시작**
  - HBM1~3까지:

    - Parallel Bump-based wide I/O
  - HBM4에서 시작되는 변화:

    - → **D2D SerDes link**
  - 기술적으로는:

    - differential signaling
    - bidirectional efficiency
    - PAM4도 채택 가능
    - short-reach PHY
    - C2C(D2D) PHY 공유
    - UCIe / BoW / LDP 표준군으로 향함
  - HBM이 단순 메모리가 아니라 die-to-die connected chiplet화라는 의미

**📌 Type I. Direct Parallel GPU-HBM Interconnect**

- - ✔ 특징:

    - 병렬 I/O 많음 (**1024 I/O**)
    - latency 최소
    - PHY 단순
    - 메모리 컨트롤러(MC)가 **GPU 쪽에 있음**
  - ❌ 단점:

    - 병렬 배선이 많아서 routing이 **빡셈**
    - interposer 층수 증가 → **비용 증가**
    - 길어지면 신호 integrity 문제
    - 속도 scaling이 **제한적 (~64Gbps 대역)**
  - 그래서 Type I은 **HBM2/3/3E까지의 주류 방식**

**📌 Type II. D2D Interconnect (Serial + SerDes)**

- - ✔ 핵심 변화:

    - 병렬 I/O를 **고속 직렬화** (SerDes)
    - link 길이 매우 짧음 (<2mm)
    - **메모리 컨트롤러(MC)를 HBM base die로 이동**
  - 이게 중요함:

    - HBM이 단순 DRAM이 아니라 logic + PHY를 가진 액티브 칩이 됨
  - ❌ 단점:

    - SerDes가 latency 추가
    - 전력 소모 증가
    - die area 증가
    - 제조 복잡도 증가

> ***Type I 은***
>
> ***병렬(Parallel)방식이어서 pin당 Data Rate Scaling이 매우 어렵다.*** ***~ 8Gbps***
>
> ***배선 길이 길어짐***
>
> ***crosstalk 커짐***
>
> ***skew 맞추기 어려움***
>
> ***패키징 포화됨***
>
> ***power distribution 복잡함***
>
> ***interposer RDL 층 증가***
>
> ******
>
> ***Type II 는***
>
> ***Bidirectional Efficiency 50%, Differential Pair Efficiency 50% → 실제 효율은 25%로 감소*********
>
> ***하지만, data rate scaling이 가능함 :*** ***~ 128Gbps***
>
> ***이론상 실제 data rate는 128Gbps × 0.25= 32Gbps*** ***(HBM8에서 32Gbps 구현 가능)***
>
> ***이번 NVIDIA의 발표에서(HBM4)는 10.74Gbps.***
>
> ******

**📌 왜 Type II로 넘어가야 하나?**

- - HBM4에서 **칩간 I/O가 두 배(1024 → 2048bit)** 로 늘어남
  - → 병렬로 계속 밀기에는:

    - bump pitch 한계
    - interposer routing 한계
    - IR/EMI 문제
    - 패키징 비용 폭증
  - 즉 **parallel scaling ≈ 한계 도달**
  - 그래서 AI/패키징 업계는:
  - **wide parallel → short-reach high-speed serial**로 이동 중 (TSMC, Hynix, Samsung, Intel 모두 같은 방향)
  - 그리고 사실 이 흐름은:

    - PCIe → CXL → D2D/BoW/UCIe → chiplet
    - GPU ↔ HBM → SerDes-based
    - NVIDIA NVLink ↔ HBM
    - Intel EMIB / Foveros
    - AMD Infinity Fabric
    - UCIe 1.0/2.0
  - 와 연결됨

**📌 Cooling & Power 변화**

- - 대역폭 2× + data rate scaling 때문에:

    - power density 증가
    - TSV thermal bottleneck 강화
    - liquid cooling 필요 증가
  - 그래서 로드맵에서는:

    - HBM2: air cooling
    - HBM3: direct-to-chip(D2C)
    - HBM4: immersion/plate + cold plate
  - Rubin NVL72도 liquid cooling 채택

    - 45°C (따뜻한 온수)
    - Chiller-less
