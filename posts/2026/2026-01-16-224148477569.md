**출처 : 카이스트 테라랩**

**📌 전체 컨셉**

- - **GPU는 로컬 HBM뿐 아니라, CXL 기반의 공유 메모리 풀과, NVLink/NVSwitch 및 InfiniBand를 통해 클러스터 전체와 연결된다**
  - 즉:

    - GPU 로컬 고대역폭 메모리: **HBM**
    - GPU 보조/대용량 메모리: **LPDDR**
    - CPU/SSD 공유 메모리 풀: **CXL**
    - GPU ↔ GPU intra-node 통신: **NVLink**
    - GPU ↔ GPU inter-node 통신: **InfiniBand**
    - GPU ↔ SSD/NVMe 확장: **CXL + PCIe**
  - 즉 **메모리 계층 + 패브릭 계층 + 스토리지 계층**을 통합한 그림.

**📌 각 구성 요소 설명**

- - **GPU + HBM**

    - 가운데 큼지막한 블록 6개가 각각 **GPU Tile + HBM stack**
    - 여기서:

      - **HBM-Link** (노란색)은 GPU 내부의 HBM 인터페이스
      - 목적: 초고대역폭, 초저지연
    - HBM 특성:

|  |  |
| --- | --- |
| **항목** | **값** |
| 대역폭 | 64 TB/s ↑ |
| 지연 | 매우 낮음 |
| 용도 | 훈련/추론 중 활성 데이터 |

- - **NVLink (좌측, 녹색)**

    - 왼쪽 녹색 영역: **NVSwitch + NVLink**
    - 역할:

      - 클러스터 내 GPU ↔ GPU 통신(intra-node fabric)
    - 특징:

      - 스케일업 (single node parallelism)
      - latency 매우 낮음
      - 대역폭 극대화
      - NVIDIA 전용 패브릭
    - 예:

      - H100 → NVLink3 → 900GB/s
  - **InfiniBand (우측, 보라색)**

    - 오른쪽 보라색 영역: **InfiniBand Network**
    - 역할:

      - **노드 간 통신(inter-node fabric)**
      - 즉 DGX ↔ DGX / Cluster ↔ Cluster 연결
    - 사용 이유:

      - HPC + AI 클러스터 표준
      - GPUDirect RDMA 지원 (CPU 우회)
  - **CXL (상단, 하늘색)**

    - 위쪽 하늘색 박스: **CXL Network Switch to CPU & Shared Memory Pool (SSD)**
    - 여기서 핵심:

      - **GPU가 CXL을 통해 CPU + SSD + 메모리 풀에 접근**
    - 즉 새로운 메모리 계층 제공:

      - 대용량 메모리 확보
      - SSD/NVMe 레벨까지 확장
      - 데이터 병목 완화
      - unified address space 가능
  - **LPDDR (하단, 회색)**

    - GPU 아래에 **LPDDR 모듈**이 있는게 포인트

      - HBM보다 느리지만 용량 크고 저전력
      - HBM swap / overflow 용도
    - 다시 말하면:

      - HBM = 빠르지만 용량 작음
      - LPDDR = 용량 크지만 느림
      - SSD = 훨씬 느리지만 매우 큼
    - 이걸 CXL까지 합치면:

      - HBM → LPDDR → CXL RAM/SSD → NVMe
    - 이렇게 계층 생김

**📌 전체 데이터 계층 구조 요약**

- - 그림이 의미하는 계층을 정리하면:

    - **Tier-0: HBM (Ultra bandwidth, low latency)**
    - **Tier-1: LPDDR (Large, slower but local)**
    - **Tier-2: CXL DRAM (Shared pool, remote-ish)**
    - **Tier-3: CXL SSD (Very large)**
    - **Tier-4: NVMe (Persistent)**
  - AI 실 workload 대응에 딱 맞는 구조

**📌 전체 패브릭 스택**

|  |  |  |
| --- | --- | --- |
| **계층** | **기술** | **목적** |
| GPU-local | HBM-Link | compute feeding |
| node-internal | NVLink | multi-GPU parallelism |
| cluster-wide | InfiniBand | distributed training |
| memory expansion | CXL | remote memory + sharing |
| storage | PCIe/CXL | NVMe, SSD |

**📌 미래 방향성**

- - 이 그림은 앞으로 나올:

    - NVIDIA GPUs
    - AMD GPUs
    - Intel Gaudi3 이후
    - CXL 3.0 Fabric
    - Disaggregated memory
    - Pooling + Composable datacenter
  - 을 정확히 반영한 구조.
  - 기업들이 가는 방향은 하나:

    - **“Compute는 GPU에, Memory는 Fabric에, Storage는 CXL에”**
  - 이게 바로 **Composed Datacenter / Memory DPU / CXL Fabric Datacenter** 모델

**📌 메모리 구성(Tiered Memory on-package)**

- - 그림에서 눈에 띄는 용량 표시:

    - **HBM (top)** = 240GB + 240GB
    - **HBF (bottom)** = 1024GB
    - **LPDDR (bottom)** = 480GB
  - 이것의 의미는 다음과 같은 **메모리 계층화**

    - Tier-0: HBM8 (초고대역폭, 적은 용량)
    - Tier-1: LPDDR (중간 대역폭, 중간 용량)
    - Tier-2: HBF (큰 용량, 낮은 대역폭)
  - 그런데 중요한 건 **3개가 모두 패키지 내부(on-package)**

**📌 Glass Interposer vs Silicon Interposer**

|  |  |  |
| --- | --- | --- |
| **요소** | **Silicon Interposer** | **Glass Interposer** |
| 대역폭 | 매우 높음 | 높음 |
| 라우팅 길이 | 짧음 | 중간 |
| 비용 | 매우 높음 | 낮음 |
| 면적 | 작음 | 크게 가능 |
| 열전도 | 좋음 | 나쁨 |
| 파워 delivery | 어려움 | 쉬움 |
| warpage | 문제 있음 | 적음 |
