**✅ DV·CV·MDI·DI, KMS·PQC 통합 및 로드맵 분석**

- - 본 보고서는 **양자정보 표현(DV/CV), 프로토콜(BB84·COW·GG02 등), 양자상태 분배 구조(P&M/EB/중앙 측정), 장치 신뢰 가정(MDI/DI), 네트워크 중계 및 제품 계층(QKD/KMS/PQC/인크립터)**을 서로 다른 분류 축으로 분석한다.
  - 제조사 비교는 브랜드 단위의 단순 목록이 아니라 제품명·세대별 실제 공개 기능을 기준으로 한다. 같은 업체에서도 BB84와 COW, DV와 CV, QKD 광학장비와 키 관리 소프트웨어의 역할이 다를 수 있다.
  - 기업이 공식적으로 공개한 제품·연구 실증·향후 계획을 구분한다. 공개되지 않은 검출기 구조나 보안 모델을 특정 프로토콜로 단정하지 않으며, 구매·실증 상태 역시 발표 당시 기준으로 해석한다.

---

**✅ 1. QKD 분류 기준**

- - BB84, B92, E91은 특정 절차를 뜻하지만, CV-QKD는 광장의 연속변수를 이용하는 **큰 기술 계열**이다.
  - MDI-QKD는 **측정장치를 신뢰하지 않는 보안 구조**이며 중앙 공동 측정이라는 특유의 구성도 수반한다. 따라서 DV 방식으로도, CV 방식으로도 구현할 수 있다.
  - E91은 얽힘 기반 프로토콜이지만 그렇다고 자동으로 모든 장치를 신뢰하지 않아도 되는 DI-QKD가 되는 것은 아니다.

|  |  |  |
| --- | --- | --- |
| **분류 축** | **무엇을 묻는가?** | **대표 구분·예시** |
| 양자정보 표현·검출 | 무엇을 어떤 물리량으로 측정하는가? | DV / CV |
| 양자상태의 준비·분배 구조 | 누가 광자를 준비하고 어디에서 측정하는가? | Prepare-and-Measure(P&M) / Entanglement-Based(EB) / 중앙 공동측정 방식 |
| 장치에 대한 보안 가정 | 광원과 검출기 중 무엇을 신뢰해야 하는가? | 장치 특성화 기반 / MDI / DI |
| 구체적 키 확립 프로토콜 | 키 생성·공개 정보·도청 평가의 구체적 규칙은? | BB84 / B92 / E91·BBM92 / COW / GG02 / TF 등 |
| 네트워크 키 전달 구조 | 여러 홉에서 최종 키를 어떻게 전달하는가? | 직접 링크 / Trusted-node 키 릴레이 / 위성 등 |

- - 서로 다른 축이므로 한 장비는 예를 들어 **DV + P&M + Decoy-State BB84 + 위상 인코딩 + Trusted-Node 네트워크**라는 여러 특징을 동시에 가질 수 있다.

**✅ 2. 첫 번째 축: DV-QKD와 CV-QKD는 무엇이 다른가?**

**📌 DV-QKD — 개별 검출 결과를 비트로 취급한다**

- - DV(Discrete-Variable)는 편광, 시간 구간(Time-bin), 위상 등 구분 가능한 양자상태를 사용하고 개별 검출 이벤트를 비트·기호로 처리하는 계열이다.
  - 실제 DV 장비는 약한 레이저 펄스를 사용하는 경우도 많아, 항상 이상적인 단일 광자 하나씩만 발사하는 것은 아니다. 이를 보완하려고 Decoy State를 사용하는 BB84 장비가 많다.
  - 같은 DV-BB84라도 **편광 인코딩**과 **위상/시간 구간 인코딩**이 가능하다. 우리가 입문편에서 설명한 수평·수직·대각선 편광은 BB84의 한 구현 예시이다.

**📌 CV-QKD — 연속적인 빛의 성분을 이용한다**

- - CV(Continuous-Variable)는 빛의 전기장에 관련된 두 직교 성분인 X와 P(Quadratures)에 정보를 실어 전송한다. 일반적으로 약한 변조의 코히런트 광과 코히런트 수신 기법을 활용한다.
  - Homodyne은 한 성분을 선택해 측정하고, Heterodyne은 두 성분에 관한 정보를 함께 얻는다. Heterodyne은 추가 측정 잡음 등 성능상 대가가 있다.
  - 일부 Heterodyne 기반 CV 프로토콜은 BB84처럼 송수신 기저가 달라 절반을 버리는 절차가 필요하지 않다. 하지만 오류 정정·도청 정보 평가·Privacy Amplification은 여전히 필요하다.
  - CV-QKD의 코히런트 검출 기술이 통신용 Coherent Optics와 유사하더라도, **일반 QAM 광전송을 그대로 QKD라고 할 수는 없다.**

|  |  |  |
| --- | --- | --- |
| **비교** | **DV-QKD** | **CV-QKD** |
| 대표 검출 | 단일 광자 검출기(SPAD·SNSPD 등) | Homodyne / Heterodyne 코히런트 검출 |
| 대표 인코딩 | 편광·시간 구간·위상 등의 양자상태 | X·P 연속 성분의 변조 |
| 대표 프로토콜 | BB84·B92·COW·BBM92 등 | GG02/GMCS·No-switching CV 등 |
| 일반 통신망 통합 | 광세기·라만 잡음·필터 설계가 중요 | 코히런트 수신 및 잡음 보정이 중요 |
| 유의점 | 광자 손실과 검출기 공격·다광자 펄스 문제 | Excess noise, 검출기 보정, 신호처리·보안 증명이 중요 |

**✅ 3. 두 번째 축: Alice와 Bob은 어디에서 양자정보를 측정하는가?**

|  |  |  |
| --- | --- | --- |
| **구조** | **양자정보 흐름** | **핵심 특징** |
| P&M (준비·측정) | Alice → Bob | Alice가 상태를 준비하고 Bob이 검출한다. 표준 BB84·B92·GG02의 전형적 형태이다. |
| EB (얽힘 기반) | 광원 → Alice와 Bob 각각 | 양측이 공유한 얽힘의 상관관계에서 키를 추출한다. 광원은 제3자 쪽에 둘 수도 있다. |
| 중앙 공동 측정 | Alice → Charlie ← Bob | 양측이 상태를 준비해 Charlie에서 공동 측정하고, 공개된 측정 결과를 활용한다. MDI-QKD의 대표 구성이다. |

- - 이 세 구성은 그림을 이해하는 편의적 구분이다. 엄격한 수학적 보안 증명에서는 P&M을 가상적인 EB 표현으로 바꿔 분석하기도 하므로, 이름만으로 물리적 구현과 보안 증명을 일대일로 대응시키면 안 된다.
  - 또한 **측정소의 위치**와 **장치를 신뢰해야 하는지**는 별개이다. 중앙에 장비가 있다고 무조건 MDI가 되지는 않는다.

---

**✅ 4. 세 번째 축: MDI-QKD와 DI-QKD에서 무엇을 신뢰하지 않는가?**

**📌 MDI-QKD — Charlie가 측정 결과를 조작할 수도 있다는 가정이다**

- - MDI(Measurement-Device-Independent)에서는 중앙의 Charlie가 광자를 함께 측정하고 결과를 발표하지만, **Charlie의 검출기 자체를 신뢰하지 않아도** 보안을 확보하도록 설계한다.
  - 핵심은 보안 분석에 필요한 조건을 충족한 Alice·Bob의 상태 준비와 후처리이다. Alice·Bob 광원의 특성화, 고전채널 인증, 장치 구현 조건은 여전히 중요하다.
  - 대표적으로 DV-MDI-QKD는 BB84와 유사한 상태 준비와 Bell-state measurement를 결합한다. CV-MDI-QKD도 존재하지만 검출·후처리 방식이 다르다.
  - 즉 **“BB84냐 MDI냐”라는 선택 질문은 부정확**한다. “BB84 상태를 활용한 DV-MDI 구성인가?”라고 물어야 한다.

**📌 DI-QKD — 장치 내부에 대한 가정을 더욱 줄이려는 방식이다**

- - DI(Device-Independent)는 장치의 세부 동작을 신뢰하기보다 Bell 부등식 위반 등 실험으로 관찰된 비고전적 상관관계를 바탕으로 보안을 입증하는 접근이다.
  - E91은 Bell 테스트를 이용하는 원래 프로토콜이지만 **“E91 = 곧바로 DI-QKD”**라고 볼 수 없다. 검출 효율, loophole, 독립 난수, 실험실 보안 등 엄격한 조건이 추가된다.
  - DI는 MDI보다 더 강한 신뢰 가정을 목표로 하지만 구현과 키 생성 성능 측면에서 훨씬 어렵다. 두 방식 모두 실사용 제품인지, 연구 실증인지 구분해야 한다.

|  |  |  |
| --- | --- | --- |
| **구분** | **MDI-QKD** | **DI-QKD** |
| 전체 이름 | Measurement-Device-Independent | Device-Independent |
| 신뢰하지 않아도 되는 대상 | 측정 장치 | 원칙적으로 송수신 양측의 양자장치 내부 동작 |
| 주요 보안 원리 | 신뢰하지 않는 중간 측정소 이용 | Bell 부등식 위반 등을 통한 보안 검증 |
| 광원에 대한 가정 | Alice·Bob의 광원을 특성화하고 신뢰 | 광원의 세부 동작을 신뢰할 필요를 줄임 |
| 구현 난이도 | 높음 | 더욱 높음 |

**✅ 5. 네 번째 축: BB84, E91, COW, GG02는 프로토콜 이름이다**

- - 프로토콜은 광자·변조 정보의 준비부터 공개 정보 교환, 오류 검증, 안전한 키를 만드는 후처리까지 구체적인 규칙을 규정한다.
  - Decoy State는 BB84와 경쟁하는 별도의 최상위 QKD가 아니라 실제 약한 광원에서 다광자 문제를 다루기 위한 **보안 기법**이다. Efficient/Biased-basis 역시 BB84의 효율 개선 기법이다.

|  |  |  |  |
| --- | --- | --- | --- |
| **프로토콜·계열** | **기본 분류** | **핵심 메커니즘** | **주의할 점** |
| BB84 (1984) | 주로 DV·P&M | 2개 기저, 상태 준비·측정, 기저 공지와 Sifting | 편광뿐 아니라 위상·시간 구간 구현도 있다. |
| Decoy-State / Efficient BB84 | DV·BB84의 변형 | 광세기 조절로 다광자 공격 평가 / 비대칭 기저 선택으로 효율 개선 | 독립적인 DV/CV 분류 축이 아니다. |
| B92 (1992) | DV·P&M | 2개 비직교 상태, 확정적으로 판별한 결과 선별 | BB84처럼 4상태 기저 일치만 보는 방법과 다르다. |
| COW / DPS | DV 계열·분산 위상 참조 | 연속 펄스 사이의 시간·간섭 특성 활용 | 보안 증명·장치 모델은 BB84와 다르다. |
| E91 (1991) | 주로 DV·EB | 얽힌 쌍의 상관관계, Bell 검사 | 원래 E91와 모든 현대 DI 보안 조건은 동일하지 않다. |
| BBM92 (1992) | DV·EB | 얽힌 광자 측정으로 공유키 확보 | 일반적으로 E91과 비교해 Bell 검사 요구 구성이 다르다. |
| GG02 / GMCS (2002) | CV·P&M | 가우시안 변조 코히런트 상태 | Homodyne 또는 Heterodyne 구성마다 후처리가 다르다. |
| No-switching CV | CV·P&M | Heterodyne으로 두 성분 관찰 | BB84식 기저 불일치 폐기가 필수는 아니다. |
| DV-MDI / CV-MDI | DV 또는 CV + MDI | 신뢰하지 않는 중앙 측정소의 공개 결과 활용 | MDI는 별도 보안 모델·구조 축과 교차한다. |
| TF-QKD | 주로 DV 기반 장거리 계열 | 중앙 간섭을 활용해 거리 손실 문제 개선 목표 | TF라는 이름만으로 상용 적용·검증을 단정할 수 없다. |

**✅ 6. 여러 홉을 잇는 Trusted Node는 MDI의 Charlie와 다르다**

- - Alice—Relay—Bob을 생각하면, 인접한 Alice–Relay와 Relay–Bob 링크 각각이 QKD 키를 만든다. 일반적인 Trusted-Node 네트워크에서는 Relay의 Key Manager가 종단 키의 릴레이 과정에서 비밀키 재료에 접근할 수 있다.
  - 따라서 **Trusted Node는 침해되지 않는다는 신뢰**가 필요하다. 반면 MDI에서 Charlie는 공개 측정 결과를 발표할 뿐, 올바른 프로토콜 조건하에서 최종 키를 알지 못해도 되도록 설계한다.
  - 중앙 측정소를 신뢰하지 않아도 된다는 이유만으로 MDI가 여러 홉을 무제한 연결하거나 양자 리피터 역할까지 한다는 뜻은 아니다.
  - ITU-T Y.3802는 QKD 키를 KMA가 받아 보관·동기화·키 릴레이하고, KSA가 암호 애플리케이션에 공급하는 구조를 정의한다. 키 릴레이에서는 OTP를 권장한다.

**✅ 7. 분류 축을 결합하면 제품의 실제 기술적 좌표가 드러난다**

- - DV/CV를 구분하는 기준은 **양자신호의 검출 모델과 취급하는 변수**다. 편광 인코딩만 DV라고 생각하거나, 위상을 이용하면 반드시 CV라고 생각하면 잘못이다. BB84의 위상·Time-bin 인코딩도 대표적인 DV 구현이 가능하다.
  - P&M과 EB는 상태를 어디서 어떻게 준비하고 분배하는지 설명한다. BB84·B92·GG02의 전형적 송수신 구성은 P&M이며 E91·BBM92는 얽힘 기반(EB)이다. 다만 보안 증명에서 P&M을 수학적으로 EB 표현으로 바꾸는 경우가 있어 분류가 곧 증명의 유일한 표현을 뜻하지는 않는다.
  - MDI는 "중앙에 측정 장비가 있다"는 장비 위치 설명이 아니다. **측정 장치의 신뢰를 보안 가정에서 배제할 수 있는지**에 관한 속성이다. 따라서 DV-MDI 또는 CV-MDI라는 조합이 가능하며, 중간 노드에서 키를 직접 볼 수 있는 Trusted Relay와 혼동해서는 안 된다.
  - 제품의 실제 비교에서는 "DV냐 CV냐"만으로 결론이 나지 않는다. 보안 증명의 가정, 비밀키 생성률(SKR), 실제 손실(dB), WDM 공존, 키 저장·공급, 운영 정책 및 암호화 엔진의 통합 범위까지 확인해야 한다.

| DV / CV | 무엇을 송신하고 어떤 수신기로 측정하는가? | 인코딩·검출기·모듈레이션 자료 | 위상 사용 = 곧 CV |

**✅ 8. QKD 제품만 설치하면 실제 데이터가 암호화되는가? — 제품의 계층부터 구분한다**

- - **아니다.** QKD 광학장비는 두 지점에 공유 비밀키를 제공하는 장치이다. 실제 Ethernet·OTN·IP 트래픽을 보호하려면 별도의 인크립터 또는 암호화 기능이 필요하다.
  - 이 차이를 이해하면 QKD, PQC, QRNG, KMS, Encrypter가 한 제품 소개에 함께 등장하는 이유가 보인다. 공급업체들이 서로 다른 계층을 단일 플랫폼으로 묶고 있기 때문이다.
  - **QKD와 ML-KEM은 공유 비밀을 확보하는 수단**이라는 공통점이 있다. 하지만 QKD는 양자 물리 채널과 광학장비에 의존하고, ML-KEM은 일반 네트워크에서 공개키 기반으로 비밀을 확립한다.

|  |  |  |  |
| --- | --- | --- | --- |
| **제품·기술 계층** | **담당 기능** | **대표 사례** | **제품 소개에서 확인할 것** |
| 난수원 | 무작위성 공급 | QRNG (qStream 등) | 난수 발생만으로 두 지점이 같은 키를 갖지는 않는다. |
| QKD 엔진 | 두 지점의 동일한 비밀키 확립 | Clavis, Toshiba QKD, Nova lq | DV/CV, BB84/COW, 실제 키율, 인코딩 확인 |
| PQC 키 확립 | 공개키·개인키 기반 공유 비밀 확립 | ML-KEM | 키 캡슐화이며 데이터 전체 암호화는 별도 |
| 인증·서명 | 통신 상대 인증·무결성 보장 | ML-DSA, SLH-DSA, MAC | 서명 검증과 실제 신원 바인딩 확인 |
| KMS / 키 전달 | 키 저장·정책·공급·릴레이 | Clarion KX, qConnect, KMS | QKD/PQC 연동, API, 키 조합 정책, 장애 대응 |
| 트래픽 인크립터 | 고객 데이터를 실제 암호화 | AES-256-GCM, ChaCha20-Poly1305, OTP | L1/L2/L3 적용 계층, throughput, key rotation |

**📌 동일한 인크립터를 쓰더라도 키 확보 경로는 달라진다**

|  |  |  |  |
| --- | --- | --- | --- |
| **구성 사례** | **키 확보** | **인증** | **암호화** |
| QKD 중심 | BB84/CV 등의 QKD + KMS | 사전 공유 인증 또는 PQC 서명 등 | AES-256-GCM |
| PQC 중심 | ML-KEM / 하이브리드 KEM + KDF | ML-DSA 등 | AES-256-GCM |
| QKD + PQC | QKD와 ML-KEM의 비밀 재료를 안전하게 결합 | 상호 인증 및 정책 관리 | AES-256-GCM 또는 별도 OTP 구성 |

- - 비대칭 암호화 기술 자체를 모두 없애는 것이 양자내성 전략은 아니다. 기존 RSA/ECDH/ECDSA의 양자 취약성을 해결하고, 강한 대칭키 암호를 데이터 보호에 사용하는 구조가 중심이다.
  - NIST는 ML-KEM을 공유 비밀 확립용으로 정의하며 [[SP 800-227]](https://csrc.nist.gov/pubs/sp/800/227/final)에서 대칭키 암호와의 결합을 설명한다. 또한 [[RFC 9180]](https://www.rfc-editor.org/rfc/rfc9180)의 HPKE 개념은 공개키 기반 시스템도 내부적으로 대칭키 AEAD를 활용할 수 있음을 보여 준다.
  - 여기서 **제품이 PQC를 지원한다는 문구만으로 ML-KEM, ML-DSA, 데이터 암호화, QKD 키 결합을 모두 구현했다는 뜻은 아니다.** 어떤 계층의 기능을 실제로 지원하는지 따로 확인해야 한다.

**✅ 12. 제품 전략에서 확인해야 할 PQC·QKD 하이브리드의 실제 의미**

- - 기업의 "Quantum-Safe" 또는 "Hybrid" 문구는 반드시 ML-KEM, QKD, AES 암호화를 모두 보유한다는 뜻이 아니다. **양자광원·검출기 장비, PQC 알고리즘을 실행하는 소프트웨어, KMS·키 브로커, 데이터 평면 인크립터**는 별도의 제품 계층이다.
  - PQC 단독 구성은 ML-KEM이나 하이브리드 KEM을 키 확립에 사용하고, QKD 중심 구성은 광학 링크의 키를 KMS로 공급한다. QKD+PQC 결합 구성에서는 서로 다른 비밀 재료를 적절한 결합 함수에 넣고 인증·키 출처·사용 목적을 추적하는 설계가 추가된다.
  - 데이터 평면에서 **AES-256-GCM을 사용한다면 QKD와 PQC 어느 쪽에서도 고객 트래픽 암호화 알고리즘 자체는 동일할 수 있다.** 기업 전략의 차이는 QKD 채널 구축 가능 범위, 키 관리 API, 크립토 애질리티, 인증 체계, 네트워크 운영자동화에서 나타난다.
  - 제품 로드맵 발표에서 "QKD Ready", "PQC Ready", "Quantum-Safe"를 동등한 상용 기능으로 취급해서는 안 된다. 제품별 지원된 알고리즘·표준·버전·인터페이스·시험 현황을 요구해야 한다.

**📌 공급사 비교용 실무 질문**

- - **① 제품명·세대·프로토콜:** 같은 브랜드라도 Clavis·Cerberis처럼 프로토콜이 다를 수 있다. 제품별 공식 문서의 명시 수준을 기록해야 한다.
  - **② 실제 SKR:** 광고된 키율은 전송거리·손실·동시 데이터 채널·검출기 조건을 함께 읽어야 한다. 장비의 내부 raw key rate와 최종 secret key rate를 혼동해서는 안 된다.
  - **③ KMS 및 암호화 연동:** Key ID, 애플리케이션 인증, 키 동기화·보관·폐기, AES 엔진의 키 갱신 인터페이스, PQC fallback을 검증해야 한다.
  - **④ 안전성 보증:** 공격 모델에 부합하는 광원·검출기 하드웨어 검사, 인증·설치 환경, 실제 제품의 인증·검증 결과를 확인해야 한다.
  - **⑤ 장래 개발:** 실증·출시·대규모 배포 계획 사이의 상태 차이를 제조사 발표일과 함께 추적해야 한다.

- - MDI-QKD, DI-QKD, TF-QKD, 양자 리피터는 안전성 또는 장거리 확장성을 높이기 위한 중요한 연구 방향이지만, 그 이름이 기업 자료에 등장했다고 해서 기존 상용 제품에 이미 탑재됐다고 판단할 수 없다.
  - 이번에 확인한 주요 제품 자료에서는 **MDI·DI를 현재 판매 중인 위 제품의 확정 프로토콜이라고 검증할 자료가 없었다.** 따라서 관련 가능성은 기술 트렌드로 설명하되 제품별 상용 탑재 여부는 미확인으로 남긴다.
  - 일부 기업의 향후 위성·리피터 연구는 확인되지만, 임의의 2027~2030년 상용화 일정을 가정해 적지는 않았다.

**✅ 14. 실제 네트워크 설계에서는 프로토콜 이름보다 확인해야 할 것이 많다**

**📌 ① 키 생성률을 데이터 전송률과 혼동하지 않는다**

- - QKD 장비의 SKR(Secret Key Rate)은 AES로 암호화할 수 있는 데이터 링크 속도와 다르다. 예컨대 수백 kb/s 비밀키 생성으로도 키를 주기적으로 교체하는 AES-256 링크의 대량 트래픽을 보호할 수 있다.
  - 반면 사용자 데이터 자체를 OTP로 암호화한다면 보호할 데이터만큼 새 키가 필요해 훨씬 높은 키 생성·전달률이 요구된다.

**📌 ② Fiber 조건과 공존 설계를 확인한다**

- - DV냐 CV냐보다 현장에서는 거리·삽입손실·커넥터·WDM 필터·광증폭기 위치·일반 채널의 광출력·라만 잡음·편광·파장 대역이 실제 도입을 좌우한다.
  - 메트로 DWDM 공존을 발표한 장비도 모든 C/L-band 채널과 모든 송신 출력을 무조건 수용하는 것은 아니다. 광링크 예산과 QBER/Excess Noise의 검증이 필요하다.

**📌 ③ 보안 주장을 어느 계층에서 하는지 확인한다**

- - 장치가 “MDI”라는 말과 네트워크가 “Trusted Node 불필요”라는 말은 다르다. 중앙 측정소의 비신뢰와 종단 키 중계 노드의 신뢰를 분리해 설계해야 한다.
  - KMS의 관리 API(예: ETSI GS QKD 014) 지원은 서로 다른 QKD 장치의 광학 프로토콜이 상호운용된다는 보장은 아니다.
  - PQC 인증의 안전성, KMS 접근통제, 키 폐기, 광학 측면채널 공격, 가용성 및 장애 시 대체 키 설정까지 검토해야 한다.

**📌 ④ 공급업체를 비교할 때는 질문을 동일하게 맞춘다**

|  |  |
| --- | --- |
| **구매·설계 질문** | **확인할 사항** |
| 양자 물리 계층 | DV/CV, 편광/위상/시간구간, 검출 방식, 신호의 파장 |
| 프로토콜·보안 증명 | BB84/Decoy/COW/GG02 등, 유한 키 분석, 구현 공격 대응 |

**✅ 15. 최종 정리 — 같은 분류표에 나열하지 말고 좌표로 읽어야 한다**

- - **DV와 CV**는 양자정보를 표현하고 검출하는 물리적 방법의 차이이다.
  - **P&M, EB, 중앙 공동측정**은 양자상태의 준비·분배·측정 구조의 차이이다.
  - **MDI와 DI**는 장치의 어느 부분에 대한 신뢰 가정을 줄일 것인지에 관한 차이이다.
  - **BB84, B92, COW, E91, BBM92, GG02**는 실제 키 생성·검증 절차의 차이이다.
  - **Trusted-Node Key Relay**는 여러 링크를 연결해 키를 공급하는 네트워크 계층이며 MDI의 Charlie와 동일하지 않다.
  - 시장에서는 BB84 계열 DV-QKD 장비의 제품화 사례가 많이 확인되지만, CV-QKD도 제품으로 판매되며 COW 방식도 상용 제품으로 출시된 이력이 있다(여기서 확인한 Cerberis 모델은 판매 종료). **시장점유율을 검증하지 않은 상태에서 “어느 방식이 시장의 몇 %를 차지한다”고 수치화하지 않았다.**
  - **한 줄 결론:** “어느 회사가 어떤 QKD를 쓰는가?”라는 질문에는 회사 이름 하나보다 **제품별 물리 계층 + 구체적 프로토콜 + 신뢰 모델 + 네트워크 구조 + 상용화 상태**라는 다섯 개의 답이 필요하다.
