**✅ 1. 기존 네트워크 보안은 무엇을 신뢰했는가?**

**📌 외부 침입을 막는 경계 중심 보안**

- - 전통적인 기업 네트워크 보안은 외부와 내부를 구분하는 경계(Perimeter)를 중심으로 발전해 왔다.
  - 인터넷과 사내 네트워크 사이에 방화벽을 배치하고, 외부에서 들어오는 트래픽을 검사하며, 승인되지 않은 접근을 차단하는 방식이다.
  - VPN, NAC, IDS/IPS 등의 기술도 네트워크의 여러 지점에서 이러한 보안을 보완해 왔다.
  - 문제는 일단 내부에 들어온 사용자나 단말에 상대적으로 넓은 접근 권한이 주어지는 환경이 많았다는 것이다.
  - 물론 기존 기업 네트워크에도 내부 방화벽, VLAN, ACL, 서버별 접근제어가 존재했다. 따라서 내부망이 무조건 개방되어 있었다는 뜻은 아니다.
  - 다만 네트워크 위치와 소속을 신뢰의 중요한 기준으로 삼았기 때문에, 하나의 계정이나 단말이 탈취되면 공격자가 예상보다 넓은 범위로 이동할 가능성이 있었다.

|  |  |  |
| --- | --- | --- |
| **비교 항목** | **기존 경계 중심 보안** | **Zero Trust 접근** |
| 기본적인 보안 관점 | 내부와 외부의 경계 보호 | 개별 사용자·장비·자원 보호 |
| 신뢰의 기준 | 네트워크 위치, 접속 인증, 기존 권한 | 신원, 장비 상태, 권한, 상황 정보 |
| 내부 사용자 | 기존 권한에 따라 비교적 넓은 접근이 가능할 수 있음 | 필요한 자원에 대한 최소 권한만 허용 |
| 내부 이동 | VLAN·방화벽·ACL 설계에 의존 | 자원·그룹별 세분화된 정책 적용 |
| 권한 변경 | 정적 정책이나 별도 자동화에 의존 | 신원·위험도 등 조건 변화에 따른 정책 갱신 |
| 공격 발생 시 | 탐지·차단·복구에 중점 | 탐지·차단에 더해 확산 경로 최소화 |

- - 이러한 차이는 단순히 보안 장비를 어디에 배치하느냐의 문제가 아니다.
  - **네트워크에 접속했다는 사실만으로 다른 자원에 접근할 권한을 부여하지 않는다는 보안 철학의 차이**다.

**📌 신뢰받는 내부 PC가 공격의 출발점이 된다면?**

- - 한 직원이 정상적으로 VPN을 이용해 회사 네트워크에 접속했다고 가정해 보자.
  - 그런데 직원의 PC가 이미 악성코드에 감염되어 있거나 계정이 탈취된 상태라면 어떻게 될까?
  - 공격자는 해당 PC가 가진 기존 네트워크 접근 권한을 악용해 파일서버, 데이터베이스, 다른 직원의 PC 등을 탐색할 수 있다.
  - 이를 네트워크 내부에서 횡방향으로 이동한다는 의미에서 Lateral Movement(횡적 이동)라고 부른다.
  - 바로 이러한 이동을 어렵게 만드는 것이 제로트러스트의 중요한 목적이다.

---

**✅ 2. 제로트러스트는 건물의 출입관리 시스템과 같다**

**📌 건물에 들어왔다고 모든 방에 들어갈 수 있는 것은 아니다**

- - Elisity는 건물 출입 자체를 막는 경비원이라기보다, 건물에 들어온 사람이 허가된 구역에만 접근하도록 통제하는 지능형 출입관리 시스템에 가깝다.
  - 회사 건물에 들어왔다고 해서 누구나 연구실, 재무부서, 서버실까지 자유롭게 들어갈 수 있어서는 안 된다.
  - 방문객은 로비와 라운지만, 일반 직원은 자신의 업무 공간과 필요한 공용 시설만 이용할 수 있도록 제한하는 것이다.
  - 서버실 관리자는 업무에 필요한 경우 서버실에 출입할 수 있겠지만, 그 권한이 다른 모든 보안 구역의 출입까지 보장하는 것은 아니다.

|  |  |
| --- | --- |
| **실제 건물 보안** | **기업 네트워크 보안** |
| 출입구에서 신원 확인 | NAC, 802.1X, 사용자 인증 |
| 직원·방문객 신원 파악 | Identity 및 장비 식별 |
| 직원별 출입 가능 구역 지정 | Microsegmentation Policy |
| 방문객은 로비·라운지만 접근 | 미인가 단말은 제한된 네트워크 자원만 접근 |
| 연구실·서버실 출입 제한 | 중요 서버·DB 접근 차단 |
| CCTV와 보안 관제 | IDS/IPS, NDR, EDR 등 |
| 위험 인물의 출입 권한 회수 | 위험 상태 기반 정책 변경 및 격리 |

- - 이 비유에서 중요한 사실은 모든 사람을 잠재적인 범죄자로 취급한다는 뜻이 아니라는 것이다.
  - **누구도 필요 이상의 권한을 가져서는 안 된다는 의미**다.

**📌 이미 허가받은 직원이라도 권한은 바뀔 수 있다**

- - 제로트러스트의 또 다른 특징은 한번 부여한 권한을 영구적으로 신뢰하지 않는다는 것이다.
  - 예를 들어 정상적으로 연구실에 출입하던 직원이 갑자기 보안 위험 인물로 판정되었다고 가정해 보자.
  - 출입관리 시스템은 기존의 출입 권한을 변경하여 연구실 출입을 제한할 수 있어야 한다.
  - 네트워크에서도 동일한 원리가 적용된다.
  - 정상적으로 사용하던 PC가 EDR에 의해 감염된 것으로 판정되거나 장비의 보안 상태가 악화되면, 기존에 허용했던 서버 접근 권한을 축소하거나 제한된 격리 그룹으로 이동시킬 수 있다.
  - 이러한 변화는 사전에 구성한 동적 정책과 외부 보안 시스템의 연동 상태에 따라 자동화할 수 있다.
  - 다만 여기서 말하는 지속적인 검증은 모든 패킷을 매번 새로 인증한다는 뜻은 아니다. 신원·장비 상태·위험도 등의 변화에 따라 접근 권한을 다시 평가한다는 의미다.

**✅ 3. 제로트러스트는 특정 제품이 아니라 보안 원칙이다**

**📌 NIST SP 800-207이 정의한 Zero Trust**

- - 2020년 미국 국립표준기술연구소(NIST)는 SP 800-207을 통해 제로트러스트 아키텍처를 체계적으로 정의했다.
  - 여기서 중요한 원칙은 사용자나 장비가 기업 내부망에 존재한다는 이유만으로 신뢰를 부여해서는 안 된다는 것이다.
  - 접근 허용은 사용자의 신원, 장비 상태, 요청하는 자원과 권한, 기타 정책 조건을 바탕으로 결정되어야 한다.
  - NIST는 보호의 중심을 네트워크 경계에서 개별 자원으로 옮겨야 한다고 설명한다.

|  |  |
| --- | --- |
| **핵심 원칙** | **의미** |
| Never Trust Implicitly | 내부망에 있다는 이유만으로 신뢰하지 않는다 |
| Verify Explicitly | 신원·장치·상황 정보 등을 이용해 접근을 확인한다 |
| Least Privilege Access | 업무 수행에 필요한 최소한의 권한만 부여한다 |
| Continuous Evaluation | 권한을 영구적 상태로 보지 않고 조건 변화에 따라 재평가한다 |
| Assume Breach | 공격자가 이미 내부에 존재할 가능성을 가정하고 방어한다 |

- - 다만 마지막의 Assume Breach는 공격을 무조건 허용한다는 의미가 아니다.
  - 침입이 발생하더라도 그 피해가 다른 자원으로 확산되지 않도록 시스템을 설계하라는 것이다.

**📌 Zero Trust가 보호해야 할 다섯 가지 영역**

- - 미국 CISA의 Zero Trust Maturity Model은 제로트러스트를 다섯 가지 보안 영역으로 구분한다.

|  |  |
| --- | --- |
| **보안 영역** | **보호 대상** |
| Identity | 사용자, 서비스 계정, 비인간 신원 |
| Devices | PC, 서버, 모바일, IoT 및 OT 장비 |
| Networks | 내부망, 외부망, 네트워크 통신 경로 |
| Applications & Workloads | 애플리케이션, 가상머신, 컨테이너, 서비스 |
| Data | 중요 데이터, 저장 정보, 전송 정보 |

- - 이러한 영역에 걸쳐 Visibility & Analytics, Automation & Orchestration, Governance와 같은 공통 역량이 필요하다.
  - 따라서 어떤 보안 제품이 제로트러스트를 지원한다고 해서 다섯 영역을 모두 책임진다는 의미는 아니다.
  - 이 점은 Elisity의 경쟁력을 이해할 때도 매우 중요하다.

**✅ 4. 기존 보안 제품과 무엇이 다른가?**

**📌 NAC와 Microsegmentation은 같은 기술이 아니다**

- - 앞서 건물의 출입구와 건물 내부의 출입통제를 구분했다.
  - 실제 네트워크에서도 이러한 역할은 서로 다른 기술이 담당한다.
  - NAC(Network Access Control)는 사용자 또는 장비의 네트워크 접속을 인증하고 허용 여부를 결정하는 데 중점을 둔다.
  - 반면 Microsegmentation은 이미 네트워크에 연결된 장비 사이에서 어떤 통신을 허용할 것인지 세밀하게 통제하는 기술이다.
  - 물론 현대적인 NAC도 역할 기반 VLAN·ACL·SGT 등을 이용해 내부 접근을 제한할 수 있으므로 두 기술이 완전히 분리된 것은 아니다.

|  |  |  |
| --- | --- | --- |
| **보안 기술** | **주요 목적** | **대표적인 역할** |
| Firewall / NGFW | 트래픽 접근 및 위협 통제 | 정책 기반 차단, 애플리케이션 식별, 위협 검사 |
| NAC (Network Access Control) | 네트워크 접속 제어 | 장비 인증, 접속 허용, 역할별 권한 |
| IDS / IPS  (Intrusion Detection/Prevention System) | 공격 탐지 및 차단 | 알려진 공격 패턴, 프로토콜 이상, 침입 시도 분석 |
| NDR (Network Detection and Response) | 네트워크 위협 탐지·대응 | 트래픽 행동 분석, 이상 징후 및 공격 활동 식별 |
| EDR (Endpoint Detection and Response) | 엔드포인트 위협 탐지·대응 | 악성 프로세스, 파일, 시스템 행위 분석 |
| ZTNA (Zero Trust Network Access) | 승인된 애플리케이션 접근 허용 | 사용자·장치 상태 기반 앱 접속 제어 |
| Microsegmentation | 내부 통신 경로 최소화 | 장비·워크로드 사이의 Allow/Deny 정책 |
| Elisity | Identity-based Microsegmentation | 장비 신원과 위험도 등을 활용한 동적 네트워크 접근 통제 |

**📌 기존 보안 기술과 대체 관계인가?**

- - 그렇지 않다. 위 기술은 서로 보완하는 관계에 있다.
  - 방화벽과 IPS는 외부 및 내부의 악성 트래픽을 검사하고, EDR은 PC와 서버의 악성 행위를 탐지하며, NDR은 네트워크 전반의 이상 행동을 분석한다.
  - Elisity는 이들과 다른 방식으로 장비와 자원 사이의 통신 권한을 제한하는 데 집중한다.
  - 다시 말해 IDS/IPS가 공격의 성격을 파악해 차단하는 기술이라면, Microsegmentation은 **악성 여부가 아직 확인되지 않았더라도 허용되지 않은 통신 경로를 막을 수 있는 기술**이다.
  - 그렇다고 기존 방화벽이 이러한 정책을 구현할 수 없다는 뜻은 아니다. 내부 방화벽과 ACL 역시 마이크로세그멘테이션에 활용할 수 있다.
  - 차이는 정책을 어느 위치에서 얼마나 세밀하게, 그리고 얼마나 쉽게 운영할 수 있느냐에 있다.

**✅ 5. 실제 네트워크에서는 어떻게 작동할까?**

**📌 직원 PC와 의료장비가 같은 기업 네트워크에 있다면?**

- - 다음과 같은 병원 네트워크를 가정해 보자.
  - 병원 직원의 PC, 의료장비, PACS 영상 서버, 전자 의무기록 시스템, 재무 서버, 인터넷 서비스가 존재한다.
  - 각 장비는 업무상 필요한 서비스와만 통신하도록 구성되어야 한다.

|  |  |  |  |
| --- | --- | --- | --- |
| **출발지** | **목적지** | **허용 여부** | **이유** |
| 의료장비 | 승인된 PACS 서버 | Allow | 의료 영상 전송 |
| 의료장비 | 승인된 DNS / NTP | Allow | 이름 확인 및 시간 동기화 |
| 의료장비 | 재무 서버 | Deny | 업무상 불필요 |
| 일반 직원 PC | 승인된 업무 애플리케이션 | Allow | 정상 업무 수행 |
| 일반 직원 PC | 서버 관리 포트 | Deny | 관리자 권한 없음 |
| 외부 방문객 단말 | 게스트 인터넷 서비스 | Allow | 방문객용 접속 |
| 외부 방문객 단말 | 내부 업무 서버 | Deny | 내부 접근 권한 없음 |
| 감염된 것으로 판정된 PC | 격리 정책상 허용되지 않은 내부 자원 | Deny | 확산 방지 |

- - 위 표는 실제 고객의 정책이 아니라 원리를 설명하기 위한 예시다.
  - 모든 의료장비에 TCP 104만 허용한다거나 모든 직원에게 동일한 정책을 적용한다는 의미는 아니다.
  - 중요한 것은 네트워크에 연결되어 있다는 사실이 다른 모든 장비와 통신할 권리를 보장하지 않는다는 것이다.

**📌 VLAN만 나누면 해결되는 문제가 아닐까?**

- - 전통적으로 네트워크를 구분하는 가장 대표적인 방법은 VLAN이었다.
  - 의료장비, 직원 PC, 서버를 다른 VLAN이나 서브넷으로 구분하고 VLAN 간 트래픽을 방화벽 또는 ACL로 제한할 수 있다.
  - 이 방식도 유효한 세그멘테이션 기술이다.
  - 그러나 동일 VLAN에 연결된 여러 장비가 서로 자유롭게 통신할 수 있도록 구성되어 있다면 하나의 장비가 감염되었을 때 다른 장비로 이동할 위험이 남는다.
  - Microsegmentation은 VLAN 단위보다 작은 장비·그룹·워크로드 단위의 통신 관계까지 통제하려는 접근이다.

|  |  |  |
| --- | --- | --- |
| **비교 항목** | **전통적인 VLAN 중심 분리** | **Microsegmentation** |
| 주된 분리 단위 | VLAN, 서브넷, 보안 구역 | 장비, 신원 그룹, 워크로드 |
| 정책 기준 | IP 대역, VLAN, ACL 등 | 신원·장비 속성·위험도 및 통신 관계 |
| 동일 VLAN 내부 통제 | 추가 제어장치나 ACL 필요 | 지원 집행 지점에서 세밀한 통제 가능 |
| 장비 위치 변경 | IP/VLAN 구조에 정책이 의존할 수 있음 | 동적 신원 기반 정책을 유지하도록 설계 가능 |
| 운영상의 과제 | 네트워크 구조와 정책 복잡성 | 자산 식별, 정책 정확도, 집행 지점의 호환성 |

- - 여기서 Microsegmentation 자체가 특별한 새로운 통신 프로토콜을 의미하는 것은 아니다.
  - 여러 보안 정책 집행 기술을 결합해 네트워크의 신뢰 영역을 더욱 작게 만드는 아키텍처에 가깝다.

---

**✅ 6. 랜섬웨어 감염을 가정해 보자**

**📌 첫 번째 방어 — 공격을 발견하기 전에 이동 경로를 제한한다**

- - 병원 직원의 PC가 악성코드에 감염되었다고 가정해 보자.
  - 공격자는 해당 PC를 이용해 병원 내부의 파일서버와 의료장비, 데이터베이스에 접근하려고 시도한다.
  - 이때 사전에 적절한 Microsegmentation 정책이 적용되어 있다면 승인되지 않은 네트워크 통신이 차단된다.
  - 보안 시스템이 랜섬웨어 종류를 정확하게 알아내지 못했더라도 이미 허용되지 않은 서버로 이동하는 경로를 차단할 수 있다는 의미다.
  - **감염된 PC의 통신 경로 예시**

|  |  |  |
| --- | --- | --- |
| **감염된 PC의 통신 대상** | **정상 시점에 허용된 권한** | **초기 감염 후 동작** |
| 승인된 업무 시스템 | 허용 | 기존 정책 범위 내 접근 가능 |
| 의료장비 네트워크 | 차단 | 접근 차단 |
| 재무 데이터베이스 | 차단 | 접근 차단 |
| 관리자 전용 서버 | 차단 | 접근 차단 |
| 승인되지 않은 내부 PC | 차단 | 접근 차단 |

- - 이 정책만으로 해당 PC 안의 랜섬웨어가 제거되는 것은 아니다.
  - 또한 이미 허용된 업무 시스템까지 악용하는 공격은 계속 발생할 수 있다.
  - 따라서 Microsegmentation의 효과는 허용된 통신 관계를 얼마나 정확하고 좁게 설계했는지에 달려 있다.

**📌 두 번째 방어 — 위험 장비로 판정되면 접근 권한을 줄인다**

- - 이번에는 EDR이 감염된 PC에서 악성 프로세스를 발견했다고 가정해 보자.
  - Elisity와 EDR이 연동되어 있다면 해당 장비의 보안 상태 정보가 IdentityGraph에 반영될 수 있다.
  - 관리자가 위험도나 신뢰 상태에 따라 적용할 정책을 사전에 설정했다면 장비는 제한된 Policy Group으로 재분류될 수 있다.
  - 이때 복구에 필요한 보안 관리 서버 등 일부 통신만 허용하고 나머지 내부 자원과의 연결을 제한하는 구성을 만들 수 있다.
  - **동적 격리 과정**

|  |  |  |
| --- | --- | --- |
| **단계** | **주체** | **수행하는 작업** |
| 1 | EDR | PC에서 의심스러운 악성 행위 발견 |
| 2 | IdentityGraph | 연동된 보안 상태 및 장비 정보 갱신 |
| 3 | Dynamic Policy Group | 사전 정의된 조건에 따라 그룹 재분류 |
| 4 | VE / 정책 집행 인프라 | 변경된 보안 정책 전달 |
| 5 | 네트워크 스위치 | 허용되지 않은 통신 차단 |
| 6 | 보안 운영팀 | 감염 조사, 복구, 정책 재검토 |

- - 이 과정은 모든 위협을 Elisity가 자체적으로 탐지한다는 의미가 아니다.
  - 공격 탐지는 EDR 같은 전문 보안 솔루션이 수행하고, Elisity는 그 판단을 네트워크 접근 통제에 활용할 수 있다.
  - 또한 각 단계의 처리 시간과 연동 주기에 따라 실제 격리 속도가 달라진다.

---

**✅ 7. Elisity는 Zero Trust의 어떤 부분을 구현하는가?**

**📌 핵심은 Identity-based Microsegmentation**

- - Elisity는 기존 기업 네트워크에 연결된 장비의 신원과 보안 관련 속성을 활용해 접근을 통제하는 플랫폼이다.
  - 사용자의 부서나 역할뿐 아니라 장비 유형, 제조사, 위치, 자산관리 시스템의 등록 상태, 보안 솔루션이 제공하는 위험 정보 등을 정책 조건으로 활용할 수 있다.
  - 이를 바탕으로 여러 장비를 Policy Group으로 분류하고 그룹 사이의 허용·차단 규칙을 집행한다.
  - 특히 기존에 설치된 지원 네트워크 스위치를 정책 집행 지점으로 활용할 수 있다는 점이 특징이다.

**📌 Elisity의 역할은 어디까지인가?**

|  |  |
| --- | --- |
| **보안 기능** | **Elisity의 주요 역할** |
| 사용자·장비 식별 | 네트워크 관측 정보와 외부 신원 시스템의 정보 결합 |
| 보안 상태 평가 | EDR·CMDB·IoT/OT 보안 제품 등의 속성 활용 |
| 통신 관계 가시화 | 장비 간 Flow와 정책 적용 상태 확인 |
| 최소 권한 정책 | 그룹 간 Allow/Deny 규칙 정의 |
| 정책 사전 검증 | Simulation Mode에서 영향 확인 |
| 동적 권한 변경 | 속성·위험 상태에 따른 Policy Group 변경 |
| 침입 후 확산 제한 | 승인되지 않은 내부 통신 차단 |
| 악성코드 직접 분석 | 전문적인 EDR·IDS/IPS 기능을 대체하지 않음 |

- - Elisity의 AI 기능은 장비 분류와 정책 추천 등을 지원한다.
  - 다만 AI가 제안한 새로운 보안 정책이 관리자 검토 없이 무조건 적용되는 구조는 아니다. 공식 자료에 따르면 AI 정책 추천은 기본적으로 Simulation Mode에 생성된다.
  - 반면 사전에 관리자가 활성화한 동적 정책은 조건 변화에 따라 자동으로 적용될 수 있다.

---

**✅ 8. Zero Trust도 완벽한 방어책은 아니다**

- - 제로트러스트가 유용한 보안 원칙이라는 사실과 이것만으로 모든 공격을 막을 수 있다는 주장은 구분해야 한다.
  - 우선 장비나 사용자의 신원을 잘못 판단하면 잘못된 접근 권한을 부여할 수 있다.
  - 외부 보안 시스템이 공격을 늦게 탐지하면 동적 격리도 늦어질 수 있다.
  - 또한 네트워크 스위치의 지원 기능이나 ACL 자원에 따라 정책 적용 범위가 제한될 수 있다.
  - 마지막으로 최소 권한 정책이 이미 허용하고 있는 업무 경로 자체가 공격에 악용될 가능성도 존재한다.

|  |  |
| --- | --- |
| **주요 한계** | **의미** |
| 신원 식별 오류 | 잘못 분류된 장비에 부적절한 권한이 적용될 수 있음 |
| 탐지 의존성 | 보안 위험 판정이 늦어지면 동적 격리도 지연 |
| 정책 설계 오류 | 허용 범위가 넓으면 공격자의 이동 경로가 남음 |
| 인프라 호환성 | 스위치 모델 및 기능에 따라 집행 가능 범위가 달라짐 |
| 정상 경로 악용 | 승인된 애플리케이션·세션을 이용하는 공격까지 모두 차단하지는 못함 |
| 운영상의 복잡성 | 지나치게 엄격한 정책은 정상 업무를 중단시킬 수 있음 |

- - 그러므로 제로트러스트는 기존 보안 시스템을 전부 교체하자는 개념이 아니다.
  - 방화벽, NAC, IDS/IPS, EDR, NDR, IAM과 같은 기존 기술을 활용하면서 암묵적인 신뢰를 줄이고, 접근 권한을 세분화하는 방향으로 보안 구조를 발전시키자는 것이다.

---

**✅ 결론 — 중요한 것은 침입 여부만이 아니라 침입 이후의 이동 범위다**

- - 기존 네트워크 보안이 외부에서 들어오는 공격을 방어하고 침입을 탐지하는 데 많은 노력을 기울여 왔다면, 제로트러스트는 여기에 또 다른 질문을 던진다.

    - **공격자가 이미 내부에 들어왔다면 어디까지 이동할 수 있는가?**
  - 정상적인 직원의 계정이나 PC가 탈취되었더라도 공격자가 내부 네트워크를 자유롭게 돌아다닐 수 없다면 피해 범위는 줄어들 수 있다.
  - 그리고 공격을 미리 탐지하지 못했더라도 불필요한 통신 경로를 사전에 차단해 두었다면 여러 공격 경로를 제한할 수 있다.
  - 이것이 Zero Trust와 Microsegmentation을 이해하는 핵심이다.
  - 하지만 이러한 개념은 Elisity만의 독자적인 기술이 아니다. 이미 여러 보안 기업들이 각기 다른 방식으로 동일한 원칙을 구현하고 있다.
  - 따라서 앞으로는 Elisity의 실제 구현 방식과 경쟁사 대비 기술적 차별성을 하나씩 검증할 필요가 있다.

> ***다음 편에서는 「Elisity의 아키텍처 — 기존 스위치가 보안 장비로 변신하는 방법」을 통해 Cloud Control Center(CCC), Virtual Edge(VE), Virtual Edge Node(VEN)가 각각 어떤 역할을 수행하고, 로컬과 클라우드 배포 방식이 실제로 어떻게 다른지 살펴보도록 하겠다.***

**✅ 용어 정리 (Glossary)**

**📌 1. 제로트러스트 핵심 개념**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **Zero Trust (제로트러스트)** | 네트워크 내부에 있다는 이유만으로 사용자를 신뢰하지 않고, 신원·장비 상태·권한 등을 검증해 접근을 통제하는 보안 원칙 |
| **Perimeter Security (경계 보안)** | 기업 네트워크의 내부와 외부를 구분하고 방화벽 등을 이용해 경계를 보호하는 전통적인 보안 접근 방식 |
| **Least Privilege (최소 권한)** | 사용자나 장비에 업무 수행에 필요한 최소한의 접근 권한만 부여하는 원칙 |
| **Continuous Evaluation (지속적 평가)** | 한번 허용한 접근 권한도 보안 상태와 정책 조건이 달라지면 재평가하는 방식 |
| **Assume Breach (침해 가정)** | 공격자가 이미 네트워크 내부에 존재할 가능성을 전제로 피해 확산을 최소화하도록 설계하는 원칙 |
| **Microsegmentation (마이크로세그멘테이션)** | 네트워크를 장비·워크로드·신원 그룹 등의 작은 단위로 구분하고, 이들 사이의 통신을 세밀하게 통제하는 기술 |
| **Lateral Movement (횡적 이동)** | 공격자가 최초 침입한 PC나 서버에서 다른 장비로 이동하며 공격 범위를 확대하는 행위 |

**📌 2. 주요 네트워크 보안 기술**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **Firewall (방화벽)** | IP, 포트, 프로토콜 등 정책 조건에 따라 네트워크 통신을 허용하거나 차단하는 장치 또는 소프트웨어 |
| **NGFW (Next-Generation Firewall)** | 기존 방화벽 기능에 애플리케이션 식별, 침입 방지, 위협 분석 등의 기능을 결합한 차세대 방화벽 |
| **NAC (Network Access Control)** | 네트워크 접속을 시도하는 사용자와 장비를 식별·인증하고, 접속 권한을 통제하는 기술 |
| **802.1X** | 네트워크 포트 또는 무선 네트워크의 접속을 인증하는 IEEE 표준 |
| **IDS (Intrusion Detection System)** | 네트워크 또는 시스템에서 침입 징후와 악성 활동을 탐지하는 시스템 |
| **IPS (Intrusion Prevention System)** | 침입을 탐지하는 데 그치지 않고 공격 트래픽을 차단하는 시스템 |
| **NDR (Network Detection and Response)** | 네트워크 트래픽과 통신 행동을 분석하여 위협을 발견하고 대응하는 기술 |
| **EDR (Endpoint Detection and Response)** | PC와 서버에서 악성 프로세스·파일·시스템 행위를 탐지하고 대응하는 기술 |
| **ZTNA (Zero Trust Network Access)** | 사용자와 장비의 신뢰 조건을 확인한 뒤 승인된 애플리케이션에 대한 접근만 허용하는 기술 |
| **IAM (Identity and Access Management)** | 사용자·서비스 계정 등의 신원과 접근 권한을 관리하는 체계 |

**📌 3. 네트워크 구성 및 데이터 분석 용어**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **VLAN (Virtual LAN)** | 하나의 물리적 네트워크를 여러 논리적인 네트워크로 분리하는 기술 |
| **ACL (Access Control List)** | IP 주소, 프로토콜, 포트 등의 조건으로 트래픽을 허용하거나 차단하는 규칙 목록 |
| **Flow** | 출발지·목적지 IP, 포트, 프로토콜 등으로 구분되는 네트워크 통신 흐름 |
| **Telemetry (텔레메트리)** | 네트워크 장비가 수집하여 분석 시스템으로 전달하는 상태·통신·성능 등의 관측 정보 |
| **NetFlow / IPFIX** | 네트워크 장비가 통신 흐름의 메타데이터와 통계 정보를 수집·전송하는 기술. IPFIX는 표준화된 Flow 정보 내보내기 프로토콜 |
| **DPI (Deep Packet Inspection)** | 패킷의 헤더뿐 아니라 Payload 등 내부 내용을 검사하여 애플리케이션이나 위협을 분석하는 기술 |
| **Allow / Deny** | 보안 정책에 따라 특정 통신을 허용하거나 차단하는 동작 |
| **Quarantine (격리)** | 위험 장비의 네트워크 접근을 제한하고 필요한 복구·관리 통신만 허용하도록 하는 보안 조치 |

**📌 4. Elisity의 주요 구성요소**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **CCC (Cloud Control Center)** | Elisity의 클라우드 기반 중앙 관리 플랫폼. 장비 가시성, 정책 관리 및 오케스트레이션 기능 제공 |
| **VE (Virtual Edge)** | 네트워크 장비에서 텔레메트리를 수집하고 CCC와 통신하며 정책 적용을 조율하는 소프트웨어 구성요소 |
| **VEN (Virtual Edge Node)** | Elisity에서 정책 집행 지점으로 사용하는 네트워크 장비. 텔레메트리 수집과 실제 통신 접근제어를 담당 |
| **IdentityGraph** | 여러 정보 출처에서 수집한 사용자·장비 속성과 보안 정보를 통합해 신원을 식별하고 분류하는 Elisity의 기능 |
| **Policy Group** | 공통된 신원·속성·보안 조건을 가진 장비를 묶어 동일한 접근 정책을 적용하기 위한 논리적 그룹 |
| **Dynamic Policy Group** | 장비의 속성이나 위험도 변화에 따라 그룹 소속과 적용 정책을 동적으로 변경할 수 있는 정책 그룹 |
| **Simulation Mode** | 보안 정책을 실제로 차단 적용하기 전에 예상 영향을 검토하는 모드 |
| **Elisity Intelligence** | AI를 이용한 장비 식별·분류 및 보안 정책 추천 등 관리 자동화 기능 |
