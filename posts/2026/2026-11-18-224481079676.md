# IBM·Fermilab·NVIDIA 공동 설계 플랫폼과 13,000배 QEC 디코더의 진짜 의미

**✅ 들어가며 — 양자컴퓨터 경쟁이 QPU 밖으로 확장되고 있다**

- - 2026년 11월 16일 IBM은 Fermilab·NVIDIA와 함께 모듈형 양자컴퓨터를 위한 공동 설계(Co-design) 플랫폼을 추진한다고 발표했다. 이와 함께 양자컴퓨터의 슈퍼컴퓨팅 자원 관리, IBM·RIKEN의 과학 계산 성과가 공개됐고, NVIDIA는 별도로 새로운 QEC 디코더 연구를 발표했다.
  - 겉으로는 서로 다른 발표지만 공통된 메시지는 명확하다. 양자컴퓨터의 발전을 가로막는 문제는 큐비트 숫자만이 아니라 모듈 간 통신, 양자정보 저장, 실시간 디코딩, 고전 연산 자원과의 통합이라는 점이다.
  - 이번 글에서는 그 새로운 발표와 디코딩 기술을 분석한다. IBM Nighthawk r3·Starling의 기존 로드맵, IonQ의 qLDPC 코드·PriorTilt·Beam Search·Soft Decoding에 대한 상세 설명은 이전 글에 정리했으므로 필요한 부분에서 해당 원문을 연결한다.
  - IBM 원문: [IBM·Fermilab·NVIDIA 11월 16일 발표](https://newsroom.ibm.com/2026-11-16-ibm,-fermilab,-and-nvidia-announce-plans-for-new-co-design-platform-to-accelerate-the-development-of-next-generation,-modular-quantum-computers) / Fermilab 원문: [Fermilab 공식 발표](https://news.fnal.gov/2026/11/fermilab-ibm-and-nvidia-plan-modular-quantum-computing-co-design-platform-to-advance-scientific-discovery/) / NVIDIA 원문: [NVIDIA 공식 발표](https://nvidianews.nvidia.com/news/nvidia-announces-collaboration-with-ibm-and-fermi-national-accelerator-laboratory-to-launch-quantum-classical-codesign-platform-plus-error-correction-breakthrough-to-advance-practical-quantum-computing)

**✅ 1. 세 회사가 맡는 역할과 실제 목표**

- - IBM은 초전도 QPU와 양자 네트워킹·소프트웨어를, Fermilab은 초고결맞음 초전도 캐비티 및 고에너지·핵물리 응용 연구를, NVIDIA는 GPU 기반 시뮬레이션·디코딩·최적화·실시간 제어를 담당하는 구상이다.
  - 실제 플랫폼은 IBM Quantum Nighthawk 계열 QPU와 NVIDIA DGX B200을 물리적으로 인접 배치하는 것을 기본으로 한다. 이것은 서로 다른 장비를 한 장소에 설치하는 것이지, 이미 복수의 QPU 사이에 완전한 양자 링크를 구축했다는 발표가 아니다.

|  |  |  |  |
| --- | --- | --- | --- |
| **기관** | **투입 자원** | **이번 협력에서의 역할** | **현재 상태** |
| IBM | Nighthawk QPU·Qiskit·양자 네트워킹 | 연산·제어·모듈 아키텍처 공동 설계 | 기존 QPU 운영, 신규 공동 플랫폼은 계획 |
| Fermilab / SQMS | 초전도 SRF 캐비티·HENP 연구자·HEPCloud | 물리 인터커넥트·양자 메모리 연구와 실제 응용 요구 정의 | 캐비티 통합은 후속 연구 단계 |
| NVIDIA | DGX B200·CUDA-Q·GPU 소프트웨어 | 대규모 QEC 실험, 시뮬레이션, 최적화, 실시간 피드백 | 플랫폼 통합 계획 및 별도 디코더 연구 공개 |

- - 연구 대상으로는 격자 게이지 이론, 중성미자 상호작용, 핵물리 시뮬레이션처럼 고전 컴퓨터만으로 계산하기 어려운 문제를 제시했다. 이는 연구 목표이지, 해당 문제에서 양자 우위를 달성했다는 발표는 아니다.
  - Fermilab은 공동 플랫폼을 향후 DOE 양자컴퓨팅 사용자 시설의 기술·연구 공동체를 만드는 기반으로 보고 있다. 그러나 특정 사용자 시설의 건설·운영 예산이 이번 발표만으로 확정된 것은 아니다.

**📌 초전도 캐비티는 무엇을 해결하는가?**

- - 이번 협력에서 가장 흥미로운 부분은 Fermilab의 SQMS(Superconducting Quantum Materials and Systems) 센터가 맡는 역할이다.
  - 초전도 양자컴퓨터는 마이크로파를 이용해 큐비트를 제어하고 정보를 교환한다. 하지만 QPU가 여러 개로 늘어나면 이를 안정적으로 연결하고 정보를 유지하는 일이 어려워진다.
  - Fermilab은 입자가속기 개발 과정에서 축적한 초전도 고주파(SRF) 캐비티 기술을 양자컴퓨팅에 적용하려 한다.

|  |  |  |
| --- | --- | --- |
| **기술** | **역할** | **기대 효과** |
| Quantum Memory | 양자 상태를 장시간 저장 | 연산과 통신의 시간적 제약 완화 |
| Entanglement Buffer | 생성된 얽힘을 보관 | 서로 다른 모듈의 연산 타이밍 조정 |
| Bosonic QEC | 캐비티의 광자 상태에 양자정보 인코딩 | 특정 오류정정 방식의 자원 효율 개선 |

- - 특히 Entanglement Buffer가 중요하다.

    - 모듈 A와 B가 연결돼 있을 때 양쪽의 연산과 얽힘 생성이 항상 완벽하게 동기화될 수는 없다. 중간에 양자정보를 보관할 수 있다면 이 문제를 완화할 수 있다.
    - 이는 IonQ가 추진 중인 양자 메모리 기반 광학 인터커넥트와도 목적이 유사하다. 다만 **Fermilab의 초전도 캐비티와 IonQ의 SiV 메모리는 서로 다른 물리적 구현**이다.

**📌 가장 중요한 구분: 먼저 에뮬레이션, 나중에 실제 양자 인터커넥트**

|  |  |  |
| --- | --- | --- |
| **단계** | **무엇을 하는가** | **성과를 어떻게 판단할 것인가** |
| 초기 플랫폼 | QPU·DGX B200을 결합하고 모듈 간 통신을 모델링·에뮬레이션 | 링크 오류·지연·제어 피드백을 반영한 설계·실험 결과 |
| 후속 연구 | SQMS(Superconducting Quantum Materials and Systems)) 초전도 캐비티를 플랫폼에 통합 | 실제 양자 상태 보존·전달·오류 특성의 실측 |
| 장기 목표 | 여러 모듈이 하나의 작업을 수행하는 내결함성 시스템 | 유효 논리 연산 처리량·정확도·자원 비용 |

- - 초전도 SRF 캐비티는 향후 양자 메모리, 얽힘 버퍼(Entanglement Buffer), 보소닉 오류정정 자원으로 연구될 예정이다. 양자 얽힘의 생성과 실제 연산 시점을 조정하는 데 도움이 될 수 있지만, 아직 플랫폼 내 작동이 입증된 완성품은 아니다.
  - 이와 별개로 IBM은 기존 L-coupler 연구에서 두 Nighthawk 칩 사이 80cm급 링크 4개, 평균 상태 전달 충실도 약 99%, 평균 원격 CZ 게이트 충실도 94.75%를 공개했다. 이는 Fermilab 캐비티 통합과는 구별되는 기존 실험이다.
  - 큐비트 수, L-coupler·C-coupler 구조, 원격 게이트 성능과 Starling의 2029년 목표는 이전 글 [IBM Nighthawk r3 전격 공개](https://blog.naver.com/4-fire/224475723315)에서 상세히 분석했다.

**✅ 2. Slurm·QRMI — QPU를 슈퍼컴퓨터의 일반 자원처럼 사용한다**

- - Slurm은 슈퍼컴퓨터에서 계산 작업을 예약하고 CPU·GPU를 할당하는 작업 스케줄러다. 양자컴퓨터를 별도 대기열과 개별 로그인 체계 없이 같은 워크플로에서 할당하는 것은 실제 운영 비용을 낮출 수 있는 변화다.
  - IBM·NVIDIA·Pasqal이 지원한 QRMI(Quantum Resource Management Interface)는 제조사에 중립적인 접근 계층이다. Slurm 26.11의 HRES(Hierarchical Resources)와 결합해 QPU 예약·할당·사용량 관리가 가능하도록 한다.
  - GPU는 일반적으로 한 컴퓨팅 노드에 속하지만, QPU는 다수의 노드에서 함께 접근하는 공유 자원이 될 수 있다. HRES는 이런 차이를 자원 모델에 반영한다.

|  |  |  |
| --- | --- | --- |
| **작업 구분** | **기존 방식** | **QRMI/HRES 통합 후 기대 모습** |
| 작업 제출 | CPU/GPU와 QPU 경로가 나뉘는 경우가 많음 | 하나의 Slurm 작업에서 혼합 자원 요청 |
| 자원 예약 | QPU 전용 연결·예약 시스템 필요 | QPU 사용 시간 예약·회계 관리 통합 |
| 제조사 교체 | 제조사별 접근 방식 차이 | 표준 인터페이스로 일부 운영 절차 재사용 |
| 남은 제약 | 하드웨어별 별도 제어와 정책 | 실제 게이트·디코더·지연 성능까지 표준화된 것은 아님 |

- - 즉, 같은 슈퍼컴퓨터 센터에서 IBM 초전도 QPU, Pasqal 중성원자 QPU 등을 자원으로 관리하는 경로가 넓어진다. 이는 기술적 표준화와 운영 통합의 진전이지 제조사 간 QEC 코드나 게이트가 호환된다는 뜻은 아니다.
  - 공식 자료: [QRMI 프로젝트 문서](https://qiskit-community.github.io/qrmi/), [NVIDIA의 Slurm 양자 자원 관리 발표](https://blogs.nvidia.com/blog/slurm-quantum-computing-supercomputing/)

**✅ 3. IBM·RIKEN·NVIDIA의 79배는 무엇을 개선한 것인가?**

- - IBM·RIKEN·NVIDIA는 Fe4S4(철-황 클러스터) 전자구조 계산에서 SQD(Sample-based Quantum Diagonalization)를 사용했다. 72개 데이터 큐비트, 최대 4,000개의 2큐비트 연산, 총 500만 샘플을 활용한 하이브리드 연구다.
  - 고전 계산법 DMRG 기준 결과와의 에너지 차이가 약 4.3 millihartree까지 줄었다. 기존 SQD 연구보다 그 차이가 약 79분의 1로 작아진 결과를 IBM은 79배 정확도 향상으로 설명했다.
  - 핵심 개선에는 분자의 전자 상태를 더 현실적으로 표현한 초기 참조 상태(Broken-symmetry UHF)를 택한 점이 포함된다. 이 성과를 곧바로 QPU 자체의 게이트 충실도가 79배 향상됐다는 의미로 받아들여서는 안 된다.
  - 4.3 mHa는 일반적으로 인용되는 화학적 정확도 1 kcal/mol(약 1.6 mHa)보다 큰 차이이며, 고전 우위에 대한 보편적 증거도 아니다. 이번 연구의 의미는 강상관 전자 문제에서 양자 샘플링과 고전 GPU 연산을 결합하는 방법을 발전시킨 데 있다.
  - 공식 자료: [IBM SC26 연구 개요](https://www.ibm.com/quantum/blog/sc26)

**✅ 4. NVIDIA TCBP-JOBS — 무엇이 13,000배 빨라졌나?**

- - NVIDIA는 협력 플랫폼 발표와 같은 날 별도 연구로 TCBP-JOBS(trajectory-calibrated BP + jittered OSD beam search)를 발표했다. 이 디코더가 곧 Fermilab 플랫폼의 실제 연결형 QPU에서 실증됐다는 의미는 아니다.
  - 기본 문제는 QEC 측정 신드롬으로부터 오류 원인을 추정하는 것이다. 양자 LDPC 코드에서 짧은 순환·퇴화(degeneracy) 때문에 BP가 한 가지 잘못된 해에 멈추거나 진동하는 경우가 있어 이를 개선하려는 접근이다.

**📌 TCBP: BP의 마지막 답이 아니라 계산 과정을 학습한다**

- - 기존 BP+OSD는 보통 BP의 최종 LLR 또는 계산 과정 중 가장 작은 LLR만 가져와 후보 순서를 정한다. 이때 중간에 오류 가능성이 높아졌다가 낮아지는 등 시간적 변화 정보가 사라질 수 있다.
  - TCBP는 오류별 BP 궤적(trajectory)의 모양을 입력으로 받아 각 오류 메커니즘의 보정된 확률을 추정한다. 공식 문서에 따르면 기본 학습 모델은 529개 가중치를 가진 소형 신경망이며, 시뮬레이션 데이터로 학습한다.
  - 연구의 기본 설정은 BP 10회 반복을 활용한다. 학습 모델은 같은 코드 계열에서 재사용될 수 있지만, 코드·오류 환경·BP 설정이 달라지면 검증 또는 재학습이 필요하다.

**📌 JOBS: 교란된 후보 순서를 GPU에서 병렬로 탐색한다**

- - TCBP로 확률 순서를 만든 다음 JOBS는 작은 무작위 교란(jitter)을 주어 서로 다른 열 순서들을 만들어낸다. 각각 OSD-0 해를 출발점으로 제한된 Beam Search를 실행한다.
  - 공식 기본 설정의 예는 16개 탐색 순서(draws), Beam Width 32, Depth 40, Patience 8이다. 이 값은 특정 설정의 예이지 모든 QEC 회로에 대한 보편적인 최적값은 아니다.
  - 여러 후보를 GPU에서 병렬 검색하므로 단일 순서가 실패하거나 불리한 답으로 수렴하는 위험을 줄일 수 있다. 다만 탐색 범위가 유한하므로 최대우도(ML) 최적 해를 언제나 보장하지는 않는다.

|  |  |  |
| --- | --- | --- |
| **기능** | **TCBP-JOBS에서 하는 일** | **기술적 의미** |
| Trajectory 학습 | BP 전체 반복의 LLR 변화로 오류별 확률 보정 | 단일 최종 LLR보다 풍부한 정보 사용 |
| GPU 병렬 탐색 | 여러 OSD 후보와 Beam Search를 병렬 수행 | 정확도·처리량 사이의 선택 폭 확대 |
| Noise Learning | 실제 신드롬 데이터에서 오류 메커니즘별 비율 추정 | 실제 장비의 오류 모델 변화에 대응하는 경로 |
| Confidence / JOBS gap | 서로 다른 논리 클래스에서 발견한 후보들의 비용 차이를 기록 | 후보 선별(Post-selection)과 Magic State Cultivation에 활용 |
| 재현성·배포 | CUDA-Q QEC의 NV-qLDPC 디코더 구성으로 제공 | 실험자들이 성능을 재검증할 수 있는 소프트웨어 경로 |

- - 특히 JOBS gap은 탐색한 후보 안에서 얻은 신뢰도 지표다. 검색하지 못한 더 좋은 후보가 존재할 가능성을 없애는 수학적 증명도, 항상 정확한 사후확률도 아니다.
  - 연구·구현 원문: [TCBP-JOBS 논문](https://arxiv.org/abs/2611.21321) / [NVIDIA CUDA-Q QEC 개발 문서](https://nvidia.github.io/cudaq-qec/performance/nv_qldpc_tcbp_jobs_user_guide.html) / [Noise Learning·디코더 목록](https://nvidia.github.io/cudaq-qec/components/qec/decoders.html)

**✅ 5. IonQ PriorTilt·Beam Search와 기술적으로 무엇이 다른가?**

- - 중요한 공통점은 NVIDIA와 IonQ의 디코더 모두 BP 기반이라는 것이다. 차이는 BP가 정체되는 문제를 어떻게 푸느냐에 있다.
  - PriorTilt는 BP 메시지 규칙을 유지하면서 정체가 의심되는 일부 오류 노드의 사전 LLR에만 작은 교란을 넣는다. Beam Search는 여러 후보를 확장·정리한다. TCBP-JOBS는 BP 궤적을 학습한 다음 GPU에서 여러 OSD 경로를 탐색한다.
  - PriorTilt의 수식, BB144·BB70·GB102 실험의 전체 수치, 99백분위 지연시간 등은 기존 [IonQ PriorTilt 논문 심층 분석](https://blog.naver.com/4-fire/224473447121)에 정리했으므로 여기서는 구조적 차이에 집중한다.

| --- | --- | --- | --- |
| **비교 항목** | **NVIDIA TCBP-JOBS** | **IonQ PriorTilt** | **IonQ Beam Search** |
| BP 개선 방식 | BP 궤적 학습과 OSD 탐색 | 희소한 사전확률 교란 | 여러 후보 경로 탐색 |

**📌 IonQ의 610배·3.1배와 NVIDIA의 13,000배를 비교하면 안 되는 이유**

- - IonQ PriorTilt의 약 610배는 BB144, p=0.001에서 표준 Min-Sum BP와 최대 반복 예산을 맞춘 뒤 측정한 논리 오류율(LER)의 개선 비율이다.
  - 같은 BB144 조건에서 PriorTilt는 Relay-BP보다 약 4.3배, IonQ Beam Search보다 약 3.1배 낮은 논리 오류율을 보고했다. 이는 디코딩 정확도의 비교다.
  - PriorTilt의 BB144 평균 디코딩 시간 0.907ms와 Beam Search 2.377ms는 Apple M3 Pro 단일 코어의 샷당 처리시간이다. BB144의 한 샷에는 신드롬 12회 추출이 포함된다.
  - PriorTilt의 BB144 99백분위는 4.52ms로 Relay-BP의 3.33ms보다 느리다. 평균만 보고 최악 구간의 실시간 운영 성능까지 더 우수하다고 판단해서는 안 된다.
  - NVIDIA의 최대 13,000배는 Google Tesseract의 특정 탐색 설정 대비 실행 시간 차이다. 따라서 「PriorTilt 610배 vs NVIDIA 13,000배」라는 숫자 대조는 비교 단위부터 다르다.

**📌 Soft Decoding과 NVIDIA JOBS gap은 비슷한 목적이 있다**

- - IonQ가 2026년 9월 연구에서 다룬 Soft Decoding은 오류 추정의 신뢰도를 평가해 신뢰도가 낮은 결과를 선택적으로 제외하는 전략을 포함한다. NVIDIA JOBS gap도 후보 논리 클래스 간 차이를 통해 결과의 신뢰도를 평가한다.
  - 그러나 두 신뢰도 점수의 정의와 오류 모델, 폐기율·채택률 조건이 같지 않다. 예컨대 IonQ Soft Decoding의 최대 580배 오류 억제와 NVIDIA JOBS gap의 후선별 효과를 숫자만으로 비교할 수 없다.

**✅ 6. 실제 시스템에서는 GPU냐 CPU냐보다** **QEC 스케줄이 중요****하다**

  - IonQ의 CPU 기반 접근은 상용 서버급 자원만으로 실시간 디코딩을 구현하려는 경로다. 다만 논문에서 제시된 대형 MegaQuOp 시스템의 처리량 추정은 실제 해당 규모 QPU의 완성·상시 가동을 뜻하지 않는다.

**✅ 7. NVIDIA가 IBM을 선택했다고 IonQ가 밀린 것인가?**

- - 그렇게 해석할 근거는 부족하다. NVIDIA는 특정 QPU 업체 하나에 독점적으로 의존하지 않고 CUDA-Q·NVQLink·가속 컴퓨팅을 다양한 양자 하드웨어에 공급하려는 플랫폼 전략을 취한다.
  - 이미 IonQ는 2026년 9월 NVIDIA Accelerated Quantum Research Center(NVAQC)에 Superion 256을 공급하고 GB200 NVL72·NVQLink 환경에서 연구할 계획을 발표했다. 설치 목표는 2027년으로, 2026년 11월 현재 완료된 대규모 FTQC 실증과는 구분해야 한다.
  - Fermilab은 이번 계획이 IBM·Oak Ridge National Laboratory·AMD의 별도 QEC 공동 설계 플랫폼을 보완한다고 밝혔다. IBM 역시 하나의 GPU 공급사에만 기술 전략을 고정한 것은 아니다.
  - IonQ의 광학 인터커넥트·SiV 양자 메모리는 초전도 SRF 캐비티 연구와 목적 일부가 유사하지만 물리적 인터페이스와 기술 성숙도가 다르다. IBM의 모듈 간 마이크로파 상태 전달 충실도 99%와 IonQ의 초당 1,000건 이상 이온–SiV 메모리 얽힘 이벤트는 서로 다른 지표다.
