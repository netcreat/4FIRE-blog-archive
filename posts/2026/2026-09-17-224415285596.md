**✅ 먼저 [[n,k,d]]를 정확히 이해해야 한다**

**📌 n, k, d의 의미**

- - [[n,k,d]]에서:

    - n = logical 정보를 담는 **Data physical qubit 수**
    - k = 그 Data block에 encode되는 **logical qubit 수**
    - d = **code distance**
  - 따라서:

    - Steane [[7,1,3]] = 7 Data → 1 logical, distance 3
    - BB5 [[30,8,4]] = 30 Data → 8 logical, distance 4
    - Q70 [[70,6,9]] = 70 Data → 6 logical, distance 9
    - Q102 [[102,22,9]] = 102 Data → 22 logical, distance 9
  - d는 stabilizer 개수도 아니고 syndrome-extraction depth도 아니다.

    - 일반적으로 distance d인 code는 최대 ⌊(d−1)/2⌋개의 arbitrary physical error를 보장된 범위에서 교정한다.
    - d=3 → 1개
    - d=4 → 1개
    - d=5 → 2개
    - d=9 → 4개
    - d=10 → 4개
  - Walking Cat 논문의 표에는 별도로 w\_check가 있다.
  - 이것이 **stabilizer 하나의 weight**, 즉 한 stabilizer check가 몇 Data qubit에 걸치는지를 나타낸다.

    - Q70은 w\_check=7
    - Q54·Q102는 w\_check=8

**✅ Syndrome은 Error 그 자체가 아니다**

**📌 Syndrome은 에러가 남긴 지문이다**

- - Data qubit에서 실제로 발생한 X·Y·Z error가 **error**다.
  - 여러 stabilizer를 측정했을 때 얻는 +1/-1 또는 0/1 결과의 조합이 **syndrome**이다.
  - 예를 들어 여러 stabilizer 결과가:

    - S1 = 정상
    - S2 = 이상
    - S3 = 정상
    - S4 = 이상
  - 이라면 decoder가 이 패턴을 보고 “어느 Data qubit에 어떤 종류의 error가 발생했을 가능성이 높은가”를 추론한다.
  - 즉:

    - Error = 고장 자체
    - Syndrome = 고장의 위치와 종류를 추론할 수 있는 센서 패턴
    - Decoder = 그 패턴을 해석하는 classical processor
  - Data를 직접 측정하면 저장된 quantum information을 파괴할 수 있기 때문에 **Ancilla가 대신 stabilizer parity 정보를 수집**한다.

**📌 Ancilla가 왜 cyclic shift를 하는가**

- - 예를 들어 A1이 담당하는 stabilizer가 D1·D4·D9·D17에 걸쳐 있다고 가정한다.
  - A1이 모든 D1→D30을 순서대로 방문하는 것이 아니다.
  - A1은 **자기 stabilizer가 요구하는 Data qubit만** 만나면 된다.
  - Walking Cat에서는 Data를 크게 움직이는 대신 Ancilla row의 상대적 위치를 cyclic shift해서 필요한 Data–Ancilla pair를 정렬한다.
  - 한 번 정렬되면 여러 Ancilla–Data pair가 동시에 2-qubit gate를 수행한다.
  - 다시 cyclic shift → 다음 interaction → 다시 shift를 반복한다.
  - 논문의 syndrome extraction algorithm도 **parallel 2Q gate layer와 ancilla cyclic transport를 교대로 수행하고 마지막에 모든 Ancilla를 측정**하는 방식으로 정의한다.

**📌 한 SEC는 A1이 모든 Data를 훑는 것이 아니다**

- - SEC = Syndrome Extraction Cycle
  - 한 SEC는:

    - Ancilla reset/preparation
    - 첫 번째 stabilizer interaction layer
    - cyclic shift
    - 다음 interaction layer
    - 필요한 횟수만큼 반복
    - 모든 Ancilla measurement
    - syndrome vector 생성
    - decoder 처리
  - 까지 완료되는 **한 번의 전체 QEC clock cycle**이다.
  - IonQ 논문도 SEC를 FTQC의 logical clock cycle처럼 생각할 수 있다고 정의한다.
  - 따라서:

    - A1의 stabilizer check만 완료 = 아직 한 SEC가 아님
    - A1, A2, A3… 전체 block의 scheduled stabilizer check가 끝남 = 1 SEC

**✅ Walking Cat 페이지의 네 가지 애니메이션은 무엇을 보여주는가**

**📌 1. SEC – All Blocks**

- - Data ion은 거의 제자리에 유지된다.
  - Ancilla ion들이 highway를 이용해 cyclic shift한다.
  - 필요한 Data와 정렬될 때마다 2Q gate를 수행한다.
  - Beacon은 scheduled gate layer마다 ion loss 여부를 확인한다.
  - 마지막에 Ancilla를 측정해 syndrome을 얻는다.
  - decoder가 syndrome을 해석한다.
  - 다음 SEC가 시작된다.
  - 논문에서 Memory block은 Data, Ancilla, Beacon, 빈 Highway row, Local Reservoir의 구조를 사용하며, syndrome extraction은 Ancilla cyclic transport로 구현된다.

**📌 2. Cat Measurement**

- - logical information을 담고 있는 Data block 자체는 움직이지 않는다.
  - Cat Factory에서 entangled Cat state를 만든다.
  - Cat ion들이 원하는 Memory block으로 이동한다.
  - logical Pauli operator가 걸쳐 있는 Data들과 Cat qubit이 interaction한다.
  - Cat을 측정하여 Data의 개별 상태를 직접 읽지 않고 **logical parity**를 얻는다.
  - 그래서 이름이 문자 그대로 Walking Cat이다.
  - IonQ는 Cat Factory를 logical measurement용 resource state를 생산하고 필요한 block으로 보내는 architecture의 backbone으로 설명한다.

**📌 3. T Gate**

- - fault-tolerant T gate에는 Magic State가 필요하다.
  - Memory의 logical qubit과 Magic Factory의 logical magic state는 각각 자기 block 안에서 QEC로 보호된다.
  - 각각에 Cat state를 보낸다.
  - 두 block에 걸친 joint logical measurement가 필요하면 Bell pair를 이용해 **두 Cat state를 stitch**한다.
  - Magic state를 소비하고 classical feed-forward/frame update를 거치면 logical T gate가 완료된다.
  - Bell Factory의 핵심 역할이 바로 **서로 떨어진 block 사이의 logical operation과 Magic State 전달을 가능하게 하는 것**이다.

**📌 4. Qubit Loss + Refill**

- - trapped ion에서는 physical carrier인 ion 자체가 trap에서 없어질 수 있다.
  - Beacon이 neighboring Data의 loss를 flag한다.
  - 가장 가까운 Local Reservoir의 fresh ion이 빈 자리를 채운다.
  - 새 ion은 사라진 quantum information을 복사해오는 것이 아니다.
  - QEC가 남아 있는 encoded information과 syndrome을 이용해 새 carrier를 다시 code space에 포함시킨다.
  - Local Reservoir가 줄어들면 Global Reservoir가 Local Reservoir를 다시 보충한다.
  - Walking Cat은 qubit loss가 이후 2Q interaction을 통해 번지는 avalanche loss를 막기 위해 loss detection과 refill을 SEC 내부에 포함한다. ([arXiv](https://arxiv.org/html/2604.19481))

**✅ 웹 데모의 BB5 [[30,8,4]]는 256개를 어떻게 쓰는가**

**📌 Memory — 100 qubits**

- - 웹 화면에서 초록색 Logical Qubits # 1–8 전체가 하나의 code block이다.
  - 30 Data가 8 logical qubits를 encode한다.
  - Walking Cat template을 적용하면:

    - Data = 30
    - Ancilla = 30
    - Beacon = 30
    - Local Reservoir = 10
  - 합계: 30+30+30+10=100

**📌 Magic Factory — 101 qubits**

- - 동일한 n=30 구조에 H-state injection qubit 하나가 추가된다.
  - 따라서: 30+30+30+10+1=101

**📌 Cat Factory — 24 qubits**

- - 웹 화면에 주황색 Cat qubit이 24개 배치되어 있다.
  - 데모에서 선택한 Cat Factory allocation이다.

**📌 Global Reservoir — 31 qubits**

- - 웹 화면의 Global Reservoir에 31개가 배치돼 있다.

**📌 합계**

- - 100+101+24+31=256
  - 즉 웹 데모는 **30-qubit code를 선택함으로써 Memory + Magic + Cat + Global Reservoir를 정확히 256 physical ions 안에 채우도록 구성**해놓았다.
  - 이 점이 매우 중요하다.
  - n=30이면 Memory와 Magic core만 합쳐도 (3×30+10)+(3×30+11)=201이고, 256에서 정확히 55개가 남는다.
  - 웹 데모에서는 그 55개를:

    - Cat = 24
    - Global Reservoir = 31
  - 로 사용해 정확히 256을 맞춘 것이다.

**✅ Steane [[7,1,3]]에서는 256개가 어떻게 배치되는가**

**📌 Memory Block 하나 — 31 qubits**

- - 첨부한 Steane 애니메이션을 보면 각 Logical Qubit #1~#5 block은 같은 구조다.
  - 각 block에서:

    - Data = 7
    - Ancilla = 7
    - Beacon = 7
    - Local Reservoir = 10
  - 따라서: **7+7+7+10=31**
  - Steane은 k=1이므로 block 하나당 logical qubit은 1개다.

**📌 Memory Block이 5개**

- - 화면에는:

    - Logical Qubit # 1
    - Logical Qubit # 2
    - Logical Qubit # 3
    - Logical Qubit # 4
    - Logical Qubit # 5
  - 총 5개의 Steane memory block이 있다.
  - 따라서: **31×5=155**
  - 즉 155 physical ions으로 5 logical qubits를 저장한다.

**📌 Magic Factory — 32 qubits**

- - Steane block과 같은 구조에 H-state injection ion 하나가 추가된다.
  - 따라서: 7+7+7+10+1=32

**📌 Cat Factory — 24 qubits**

- - 첨부 화면에서 Cat Factory에 24개의 ion이 배치돼 있다.
  - 앞서 BB5와 같은 24-qubit Cat Factory를 웹 데모가 재사용하고 있다.
  - 이것을 Steane code의 이론적인 필수 Cat width라고 해석할 필요는 없다.
  - **웹 데모의 resource allocation choice**다.

**📌 Global Reservoir — 45 qubits**

- - 첨부한 Steane 화면에서 Global Reservoir에 표시된 ion을 직접 세면 40 + 5=45개다.

**📌 전체 합계는 256**

- - 155+32+24+45=256

**✅ Steane과 30-qubit 데모를 비교하면 의미가 더 잘 보인다**

**📌 Steane**

- - 5개의 memory block
  - 5 logical qubits
  - distance 3
  - 실제 배치 256 qubits
  - logical density가 매우 낮다.
  - 대신 작은 code라 여러 independent block을 한 tile에 배치하기 쉽다.
  - QEC와 ion movement를 보여주는 교육용 데모로 이해하기 좋다.

**📌 BB5 [[30,8,4]]**

- - memory block 하나
  - 8 logical qubits
  - distance 4
  - Memory + Magic + Cat + Reservoir가 정확히 256
  - Steane보다 logical density가 훨씬 높다.
  - qLDPC가 왜 surface/전통적인 작은 code보다 physical-qubit efficiency 측면에서 매력적인지를 직관적으로 보여준다.

**📌 하지만 둘 다 최종 Walking Cat 목표와는 거리가 있다**

- - Walking Cat 논문에서 실제로 약 10−10 수준의 logical error target을 대상으로 상세하게 설계·simulation한 것은 Q54, Q70, Q102다.
  - 논문 조건에서 estimated logical error/SEC는:

    - Q102 ≈ 10−11
    - Q70 ≈ 10−10
    - Q54 ≈ 3×10−10
  - 이 수치는 **실제 Superion에서 측정한 성능이 아니라 논문의 noise model 아래에서 얻은 simulation 결과**라는 점이 중요하다.

**✅ 그렇다면 256 physical qubits에 어떤 코드까지 들어갈 수 있을까**

**📌 Memory block만 놓고 보면 기준은 매우 간단하다**

- - Memory 공식:

    - 3n+10≤256
  - 따라서:

    - n≤82
  - 즉 n≤82인 code는 **Memory core 자체는** 한 256 tile 안에 들어갈 수 있다.

**📌 Walking Cat Table 9에 있는 코드에 적용하면**

- - BB [[30,4,5]]

    - Memory = 100
    - 충분히 들어간다.
  - BB [[48,4,7]]

    - Memory = 3×48+10=154
    - 들어간다.
  - Q54 [[54,2,10]]

    - Memory = 172
    - 들어간다.
  - Q70 [[70,6,9]]

    - Memory = 220
    - 들어간다.
  - BB [[72,12,6]]

    - Memory = 226
    - 들어간다.
  - BB [[90,8,10]]

    - Memory = 280
    - **들어가지 않는다.**
  - Q102 [[102,22,9]]

    - Memory = 316
    - **들어가지 않는다.**
  - [[144,12,12]]

    - Memory = 442
    - 불가능하다.
  - HGP 450/882 계열도 당연히 단일 256 tile에는 들어가지 않는다. 해당 code들이 Walking Cat three-ring framework와 호환된다는 것과 한 256 tile에 들어간다는 것은 전혀 다른 문제다.

---

**✅ 하지만 “Memory가 들어간다”와 “완전한 FTQC가 된다”는 완전히 다르다**

- - Memory만 있어서는 universal fault-tolerant computation을 할 수 없다.
  - 최소한:

    - Memory
    - Magic Factory
    - Cat Factory
    - Bell Factory
    - Local/Global Reservoir
    - Cat/Bell transport capacity
    - real-time decoder
  - 가 필요하다.
  - Walking Cat 논문의 실제 대형 configuration은 이 항목들을 모두 physical-qubit resource estimate에 포함한다.

---

**✅ Q54를 256에 넣으면**

**📌 Q54 Memory로만 사용한다면**

- - Q54 = [[54,2,10]]
  - Memory:

    - 3(54)+10=172
  - Q54의 일반 block width는 16이므로 companion Cat Factory는:

    - 2(16)=32
  - 따라서:

    - 172+32=204
  - Memory + Cat만 보면 256 안에 들어간다.

**📌 그러나 Q54의 진짜 Walking Cat 역할은 CH2 Magic Factory다**

- - 논문은 Q54를 주로 **CH2 Magic Factory용 code**로 선택한다.
  - Q54 Magic Factory 본체:

    - 3(54)+11=173
  - 그런데 CH2는 특별히 **54-qubit Cat**으로 transversal H verification을 해야 한다.
  - 따라서 companion Cat Factory는:

    - 2(54)=1082(54)=108
  - 합계:

    - 173+108=281
  - 따라서 **완전한 Q54/CH2 module은 256 하나에 들어가지 않는다.**
  - 즉 Q54 Magic Factory 자체는 256에 들어가지만, 그 Factory를 실제로 돌리는 companion Cat resource까지 고려하면 인접 tile 또는 더 큰 shared fabric가 필요하다.

---

**✅ Q70을 256에 넣으면 매우 흥미로운 일이 생긴다**

**📌 Q70 Memory**

- - Q70 = [[70,6,9]]
  - Memory:

    - 3(70)+10=220
  - Q70 block width = 18
  - Cat Factory:

    - 2(18)=36
  - 합계:

    - 220+36=256
  - 즉 **Q70 Memory + companion Cat Factory가 정확히 256 physical qubits**다.
  - 이것은 256 unit cell과 굉장히 흥미롭게 맞아떨어진다.
  - 하지만 논문이나 IonQ가 “Superion 256 한 chip = Q70 block 하나”라고 공식적으로 정의한 것은 아니다.
  - qubit allocation 관점에서 정확히 맞는다는 의미다.

**📌 Q70 MEK Magic Factory**

- - Q70은 Walking Cat의 single-code architecture에서 Magic Factory로도 사용할 수 있다.
  - Q70 MEK:

    - 3(70)+11=221
  - Cat Factory 36을 붙이면:

    - 221+36=257
  - 단 **1 qubit 차이로 256을 넘어간다.**
  - 따라서 Q70으로:

    - Memory + Cat → 한 256에 정확히 가능
    - MEK + Cat → 257로 한 256에 미세하게 초과
  - 가 된다.
  - 더구나 universal system에는 Bell/Global Reservoir/transport까지 필요하므로 결국 **여러 tile을 연결해야 한다.**
  - Q70은 논문에서 Memory와 MEK Magic Factory 양쪽에 사용할 수 있는 single-code architecture로 특별히 선택되었다.

---

**✅ Q102를 256에 넣으면**

**📌 Memory 자체부터 256을 넘는다**

- - Q102 = [[102,22,9]]
  - Memory:

    - 3(102)+10=316
  - 따라서 **Memory block 하나만으로도 256을 초과**한다.

**📌 Cat까지 포함하면**

- - Q102 block width = 30
  - Cat Factory:

    - 2(30)=60
  - 따라서:

    - 316+60=376
  - 최소한 여러 256-unit-cell 영역에 걸쳐 배치해야 한다.

**📌 그런데 왜 굳이 Q102를 쓰는가**

- - Q102는 102 Data에서 무려 22 logical qubits를 encode한다.
  - Q70의 70→6보다 훨씬 높은 logical density다.
  - Walking Cat 논문이 Q102를 **dense architecture**의 중심으로 선택한 이유다.
  - 즉 Q102는:

    - 작은 hardware에는 부담스럽지만
    - system scale이 커질수록 logical-qubit density에서 큰 이득을 준다.

---

**✅ 256에서 “사용 가능한 코드”라는 표현은 세 가지로 구분해야 한다**

**📌 1. 현재 Walking Cat 웹 데모에서 선택 가능한 코드**

- - Steane [[7,1,3]]
  - BB5 [[30,8,4]]
  - 이 두 개만 현재 인터랙티브 페이지에서 직접 선택할 수 있다.

**📌 2. 계산상 256 안에 Memory block이 들어가는 코드**

- - n≤82인 code
  - 예:

    - [[30,4,5]]
    - [[48,4,7]]
    - Q54
    - Q70
    - [[72,12,6]]
  - 하지만 **Memory가 들어간다는 것만으로 그 code를 Superion 256이 실제 지원·검증했다고 말할 수는 없다.**

****

**📌 3. 실제** **Walking Cat full-stack architecture를 한 256에서 완성할 수** **있는가**

- - 답은 사실상 **아니다.**
  - 작은 n≈30 데모에서는 모든 component를 256 안에 압축해 보여줄 수 있다.
  - 하지만 Walking Cat 논문의 실제 target code인 Q54/Q70/Q102까지 올라가면 Magic/Cat/Bell/Reservoir/transport를 포함하는 순간 한 256 cell을 넘긴다.
  - 그래서 IonQ가 공식적으로 **10K를 Walking Cat을 실행하도록 설계되는 첫 hardware generation**이라고 표현한 것이 중요하다.

---

**✅ 그렇다면 Q54·Q70·Q102를 쓰려면 무엇이 필요한가**

**📌 첫째, 256 cell을 넘어가는 physical fabric가 필요하다**

- - 하나의 QEC block을 반드시 하나의 die/tile 안에 가둘 필요는 없다.
  - QCCD의 장점은 ion을 이동시켜 필요한 gate zone으로 가져갈 수 있다는 것이다.
  - 따라서 larger code는 여러 unit cell에 걸쳐 배치하고 transport network로 연결할 수 있다.
  - Walking Cat의 핵심 자체가 fixed wire보다 **movement를 connectivity로 사용**하는 것이다.

**📌 둘째, 전용 Cat Factory가 필요하다**

- - Q70 Memory → Cat 36
  - Q102 Memory → Cat 60
  - Q54 CH2 → Cat 108
  - code가 커지면서 단순 Data 수만 늘어나는 것이 아니라 logical operator를 측정할 Cat resource도 커진다.

**📌 셋째, Magic Factory가 별도로 필요하다**

- - Q70 → MEK를 사용 가능
  - Q54 → CH2를 사용
  - Q102는 dense Memory로 사용하고 Magic State는 보통 별도의 Q54/CH2에서 공급받는다.
  - 즉 Q102 machine이라고 해서 모든 component가 Q102일 필요는 없다.

**📌 넷째, Bell Factory가 필요하다**

- - 서로 떨어진 두 Cat을 stitch한다.
  - Memory–Memory inter-block measurement
  - Memory–Magic interaction
  - logical T gate
  - 등에 필요하다.
  - 논문에서는 memory+magic block 총 수를 N이라 할 때 Bell Factory를 대략 ⌈N/3⌉개 할당한다.

**📌 다섯째, Global Reservoir와 transport capacity가 필요하다**

- - Local Reservoir가 loss에 즉각 대응한다.
  - Global Reservoir는 여러 local reservoir를 보충한다.
  - 대규모 Walking Cat configuration에서는 Cat이 factory에서 block으로 갔다가 다시 돌아오는 동안 다음 Cat 생산을 멈추지 않기 위해 **추가 transport Cat qubits**도 잡아둔다.

**📌 여섯째, decoder가 SEC보다 빨라야 한다**

- - physical qubit이 늘어날수록 syndrome 데이터도 증가한다.
  - QEC hardware가 아무리 좋아도 decoder가 SEC를 따라잡지 못하면 logical operation이 stall된다.
  - Walking Cat은 Q70/Q102에 streaming beam decoder를 적용하고 real-time processing을 architecture의 일부로 포함한다.

---

**✅ 256에서 10K로 가는 것은 단순히 큐비트가 39배가 되는 문제가 아니다**

**📌 숫자로는 약 39배다**

- - 10000/256≈39
  - Walking Cat 웹페이지도 10K를 여러 256-qubit unit cell로 구성된 시스템으로 시각화한다.
  - 다만 실제 제품의 정확한 physical tiling이 단순히 39개의 동일 256 die라는 뜻까지는 아니다.
  - 핵심은 **같은 256-class building block을 반복해 확장하는 modular architecture**다.

**📌 256에서는 “한 기능을 담는 것”이 중심이다**

- - Q70의 예:

    - Q70 Memory + Cat = 256
  - 이 상태에서는 6 logical qubits를 상당히 강하게 보호하는 하나의 module을 만들 수 있다.
  - 그러나:

    - Magic Factory 없음
    - Bell Factory 없음
    - shared Global Reservoir 없음
    - large routing network 없음
  - 따라서 **하나의 완전한 general-purpose FTQC라기보다 logical-memory building block에 가까운 크기**다.

**📌 10K에서는 component를 역할별로 분리할 수 있다**

- - 여러 Q70/Q102 Memory block
  - 여러 Cat Factory
  - Q54 CH2 또는 Q70 MEK Factory
  - Bell Factory
  - Global Reservoir
  - transport loop
  - 를 하나의 machine 안에 동시에 구성할 수 있다.
  - 여기서부터 Walking Cat의 **Modularity와 resource-state logistics**가 본격적으로 의미를 갖는다.

---

**✅ 10K는 256의 “큰 버전”이 아니라 architecture의 phase change에 가깝다**

**📌 256의 의미**

- - semiconductor 공정으로 만들어지는 256-qubit QPU
  - Electronic Qubit Control
  - ion trapping과 transport
  - 반복 제조 가능한 unit-cell/platform
  - 작은 QEC와 resource movement 검증
  - large-code FTQC의 building block
  - IonQ는 2026년 9월 기준 fully integrated 256-qubit QPU를 제작했고 prototype에서 first ions를 trapped했으며, 고객 납품은 2027년으로 안내하고 있다.

**📌 10K의 의미**

- - 여러 logical blocks를 동시에 유지
  - Q70/Q102 같은 production-grade qLDPC 후보 사용
  - Memory·Magic·Cat·Bell을 별도 factory로 배치
  - Cat/Bell resource를 block 사이로 이동
  - continuous SEC + real-time decoding
  - Local/Global ion reservoir 운영
  - application에 따라 Memory와 Factory 비율을 조절
  - IonQ가 **Walking Cat을 실제로 run하도록 설계한 첫 hardware generation**으로 명시한 시스템이다.

---

**✅ 10K에서는 QEC code를 하나로 고정할 필요도 없다**

**📌 Q70은 속도 중심**

- - [[70,6,9]]
  - 6 logical qubits/block
  - block width 18
  - Memory와 MEK Magic Factory 모두 가능
  - 6-qubit Clifford group을 frame tracking으로 처리할 수 있는 것이 큰 장점이다.

**📌 Q102는 밀도 중심**

- - [[102,22,9]]
  - 22 logical qubits/block
  - block width 30
  - 동일한 physical-qubit budget에서 훨씬 많은 logical memory를 확보한다.
  - 대신 block 자체가 316 qubits라 256 단일 cell부터 넘어간다.

**📌 Q54는 Magic State 생산 중심**

- - [[54,2,10]]
  - strongly transversal Hadamard 특성을 이용해 CH2 factory를 구현한다.
  - logical memory density가 목적이 아니라 **빠르고 효율적인 high-fidelity Magic State production**이 목적이다.

**📌 그래서 미래 시스템은 application에 따라 달라진다**

- - logical memory가 많이 필요한 application → Q102 비중 증가
  - 빠른 Clifford-heavy workload → Q70 장점
  - T-heavy workload → CH2/MEK Factory 비중 증가
  - 즉 “Superion 10K = logical qubit 숫자 하나”로 보는 것보다:

    - **어떤 code를 몇 block 쓰는가**
    - **Magic Factory를 몇 개 두는가**
    - **Cat throughput을 얼마나 확보하는가**
  - 가 실제 application performance를 결정하게 된다.

---

**✅ 256과 10K를 가장 단순하게 비교하면**

**📌 Superion 256**

- - 하나의 작은 chip/fabric 안에서:

    - Steane 5 logical block + support resources
    - 또는 BB5 [[30,8,4]] 8-logical Memory + Magic + Cat + Reservoir
    - 또는 계산상 Q70 Memory + Cat
  - 정도의 **작은 FTQC subsystem을 표현할 수 있는 규모**다.
  - 그러나 Walking Cat의 실제 large-code full-stack FTQC를 한 256 안에서 완결시키기에는 공간이 부족하다.

**📌 Superion 10K**

- - 수십 개의 256-class resource budget을 하나의 fabric에서 활용할 수 있다.
  - QEC code block 하나가 unit-cell 경계를 넘어가도 문제가 되지 않는다.
  - Memory·Magic·Cat·Bell·Reservoir가 각각 필요한 만큼 공간을 점유한다.
  - machine 전체를 하나의 **quantum data center inside a chip/fabric**처럼 resource scheduling할 수 있다.
  - 이것이 256 → 10K에서 발생하는 가장 중요한 변화다.

---

**✅ 결국 Walking Cat 페이지가 말하려는 것은 “256으로 모든 걸 한다”가 아니다**

- - 현재 웹 데모만 보면 256 physical qubits 안에 무엇을 어떻게 우겨 넣느냐가 가장 눈에 띈다.
  - 그러나 진짜 의미는 반대에 가깝다.
  - **256을 하나의 반복 가능한 physical building block으로 만들고, 그 위에 QEC code와 factory architecture를 자유롭게 배치할 수 있도록 한다는 것**이 핵심이다.
  - 웹 [[30,8,4]]에서는 allocation이 우연이 아니라 정확히 256에 맞춰진다.
  - Q70에서는 Memory+Cat만으로 정확히 256이 된다.
  - Q54 CH2부터는 281이 필요해 unit-cell 경계를 넘어간다.
  - Q102에서는 Memory+Cat만 376이어서 처음부터 multi-cell architecture가 필요하다.
  - 따라서 code가 발전할수록 “한 code를 한 chip 안에 넣을 수 있나?”라는 질문보다 “여러 tile에 걸쳐 Memory, Factory, transport resource를 어떻게 최적 배치할 것인가?”가 더 중요한 문제로 바뀐다.

**✅ 최종적으로 정리하면**

- - **Steane [[7,1,3]]**

    - 웹 데모용 small-code configuration
    - 5 Memory blocks = 155
    - Magic = 32
    - Cat = 24
    - Global Reservoir = 45
    - 총 **256**
  - **BB5 [[30,8,4]]**

    - Memory = 100
    - Magic = 101
    - Cat = 24
    - Global Reservoir = 31
    - 총 **256**
    - 256 unit의 구성요소를 가장 완벽하게 보여주는 demo
  - **Q54**

    - Memory+Cat은 204로 들어감
    - 하지만 실제 CH2 Magic+Cat은 **281**
    - full Magic module은 multi-tile 필요
  - **Q70**

    - Memory+Cat = **256 정확히**
    - MEK+Cat = **257**
    - 256과 매우 잘 맞지만 universal FTQC에는 다른 tile의 resource가 필요
  - **Q102**

    - Memory만 **316**
    - Memory+Cat = **376**
    - 처음부터 multi-tile을 전제로 해야 함
  - **256의 본질**

    - Walking Cat의 모든 기능을 완성하는 종착점이라기보다 **반복 생산 가능한 physical unit와 핵심 primitive의 단계**
  - **10K의 본질**

    - Q70/Q102 Memory, Q54/Q70 Magic, Cat, Bell, Reservoir, routing을 한 시스템 안에 실제 architecture로 조합할 수 있는 규모
    - 그래서 IonQ가 10K를 **Walking Cat을 실행하도록 만들어지는 첫 hardware generation**이라고 표현한 것이다.
  - 결국 **256 →** **10K의 핵심은** **39배 더 많은 qubit이 아니라, QEC가 한 작은 block의 실험에서 벗어나 Memory·Magic·Cat·Bell이 동시에 돌아가는** **진짜 modular FTQC architecture로 넘어간다는 것**이다.
