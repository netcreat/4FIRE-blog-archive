**✅ 반복연산의 오류 누적**

- - 이 계산은 양자컴퓨터의 오류 누적을 직관적으로 이해하는 데도 어느 정도 도움이 된다.
  - 반복 연산의 무오류 확률

    - P0 = FN = (1−p)N

      - F: 한 번의 연산 정확도
      - p: 한 번의 연산 오류율
      - N: 연산 횟수
      - P0: N번 모두 정확할 확률
    - 한 번 이상 오류가 발생할 확률은 다음과 같다.

      - P(error) = 1−(1−p)N

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **Accuracy per operation** | **Error rate (p)** | **Error-rate notation** | **Accuracy after 365 operations** | **Probability of at least one error** |
| 99% | 1% | 10^-2 | **2.551796%** | **97.448204%** |
| 99.9% | 0.1% | 10^-3 | **69.406989%** | **30.593011%** |
| 99.99% | 0.01% | 10^-4 | **96.415633%** | **3.584367%** |
| 99.999% | 0.001% | 10^-5 | **99.635663%** | **0.364337%** |
| 99.9999% | 0.0001% | 10^-6 | **99.963507%** | **0.036493%** |
| 99.99999% | 0.00001% | 10^-7 | **99.99635%** | **0.00365%** |
| 99.999999% | 0.000001% | 10^-8 | **99.999635%** | **0.000365%** |
| 99.9999999% | 0.0000001% | 10^-9 | **99.9999635%** | **0.0000365%** |
| 99.99999999% | 0.00000001% | 10^-10 | **99.99999635%** | **0.00000365%** |

- - 이 계산은 작은 오류율도 반복되면 누적된다는 원리를 보여준다.
  - 그러나 365라는 숫자는 실제 양자컴퓨터의 성능 지표가 아니다. 실제 회로의 큐비트 수와 depth, gate count는 알고리즘마다 다르다.
  - 따라서 이 계산은 오류 누적을 이해하기 위한 직관적인 예시로만 사용해야 한다.

**✅ 고전컴퓨터의 10****-15** **은 어디에서 나오는가**

- - 고전컴퓨터에서 종종 언급되는 10-15급 오류율도 단일 트랜지스터나 CPU 논리게이트가 본질적으로 제공하는 정확도가 아니다.
  - 주로 저장장치나 통신에서 ECC, LDPC, CRC, 재판독과 재전송 등을 적용한 뒤 남는 잔여 비트 오류율을 의미한다.

|  |  |  |
| --- | --- | --- |
| **영역** | **10^-15의 의미** | **주요 보호 방식** |
| SSD·HDD | 읽은 10^15 비트당 복구 불가능한 오류 약 1개 | **LDPC/BCH**, 재판독, RAID |
| 고속 네트워크 | 전송한 10^15비트당 잔여 오류 1개 이하 | FEC, CRC, 패킷 재전송 |
| CPU 연산 | 보편적인 “연산당 10^-15” 규격 없음 | parity, ECC, replay, lockstep |
| 전체 컴퓨터 | SDC·시스템 장애율로 측정 | 하드웨어·OS·소프트웨어 중복 보호 |

- - 고전 디지털 게이트에는 또 하나의 중요한 특징이 있다.

    - 각 단계에서 입력 전압을 다시 0이나 1로 판정해 신호를 재생한다. 따라서 작은 아날로그 노이즈가 모든 연산 단계를 거치며 동일한 형태로 계속 누적되는 구조가 아니다.
  - 반면 양자게이트에서는 작은 회전각 오류, 위상 오류, leakage와 decoherence가 양자상태에 남아 이후 연산과 결합할 수 있다. 양자상태를 매 단계 측정해 0이나 1로 복원할 수도 없다.
  - 따라서 물리 양자게이트 오류율과 고전 시스템의 보정 후 BER을 직접 비교하는 것은 공정하지 않다.
  - 양자컴퓨터와 고전컴퓨터의 신뢰도를 비교하려면 양쪽 모두 오류 검출과 교정을 거친 뒤의 논리 연산 오류율을 비교해야 한다.

**✅ 99.99% 물리 2Q fidelity의 의미**

- - IonQ와 Oxford Ionics는 2025년 Electronic Qubit Control을 이용해 99.99%를 넘는 물리 2Q gate fidelity를 발표했다.
  - 이는 오류수정을 적용하기 전의 물리 게이트 성능이라는 점에서 중요한 결과다.
  - 그러나 99.99%라는 숫자만으로 실제로 얼마나 복잡한 회로를 실행할 수 있는지는 알 수 없다.
  - 현실적으로는 다음 세 요소를 함께 봐야 한다.

    - W: 알고리즘이 실제로 사용하는 active-qubit width
    - D2Q: 순차적으로 실행되는 2Q gate depth
    - ρ: 각 2Q layer에서 gate에 참여하는 큐비트의 비율
    - G2Q: 전체 2Q gate 수
  - 각 layer에서 동시에 실행되는 평균 2Q gate 수는 다음과 같이 추정할 수 있다.

    - 아래 수식에서 2로 나눈 이유는 큐비트 2개를 사용하기 때문이다.

- - 따라서, 전체 2Q gate 수는 다음과 같이 계산할 수 있다.

- - 2Q gate 오류가 서로 독립적이고 모든 gate의 fidelity가 같다고 단순화하면 전체 2Q gate 무오류 확률은 다음과 같다.

- - - p0: 전체무오류 확률
    - p2Q: 2큐비트 게이트 오류율
    - G2Q: 전체 2큐비트 게이트 수
  - 전체 회로가 90% 또는 99%의 무오류 확률을 가지려면 필요한 fidelity는 다음과 같다.

|  |  |  |
| --- | --- | --- |
| **전체 2Q 게이트 수** | **90% 성공에 필요한 2Q fidelity** | **99% 성공에 필요한 2Q fidelity** |
| 10^2 | 99.8947% | 99.98995% |
| 10^3 | 99.9895% | 99.998995% |
| 10^4 | 99.99895% | 99.9998995% |
| 10^6 | 99.9999895% | 99.999998995% |
| 10^9 | 99.9999999895% | 99.999999998995% |

- - 즉 99.99%라는 fidelity도 회로 규모에 따라 의미가 완전히 달라진다.

    - 100개의 2Q 게이트: 상당히 안정적
    - 1,000개의 2Q 게이트: 약 90.5% 무오류
    - 10,000개의 2Q 게이트: 약 36.8% 무오류
    - 1,000,000개의 2Q 게이트: 사실상 무오류 실행 불가능

**📌 10,000개 게이트 회로를 예로 들면**

- - G2Q=10,000 이라고 가정했을 때:

|  |  |  |
| --- | --- | --- |
| **2Q fidelity** | **오류율** | **전체 무오류 확률** |
| 99.9% | 10^−3 | 0.0045% |
| 99.99% | 10^−4 | 36.79% |
| 99.999% | 10^−5 | 90.48% |
| 99.9999% | 10^−6 | 99.005% |
| 99.99999% | 10^−7 | 99.900% |

- - 따라서 **99.99%는 수백∼수천 게이트에는 강력하지만, 수만 게이트 회로에는 아직 부족하다.**
  - 수만 개의 물리 게이트를 오류수정 없이 안정적으로 실행하려면 10−5∼10−6 수준의 물리 오류율이 의미 있는 목표가 된다.

**📌 Width와 depth를 반영한 현실적인 예시**

- - 물리 2Q fidelity를 99.99%라고 놓으면 오류율은 10-4이다.
  - 각 layer에서 active qubit의 50%가 2Q gate에 참여한다고 가정한다.

    - ρ = 0.5
  - 이 경우 layer당 평균 2Q gate 수는 W ÷ 4가 된다.

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **Active qubits (W)** | **2Q depth (D\_{2Q})** | **평균 2Q gates/layer** | **총 2Q gates** | **2Q gate가 모두 무오류일 확률** |
| 64 | 25 | 16 | 400 | **96.08%** |
| 64 | 100 | 16 | 1,600 | **85.21%** |
| 64 | 500 | 16 | 8,000 | **44.93%** |
| 100 | 25 | 25 | 625 | **93.94%** |
| 100 | 100 | 25 | 2,500 | **77.88%** |
| 100 | 500 | 25 | 12,500 | **28.65%** |
| 256 | 25 | 64 | 1,600 | **85.21%** |
| 256 | 100 | 64 | 6,400 | **52.73%** |
| 256 | 500 | 64 | 32,000 | **4.08%** |

- - 계산은 다음과 같다.

    - P0,2Q=(0.9999)G2Q
  - 예를 들어 100개의 큐비트를 사용하고 2Q depth가 100이라면:

    - G2Q=0.5×100/2 ×100=2,500
  - 따라서:

    - P0,2Q=(0.9999)2,500 ≈77.88%

> ***따라서 물리 gate fidelity의 의미는 gate fidelity 하나로 결정되지 않는다.***
>
> ***Circuit width × 2Q depth × Entangling density***
>
> ***이 세 요소를 함께 봐야 한다.***

- - All-to-all connectivity는 불필요한 SWAP gate와 추가 depth를 줄일 수 있기 때문에 전체 error budget을 개선한다.
  - 높은 병렬성 역시 실행시간과 decoherence를 줄인다. 그러나 병렬화가 전체 gate count 자체를 없애는 것은 아니다.

**✅ 이 수치가 실제 알고리즘 성공률과 다른 이유**

- - 앞의 계산은 모든 물리 2Q gate에서 단 한 번도 오류가 발생하지 않을 확률이다.
  - 이것을 실제 알고리즘의 성공률과 완전히 동일하게 보면 안 된다.

    - 일부 오류는 최종 observable에 거의 영향을 주지 않을 수 있다.
    - coherent error는 같은 방향으로 누적돼 단순 확률 모델보다 빠르게 커질 수 있다.
    - 특정 qubit pair의 성능이 평균보다 낮을 수 있다.
    - 병렬 gate에서 crosstalk이 증가할 수 있다.
    - leakage는 일반적인 Pauli error와 다르게 누적된다.
    - calibration drift로 시간에 따라 성능이 달라질 수 있다.
    - 측정, idle, 이온 이동 오류는 2Q fidelity에 포함되지 않을 수 있다.
    - error mitigation이나 QEC가 최종 결과의 오류를 줄일 수 있다.
  - 따라서 gate fidelity는 다음 지표와 함께 봐야 한다.

    - Native 1Q·2Q gate count
    - 2Q depth와 병렬성
    - Active-qubit width
    - Connectivity와 SWAP overhead
    - SPAM, idle, transport, leakage
    - Application benchmark
    - Mirror circuit 또는 XEB
    - Quantum Volume
    - Logical error per cycle
    - Time-to-solution

**✅ 물리 fidelity와 논리 fidelity의 역할**

- - 실용적인 목표는 물리큐비트의 오류율을 무조건 10-15까지 낮추는 것이 아니다.

    - 먼저 물리 오류율을 QEC threshold보다 충분히 낮추고, 오류수정 overhead가 감당 가능한 수준까지 개선해야 한다.

      - QEC threshold는 일종의 손익분기점

        - 물리 오류율이 임계값보다 낮은 경우

          - 더 많은 물리큐비트를 사용하고 code distance를 높일수록 논리 오류율이 감소한다.
          - 충분한 자원을 투입하면 원칙적으로 논리 오류율을 계속 낮출 수 있다.
        - 물리 오류율이 임계값보다 높은 경우

          - 오류가 QEC의 교정 능력보다 빠르게 발생한다.
          - 물리큐비트를 더 많이 붙이고 code distance를 높여도 논리 오류율이 낮아지지 않으며, 오히려 오류가 발생할 지점만 늘어날 수 있다.
  - 물리 오류율의 개선 경로:

    - 10-3 → 10-4 → 10-5 → 10-6
  - 물리 오류율이 10-5∼10-6 까지 내려가면 동일한 논리 오류율을 달성하는 데 필요한 physical-qubit overhead와 오류수정 부담을 크게 줄일 수 있다.
  - 따라서 QEC threshold 아래로 내려갔다고 물리 fidelity 개선의 가치가 사라지는 것은 아니다.
  - 다만 최종 알고리즘이 요구하는 10-10, 10-12 또는 그 이하의 오류율까지 물리게이트만으로 달성할 필요는 없다. 그 역할은 논리큐비트와 QEC가 맡는다.
  - 필요한 논리 오류율은 다음 관계로 정해진다.

- - - 이 식은 앞서 살펴본 식을 통해서 나온다.

- - - - 위 식은 물리 2Q 게이트에 적용된 것이고, 이를 논리 연산에 적용하면 다음과 같다.

- - - - - pL: 논리 연산 한 번의 오류율
        - GL: 전체 논리 연산 수
        - Ptarget: 모든 논리 연산이 성공할 목표 확률
      - 양변에 GL 제곱근을 취하면,

- - - - 여기에서 오류율이 매우 작다는 조건하에 아래와 같이 자연로그 방식의 1차 근사를 적용한다

- - - 예를 들어 109개의 logical operation을 99%의 성공률로 실행하려면 약 10-11의 logical error rate가 필요하다.

|  |  |
| --- | --- |
| **목표 논리 무오류 확률** | **허용되는 logical error rate** |
| 50% | 약 6.93 × 10^-10 |
| 90% | 약 1.05 × 10^-10 |
| 99% | 약 1.01 × 10^-11 |
| 99.9% | 약 1.00 × 10^-12 |
| 99.99% | 약 1.00 × 10^-13 |
| 99.999% | 약 1.00 × 10^-14 |

- - - 전체 성공률을 90%에서 99%로 높이려면 논리 오류율을 약 10분의 1로 낮춰야 한다. 99.9%를 원하면 다시 약 10분의 1로 낮춰야 한다.

|  |  |
| --- | --- |
| **Logical error rate** | **99% 무오류 확률을 유지할 수 있는 연산 수** |
| 10^-7 | 약 10만 개 |
| 10^-8 | 약 100만 개 |
| 10^-9 | 약 1,000만 개 |
| 10^-10 | 약 1억 개 |
| 10^-11 | 약 10억 개 |
| 10^-12 | 약 100억 개 |
| 10^-15 | 약 10조 개 |

**📌 전체 성공률 99%가 충분한가?**

- - 다음과 같은 경우에는 99%가 상당히 적절하다.

    - 결과를 고전컴퓨터로 검증할 수 있는 알고리즘
    - 실패하면 다시 실행할 수 있는 계산
    - 한 번의 실행 비용이 지나치게 크지 않은 경우
    - 결과 후보를 양자컴퓨터가 만들고 고전컴퓨터가 검증하는 경우
    - 여러 번 실행해 통계적으로 결과를 얻는 알고리즘
  - 다음과 같은 경우에는 1%의 실패 확률이 너무 높을 수 있다.

    - 한 번 실행하는 데 수일 또는 수개월이 걸리는 계산
    - 실행 비용이 매우 큰 계산
    - 정답을 사후 검증하기 어려운 알고리즘
    - 암호·국방·의료·금융처럼 잘못된 결과의 피해가 큰 경우
    - 동일한 correlated error가 반복 실행에도 재현될 수 있는 경우
    - 계산 결과가 후속 시스템에 자동으로 투입되는 경우

> ***물리 fidelity의 역할***
>
> ***→ QEC가 효율적으로 작동할 수 있도록 오류수정 overhead를 줄인다.***
>
> ***논리 fidelity의 역할***
>
> ***→ 전체 알고리즘이 요구하는 최종 신뢰도를 달성한다.***

---

**✅ 투자자라면 무엇을 봐야 하는가**

- - 99.99%라는 물리 2Q gate fidelity는 분명 중요한 기술적 성과다. 그러나 투자자에게 더 중요한 질문은 그 수치가 실제 시스템의 성능과 경제성으로 이어지는가이다.

**📌 첫째, 최고 fidelity보다 측정 조건을 확인해야 한다.**

- - 회사가 발표한 수치가 특정한 두 큐비트에서 얻은 최고 기록인지, 전체 큐비트 쌍의 평균인지, 중앙값인지 구분해야 한다. Randomized Benchmarking으로 측정한 gate fidelity인지, Bell-state fidelity인지도 확인해야 한다.
  - 동시에 여러 게이트를 실행했을 때 fidelity가 유지되는지, 장시간 운용 중 calibration drift가 얼마나 발생하는지, 최악의 큐비트 쌍은 어느 정도인지도 중요하다.
  - 투자자가 확인해야 할 항목은 다음과 같다.

    - 전체 큐비트 쌍의 fidelity 분포
    - 평균값·중앙값·최악값
    - 병렬 게이트 실행 시 fidelity
    - crosstalk과 leakage
    - 수시간 또는 수일 동안의 안정성
    - 외부 연구기관의 검증 또는 동료평가 여부

**📌 둘째, fidelity가 시스템 규모와 함께 유지되는지를 봐야 한다.**

- - 10큐비트에서 얻은 99.99%가 100큐비트, 1,000큐비트에서도 유지된다는 보장은 없다. 큐비트가 늘어나면 제어선, 이온 이동, 병렬 동작, 열과 전력, calibration, 제조수율 등의 문제가 함께 커진다.
  - 따라서 로드맵의 큐비트 수보다 현재 실제로 몇 개의 active qubit이 동일한 품질로 작동하는지가 더 중요하다.
  - IonQ의 2026년 이후 큐비트 및 논리 오류율 수치는 현재 실적이 아니라 향후 로드맵이라는 점도 구분해야 한다.

**📌 셋째, QEC가 실제로 논리 오류율을 낮추는지 확인해야 한다.**

- - 논리큐비트를 만들었다는 발표만으로는 충분하지 않다. 오류수정 강도를 높였을 때 논리 오류율이 실제로 감소하는 below-threshold behavior가 관측돼야 한다.
  - 특히 다음을 구분해야 한다.

    - 논리큐비트를 단순히 저장할 때의 오류율
    - QEC cycle당 논리 오류율
    - 논리게이트를 실행할 때의 오류율
    - 측정과 feed-forward를 포함한 전체 오류율
    - 물리큐비트 한 개당이 아니라 논리 연산 한 번당 드는 overhead
  - 메모리 상태를 짧게 유지하는 실험과 수많은 논리게이트를 실행하는 fault-tolerant computation은 난도가 크게 다르다.

**📌 넷째, 실제 애플리케이션 회로에서의 성능을 봐야 한다.**

- - 평균 gate fidelity만으로 애플리케이션 성능을 완전히 예측할 수는 없다. IonQ Forte 연구에서도 전체 435개 큐비트 쌍을 측정한 component-level 모델이 애플리케이션 성능과 상관관계를 보였지만, 모델에 포함되지 않은 오류로 인해 실제 성능은 예측보다 낮았다.

- - 따라서 투자자는 다음 자료를 확인해야 한다.

    - 실제 알고리즘의 compiled native gate count
    - active-qubit width와 2Q depth
    - connectivity와 SWAP overhead
    - application benchmark 결과
    - 동일 회로를 반복했을 때의 결과 분포
    - 고전 알고리즘과 비교한 정확도와 실행시간
  - Width와 depth를 독립적으로 측정하는 volumetric benchmark가 중요한 이유도 여기에 있다.

**📌 다섯째, 속도와 비용을 함께 봐야 한다.**

- - 높은 fidelity라도 한 번의 논리게이트가 지나치게 느리거나 오류수정에 너무 많은 물리큐비트가 필요하면 상업적 경쟁력이 떨어질 수 있다.
  - 중요한 경제성 지표는 다음과 같다.

    - 논리큐비트 하나에 필요한 물리큐비트 수
    - 논리게이트 실행속도
    - 초당 실행 가능한 논리 연산 수
    - 한 번의 성공적인 계산에 필요한 반복 횟수
    - 계산 한 건당 전력·장비·클라우드 비용
    - uptime, calibration 시간과 시스템 가동률
    - 목표 결과를 얻기까지의 time-to-solution

**📌 여섯째, 기술 로드맵과 실증 결과를 분리해야 한다.**

- - 로드맵에 표시된 미래의 물리큐비트 수와 논리큐비트 수는 기술적 목표다. 투자자는 각 단계 사이에 검증 가능한 중간 이정표가 존재하는지 확인해야 한다.
  - 예를 들어 99.99% fidelity, 수백 개 큐비트, 병렬 동작, 실시간 decoding, 모듈 간 연결과 수천 개 논리큐비트가 각각 별개의 실증 과제로 제시돼야 한다. 일정이 지연됐을 때 필요한 추가 자본과 주식 희석 가능성도 함께 검토해야 한다.

**📌 마지막으로 기술성과 매출의 질을 함께 봐야 한다.**

- - 매출이 일회성 정부 계약인지 반복적인 상업 매출인지
  - 고객이 실험 이후 계약을 갱신하는지
  - 실제 QPU 사용량이 증가하는지
  - 특정 고객이나 정부 사업에 매출이 집중돼 있는지
  - 현금소진 속도와 추가 자금조달 가능성
  - 연구 성과가 제품 출하와 서비스 매출로 연결되는지

**📌 결국 투자자가 물어야 할 핵심 질문은 다음과 같다.**

- - “이 회사는 정해진 논리 오류율에서 몇 개의 논리큐비트로 얼마나 깊은 회로를 실행할 수 있으며, 그 결과를 얻는 데 얼마나 많은 시간과 비용이 드는가?”
  - 큐비트 수, 최고 gate fidelity, 논리큐비트 수 가운데 하나만으로 회사를 평가해서는 안 된다.
  - 검증된 width–depth 성능, 논리 오류 억제, 실행속도, 오류수정 overhead, time-to-solution과 상업적 수요가 함께 개선되는지를 봐야 한다.
  - 99.99%는 출발점으로서 중요하지만, 투자 가치를 결정하는 것은 그 수치가 확장 가능한 논리 연산 능력과 경제성으로 전환되는 속도다.

**✅ 결론**

- - 100개, 1,000개, 100만 개를 임의로 승수에 넣는 것은 오류 누적의 수학적 성질을 보여줄 수는 있지만 실제 QPU의 계산 능력을 평가하기에는 부족하다.
  - 반대로 99.99%라는 단일 gate fidelity만 보고 “충분히 유용하다”거나 “아직 쓸모없다”고 판단하는 것도 적절하지 않다.
  - 실제 계산 능력은 다음 질문으로 평가해야 한다.
  - 목표 정확도를 유지하면서 얼마나 많은 큐비트를 사용해, 얼마나 깊고 조밀한 entangling circuit을 실행할 수 있는가?
  - 이를 한 문장으로 정리하면 다음과 같다.

    - Useful quantum capability = 정해진 정확도를 유지하면서 실행할 수 있는 가장 큰 width–depth circuit
  - 결국 중요한 것은 큐비트 수나 gate fidelity 어느 하나가 아니다.
  - 얼마나 많은 큐비트를, 얼마나 정확하게, 얼마나 깊은 회로까지 서로 얽어 사용할 수 있는가가 양자컴퓨터의 실질적인 계산 능력을 결정한다.
