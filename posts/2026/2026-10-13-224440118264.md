**✅ 1. Zero Trust 시장은 모두 같은 기술을 판매하지 않는다**

**📌 ZTNA와 Microsegmentation은 서로 다르다**

- - Zero Trust는 특정 제품이 아니라 명시적인 검증과 최소 권한에 기반한 보안 원칙이다.
  - 이를 구현하는 제품은 보호 대상과 정책을 집행하는 위치에 따라 여러 분야로 나뉜다.

|  |  |  |
| --- | --- | --- |
| **기술 영역** | **주요 목적** | **대표 기업** |
| **ZTNA / SASE** | 사용자와 애플리케이션 사이의 접근 통제 | Zscaler, Cloudflare, Netskope, Palo Alto, Fortinet |
| **NAC** | 사용자·장비의 네트워크 접속 인증 및 제어 | Cisco ISE, Aruba ClearPass, Forescout |
| **Microsegmentation** | 내부 장비와 워크로드 사이의 통신 제한 | Elisity, Illumio, Akamai, Zero Networks, ColorTokens |
| **Host-based Segmentation** | OS 방화벽을 이용한 통신 제한 | Illumio, Zero Networks, Cisco Secure Workload |
| **Hypervisor-based Segmentation** | 가상머신 사이의 통신 제어 | VMware vDefend |
| **PQC / Quantum-safe Networking** | 양자컴퓨터 공격에 대비한 암호화·키 교환 | Cloudflare, Fortinet, Palo Alto, IonQ 등 |

- - Elisity의 직접적인 경쟁 영역은 Microsegmentation이다.
  - 반면 Cloudflare나 Zscaler는 사용자와 애플리케이션 사이의 접속 보호와 클라우드 기반 보안 서비스를 중심으로 발전해 왔다.
  - 따라서 모든 제품을 하나의 제로트러스트 시장에 묶어 성능을 비교하는 것은 적절하지 않다.
  - 하지만 PQC까지 경쟁 범위를 넓히면 상황이 달라진다.
  - IonQ가 Elisity를 통해 진출하려는 차세대 기업 보안 시장에는 이미 대규모 고객 기반과 PQC 기술을 함께 보유한 기업들이 존재하기 때문이다.

**✅ 2. 마이크로세그멘테이션 경쟁사들의 기술 아키텍처**

**📌 핵심 차이는 정책을 어디에서 집행하는가에 있다**

|  |  |  |  |
| --- | --- | --- | --- |
| **기업** | **대표 솔루션** | **주요 정책 집행 지점** | **기술적 특징** |
| **Elisity** | Identity-based Microsegmentation | 기존 지원 스위치 | IdentityGraph, VE/VEN, Agentless |
| **Illumio** | Illumio Segmentation / Core | 호스트 OS, 일부 네트워크 제어점 | 워크로드 중심, 에이전트, NEN |
| **Akamai** | Guardicore Segmentation | 호스트, DPU, 지원 스마트 스위치 | 프로세스 가시성, 혼합형 집행 |
| **Zero Networks** | Zero Networks Segment | OS 방화벽, 기존 스위치 ACL | Agentless, 자동 정책, JIT MFA |
| **ColorTokens** | Xshield | 호스트, Gatekeeper, 네트워크 | 에이전트·에이전트리스 혼합 |
| **Cisco** | ISE/TrustSec · Secure Workload | 스위치, 호스트, 방화벽, 클라우드 | SGT/SGACL, 워크로드 정책 |
| **VMware / Broadcom** | vDefend | 하이퍼바이저의 가상 NIC | VM 단위 분산 방화벽 |

**📌 Elisity — 기존 스위치를 활용하는 접근**

- - Elisity는 Cloud Control Center(CCC)에서 정책을 관리하고 Virtual Edge(VE)를 통해 기존 스위치인 Virtual Edge Node(VEN)에 전달한다.
  - VEN은 기존 스위치의 네이티브 기능을 활용해 보안 정책을 집행한다.
  - 따라서 지원되는 네트워크 장비를 이미 보유하고 있다면 신규 전용 보안 장비 없이도 배포할 수 있다.
  - 특히 의료장비, IoT, OT처럼 별도 에이전트를 설치하기 어려운 장비를 보호하는 데 유리하다.
  - 그러나 Cisco, Arista, Juniper, Aruba의 모든 모델을 지원하는 것은 아니며, 모델별 정책 집행 능력도 다르다.

**📌 Illumio — 서버와 워크로드 중심의 접근**

- - Illumio는 Virtual Enforcement Node(VEN)라는 에이전트를 서버와 PC에 설치하고 운영체제의 기존 방화벽을 이용하는 방식이 대표적이다.
  - 중앙 Policy Compute Engine(PCE)이 통신 관계를 분석하고 정책을 관리한다.
  - 호스트 내부의 애플리케이션과 프로세스 정보를 활용할 수 있으므로 서버와 클라우드 워크로드에 대한 세밀한 통제에 강점이 있다.
  - 그러나 Illumio도 모든 장비에 반드시 에이전트를 설치해야 하는 것은 아니다.
  - Network Enforcement Node(NEN)를 통해 지원 로드밸런서 등의 네트워크 집행 지점을 활용하고, 에이전트가 없는 워크로드를 정책에 포함할 수 있다.
  - 클라우드 네이티브 제어 기능을 이용한 에이전트리스 보호 방식도 제공한다.

**📌 Zero Networks — Elisity와 가장 유사한 경쟁 구조**

- - Zero Networks는 기존 Windows와 Linux 등의 호스트 방화벽을 중앙에서 관리한다.
  - OT·IoT 장비처럼 에이전트를 설치하기 어려운 환경에서는 기존 스위치와 라우터의 ACL을 이용한다.
  - 통신 관계를 학습한 뒤 필요한 경로를 허용하는 정책을 생성하는 자동화 기술도 제공한다.
  - 여기에 Just-in-Time MFA를 이용해 RDP, SSH, SMB 등 민감한 관리자 접근을 일시적으로 허용할 수 있다.
  - 즉, 기존 인프라를 활용한 에이전트리스 접근은 Elisity만의 기술이 아니다.

**📌 Akamai — 호스트에서 DPU까지 확장**

- - Guardicore는 전통적인 호스트 에이전트 방식 외에도 네트워크 하드웨어 기반 집행을 지원한다.
  - HPE Aruba CX 10000의 AMD Pensando DPU를 활용하면 호스트에 새로운 에이전트를 설치하지 않고 네트워크 패브릭에서 통신을 통제할 수 있다.
  - NVIDIA BlueField 기반 집행 방식도 확장하고 있다.
  - 이러한 접근은 데이터센터의 서버 간 통신을 네트워크 인프라 수준에서 세밀하게 제한하려는 전략이다.
  - 다만 해당 DPU나 스마트 스위치가 없다면 추가 하드웨어 비용이 발생할 수 있다.

**📌 ColorTokens — 에이전트와 Gatekeeper 결합**

- - ColorTokens는 호스트 에이전트, Gatekeeper, 기존 네트워크 장비 및 클라우드 제어 기능을 결합한다.
  - 일반 서버나 PC에서는 에이전트를 활용하고, 의료장비와 OT 자산에서는 에이전트리스 Gatekeeper를 이용할 수 있다.
  - Gatekeeper는 가상 또는 물리 장비로 구성할 수 있다.
  - 기존 EDR과의 연동을 활용해 신규 에이전트 설치 부담을 낮추는 방식도 제공한다.
  - 따라서 환경에 따라 신규 전용 물리장비가 필요할 수도 있고 기존 인프라를 활용할 수도 있다.

**✅ 3. 경쟁사들은 실제로 얼마나 많은 장비를 추가해야 할까?**

**📌 가상의 기업 네트워크를 기준으로 비교한다**

- - 다음과 같은 기업 네트워크를 가정해 보자.

|  |  |  |
| --- | --- | --- |
| **자산 종류** | **수량** | **주요 특징** |
| Access Switch | 100대 | 여러 제조사의 네트워크 장비 |
| 업무용 PC | 3,000대 | Windows 기반 관리형 장비 |
| 서버 및 VM | 200대 | Windows/Linux 및 가상화 |
| IoT·OT·의료장비 | 800대 | 에이전트 설치가 어렵거나 불가능 |
| **총 보호 대상** | **4,000개** | PC·서버·IoT·OT |

- - 이 환경에서 기존 네트워크를 최대한 활용한다고 가정하면 다음과 같다.

**📌 기업별 신규 구성요소**

|  |  |  |  |
| --- | --- | --- | --- |
| **기업** | **신규 전용 물리장비** | **단말 에이전트** | **추가 관리 인프라** |
| **Elisity** | 0대 가능 | 0개 | CCC + VE |
| **Illumio** | 0대 가능 | 호스트 방식이면 최대 3,200개 | PCE, VEN, 필요 시 NEN |
| **Akamai** | 0대 가능 | 호스트 방식이면 최대 3,200개 | 중앙 관리 및 집행 구성요소 |
| **Zero Networks** | 0대 가능 | 기본 방식에서 0개 | Segment 컨트롤러 |
| **ColorTokens** | 0대 가능 | 방식에 따라 선택 | Xshield, Gatekeeper 등 |
| **Cisco** | 0대 가능 | 제품·집행 방식별 상이 | ISE, Secure Workload 등 |
| **VMware / Broadcom** | 기존 ESXi 활용 가능 | VM 내부에는 불필요 | NSX/vDefend 관리 구성요소 |

- - 여기서 0대란 기존 하드웨어가 필요한 기능을 지원한다는 전제에서 신규 전용 물리장비가 필요하지 않을 수 있다는 의미다.
  - Illumio와 Akamai의 최대 3,200개 에이전트는 PC와 서버 전체를 호스트 에이전트 방식으로 보호하는 경우를 가정한 것이다.
  - 실제로는 에이전트리스 방식과 혼합해 설치 수량을 줄일 수 있다.
  - 반대로 Elisity도 기존 스위치 중 지원되지 않는 장비가 있다면 장비 교체나 다른 집행 지점이 필요할 수 있다.
  - 따라서 **추가 물리장비가 0대라는 사실만으로 Elisity가 경쟁사보다 저렴하다고 판단해서는 안 된다.**

**✅ 4. 어느 방식이 실제로 더 유리할까?**

**📌 정책 집행 위치에 따른 경쟁력**

|  |  |  |  |
| --- | --- | --- | --- |
| **비교 기준** | **스위치 기반** | **호스트 기반** | **하이퍼바이저 기반** |
| 대표 제품 | Elisity, Cisco, 일부 Zero Networks | Illumio, Zero Networks, Akamai | VMware vDefend |
| 단말 에이전트 | 일반적으로 불필요 | 제품·방식별 차이 | 게스트 VM 내부에는 불필요 |
| IoT·OT 보호 | 지원 스위치를 통한 적용 | 별도 네트워크 집행 필요 가능 | 일반 물리 장비에는 직접 적용 어려움 |
| 동일 VLAN 통신 | 네트워크 집행 지점에 의존 | 호스트에서 통제 가능 | VM 사이에 적용 가능 |
| 프로세스별 제어 | 제한적 | 상대적으로 유리 | 제품별 기능 확인 필요 |
| 정책 세분화 | ASIC·ACL·Tag 기능에 의존 | OS 방화벽 기능에 의존 | 가상화 계층 기능에 의존 |
| 클라우드 보호 | 별도 집행 지점 검토 | 직접 보호 가능 | VMware 환경 중심 |
| 주요 운영 부담 | 장비 호환성, ACL·TCAM | 호스트 관리, 에이전트·방화벽 | 가상화 인프라·라이선스 |

**📌 보안 환경별로 경쟁력이 달라진다**

|  |  |  |
| --- | --- | --- |
| **기업 환경** | **주요 검토 대상** | **기술적 이유** |
| 병원·의료장비 네트워크 | Elisity, Zero Networks, ColorTokens | 비관리형 단말 보호 |
| 서버 중심 데이터센터 | Illumio, Akamai, VMware | 워크로드·애플리케이션 단위 통제 |
| 제조·OT 네트워크 | Elisity, Zero Networks, ColorTokens | 기존 네트워크와 Agentless 집행 |

| 관리 계정 탈취 대응 | Zero Networks | JIT MFA |
| 클라우드·Kubernetes 환경 | Illumio, Akamai, Cisco, VMware | 클라우드·워크로드 제어 |

- - 결국 Elisity의 실제 경쟁력은

    - 기존 스위치를 얼마나 많이 재활용할 수 있는지,
    - 지원되는 정책이 얼마나 세밀한지,
    - 정상 업무를 중단하지 않고 자동화할 수 있는지
  - 에 달려 있다.
  - 하지만 여기까지의 경쟁은 어디까지나 기존 네트워크의 접근 통제 시장에 관한 이야기다.
  - IonQ가 Elisity를 인수하는 전략까지 평가하려면 PQC와 QKD라는 또 다른 경쟁 영역을 살펴봐야 한다.

**✅ 5. PQC와 Zero Trust는 왜 결합하려는 것일까?**

**📌 두 기술은 해결하려는 문제가 다르다**

- - Zero Trust는 누가 어떤 자원에 접근할 수 있는지를 통제한다.
  - 반면 PQC는 양자컴퓨터 공격에 취약한 기존 공개키 암호체계를 대체하거나 보완하는 기술이다.
  - 제로트러스트 정책이 아무리 정교해도 전송 중인 암호화 데이터를 장래에 복호화할 수 있는 위험까지 해결하지는 못한다.
  - 반대로 통신을 PQC로 보호한다고 해서 접근 권한이 없는 사용자의 접속이 자동으로 차단되는 것도 아니다.

|  |  |  |
| --- | --- | --- |
| **기술** | **해결하려는 문제** | **주요 보호 대상** |
| **Zero Trust** | 미인가 접근, 과도한 권한 | 사용자·장비·애플리케이션 |
| **Microsegmentation** | 내부 횡적 이동과 피해 확산 | 네트워크 통신 경로 |
| **PQC** | 양자컴퓨터에 취약한 공개키 암호체계 | 키 교환, 전자서명 등 |
| **QKD** | 양자역학적 방식의 키 분배 | 특정 통신 경로의 키 생성·공유 |
| **Crypto-Agility** | 암호 알고리즘의 교체·관리 어려움 | 기업 전체의 암호화 인프라 |

**📌 PQC는 모든 암호화를 새로운 방식으로 바꾸는 것은 아니다**

- - 예를 들어 TLS 1.3에서 Hybrid ML-KEM을 사용하면 기존의 타원곡선 기반 키 교환과 양자내성 KEM을 결합해 세션 키를 설정할 수 있다.
  - 이때 실제 애플리케이션 데이터의 대칭키 암호화에는 여전히 AES-GCM 등의 알고리즘을 사용할 수 있다.
  - 또한 양자내성 키 교환을 적용했다고 해서 서버 인증서의 전자서명까지 자동으로 양자내성 방식으로 바뀌는 것은 아니다.
  - 따라서 기업 전체의 PQC 전환을 평가하려면 키 교환과 인증·서명, 저장 데이터, 관리 프로토콜을 따로 구분해야 한다.

**📌 PQC를 적용해도 Zero Trust는 필요하다**

- - 예를 들어 공격자가 정상 직원의 계정을 탈취했다면 PQC로 보호된 연결을 이용해 정상적인 인증 절차를 통과하려고 시도할 수 있다.
  - PQC는 암호화된 통신의 기밀성 및 관련 암호학적 보안 성질을 강화하지만, 탈취된 정상 권한으로 어떤 서버까지 접근할 수 있는지 결정하지는 않는다.
  - 반대로 제로트러스트는 네트워크 접근 권한을 통제하지만 통신에 사용한 암호 알고리즘이 미래의 양자 공격에 견딜 수 있는지까지 반드시 보장하지는 않는다.
  - **따라서 PQC와 Zero Trust는 경쟁 기술이 아니라 서로 다른 취약점을 보완하는 기술**이다.

    - **Elisity의 강점은 내부 스위치 기반의 장비 간 통신 통제**라는 차이가 있다.

**✅ 9. Fortinet — PQC뿐 아니라 QKD까지 활용한다**

**📌 IonQ와 비교할 때 반드시 살펴봐야 할 기업**

- - Fortinet은 FortiOS 7.6 계열에서 PQC 기반 IPsec 키 교환을 지원하기 시작했다.
  - FortiOS 7.6.3의 기능 설명에는 PQC와 QKD, 기존 Diffie-Hellman 키 교환을 함께 결합하는 구조가 명시되어 있다.
  - 이는 QKD 시스템에서 제공받은 키 자료와 PQC 및 기존 키 교환을 함께 사용해 IPsec Security Association을 구성하는 방식이다.
  - 2026년 3월 발표한 FortiOS 8.0에서는 양자내성 VPN, 관리 접속 보호, Hybrid PQC 기반 SSL 검사와 SASE 기능을 더욱 강화했다.

**📌 Fortinet의 양자보안 기술**

|  |  |  |
| --- | --- | --- |
| **기술** | **역할** | **확인된 지원 범위** |
| Hybrid PQC IPsec | 양자내성 VPN 키 교환 | FortiOS 지원 버전 |
| QKD 연동 | 외부 QKD 시스템의 키 활용 | 지원 IPsec 구성 |
| DH + PQC + QKD | 서로 다른 키 자료를 결합 | FortiOS 7.6.3 기능 설명 |
| ML-DSA 관련 기능 | 양자내성 인증·서명 지원 확대 | FortiOS 8.0 제품 기능 |
| Hybrid PQC SSL Inspection | 양자내성 키 교환을 사용하는 암호화 트래픽 검사 | FortiOS 8.0 |
| ZTNA / FortiSASE | 사용자·애플리케이션 접근 통제 | 기존 보안 플랫폼 |

**📌 중요한 차이는 QKD 시스템을 직접 보유하는가다**

- - Fortinet은 QKD 시스템과 연동하는 암호화·네트워크 보안 장비를 제공한다.
  - 반면 IonQ는 QKD 및 양자 네트워킹 기술 자체를 보유하고, 관련 양자보안 네트워크 구축 사업도 수행하고 있다.
  - 이는 양사의 공급 범위가 다르다는 것을 의미한다.
  - 그러나 고객 입장에서는 Fortinet과 외부 QKD 공급업체를 조합해 필요한 기능을 구현할 수도 있다.
  - 따라서 IonQ가 QKD 기술을 직접 보유하고 있다는 사실이 모든 고객에게 결정적인 우위가 된다고 볼 수는 없다.
  - 실제 경쟁력은 QKD 장비의 도입 비용, 거리·광섬유 제약, 통합 운영의 복잡성, 키 공급 성능, 보안 정책 연동 수준 등을 함께 비교해야 한다.
  - **Fortinet의 사례는 PQC·QKD·Zero Trust의 결합 자체가 더 이상 IonQ만의 독점적인 전략이 아니라는 점을 보여준다.**

**✅ 10. Zscaler — PQC 트래픽을 검사하고 암호 위험을 가시화한다**

**📌 암호화된 통신을 보호하는 것과 검사하는 것은 다르다**

- - Zscaler는 Cloudflare와는 조금 다른 방향의 경쟁력을 강조한다.
  - Cloudflare가 PQC 기반 연결 보호를 적극적으로 확대하고 있다면, Zscaler는 PQC가 적용된 TLS 통신에서도 기존의 보안 검사와 정책 집행을 유지하려는 전략이다.
  - 중요한 이유가 있다.
  - 암호화 수준이 강화되면 기존의 보안 검사 시스템이 새로운 키 교환 알고리즘을 이해하거나 협상하지 못해 트래픽 가시성을 잃을 가능성이 있기 때문이다.

**📌 Zscaler의 기능**

|  |  |  |
| --- | --- | --- |
| **기능** | **설명** | **2026년 10월 상태** |
| PQC Visibility | 사용 중인 키 교환·서명 알고리즘 가시화 | 제공 |
| Crypto Inventory | 관찰된 암호화 통신 정보 수집 | 제공 |
| Hybrid ML-KEM Inspection | PQC TLS 연결을 복호화·검사하는 기능 | Beta |
| 기존 Zero Trust Policy | 접근 및 보안 정책 적용 | 상용 플랫폼 |

- - Zscaler의 2026년 하반기 제품 업데이트에서는 암호화 가시성과 리포팅은 제공 중이고, PQC TLS 심층 검사는 Beta 단계라고 명시한다.
  - 따라서 PQC 검사 기능을 모든 고객에게 이미 일반 제공된 기능으로 취급해서는 안 된다.

**📌 Elisity와 비교할 때 중요한 점**

- - Zscaler는 TLS 연결에서 어떤 키 교환 알고리즘과 서명 알고리즘을 사용하고 있는지 가시화하는 기능을 강화하고 있다.
  - 이 정보는 기업이 기존 RSA/ECC 기반 암호 시스템을 식별하고 PQC 전환 우선순위를 결정하는 데 활용될 수 있다.
  - 그런데 IonQ와 Elisity가 제시한 미래의 IdentityGraph 확장 역시 암호화 자산과 위험 정보를 통합하는 방향이다.
  - 따라서 **암호화 자산의 가시성 확보 자체도 이미 경쟁이 시작된 시장**이라고 볼 수 있다.
  - 다만 Zscaler의 Crypto Inventory가 곧 Elisity와 동일한 신원 기반 마이크로세그멘테이션 정책 집행을 의미하는 것은 아니다.
  - 실제 비교에서는 탐지한 암호화 상태를 어떤 보안 정책에 연결할 수 있는지 검증해야 한다.

**✅ 11.** **Akamai — Microsegmentation과 PQC를 모두 보유한 경쟁사**

**📌 Guardicore와 Enhanced TLS의 조합**

- - Akamai는 2026년 8월 12일부터 Enhanced TLS 네트워크에서 클라이언트, Akamai 내부, Origin Server 방향의 PQC 적용을 일반 제공한다고 발표했다.
  - 클라이언트에서 Akamai Edge로 이어지는 구간, Akamai 내부 구간, 고객 Origin으로 이어지는 구간에 Hybrid PQC를 적용하는 방식이다.
  - 한편 Akamai는 Guardicore Segmentation을 통해 이미 서버·워크로드 중심의 마이크로세그멘테이션 제품도 보유하고 있다.

|  |  |
| --- | --- |
| **기술 분야** | **Akamai의 보유 기술** |
| Zero Trust | Enterprise Application Access 등 |
| Microsegmentation | Guardicore Segmentation |
| Host-based Security | Guardicore Agent |
| Agentless Network Security | Aruba CX 10000 등 |
| PQC | Enhanced TLS 기반 Hybrid PQC |
| 위협 분석 | Akamai의 애플리케이션·네트워크 보안 제품군 |

**📌 왜 중요한 비교 대상인가?**

- - Akamai는 Elisity와 직접 경쟁하는 Microsegmentation 기술을 보유하고 있다.
  - 동시에 PQC 기반 전송 보호 기술도 상용화했다.
  - 따라서 IonQ가 Elisity를 통해 추진하는 Zero Trust와 PQC의 결합이라는 큰 방향에서 이미 유사한 기술 포트폴리오를 보유한 셈이다.
  - 그러나 Akamai가 Guardicore의 정책 결정에 PQC 암호화 상태를 직접 입력하고, 그 위험도에 따라 장비의 접근 권한을 동적으로 변경한다는 기능까지 확인된 것은 아니다.
  - **두 기술을 하나의 회사가 보유하는 것과 실제 정책 엔진에서 통합하는 것은 서로 다른 문제**다.
  - 이 구분은 IonQ–Elisity의 경쟁력을 평가할 때도 똑같이 적용해야 한다.

**✅ 12. 그렇다면 IonQ–Elisity는 무엇을 더할 수 있을까?**

**📌 2026년 10월 12일 공식 발표의 핵심**

- - IonQ는 Elisity를 최대 13억 달러 규모의 주식 거래로 인수하는 확정 계약을 발표했다.
  - 최대 거래금액에는 성과 조건에 따라 지급될 수 있는 최대 1억 5천만 달러의 Earnout이 포함되어 있다.
  - 거래는 2026년 4분기 종결을 목표로 하고 있으며 필요한 승인과 거래 종결 조건이 남아 있다.
  - 이 발표에서 IonQ가 제시한 핵심 기술 방향은 Elisity의 IdentityGraph에 **Cryptographic Inventory와 Cryptographic Risk 정보를 통합하는 것**이다.
  - 다시 말해 장비의 신원과 기존 보안 상태뿐 아니라 사용하고 있는 암호화 기술의 위험도까지 정책 판단에 활용하려는 구상이다.

**📌 기존 IdentityGraph와 확장된 IdentityGraph**

|  |  |  |
| --- | --- | --- |
| **정보 종류** | **기존 Elisity** | **IonQ와의 통합 구상** |
| 장비 신원 | 지원 | 유지 |
| 네트워크 위치 | 지원 | 유지 |
| 장비 유형 | 지원 | 유지 |
| EDR·CMDB 위험 정보 | 외부 연동 | 유지·확장 |
| 통신 관계 | 지원 | 유지 |
| 암호 알고리즘 목록 | 통합 핵심 기능으로 확인되지 않음 | 추가 계획 |

| PQC 전환 상태 | 통합 핵심 기능으로 확인되지 않음 | 관리 확대 가능 |

| QKD·PQC 통합 정책 | 상용 통합 확인되지 않음 | 향후 구현 가능성 |

- - 여기서 오른쪽 열은 IonQ가 발표한 기술 통합 방향과 이를 통해 발전할 수 있는 기능을 정리한 것이다.
  - 모든 항목이 이미 구현된 상용 기능이라는 뜻은 아니다.

**📌 기존 Zero Trust와 미래의 Crypto-aware Zero Trust**

- - 기존 제로트러스트 정책은 누가 어떤 장비로 어떤 자원에 접근하려 하는지를 확인한다.
  - 여기에 암호화 상태를 통합하면 해당 통신이 조직의 암호화 보안 요구사항을 충족하는지도 접근 정책의 조건으로 활용할 수 있다.

|  |  |
| --- | --- |
| **상황** | **가능한 정책** |
| 승인된 장비 + 승인된 PQC 연결 | 업무상 필요한 통신 허용 |
| 승인된 장비 + 기존 암호 알고리즘 | 위험도에 따라 경고·제한 |
| 중요 서버 + PQC 미지원 | 승인된 보안 게이트웨이를 경유하도록 제한 |
| 미확인 장비 + 암호 상태 불명 | 민감 자원 접근 제한 |
| 감염된 장비 + PQC 지원 | PQC 지원 여부와 관계없이 격리 |
| 레거시 의료장비 + PQC 미지원 | 운영상 필요한 통신을 제한적으로 허용하고 전환 계획 관리 |

- - 이러한 정책은 현재 구현이 확인된 Elisity 기능이 아니라, 암호화 위험 정보를 IdentityGraph와 Policy Engine에 결합했을 때 가능한 미래 시나리오다.
  - 여기서 중요한 것은 모든 PQC 미지원 장비를 무조건 차단하는 방식이 현실적이지 않다는 사실이다.
  - 의료장비, OT, 레거시 서버는 소프트웨어나 암호 라이브러리 업데이트가 어렵거나 지원이 종료되었을 수 있다.
  - 따라서 실제 기업 환경에서는 별도 보안 게이트웨이, 통신 구간 보호, 단계적인 암호 전환, 예외 정책이 함께 필요할 수 있다.

**✅ 14. IonQ가 Elisity 인수로 얻을 수 있는 시너지는 무엇인가?**

**📌 직접적인 시너지는 판매 채널과 정책 집행 기반에서 시작될 수 있다**

- - IonQ가 보유한 PQC·QKD 제품만으로 기존 기업 네트워크의 모든 장비를 식별하고 접근제어 정책까지 관리하기는 어렵다.
  - Elisity는 이미 기업 네트워크에 배포되는 중앙 정책 관리 플랫폼과 스위치 기반 집행 기술을 갖추고 있다.
  - 또한 IonQ 공식 발표에 따르면 Elisity는 100개 이상의 글로벌 고객 배포 사례와 CISO·기업 보안 조직과의 관계를 보유하고 있다.
  - 이는 기술 통합 이전에도 양자보안 제품을 판매할 고객 접점을 확대할 수 있음을 의미한다.

| IdentityGraph | 암호화 자산·위험 관리 | 신원과 암호 위험의 통합 가시성 |

- - 예를 들어 기존 기업이 Cisco ISE와 TrustSec, Palo Alto NGFW를 사용하면서 Fortinet 또는 다른 PQC 제품을 도입할 수 있다.
  - 필요한 경우 별도의 암호 자산 탐지 및 관리 플랫폼을 추가할 수도 있다.
  - QKD 역시 QKD 공급업체와 네트워크 보안 장비 제조사의 협력을 통해 구축할 수 있다.
  - 따라서 IonQ가 모든 구성요소를 직접 보유한다는 사실만으로 기술적인 우위가 자동으로 만들어지지는 않는다.
  - 수직계열화의 가치는 통합 비용을 줄이고, 상호운용성을 높이며, 경쟁사보다 더 뛰어난 운영 성능을 제공할 때 발생한다.

**✅ 15. 그렇다면 최대 13억 달러의 인수금액은 정당할까?**

**📌 좋은 기술을 보유한 기업이라는 것만으로는 부족하다**

- - 이번 인수의 전략적 가치를 평가하기 위해서는 Elisity가 독립기업으로 성장할 때의 가치와 다른 보안 기업이 인수했을 때의 가치, IonQ가 인수했을 때의 추가 가치를 구분해야 한다.
  - Elisity의 기존 마이크로세그멘테이션 기술만을 기준으로 보면 시장에는 이미 강력한 경쟁사들이 존재한다.
  - 기존 스위치 활용, 에이전트리스 방식, 장비 분류, AI 정책 추천 등은 모두 경쟁이 진행 중인 기술이다.
  - 여기에 PQC를 결합하는 전략도 이미 Cloudflare, Fortinet, Palo Alto, Zscaler, Akamai 등이 적극적으로 추진하고 있다.

**📌 인수로 만들어 내야 할 추가 가치**

|  |  |
| --- | --- |
| **가치 구분** | **의미** |
| Elisity 독립 가치 | 기존 고객·매출·제품·성장성 |
| 일반 보안기업 인수 가치 | 판매 채널·제품 통합·기존 고객 확대 |
| IonQ 특유의 추가 가치 | PQC·QKD·암호위험 관리와의 차별적 통합 |
| 최종 검증 지표 | 새로운 매출, 이익, 고객 유지, 개발비 절감, 제품 경쟁력 |

- - IonQ가 다른 보안기업과 비교해 더 높은 인수가치를 정당화하려면 세 번째 영역에서 충분한 추가 가치가 발생해야 한다.
  - 단순한 제품 교차 판매나 일반적인 PQC 지원 기능만으로는 그 차이를 설명하기 어렵다.
  - 또한 모든 기술을 직접 보유하는 방식이 파트너십이나 기술제휴보다 반드시 효율적인 것도 아니다.
  - 따라서 IonQ가 Elisity를 인수해서 얻게 되는 추가적인 매출과 비용 절감, 기술적 차별성이 실제로 어느 정도인지 확인해야 한다.

**✅ 결론 — 진정한 경쟁은 PQC의 보유 여부가 아니라 통합의 깊이에서 결정된다**

- - Elisity는 기존 네트워크 스위치를 이용한 신원 기반 마이크로세그멘테이션 분야에서 경쟁력 있는 기술을 보유하고 있다.
  - 그러나 Agentless, 기존 장비 활용, 자동 정책 생성이라는 특징만으로 시장에서 독보적인 지위를 확보했다고 보기는 어렵다.
  - Zero Networks, Illumio, Akamai, ColorTokens, Cisco 등도 다양한 방식으로 유사한 기능을 제공하기 때문이다.
  - 더 나아가 PQC와 Zero Trust의 결합 역시 더 이상 새로운 아이디어가 아니다.
  - Cloudflare는 PQC 기반 SASE 연결을 상용화했고, Palo Alto와 Fortinet은 지원 네트워크 제품에 양자내성 암호 기능을 추가했다.
  - Zscaler는 PQC 트래픽과 암호화 알고리즘의 가시성을 확대하고 있으며, Akamai도 Guardicore와 PQC 기반 Enhanced TLS를 모두 보유하고 있다.
  - 특히 Fortinet은 외부 QKD 시스템의 키까지 PQC와 결합할 수 있으므로 QKD를 함께 제공한다는 사실만으로 IonQ가 유일한 경쟁력을 갖는다고 주장하기는 어렵다.
  - 그러나 여기서 새로운 가능성이 존재한다.

    - **IonQ가 PQC·QKD를 단순한 암호화 제품으로 공급하는 데 그치지 않고, Elisity의 IdentityGraph와 Policy Engine에 암호화 자산과 위험 정보를 결합해 실제 접근 정책으로 연결한다면 기존 보안 플랫폼과 차별화할 여지가 있다.**
  - 이는 누가 어떤 장비를 이용해 어디에 접근하는가뿐 아니라, 그 통신이 어떤 암호화 보안 수준을 충족하는가까지 판단하는 통합 보안 체계로 발전할 수 있다는 의미다.
  - 하지만 이것이 실제 경쟁우위가 되려면 경쟁사도 구현할 수 있는 단순한 기능 조합을 넘어 성능과 운영 비용, 상용화 수준에서 우수성을 입증해야 한다.
  - 또한 현재 IonQ가 발표한 IdentityGraph의 암호화 위험 정보 통합은 향후 로드맵이지 이미 완성된 상용 기능은 아니다.

    - **결국 Elisity가 가진 기존 경쟁우위와 IonQ가 인수를 통해 새롭게 만들어야 할 경쟁우위는 분리해서 평가해야 한다.**
  - IonQ가 Elisity에 최대 13억 달러를 베팅한 진정한 이유가 단순한 시장 진출을 넘어 차세대 통합 보안 플랫폼의 확보라면, 이제 그 가능성을 실제 제품과 고객 성과로 증명할 차례다.

**✅ 용어 정리 (Glossary)**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **Zero Trust** | 신원·장비 상태·권한 등을 검증해 최소한의 접근만 허용하는 보안 원칙 |
| **Microsegmentation** | 장비·워크로드 간 네트워크 통신을 세밀하게 제한하는 기술 |
| **ZTNA** | Zero Trust Network Access. 승인된 애플리케이션에 대한 접근만 허용하는 기술 |
| **SASE** | Secure Access Service Edge. 네트워크 접속과 클라우드 보안 기능을 결합한 아키텍처 |
| **Agentless** | 보호 대상 단말에 전용 에이전트를 설치하지 않고 접근제어를 구현하는 방식 |
| **PQC** | Post-Quantum Cryptography. 양자컴퓨터 공격에 견디도록 설계된 암호 기술 |
| **QKD** | Quantum Key Distribution. 양자역학적 특성을 이용해 암호키를 분배하는 기술 |
| **ML-KEM** | NIST가 표준화한 양자내성 키 캡슐화 메커니즘 |
| **ML-DSA** | NIST가 표준화한 양자내성 전자서명 알고리즘 |
| **Hybrid Key Exchange** | 기존 공개키 기반 키 교환과 PQC 기반 키 교환을 결합하는 방식 |
| **Crypto Inventory** | 기업 시스템이 사용하는 암호 알고리즘·인증서·키·프로토콜 등의 목록 |
| **Cryptographic Risk** | 사용 중인 암호 기술의 취약성·노후화·양자 위협 등에 따른 위험 |
| **Crypto-Agility** | 암호 알고리즘과 관련 구성요소를 효율적으로 교체·관리할 수 있는 능력 |
| **HNDL** | Harvest Now, Decrypt Later. 현재 암호문을 수집해 향후 복호화하는 공격 전략 |
| **IdentityGraph** | Elisity의 사용자·장비·자산·위험 정보 통합 엔진 |
| **PEP** | Policy Enforcement Point. 접근제어 정책을 실제로 집행하는 지점 |
| **DPU** | Data Processing Unit. 네트워크·스토리지·보안 처리를 가속하는 프로세서 |
| **NEN** | Network Enforcement Node. Illumio의 네트워크 집행 연동 구성요소 |
| **SGT / SGACL** | Cisco TrustSec의 보안 그룹 태그 및 그룹 기반 ACL |
| **JIT MFA** | Just-in-Time Multi-Factor Authentication. 필요한 시점에 추가 인증 후 접근을 허용하는 기술 |
| **TCO** | Total Cost of Ownership. 도입부터 운영·유지보수까지의 총소유비용 |
| **Earnout** | 인수 후 일정 성과 조건을 충족할 때 추가 지급되는 조건부 대가 |
