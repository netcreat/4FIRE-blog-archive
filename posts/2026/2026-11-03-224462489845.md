- - 앞선 개론편에서 “주요 암호 알고리즘을 전자서명·키 전달·데이터 암호화로 구분해 살펴보겠다”고 예고했다. 이번 1편에서는 그 약속대로 각 기술이 어떤 역할을 수행하고 양자컴퓨터에 얼마나 취약한지부터 살펴보겠다.
  - **이번 편의 핵심:** RSA는 키 전송과 서명에 쓰이는 비대칭 암호 계열이고, PQC는 단일 알고리즘이 아니라 키 설정·전자서명용 양자 내성 기술의 집합이다. AES는 대량의 실제 데이터를 보호하는 대칭키 암호이다.

---

**✅ 1. 가장 먼저 구분해야 할 것: 키 설정·인증과 데이터 암호화**

- - **기술을 혼동하면 결론도 잘못된다.**

    - RSA/ECDHE와 ML-KEM은 통신 상대가 공유 비밀을 설정하기 위한 공개키 계열의 기술이고, AES-256은 그 비밀로부터 유도한 대칭키를 이용해 실제 메시지를 암호화하는 기술이다.
  - **한 가지 정확한 구분:**

    - RSA는 과거에 키 전송·암호화·서명에도 활용됐고, ECDSA·ML-DSA는 키를 배포하는 기술이 아니라 디지털 서명 기술이다.
    - 따라서 ‘RSA와 모든 PQC가 키를 공유한다’보다는 ‘키 설정용 공개키 기술과 인증용 서명 기술이 있으며
    - AES는 데이터 암호화에 쓰인다’고 설명하는 것이 정확하다.
  - **이 글의 핵심 질문:** AES-256 자체가 강력하다면, 왜 그 키를 안전하게 전달하고 보호하는 일은 여전히 어려울까?

**📌 암호화와 키 교환은 다른 문제다**

- - 현대적인 인터넷 통신에서는 일반적으로 두 종류의 암호 기술을 함께 사용한다.
  - 첫 번째는 공개키 암호 기술이다.

    - RSA
    - ECDH / ECDHE
    - ECDSA
    - EdDSA
  - 이들 기술은 모두 같은 기능을 수행하는 것은 아니다. RSA는 구성 방식에 따라 암호화, 키 전송, 디지털 서명 등에 활용되고, ECDH는 공유 비밀을 설정하며, ECDSA와 EdDSA는 디지털 서명에 사용된다.
  - 두 번째는 대칭키 암호 기술이다.

    - AES-128
    - AES-256
    - ChaCha20
  - 이들은 실제 데이터를 암호화 및 복호화하는 역할을 담당한다.
  - 예를 들어 웹 브라우저가 은행 서버에 TLS 1.3으로 접속한다고 가정해 보겠다.
  - 일반적인 구조는 다음과 같다.

    - **1단계. 서버 인증**

      - 서버가 자신의 인증서를 제시한다.
      - 클라이언트가 인증서와 서명 등을 검증한다.
      - 서버가 올바른 상대인지 확인한다.
    - **2단계. 키 설정**

      - 클라이언트와 서버가 ECDHE 등을 이용해 공유 비밀을 생성한다.
      - 이 공유 비밀로부터 세션키를 유도한다.
    - **3단계. 데이터 암호화**

      - 생성된 세션키로 AES-GCM 등의 대칭키 암호를 실행한다.
      - 실제 금융정보, 로그인 데이터, 파일 등을 암호화해 전송한다.
  - 단순화하면 다음과 같다.

    - **기존 TLS 통신**
    - ECDHE → 공유 비밀 → KDF → AES 세션키 → 데이터 암호화
  - 중요한 것은 RSA나 ECC가 대용량 데이터를 직접 암호화하는 데 반드시 필요한 것이 아니라는 점이다.
  - 현대적인 TLS 통신에서 실제 데이터 암호화의 핵심은 이미 AES 같은 대칭키 암호이다.
  - 이 구조를 이해해야 양자컴퓨터의 위협이 어디에서 발생하는지 알 수 있다.

**📌 용도·대칭/비대칭·양자 위험을 한눈에 비교하면**

- - 전자서명은 “누가 서명했으며 내용이 변조되지 않았는가”를 확인하고, 키 설정은 “양쪽이 어떻게 같은 비밀을 확보하는가”를 해결한다. 데이터 암호화는 확보한 비밀키로 실제 메시지나 파일을 보호한다.
  - RSA 전체를 하나의 용도로만 분류하면 오해가 생긴다.

    - 예를 들어 RSA-PSS는 전자서명, RSA-OAEP는 작은 비밀값의 암호화·키 전송에 사용한다.
    - ECDH와 ECDSA도 서로 다른 알고리즘이다.
  - PQC 역시 하나의 암호가 아니다.

    - ML-KEM은 공유 비밀 설정,
    - ML-DSA·SLH-DSA는 전자서명을 담당한다.
  - AES-256과 ChaCha20은 일반적인 데이터 암호화에 계속 사용할 수 있다.

- - **주의:**

    - 여기서 “Shor에 취약”은 현재 바로 해독할 수 있다는 뜻이 아니라, 충분한 오류 정정 양자컴퓨터가 등장하면 알려진 효율적인 공격이 있다는 의미이다.
    - 모든 비대칭 방식이 양자 공격에 취약한 것도 아니다. PQC의 알고리즘은 비대칭이지만 양자 내성이 있다.
  - QKD는 비대칭키 암호가 아니며, OTP는 키 교환 기술이 아니다. 둘은 각각 키 분배와 데이터 암호화라는 서로 다른 역할을 수행한다.

**✅ 2. RSA·ECC는 Shor에 취약한데 AES-256은 왜 다를까?**

**📌 RSA와 ECC가 위험한 이유: Shor 알고리즘**

- - RSA의 안전성은 큰 정수를 소인수분해하는 것이 어렵다는 사실에 의존한다.
  - ECC는 타원곡선 이산로그 문제의 계산적 어려움에 의존한다.
  - 기존 컴퓨터에서는 이러한 수학적 문제를 현실적인 시간 안에 해결하기가 매우 어렵다.
  - 하지만 1994년 Peter Shor가 개발한 양자 알고리즘은 소인수분해와 이산로그 문제를 다항시간에 해결할 수 있다는 것을 보여줬다.
  - 즉, RSA와 ECC에는 이미 알려진 효과적인 양자 공격 알고리즘이 존재한다.
  - 문제는 이 알고리즘을 실제로 실행할 수 있는 충분히 강력한 오류 정정 양자컴퓨터가 언제 등장할 것인지이다.
  - 이것은 단순히 기존 컴퓨터보다 100배나 1,000배 빠르다는 이야기가 아니다.
  - **기존 컴퓨터로 해결하기 매우 어려운 수학적 문제를 양자컴퓨터가 근본적으로 다른 계산 복잡도로 해결할 수 있다는 의미이다.**

**📌 대칭키 AES는 상황이 다르다**

- - AES에 대해서는 Shor 알고리즘과 같은 구조적 공격이 알려져 있지 않는다.
  - 대신 **Grover 알고리즘**을 생각할 수 있다.
  - Grover 알고리즘은 구조 없는 무차별 탐색에 필요한 반복 횟수를 대략 제곱근 수준으로 줄인다.
  - 비밀키 길이가 n비트라면, 가능한 키의 개수는 다음과 같다.

    - N=2n
  - 구조적 취약점이 없는 무차별 탐색을 가정하면 다음과 같다.

    - 고전 컴퓨터: O(2n)
    - Grover 양자 알고리즘: O(2n/2)
  - 이를 AES 키 탐색에 적용하면 다음과 같다.

|  |  |  |
| --- | --- | --- |
| **암호** | **고전적 키 탐색** | **이상적인 Grover 공격** |
| AES-128 | 2^128 | 2^64 |
| AES-192 | 2^192 | 2^96 |
| AES-256 | 2^256 | 2^128 |

- - 이론적으로 AES-256의 키 탐색 복잡도는 Grover 알고리즘을 사용하면 2128 수준으로 줄어든다.
  - 그러나 2128이라는 숫자 자체가 엄청나다.

    - 현실성을 무시하고 양자컴퓨터가 초당 10억 번의 완전한 Grover 반복을 수행할 수 있다고 가정하자.

      - 대략 2128 반복 기준으로 AES-256 경우 약 1.08×1022년
  - 게다가 Grover의 반복 한 번은 일반적인 CPU 연산 한 번과 같지 않는다.
  - 양자 회로, 오류 정정, 게이트 실행시간, 안정적인 논리 큐비트, 장시간의 연속 계산이 모두 필요한다.
  - Grover 알고리즘은 대규모 병렬화에 따른 시간 단축에도 제약이 있다.
  - 이 때문에 NIST는 2026년 8월 갱신한 공식 FAQ에서 Grover 알고리즘의 현실적인 효과가 제한적일 수 있으며, 현재 알려진 공격만을 고려하면 **AES-128도 앞으로 수십 년간 안전할 가능성이 높고 AES-192와 AES-256은 더욱 오랫동안 안전할 것으로 평가했다.**
  - 물론 새로운 AES 관련 암호 분석 기법이 발견되지 않는다는 조건이 붙다.
  - **RSA/ECC는 수학적 기반을 효율적으로 해결하는 양자 알고리즘이 이미 존재하지만, AES-256에는 그러한 결정적인 공격이 알려져 있지 않다는 것이 핵심적인 차이다.**
  - **Grover의 2****128****은 ‘초당 수행하는 양자 게이트’가 아니다.** AES-256 키를 찾기 위한 이상적인 검색 반복 횟수의 규모이며, 실제 한 번의 반복마다 복잡한 가역 AES 회로와 오류 정정이 필요한다.
  - **양자컴퓨터 100만 대를 병렬로 동원해도 100만 배 빨라지는 구조는 아니다.** 일반적인 독립 분할 Grover 탐색에서 P개 장치가 주는 이상적인 실행시간 단축은 대략 √P배이다. 따라서 100만 대를 써도 단축은 약 1,000배 수준이며, 오버헤드를 무시한 계산에서도 2128을 약 2118 규모로 낮추는 정도이다.
  - **NIST의 판단:** Grover의 완전한 제곱근 가속은 계산을 길게 직렬로 수행해야 하며, 실제 병렬 연산과 하드웨어 비용까지 고려하면 AES-192·256은 매우 오랫동안 안전할 가능성이 높다.
  - **단, “절대로 깨지지 않는다”는 뜻은 아니다.** 컴퓨팅 자원과 시간이 물리적으로 무제한이라면 키 탐색이 원리적으로 가능하며, 미래에 AES 자체의 새로운 수학적 취약점이 발견될 가능성도 논리적으로 배제할 수 없다. 그러나 현재의 현실적인 공격 난이도가 극히 높다는 주장은 충분히 뒷받침된다.

**✅ 3. 그렇다면 왜 PQC가 필요하며, 미래에도 안전할까?**

- - **바로 이 지점에서 PQC가 등장한다.** USB로 비밀키를 직접 운반하는 방식은 대규모 인터넷에 확장하기 어렵고, QKD는 특수 광학 장비와 회선이 필요한다. 반면 ML-KEM 같은 PQC는 기존의 일반적인 디지털 네트워크에서 소프트웨어와 표준 프로토콜로 대량의 통신 세션을 설정할 수 있다.
  - **PQC의 실용적인 장점은 “완벽한 수학적 불멸성”이 아니다.** 기존 공개키 키 설정이 제공하던 배포 편의와 규모의 경제를 유지하면서, 현재 알려진 Shor 공격에 대응할 수 있다는 점이다.
  - **선택의 원리는 분명한다.** 가능한 경우 안전한 사전 공유키·전용 QKD가 유용할 수 있지만, 대부분의 인터넷 서비스에서 비용과 상호운용성을 고려하면 PQC 기반 키 설정이 현실적인 기본 해법이 된다.

**📌 PQC는 Quantum-Proof가 아니라** **Quantum-Resistant****다**

- - PQC는 현재 알려진 고전 및 양자 공격에 대해 안전하도록 설계된 암호 기술이다.
  - 대표적인 알고리즘은 다음과 같다.

|  |  |  |
| --- | --- | --- |
| **알고리즘** | **수학적 기반** | **용도** |
| ML-KEM | 격자 기반 MLWE | 키 설정 |
| ML-DSA | 격자 기반 | 디지털 서명 |
| SLH-DSA | 해시 기반 | 디지털 서명 |
| HQC | 코드 기반 | 추가 키 설정 표준화 대상으로 선정 |

- - ML-KEM은 Module Learning With Errors라는 수학적 문제에 기반한다.
  - 이 문제는 작은 오류가 포함된 선형대수 문제를 해결해야 하는 구조이다.
  - 현재 알려진 Shor 알고리즘은 MLWE 문제를 RSA의 소인수분해처럼 효율적으로 해결하지 못한다.
  - 따라서 양자컴퓨터가 1만 논리 큐비트에서 100만, 1억 논리 큐비트로 발전한다고 해서 ML-KEM이 자동으로 깨지는 것은 아니다.
  - 그러나 새로운 수학적 발견이 나타난다면 이야기는 달라진다.
  - 예를 들어 미래에 MLWE를 효율적으로 해결하는 새로운 양자 알고리즘이 발견됐다고 가정해 보겠다.
  - 이 경우 기존에 안전하다고 생각했던 ML-KEM의 공격 복잡도가 급격히 낮아질 수 있다.

    - 2026년 7월 실제로 발생한 사례: HAWK

      - 2026년 7월 28일 Anthropic 연구진은 AI를 활용한 암호 분석으로 PQC 후보 디지털 서명 알고리즘 HAWK에 대한 개선된 공격을 발표했다.
      - HAWK-512에 대한 추정 키 복구 공격 비용을 기존 2150에서 2108 수준으로 낮췄으며, 개발팀은 NIST 표준화 후보에서 HAWK를 철회했다.
      - 이는 양자컴퓨터가 아닌 고전적인 암호 분석의 진전이다. NIST는 이 결과가 이미 표준화된 ML-KEM 및 ML-DSA에는 영향을 미치지 않는다고 밝혔다.
      - 이 사례가 흥미로운 이유는 미래의 암호학적 위험이 양자컴퓨터의 하드웨어 발전뿐만 아니라 AI를 이용한 수학 연구에서도 발생할 수 있다는 점을 보여주기 때문이다.
  - 그렇다면 두 가지 대응이 가능한다.

    - 공격이 점진적으로 개선된 경우: 더 높은 보안 파라미터로 전환한다.
    - 수학적 기반 자체가 취약해진 경우: 다른 수학적 기반을 사용하는 암호로 교체한다.
  - 실제로 NIST는 2025년 **HQC**를 ML-KEM의 대안이 될 추가 키 설정 알고리즘으로 선정했다.
  - HQC는 격자 문제가 아니라 코드 기반 수학을 사용한다.
  - 이는 ML-KEM이 이미 취약하다는 뜻이 아니라, 특정 수학적 계열 전체에 문제가 발생할 가능성에 대비하는 것이다.

**📌 결국 미래에는 PQC도 다시 교체해야 할까?**

- - 그럴 수도 있다.
  - 암호화 기술은 원래 지속적으로 변화해 왔다.

    - DES → 3DES → AES
    - SHA-1 → SHA-2 / SHA-3
    - RSA/ECC → PQC
    - 미래에는 PQC Generation 1 → 새로운 PQC Generation 2
  - 그러나 교체해야 할 가능성과 반드시 무너진다는 것은 전혀 다르다.
  - 이 때문에 NIST는 특정 알고리즘의 도입만이 아니라 **Crypto Agility**, 즉 암호 민첩성을 강조하고 있다.
  - Crypto Agility는 기존 암호의 안전성이 약화되거나 새로운 표준이 등장했을 때 보안과 서비스 운영을 유지하면서 암호 알고리즘을 교체하고 조정할 수 있는 능력을 의미한다.
  - **PQC가 언젠가 깨질 것이라는 주장도 아직은 가설이다.** RSA·ECC에는 1994년부터 Shor라는 효율적인 양자 알고리즘이 알려져 있다. 반면 ML-KEM을 똑같이 무너뜨리는 범용적이고 효율적인 양자 알고리즘은 현재 알려져 있지 않는다.
  - **새로운 ‘****양자판 Shor****’가 반드시 등장한다는 법칙은 없다.** 미래에 격자 기반 암호에 대한 혁신적인 공격이 발견될 수도 있고, 오랜 기간 발견되지 않을 수도 있다. 따라서 “PQC도 언젠가 반드시 깨진다”와 “PQC는 영원히 안전하다”는 양쪽 모두 근거 없는 단정이다.
  - **새로운 공격이 발견되더라도 즉시 모든 PQC가 무너지는 것은 아니다.** 해당 공격이 어떤 수학적 계열과 파라미터에 통하는지, 실제 공격 자원이 얼마인지에 따라 영향이 달라진다. 이러한 불확실성에 대응하기 위해 알고리즘 다양성과 Crypto Agility가 필요한다.

**📌 전자서명까지 PQC로 전환해야 하는 이유**

- - TLS에서는 서버가 진짜 은행 서버인지 확인하기 위한 인증서와 디지털 서명도 사용한다. 키 교환만 ML-KEM으로 전환하고 인증서 서명에 RSA·ECDSA를 계속 쓰면, 장기적인 양자 인증 위험이 남다.
  - 따라서 장기적인 PQC 전환은 키 설정(ML-KEM)뿐 아니라 전자서명(ML-DSA·SLH-DSA), 인증서와 소프트웨어 업데이트 검증 체계까지 포함한다.
  - 반대로 AES-256은 현재 알려진 양자 공격 때문에 무조건 교체해야 하는 대상이 아니다. 이는 키 설정, 전자서명, 데이터 암호화라는 세 역할을 구분해야 하는 이유이다.
