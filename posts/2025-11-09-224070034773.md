**✅Quantum Routing Protocol (QRP)**

**💡개론**

- - Quantum Routing Protocol(QRP)은 엔드투엔드 양자얽힘(E2E Entanglement)을 네트워크 전역에서 생성·유지·복구·관리하기 위한 **네트워크 계층 프로토콜**이다.
  - 고전 인터넷이 데이터 패킷(payload)을 전달한다면, 양자 인터넷은 상관관계(entanglement)를 전달한다.
  - 즉 QRP는:

    - 어떤 노드들이 얽힘을 공유하는지 파악하고
    - EPR 링크를 생성하고
    - 중간 노드에서 스와핑을 실행하며
    - decoherence 또는 링크 실패 발생 시 대체 경로로 재라우팅하고
    - 사용 후 리소스를 즉시 해제한다.

**💡표준**

- - RFC표준이 여러개 있지만, 아키텍처·용어·유스케이스’ 표준이지, ‘프로토콜 표준’이 아니다.

    - “양자 인터넷이 어떤 개념인가?”
    - “기본 용어는 무엇인가?”
    - “어떤 상황에서 사용할 수 있는가?”
    - “네트워크가 어떤 계층으로 구성되는가?”
  - RFC 9340 — Quantum Internet Architecture

    - 양자 인터넷의 목표
    - 계층 모델 (QLL, QNL, QTL)
    - classical plane + quantum plane 공존
    - general requirements (요구사항)
  - RFC 9450 — Quantum Internet Terminology

    - qubit, entanglement, swapping, fidelity 등 용어 정의
    - quantum vs classical channel 설명
  - RFC 9484 — Use Cases

    - QKD
    - distributed sensing
    - blind quantum computation
    - quantum position verification
  - 실제 동작 프로토콜은 아직 "표준"이 아닌 업체별 구현 단계임 - 사실상의 업계 표준

    - **Cisco (Quantum Networking Software)**

      - QuTech 논문 기반
      - 자체적인 control-message schema 사용
      - “Qnets controller” prototype에서 비슷한 필드 구조 등장
    - **Aliro (AliroNet Controller)**

      - **개요**

        - MIT 출신들이 만든 **양자 네트워크 소프트웨어 기업**
        - (“Cisco of Quantum SDN”이라고 부르는 사람도 많음)
        - **QRP-like 메시지 구조를 최초로 상용 API로 정의해 배포한 회사**
      - AliroNet Controller ↔ Quantum Node 간
      - REST/gRPC 기반 QRP-like message
      - Message-type, Slot-ID, Session-ID 구조 사용
    - **QuTech (network control plane prototypes)**

      - **개요**

        - 네덜란드의 **세계 최고 양자 네트워크 연구 기관**
        - (양자 인터넷 분야에서는 사실상 세계 1위)
        - **현재 QRP 구조의 50% 이상이 QuTech 논문에서 직접 나온 개념임.**
      - BSM-COMMAND
      - Memory-slot assignment
      - Fidelity reports
      - Entanglement-ID
      - 실험 논문마다 구조가 거의 동일함
    - **Qunnect (RELAY controller protocol)**

      - **개요**

        - MIT, Stony Brook 출신들이 만든 **양자 네트워크 하드웨어 제조사**
        - 미국 최초 상업 양자 네트워크(EPB Chattanooga)의 **물리 장비 거의 전부가 Qunnect 제품**.
        - 이들이 만든 classical control API/메시지 구조가 상당히 표준 후보처럼 취급됨
      - Controller ↔ repeater 간 classical messaging
      - Slot allocation, timestamp sync, BSM result 구조 동일
    - **EPB-Quibitekk**

      - Entanglement scheduling controller
      - 보고된 구조가 거의 동일

**💡QRP Internal Data Structures**

- - **Entanglement Map (EMAP)**

    - 각 노드 간 “얽힘 상태”의 가중치 테이블
    - 필드:

      - 링크 피델리티 F
      - EPR generation success probability p
      - BSM success probability qs
      - decoherence deadline
      - memory pool usage
    - 즉, 고전 라우팅에서의 링크-상태 테이블(LSDB)에 해당.

**💡QRP Operation (전체 절차)**

1. 1. **Route Discovery (경로 탐색)**

      - QRP는 **entanglement route**를 아래 기준으로 탐색한다.

        - **최대 피델리티 경로 (max-Fidelity path)**
        - **최소 decoherence risk**
        - **최대 end-to-end success probability**
        - **최소 classical round-trip 지연**
      - 패킷 종류:

        - **QRP-REQ** : 경로 요청
        - **QRP-REP** : 후보 경로 응답
        - **QRP-METRIC** : 링크 품질 정보 전파(OSPF LSUPD 유사)
      - 알고리즘 기반:

        - Pant et al., “Routing Entanglement in the Quantum Internet”
        - Cisco Research: Rate/Fidelity 최적경로 최적화
   2. **Entanglement Establishment (얽힘 확립)**

      - 각 링크는 **Elementary Link Protocol(ELP)** 수행:

        1. Photon pair emission (광자 쌍 방출)
        2. 전송 후 **heralding signal(HER)** 수신
        3. 성공한 Bell pair만 메모리 슬롯에 기록
        4. 실패한 슬롯은 즉시 재시도
      - 관련 프로토콜:

        - Dahlberg, “A Link Layer Protocol for Quantum Networks (SIGCOMM)”
   3. **Entanglement Swapping (스와핑)**

      - 중간 노드에서:

        - QRP는 CorrectionCode를 고전 제어 채널로 다음 노드로 전달함.
      - 필드:

        - **Swap-ID**
        - **CorrectionCode (X, Z 플래그)**
        - **Timestamp (decoherence check 용)**
   4. **End-to-End Entanglement Confirmation**

      - 모든 스와핑이 성공하면:

        - **QRP-CONFIRM** 패킷을 엔드노드로 송신
        - 앨리스와 밥은 최종 Pauli 프레임을 업데이트하여 Bell pair를 정합시키고 사용 가능한 상태로 만듦
   5. **Fidelity Monitoring & Error Recovery**

      - - QRP는 링크 수준 및 end-to-end fidelity를 지속적으로 추적한다.
        - 기준:

          - F < F\_min (ex: 0.85)
          - → **EPP(정제)** 또는 **재생성(re-generate)** 실행
        - 재라우팅 조건:

          - 링크 장시간 실패
          - decoherence 타이머 초과
          - 노드 장애
        - 재라우팅 방식:

          - classical routing의 SPF 재계산과 동일
          - (단, 피델리티·메모리·스와핑 비용 포함한 quantum metric 사용)
   6. **Resource Release (소멸)**

      - 사용이 끝난 EPR pair는:

        - 상태를 “free”로 비움
        - 메모리 풀에 반환
        - EMAP 업데이트
        - 필요하면 정제 leftover pair도 삭제

**💡QRP Supporting Protocol Suite**

- - 고전 IP가 ICMP/TCP/ARP 등 보조 프로토콜을 가진 것처럼, 양자 네트워크는 아래 보조 계층을 가진다.

|  |  |
| --- | --- |
| **Protocol** | **역할** |
| **EDP** (Entanglement Distribution Protocol) | 전송 계층 – 연속 생성, 재시도 기법 |
| **EPP** (Purification) | 피델리티 개선 |
| **QP (Quantum Ping)** | Bell pair living check |
| **QCMP (Quantum Control Message Protocol)** | Control-plane: metric, states 공유 |
| **QEC Layer** | 오류 정정 지원 (서페이스 코드 등) |

- - 이 구조는

    - RFC 9340
    - QuTech’s Quantum Network Stack
    - DARPA ONIS/INQNET 모델을 기반으로 한다.

**💡QRP vs Classical Routing**

|  |  |  |
| --- | --- | --- |
| **항목** | **고전 인터넷** | **양자 네트워크(QRP)** |
| 전송 단위 | Packet | Entanglement |
| 복제 | 가능 | 복제 불가 → 스와핑 |
| 오류 | ARQ 재전송 | 재생성 + Purification |
| 떨림 대응 | 버퍼 재전송 | decoherence 타이머 기반 |
| 경로 실패 | 재라우팅 | 경로 재탐색 + Bell pair 폐기 |
| 성능 기준 | 대역폭/지연 | fidelity/스와핑 성공률/decoherence |

**✅양자컴퓨터와 고전컴퓨터**

**💡양자네트워크에 패킷이?**

- - **QRP 헤더가 존재하는 이유는, “양자 정보(얽힘)”를 이동시키기 위한 것이 아니라**
  - **그 양자 정보를** ***관리하고 제어하기 위해 필요한 고전(클래식) 제어 메시지*** **때문이다.**
  - 즉:

    - ❗ **양자 라우팅 = 광자나 큐비트가 패킷처럼 전송되는 것이 아님**
    - ✅ **하지만 라우팅 과정 전체를 제어하기 위한 고전 패킷은 반드시 필요함**
  - 그래서 QRP 헤더는
  - 양자 패킷의 헤더가 아니라, “고전 제어 패킷의 헤더”라고 이해하는 것이 맞다.

**💡왜 “패킷”이 필요한가? (Quantum-classical Hybrid Networks)**

- - 양자 네트워크는 사실상 **두 네트워크가 결합된 형태**로 동작한다.
  - **1) Quantum channel (광자 전송)**

    - 편광/위상/주파수로 큐비트를 보냄
    - 얽힘 생성 → 스와핑
    - 복제 불가(no-cloning) → 데이터 패킷 존재하지 않음
    - 헤더/주소/길이 등 존재할 수 없음 (측정하면 상태 파괴)
  - **2) Classical channel (전통 네트워크)**

    - 양자 네트워크의 모든 제어는 결국 고전 패킷으로 이루어진다.
    - 필요한 이유:

      - 스와핑 결과 전달(BSM result: X/Z correction)
      - 얽힘 성공 여부 전송(heralding signal)
      - 라우팅테이블 업데이트
      - 피델리티 보고
      - 재라우팅 알림
      - 엔드투엔드 준비 확인(confirm)
  - **얽힘 = 양자 채널에서 생성**
  - **얽힘을 “어떻게, 언제, 어디로” 만들지는 classical channel에서 패킷으로 조정**

> **여기서 또 고전 컴퓨텅이 필요해?**

**💡왜 양자 라우팅에 classical header가 반드시 필요한가?**

- - **이유 1) 양자 상태는 읽으면 붕괴됨**

    - → 주소/길이/타입 같은 헤더를 양자 상태에 붙일 수 없음.
  - **이유 2) BSM 측정 결과는 고전 정보**

    - → 다음 단계 스와핑을 위해 반드시 classical 패킷으로 전달해야 함.
  - **이유 3) 노드 간 협력이 classical channel 위에서 이루어짐**

    - → 경로 선택 / 리소스 조정 / 정제 여부는 “통신 프로토콜” 필요.
  - **이유 4) 얽힘은 “분배되는 자원”일 뿐**

    - → 그 자원을 연결하고 유지하기 위한 “상태 관리 메시지”가 필요함.

> **양자 라우팅은 양자 정보가 ‘전송’되는 게 아니라, ‘생성 조건을 조율’하는 것.**
>
> 이 조율 과정이 전부 고전 패킷을 필요로 한다.

**💡그러면 QRP 헤더는 어디에 쓰이는 메시지인가?**

- - **QRP 헤더는 아래 “고전 메시지”에서 사용된다:**

    - 경로 요청(Route Request)
    - 경로 응답(Route Reply)
    - 얽힘 성공 알림(HER)
    - 스와핑 결과(BSM code)
    - 피델리티 정보(Fidelity Tag)
    - 재라우팅 요청(Re-route)
    - 엔드투엔드 완료 메시지(Confirm)
    - 정제 요청(EPP Request)
  - 즉, 이 모든 정보는 **네트워크 장비(중계 노드)** 사이에서 **일반 TCP/UDP/IP 패킷처럼 고전 통신망으로 전달됨.**

**💡Quantum 네트워크 도메인에 존재하는 장비 (얽힘 물리처리)**

- - 이들은 **얽힘 생성, BSM, 광자 처리** 같은 물리 연산을 수행하는 장비들이다.
  - **Beam splitter (빔 스플리터)**

    - 광자를 50:50으로 분리
    - 얽힘 생성, 간섭 검출 용
    - 데이터 플레인(DP)의 물리적 부품
  - **SNSPD (초전도 나노와이어 단일광자 검출기)**

    - 스와핑/측정 시 단일광자 검출 담당
  - **BSM 모듈 (Bell-State Measurement Module)**

    - 스와핑의 핵심 장치
    - beam splitter + 위상 보정 + single-photon detector
  - **QFC (Quantum Frequency Converter)**

    - 서로 다른 파장 장비들을 연결할 때 사용
  - **Quantum Memory (rare-earth, ion trap, NV센터 등)**

    - 완성된 Bell pair를 임시 저장하는 역할

**💡고전 네트워크 도메인에서 QRP를 송수신하는 장비**

- - **하이브리드 - 광학 관련 부품 + 고전 CPU/FPGA**

    - **Quantum Repeater (양자 중계기)**
    - **Quantum Router (양자 라우터)**
    - **양자 리피터/라우터의 내부 구조**

      - **Classical Control Hardware**

        - ARM/통상 CPU + NIC
        - FPGA/SoC 기반 **real-time control logic**
        - Classical network interface (Ethernet, TCP/IP)
        - → QRP 메시지 송수신, 라우팅 테이블 유지, 스케줄링
      - **Quantum Hardware**

        - Photon-pair source (SPDC, QD single-photon, trapped-ion photonic link)
        - BSM module
        - Quantum memory
        - Phase/polarization stabilizers
        - Fiber interface (DWDM 기반)
  - **순수 고전 컴퓨팅 컴포넌트**

    - **Quantum Node ControllerOrchestrator**
  - 이 장비들이 바로 **QRP 메시지를 직접 송수신하고 라우팅 결정을 내리는 '네트워크 장비' 역할**을 맡는다.

- - **한편, ELP와 EDP는 Controller가 개입되지 않는다.**

    - **ELP (Elementary Link Protocol)**

      - **역할: 바로 옆 노드와 얽힘을 만드는 로우레벨 프로토콜**
      - 광자 송출
      - 검출기 신호(herald)
      - 단일 링크에서 얽힘 성공/실패 보고
      - decoherence 측정 일부
      - 단순 슬롯 사용
      - BSM 이전 단계
      - 📌 비유: “Ethernet + MAC level control”
    - **EDP (Entanglement Distribution Protocol)**

      - **역할: 엔드투엔드 터널 품질을 보장하는 Transport 계층**
      - 얽힘의 순번 관리
      - 피델리티 체크
      - Purification 요청
      - 재시도/재생성
      - 순서 보장
      - 목표 품질 이상이 될 때까지 관리
      - 즉, “TCP-like”이다.
      - 📌 비유: “TCP + ARQ + QoS transport”

**💡양자 리피터 vs 양자 라우터**

|  |  |  |
| --- | --- | --- |
| **구성 요소** | **Quantum Repeater** | **Quantum Router** |
| Photon Source | ✅ | ✅ (있을 수도 있음) |
| BSM Module | ✅ | ✅ |
| Quantum Memory | ✅ | ✅ |
| Classical Processor | ⚪ 최소 수준 (기본 제어) | ✅ 고급 CPU/FPGA |
| 라우팅 테이블 | ❌ 없음 | ✅ 있음 |
| QRP 실행 | ❌ 불가능 | ✅ 가능 |
| 링크 상태 수집 | ⚪ 일부만 | ✅ 전체 네트워크 |
| 스케줄링 | 매우 제한적 | 매우 고급 |

- - **Quantum Repeater**

    - 링크 중간 중간에 배치됨
    - 광자 손실·거리 제한 극복
    - 20~100km 간격으로 설치
    - 거의 모든 양자 네트워크에서 필수
    - 구현 난이도 : 높음
    - 필요 기술 : 광학, BSM, 메모리
    - 현재 실험 수준 : 다수 실험 성공
    - 예시

      - QuTech NV-Center Repeater
      - Qunnect "RELAY" Device
      - Tianjin’s cold-atom repeater experiments
      - ORNL–Qubitekk repeater nodes
  - **Quantum Router**

    - 네트워크 중심/거점에 배치됨
    - 여러 라우팅 선택지가 있는 곳
    - 경로 최적화 필요할 때만 존재
    - Cisco, Aliro, QuTech가 개발 중
    - 구현 난이도 : 매우 높음
    - 필요 기술 : 광학, BSM, 메모리 + 분산 시스템, Routing, Control, SDN
    - 현재 실험 수준 : 아직 초기 연구 단계
    - 예시

      - Cisco Quantum Router Prototype (control software 중심)
      - AliroNet Q-Router (가상 라우팅 레이어)
      - QuTech 의 “Network Node with full routing logic” 연구

> 따라서 모든 양자 네트워크에 리피터는 반드시 필요,
>
> 하지만 라우터는 고급/대규모 네트워크에서만 필요.

**💡고전 라우팅 프로토콜 vs 양자 라우팅 프로토콜**

|  |  |  |
| --- | --- | --- |
| **항목** | **Classical Internet** | **Quantum Internet** |
| 라우팅 구조 | 완전 분산(P2P) | 완전 중앙집중(Controller) |
| 패킷 교환 | Router ↔ Router | Controller ↔ Node |
| 자원 특성 | 비확률적, 안정적 | 확률적, 소멸성 |
| 최적화 필요 | 낮음 | 매우 높음 |
| 동기화 필요 | ms | ps |
| 라우팅 알고리즘 | OSPF/BGP | QRP (Controller-driven) |

**✅Quantum Controller ↔ Device 간 QRP 패킷 구조**

- - 여기서 말하는 QRP 패킷은 양자 데이터 패킷이 아니라 “클래식 제어 메시지 패킷”이다.
  - 즉, 이건 양자 상태(광자)에 붙는 게 아니라 Ethernet → IP → TCP → QRP 헤더 구조로 간다.

**💡QRP 헤더 구조 (Draft)**

*(RFC 스타일 참고하여 구성한 설계안)*

|  |  |  |
| --- | --- | --- |
| **필드** | **길이** | **기능** |
| Version | 4bit | QRP 버전 |
| MsgType | 8bit | REQ, REP, HER, SWAP, CONFIRM 등 |
| Path-ID | 16bit | 엔탱글 경로 식별자 |
| Node-ID | 16bit | 송신자 노드 |
| FidelityTag | 8bit | 피델리티 점수 |
| QMem-Index | 16bit | 메모리 슬롯 번호 |
| CorrectionCode | 4bit | X/Z Pauli frame |
| Timestamp | 32bit | decoherence 체크 |
| Flags | 8bit | Purge, Retry, Swap 등 |

**💡QRP Payload 구조**

- - Payload는 Message-Type에 따라 내용이 다름.
  - 예:

    - BSM-Result 메시지 → X/Z correction bits 포함
    - Fidelity-Report 메시지 → 0.91 같은 수치 포함

**💡Quantum Controller ↔ Node 메시지 흐름 예시**

A → B로 얽힘 생성한다고 가정

1. 1. **Controller → R1**

      - QRP(MEM-ALLOC, slot=3)
   2. **Controller → R2**

      - QRP(MEM-ALLOC, slot=5)
   3. **R1 → Controller**

      - QRP(ENTANGLE-ACK, success=1)
   4. **R2 → Controller**

      - QRP(ENTANGLE-ACK, success=1)
   5. **Controller → R1**

      - QRP(BSM-COMMAND, timestamp=17ps)
   6. **R1 → Controller**

      - QRP(BSM-RESULT, X=1, Z=0)
   7. **Controller → B**

      - QRP(CORRECTION-CODE)
