**🔁기본 개념 정리**

양자 오류 정정(QEC, Quantum Error Correction)은 양자 컴퓨터에서 발생하는 오류를 감지하고 정정하는 기술로, 양자 컴퓨터의 신뢰성을 높이는 데 핵심적인 역할을 한다. 이를 이해하기 위해 반드시 필요한 요소의 기본적인 정의는 반드시 알고 넘어가야 한다.

**🧱 물리 큐비트와 논리 큐비트**

- **물리 큐비트**: 양자 정보를 실제로 저장하는 기본 단위지만, 외부 환경이나 노이즈 때문에 쉽게 오류가 발생.
- **논리 큐비트**: 여러 개의 물리 큐비트를 묶어서 만든 가상의 큐비트. 물리 큐비트에 오류가 발생하더라도 이를 감지하고 정정할 수 있도록 설계되어 안정적인 양자 정보를 유지한다.

****

**🔐인코딩 (Encoding)**

- 물리 큐비트를 논리 큐비트로 변환하는 과정으로, 스태빌라이저 조건을 만족하도록 초기 상태를 설정
- 인코딩은 시스템이 초기화될 때, 즉 논리 큐비트의 상태를 처음 준비하는 단계에서 수행됨.

****

**⚙️스태빌라이저 (Stabilizer)**

- **스태빌라이저**는 논리 큐비트의 상태를 보호하고 오류를 감지하기 위해 사용하는 연산자.
- 특정 패턴의 연산을 통해 "정상 상태"인지 확인한다.
- 스태빌라이저가 측정되었을 때 결과가 **+1**이면 정상이고, **-1**이면 오류가 발생했다는 신호이다.

  - 스태빌라이저는 특정 연산자의 고유값 +1을 가지는 상태만을 코드 공간으로 정의하며, 이는 정상 상태임을 의미한다.
  - 오류가 발생하면 상태가 스태빌라이저 연산자의 -1 고유값을 갖는 상태로 벗어나게 되므로, **측정값이 -1이라는 것은 시스템이 오류 상태로 이동했음을 의미한다.**

****

**🧪 안실라 큐비트 (Ancilla Qubit)**

- 안실라 큐비트는 오류를 감지하기 위해 추가로 사용하는 보조 큐비트이다.
- 이들은 스태빌라이저 연산을 측정하는 데 사용되며, 측정 결과를 통해 오류의 존재와 위치를 파악할 수 있다.

****

**🧮디코더 (Decoder)**

- - 디코더는 안실라 큐비트의 측정 결과를 분석해서 어떤 물리 큐비트에 오류가 발생했는지 추론하고, 이를 정정하는 역할 수행
  - 마치 퍼즐을 풀듯이 오류 패턴을 해석한다.

****

**🩺증후군(Syndrome)**

- - 스태빌라이저 측정 결과로 얻어지는 데이터로, 오류의 존재와 위치를 나타냄.
  - 디코더가 증후군을 분석해 어떤 큐비트에 어떤 오류(X, Z, Y)가 발생했는지 추론.
  - 증후군은 디코더가 오류를 정정하는 데 필요한 "증상" 역할을 하며, QEC의 동작에서 핵심적인 중간 단계.

    - 의사가 환자의 병을 고치려면 먼저 증상부터 파악하는 원리

****

**🔧논리 연산자(Logical Operators)**

- - 논리 큐비트에 대해 양자 연산을 수행하는 연산자.
  - QEC 코드가 단순히 오류 정정뿐 아니라 양자 계산을 가능하게 하려면 논리 연산이 필요.
  - 논리 연산자는 QEC 코드가 실제 양자 컴퓨터에서 계산을 수행할 수 있도록 만듦.

****

**🌐오류 모델(Error Model)**

- - QEC 코드가 다루는 오류의 종류와 확률 분포(예: 비트 플립, 위상 플립, 탈일관성 오류 등).
  - 디코더는 특정 오류 모델을 가정하고 증후군 데이터를 분석하므로, 오류 모델은 코드와 디코더 설계에 영향을 미침.
  - 오류 모델은 디코더의 효율성과 QEC 코드의 성능(예: 오류 임계값)을 결정.

****

**📉오류 임계값(Error Threshold)**

- - QEC 코드가 오류를 성공적으로 정정할 수 있는 최대 오류 확률.
  - 오류 임계값이 높을수록 코드가 더 많은 오류를 견딜 수 있음.
  - 오류 임계값은 QEC 코드의 실용성을 평가하는 기준.

****

**🧾패리티 검사 행렬(Parity-Check Matrix)**

- 스태빌라이저를 수학적으로 표현하는 행렬로, 오류 감지의 구조를 정의.
- QEC 코드의 스태빌라이저를 명시적으로 나타내며, 디코더가 증후군을 분석하는 데 사용.
- 패리티 검사 행렬은 QEC 코드의 설계와 디코딩의 기초.

**🧩QEC Code - 양자 정보를 오류로부터 보호하기 위한 체계적인 프레임워크**

- **QEC 코드가 정의하는 것**

  - **스태빌라이저** - QEC 코드의 핵심으로, 오류를 감지하기 위한 연산자 집합
  - **논리 큐비트** - 물리 큐비트를 어떻게 논리 큐비트로 매핑할지 정의한다. 이는 코드의 인코딩 구조를 포함함.
  - **패리티 검사 구조** - 코드의 오류 감지 방식을 설정한다.
  - **논리연산** - 논리 큐비트에 대한 양자 게이트를 정의
- **QEC 코드가 직접 정의하지 않지만, 서로 호환될 수 있도록 설계하게 됨.**

  - **인코딩 과정의 세부 구현** - 물리 큐비트를 초기화하고 논리 상태로 변환하는 구체적인 회로는 하드웨어와 구현 방식에 따라 달라짐
  - **디코더 알고리즘** - QEC 코드는 신드롬 (Syndrome) 데이터를 생성하지만, 이를 분석해서 오류를 정정하는 디코더의 구체적인 알고리즘은 별도로 설계됨.

    - **MWPM - 서피스 코드**와 조화
    - **BP (BP,BP-OSD) - qLDPC**와 조화
    - **Lookup Table - Shor 코드**와 조화
  - **안실라 큐비트의 물리적 구현** - 안실라 큐비트는 스태빌라이저 측정을 위해 필요하지만, 그 물리적 배치나 측정 회로는 QEC 코드가 아니라 시스템설계자가 결정한다.

**위 그림은 Surface 코드를 이용해 시간이 흐르면서 발생하는 오류를 감지하는 과정을 나타낸다.** 시간은 아래에서 위로 흐르며, 각 수평 평면은 하나의 스태빌라이저 측정 단계를 의미한다.

수직의 굵은 빨간색(회색) 선은 **측정 결과가 변화한 시점들**을 연결하며, 이 선들의 **공간적 연결**은

- - X: 비트 플립 에러
  - Z: 위상 플립 에러
  - Y=ZX: X 및 X 연산이 동시에 적용된 상태로, 인접한 X 스태빌라이저와 Z 스태빌라이저 모두에서 -1이 나오는 증후군 패턴을 남긴다
- **논리 연산자 (Logical Operators)**

  - 아래 9 × 9 Surface 코드 격자는 좌우에 X 경계, 상하에 Z 경계를 둔 정사각형 형태의 2차원 데이터 큐비트 배열을 나타낸다.
  - 논리 거리 d=5의 의미는 오류를 일으키지 않고 통과하려면 최소 5개의 큐비트를 거쳐야 하는 길이다.

    - 거리 d일 경우
    - 전체 큐비트 수 =(*2d-1*)2
    - 데이터 큐비트 수= *2d**2**-2d+1*
    - 스태빌라이저 큐비트 수=*2d*(*d-1*)
  - 이 배열은 d가 5이므로

    - **한 개의 논리 큐비트를 위해 필요한 전체 큐비트 수는 81개**이고(**오버헤드 1:81**),
    - 총 **41개의 데이터 큐비트**를 포함하고 있지만,
    - **X 및 Z 스태빌라이저는 각각 총 40개**만 존재한다.

- - X 연산자의 곱 체인

    - **X̂****L** **= X̂****1****X̂****2****X̂****3****X̂****4****X̂****5**는 두 X 경계를 연결하며, 배열 내 모든 스태빌라이저들과 교환 가능하고,
    - 배열 상태를 기본 상태 **|ψ⟩**에서 **|ψ****L****⟩ = X̂****L****|ψ⟩**로 바꾸지만, 측정 결과는 **|ψ⟩와 동일**하다.
  - 또 다른 곱 체인

    - **Ẑ****L** **= Ẑ****6****Ẑ****7****Ẑ****3****Ẑ****8****Ẑ****9**은 두 Z 경계를 연결하며, 마찬가지로 배열 스태빌라이저들과 교환 가능하다.
    - 이 연산자는 배열 상태를 **|ψ⟩**에서 **|ψ****L****⟩ = Ẑ****L****|ψ⟩**로 바꾼다.
  - 한편, **X̂****L** **체인을 X̂′****L** **= X̂****1****X̂****10****X̂****11****X̂****12****X̂****3****X̂****4****X̂****5**로 수정하면, 새로운 기본 상태 **|ψ****X′****⟩ = X****2,10,11,12****|ψ****X****⟩**를 생성하게 되며,
  - 이는 |**ψ****X****⟩** 상태에 대해 검은색으로 둘러싸인 **측정-X 큐비트(X****2,10,11,12****)의 측정 결과(±1)**에 따라 달라진다.
- **업계 동향 오버헤드**

  - 구글은 2023년 Nature 논문 기준 distance-25에서 논리 오류율 ≈ 10-4를 보고했다.

    - distance 25 : 1 논리 큐비트를 위해 필요한 최소 물리 큐비트 2,401개
    - 논리 오류율 ≈ 10-9을 구현하기 위해서는 distance 30 이상 필요 → 최소 3,721개의 물리 큐비트 필요함
  - 구글은 2024년 105큐비트 윌로우를 이용하여 [101,1,7]을 구현하였음

    - distance 7
    - 데이터 큐비트 : 49개
    - 안실라 큐비트 : 48개
    - 추 큐비트 : 4개 (Leakage Removal)
    - **임계값 이하 성능 : 0.143%의 논리적 오류율**
  - IBM은 정확한 연구 결과를 발표하지 않았지만, 새로 개발한 qLDPC에서 288개의 물리 큐비트로 12 논리 큐비트를 구현할 수 있다고 밝히면서, 이는 Surface Code 4,000개에 해당된다고 비교하였다.

    - 이는 대략 논리 큐비트 1개당 약 300개~400개의 물리 큐비트가 필요하다는 의미이고 대략 d=9에 해당하는 값이다.

**🔁인코딩과 디코딩**

- 논리 큐비트의 상태를 처음 준비하는 단계에서 인코딩이 이루어지고, 그 후 물리 큐비트에 오류가 발생하면, 스태빌라이저 측정을 통해 오류 감지, 및 오류 정정 과정을 반복적으로 실행하게 된다.
- 디코더는 양자 오류 정정(QEC)에서 오류를 감지하고 정정하는 **핵심 장치**이다. 양자 상태는 쉽게 오류가 발생하는데, 디코더는 안실라 큐비트(측정용 큐비트)의 결과, 즉 "증후군"을 분석해서 어떤 큐비트에 오류가 생겼는지 알아내고, 그 오류를 고칠 방법을 제안한다. 디코더마다 작동 방식이 달라서 상황에 맞는 디코더를 선택하는 게 중요하다.

****

**🔐직관적 설명**

- **QEC 코드**: 논리 큐비트의 "집"을 설계 (스태빌라이저로 **코드 공간** 정의).
- **디코더**: 집이 어지럽혀졌을 때(오류로 코드 공간 이탈), 어디가 잘못됐는지 찾아(증후군) 원래대로 정리(오류 정정).
- **호환성** : QEC 코드가 집의 구조를 알려주고, 디코더는 그 구조를 이해해 청소. 초기화 방식(가구 배치)은 유연하지만, 구조(스태빌라이저)는 일치해야 함.

**🔐인코딩(초기화) 단계:**

- **물리 큐비트 초기화**:

  - 모든 큐비트를 ∣0⟩ 상태로 초기화.
- **논리 큐비트 설정**:

  - 논리 큐비트를 ∣0⟩*L*로 설정하기 위해, 모든 데이터 큐비트를 ∣0⟩로 유지.
  - 이 상태는 여러 물리 큐비트에 분산된 논리 상태로 표현.
- **스태빌라이저 설정**:

  - 서피스 코드에서는 **X 스태빌라이저**와 **Z 스태빌라이저**를 정의함.
  - 이 연산자들은 모두 +1 고유값을 갖도록 설정되며, 이를 통해 논리 큐비트가 보호됨

****

**🔐디코딩(오류 정정) 단계:**

- **스태빌라이저 측정**:

  - 안실라 큐비트를 사용해 X 스태빌라이저와 Z 스태빌라이저를 측정.
  - 데이터 큐비트의 오류는 주변 **X 스태빌라이저**에 영향을 미침.

    - 그 큐비트에 인접한 X 스태빌라이저가 -1을 반환.
    - Z 스태빌라이저(A)는 +1을 반환
- **오류 감지 과정**:

  - 만약 데이터 큐비트에 오류가 발생하면 스태빌라이저 측정 결과가 달라진다.
  - **X 오류**: 데이터 큐비트가 ∣0⟩에서 ∣1⟩로 바뀌면, 인접한 **X 스태빌라이저**가 -1을 반환한다.
  - **Z 오류**: 데이터 큐비트의 위상(phase)이 바뀌면, 인접한 **Z 스태빌라이저**가 -1을 반환한다.
  - 예:

    - 측정 결과, 두 개의 X 스태빌라이저가 -1을 반환했다고 가정한다.
    - 이는 오류의 위치를 나타내는 **증후군(Syndrome)** 정보임.
- **오류 정정 과정**

  - 안실라 큐비트가 스태빌라이저를 측정해서 -1을 반환한 위치를 디코더가 분석하고 큐비트의 상태를 바꾼다
  - 예:

    - 두 개의 X 스태빌라이저가 -1을 반환하면, 그 사이의 데이터 큐비트에 X 오류가 발생했을 가능성이 높다.
    - 디코더는 -1을 반환한 X 스태빌라이저의 패턴을 분석한다.
    - 디코더는 이 데이터 큐비트에 X 연산을 적용하여 ∣1⟩를 다시 ∣0⟩로 되돌린다.
    - 이로써 논리 큐비트가 원래 상태로 복구된다.

**🔐오류 정정 과정의 반복**

위의 과정은 단발성으로 끝나지 않는다. 물리 큐비트는 시간이 흐를수록 다시 오류에 노출되기 때문에, 양자 컴퓨터는 지속적으로 스태빌라이저 측정과 디코딩, 그리고 오류 정정을 반복해야 한다. 이 과정을 주기적으로 수행함으로써, 논리 큐비트의 상태를 가능한 한 오랫동안 안정적으로 유지할 수 있다.

- **초기화 (인코딩)**

  - → 모든 물리 큐비트를 ∣0⟩ 상태로 초기화
  - → 논리 큐비트를 ∣0⟩L> 상태로 구성
  - → 스태빌라이저 연산자가 +1을 반환하도록 설계
- **오류 발생**

  - → 외부 노이즈 등으로 물리 큐비트에 X, Z, Y 오류 발생 가능
- **스태빌라이저 측정**

  - → 안실라 큐비트를 이용해 X/Z 스태빌라이저 측정
  - → -1 값이 나타나면 오류의 신호
- **신드롬 생성**

  - → 어떤 스태빌라이저에서 오류가 발생했는지 기록
- **디코더 분석**

  - → 증후군 패턴을 바탕으로 오류의 위치와 종류를 추정
  - → 오류 정정 연산 제안
- **오류 정정**

  - → 해당 큐비트에 X/Z 연산을 가해 원래 상태로 복구

특히 Relay-BP는 고성능 CPU나 GPU 없이도, **FPGA나 ASIC** 같은 하드웨어에서 구현이 가능하도록 설계되어 있다. 이는 양자 오류 정정의 상용화에 중요한 진전을 의미한다.

왜냐하면, 현재 양자컴퓨터의 오류 정정 과정 중 신드롬 디코딩(오류 추론)은 여전히 고전 컴퓨터(CPU/GPU)의 도움을 받아야 하는 대표적인 영역이기 때문이다.

**🔁맺음말**

양자 오류 정정은 단순한 부가 기술이 아니라 **신뢰 가능한 양자 계산을 가능케 하는 필수 기반 기술**이다. 물리 큐비트는 본질적으로 매우 불안정하며, 이를 극복하기 위해 스태빌라이저 기반의 QEC 구조, 보조 큐비트(안실라), 디코더, 오류 모델 설계가 유기적으로 작동해야 한다.

이번 글에서는 QEC의 각 구성 요소를 정리하고, 오류 감지부터 정정에 이르는 전체적인 과정을 **Surface code**를 통해 시각적으로 살펴보았다.

구글과 IBM 등 주요 기업은 각각 서피스 코드와 qLDPC라는 두 축의 기술 개발에 집중하고 있으며, 최근에는 **Relay-BP**와 같은 경량 디코더도 등장해 고전 연산 자원의 제약을 극복하려는 시도가 이어지고 있다.

결국 QEC는 양자컴퓨터를 단순한 실험 기계가 아닌 **대규모 양자 계산 플랫폼**으로 끌어올리는 핵심 기술이다. 우리가 지금 배우고 있는 이 복잡한 구조 하나하나가 미래의 실용적인 **FTQC(Fault-Tolerant Quantum Computing)** 시대를 현실로 만드는 디딤돌이 된다.
