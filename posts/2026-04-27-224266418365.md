**✅ XVII. Decoder**

**📌 왜 디코더가 중요한가**

- - Walking Cat 구조에서는 **연산 = measurement + feedforward**
  - 즉,

    - 측정 결과 → 다음 연산 결정
    - 특히 T gate, Ry(π/4) 같은 것
  - 그래서 문제:

    - measurement error 있으면

      - → 잘못된 gate 실행
      - → 전체 계산 붕괴
  - **실시간 decoding 필수**

****

**📌 기존 방식의 문제 (Global decoding)**

- - 기존:

    - 모든 syndrome 모아서 한 번에 decode
  - 문제:

    - latency 큼
    - memory 폭발
    - 실시간 불가능
  - **수천~수백만 SEC 기다려야 함**

**📌 해결: Streaming (Sliding Window) Decoder**

- - 핵심 아이디어:

    - “조금씩 보면서 바로바로 고친다”
  - **직관**

    - Global:

      - 전체 로그 다 보고 판단
    - Streaming:

      - 최근 몇 개만 보고 판단 → 계속 업데이트
    - 거의 실시간 처리 가능

**📌 왜 이게 가능한가 (핵심 구조)**

- - **Parity-check matrix 구조**
  - 논문 핵심 포인트:

    - LDPC matrix가 **staircase 구조**
    - 즉:

      - 시간 방향으로 반복 구조
      - locality 존재
    - 그래서 “멀리 있는 정보 필요 없음”

      - → local window로 충분

**📌 Error 유형 (중요 포인트)**

- - decoder는 error를 4가지로 본다:

|  |  |
| --- | --- |
| **타입** | **의미** |
| Type I | 일시적 (한 번 튀고 끝) |
| Type II | 초반 지속 |
| Type III | 중간부터 지속 |
| Type IV | 마지막에 나타남 |

- - 핵심:

    - 대부분 error는 **local + 시간 제한적**
    - 그래서 window decoding 가능

**📌 알고리즘 구조 (핵심 흐름)**

- - **전체 구조**

    - 디코딩은 두 층으로 되어 있음:

      - **Outer 구조**

        - **Sliding Window (Streaming)**

          - 시간 축을 작은 창(window)으로 나눔
          - 일부만 보고 바로 결정 (commit)
          - 계속 앞으로 이동
      - **Inner 구조**

        - **Beam Search + Belief Propagation (BP)**

          - 각 window 안에서 실제 decoding 수행
          - 후보 해를 여러 개 유지하면서 탐색
  - **핵심 알고리즘 3개**

    1. **Belief Propagation (BP)**

       - 기본 디코딩 엔진
       - 역할:

         - syndrome → error 확률 추정
       - 방법:

         - factor graph 위에서 메시지 전달
         - 각 에러 비트의 확률 업데이트
       - 문제:

         - LDPC에서 loop 때문에 **local minimum / 잘못된 수렴 가능**
    2. **Beam Search (핵심 개선)**

       - BP의 약점을 보완
       - 아이디어:

         - “가능한 해를 하나만 보지 말고 여러 개 유지하자”
       - 동작:

         1. 초기 후보 생성
         2. 확률 높은 후보 K개 유지 (beam width)
         3. 확장 + pruning 반복
       - 결과:

         - BP보다 정확도 ↑
         - worst-case 오류 ↓
    3. **Sliding Window (Streaming)**

       - 시간 축 처리 방식
       - 아이디어:

         - “전체를 한 번에 풀지 말고, 부분적으로 풀자”
       - 동작:

         - [SEC 1~5] → decode → 일부 확정
         - [SEC 2~6] → decode → 일부 확정
         - ...
       - 핵심 파라미터:

         - w = window size
         - c = commit size
    - Beam Search 알고리즘은 지난해 12월에 공개된 바 있다.

| BP | 빠른 근사 |
| Beam | 정확도 보완 |

- - 전체 파이프라인:

    1. First window
    2. Middle windows 반복
    3. Last window
  - 각 단계에서:

    - parity-check submatrix 생성
    - prior probability 적용
    - inner decoder (BP/**beam search**) 실행
    - 일부 결과 commit
  - 중요한 점:

    - **이미 확정된 error는 이후 계산에 반영됨**

> ***BP로 빠르게 추정하고, Beam으로 틀린 경로를 보완하며, Sliding Window로 실시간으로 확정한다.***

**📌 성능 결과 (논문 핵심)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMTQ2/MDAxNzc3MjUwMTA5MzU5.qRpr3fQBkCimbUcEeufVX458i5UEg2vw_qWRrjTKNHMg.PIdMGTlN-OU2_NAzUY92uHZ_OIYLa1o0KVEccZXiu44g.PNG/image.png?type=w800)](#)

- - **정확도**

    - Global 대비:

      - 최대 2배 수준 error 증가
      - 경우에 따라 더 좋음
  - **속도 (핵심)**

    - 매우 빠름
  - **Reaction time**

    - ~0.3 ~ 0.8 ms 수준
    - **실시간 피드백 가능**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMjg3/MDAxNzc3MjUwMjk0OTY5.Shd2YV2GcAd7883g40BbS5WnPjwH2GrK4dWdU55uiG8g.b5xrYFr0_LAru1bncsU7vC-oVBkylzvIWEFoiqH50FAg.PNG/image.png?type=w800)](#)

- - **용어**

    - SEC = Syndrome Extraction Cycle : 오류가 있는지 한 번 검사하는 전체 사이클
    - 1-norm distance : 지금 시스템의 qubit reservoir 상태가 최종 안정 상태에 얼마나 가까워졌는가
  - 그래프 해석

    - 약 250 SEC 이후, 두 분포 모두 steady state의 1% 이내로 들어간다.

      - 처음에는 reservoir에 qubit이 얼마나 남아 있는지 분포가 불안정하지만, 약 250번의 오류검사 사이클이 지나면 시스템이 거의 정상적인 장기 운영 상태에 들어간다는 뜻

****

**📌 가장 중요한 결론**

- - **핵심 insight**

    - Quantum computing bottleneck:

      - 연산 속도 ❌
      - gate fidelity ❌
      - **decoding latency**
  - **이 논문의 해결**

    - Streaming decoder 도입으로

      - 실시간 decoding 가능
      - memory 폭발 해결
      - latency 문제 해결

> ***“전체를 기다리지 말고, 지금 보이는 것만으로 바로 수정하라”***

**📌 시스템 전체 연결**

- - 이제 구조가 완전히 이어진다:

|  |  |
| --- | --- |
| **요소** | **역할** |
| Cat factory | 연산 |
| Magic factory | T 생성 |
| Bell factory | 연결 |
| Qubit factory | 생존 |
| Decoder | **두뇌** |

- - Decoder 없으면:

    - 모든 구조 무의미
  - Decoder 덕분에:

    - measurement-based QC가 실제로 돌아감

**✅ XVIII. Enriched Walking Cat Architecture**

**📌 문제: Instruction set이 너무 제한적**

- - 기존 구조:

    - 할 수 있는 것

      - Pauli measurement
      - Clifford 일부
      - T gate (via magic factory)
    - 하지만:

      - “직접적인 gate set”은 제한적

**📌 해결: 물리 Clifford를 이용한 확장**

- - 핵심 아이디어:

    - **“measurement 전에 Clifford를 걸어서 측정 가능한 연산을 바꿔버린다”**
  - **구조**

|  |
| --- |
| [Clifford U 적용]  → Measurement (DMX or DMZ)  → 결과 = U† P U 형태 |

- - - 즉:

      - 원래 못 측정하던 것도
      - Clifford로 변환해서 측정 가능

**📌 DMX / DMZ (핵심 primitive)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMjMg/MDAxNzc3MjUzMzA5NjE3.tbzpdKSrvSdcxpd9xeWa7qh5TfWM4MNNPmV5WzIaaOQg.quCPmPQT6PMBJDLsWz8ZH50zEXAfTrHnEjn-MRNfz4sg.PNG/image.png?type=w800)](#)

- - DMX: destructive X measurement
  - DMZ: destructive Z measurement
  - 이걸 이용해서 다양한 logical Pauli measurement 생성

**📌 핵심 확장 방법 3가지**

1. 1. **Parity Measurement 확장**

      - 기본:

        - P\_A ⊗ P\_D
      - Clifford 추가하면:

        - U† (P\_A ⊗ P\_D) U
      - 가능한 측정 집합이 **폭발적으로 증가**
   2. **Cyclic gates (중요)**

      - 아이디어:

        - qubit을 “회전/순환 이동”시킴
      - 수식:

        - (u, v, w) → (u ⊕ r, v ⊕ s, w ⊕ t)
      - 의미:

        - qubit 위치를 바꿔서
        - logical 연산 구현
      - **핵심 직관**

        - **“게이트를 직접 하지 말고 큐비트를 움직여서 게이트 효과를 만든다”**
   3. **Transversal Clifford**

      - 형태:

        - U = ⊗ U\_i
      - 특징:

        - 각 qubit 독립적으로 작동
        - error propagation 없음
      - 조건:

        - self-orthogonal code에서 가능

**📌 핵심 결과**

- - 이 구조 덕분에:

    - 단순 measurement 기반 시스템이 **Universal gate set으로 확장됨**
