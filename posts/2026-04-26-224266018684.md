**✅ XV. Magic Factory**

- - **Magic factory = fault-tolerant T gate를 위해 필요한 high-quality |H⟩ state를 생산하는 공장**

****

**📌 왜 Magic Factory가 필요한가**

- - Clifford 연산 → 쉽게 가능 (frame tracking)
  - **Non-Clifford (T gate)** → 직접 구현 어려움

    - 해결 → **magic state |H⟩ injection**

****

**📌 T gate란?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTkz/MDAxNzc3MjA4NzY2ODY1.caQuUYiK8TP7BPmasKQJrUX0ehJzJRUWrHIca7msc98g.OvgrhwsMGSVtcztzYGjHJD3RZZK3PS1jMpMa4y07MJAg.PNG/image.png?type=w800)](#)

- - **정의**

- - - 의미:

      - Z축 기준으로 **45도 회전**
  - **왜 중요한가**

    - 양자컴퓨터는:

      - Clifford만 → 부족 (고전적으로 시뮬레이션 가능)
      - T 포함 → 진짜 양자컴퓨팅 가능
    - 그래서, T gate = “비선형성 / 진짜 양자 성능의 핵심”
  - **State Injection이란?**

    - T gates는 직접 구현 ❌ → 대신 “state injection” 사용
    - 개념:

      - “특수한 상태를 미리 만들어서 그걸 이용해 gate를 구현”
    - 즉, Gate를 직접 하지 않고 State + measurement로 구현
  - **그럼 |H⟩ state는 뭐냐?**

    - **정의**

- - - 숫자로 보면:

      - |H⟩ ≈ 0.924|0⟩ + 0.383|1⟩
    - **직관**

      - |+⟩ = (|0⟩ + |1⟩)/√2 → 45도
      - |H⟩ → 그보다 작은 각도
      - 즉, “π/8 회전이 들어간 상태”
  - **왜 |H⟩가 T gate랑 연결되냐**

    - 핵심:

      - |H⟩ = T |+⟩
    - 즉:

      - T gate의 결과 상태
    - 그래서:

      - |H⟩ state를 준비하면 → T gate를 구현할 수 있음
  - **그래서 이름이 왜 “H-state injection”이냐**

    - **과정**

      - ancilla 준비:

        - |H⟩ state
      - 데이터 qubit과 entangle (YY measurement 등)
      - 측정
      - 결과에 따라 보정
      - 결과:

        - 데이터 qubit에 T gate 적용됨
    - **그래서 이름**

      - |H⟩ state를 "주입"해서 T gate를 만든다
      - 따라서 H-state injection
  - T gate = 직접 게이트 ❌ = |H⟩ state + measurement ✔
  - **왜 magic factory가 필요한가**

    - 문제:

      - |H⟩ state는 noisy하게 만들어짐
    - 그래서:

      - 여러 개 만들고 → 정제 (distillation)
    - 이것이 Magic factory

****

**📌 두 가지 프로토콜**

|  |  |  |
| --- | --- | --- |
| **방식** | **코드** | **특징** |
| **CH2** | Q54 | 단순, 작은 코드 |
| **MEK** | Q70 | 효율적, 대규모 |

- - 둘 다:

    - noisy |H⟩ → 검증 → 정제 → 출력
  - 아래 표를 보면,

    - CH2는 간단 + 충분히 좋은 품질 → 최적
    - MEK는 복잡 + 과한 정제 → 비효율

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTE5/MDAxNzc3MjA4Mjk4MTYz.rfhOguURdgLPFrdsf4utFVKaRO_DQ-T47LO3ZSoPT1gg.PXeYZon1FCPZ0roj4w4dqeq8dwBOFwOzAo6eFWJsFHcg.PNG/image.png?type=w800)](#)

**📌 전체 구조 (공통 흐름)**

- - 핵심 파이프라인:

    - H-state injection → verification → accept/reject → output
  - 구성 요소:

    - injection (EDM 기반)
    - verification (cat-based measurement)
    - postselection (reject bad states)

**📌 에러 모델 (중요)**

- - 기본 가정:

    - 물리 오류율:
    - p = 10-4
    - loss, leakage 존재
  - 핵심:

    - **모든 error는 거의 injection 단계에서 발생**
    - 즉, 나머지 logical 연산은 거의 perfect로 취급

**📌 CH2 Factory (Q54)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMjg1/MDAxNzc3MjEwMDQwNzky._5nNpseMY00S_u_OrV8RCfOSefLs4DIWn7pkZYWu8Nsg.tB1HuVb6sGSZzadEayUHfjPjFhdFZ8zSBA7tF47-Uicg.PNG/image.png?type=w800)](#)

- - **구조**

    - 2개의 |H⟩ 생성
    - transversal H² measurement로 검증
    - 핵심:

      - cat state 기반 verification
  - **주요 결과**

    - injection round: r = 3
    - output error: ~ 7.2 × 10-8
    - 실패율: ~ 2.28%
    - 평균 시간: ~ 13.44 SEC (≈ 6.72 per state)
  - **직관**

    - CH2는:

      - **빠르고 단순**
      - 하지만, error suppression 한계 있음
    - **짧게 2번 검사하고 끝.**

**📌 MEK Factory (Q70)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMjU0/MDAxNzc3MjEwNTkxMzU3.jMxlncoW8D7vjkaSU98lbJ9_ypOwN_y1u7xZqF-XSaEg.xQiyV8S43ac-qfs3F3218kAxPrp_kmzpD8hxk6YLj8kg.PNG/image.png?type=w800)](#)

- - **구조**

    - [[4,2,2]] 코드 사용
    - 10개의 |H⟩ input
    - 복잡한 distillation
    - 핵심:

      - 더 강한 error filtering
  - **주요 결과**

    - injection round: r = 3
    - output error: ~ 3.6 × 10-7
    - 실패율: ~ 11.97%
    - 평균 시간: ~ 47.6 SEC (≈ 23.8 per state)
  - **직관**

    - MEK는:

      - 더 복잡
      - 더 느림
      - 하지만, **large-scale system에 더 적합 (Q70 위에서 돌아감)**
    - **여러 개를 얽어서 오래 정제**

****

**📌 핵심 비교**

|  |  |  |
| --- | --- | --- |
| **항목** | **CH2** | **MEK** |
| 코드 | Q54 | Q70 |
| 복잡도 | 낮음 | 높음 |
| 속도 | 빠름 | 느림 |
| 실패율 | 낮음 (~2%) | 높음 (~12%) |
| 출력 오류 | 더 낮음 (~10⁻⁸) | 약간 높음 (~10⁻⁷) |
| 확장성 | 제한적 | 더 좋음 |

**📌 가장 중요한 포인트**

- - **전체 병목 = Magic Factory**

    - logical measurement → 이미 매우 안정적
    - 하지만, **T gate = magic state 없으면 불가능**
    - 즉, 전체 시스템 속도 ≈ magic state 생산 속도
  - **비용 구조**

    - 대부분 비용:

      - injection 반복
      - verification
      - 실패 → restart
    - 그래서, r 선택이 매우 중요
  - **error scaling**

    - 핵심:

      - injection error → filtering → residual error
    - 결과:

      - 매우 낮은 logical error (~10-8 수준)
  - **cat state 역할**

    - verification
    - logical measurement
    - injection support
    - 즉, cat factory ↔ magic factory 강하게 연결

**📌 시스템 레벨 의미**

- - 전체 구조:

|  |
| --- |
| Cat Factory → Measurement  Bell Factory → 연결  Magic Factory → T gate resource |

- - 역할 분리:

|  |  |
| --- | --- |
| **컴포넌트** | **역할** |
| Cat | measurement |
| Bell | 연결 |
| Magic | non-Clifford 연산 |

**📌 핵심 결론**

- - Walking cat architecture는:

    - Gate-based QC ❌
    - Measurement-based QC + Resource factory ⭕
  - 특히, **Magic factory = “연산을 가능하게 만드는 연료 생산 시스템”**

> ***Cat = 측정, Bell = 연결, Magic = 계산 가능하게 만드는 핵심 리소스 (T gate 연료)***

**✅ XVI. Qubit Factory**

- - **Qubit factory = 시스템 전체에서 계속 소모되는 큐비트를 “끊임없이 보충”해서 연산이 멈추지 않게 하는 공급 시스템**

****

**📌 왜 필요한가**

- - 이 구조의 본질:
  - 모든 컴포넌트 (M, T, C, B)가 계속 qubit을 잃는다

    - Memory (M)
    - Magic factory (T)
    - Cat factory (C)
    - Bell factory (B)
  - 매 SEC마다 qubit loss 발생 (decoherence, leakage, measurement 등)
  - **핵심 문제**

    - 만약:

      - loss > supply
    - 결과:

      - 시스템 멈춤 (fatal failure)

**📌 해결 구조 (Reservoir 모델)**

- - 논문이 도입한 개념:

    - Global Reservoir (큐빗 저장소)
  - 역할:

    - 모든 subsystem에 qubit 공급
    - 부족하면 채워줌
  - **동작 방식**

    - 매 SEC마다:
    - **(1) Loss 발생**

      - 각 subsystem에서 qubit 감소
    - **(2) Loading (보충)**

      - L개의 loading zone이
      - qubit을 생성해서 reservoir에 추가
  - **핵심 식**

    - X\_{t+1} = max(0, min(R, X\_t - k + a))

      - X\_t: 현재 reservoir 상태
      - k: loss된 qubit 수
      - a: 새로 추가된 qubit 수
      - R: 최대 저장 용량
  - 즉:

    - 줄고
    - 채워지고
    - capacity로 제한됨

**📌 시스템 failure 정의**

- - 시스템이 죽는 조건:

    - Reservoir = 0
  - 즉:

    - 쓸 qubit 없음
    - 어떤 subsystem도 복구 못함
  - **목표**

    - P(failure) < ε (예: 10-10)
    - long-term 안정성 확보

**📌 핵심 변수 2개**

- - **L — loading zones**

    - qubit 생산 속도
    - 많을수록 supply ↑
  - **R — reservoir size**

    - 저장 capacity
    - 클수록 안정성 ↑

**📌 핵심 trade-off**

|  |  |
| --- | --- |
| **변수** | **효과** |
| L ↑ | 더 빨리 채움 |
| R ↑ | 버퍼 증가 |
| 둘 다 ↑ | 안정성 ↑ but 비용 ↑ |

**📌 중요한 결과 (논문 핵심)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMjAg/MDAxNzc3MjExNTAxODMw.LSBA9bqGYD0_jAnpXYkr-Zc84e0yafD9xpvwxyPY7_Yg.U0eU_q75ZctoN4Z7WB_bRhoysRSx3I3m3vUFptNhsLMg.PNG/image.png?type=w800)](#)

- - 그래프:

    - x축: L (loading zones)
    - y축: R (필요 reservoir)
  - **핵심 발견**

    1. **최소 loading zone 존재**

       - 일정 L 이하:

         - 아무리 R 커도 실패
       - 즉, **공급 속도가 부족하면 구조적으로 불가능**
    2. **diminishing returns**

       - L 늘리면:

         - 처음 → R 급격히 감소
         - 이후 → 거의 변화 없음
       - 즉, 적정 L 이후는 의미 없음
    3. **최소 reservoir 존재**

       - 아무리 L 많아도:

         - R 최소값 존재 (~120 qubits)
       - 이유:

         - 동시에 큰 loss 이벤트 발생 가능

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTQ0/MDAxNzc3MjExNzc0MzQz.jlHEJ-zotv_INckEMapc37y6KAeEBHfZqhxf7yKPBh4g.s69nFG5iBmZ7faQlMENjnavhCtl9j-4_CD2Ma3lu-2sg.PNG/image.png?type=w800)](#)

- - **그래프 의미**

    - 색: 시스템 failure 확률

      - 빨간 영역 = 실패
      - 초록 영역 = 안정
    - 선: 등확률선 (iso-lines)
  - **포인트**

    - 특정 조합만 실제로 동작 가능

**📌 모델링 방식**

- - Markov Chain 사용
  - **상태 정의**

    - State = reservoir에 남은 qubit 수

      - 0 ~ R
  - **transition**

    - loss + addition 확률 기반 이동
  - **결과**

    - steady-state에서 P(reservoir = 0) 계산 → system failure probability

**📌 핵심 통찰**

1. 1. **시스템은 “연산”이 아니라 “물류 문제”**

      - Quantum computing = resource flow system

        - qubit 흐름
        - 생산
        - 소비
        - 재고
   2. **병목은 계산이 아니라 공급**

      - 중요:

        - Cat → 충분
        - Bell → 충분
        - Magic → 비용 큼
      - 진짜 문제:

        - qubit이 계속 사라진다
   3. **안정성 = 재고 관리**

      - classical datacenter analogy:

        - CPU → cat
        - network → bell
        - accelerator → magic
        - **RAM / power supply → qubit reservoir**

****

**📌 전체 구조 연결**

- - 지금까지 다 합치면:

|  |
| --- |
| Qubit factory (supply)  ↓  Cat factory (measurement)  ↓  Bell factory (connection)  ↓  Magic factory (T gate)  ↓  Logical computation |

> ***Qubit factory는 양자컴퓨터를 “계속 살아있게 만드는 생명 유지 시스템”이다.***
