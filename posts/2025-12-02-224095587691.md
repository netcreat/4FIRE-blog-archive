# IonQ, Recursive Clifford noise reduction 발표

Published: 2025-12-02T15:29:50.136000+09:00

Original Naver post: https://blog.naver.com/4-fire/224095587691

---

**📌 논문 핵심 요약**

**배경**

- - 양자컴퓨터는 **물리 에러율이 높고**, **완전한 오류정정(QEC)** 을 적용할 만큼 **큐비트 수가 부족**함.
  - **오류 완화(Error mitigation)** 기법이 중요해짐 — 특히 **Clifford 회로**에서 적용 가능한 **CliNR (Clifford Noise Reduction)** 방법이 제안되었다.

**기존 CliNR 방식의 한계**

- - 에러가 발생한 블록을 검증 후 실패 시 전체 재시작하는 구조로, **회로 길이가 커지면 재시작 확률이 1에 수렴**.
  - 적용 가능한 회로 크기가 **s < ~1/(n p****2****)** 로 제한됨.
  - (s=회로 게이트 수, n=큐비트 수, p=물리 오류율)

**⭐ 본 논문의 주요 기여: Recursive CliNR**

- - **CliNR 블록을 재귀적으로 계층화(트리 구조)** 하여, **검증되지 못한 주입 단계(RSI)의 오류도 상위 단계에서 다시 검증** 가능하게 함.
  - 결과적으로 **더 큰 회로에 적용 가능**하고 **논리적 오류율을 더 낮출 수 있음**.

**📈 이론적 주요 결과**

- - Theorem 1:

    - np → 0 이면, 회로 크기 s 제약 없이 논리 에러율을 0으로 수렴시킬 수 있다.
    - Gate overhead: ωG ≤ 24 (s p)4
    - Qubit overhead: (2D + 1)n + 1
    - 여기서 **D = ⌈log(sp)⌉ + 1**
    - 논리 오류율 **plog ≈ s · (n p)****(D+1)**

|  |  |  |
| --- | --- | --- |
| **항목** | **기존 CliNR** | **Recursive CliNR** |
| 적용 가능한 회로 크기 | s < 1/(n p^2) | 제한 없음 (np → 0 조건만) |
| 검증되지 않는 오류 | RSI 블록 | 상위 레벨에서 재검증 |
| 에러 감소 속도 | O(s n p²) | O(s n^D p^(D+1)) |
| 큐비트 오버헤드 | 3n | (2D+1)n + 1 |

**🔬 실험 결과 요약**

- - 시뮬레이션과 Markov 모델 결과:

    - **n = 70, p = 10****-3** 에서 gate overhead ωG ≈ 15 이후 **재귀 구조가 더 낮은 logical error 제공**
    - **n = 400, p = 10****-4** 에서는 **훨씬 큰 이득**, 같은 gate overhead에서 error가 약 **1/3 수준**
  - 실제 이온트랩 환경의 오류율 p≈10-3–10-4 기준에서 매우 유효.

**💡 의미 및 결론**

- - **Fault-tolerant QEC 이전에 실용적 양자컴퓨터(utility-scale QC) 구현 전략**
  - QEC 없이도 **크고 깊은 Clifford 회로 실행 가능**
  - 이온트랩 기반에서 특히 강점 (idle error 매우 작음)
  - 미래에는 **QEC + CliNR 병합 사용 가능성**

**📌 np와 sp는 무엇인가?**

- - 논문에서는 양자 회로의 오류 누적을 설명하기 위해 **두 가지 변수**를 사용함:

|  |  |
| --- | --- |
| **기호** | **의미** |
| **n** | 회로가 동시에 사용하는 **큐비트 수** |
| s | 회로의 size(gate 수, 연산 횟수) |
| **p** | 각 연산(게이트, 측정, idle 등)에서 발생하는 **물리적 에러율** |

- - 그래서

    - **np = 큐비트 수 × 물리적 에러율**

      - 즉, 한 “층(layer)”의 회로를 통과할 때 발생 가능한 **총 에러 양(확률적 기대값)**
    - **sp=회로 크기 × 에러율**

      - 즉, **회로 전체에서 기대되는 총 오류량**(기대값, expected total error count)을 의미함.

****

**🤔 왜 np가 중요할까?**

- - 간단한 예:

    - 큐비트가 1개(n=1), 에러율 p=0.01(1%) → np=0.01 (거의 문제 없음)
    - 큐비트가 1000개(n=1000), 같은 p=0.01 → np=10 (거의 항상 에러 발생)
  - 즉, **큐비트가 많아지고 회로가 길어질수록 에러는 누적**됨.

**🤔 왜 sp가 중요할까?**

- - 간단한 예:

    - 회로 길이 s = 1,000 gates, gate error rate p = 0.001 (0.1%) → sp=1

      - 회로 한번 실행하면 1개의 오류가 발생
    - 회로 길이 s = 1,000,000 gates, gate error rate p = 0.001 (0.1%) → sp=1000

      - 회로 한번 실행할때 1000개의 오류가 쏟아지기 때문에 정상 동작이 불가능

**🚀 요약**

|  |  |
| --- | --- |
| **항목** | **의미** |
| **np** | 병렬적으로 존재하는 qubits × 각 연산의 에러율 (한 레이어 전체 에러 기대량)  Recursive CliNR가 오류를 제곱 형태로 줄여나가기 위해 필요한 **기본 환경 조건** |
| **sp** | 회로 전체에서 누적되는 총 에러 기대량  회로가 얼마나 커질 수 있는지, 몇 레이어 재귀가 필요한지 결정 |
| **재귀 깊이 D = log(sp)** | 회로 길이에 따라 필요 검증 수준 결정 |
| **np → 0이면** | Recursive 검증으로 논리 오류율 plog → 0 가능 |

> ***sp는 회로 전체에서 기대되는 누적 오류량이며, sp가 클수록 더 깊은 재귀 CliNR을 적용해야 한다.***

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTEyMDJfMTU5/MDAxNzY0NjU2MDQwMjYy.hY6Ke4cXosOcS-Tg7v45csiL7P8z8iwfFSsSPooUHpEg.kfYuhvLRw9uUn5tEq0N8nbdvwzZvHr1J-xfau6aN9GIg.PNG/image.png?type=w800)](#)

[**Recursive Clifford noise reduction**](https://arxiv.org/html/2511.22624v1)

- - **기존 단일 CliNR 블록을 재귀적으로 여러 단계로 쌓아**
  - **오류를 계층적으로 걸러내는 Recursive CliNR 구조를 보여준다.**
  - **즉, 블록-of-블록 계층 구조 + 실패 블록만 재검증 → 큰 회로도 안정적으로 실행 가능******

**🧠 직관적 예시**

**🌟 예제1**

- - n = 100 qubits
  - p = 10-4
  - s = 106 gates

    - → np = 0.01 (에러율 작다)
    - → sp = 1000 (회로가 크다)
    - → D = log(sp) ≈ 10
    - 따라서 plog ≈ s × (np)D = 106 × (0.01)10 = 106 × 10-20 = 10-14 → 사실상 0

**🌟 예제2 (일반적인 초전도체방식)**

- - n = 100 qubits
  - p = 10-3
  - s = 106 gates

    - → np = 0.1 (에러율이 작긴 하지만....)
    - → sp = 1000 (회로가 크다)
    - → D = log(sp) ≈ 10
    - 따라서 plog ≈ s × (np)D = 106 × (0.1)10 = 106 × 10-10 = 10-4 → 작지 않은 논리 오류율

> ***np는 에러 억제 가능성(조건), sp는 억제해야 할 전체 범위(필요 깊이)***
>
> *np가 매우 작다면 재귀를 충분히 반복하여 sp가 크더라도 논리 오류율을 0에 가깝게 만들 수 있다.*

**✅****이번 논문의 핵심 요약**

**📌 왜 Recursive(재귀적) CliNR인가?**

- - Recursive CliNR는 **에러 검증(verification)을 여러 레벨(level)로 단계적으로 반복 적용**하는 구조이기 때문에 재귀적이라고 부른다.
  - 즉, **한 번의 검증으로 충분하지 않으면**, 그 검증 과정을 **더 큰 단위로 묶어서 다시 검증하는 구조**를 갖는다.

**🪜 구조를 단계로 표현하면**

|  |  |  |
| --- | --- | --- |
| **Level** | **재귀 단계** | **무엇을 하는가** |
| **Level 0** | 기본 클리포드 연산 | 단순 실행 — 에러 발생 가능 |
| **Level 1** | 블록 단위 검증 | 작은 블록을 만들어 결과가 올바른지 확인 |
| **Level 2** | 상위 블록 검증 | Level 1 블록들 간의 일관성을 검증 |
| **Level 3** | 더 큰 블록 검증 | 더 큰 영역에서 실패한 블록을 다시 걸러냄 |
| … | 계속 확장 | **D = log₂(sp)** 만큼 반복 |

**🔁 수학적으로는 이렇게 보임**

- - 오류가 p라고 할 때,

    - Level 0: error = p
    - Level 1: error = p2
    - Level 2: error = p3
    - Level 3: error = p4

**🧹 집 청소 예시**

- - 동생들 셋을 데리고 내가 먼저 1차로 각방을 청소한다 → Level 0 (방1, 방2, 방3, 방4)
  - 삼촌과 이모가 다시 점검한다 → Level 1 (삼촌-방1,2, 이모-방3,4)
  - 엄마가 또다시 점검한다 → Level 2 (방1,2,3,4)
  - 할머니가 전체 점검한다 → Level 3 (방과, 거실, 화장실도 점검한다)
  - 즉 하나의 검증이 실패하면 **상위 검증이 그 오류를 다시 걸러냄**.

> ***Recursive CliNR는 전체 회로를 반복하는 구조가 아니라, 회로를 작은 블록으로 나누고, 블록을 합쳐가며 재귀적으로 검증하는 계층적 검증 구조이다.***

|  |  |
| --- | --- |
| **기존 오류 완화** | **Recursive CliNR** |
| 한 번 검증하고 끝 | 검증을 여러 단계로 반복 |
| 실패 시 회로 전체 재시작 | 상위 단계에서 다시 걸러냄 |
| 작은 회로만 가능 | 큰 회로도 가능 |

> ***오류 정정(QEC)처럼 많은 추가 큐비트 필요하지 않음***
>
> ***오류 완화(EM)보다 훨씬 강력한 축소 효과***
>
> ***np → 0 라면 회로 크기 s 제한 없이 오류 → 0 가능***

**📌Q&A**

**1. 재귀를 몇 번 돌리나? (Recursive depth D)**

- - D = ⌈log₂(sp)⌉ + 1
  - 회로 길이가 1000배 늘어나도 재귀 깊이는 10단계만 증가한다.
  - → 즉, **logarithmic scaling** 덕에 매우 efficient.
  - 그럼 기존 방식에 비해 더 많은 연산이 필요한건가?

    - 그렇다. 단기 연산량은 증가하지만 전체 실패 확률이 감소하여 restart cost가 낮아져서 전체적으로 효율적임

**2. QEC와 같이 적용 가능하나?**

- - Recursive CliNR는 **Error Mitigation (오류 완화)** 기술이고,
  - QEC는 **Error Correction (오류 정정)** 기술이다.
  - 특히 QEC는 많은 overhead가 필요하므로, CliNR + QEC = 훨씬 효율적이고 자원 줄어든 FTQC 가능

    - 먼저 CliNR로 p를 충분히 낮춘 뒤 줄어든 logical error에서 QEC 적용 → 효율적

**3. 이 개념이 가장 적합한 것은?**

- - 회로의 에러율이 작을수록 유리한 개념이다.
  - 세계에서 에러율이 가장 작은 플랫폼은 IonQ의 이온트랩기반이다.

|  |  |  |  |
| --- | --- | --- | --- |
| **플랫폼** | **typical p** | **idle error** | **np scaling** |
| Trapped ion | 10^-4 ~ 10^-5 | 매우 작음 | np ≪ 1 달성 가능 |
| Neutral atom | 10^-3 | 중간 | 경계선 |
| Superconducting | 10^-3 ~ 10^-2 | idle error 상당 | np ≥ 1(불리) |

> IonQ의 접근법은 꽤나 실용적이다. 개발 리소스가 부족하면 QEC 개발에 집중 투자하는 것이 일반적일텐데, 물리 큐비트가 충분히 확보되지 않은 상황에서 사용가능한 CliNR라는 알고리즘을 지속적으로 계산하고, QEC를 도입할 경우에도 사용할 수 있도록 방향을 잡은 것에 대해 놀라지 않을 수 없다.
