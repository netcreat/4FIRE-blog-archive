**✅****초록 (Abstract)**

Quantinuum과 MS Quantum은 테서랙트 코드(tesseract code)라 불리는 새로운 4차원 위상적 오류 정정 코드를 이용해 **양자 계산과 오류 정정을 동시에 수행하는 실험**을 시연하였다.

실험에서는 56개의 물리 큐비트(physical qubits)로 구성된 **H2 trapped-ion QCCD 양자 프로세서**를 사용하여, 12개의 논리 큐비트(logical qubits)를 구성한다.

- - 테서랙트 코드는 **LDPC(low-density parity-check)** 계열의 위상 코드로,
  - 물리적 자원 대비 효율이 높고, **논리 연산 및 오류 정정을 병렬로 수행**할 수 있는 장점을 가진다.
  - **Bacon-Shor 기반의 피드백 회로**와 결합하여 테서랙트 코드를 동작시키고,
  - **에러율 10****-3** **이하**에서 동작 가능한 **논리 게이트 세트**를 실험적으로 입증한다.
  - 추가적으로, **동시 다중 논리 연산**, **논리 상태 준비**, **논리 측정**, **오류 정정 복원**을 포함한 전 과정을 수행한다.

이번 실험은 **실시간 오류 정정 기반 논리 연산**을 양자 하드웨어에서 동작시킨 첫 사례 중 하나이며, 향후 **확장형 양자 컴퓨팅**을 위한 핵심적인 기반을 마련한다.

**✅****서론 (Introduction)**

양자 컴퓨터의 실용화를 위해서는 **수백만 개의 물리 큐비트**가 필요하다는 것이 잘 알려져 있다. 하지만 현재의 양자 하드웨어는 **에러율**과 **디코히어런스 시간** 때문에 확장성에 한계가 있다. 따라서, 효율적인 오류 정정(QEC)과 **논리 큐비트(logical qubits)** 기반의 연산이 필수적이다. 우리는 이 논문에서 테서랙트 코드(tesseract code)라는 새로운 **4차원 LDPC 위상 코드**를 제안하고, Quantinuum의 **H2 trapped-ion QCCD 시스템**을 통해 **12개의 논리 큐비트를 실험적으로 구현**한다.

기존의 서페이스 코드(surface code)는 2D 격자에서 오류 정정을 구현하며 높은 임계값(threshold)을 제공하지만,

- - **연결 구조가 제한적**이고
  - **게이트 수행 속도가 느리며**
  - **오버헤드가 커서** 대규모 시스템에서는 비효율적이다.

이에 비해 **테서랙트 코드**는 다음과 같은 특징을 가진다:

1. **4차원 격자 기반 구조**

   - 2D 서페이스 코드보다 높은 **연결성(connectivity)** 제공
   - 다중 논리 큐비트 간의 병렬 연산 가능
2. **저밀도 패리티 검사(LDPC)**

   - 단일 큐비트가 제한된 수의 패리티 제약만 만족하면 되므로 **자원 효율성이 높음**
3. **H2 QCCD 아키텍처 최적화**

   - **racetrack 구조의 1D 선형 트랩**을 사용하지만, **멀티존 셔틀링**으로 4D 격자에 해당하는 상호작용을 **물리적으로 에뮬레이션**함.

본 실험은 다음을 목표로 한다:

- - **56개의 물리 큐비트 → 12개의 논리 큐비트 구성**
  - 논리 게이트 집합(Logical Gate Set)의 실험적 검증
  - 실시간 오류 정정(Realtime QEC)의 하드웨어 통합
  - **Hamiltonian 시뮬레이션**, **QAOA**, **논리 상태 준비** 등
  - 어플리케이션 벤치마크 수행

위에서 간단히 논문의 요약을 살펴봤다. 이제 이번 실험이 어떻게 구동되는지와 시사점을 파악해 보겠다.

**✅** **테서랙트 코드 아키텍처 (Tesseract Code Architecture)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTA4MjFfNzIg/MDAxNzU1NzQ4MDM0MTQ0.URuusCzZrrohFbc4tFieTUwVbFFjVo3XAJON94Opm_Ag.K1jQf1J_MohD2qvJvpQqb2ZIQ05kd9daaxZQKSR8-qwg.PNG/image.png?type=w800)](#)

**💡** **개요**

- **Tesseract = 4차원 초정육면체 (hypercube)**

  - 2D → 정사각형: 변 4개, 꼭짓점 4개
  - 3D → 정육면체: 면 6개, 꼭짓점 8개
  - 4D → 테서랙트: "면" 대신 "셀(cell)"이라는 3차원 단위가 8개
  - (즉, 4차원 공간에서 3D 정육면체 8개가 서로 연결돼 있는 구조)
- **[[16,6,4]] 컬러 코드****를** **4차원 초정육면체(테서랙트)** **위에 정의한다.**

  - n = 16: 꼭짓점(vertex)이 16개 → 각 꼭짓점이 물리 큐비트가 된다.
  - k = 6: 논리 큐비트 6개를 부호화한다. (여기서 2개의 큐비트는 게이지 큐비트(gauge qubits)처럼 사용해서, [16, 4, 4]로 변환하여 사용한다.
  - d = 4: 코드 거리 4(최소 비자명 논리 연산의 가중치가 4).

****

- **테서랙트 서브시스템 컬러 코드**는 **[[16, 4, 4]]**(16 물리, 4 논리, 거리 4) 특성을 갖는 **서브시스템(subsystem) 형태의 컬러 코드**이다.
- 이 코드는 **저밀도 패리티 검사(LDPC) 성격**을 가지며, **플래그(flag) 기반 안정자 측정**과 결합해 **짧은 회로 깊이**로 **오류의 감지·국소화**를 가능하게 한다.
- 핵심 아이디어는 **일부 연산을 ‘게이지(gauge)’ 자유도로 밀어내어**(서브시스템화) **측정 회로의 복잡도를 낮추는 것**이다.

**💡****왜 56 물리 큐비트로 12 논리 큐비트를 만들 수 있는가**

일반적으로 surface code에서는 **1개 논리 큐비트당** 약 **d****2****개의 물리 큐비트**가 필요하다. 예를 들어, IBM이 쓰는 **distance-5 surface code**라면 **1논리 ≈ 25~49 물리 큐비트**예요.

그런데 Quantinuum은 단 56개 물리 큐비트로 **12개의 논리 큐비트**를 만들었는데, 어떻게 가능한가?

- **Tesseract 코드의 4D 특성**

  - **2D Surface Code: 물리적 격자 위에서 stabilizer를 구성 → 최소 2D에서만 인접한 큐비트와 연결 가능**
  - **4D Tesseract Code:** **4차원 격자에서 모든 stabilizer가 고르게 연결됨**
  - **결과적으로 물리 큐비트 하나가 훨씬 많은 논리 정보에 기여할 수 있음**
- **효과:**

  - **Overhead가 약** **70% 이상 절감**
  - **56개의 물리 큐비트만으로도** **논리적 자유도를 극대화** **가능.**

**✅****코드 구조적 단점**

**💡****[[16,4,4]] → 논리당 오버헤드가 낮지만 거리(distance)가 4에 불과**

- - 1개 논리 큐비트를 보호하려면 약 2.7개의 물리 큐비트 사용 → 오버헤드가 낮다는 장점.
  - 하지만 distance = 4라서, 최대 1비트 에러만 확실히 교정 가능.
  - 실용적 FTQC에서는 distance ≥ 9 ~ 13 이상이 필요한데, 이 코드로는 규모 확장 불리.

****

**💡****서브시스템 컬러 코드 → 플래그·포스트셀렉션 의존성**

- - Tesseract는 gauge qubit을 포함한 서브시스템 코드라서 측정 안정성이 불안정.
  - 실험에서는 플래그 큐비트와 포스트셀렉션(실패 케이스 버림)을 적극 활용.
  - **→ 논문에서 보고된 12 로지컬 큐비트 성공률은 사실상 후처리 필터링된 결과.**
  - 실시간으로 모든 실패 샷을 살리려면 성능 급격히 저하.

****

**💡****LDPC 계열이라 디코딩이 복잡함**

- - 컬러 코드 기반 LDPC라서 시스템 해밀토니안·패리티 검증 매트릭스가 복잡.
  - 서페이스 코드처럼 매칭 기반 디코더(MWPM)를 단순하게 쓰기 어려움.
  - 고속 디코딩하려면 BP+OSD, MLE(Tesseract Decoder), Neural BP 등 **고급 디코더 필요.**
  - → 실시간 디코딩 요구(QEC cycle < 1ms) 충족 어려움 → 하드웨어 제약.

****

**✅****하드웨어 요구사항의 단점**

**💡****모든 큐비트 연결성(All-to-all)에 의존**

- - Tesseract 코드는 논리 블록별로 높은 연결성이 필요.
  - Quantinuum H1/H2 장비는 트랩드 이온 all-to-all 아키텍처라 잘 맞지만,
  - 초전도체·스핀큐비트처럼 최근접 NN 연결성만 지원하는 플랫폼에서는 비효율적.

****

**💡****스위트 스팟이 ‘작은 논리계 실험’에 있음**

- - 소규모 논리 큐비트 실험에서는 효과적:
  - 낮은 오버헤드
  - 작은 블록에서 높은 피델리티 가능
  - 하지만 100+ 논리 큐비트 이상으로 확장하려면
  - → 게이지 안정화, 디코딩 복잡성, 측정 연산량이 급증.

**💡****Quantinuum이 Tesseract를 쓰는 이유**

- - **목표: “****FT 논리 큐비트 10개 이상 실험”을 세계 최초로 달성** → 업계 과시 목적.
  - H1/H2 장비의 **all-to-all 특성과 잘 맞음.**
  - **소규모 블록에서 논리 게이트 피델리티를 극대화 가능**.
