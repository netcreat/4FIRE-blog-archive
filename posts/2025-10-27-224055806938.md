**✅논문 요약**

**🔹 연구 핵심 요약**

- - **목표**

    - IBM은 [[144, 12, 12]] **Gross 코드**와 [[56, 2, 10]] **Loon 코드** 같은 **양자 LDPC(bivariate bicycle) 코드**를 대상으로 **Relay-BP 디코더를 FPGA 상에 구현******하여 **실시간 오류 보정 가능성**을 입증하였다.
    - 목표는 **1 µs 이하의 오류 정정 사이클**을 구현해 **양자 메모리의 백로그(backlog) 문제를 제거**하는 것이다.
  - **주요 성과**

    - **AMD VU19P FPGA** 상에서 **24 ns에 1회 BP(iteration) 수행**, 평균 10 회 이내 수렴 → **12-cycle 윈도우 기준 240 ns 이내 디코딩** 달성. 이는 QPU의 1 µs 사이클보다 빠르므로 실시간 처리 가능.
    - **정수 4비트 연산(int4)** 로도 부동소수점 64비트 정확도에 근접한 **논리 오류율** 달성.
    - X/Z 분리 디코딩은 4비트, XYZ 상관 디코딩은 6비트면 충분.
    - FPGA의 LUT 51.6% 사용, 총 전력 58 W, 클럭 4 ns.

**🔹 기술 내용 요약**

- - **Relay-BP 알고리즘**

    - 기존 Belief Propagation(BP)에 **비균질 메모리 강도(disordered memory strength)** 를 도입한 DMem-BP를 기반으로, **Relay ensemble** 기법(순차 다중 BP 실행) 도입 → 정확도와 수렴 속도 개선.
    - 각 BP ‘leg’가 이전 결과를 다음 leg로 전달 → 정보를 릴레이처럼 전파.
  - **FPGA 구현 구조**

    - **Variable Node Unit (VNU)** 및 **Check Node Unit (CNU)** 을 각각 그래프 노드에 1:1 할당하여 **메시지를 배선 레벨에서 교환** → 중앙 메모리 병목 해소.
    - 한 BP iteration = 2 FPGA clock cycle.
    - **윈도우 디코더(windowed decoder)** 를 사용해 W (코드 거리 d) 사이클 단위로 슬라이딩 처리.
  - **정수 저정밀도 연산**

    - **int4 (부호 + 3비트)** 정밀도로 Relay-BP를 정수 도메인에서 수행, 고정소수점 대신 단순 비트シ프트로 메모리 강도 스케일링 구현.
    - **성능 비교 결과**: 정수형에서도 BP 수렴 특성이 거의 동일, 논리 오류율 손실 미미.

**🔹 검증 및 결과**

- - **실시간 검증 하네스(test harness)** 에서 소프트웨어 시뮬레이션과 FPGA 출력의 일치성 확인.
  - 실제 양자 제어 시스템(QPU readout 스트림)에 연동 가능 설계.
  - **12-cycle gross code 메모리** 실험에서
  - 평균 20 회 BP iteration → **480 ns 전체 윈도우 디코딩**,
  - **사이클당 40 ns 평균 디코딩 시간** 확보.
  - **Loon 및 Kookaburra 코드** 에서도 FPGA 정수 연산 버전이 부동소수점 버전과 동일한 정확도 달성.

**🔹 의의와 전망**

- - 이번 연구는 **양자 LDPC 코드용 Relay-BP 디코더의 세계 최초 실시간 FPGA 구현**으로, IBM이 **Starling(2029)** 시스템 목표에 맞춰 **하드웨어 QEC 스택을 현실화**했음을 보여준다.
  - **비용 효율적이고 재프로그래머블한 FPGA**를 사용했기 때문에, 고가의 ASIC 없이도 양자 메모리 실험 및 제어 시스템에 직접 통합 가능.
  - 향후 계획은 (1) 실제 큐비트 측정 데이터 적용, (2) 논리 연산 디코딩으로 확장, (3) 리소스 최적화 및 ASIC 이행.

**📘 정리하면,**

> IBM은 **Relay-BP 알고리즘을 AMD FPGA 하드웨어로 완전 병렬 구현**하여 **24 ns 수준의 실시간 QEC 디코딩**을 실현했다.
>
> 이로써 IBM 양자 LDPC 메모리 시스템은 **1 µs 이내 오류 보정 사이클**을 달성했으며, 이는 **저비용 상용 칩에서도 양자 오류 보정이 가능함**을 보여주는 중요한 이정표이다

**✅논문 분석**

**💡****Gross 코드 vs Loon 코드 비교**

- - **코드 파라미터**

    - **Loon**: [56,2,10] → 길이 56, 논리큐비트 2, 코드거리 10.
    - **gross**: [144,12,12] → 길이 144, 논리큐비트 12, 코드거리 12.
  - **윈도우 길이(글로벌 디코딩)**

    - Loon 실험: **10+1 cycles**
    - gross 실험: **12+1 cycles** (그림 7 기준)
  - **정밀도 요구**

    - **분리 X/Z 디코딩**: **int4**(4비트)로 부동소수점과 동급 정확도
    - **상관 XYZ 디코딩**: **int6**(6비트) 필요
  - **실시간 한계선(부록 예시)**

    - Loon(10+1): **게이트웨어 20ns/iteration** 가정 시 (10,6) 윈도우에서 윈도우당 **≈270회 BP 반복**까지 실시간 지속 가능
    - gross(12+1, Kookaburra 하드웨어): **24ns/iteration** 가정 시 (12,8) 윈도우에서 **≈333회 BP 반복**까지 가능

> **요약**
>
> gross 코드는 더 큰 코드거리·논리수(12)를 가지며, FPGA 상 **24ns/iteration** 환경에서도 12-사이클 창을 매우 빠르게 처리한다.
>
> Loon은 더 작아 윈도우 길이가 짧고, 동일한 정수 정밀도에서 부동소수점과 동급 논리 오류율을 낸다.

**💡****FPGA 구현 구조**

- - **VNU/CNU 1:1 매핑**: 변수노드·검사노드를 **FPGA 상에 전용 유닛으로 1:1 배치**하고, **메시지를 배선 수준으로 교환**해 메모리 경합을 제거. **VNU·CNU 각 1클럭, ‘flooding’ 스케줄에서 BP 1회=2클럭** → 24ns/iteration을 가능케 함 .
  - **윈도우 디코더**: **슬라이딩 윈도우 길이 W**만큼의 신드롬을 입력받아 처리·커밋하는 시스템 통합 구조. 검증 하네스는 **1µs 간격으로 신드롬을 공급**, 윈도우/커밋 조건이 차면 디코더를 구동한다(매핑·반복회수·수렴 체크 포함)

**💡****이터레이션(iteration) vs 사이클(cycle)**

- - **BP 이터레이션**:

    - Relay-BP 디코더 내부의 **메시지 패싱 1회전**을 뜻한다.
    - VNU↔CNU가 메시지를 주고받아 신념값을 갱신하는 **알고리즘 반복 1번**이며, 본 구현에선 **VNU 1클럭 + CNU 1클럭 = 2클럭**이 한 번의 BP 이터레이션이 된다.
    - **24ns/iteration**이 보고된다. 이 값은 **디코더 내부 연산 속도**를 가리킨다
  - QPU가 **매 1 µs**마다 신드롬을 생성한다(사이클).
  - 디코더는 **12개 사이클을 모아 윈도우 1개**를 구성한다(W=12, gross).
  - 윈도우 1개를 풀기 위해 Relay-BP가 **BP 이터레이션을 평균 <10번** 수행한다.
  - **1 이터레이션 = 24 ns**이므로 **총 ≲240 ns**에 윈도우 1개 디코딩 완료

    - QPU의 사이클 1**µs 보다 빠**름 → **실시간 충족**.

**1️⃣ 입력 계층 (왼쪽 파란색)**

- - **High-speed serial links**

    - → QPU에서 들어오는 **신드롬 데이터 스트림**을 초고속 링크(예: 10 Gb SerDes)로 수신한다.
  - **Syndrome Mapping**

    - → 들어온 신드롬 비트를 **그래프 노드 인덱스에 매핑**하여 내부 디코더가 바로 사용할 수 있는 형태로 변환한다.
  - **Registers & Trace-recorder / Decoder Register Interface**

    - → 디코더 설정값(윈도우 길이, 반복 횟수, 스케일링 상수 등)을 저장하고 실험 시퀀스(trace)를 기록한다.
  - **Logical Pauli Frame Update (출력)**

    - → 디코딩 결과(에러 추정 ê̂)를 **논리 파울리 프레임 업데이트** 형태로 QPU 제어기에 돌려보낸다.

**2️⃣ 윈도잉 디코더(Windowing decoder, 연두색 영역)**

- - **Detector Window Processing**

    - → 스트리밍된 신드롬을 여러 사이클 단위(예: 12-cycle window)로 묶어 처리한다.
    - 이 윈도우는 시간적 슬라이딩 방식으로 이동하며 연속된 오류를 추적한다.
  - **Decoder Controller**

    - → 윈도우 크기·BP iteration 횟수 제한 등을 관리하며 내부 Relay decoder를 스케줄링한다.

**3️⃣ 릴레이 디코더(Relay decoder, 회색 영역)**

- - **Variable Node Units (VNU)**

    - → 각 변수노드 vj에 대응하는 **신념값(Λ, M)** 계산을 수행한다.
  - **Check Node Units (CNU)**

    - → 각 검사노드 i가 **패리티 제약 H x = σ**를 만족하도록 메시지 µ, ν를 갱신한다.
  - **Convergence Checker**

    - → 각 BP iteration 마다 모든 노드가 수렴했는지( H ê = σ ) 검사한다.
  - **Controller**

    - → VNU/CNU의 실행을 동기화하며 “다음 Relay leg”으로 넘어가는 시점을 제어한다.
  - 이 영역이 실제로 **BP iteration = 24 ns** 에 해당하는 완전 병렬 연산 블록이다. 노드 간 메시지는 중앙 RAM 이 아닌 **FPGA 배선(wiring)** 으로 직접 교환되어 메모리 병목을 제거한다.

**4️⃣ 출력 및 커밋 단계**

- - **Commit Region Identification**

    - → 슬라이딩 윈도우 중 이미 안정화된(detector 수렴한) 부분을 식별하여 “커밋”한다.
  - **Logical Pauli Frame Calculation**

    - → 커밋된 오류 벡터 ê̂ 를 논리 연산 행렬 A 에 곱해 **논리 파울리 프레임 업데이트**를 계산한다.
  - 결과는 앞단 High-speed link를 통해 QPU 제어기로 전송된다.

**✅****GPU, ASIC, FPGA: 양자 오류 정정(QEC)을 위한 하드웨어 비교**

**💡****서론**

- - 양자 오류 정정(QEC)이 없이는 양자 컴퓨터는 결코 고전적 시스템을 능가할 수 없다. QEC를 실시간으로 처리하기 위해서는 엄청난 양의 데이터를 초저지연으로 연산할 수 있는 고성능 디코더가 필요하며, 이로 인해 하드웨어 성능 한계에 직면하게 된다.
  - 양자 시스템이 확장됨에 따라 테라바이트급 데이터를 초미세한 시간 단위로 처리해야 하므로, 어떤 하드웨어 플랫폼을 선택하느냐가 향후 양자 컴퓨터의 성능을 결정하게 된다. 현재의 주요 후보는 GPU, FPGA, ASIC이다.

**💡****하드웨어 아키텍처의 기본 개념**

- - **단일 명령–단일 데이터 (SISD)**

    - 고전적인 CPU의 폰 노이만 구조로, 명령과 데이터를 메모리에 저장하고 순차적으로 처리한다.
  - **단일(또는 복수) 명령–복수(또는 단일) 데이터 (SIMD/MIMD)**

    - GPU나 벡터 확장 구조가 여기에 해당한다. 동일한 연산을 여러 데이터에 병렬 수행하여 메모리 접근 횟수를 줄인다.
  - **데이터플로우/시스톨릭 어레이**

    - 데이터가 메모리에 저장되지 않고, 여러 병렬 유닛 간에 흐르며 동기화된다. TPU 같은 ASIC이 대표적이다.

**💡****GPU (Graphics Processing Unit)**

- - GPU는 원래 그래픽 렌더링용으로 개발되었으나, 오늘날에는 AI와 HPC의 핵심 병렬 컴퓨팅 장치로 진화하였다.

    - **구조:** 수천 개의 단순 코어(예: NVIDIA H100은 약 14,500개 코어)를 포함한 스트리밍 멀티프로세서(SM) 구조.
    - **특징:** 단일 명령–복수 데이터(SIMD) 구조로 대규모 병렬 연산에 최적화.
    - **장점:** 높은 처리량(throughput), 공유 메모리를 통한 스레드 간 통신 효율.
    - **단점:** 지연(latency)보다 처리량 위주 설계 → 개별 연산의 응답 속도는 느림.
  - **QEC 적용 예:**

    - NVIDIA의 **CUDA-Q** 플랫폼은 QPU, GPU, CPU를 통합하여 QEC 디코딩 속도를 29~35배 향상.
    - **cuQuantum** 라이브러리는 양자 회로 시뮬레이션을 최대 81배 빠르게 수행.

**💡****FPGA (Field-Programmable Gate Array)**

- - FPGA는 프로그래머블 하드웨어로, 작은 논리 회로를 조합하여 맞춤형 디지털 회로를 구현할 수 있다.

    - **구조:** 수백만 개의 LUT(lookup table), 플립플롭, 멀티플렉서로 구성.
    - **특징:** 병렬 연산 구조와 공간적 병렬성(spatial parallelism)을 통해 초저지연 연산 가능.
    - **장점:** 특정 알고리즘에 맞게 구조를 최적화할 수 있음.
    - **단점:** 프로그래밍이 복잡하고 개발 시간이 길다.
  - **QEC 적용 예:**

    - Riverlane은 Rigetti와 협력해 FPGA 기반 디코더를 구현, **20μs 이하 지연으로 실시간 오류 정정** 달성.
    - IBM, Xanadu 등도 FPGA 기반 제어 스택을 활용하여 수천 큐비트로 확장 가능한 시스템을 시연.
    - 재구성 가능성 덕분에 QEC 알고리즘 변화에 빠르게 대응 가능.

**💡****ASIC (Application-Specific Integrated Circuit)**

- - ASIC은 특정 목적에 맞게 설계된 전용 칩으로, 속도와 효율 면에서 최고 수준의 하드웨어다.

    - **구조:** 시스톨릭 어레이 구조를 사용해 메모리 접근을 최소화.
    - **특징:** 데이터가 파이프라인을 통해 흘러가며 각 연산 유닛이 결과를 인접 유닛에 전달.
    - **장점:** 초저지연, 낮은 전력소모, 고효율.
    - **단점:** 설계 비용이 매우 높고, 제작 후 수정 불가.
  - **QEC 적용 예:**

    - 표면코드(surface code) 및 위상학적 코드용 ASIC 디코더가 연구 중이며, 범용 하드웨어보다 속도와 에너지 효율이 높음.
    - 산업 규모 양자 시스템에서는 QEC 파이프라인을 ASIC으로 직접 통합하는 방식이 주류가 될 전망.

**💡****결론 및 전망**

- - 미래의 양자 컴퓨팅은 단일 하드웨어 아키텍처로는 실시간 QEC 요구를 충족할 수 없을 것이다.

    - **GPU**는 대규모 병렬 디코딩 및 시뮬레이션에 유리하다.
    - **FPGA**는 실시간 제어 및 저지연 응답에 적합하다.
    - **ASIC**은 최종적으로 산업용 양자 시스템에서 초고속 QEC 파이프라인 구현의 핵심이 될 것이다.
  - Riverlane의 **Deltaflow QEC Stack**은 이러한 이유로 GPU·FPGA·ASIC을 통합한 **이기종(hybrid) 아키텍처** 접근법을 채택하고 있다.
  - 결국, 초당 100TB에 달하는 QEC 데이터를 얼마나 빠르고 효율적으로 처리하느냐가 양자 컴퓨터의 “실용적 우위(quantum utility)” 달성을 좌우할 것이다.

>
> 앞으로 수천 큐비트가 안정적으로 동작하는 시대가 오면, **GPU는 더 이상 실시간 오류 정정의 대안이 되기 어렵다.**
>
> 이 시점에서는 최소한 **FPGA 수준의 지연 시간과 병렬 구조**가 필요하며, 성능 요구가 더 높아지면 **FPGA와 HBM(High Bandwidth Memory)을 결합한 구조**가 유력한 선택이 될 것이다.
>
> 궁극적으로 양자컴퓨터가 대중화되어 **대규모 디코딩 연산이 절대적으로 필요한 상황**이 되면, 초기 개발비가 높더라도 **대량 생산을 통해 단가를 낮출 수 있는 ASIC**이 주류로 자리 잡을 가능성이 크다.
>
> 
>
> 특히 주목할 점은, **Google이 이미 TPU라는 자체 ASIC을 직접 설계·생산하고 있다는 사실**이다.
>
> 이는 장기적으로 양자 오류 정정 전용 ASIC 시대를 대비한 중요한 전략적 포석으로 볼 수 있다.
