**✅ IX. Memory Block**

- - **기존 이해 (틀리기 쉬운 포인트)**

    - 그냥 qubit 저장소
  - **실제**

    - **지속적으로 움직이고 계산하는 시스템**
  - **핵심 구조**

    - Memory block = 4개의 레이어

      - Data qubit (실제 정보)
      - Ancilla (오류 체크)
      - Beacon (loss 감지)
      - Highway (이동 통로)
  - **핵심 아이디어**

    - “고정된 격자”가 아니라 ancilla가 이동하면서 data를 검사하는 구조
  - **진짜 중요한 포인트**

    - 오류 정정 = 계산이 아니라 **movement + interaction**

      - ancilla 이동
      - data와 만나서 측정
      - 다시 이동

**📌 Three-ring Framework (이 구조의 핵심)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTQ4/MDAxNzc3MTY3MjUzMzMz.GZbThEaQEkZK4iAXs6ebU-RcvWGsR_IaN-SWe76fI8gg.xKZDXoeb_9NOr2rlbMnQpZ4jB6jjGWkWhcqLUuYRD3Ag.PNG/image.png?type=w800)](#)

- - **핵심 파라미터**

    - **[[n, k, d]]**

      - n = 물리 큐비트 수
      - k = 논리 큐비트 수
      - d = 코드 distance
      - **예시**

        - Q102 → [102, 22, 9]
        - Q70 → [70, 6, 9]
        - Q54 → [54, 2, 10]
      - **의미**

        - logical density:

          - Q102 → 22 logical
          - Q70 → 6 logical
      - **핵심**

        - LDPC라서 k > 1 가능 (여러 logical per block)
    - **r****enc** **= k/n**

      - 인코딩 효율
      - **예시**

        - Q102 → 22/102 ≈ 0.22
        - Q70 → 6/70 ≈ 0.085
      - **의미**

        - Q102가 훨씬 효율적
    - **d****circ**

      - 회로 레벨 distance
      - 실제 오류에 대한 robustness
    - **w****check**

      - 체크 weight

        - ancilla가 접촉하는 qubit 수
      - **의미**
      - 낮을수록:

        - 빠름
        - locality 좋음
  - 이건 그냥 구조 설명이 아니라 **“왜 이동이 가능한가”를 설명하는 수학적 모델**
  - **핵심 개념**

    - 3개의 방향 이동:

      - short ring → z 방향
      - medium ring → v 방향
      - long ring → u 방향
  - **의미**

    - 모든 이동을 이렇게 표현 가능:

      - (shift r, s, t)
    - 즉 **복잡한 이동 = 단순한 cyclic shift 조합**
  - **왜 중요?**

    - 이동을 회로처럼 설계 가능해짐

      - 병렬 처리 가능
      - scheduling 가능
      - latency 예측 가능

**📌 Ring shift 구조**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfNTAg/MDAxNzc3MTY3NjIxNDI2.nl-NW2zhktXwCd5ha2C9KCdtsd0W-pktFg4VJONscaMg.ndO92prxHDb3fy7HJODk78C1jbGHfwsjc68MY9Gp7H8g.PNG/image.png?type=w800)](#)

- - **구조 설명**

    - 3개의 중간 링 (M0, M1, M2) 각각 ancilla 블록
    - **그룹**

      - M0 = 왼쪽 9개 ancilla
      - M1 = 중앙 9개
      - M2 = 오른쪽 9개
  - **shift 연산**

    - **3가지 shift**

      - **Shift(M0; 0,0,1)**

        - M0에서:

          - short ring → +1 이동
      - **Shift(M1; 0,1,2)**

        - M1에서:

          - short ring → +2
          - medium ring → +1
      - **Shift(M2; 0,2,0)**

        - M2에서:

          - short ring → +2~3
          - medium ring → 이동
  - **핵심 개념**

    - **cyclic shift**

      - ancilla들이:

        - 순환 이동
        - 서로 다른 qubit과 상호작용
    - **결과**

      - 하나의 ancilla로 여러 stabilizer 측정 가능
  - **병렬성**

    - **중요한 문장**

      - r = 0 → 모든 shift 병렬 가능
    - **의미**

      - 모든 ancilla 동시 이동
      - 완전 병렬 처리
  - **이 구조의 진짜 의미**

    - **기존 (surface code)**

      - local interaction
      - 느린 propagation
    - **여기**

      - cyclic 이동
      - 빠른 global coverage
  - **가장 중요한 insight**

    - **LDPC가 가능한 이유**

      - 이동 구조 (shift)
    - **고밀도 가능 이유**

      - multiple logical per block
    - **빠른 syndrome 이유**

      - 병렬 shift

**📌 Syndrome Extraction (진짜 실행 루틴)**

- - 이게 실제 “한 사이클”
  - **한 사이클 (SEC)의 본질**

|  |
| --- |
| 1. ancilla 준비  2. data 옆으로 이동  3. 2-qubit gate 수행  4. 다시 이동  5. 반복  6. 마지막에 측정 |

- - **핵심 특징**

    - 중요한 건 gate가 아니라 이동 → gate → 이동 → gate
  - **중요한 포인트**

    - 모든 것이 “정렬(alignment)” 문제

      - ancilla가 data 옆에 와야 gate 가능
      - 그래서 계속 이동

**✅ X. Loss & Leakage 문제**

- - 이건 이 구조에서 제일 현실적인 문제
  - **두 가지 문제**

    - **1) Loss (큐비트 사라짐)**

      - 완전히 없어짐
    - **2) Leakage (상태 이탈)**

      - 계산 공간 밖으로 나감

**📌 해결 전략 (핵심)**

- - **Beacon qubit**

    - data 옆에 항상 붙어 있음

      - data ↔ beacon
    - loss 발생하면 beacon으로 감지
  - **즉시 감지**

    - 매 layer마다 체크

      - gate → 바로 loss 검사
    - **왜 중요?**

      - 안 하면 loss → 얽힘 통해 확산 → catastrophic failure
  - **Local reservoir (즉시 교체)**

    - 여분 qubit 준비

      - lost → 바로 교체
    - **핵심**

      - 중앙에서 공급 ❌
      - 로컬에서 즉시 교체 ⭕
  - 아래 표는 어떤 순서로 검사할지 미리 정해둔 스케줄표다.

    - 어떤 ancilla가 언제 어떤 data를 검사할지 정의한 것

**📌 Syndrome extraction 시뮬레이션**

- - 아래 그림은 한 번의 syndrome extraction이 실제로 어떻게 진행되는지 시뮬레이션

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTc3/MDAxNzc3MTY4NTgzMjc5.UfuLf5zqgtzG92DxZEazV_RCkiWha3AHCt3qIpS6PJYg.mWk7SNCJ0ZzREsq1s091OLKBSFxrs_zFLKpcmPAYblcg.PNG/image.png?type=w800)](#)

- - **정의**

    - **🟢 초록 점** → ancilla
    - **⚫ 진한 점** → data qubit
    - **🔵 / 🔴** → 특정 ancilla (X / Z 체크용)
  - **전체 흐름**

    - 이 그림은 **round 1 ~ 4** 진행을 보여준다
    - **Round 1**

      - 상태:

        - A1 (no shift)
      - 의미:

        - ancilla가 이미 data 옆에 있음
        - 이동 없음
      - 수행:

        - X ancilla → CX
        - Z ancilla → CZ
    - **Round 2**

      - 상태:

        - A2 (0,1,0) shift
      - 의미:

        - medium-ring 방향으로 이동
      - 결과:

        - ancilla가 **다른 data 옆으로 이동**
      - 수행:

        - 다시 gate 수행
    - **Round 3**

      - 상태:

        - B1 (1,2,0) shift
      - 의미:

        - long-ring shift 발생
      - 결과:

        - ancilla가 완전히 다른 블록으로 이동
    - **Round 4**

      - 상태:

        - B2 (0,1,1) shift
      - 의미:

        - short + medium shift 조합
  - **핵심 패턴 (진짜 중요한 부분)**

    - 이걸 단순화하면:

      - 정렬 → gate → 이동 → 정렬 → gate → 이동
    - **핵심 구조**

      - ancilla는

        - 한 자리에서 여러 data를 검사 ❌
        - 이동하면서 여러 data를 검사 ⭕
  - **왜 이렇게 하냐?**

    - **❌ 기존 방식**

      - ancilla를 여러 개 둠
    - **⭕ 여기**

      - ancilla는 적게
      - 대신 이동
    - 결과

      - resource 절약 + 병렬성 유지

**📌 메모리 성능**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfNzkg/MDAxNzc3MTY5NjA5NTUy.ZT3U5ebCjPWBcKwL2ay8vm9FSkZ5VH4ZOT6Cj7KXU1Ig.8A2w_yT2MxIHAx84Hi0fgvfGszHzx7Kv3JBPtMfWdewg.PNG/image.png?type=w800)](#)

- - **주요 결과**

    - **Logical error rate**

      - **loss + leakage 포함해도 10****-11** **유지**
      - physical qubit 포함:

        - data
        - ancilla: syndrome extraction
        - beacon: loss correction
        - reservoir: reloading
    - **Loss distribution**

      - 한 사이클에서 qubit 몇 개 잃는지
      - **핵심**

        - 0개 손실 ≈ 99.9%
        - 1개 손실 ≈ 매우 낮음
        - 2개 이상 → 극히 희귀
      - **의미**

        - rare event 모델

**📌 Leakage 처리**

- - **방법**

    - teleportation 기반

      - **data → ancilla로 이동**
      - → measurement
      - → reset
  - **의미**

    - 직접 고치는 게 아니라 새 qubit로 갈아탐

**📌 성능 결과**

- - **Loss 영향**
