# 미 국방부가 꿈꾸는 우주의 인터넷

Original Naver post: https://blog.naver.com/4-fire/224278123534

**✅ 서론 — DIU PROJ00651과 DARPA Space-BACN이 의미하는 것**

- - 2026년 미국 국방부 산하 Defense Innovation Unit(DIU)는 **PROJ00651**이라는 이름의 차세대 군용 레이저 통신 프로젝트를 공개했다.

[**DIU Submission Opportunity - Point Break**

Submit your commercial solution to this national security challenge

www.diu.mil](https://www.diu.mil/work-with-us/submit-solution/PROJ00651)

- - 동시에 DARPA는 기존에 추진해 오던 Space-BACN 프로그램을 DIU 단계로 넘기며, 연구·시제품 수준이었던 기술을 실제 궤도(on-orbit) 실증과 operational deployment 단계로 전환하기 시작했다.

www.darpa.mil](https://www.darpa.mil/news/2022/low-earth-orbit-translator)

- - 이 흐름은 단순한 “위성 레이저 통신 개발” 정도로 보면 본질을 놓치게 된다.
  - 핵심은:

    - **RF 중심의 군 네트워크를 광 기반(Optical) 우주 메쉬 네트워크로 전환하려는 미국 국방부의 장기 전략**이라는 점이다.
  - 현재 군 통신은 대부분 RF(Radio Frequency)에 의존한다.
  - 하지만 현대 전장에서는:

    - 전자전(EW)
    - 재밍(jamming)
    - 스푸핑(spoofing)
    - SIGINT 감청
    - anti-access / area denial(A2/AD)
  - 등이 급격히 고도화되고 있다.
  - 특히:

    - 저궤도 위성 증가
    - AI 기반 ISR 데이터 폭증
    - 실시간 sensor fusion
    - multi-domain operation
    - JADC2 개념 확산
  - 으로 인해 기존 RF 링크만으로는 미래 전장의 데이터 수요를 감당하기 어렵다는 인식이 커지고 있다.
  - 이 때문에 미 국방부는:

    - Low Probability of Intercept (LPI)
    - Low Probability of Detection (LPD)
    - 초고대역폭
    - anti-jam 특성
    - ultra-low latency backbone
  - 을 제공할 수 있는 **Laser Communications(Lasercom)** 으로 이동하려 하고 있다.
  - 그리고 이 프로젝트는 단순 SATCOM 업그레이드가 아니라:

    - orbital optical internet
    - military optical mesh
    - AI battlespace backbone
    - SDA PWSA Transport Layer
    - Golden Dome
    - JADC2
    - future quantum networking infrastructure
  - 로 이어지는 거대한 흐름의 일부다.

**✅ RF 기반 군 네트워크의 한계**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMTIx/MDAxNzc4MTUzOTE0Njg3.OlNmaxEwRze93G8ki8X7S5_oEgEvhrrIE6bBERPGOPog.6g7tGnTcCvevczhDhlskGH4gopwOHCKxDdRyQ1iOb9og.PNG/image.png?type=w800)](#)

- - 과거 군 네트워크 구조는 기본적으로 RF 중심이었다.
  - 대표적으로:

    - SATCOM
    - tactical radio
    - Link-16
    - airborne relay
    - microwave backhaul
  - 등이 핵심이었다.
  - 하지만 이 구조는 몇 가지 치명적 한계를 가진다.

**📌 재밍에 취약**

- - RF는 전파가 넓게 퍼진다.
  - 즉:

    - 탐지가 쉽고
    - 위치 노출 가능성이 높으며
    - 재밍 장비로 간섭 가능
  - 하다.
  - 현대 전장에서는 수십~수백 달러 수준의 저가 jammer조차 tactical RF link를 방해할 수 있다.

**📌 대역폭 한계**

- - ISR, SAR, hyperspectral imaging, AI inference 데이터가 폭증하면서 기존 RF 기반 SATCOM은 병목이 발생하고 있다.
  - 특히:

    - 실시간 targeting
    - drone swarm coordination
    - distributed sensing
    - AI battlefield fusion
  - 같은 구조에서는 massive east-west traffic이 발생한다.

**📌 우주 네트워크 확장성 부족**

- - RF는 spectrum scarcity 문제를 가진다.
  - 즉:

    - 주파수 충돌
    - licensing
    - interference
    - congestion
  - 문제가 갈수록 심해진다.
  - 특히 수천~수만 개 LEO 위성이 등장하는 환경에서는 RF만으로 scalable mesh를 만들기 어렵다.

**✅ 왜 Lasercom인가?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMzMg/MDAxNzc4MTUzOTMxOTky.BBotal5Gk_COE9obT60MohyR1GpwrDaxUP9ldlmXroUg.SG7ngK1gNr3ifdsOgZk1QuwsyP631pbt__nluRRBSy0g.PNG/image.png?type=w800)](#)

- - 이 때문에 미 국방부는 광통신으로 이동하기 시작했다.
  - Lasercom의 장점은 다음과 같다.

|  |  |
| --- | --- |
| **특성** | **의미** |
| Narrow Beam | 탐지 어려움 |
| LPI/LPD | 저탐지·저감청 |
| Massive Bandwidth | 초고속 데이터 |
| Anti-Jam | RF 대비 재밍 어려움 |
| Low Latency | 실시간 데이터 전달 |
| Directionality | point-to-point secure link |

> ***“전장의 인터넷 백본”을 RF에서 optical로 바꾸려는 것이다***

**✅ DIU PROJ00651의 핵심 구조**

- - DIU는 프로젝트를 크게 두 개의 LOE(Line of Effort)로 나눴다.

|  |  |
| --- | --- |
| **LOE** | **목표** |
| LOE 1 | Multi-Waveform Optical Terminal |
| LOE 2 | Airborne ↔ pLEO Optical Network |

**✅ LOE 1 — Multi-Waveform Optical Terminal**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMTQy/MDAxNzc4MTUzOTU5ODU3.YFY50cC5I__uq38z7dUAwXK7leSzNe10OQBKyjWZhLsg.9Av6dZhFk7H555meLVp714q9PvULCYP3dprVv2_U3rEg.PNG/image.png?type=w800)](#)

- - 이 부분의 핵심 목표는 하나의 Optical Communication Terminal(OCT)이 여러 광통신 프로토콜을 지원하게 만드는 것이다.
  - 쉽게 말하면:

    - 현재는 각 constellation과 기관마다 사용하는 lasercom 언어가 다르다.
    - 예:

      - SDA 3.2
      - SDA 4.0
      - LCRD
      - OpenZR+
      - JLIS/OIC2
    - 등이다.
  - 문제는 이들이 서로 호환되지 않는다는 점이다.
  - 즉:

    - 위성 A ↔ 위성 B
    - 군 위성 ↔ 상업 위성
    - 공중 플랫폼 ↔ 우주 플랫폼
  - 간에 optical interoperability가 매우 제한적이다.

---

**✅ 이것은 “광통신용 Cisco Router”를 만들겠다는 의미******

- - DIU의 철학은 매우 명확하다.
  - 현재 우주 광통신은 **constellation마다 다른 proprietary network**상태다.
  - 즉:

    - vendor lock-in
    - isolated mesh
    - stovepipe architecture
  - 문제가 심하다.
  - DIU가 원하는 것은 **하나의 광단말이 여러 optical waveform을 동적으로 지원**하는 구조다.
  - 즉:

    - optical SDN
    - orbital MPLS
    - space routing layer
    - multi-waveform interoperability
  - 개념이다.

**✅ 핵심 파형들(Waveforms)의 의미******

**📌 SDA 3.2**

- - Space Development Agency의 Tranche 3 핵심 optical 표준.
  - 목적:

    - PWSA 내 optical ISL(inter-satellite link)
    - LEO transport layer
    - tactical mesh interoperability
  - 즉 현재 군용 실전 표준에 가까운 포지션이다.

**📌 SDA 4.0**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMTg3/MDAxNzc4MTUxMTE5MjY4.y_peT2Nc2y83Jo0ndQg7ecib_220ILFhjC3vX1oFAksg.E9TaimFLhsRDAtscqvdrb5qKlfkWDlXJrQ2IELIGwI8g.PNG/image.png?type=w800)](#)

- - SDA 3.2의 확장판.
  - 특징:

    - longer range waveform
    - MEO integration
    - missile tracking architecture 연계
  - 즉 미래 multi-orbit network까지 고려한 구조다.

**📌 LCRD**

- - NASA의 Laser Communications Relay Demonstration 계열.
  - 성격은 군용 tactical mesh보다는:

    - GEO optical relay
    - atmospheric compensation
    - optical relay operations
  - 쪽에 가깝다.
  - 즉 NASA식 광중계 운용 유산이다.

**📌 OpenZR+**

- - 이건 우주 전용이 아니라 commercial coherent optical transport 계열이다.
  - 즉:

    - data center interconnect
    - metro optical network
    - coherent pluggable optics
    - 400G/800G optical transport
  - 등과 연결된다.
  - DIU가 OpenZR+를 포함한 이유는 매우 중요하다.

    - 이는 **우주망도 결국 terrestrial cloud/AI/datacenter backbone과 연결될 것**이라는 의미다.

**📌 JLIS/OIC2**

- - DIU 공고에서 primary waveform으로 지정된 핵심 군용 optical interoperability 계열.
  - 즉, 이번 프로젝트의 “군용 기준 언어”에 해당한다.

**✅ 왜 서로 호환이 안 되는가?**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMTg5/MDAxNzc4MTUzOTg2Nzkz.zxrT9e6i9vrTCKkYxIDyy2cYE9xe1r5FsrFCJaF5F5wg.JWUNtRIFVvHJIdkdZexkR-jwDHh5UYT4KEjR4NwSmPEg.PNG/image.png?type=w800)](#)

- - 이건 단순 “파장이 달라서” 수준이 아니다.

**📌 Optical Physics 차이**

- - 각 시스템은:

    - wavelength
    - beam divergence
    - detector sensitivity
    - optical filtering
    - transmitter power
  - 등이 다를 수 있다.
  - 즉 물리적으로 신호를 제대로 수신하지 못할 수 있다.

**📌 Modem 구조 차이**

- - 핵심 문제다.
  - 광신호가 도착해도:

    - modulation
    - coding
    - synchronization
    - framing
    - FEC
    - timing recovery
  - 가 다르면 데이터 해석이 안 된다.
  - 즉, 같은 광섬유를 꽂아도 Ethernet과 Fibre Channel이 서로 안 통하는 것과 유사하다.

**📌 PAT 절차 차이**

- - Lasercom 최대 난제.

    - PAT = Pointing Acquisition Tracking
    - 레이저는 RF처럼 퍼지지 않는다.
  - 즉:

    - 수백~수천 km 거리
    - 초고속 이동체
    - 대기 흔들림
  - 상황에서 상대 단말을 정확히 조준해야 한다.
  - 문제는:

    - beacon sequence
    - acquisition timing
    - tracking loop
    - re-acquisition procedure
  - 등이 업체별로 다를 수 있다는 점이다.
  - 즉 같은 파장을 써도 링크가 안 잡힐 수 있다.

**📌 Network Layer 차이**

- - 광 링크가 잡혀도:

    - routing
    - scheduling
    - encryption handoff
    - make-before-break
    - link management
  - 등이 다르면 end-to-end network가 성립하지 않는다.

**✅ 핵심 기술 — MCP와 FPGA 기반 Software Defined Modem**

**✅ 가장 어려운 기술 — PAT**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA1MDdfMTYz/MDAxNzc4MTU0MDMxOTQ5.41EM7vRwnRB6g81zRQX7SluzWZFHSaD04q3UxS1uMQUg.w8267iJrBPkdHKNFLjM_xoL5n3TPAUgiRV1Uq4XyU5Qg.PNG/image.png?type=w800)](#)

- - 이 구조에서 최대 난제는 PAT다.
  - 레이저는 RF처럼 broadcast되지 않는다.
  - 즉:

    - aircraft가 움직이고
    - 위성이 움직이고
    - 대기가 흔들리는 상황
  - 에서 laser beam alignment를 유지해야 한다.
  - DIU가 중요하게 보는 항목:

|  |  |
| --- | --- |
| **항목** | **의미** |
| Link Acquisition | 링크 시작 |
| Link Duration | 유지 시간 |
| Re-Acquisition | 링크 복구 |
| Turbulence Mitigation | 대기 보정 |
| Data Rate | 처리량 |

- - 특히, 링크 손실 후 수분 내 재연결같은 operational resilience를 매우 중요하게 본다.

**✅ “Make-Before-Break”의 의미**

- - DIU는 2030년까지 seamless global lasercom coverage를 언급한다.
  - 그리고 핵심 표현이 make-before-break architecture이다.
  - 이건:

    - 현재 링크가 끊기기 전에
    - 다음 위성과 미리 연결
  - 하는 carrier-grade handoff 구조다.
  - 즉:

    - MPLS FRR(Fast Reroute)
    - SD-WAN failover
    - cellular handover
  - 의 우주 버전이다.

---

**✅ DARPA Space-BACN의 등장******

- - 이 프로젝트의 직접적 전신이 바로 2022냔에 시작되었던 Space-BACN이다.
  - 정식 명칭:

    - **Space-Based Adaptive Communications Node**
  - DARPA의 핵심 문제의식은 단순했다.

    - **“왜 constellation끼리 연결이 안 되는가?”**였다.
  - 즉:

    - Starlink
    - Kuiper
    - SDA
    - military SATCOM
  - 등이 서로 isolated optical island 상태라는 것이다.

**✅ Space-BACN의 핵심 철학******

- - DARPA는 새로운 단일 표준을 만들려 한 것이 아니다.
  - 핵심 개념은 Tailorable Interoperability였다.
  - 즉, 모두 하나 규격으로 통일이 아니라, 서로 다른 네트워크를 연결하는 우주용 브리지를 만들겠다는 것이다.

---

**✅ Mosaic Warfare와의 연결******

- - 이 철학은 DARPA의 Mosaic Warfare와 연결된다.
  - 과거 군 구조:

    - 센서
    - 무기
    - 통신
    - 컴퓨팅
  - 을 하나 플랫폼에 넣는 monolithic architecture였다.
  - DARPA는 이를 비효율적이라 본다.
  - 대신, **필요한 순간 서로 다른 자산을 동적으로 조합**하는 구조를 원한다.
  - 즉:

    - 위성
    - UAV
    - ISR
    - relay
    - cloud node
  - 를 실시간으로 orchestration하는 구조다.

---

**✅ MINC (Mission-Integrated Network Control) 프로그램과의 관계**

- - DARPA는 또 다른 프로그램인 MINC를 언급한다.
  - MINC는:

    - resource broker
    - network path selector
    - orchestration layer
  - 역할이다.
  - DARPA는 미래 전장을 "순간적으로 조합되는 네트워크"로 보기 시작했다.

    - 즉, 위성의 센서, 저 UAV의 relay, 함정의 weapon system을 실시간으로 조합하는 구조다.
    - 문제는 "누구를 누구와 연결할지"를 실시간으로 판단해야 하는데,
    - 여기서 등장하는 것이 MINC다.
  - 즉, MINC가 **“어떤 위성과 어떤 플랫폼을 연결할지”**결정하고,
  - Space-BACN은 **“서로 다른 네트워크를 실제 연결”**하는 역할이다.
