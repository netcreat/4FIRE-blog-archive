# Zero Trust: AI 에이전트와 양자컴퓨팅 시대의 새로운 보안 원칙

Published: 2026-03-16T21:24:39.011000+09:00

Original Naver post: https://blog.naver.com/4-fire/224218780692

---

- - 최근 양자컴퓨팅 업계에서 흥미로운 뉴스가 보도되었다.
  - IonQ와 Xanadu가 미국 메릴랜드 대학 기반 연구기관인 ARLIS와 함께 **Zero Trust 기반의 양자컴퓨팅 보안 연구에 협력한다는 발표**가 나온 것이다. 이 협력은 양자컴퓨터 시스템에 Zero Trust 아키텍처를 적용하여, 하드웨어·소프트웨어·네트워크 전반에 걸쳐 접근을 지속적으로 검증하는 보안 모델을 연구하는 것을 목표로 한다.
  - 표면적으로 보면 이는 단순한 보안 연구 협력처럼 보일 수 있다. 그러나 조금만 들여다보면 이 협력은 단순히 양자컴퓨터 보안을 강화하는 문제를 넘어, **미래의 디지털 인프라가 어떤 방식으로 설계될 것인가**라는 훨씬 큰 질문과 연결되어 있다.
  - 특히 최근 몇 년 사이 인공지능 기술이 급격히 발전하면서 ‘에이전트(Agent)형 AI’가 빠르게 등장하고 있다. 이제 AI는 단순히 질문에 답하는 도구가 아니라, 스스로 계획을 세우고 도구를 호출하며 실제 행동을 수행하는 **자율적 소프트웨어 행위자**로 발전하고 있다. 이러한 변화 속에서 미국 정부도 새로운 표준 논의를 시작했다. 실제로 NIST는 2026년 2월 **AI Agent Standards Initiative**를 발표하며, 자율적으로 행동하는 AI 시스템의 **보안·신원(identity)·상호운용성에 대한 표준 논의**를 공식적으로 시작했다.
  - 이와 동시에 AI 에이전트의 보안 문제 역시 빠르게 부각되고 있다. 최근 여러 연구와 보고서들은 AI 에이전트가 실제 서비스와 시스템에 접근하기 시작하면서 **데이터 유출, 권한 남용, 프롬프트 인젝션과 같은 새로운 공격 표면이 등장하고 있다**고 경고한다.
  - 또한 최근 공개된 **OpenClaw와 같은 개인용 AI 에이전트 시스템**은 이러한 문제를 더욱 현실적인 이슈로 만들었다. 일부 사례에서는 AI 에이전트가 사용자의 명시적 지시 없이 서비스 계정을 생성하거나 활동을 수행하는 사례까지 보고되면서, **AI가 실제로 행동하는 시스템이 되었을 때 책임과 보안을 어떻게 관리할 것인가**라는 문제가 본격적으로 논의되기 시작했다.
  - 이러한 흐름 속에서 등장한 것이 바로 **Zero Trust**라는 개념이다.
  - Zero Trust는 단순한 보안 기술이 아니라, “아무것도 기본적으로 신뢰하지 않고 모든 접근을 지속적으로 검증한다”는 철학을 기반으로 하는 새로운 보안 아키텍처이다. 그리고 흥미롭게도 이 개념은 이제 단순한 기업 보안을 넘어 **AI 에이전트, 클라우드, 그리고 양자컴퓨터와 같은 미래 컴퓨팅 인프라 전체에 적용되는 기본 원칙**으로 확장되고 있다.
  - 이번 글에서는 다음 질문을 중심으로 살펴보고자 한다.

    - Zero Trust란 무엇인가
    - 왜 지금 AI 에이전트와 함께 이 개념이 다시 주목받고 있는가
    - IonQ와 Xanadu가 참여한 Zero Trust 양자 보안 연구는 무엇을 의미하는가
  - 그리고 이 협력이 **미래 AI와 양자컴퓨팅 인프라의 보안 구조를 어떻게 바꾸게 될지**를 함께 살펴보겠다.

**✅ 출발점: 왜 Zero Trust가 등장했는가**

- - 과거 IT 보안은 기본적으로 이런 철학이었다.

    - 회사 내부망은 상대적으로 신뢰
    - 외부는 위험
    - 경계에 방화벽을 두고 보호
  - 즉, **“안과 밖”을 나누는 perimeter 보안**이 기본이었다.
  - 그런데 환경이 바뀌었다.

    - 클라우드 사용 증가
    - 원격근무 보편화
    - SaaS 확산
    - 내부자 위협 증가
    - 계정 탈취와 lateral movement 문제 확대
  - 이제는 “회사 내부”라는 개념 자체가 흐려졌다.
  - 그래서 나온 철학이 **Zero Trust**이다.
  - 핵심은 한 문장이다.

> ***아무도 기본적으로 신뢰하지 말고, 모든 요청을 계속 검증하라.***

---

**✅ NIST SP 800-207: Zero Trust를 체계화한 문서**

- - [Zero Trust Architecture](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-207.pdf)
  - 이 철학을 가장 체계적으로 정리한 대표 문서가 바로 **2020년에 제정된 NIST SP 800-207 (Zero Trust Architecture)** 이다.
  - 이 문서의 핵심 메시지는 다음과 같다.
  1. **신뢰의 기준은 네트워크 위치가 아니다**

     - 내부망에 있다고 해서 신뢰할 수 없고, 외부라고 해서 무조건 차단하는 것도 아니다.
  2. **보호 대상은 네트워크가 아니라 리소스다**

     - 보호해야 하는 것은 서버, 데이터, 애플리케이션, 서비스다.
  3. **접근은 매번 검증해야 한다**

     - 사용자, 기기, 위치, 시간, 행동 패턴 등을 종합해 매 요청을 평가한다.
  4. **최소 권한만 부여한다**

     - 필요한 권한만 잠깐 주고, 광범위한 권한은 주지 않는다.
  5. **로그와 모니터링이 필수다**
  - 접근과 행동을 모두 기록하고, 이상 행동을 감지해야 한다.
  - 즉, Zero Trust는 “제품”이 아니라 **identity + policy + monitoring + enforcement로 구성된 아키텍처**다.

**📌 Zero Trust Architecture 핵심 구성요소**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjAzMTZfOTcg/MDAxNzczNjYyNDMzODEw.gkozyQaZ901PoF70e6wLFFKTByPu5wEhKqmorLpFkhgg.dAh_1nBAyeYcWzk0tkTJriWmFRvVKbV9rgQehGCk-yEg.PNG/image.png?type=w800)](#)

- - NIST는 ZTA를 다음 구조로 설명한다.

    - **Policy Engine (PE)**

      - 접근 여부를 판단하는 엔진
      - 판단 요소

        - 사용자 identity
        - device 상태
        - 행동 패턴
        - 위험 점수
    - **Policy Administrator (PA)**

      - Policy Engine의 결정을 실제 시스템에 적용
      - 예

        - 접근 허용
        - 접근 차단
        - 인증 요구
    - **Policy Enforcement Point (PEP)**

      - 실제 접근을 제어하는 지점
      - 예

        - gateway
        - proxy
        - firewall
  - 즉 구조는 다음과 같다.

|  |
| --- |
| User / Device  ↓  Policy Enforcement Point  ↓  Policy Engine  ↓  Resource |

- - 이 구조가 Zero Trust의 핵심이다.

**📌 Zero Trust 판단에 사용하는 데이터**

- - 접근 여부는 여러 신호를 이용해 판단한다.
  - 대표적인 요소

    - 사용자 identity
    - device 상태
    - 위치
    - 시간
    - 행동 패턴
    - threat intelligence
  - 즉 **context-aware security**다.

**📌 Zero Trust 구현 모델 (3가지)**

- - NIST는 세 가지 구현 방식을 제시한다.

    1. **Identity-based architecture**

       - Identity provider 중심
       - 예

         - MFA
         - SSO
         - IAM
    2. **Micro-segmentation architecture**

       - 네트워크를 작은 영역으로 분리
       - 효과

         - 내부 공격 확산 방지
         - lateral movement 차단
    3. **Software Defined Perimeter (SDP)**

       - 사용자가 **특정 서비스에만 접근**
       - 기존 VPN과 다른 점
       - VPN

         - 접속 → 내부망 전체 접근
       - Zero Trust

         - 접속 → 특정 앱만 접근

**📌 Zero Trust가 해결하려는 보안 문제**

- - 이 모델은 다음 공격을 막기 위해 등장했다.
  - 대표 공격

    - credential theft
    - insider attack
    - lateral movement
    - supply chain 공격
  - Zero Trust는

    - 최소 권한
    - 지속 검증
    - micro-segmentation
  - 으로 공격 확산을 제한다.

**✅ 기술적으로 Zero Trust는 어떻게 구현되는가**

- - Zero Trust는 개념만 있는 것이 아니라 실제 구현 구조가 있다.
  - 핵심 흐름은 이렇다.
  - **사용자/기기 요청**

    - → **정책 판단**
    - → **접근 허용 또는 차단**
    - → **행동 지속 모니터링**
  - 기술적으로는 보통 다음 요소들이 들어간다.

    1. **Identity 기반 인증**

       - MFA
       - SSO
       - IAM
       - 인증서 기반 신원 확인
       - Provider

         - Okta
         - Microsoft Entra ID
         - Ping Identity
    2. **Device posture 검증**

       - OS 패치 상태
       - 보안 솔루션 상태
       - 기기 인증서
       - 관리된 디바이스 여부
       - 대표 솔루션

         - CrowdStrike
         - Micorosoft Defender
         - VMware Workspace ONE
    3. **ZTNA**

       - 기존 VPN처럼 내부망 전체를 열어주는 것이 아니라,
       - 특정 애플리케이션에만 접근을 허용한다.
       - 대표 기술

         - Zscaler
         - Cloudflare
         - Palo Alto Networks
    4. **Micro-segmentation**

       - 내부 서버들끼리도 자유롭게 통신하지 못하게 잘게 나눈다.
       - 대표 기술

         - Illumio
         - VMware NSX
    5. **Continuous verification**

       - 한 번 로그인했다고 끝나는 것이 아니라,
       - 행동 중에도 계속 재평가한다.
    6. **Audit / SIEM / Analytics**

       - 누가, 언제, 어디서, 무엇을 했는지 전부 남긴다.
  - 실제 기업 환경 구현 예

|  |
| --- |
| User laptop  ↓  MFA 인증  ↓  device posture check  ↓  ZTNA gateway  ↓  policy engine  ↓  application access |

- - 이것을 AI / Quantum 환경에서 쓰면,

    - AI agents

      - → identity verification
      - → tool permission
      - → API access control
    - quantum computers

      - → user identity
      - → job authorization
      - → compute access
    - cloud HPC
    - 즉 사용자, AI, 장비 모두 동일한 정책으로 관리하게 된다.
  - 즉 Zero Trust는 **“로그인 보안”이 아니라 “행동 통제와 지속 검증”의 구조**다.

**✅ 여기서 왜 AI Agent가 연결되는가**

[![](https://dthumb-phinf.pstatic.net/?src=%22https%3A%2F%2Fwww.nist.gov%2Fsites%2Fdefault%2Ffiles%2Fstyles%2Fsocial%2Fpublic%2Fimages%2F2024%2F04%2F16%2Fshutterstock_695169133.jpg%3Fitok%3DuC3iYMG_%22&type=ff500_300)](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure)
[**Announcing the "AI Agent Standards Initiative" for Interoperable and Secure Innovation**

The Initiative will ensure that the next generation of AI is widely adopted with confidence, can function securely on behalf of its users, and can interoperate smoothly across the digital ecosystem.

www.nist.gov](https://www.nist.gov/news-events/news/2026/02/announcing-ai-agent-standards-initiative-interoperable-and-secure)

- - 이 지점에서 최근 NIST의 **AI Agent Standards Initiative**가 연결된다.
  - 기존 AI는 질문에 답하는 수준이었다.
  - 하지만 에이전트 AI는 다르다.

    - 목표를 이해하고
    - 계획을 세우고
    - 도구를 호출하고
    - 실제 행동을 수행하고
    - 결과를 보고 다시 수정한다
  - 즉, **행동하는 소프트웨어**다.
  - 예를 들면:

|  |  |
| --- | --- |
| **기존 AI** | **에이전트 AI** |
| 이메일 초안 작성 | 이메일 보내기 + 캘린더 예약 |
| 코드 생성 | 코드 작성 + 테스트 + 배포 |
| 분석 보고 | 데이터 수집 → 분석 → 자동 의사결정 |

- - 이 순간부터 AI는 단순 모델이 아니라 **실제 시스템에 영향을 주는 행위자(actor)** 가 된다.
  - 그러면 같은 질문이 생긴다.

    - 이 에이전트는 누구인가
    - 어떤 권한을 가졌는가
    - 어떤 도구를 쓸 수 있는가
    - 어떤 행동을 했는가
    - 누가 책임지는가
  - 이게 바로 Zero Trust 문제와 정확히 겹친다.
  - **AI Agent에 필요한 Zero Trust적 요소**

    - agent identity
    - authorization
    - tool access control
    - action logging
    - policy enforcement
    - continuous validation
  - 즉, NIST가 AI Agent 쪽에서 고민하는 것은 사실상 **“Zero Trust를 AI 에이전트에 확장 적용하는 것”**에 가깝다.

**✅ 왜 이것이 양자컴퓨터와도 연결되는가**

- - 이제 양자컴퓨터를 보겠다.
  - 예전 양자컴퓨터는 실험실 장비에 가까웠다.
  - 하지만 지금은 점점 다음 구조로 이동하고 있다.

    - 클라우드 접속
    - 원격 job submission
    - 정부/연구기관/기업 사용자 접근
    - HPC와 연동
    - 향후 양자 네트워크 연결 가능성
  - 즉 양자컴퓨터도 더 이상 “랩 안의 고립된 장비”가 아니라 **네트워크로 연결된 compute resource**가 되고 있다.
  - 그러면 보안 질문이 똑같이 생긴다.

    - 누가 이 양자 시스템에 접근하는가
    - 어떤 job을 제출할 수 있는가
    - 어떤 데이터가 오가는가
    - 어떤 제어 시스템이 연결되는가
    - 클라우드와 어떻게 연동되는가
    - 다른 시스템과 연결될 때 어떻게 보호할 것인가
  - 이때도 기존 perimeter 보안만으로는 부족하다.
  - 결국 양자컴퓨터 역시 **Zero Trust 관점**으로 보게 된다.
  - 즉,

    - **AI Agent가 행동하는 행위자라면**
    - **양자컴퓨터는 보호해야 할 고가치 리소스**다.
  - 둘 다 Zero Trust 틀 안에 들어간다.

---

**✅ 여기서 ARLIS가 왜 등장하는가**

- - 이 지점에서 ARLIS가 중요해진다.
  - 사용자께서 헷갈렸던 부분이 바로 이것이다.

    - DARPA는 많이 들어봤는데
    - 왜 실제 Zero Trust 양자 보안 연구는 ARLIS가 하지?
  - 이걸 구조적으로 보면 명확하다.

**📌** **DARPA**

- - 국방부 산하 정부기관
  - 혁신 기술 프로그램 기획
  - 초기 연구 촉진
  - 자금과 프로그램 설계

**📌** **ARLIS**

- - University of Maryland 기반 UARC

    - UARC (University Affiliated Research Center)란?

      - 정부와 거의 준정부 기관처럼 협력한다.
      - 특징

        - 대학 소속 연구소
        - 정부 장기 연구 파트너
        - 국방 / 정보기관 프로젝트 수행
      - 대표 UARC

|  |  |
| --- | --- |
| **연구소** | **대학** |
| Johns Hopkins Applied Physics Laboratory | Johns Hopkins |
| MIT Lincoln Laboratory | MIT |
| Applied Research Laboratory for Intelligence and Security | University of Maryland |

- - ARLIS는 정보·보안 중심 응용 연구 수행

    - 정부/국방이 필요로 하는 보안 문제를 실제 시스템 수준에서 연구

- - 즉 아주 단순하게 말하면

    - **DARPA = 기술 개발을 촉진하는 쪽**
    - **ARLIS = 실제 적용 보안 연구를 수행하는 쪽**
  - 양자컴퓨터 Zero Trust 문제는 하드웨어의 기초 원리 연구가 아니라 “실제 인프라로 쓸 때 보안을 어떻게 설계할 것인가”의 문제다.
  - 그래서 ARLIS가 자연스럽게 중심에 온다.

---

**✅ ARLIS의 양자 Zero Trust 프로젝트 의미**

- - ARLIS가 진행하는 양자 관련 Zero Trust 프로젝트의 핵심은 단순하다.
  - SEQCURE (Securing Experimental Quantum Computing Usage in Research Environments)

    - 양자컴퓨터를 미래의 국가·국방 인프라로 사용할 수 있도록 보안 구조를 설계하는 것
  - ARLIS가 보는 미래 양자 인프라

|  |
| --- |
| Quantum Computer  │  Quantum Cloud  │  Quantum Network  │  Classical HPC  │  Government / Defense systems |

- - 여기서 중요한 포인트는 다음이다.

    1. **양자컴퓨터를 “중요 인프라”로 보기 시작했다**

       - 이건 단순 실험장비 취급이 아니라는 뜻이다.
    2. **NIST Zero Trust 철학을 양자 환경에 적용한다**

       - 즉, 양자컴퓨팅에도 동일한 보안 원칙을 넣겠다는 것이다.
    3. **향후 양자 네트워크, 클라우드, 정부 시스템 연계를 염두에 둔다**

       - 현재 문제만이 아니라 앞으로의 구조를 미리 설계하는 것이다.
  - 즉 ARLIS 프로젝트는 양자 보안의 개별 기능 연구가 아니라 **양자 인프라 보안의 아키텍처 연구**다.

- - 이 부분이 투자자 관점에서 중요하다.
  - IonQ 같은 회사가 단순히 큐비트 수 경쟁만 하는 기업이라면, 이런 Zero Trust·보안·국방 인프라 논의에 깊게 연결될 이유가 적다.
  - 하지만 IonQ는 스스로를 점점 더

    - 양자 컴퓨팅
    - 양자 네트워킹
    - 보안
    - 정부 인프라
    - 클라우드 연동
  - 까지 아우르는 방향으로 포지셔닝하고 있다.
  - 즉, 단순 QPU 공급자가 아니라 **미래 양자 인프라의 구성요소 제공자**로 가려는 것이다.
  - 그래서 ARLIS 같은 기관과의 Zero Trust 프로젝트는 “보안 프로젝트 하나 추가”가 아니라 회사가 어디로 가고 있는지를 보여주는 신호로 볼 수 있다.

**✅** **맺음말**

- - 지금까지 살펴본 것처럼 **Zero Trust**는 단순한 보안 기술이나 특정 기업의 제품 전략이 아니다. 그것은 **디지털 인프라가 변화하면서 자연스럽게 등장한 새로운 보안 철학**에 가깝다.
  - 과거의 컴퓨팅 환경에서는 네트워크의 경계를 기준으로 내부와 외부를 구분하는 것이 가능했다. 하지만 클라우드, 원격 접속, 분산 시스템이 보편화되면서 이러한 경계는 점점 의미를 잃어가고 있다. 이제는 사용자가 어디에 있든, 어떤 장치를 사용하든, 심지어 사람이 아닌 소프트웨어가 행동하더라도 **모든 접근을 지속적으로 검증해야 하는 환경**이 되었다.
  - 이 변화는 특히 **AI 에이전트와 양자컴퓨팅**이 등장하면서 더욱 분명해지고 있다. AI 에이전트는 단순히 정보를 생성하는 모델을 넘어 실제 시스템을 호출하고 데이터를 이동시키며 작업을 수행하는 행위자(actor)가 되고 있다. 동시에 양자컴퓨터 역시 실험실 장비에서 벗어나 클라우드와 네트워크를 통해 접근되는 **고가치 컴퓨팅 자원**으로 변하고 있다. 이러한 환경에서는 더 이상 “내부 시스템”이라는 개념만으로 보안을 설명할 수 없다.
  - 이러한 맥락에서 IonQ와 Xanadu가 참여한 Zero Trust 기반 연구는 단순히 양자컴퓨터 보안을 강화하는 프로젝트라기보다는, **AI와 양자컴퓨팅이 결합된 미래 인프라를 어떻게 안전하게 운영할 것인가**라는 질문에 대한 초기 실험에 가깝다. 그리고 그 중심에는 NIST가 제시한 Zero Trust 아키텍처와 AI Agent 보안 논의가 놓여 있다.
  - 물론 이러한 변화가 단기간에 완성될 가능성은 높지 않다. 기술은 항상 이상적인 구조보다 훨씬 복잡한 현실 속에서 발전해 왔다. 다만 한 가지 분명한 점은, **컴퓨팅 시스템이 점점 더 자율적으로 행동하고 서로 연결되는 시대에 보안의 기준 역시 함께 변화하고 있다는 사실**이다.
  - 어쩌면 지금 우리가 보고 있는 Zero Trust 논의는 단순한 보안 트렌드가 아니라, **AI와 양자컴퓨팅 시대의 디지털 질서를 새롭게 정의하는 과정의 시작**일지도 모른다.
