- - 2026년 8월 13일 미국 우주군 Space Systems Command(SSC)는 Amazon LEO for Government, Lockheed Martin, Northrop Grumman, Rocket Lab, York Space Systems 등 5개 기업을 Space Data Network(SDN) 구축을 위한 새로운 파트너로 선정했다.
  - 각 기업은 두 종류의 계약을 받는다.

    - $10M 규모의 fixed-price contract

      - 6~9개월 동안 ground-to-space 및 space-to-space multi-vendor interconnectivity를 실증한다.
    - $2M 규모의 OTA

      - 6개월 동안 Space Exchange Point(SEP) satellite의 개발 및 fielding을 시작한다.
  - 따라서 업체당 $12M, 총 $60M 규모다. 이번 사업의 목적은 단순히 위성 5대를 구매하는 데 있지 않다. 서로 다른 상업·군사 위성 시스템이 공통된 physical, electrical, data interface와 security protocol을 통해 SDN에 연결될 수 있는 기반을 만드는 것이 핵심이다.
  - 그런데 여기서 바로 의문이 생긴다.

**✅ SpaceX의 SDN Backbone과 이번 5개 기업의 차이**

**📌 SpaceX가 만드는 것은 Core Backbone이다**

- - Space Force는 SDN Backbone을 pLEO satellite constellation이 하나의 integrated network처럼 동작하는 구조라고 설명한다.
  - 이 네트워크는 다음 역할을 담당한다.

    - high-capacity data transport
    - low-latency transport
    - global tactical communications
    - broadband communications
    - sensor data backhaul
    - sensors와 shooters 간 연결
  - Space Force는 이를 USSF warfighting system의 foundational data backhaul layer로 규정하고 있다. 또한 SDA Transport Layer와 함께 LEO 영역의 hybrid mesh data network를 형성하도록 설계하고 있다.
  - 즉 SpaceX는 SDN이라는 전체 네트워크 안에서 대량의 데이터를 실어 나르는 core transport infrastructure를 담당한다.

**📌 이번 5개 기업은 SDN에 다른 네트워크를 붙인다**

- - 이번 계약은 성격이 다르다.
  - Space Force는 서로 다른 vendor system 사이에서 실제 데이터를 이동시키고, 이들이 SDN Backbone과 통신할 수 있음을 검증하려 한다.
  - 그리고 이를 실제 궤도에서 구현하기 위해 SEP라는 새로운 satellite node를 개발한다.
  - 구조를 단순화하면 다음과 같다.

|  |
| --- |
| Commercial Satellite Networks  ↓  Government Satellites  ↓  SDA Transport Layer  ↓  SEP  ↓  SDN Backbone  ↓  Ground / C2 / Shooter |

- - 즉 이번 사업은 또 하나의 독립적인 SDN Backbone을 만드는 계약이 아니라, 여러 네트워크를 기존 SDN Backbone과 연결하는 integration layer를 만드는 계약으로 보는 것이 적절하다.

---

**✅ SEP — 우주에 올라가는 네트워크 교환점**

**📌 SEP는 단순 광중계 위성이 아니다**

- - 이번 발표에서 가장 중요한 개념은 **Space Exchange Point**, 즉 SEP다.
  - SSC는 SEP를 orbital router라고 표현한다.

    - 서로 다른 commercial network와 government satellite system이 SDN Backbone에 직접 연결되도록 하는 specialized spacecraft다.
  - 지상의 네트워크에 비유하면 단순 광케이블이나 repeater보다는 router, gateway, Internet Exchange Point의 조합에 가깝다.
  - 서로 다른 네트워크들이 모두 같은 PHY나 같은 waveform을 사용할 필요는 없다.
  - 중요한 것은 각 네트워크 사이에서 데이터를 넘길 수 있는 공통 interface와 gateway가 존재하는 것이다.

**📌 기존 위성을 개조하는 개념은 아니다**

- - 여기서 중요한 구분이 필요하다.
  - 이번 사업은 이미 궤도에 올라간 모든 위성에 새로운 EST terminal을 사후 장착하는 개념이 아니다.

    - 궤도에 있는 위성에 새로운 telescope, laser transmitter, optical modem, PAT hardware를 추가하는 것은 현실적으로 불가능하다.
  - 대신 새로운 SEP spacecraft를 제작해 궤도에 올리고, 이 SEP가 기존 또는 미래 위성망과 SDN Backbone 사이를 연결하는 방향이다.
  - 즉 새로 만들어야 하는 것은 모든 constellation이 아니라 network-to-network gateway node다.

|  |
| --- |
| 기존 Commercial/Government Network  ↓  새로운 SEP  ↓  SDN Backbone |

- - 이라는 구조가 된다.

---

**✅ SEP의 핵심 통신장비 — EST란 무엇인가**

**📌 EST는 OISL 전체를 부르는 명칭이 아니다**

- - EST는 **Enterprise Space Terminal**의 약자다.
  - 광통신 전체나 OISL 전체를 포괄하는 일반명사가 아니라 **SSC가 추진하는 특정 optical communications terminal** 개발 프로그램이다.
  - SSC는 EST를 **long-range** **space optical communications terminal**로 정의하고 있으며, standardized enterprise waveform을 구현해 서로 다른 미래 DoD space system들이 직접 optical crosslink를 형성할 수 있도록 하는 것이 목적이다.
  - 즉 구조를 구분하면 다음과 같다.

    - OISL

      - Optical Inter-Satellite Link라는 통신 방식
    - OCT

      - OISL을 실제 구현하는 Optical Communications Terminal
    - EST

      - SSC가 개발하는 장거리 enterprise OCT 프로그램
    - SEP

      - EST 계열 optical payload와 routing 기능을 탑재할 수 있는 orbital gateway spacecraft

**📌 EST는 실제 레이저 통신을 사용한다**

- - EST는 RF terminal이 아니라 free-space optical communications terminal이다.
  - Space Force가 원하는 것은 low-SWaP-C의 장거리 laser terminal을 만들어 서로 다른 위성에 동일한 enterprise waveform을 구현하는 것이다. Phase 2에서는 CACI, General Atomics, Viasat이 선정됐다.
  - SSC는 EST가 Beyond Low Earth Orbit, 즉 bLEO 영역의 통신까지 염두에 둔다고 설명한다.

**✅ EST의 기술적 요구조건**

- - EST의 모든 세부 PHY specification이 공개된 것은 아니지만, 초기 공식 RFI를 통해 상당히 넓은 capability envelope를 확인할 수 있다.
  - RFI에서는 업체들에게 대략 다음 영역을 고려하도록 요구했다.

|  |  |
| --- | --- |
| **항목** | **EST 공개 요구·설계 범위** |
| 통신 방식 | Free-space optical / laser |
| 주요 용도 | Long-range space crosslink |
| 데이터율 | 약 300 Mbps ~ 20 Gbps |
| 최대 링크 거리 | 최대 약 80,000 km |
| 운용 | Symmetric / asymmetric Tx-Rx |
| Coding | DVB-S2, 5G-NR 등 검토 |
| 핵심 요구 | PAT, interoperability |
| 설계 방향 | Low SWaP-C, modular, scalable |
| 궤도 | LEO를 넘어 bLEO / multi-orbit |

- - 해당 수치는 최종 production specification이라기보다 초기 RFI에서 제시된 design envelope라는 점은 구분해야 한다. 그러나 Space Force가 EST를 단순한 LEO용 OCT보다 훨씬 긴 거리의 enterprise optical connectivity를 목표로 설계하고 있다는 점은 분명하다.

- - EST를 이해하기 위해서는 이미 SDA가 사용하고 있는 OCT Standard와 비교해야 한다.
  - 둘 다 laser communications terminal이지만 목표하는 mission이 다르다.

|  |  |  |
| --- | --- | --- |
| **구분** | **SDA OCT Standard 4.0** | **SSC EST** |
| 핵심 임무 | PWSA의 proliferated LEO mesh | 장거리 multi-orbit 연결 |
| 일반적인 설계 거리 | **5,500 km** 기준 requirement | 최대 약 **80,000 km** RFI envelope |
| 장거리 모드 | 20,000 km burst mode | bLEO 장거리 통신 |
| Continuous 데이터 | **최대 약 2.5 Gbps** Ethernet | **최대 20 Gbps** class 목표 |
| 장거리 속도 | 20,000 km에서 48.9 / 36.7 Mbps burst | 고속 장거리 enterprise link 목표 |
| Waveform | SDA OCT Standard | Standardized enterprise waveform |
| 주 역할 | 다수 LEO 노드간 mesh | LEO-MEO-GEO 계열 장거리 bridge |
| 우선순위 | 대량배치·상호운용·저비용 | 거리·성능·multi-orbit |

- - SDA OCT 4.0은 5,500 km 거리에서 remote receive aperture에 일정 수준 이상의 irradiance를 전달하도록 요구하며, continuous bidirectional Ethernet throughput을 최대 약 2.5 Gbps까지 지원하도록 규정한다.
  - 광학 규격도 상당히 구체적이다. 대표 채널은 1553.33 nm와 1536.61 nm이며, transmitter는 최소 2.5 W 이상의 최대 출력 capability를 가져야 한다. OOK-NRZ와 Manchester encoding을 지원하며, on-orbit software 및 firmware reprogramming도 요구한다.
  - SDA OCT 4.0은 장거리용 burst mode도 추가했다. 20,000 km에서 사용할 수 있지만 payload data rate는 48.9 Mbps 또는 36.7 Mbps까지 낮아진다. 장거리를 확보하기 위해 평균 데이터율을 희생하고 peak optical power를 높이는 방식이다.
  - 이 차이는 중요하다.

    - **EST가 SDA OCT의 단순한 상위 버전인 것이 아니다.**
  - SDA는 수백~수천 대의 proliferated LEO satellite에 넣을 수 있는 cost, SWaP, interoperability, fast deployment가 중요하다.
  - EST는 훨씬 적은 수의 strategic gateway에서도 더 먼 거리와 multi-orbit connectivity를 확보하는 것이 중요하다.

**✅ 같은 Space Force인데 왜 서로 다른 표준을 사용하는가**

**📌 첫 번째 이유는 역사다**

- - SDA OCT Standard는 SDA가 현재의 Space Force 조직에 편입되기 전부터 만들어지기 시작했다.
  - SDA는 2022년 10월 U.S. Space Force의 Direct Reporting Unit으로 이전됐으며, 이미 그 이전부터 PWSA를 위한 자체 optical interoperability architecture를 개발하고 있었다.
  - 즉 SSC와 SDA가 처음부터 하나의 조직에서 두 개의 경쟁 표준을 동시에 만든 것이 아니다.

**📌 두 번째 이유는 Mission이 다르다**

- - SDA의 핵심 목표는 proliferated LEO architecture다.
  - 많은 위성을 빠르게 배치하고 서로 optical mesh로 연결해야 한다.
  - 반면 EST는 Beyond-LEO를 포함하는 long-range enterprise connectivity를 목표로 한다.
  - 따라서 두 시스템에 동일한 link budget과 동일한 hardware requirement를 강제로 적용하는 것이 오히려 비효율적일 수 있다.

**📌 세 번째 이유는 모든 PHY를 하나로 통일할 필요가 없기 때문이다**

- - SDA도 이미 OCT Standard 4.0에서 long-range waveform을 추가해 향후 SSC의 MEO Missile Track Custody satellite와 PWSA Transport Layer를 연결하는 방향을 명시하고 있다.
  - 즉 미국 우주군의 방향은 하나의 optical waveform만 남기고 나머지를 없애는 것이 아니다.
  - 서로 다른 목적에 최적화된 PHY와 waveform을 유지하면서, 상위 계층에서 서로 연결하는 구조에 가깝다.
  - 바로 여기서 SEP가 필요해진다.

**✅ 그렇다면 Space-BACN은 무엇이 다른가**

- - EST와 SDA OCT를 보면 자연스럽게 DARPA의 Space-BACN이 떠오른다.

[**미 국방부가 꿈꾸는 우주의 인터넷**

- - Space-BACN의 문제의식도 동일했다.
  - Starlink, Amazon, 군 위성망 등 서로 다른 constellation이 optical link를 사용하면서도 서로 직접 통신할 수 없는 isolated network가 된다는 문제다.
  - DARPA는 이를 해결하기 위해 하나의 공통 waveform을 강제하기보다, 여러 optical intersatellite link standard에 적응할 수 있는 reconfigurable optical terminal을 개발하려 했다.

**📌 EST는 공통 언어를 만든다**

- - EST의 철학은 비교적 단순하다.
  - 모든 EST-compatible terminal이 동일한 standardized enterprise waveform을 구현하면 서로 직접 통신할 수 있다.

    - Satellite A — EST waveform
    - Satellite B — EST waveform
    - Satellite C — EST waveform
  - 의 구조다.

**📌 Space-BACN은 여러 언어를 번역한다**

- - Space-BACN은 방향이 다르다.
  - DARPA는 multiple OISL standard에 적응하는 low-cost reconfigurable terminal을 목표로 했다.
  - Phase 1에서는 CACI, MBRYONICS, Mynaric이 optical aperture 분야에 참여했고, II-VI, Arizona State University, Intel Federal 등이 최대 100 Gbps single-wavelength reconfigurable modem을 연구했다. SpaceX, Viasat, Amazon Kuiper 등은 cross-constellation command-and-control 영역에 참여했다.
  - 따라서 개념을 단순화하면 다음과 같다.

    - **EST = 모두가 사용할 새로운 공통 언어**
    - **Space-BACN = 기존에 존재하는 여러 언어를 이해하는 통역기**
  - 이다.
  - 이 두 접근은 경쟁 관계라기보다 상호보완적일 수 있다.

**✅ NEBULA — 광링크를 연결한 뒤 패킷은 어떻게 움직이는가**

- - 여기까지는 대부분 optical PHY와 terminal 이야기다.
  - 하지만 두 위성 사이에 laser link가 만들어졌다고 해서 network가 완성되는 것은 아니다.
  - 어떤 경로로 패킷을 전달할지, 우선순위를 어떻게 정할지, 장애가 발생하면 어떻게 우회할지, 기밀 데이터와 비기밀 데이터를 어떻게 분리할지에 대한 network architecture가 필요하다.
  - SDA에서는 이 역할을 NEBULA가 담당한다.
  - NEBULA는 Network Established Beyond the Upper Limits of the Atmosphere의 약자로, PWSA의 networking requirements를 정의한다. SDA는 PWSA의 각 satellite가 OCT를 사용하면서 동시에 동일한 NEBULA network의 일부가 된다고 명시한다.

**📌 NEBULA의 핵심은 IP와 MPLS다**

- - NEBULA는 단순한 laser communication specification이 아니다.

**✅ Open Architecture의 역설 — 개방할수록 보안은 더 중요해진다**

- - SDN은 SpaceX, SDA뿐 아니라 다양한 상업·군사 위성망을 표준 인터페이스를 통해 연결하는 open architecture를 지향한다.
  - 하지만 참여 업체와 접속 지점이 늘어날수록 공격 표면도 커진다.
  - 따라서 Space Force는 physical·data interface뿐 아니라 **security protocol까지 표준화해 새로운 vendor를 안전하게 onboarding**하는 것을 핵심 요구사항으로 명시하고 있다.

**📌 RED/BLACK과 HAIPE — 현재의 보안 구조**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA4MTRfMzEg/MDAxNzg2Njg0NzQ0ODcx.vTuKtEgIq1C8a_mJ65d4PekUIZulKWYAl9axXB0mOeIg.6GY73PlkTeNGSlr8Ak_rCi52UhMVuzYFUjmOWgp8IR8g.PNG/image.png?type=w800)](#)

- - 현재 SDA의 NEBULA는 classified data를 처리하는 RED domain과 암호화된 데이터가 이동하는 BLACK network를 분리한다.
  - RED traffic은 위성의 MPLS backbone으로 들어가기 전에 HAIPE 또는 다른 network encryptor를 통과하며, NEBULA는 IP/MPLS를 통해 암호화된 데이터를 전달한다.
  - 즉 optical link 자체가 보안을 제공하는 것이 아니라 **HAIPE 암호화 + RED/BLACK separation + 인증 + network security**가 함께 보안을 구성한다.

**📌 PQC — 미래 SDN에서 피하기 어려운 변화**

- - 문제는 SDN이 앞으로 수십 년간 사용될 수 있는 장기 국방 인프라라는 점이다.
  - NSA는 National Security Systems가 향후 quantum-resistant algorithm으로 전환해야 한다고 이미 CNSA 2.0을 통해 방향을 제시하고 있다.
  - 따라서 미래 SDN의 HAIPE, IPsec, TLS, 인증 및 key establishment 구조 역시 장기적으로 **PQC migration을 수용할 수 있어야 한다**고 보는 것이 자연스럽다.

**📌 QKD — 필수요소라기보다 장기적인 선택지**

- - Optical space network는 물리적으로 QKD를 적용하기 좋은 환경처럼 보이지만, 현재 미국 NSS 정책에서 QKD가 기본 보안수단으로 채택된 것은 아니다.
  - NSA는 특수 hardware, 인증 문제, 비용, trusted relay, DoS 위험 등을 이유로 현재 NSS 보호에 QKD 사용을 권고하지 않고 있으며, PQC를 더 현실적인 해결책으로 평가하고 있다.
  - 따라서 현재 기준으로 **PQC는 직접적인 보안 전환 경로이고, QKD는 기술적 한계가 해결될 경우 추가될 수 있는 보완 계층**으로 보는 것이 적절하다.

**📌 Crypto Agility — 결국 가장 중요한 것은 교체 가능성이다**

- - SDN은 하나의 vendor와 하나의 기술로 고정된 네트워크가 아니다.
  - 위성, SEP, optical terminal과 암호 기술이 계속 교체되는 구조이므로 특정 cryptographic algorithm을 hardware에 고정하기보다 새로운 알고리즘을 software·firmware update를 통해 적용할 수 있는 crypto agility가 중요하다.
  - 결국 secure open architecture의 핵심은 **누구나 들어올 수 있는 네트워크가 아니라, 정해진 interface와 security baseline을 만족하는 기술이 경쟁하며 교체될 수 있는 네트워크를 만드는 것**이다.

**✅ 5개 Prime과 3개 EST 업체 — 중요한 것은 1:1 매칭이 아니다**

- - 여기서 5개의 spacecraft 업체와 3개의 EST 업체 숫자가 맞지 않는다는 점이 오히려 이번 사업의 핵심을 보여준다.
  - Space Force가 원하는 것은 특정 terminal이 특정 satellite bus에 종속되는 구조가 아니다.
  - 예를 들어 CACI terminal을 York bus에 탑재할 수도 있고, 다른 조건을 충족하면 Rocket Lab bus에 탑재할 수도 있어야 한다.
  - 마찬가지로 같은 satellite bus도 mission에 따라 GA 또는 다른 compatible optical payload를 사용할 수 있어야 한다.
  - 실제 5개 prime과 EST 개발사의 pairing은 아직 공개되지 않았다.
  - 그러나 SSC가 밝힌 목표는 분명하다.
  - 향후 communications payload가 competing spacecraft bus와 seamless하게 통합돼야 하며, bus가 달라질 때마다 expensive custom redesign을 반복하지 않아야 한다.
  - 즉 목표는 1:1 관계가 아니라 다음과 같은 구조다.

    - **N개의 Optical Payload 업체 × M개의 Spacecraft Bus 업체**
  - 이것이 open architecture와 persistent competition의 의미다.

**✅ Rocket Lab·Mynaric와 IonQ·Skyloom을 어떻게 봐야 하나**

**📌 Rocket Lab의 강점**

**📌 Skyloom이 이번 5개 기업에 없는 이유**

- - Skyloom이 이번 5개 prime에 포함되지 않았다고 해서 SDN에서 탈락했다고 해석하는 것도 적절하지 않다.

  - 반면 이번 5개사 선정은 OCT vendor 선정이라기보다 SEP spacecraft를 실제로 제작·통합·fielding할 satellite bus/system prime을 선정하는 성격이 강하다.
  - 따라서 Skyloom에게 더 중요한 질문은 다른 데 있다.
  - 향후 SEP prime의 optical payload supplier로 참여하는지, 새로운 SDN interface나 waveform을 지원하는지, 그리고 IonQ가 Skyloom을 단순 component supplier에서 system-level network provider로 확장할 수 있는지가 더 중요한 관전 포인트다.

**✅ 결론 — 미국은 하나의 위성망을 만드는 것이 아니다**

- - 이번 발표를 통해 가장 분명해진 것은 미국 우주군이 단 하나의 거대한 constellation을 만들려는 것이 아니라는 점이다.
  - SpaceX의 SDN Backbone이 존재하고, SDA의 Transport Layer가 존재하며, 다양한 commercial constellation과 government satellite가 따로 존재한다.
  - 이들 모두를 하나의 PHY나 하나의 vendor로 통일하는 대신 서로 다른 기술과 네트워크를 유지하면서 공통 interface와 gateway를 이용해 연결하려 하고 있다.
  - 이를 정리하면 다음과 같다.

    - **SDA OCT는 proliferated LEO mesh를 위한 optical language다.**
    - **EST는 long-range multi-orbit network를 위한 enterprise optical language다.**
    - **Space-BACN은 서로 다른 optical language를 연결하기 위한 translator다.**
    - **NEBULA는 연결된 node 사이에서 packet이 어떻게 움직여야 하는지를 정의하는 network architecture다.**
    - **SEP는 서로 다른 network를 실제 우주에서 연결하는 orbital router다.**
    - **SpaceX SDN Backbone은 대량의 데이터를 실어 나르는 core transport infrastructure다.**
  - 그리고 이 모든 것을 하나의 resilient, secure, open architecture로 묶으려는 것이 Space Data Network다.
  - SDN은 장기간 운용될 국방 인프라이기 때문에 향후 quantum computer의 위협까지 고려해야 한다. 따라서 기존 암호체계를 고정해 사용하는 것이 아니라 **PQC(Post-Quantum Cryptography)로 전환할 수 있는 crypto agility를 architecture 단계부터 확보하는 것이 중요하다.**
  - 즉 미래 SDN에서 PQC는 별도의 quantum network를 만드는 기술이라기보다, 기존 IP/MPLS 기반 군사 네트워크의 인증·암호화·key establishment를 quantum-resistant하게 만드는 security layer로 이해하는 것이 적절하다.
  - 결국 Space Force가 만들고 있는 것은 단순한 위성 통신망이 아니다.

    - **여러 회사의 위성, 여러 종류의 광통신 표준, 여러 궤도, 여러 군사 네트워크가 필요에 따라 연결되고 분리되며 장애가 발생하면 다른 경로로 우회할 수 있는 개방형 우주 데이터 인프라를 만들고 있는 것이다.**
    - 이번 $60M 규모의 계약이 SpaceX의 $2.29B 계약보다 훨씬 작음에도 주목할 가치가 있는 이유가 바로 여기에 있다.
  - 이번 계약에서 Space Force가 사고 있는 것은 위성 5대가 아니라, 향후 수많은 위성과 수많은 업체가 경쟁하면서도 하나의 네트워크처럼 움직일 수 있도록 만드는 표준화된 연결 방식이기 때문이다.
