**✅각업체별 비교**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **업체** | **주 원자(큐비트) / 얽힘** | **주력 모드** | **접근/유통** | **강점(차별점)** |
| **QuEra (미국)** | 루비듐(Rb), 리드버그 | **아날로그****(AHS)** 중심 + (점진적) 디지털 | **Amazon Braket**에서 Aquila 제공 | **Aquila 256**로 대중 접근성(브라켓) 확보 |
| **Atom Computing (미국)** | **스트론튬(Sr), 이테르븀(Yb), 핵스핀** | 디지털 + QEC/논리큐비트 지향 | **Microsoft(Azure) 협업/상용 머신** 내세움 | **1000+ 규모(예: 1180/1225급 발표)** + **논리큐비트(24 entangled, 28 logical 알고리즘)** 성과를 MS와 강조 |
| **Pasqal (프랑스)** | (주로) 루비듐, 리드버그 | 아날로그/디지털 혼합(자사 스택) | **Google Cloud Marketplace**에서 100-qubit QPU 접근 | **2025 로드맵**으로 FTQC(내결함)까지 단계 제시 + **포토닉(PIC) 내재화**(Aeponyx 인수) |
| **Infleqtion (미국)** | 세슘(Cs), 리드버그 | “풀스택 + FT 지향” | **NQCC(영국) 테스트베드** 선정/납품 로드맵 공개 | **최대 1600 사이트 데모**, **2Q 게이트 99.73%±0.03%**(자사 주장/표기) + **Superstaq 컴파일러 통합** |

💡 **같은 중성원자”인데도 갈리는 포인트 5가지**

1. 1. **원자 종 선택**

      - **Rb/Cs 계열(전통적 Rydberg 게이트)** vs **Yb/Sr(알칼리-토, 핵스핀/시계전이 활용)**
      - → 장점이 “레이저/준위 구조/코히런스/QEC 설계”에서 갈린다.
   2. **주력 컴퓨팅 모드**

      - 아날로그(AHS - Analog Hamiltonian Simulation)로 “많은 큐비트에서 유용한 시뮬레이션/최적화”를 먼저 파는 쪽(QuEra의 Aquila/Braket)
      - 디지털/논리큐비트로 “내결함”을 강하게 미는 쪽(**Atom, Pasqal 로드맵, Infleqtion** 로드맵)
   3. **스케일 전략**

      - “일단 사이트/큐비트 수를 크게” (Atom의 1000+ 발표 흐름)
      - “고충실도/원자 손실·읽기(미드서킷 포함) 쪽을 강화” (Infleqtion이 99.73% 및 시스템/스택을 강조)
   4. **광학/제어의 집적**

      - Pasqal이 **PIC 기업(Aeponyx)** 인수로 “광학 제어를 칩화/내재화” 방향을 분명히 했다
   5. **유통 채널**

      - QuEra는 **AWS Braket**으로 빠르게 사용자 기반 확보
      - Pasqal은 **Google Cloud Marketplace**에서 접근성을 키움
      - Atom은 **Microsoft Azure**와 “논리큐비트/가상화” 결합을 전면에 둔다

💡**선택 가이드 (사용자 관점)**

- - **“지금 당장 대규모 실험(아날로그/최적화/시뮬레이션)을 돌려보고 싶다”** → QuEra(AWS Braket Aquila)
  - **“클라우드로 상용 QPU를 써보고, 로드맵/산업 적용까지 보고 싶다”** → Pasqal(Google Cloud)
  - **“논리큐비트·QEC 성과/긴 코히런스 쪽 서사를 중요시한다”** → Atom Computing( MS와 논리큐비트 강조 )
  - **“큰 어레이 + 높은 2Q 충실도/풀스택(컴파일러 포함) 지향을 본다”** → Infleqtion

**💡아날로그 vs 디지털**

|  |  |  |
| --- | --- | --- |
| **기준** | **아날로그(AHS)** | **게이트 기반** |
| **지금 당장 쓸 수 있음** | ✅ 매우 높음 | ❌ 제한적 |
| **큐비트 수 확장** | ✅ 수백~수천 가능 | ❌ 느림 |
| **오류 누적** | ✅ 상대적으로 적음 | ❌ 깊이에 비례 |
| **범용성** | ❌ 특정 문제 특화 | ✅ 범용 |
| **오류보정(FTQC)** | ❌ 불가 | ✅ 가능 |
| **장기 잠재력** | ⚠️ 제한적 | ✅ 압도적 |

- - 아날로그 모드(AHS)는 **임의의 양자회로를 구현할 수 없다.**

    - Shor 알고리즘 ❌
    - Grover 반복 ❌
    - 양자 푸리에 변환(QFT) ❌
    - 임의의 Clifford + non-Clifford 조합 ❌
    - 왜냐하면 AHS는:

      - “게이트를 나열하는 방식”이 아니라 “하나의 해밀토니언을 시간에 따라 진화시키는 방식” 이기 때문이다.
    - 즉,

      - 회로 모델 ❌
      - 프로그램 가능 계산기 ❌
      - **특정 물리 문제 전용 계산기** ✔️
  - 아날로그 모드에서는:

    - 중간 측정 ❌
    - 신드롬 추출 ❌
    - 오류 탐지 → 피드백 ❌
  - 그래서:

    - QuEra → **AHS 상용 + Gemini(게이트 R&D)**
    - Pasqal → **AHS 수익 + 디지털 로드맵**
    - Atom Computing → **게이트/논리큐비트 직행**
    - 이라는 **이중 전략**이 나온다.

**✅****중성원자 기반이 아직 아날로그에 머물고 있는 이유**

****

**💡 2Q 게이트가 “자연스러운 상호작용”이 아니다**

- - **아날로그에서는**

    - Rydberg 상호작용 = **그 자체가 해밀토니안**
    - “켜 놓고 시간 진화” → 계산
    - 정확한 타이밍·위상 필요 ❌
    - 👉 **아날로그는 물리 친화적**
  - **디지털에서는**

    - 정확한:

      - 게이트 각도
      - 위상
      - 시작/종료 시점
    - **정밀한 pulse shaping** 필요
  - 문제는:

    - Rydberg 상호작용은

      - 강하지만
      - **너무 거칠고 비선형적**
  - ➡️ **아날로그에선 장점, 디지털에선 독**이다.

**💡 2Q 동안 “다른 코히런스 시계”를 쓴다 (핵심)**

- - 중성원자의 구조적 약점:

|  |  |
| --- | --- |
| **상태** | **코히런스 지배자** |
| idle / 1Q | 바닥 상태 T₂ (초 단위 가능) |
| **2Q 중** | **Rydberg 수명 (µs~100µs)** |

- - 연산을 시작하는 순간 가장 약한 물리 상태로 갈아탄다.
  - 디지털 QEC는:

    - **수천~수만 번의 2Q 반복**이 필요한데
    - 중성원자는 **2Q 자체가 코히런스 병목**
  - ➡️ 디지털 전환의 가장 본질적 장애물

**💡 원자 이동(rearrangement)은 디지털에 독이 된다**

- - 아날로그:

    - 매 shot마다 재배열 OK
    - 배열만 맞으면 됨
  - 디지털 QEC:

    - **레이아웃 고정**
    - **반복 사이클**
    - **타이밍 일관성**
  - 하지만:

    - 중성원자의 강점 = “움직임”
    - 디지털의 요구 = “정지”
  - ➡️ **장점이 단점으로 반전**

****

**💡 측정·리셋·피드백이 느리고 파괴적**

- - 디지털 QEC 필수 조건:

    - mid-circuit measurement
    - 빠른 reset
    - classical feedback
  - 중성원자 현실:

    - 측정 시:

      - atom loss
      - heating
    - reset = reloading 필요
  - 최근엔 많이 개선됐지만 “비파괴·고속·반복 측정”은 아직 초전도/이온 대비 불리

**💡 아날로그는 “에러 허용”, 디지털은 “에러 적대적”**

|  |  |  |
| --- | --- | --- |
| **항목** | **아날로그** | **디지털** |
| 에러 성격 | 평균화 | 누적 |
| 요구 fidelity | 중간 | 매우 높음 |
| calibration | 느슨 | 극도로 정밀 |
| drift 허용 | 큼 | 거의 없음 |

- - 중성원자는:

    - 드리프트
    - 레이저 노이즈
    - 전기장 변동
  - 에 **구조적으로 민감**
  - ➡️ 디지털 FTQC의 적합성과 충돌

**💡 그래서 업계의 실제 전략은 이렇다**

- - 중성원자 진영이 택한 **우회로**들:

    1. **아날로그로 시장/자금 확보**
    2. 시스템 안정성·스케일 먼저 완성
    3. 그 위에:

       - cryogenic Rydberg
       - Rydberg dressing
       - qLDPC
       - 소프트웨어 보정

> ***“정면 돌파가 아니라, 디지털의 요구를 낮추거나 물리를 바꾸는 방향”***

**✅****게이트 기반 제품 상용화를 위한 과제들**

**💡****QuEra**

1. 1. **게이트 기반(디지털)에서의 2Q 품질/안정성****: 중성원자에서 디지털 2Q는 리드버그/레이저 노이즈/모션 등으로 까다롭고, FT로 가려면 여기서 더 전진해야 함.**
   2. **오류정정 로드맵 실증****: 로드맵(논리 큐비트 방향)을 명시. 실험으로 “논리 게이트/논리 사이클”을 쌓아야 함.**
   3. **손실 보정(continuous reloading) + 연산 병행****: ‘qubit sustainability’가 바로 이 축. (이게 갖춰져야 deep circuit이 가능)**
   - **한 줄****: “스케일/유지”는 크게 전진, 이제** **디지털 2Q·논리 게이트****가 마지막 큰 산.**

****

**💡****Atom Computing**

1. 1. **논리 큐비트/오류정정의 실증을 ‘지속 가능한 시스템’으로****: 로드맵/백서에서 논리 큐비트 확장 의지를 강조.**
   2. **게이트 기반에서의 2Q 품질 + 손실/재배열 운영****: 큰 배열을 “계속 돌리는” 운영기술.**
   3. **클라우드/스택 통합****: 실제 사용자 워크플로로 연결(파트너 생태계 포함).**
   - **한 줄****: 큰 배열 기반 장점을** **논리 연산/제품 운영****으로 변환.**

****

**💡****Pasqal**

1. 1. **아날로그 강점 → 디지털 FT 전환****: 중성원자는 아날로그(해밀토니안 시뮬/최적화)에 강했는데, “게이트 기반 FT”로 넘어가는 과정이 핵심.**
   2. **디지털 게이트/오류정정 스택 제품화****: 2025 로드맵에서 디지털 FTQC 경로를 명시.**
   3. **시스템 자동화/현장 배치(rapid deployment)****: 실제 산업 현장/클라우드 제공을 위한 운영성.**
   - **한 줄****: “중성원자=아날로그”를 넘어** **디지털·FT로 체질 전환****.**

****

**💡****Infleqtion**

1. 1. **고충실도 2Q를 대규모에서 ‘일관되게’****: 회사는 높은 entangling gate fidelity를 강조하지만, 상용은 “대규모에서도 동일”이 관건.**
   2. **컴파일러/소프트웨어 스택과 실제 하드웨어의 co-design****: Superstaq 등 스택을 강조—하드웨어 변동성을 SW로 흡수하는 방향.**
   3. **NQCC 등 실증 프로젝트에서의 반복 가능 성능****: 테스트베드/고객 과제 수행이 곧 상용화 단계.**
   - **한 줄****: “좋은 데모”를** **지속 가능한 제품 성능****으로 고정.**
