**📌 요약**

- - 이번 연구는 이온 체인(long chain) 기반의 양자컴퓨터에서 나타나는 **체인 손실(chain loss)** 문제를 다룬다.
  - 단일 이온 손실이 발생하면 **전체 체인이 붕괴하거나 대부분의 큐비트가 손실되는 치명적 결과**가 발생하므로, 이를 **에러 정정이 가능하도록 변환하는 방법**을 제안한다.

**🔑 핵심 아이디어**

1. 1. **분산형 양자오류정정(Distributed QEC)**

      - 데이터 큐비트를 여러 체인에 분산하여 저장한다.
      - 단일 체인에 code distance 이상 큐비트가 몰리지 않도록 재배치한다.
      - [[72, 12, 6]] BB 코드(Bravyi-Bicycle code)를 사용하여 실험한다.
   2. **비컨 큐비(Beacon Qubit) 도입**

      - 각 체인에 하나 이상의 비컨을 두고 항상 |1⟩ 상태로 유지한다.
      - 주기적으로 측정하여 광자를 감지하면 체인이 살아 있음을 확인한다.
      - 측정 결과가 0이면 즉시 체인 손실로 판단한다.
      - 복수 비컨 사용 시 **다수결로 false positive / false negative 방지**가 가능하다.
   3. **체인 손실을 지워짐(Erasure) 오류로 변환**

      - 손실된 체인은 즉시 새 체인으로 교체하고 **완전 혼합 상태(I/2)** 로 초기화한다.
      - 위치 정보가 있는 erasure로 처리하므로 **Pauli error보다 수정이 용이하다**.

**📈 시뮬레이션 결과**

- - Stim + BP-OSD 디코더로 회로 레벨 시뮬레이션 수행
  - 체인 손실 확률 *p**loss**=p**α* 모델 사용
  - **α ≥ 1.9면 체인 손실이 성능에 거의 영향을 주지 않는다**
  - **α = 1.5에서는 오류율이 100배 이상 악화** → 체인 손실이 지배적 요소가 됨
  - **빠른 비컨 측정이 중요**

    - 측정 지연이 생기면 오류율 gap이 매우 커진다

**🧠 의미**

- - 긴 체인 시스템에서 실제로 가장 위험한 노이즈 소스인 **체인 전체 손실을 QEC가 처리 가능한 영역으로 변환한 첫 연구**다.
  - **이온트랩에서의 long chain 아키텍처의 실용적 확장성 확보에 중요**한 결과이다.
  - **Distributed QEC + Beacon + Erasure decoding** 조합이 체인 loss 문제를 해결할 수 있음을 보여준다.

**📍 향후 연구 방향**

- - 비컨 측정 속도 개선
  - 체인 교체를 위한 실제 **리로드 시스템 연구**
  - Leakage 오류 처리 및 QEC 코드 확장
  - Classical distributed storage 복구 기술과의 접목

**✅****이번 연구의 핵심**

- - 위에서 살펴본대로 이온 트랩에서는 이온손실이 치명적인 오류이다.
  - 이온 체인을 사용하는 구조에서는 **이온 하나가 손실되는 순간 전체 체인이 붕괴하거나 대부분의 큐비트가 사라지는 심각한 문제**가 발생한다.

    - 긴 이온 체인은 많은 이온을 **단일 potential well****(전기 포텐셜 우물)** 에 담아놓은 구조다.

      - 이 때 **한 개 이온이라도 이탈**하면:

        1. 전하 간 Coulomb repulsion 균형이 깨지고
        2. 남은 이온들이 급격히 재배열되며 높은 모션 에너지(heat)가 발생하고
        3. 위치가 레이저 포커싱 지점에서 벗어나 측정 및 제어 불가능해지고
        4. 결과적으로 **측정 시 모든 큐빗이 |0⟩(dark)처럼 보이며 정보가 완전히 소실됨**
        5. **그대로는 복구 불가 — erasure로 처리해야 함**
  - 이온 손실은 드물지만, 긴 체인에서는 단일 손실이 **전체 계산을 망칠 수 있는 치명적 에러**로 확산된다.
  - 이 논문은

    - **여러 긴 체인에 분산된 QEC 코드**
    - **체인 생존을 감시하는 비컨 큐비트**
    - **손실을 erasure 오류로 변환하여 수정하는 디코더**
  - 세 가지 요소를 결합하여 **체인 손실 문제를 해결하는 방법**을 제안한다.
  - 이번 연구는 지난 8월에 발표된 **2×L 모듈 배열(Distributed QEC architecture)** 모델을 기반으로 한다.

    - 지난 연구에 대한 내용은 아래 링크를 참고하자.

- - - 두 개의 행(row)으로 구성되고, 위 행은 **고정 데이터 모듈**, 아래 행은 **이동 ancilla 모듈**이다.
    - 모듈 간 연결을 위해 **cyclic shift**를 수행하고, ancilla 모듈을 데이터 모듈과 병합하여(stitching) 2큐비트 게이트를 실행한다.
    - 하지만 이러한 구조에서는 모듈 하나가 손실되면 shift와 merge 연산을 거치며 연쇄적으로 전체 모듈이 손실되는 ‘재앙적 전파(catastrophic failure)’가 발생한다.
    - 즉, 체인 손실은 단순한 로컬 오류가 아니라 **시스템 전체를 파괴하는 글로벌 에러로 진화**한다.

- - 한 개의 모듈이 손실되면,
  - 몇 번의 **순환 이동(cyclic shift)** 과 **병합(merge)** 연산이 반복된 이후
  - **모든 모듈이 연쇄적으로 손실되는 현상**이 발생한다는 것을 보여준다.
  - 안실라 한 모듈의 손실이 여러 모듈에 걸쳐 연쇄적으로 확산되며, 결국 전체 체인이 붕괴되는 최악의 상황을 그림으로 설명한 것.

**💡Beacon 큐비트를 이용하여 체인 손실 교정**

- - 체인 손실을 탐지하기 위해 **비컨 큐비트를 체인마다 하나 이상 배치하고 항상 |1⟩ 상태로 유지하며 주기적으로 측정**한다.
  - |1⟩ 상태는 실제 이온이 존재할 때 광자를 방출하므로, 측정 결과 0(광자 없음)이 나오면 체인이 손실된 것으로 판단한다.
  - **비컨 큐비트 설계의 핵심**

    - **비컷 큐비트도 검출 오류를 일으킬 수 있다.**

      - **False Positive - 체인이 정상인데도 측정 오류로 손실로 오판**
      - **False Negative - 체인이 정상인데도 측정 오류로 손실로 오판**
    - 다수 비컨(예: 3개)을 사용해 **다수결 판단**으로 두 종류 오류를 억제한다.
  - **체인 손실 후 처리**

    - 손실이 감지되면 **즉시 새로운 체인을 리로드하고 I/2 상태로 초기화**한다.

      - **완전 혼합 상태 I/2** 는 양자정보상태에서 정보가 없는 상태를 의미함.

        - "해당 큐비트는 더 이상 정보가 없으니 버리고, 새큐비트로 교체해야 함" 이라는 뜻
    - 이는 **체인 손실을 ‘erasure error’로 변환**하는 효과를 가지며, erasure 오류는 위치 정보가 있어 일반 Pauli 오류보다 교정이 훨씬 쉽다.
  - **코드 배치 조건**

    - 하나의 체인에 code distance 이상 데이터 큐비트를 넣지 않는다.
    - [72, 12, 6] BB 코드에서 모듈당 12큐비트 → 3개로 재배치하여 단일 체인 손실을 복구 가능하게 조정한다.

      - n=72 : 전체 물리 큐비트 수
      - k=12 : 논리 큐비트 수
      - d=6 : code distance

        - code distance란 논리 상태를 바꾸려면 최소 몇 개의 물리 큐빗에 오류가 동시에 발생해야 하는가를 설명

**✅생방송의 긴장감에서 해방**

- - 출연진들을 포함한 제작관련자들(일명 방송국놈들)을 포함한 모든 방송 관계자들은 생방송을 할 때 긴장을 엄청 많이 한다고 들었다.
  - 이유는 간단하다. 약간의 실수가 있어도 모든 시청자들이 알게되고, 되돌릴 수 없기 때문이다.
  - 하지만, 녹화방송은 비교적 여유롭다. 물론 NG를 여러번 내면 뒤통수에 꽂히는 따가운 눈총을 견딜 수 있는 멘탈은 몇 안 될 것이다. 그러다보니 1시간 분량 컨텐츠를 만들기 위해 보통 10시간 촬영은 기본이고, 수십대의 카메라가 동원되고, 밥차도 따라 오고, 촬영이 끝나고 난 후 여러번의 편집을 거치고, CG와 자막을 추가해야만 비로소 **우리가 재미있게 컨텐츠를 감상하게 된다.**

**💡소년의 시간(넷플릭스 - 2025)**

- - 최근 본 넷플릭스 시리즈물 중 소년의 시간이 생각이 난다. 스토리도 탄탄하지만, 모든 촬영을 원테이크로 진행해서 더욱 화제가 됐었다.
  - 단 한번의 롱테이크로 촬영을 끝내야 하기 때문에 생방송 못지 않게 촬영진들과 연기자들이 호흡을 많이 맞췄을 것이라 생각이 든다.

**💡원테이크에서 멀티테이크와 컷 편집으로.**

- - 지금까지의 이온트랩 방식의 QPU에서는 게이트 오류만 완화 또는 정정을 하고, 물리 오류가 생겨서 이온 손실 및 Chain Collapse가 발생하게 되면 다음과 같은 현상이 발생했다.

    - 갑자기 readout이 다 이상해짐
    - 게이트가 작동하지 않음
    - 상태가 유지되지 않음
    - 결과적으로 **logical computation 전체가 실패**

      - **연산 중 collapse 발생**
      - **→ 전체 실험 중단**
      - **→ 재초기화(reload entire chain)**
      - **→ 다시 처음부터 수행**

|  |  |
| --- | --- |
| **문제** | **설명** |
| 계산 길수록 실패 확률 커짐 | chain 길면 lost-ion 하나로 끝 |
| 많은 리소스 낭비 | 수시간~수일 계산을 다시 해야 함 |
| FTQC(fault-tolerant) 불가능 | 실시간 graceful recovery 없음 |
| collapse 위치 알 수 없음 | debugging도 힘듦 |
| 오류 전파 파악도 못함 | Fig.1 domino propagation |

> 지금까지의 long chain QC는 사실상 “희망회로 돌리기”였고, "롱테이크"로 촬영하면서 실수가 안나길 간절히 바라는 수준이었만,
>
> 이번 연구를 계기로, 여러 카메라(멀티 체인)로 녹화하고, 문제 생기면 잠깐 끊고, 다시 시작하여 깔끔하게 녹화를 끝낼 수 있다. 물론 그래도 생기는 문제는 편집(QEC)로 해결을 하면 된다.
