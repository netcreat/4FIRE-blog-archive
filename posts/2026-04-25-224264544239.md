**✅ V. THE LOGICAL ARCHITECTURE COMPONENTS**

- - 이 섹션은 새로운 개념을 만드는 게 아니다.

    - 이미 정의된 moving-qubit 모델 위에서 “fault-tolerant computation을 실제로 어떻게 구성할 것인가”를 설명한다.
  - 핵심 포인트:

    - logical qubit은 memory block에 저장됨
    - 연산은 circuit이 아니라 **logical measurement**로 수행됨
    - 필요한 resource는 factory에서 생성됨
  - 여기서 중요한 문장은
  - **computation model = Pauli-based computation model******
  - 즉, 연산 = gate 실행이 아니라 **Pauli measurement 중심 구조**
  - ****

**📌 전체 구조**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjVfMjM4/MDAxNzc3MDczOTY1MTg2.QO5mmL-VHujTBLRcBYRQ5JXXc2p88BTqXxeJ1-ku2G4g.LmzVbkIiE8YlwMvGw7SszFeDWxYFrR5Xlfe3KPJ6t7Ig.PNG/image.png?type=w800)](#)

- - **구성 요소**

    - M = Memory block
    - T = Magic factory
    - C = Cat factory
    - B = Bell factory
    - Q = Qubit factory
  - **실제 동작 흐름**

    - logical qubit → Memory에 저장
    - magic state → Magic factory에서 생성
    - cat state → Cat factory에서 생성
    - Bell state → Bell factory에서 생성

      - cat state 두 개 연결 (stitching)
      - block 간 연산 가능하게 함
      - measurement 이후 cat state → 다시 factory로 돌아감 (reuse)

        - cat state는 소모되지만 구조적으로 재활용 루프가 있음
  - **연산 방식**

    - cat state를 memory 또는 magic block 옆으로 이동시켜 **logical measurement 수행**

**📌 왜 qubit factory가 필요한가**

- - lost qubit을 대체
  - global reservoir + loading zone 포함

    - loss 발생 → Q에서 qubit 공급

**📌 Bell factory**

- - **역할**

    - Bell state 생성
  - **특징**

    - 매우 단순
    - CX gate만 수행
  - **하지만 중요한 이유**

    - cat stitching 가능
    - block 간 연산 가능
    - magic distribution 가능

**📌 Qubit factory**

- - **역할**

    - lost qubit replacement
  - **구성**

    - loading zone
    - storage (global reservoir)
    - distribution
  - **매우 중요한 제약**

    - reservoir는 유한하기 때문에 고갈되면 시스템 failure

**📌 Component interfaces (F)**

- - 인터페이스 3가지:

    - **Qubit transport**

      - reservoir → component 이동
    - **Bell stitching**

      - cat state 연결
    - **Cat-based measurement**

      - logical measurement 수행
  - **“데이터 이동 + 상태 이동 + measurement orchestration”**

**✅ VI. ACCESSIBLE LOGICAL OPERATIONS******

**📌 이 섹션의 출발점**

- - 앞 섹션에서는 memory block, magic factory, cat factory, Bell factory, qubit factory 같은 구성 요소를 정의했다.
  - 그 다음 이 섹션에서는 실제 연산을 논하기 전에 먼저 다음을 정리한다.
  - logical Pauli operator

    - → physical representative
    - → accessible logical Pauli operator
    - → accessible logical Clifford gate
  - 즉, 이 섹션은 “게이트 구현법”보다 먼저, **논리 연산을 물리적 측정 가능한 형태로 어떻게 표현하는가**를 다룬다.

**📌 Logical operators and their physical representatives**

- - 여기서는 먼저 stabilizer code에서 logical operator를 어떻게 표현하는지 복습한다.
  - 논리 Pauli operator는 코드 공간 위에서 작용하는 연산이지만, 실제 하드웨어는 논리 연산을 직접 볼 수 없다.
  - 그래서 논리 연산 P에 대응하는 물리 Pauli operator Pˉ를 찾아야 한다.
  - 핵심은 이것이다.

    - 물리 데이터 큐비트에 Pˉ를 적용하거나 측정하는 것이 코드 공간 안에서는 논리 연산 P를 적용하거나 측정하는 것과 동등하다.
  - 하지만 하나의 logical operator에 대응하는 physical representative는 하나만 있는 것이 아니다.
  - stabilizer를 곱하면 같은 logical operator를 나타내는 다른 physical Pauli operator를 만들 수 있다.
  - 즉:

    - 같은 logical Pauli
    - → 여러 physical representative 가능
    - → 그중 weight가 작은 것을 선택하는 것이 중요
  - 이게 나중에 Section XIV의 weight-reduced logical Pauli operator로 이어진다.

> *“논리 연산을 직접 못하니까, 대신 가장 쉬운(weight가 작은) 물리 연산으로 바꿔서 한다”*

**📌 Accessible logical Pauli operators**

- - 이 파트가 Section VI의 중심이다.
  - 논문은 각 block마다 하나의 파라미터 w, 즉 **logical width**를 정의한다.
  - 어떤 logical Pauli operator P가 있다고 할 때, 그 operator가 접근 가능하려면 조건이 있다.
  - 그 logical Pauli를 표현하는 physical representative 중 weight가 w 이하인 것이 있어야 한다.
  - 즉, cat factory가 만들 수 있는 cat state 크기가 제한되어 있기 때문에, 모든 logical Pauli를 마음대로 측정할 수 있는 것이 아니다.
  - **핵심 구조**

|  |
| --- |
| logical Pauli P  ↓  physical representative 후보들  ↓  weight가 w 이하인 대표를 찾음  ↓  있으면 accessible logical Pauli |

- - - 논문은 이를 위해 lookup table을 둔다.
    - 이 table은:

      - 측정 가능한 logical Pauli
      - → 실제 측정해야 하는 physical Pauli representative
      - 를 저장한다.
    - 여기서 중요한 점은, cat factory의 크기와 block width가 직접 연결된다는 것이다.
    - cat factory가 충분히 큰 cat state를 만들 수 있어야 그 block에서 더 많은 logical Pauli 측정을 지원할 수 있다.
  - **4. 여기서 cat state의 역할**

    - cat state는 logical Pauli operator를 측정하기 위한 물리적 측정 도구다.
    - 즉, 이 섹션에서 cat state의 역할은: accessible logical Pauli 측정을 가능하게 하는 measurement resource이다.

> *아무 논리 연산이나 다 할 수 있는 게 아니라서, weight가 작은 것을 골라서 사용해야 함.*
>
> *cat factory 크기가 크면, 더 큰 cat state 가능하고, 더 복잡한 연산 가능*

**📌 Clifford frame-tracking**

- - 논문은 일부 Clifford gate를 실제 물리 gate로 직접 수행하지 않고, **software frame-tracking**으로 구현할 수 있다고 설명한다.
  - 즉, 큐비트에 실제 Clifford gate를 가하는 대신, 현재 logical frame이 어떻게 바뀌었는지를 소프트웨어로 추적한다.
  - **핵심 아이디어**

    - 어떤 Clifford gate U가 있으면, 그 gate는 Pauli operator를 다른 Pauli operator로 변환한다.
    - 즉:

      - P → U† P U
      - 따라서 실제로 U를 물리적으로 적용하지 않아도, 앞으로 측정해야 할 Pauli operator를 U†PU로 바꿔서 측정하면 된다.
  - **직관**

    - 기존 방식:

      - logical gate U를 실제로 적용
      - → 이후 Pauli P 측정
    - frame-tracking 방식:

      - U는 실제로 적용하지 않음
      - → 대신 측정할 Pauli를 U†PU로 바꿈
      - 결과는 동일하다.

> *사람이 옆을 볼 수 있는 방법*
>
> *1. 직접 몸을 돌려서 옆을 보는 방법*
>
> *2. 사람은 그대로 있고, 공간이 돌아서 내 눈앞에 펼쳐짐.*
>
> *결과는 같지만, 게이트 연산을 안하기 때문에 오류가 줄어서 시간 절약 자원 절약이 가능하다.*

****

**📌 Accessible logical Clifford gates**

- - 모든 Clifford gate를 frame-tracking으로 구현할 수 있는 것은 아니다.
  - 어떤 Clifford V가 accessible 하려면, 그 Clifford가 accessible logical Pauli operator들의 집합을 보존해야 한다.
  - 즉:

    - accessible Pauli → Clifford로 변환 → 여전히 accessible Pauli
  - 여야 한다.
  - 만약 Clifford를 적용한 뒤 필요한 Pauli 측정이 cat factory가 지원할 수 없는 큰 weight가 되어버리면, 그 Clifford는 이 방식으로 접근 가능하지 않다.

> *비유*
>
> *사람이 옆을 볼 수 있는 방법*
>
> *1. 직접 몸을 돌려서 옆을 보는 방법*
>
> *2. 사람은 그대로 있고, 공간이 돌아서 내 눈앞에 펼쳐짐.*
>
> *결과는 같지만, 게이트 연산을 안하기 때문에 오류가 줄어서 시간 절약 자원 절약이 가능하다.*

**📌 이 섹션에서 실제로 말하는 것**

- - 이 섹션은 다음을 정의한다.

    - 1. logical Pauli operator를 physical representative로 표현한다.
    - 2. 그중 weight가 작은 representative를 선택한다.
    - 3. cat factory가 만들 수 있는 크기 안에 들어오면 accessible Pauli로 인정한다.
    - 4. accessible Pauli 집합을 보존하는 Clifford gate는 frame-tracking으로 구현 가능하다.

> *Section VI는 cat state, magic state, Bell state로 모든 연산을 설명하는 파트가 아니라, stabilizer code 위에서 측정 가능한 logical Pauli operator를 정의하고, 그 operator 집합을 보존하는 Clifford gate를 software frame-tracking으로 구현할 수 있음을 보이는 파트다.*
