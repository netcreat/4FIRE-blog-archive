  - 이 시스템은 **업계 최고 수준의 양자 게이트 정확도(최고 fidelity)** 및 **최초의 실시간 제어 엔진**을 갖추고 있어, 기업들이 실제 업무에서 양자 컴퓨팅을 활용할 수 있도록 설계되었다.

**✅ Helios 주요 특징**

**💡세계 최고 Fidelity**

- - **물리 큐비트(Physical qubits)**

    - **98 PQ**
    - **2큐비트 게이트 정확도: 99.921%**
    - **1큐비트 게이트 정확도: 99.9975%**
  - **논리 큐비트(Logical qubits)**

    - **94 LQ (Error-Detected)**: 전역 얽힘 상태에서 물리보다 더 높은 성능
    - **50 LQ (Error-Detected)**: 자성 시뮬레이션에서 물리보다 높은 성능
    - **48 LQ (Error-Corrected)**: **완전한 에러 보정**, SPAM fidelity 99.99%

**💡개발자 중심 아키텍처**

- - **새로운 Python 기반 언어 Guppy 출시**

    - 양자/고전 자원을 **단일 프로그램에서 하이브리드 통합**
    - 이종 컴퓨팅(heterogeneous computing)과 유사한 방식으로 개발 가능
  - **실시간 제어 엔진**

    - 기존 "실행 → 피드백 → 재실행" 구조를 뛰어넘어
    - **양자-클래식 연산을 실시간으로 혼합 운영**
    - 양자 오류 보정, 적응형 알고리즘에서 핵심 역할

**✅ Quantinuum Helios — ‘불가능의 재정의’**

**💡 Helios의 탄생: H2의 두 배 성능, 새로운 quantum advantage 영역으로**

- - Helios는 이전 세대 **H2(이미 양자 우위 달성)** 기반에서 **큐비트 수 거의 2배**, **fidelity 업계 최고치** 달성.
  - “세계에서 가장 강력한 상용 양자컴퓨터”로 공개.
  - 출시 전 2개월간 SoftBank, JPMorganChase 등이 초기 접근 프로그램에서 **실제 상용 연구 수행** → 이미 엔터프라이즈 급 검증 완료.
  - 클라우드와 온프레미스 모두 제공되며, **NVIDIA GB200 + NVQLink 통합 옵션**도 지원.

**💡 Helios가 만든 ‘스타 파워’ 양자우위**

- - **Random Circuit Sampling (RCS) 성능**

    - Helios의 RCS 결과는 Google의 "10^26년 필요" 수준보다 훨씬 높은 난도.
    - **단일 데이터센터 랙 전력**으로 수행.
    - 고전 시뮬레이션은 **태양 전체**, 혹은 “가시 우주의 모든 별”의 에너지가 필요.
  - **Fidelity**

    - **98 fully connected qubits**

      - 1Q: **99.9975%**
      - 2Q: **99.921%**
    - 상용 시스템 중 최고 정확도.

**💡 세계 최초: 상업용 Ion-Junction QCCD 아키텍처**

- - **“교차로(junction)” 등장**

    - QCCD의 핵심 구조: **ion routing traffic intersection**
    - 단일 직선형 trap → **도시의 도로망 같은 grid 확장 가능 구조**로 진화
    - 미래에는 **수백 개 junction**, 수천 큐비트 확장 목표
  - **Helios QPU 구조 (중요!)**

    - **Ring storage (메모리)**
    - **Cache (대기 영역)**
    - **Logic zones (계산 구역)**
    - **Leg storage (출력)**
    - → **하드디스크처럼 회전하며** 큐비트를 이동시키면서 병렬 계산 가능.

- - **기존 세대와 차이**

|  |  |
| --- | --- |
| **이전 (H1/H2)** | **Helios** |
| ion swap 기반 순차 정렬 | ring·cache·logic 통한 병렬 정렬 |
| cooling ↔ entangling 충돌 | cooling과 sorting 병렬 처리 |
| 확장성 제한 | junction 도입으로 확장성 개방 |

- - **All-to-All 물리 이동 가능**

    - → 슈퍼컨덕팅처럼 배선 고정(fixed qubit) 아키텍처의 한계를 넘어
    - → **모든 큐비트가 서로 직접 얽힐 수 있어** 복잡한 코드/알고리즘 수행 가능.

**💡 Ytterbium → Barium: 산업화 가능한 양자 하드웨어**

- - IonQ도 최근 Ba⁺ 도입했듯, Ba 이온은 UV 대신 **가시광 제어** 가능

    - → 지금까지의 비용·부품·내구성 문제를 대폭 해소
    - → 상용 확장성에서 결정적 장점
  - Ba 이온은 **자연적 leakage error 탐지·제거 가능**

    - → logical fidelity 향상

**💡 소프트웨어 혁명: Guppy + Real-Time Engine**

- - Quantinuum은 Helios와 함께 **새로운 전체 소프트웨어 스택**을 공개.
  - **Python 기반 언어 Guppy**

    - 동적 quantum-classical control
    - 조건문, 루프, 함수, early exit 가능
    - **클래식 프로그래밍처럼 양자 프로그램 작성**
  - **Real-time Control Engine**

    - 양자-고전 연산을 **실시간 혼합 실행**
    - GPU 가속(CUDA-Q), 동적 routing, 실시간 measurement feed-forward
    - 완전한 동적 회로 (dynamic circuits) 구현 가능
    - → IBM Heron도 피드백 지원하지만 Helios는 **전 스택 실시간 동기화**로 차별화.

- - **업계 유일:**

    - **보편적 fault-tolerant gate set 시연**
    - 가장 다양한 error-correcting code 구현

**✅ “QED는 원래 스케일되지 않는 기술이다 → 그런데 Quantinuum이 스케일 가능하다고 밝혀버렸다”**

- - 기존의 QED(Quantum Error Detection)는:

    - **오류를 고치지 못하고**
    - **잡히면 버리기만(post-selection)** 하기 때문에
    - 큐비트 수가 늘거나 회로가 깊어질수록

      - → **폐기율이 지수적으로 증가**
      - → 스케일 불가능(NISQ 한정)
    - 이라는 한계가 있었다.
  - 그런데 Quantinuum이 우연한 연구 과정에서 이 “스케일 불가능한 QED”를 **스케일 가능한 에러 관리 방식으로 바꾸는 아이디어**를 발견했다는 내용이다.
  - 결론부터 말하면:

> **오류가 감지되면 버리는 게 아니라**
>
> **→ 논리 회로 내부에서 “랜덤 reset 이벤트”로 변환하여**
>
> **→ 시뮬레이션의 일부로 활용하는 프로토콜을 개발했다.**

- - 즉 오류가 생겨도 버리지 않고 **논리 회로가 그 오류를 동적으로 흡수하고 활용**하는 방식.

**💡 핵심 아이디어: “오류를 버리지 말고 ‘무작위 리셋(random reset)’으로 바꿔라”**

- - **기존 QED 방식**

    - 오류 감지 → “Discard”
    - post-selection 폭증
    - 스케일 불가
  - **새로운 Quantinuum 방식**

    - 오류 감지 → **논리 회로 내부에서 ‘랜덤 초기화(reset)’ 이벤트로 변환**
    - 이 reset이 바로 **QCP(quantum contact process)** 모델이 자연스럽게 필요로 하는 연산
    - 그래서 오류를 **낭비하지 않고, 시뮬레이션의 일부로 사용**할 수 있게 됨
    - → **post-selection이 사실상 필요 없어짐**

> 원래라면 폐기해야 할 샷(86% discard 등)을 **연산 구조 자체의 일부로 다시 쓰는 방식**을 만든 것.

**💡 “스케일 가능해진 QED”가 정확히 무엇을 의미하나?**

- - QED가 스케일된다 = **오류를 감지해도 회로가 무너지지 않고, 버리는 비용이 폭발하지 않는다**는 뜻이다.
  - 기존 QED는:

    - 1단 QED → OK
    - 2단 → 86%2 = 98% 폐기
    - 3단 → 사실상 usable shot=0
  - 즉, z → z2 → z3 으로 폐기율이 폭증.
  - 그런데 이번 Quantinuum 프로토콜은 다음을 가능하게 함:

    - 폐기율 폭증이 없음
    - 감지된 오류를 회로 내부에서 “reset event”로 처리
    - 전체 회로를 버릴 필요 없음
    - 논리 회로가 노이즈에 적응(adapt)
    - 오류가 모델과 결합하므로 “물리적 noise = 시뮬레이션 변수”가 됨
    - QED의 비용이 **상수 또는 선형** 수준으로 유지됨
    - → 즉 **scaling 가능**
  - 이건 QED의 근본 구조적 한계를 뒤집는 결과.

**💡 왜 이 아이디어가 나왔나?**

- - (배경: Quantum Contact Process)

    - Quantinuum 팀은 **contact process**(전염 확산 모델)를 양자화한 QCP(Quantum Contact Process)를 연구 중이었음.
    - QCP는 “랜덤 reset 이벤트”가 본질적 구성 요소임:

      - 감염 → 상태 변화
      - 회복 → reset
      - 확산 → entanglement dynamics
  - 그런데 우연히 실험/이론 연구 과정에서 **하드웨어 오류가 감지될 때 나타나는 패턴이 QCP의 reset rule과 거의 동일하다는 사실을 발견**함.
  - 즉:

    - “오류 = QCP 모델이 요구하는 reset 연산”
    - (확산 모델의 한 연산으로 흡수 가능)
    - 이걸 이용하면 QED의 expensive post-selection을 피할 수 있다는 깨달음이 옴.

**💡 새로운 프로토콜의 핵심**

1. 1. **논리 회로가 noise를 동적으로 감지**
   2. 감지하면 → **논리 회로의 규칙에 맞게 reset**
   3. reset은 시뮬레이션의 일부
   4. 따라서 discard가 필요 없음
   5. 회로가 noise와 함께 “진화”하는 구조
   6. 논리 레벨에서 유지되는 fidelity는 거의 break-even
   7. (Logical performance ≈ Physical performance)
   - → **무거운 QEC 없이도 논리적 품질 유지 가능**

****

**💡 실제로 H2 시스템에서 검증됨**

- - Quantinuum은 이 프로토콜을 H2에서 실행하여:

    - **near break-even logical performance**
    - 즉, Iceberg 같은 강력한 QED 없이도
    - 논리회로가 물리회로와 거의 동일한 품질을 유지
    - **post-selection 비용은 거의 제로**
  - 라는 결과를 얻음.

**💡 왜 이건 “QED의 스케일링 문제 해결”로 평가되는가?**

- - 기존:

    - QED는 단층(1-layer)만 의미 있음
    - QED × 2 = discard 폭증
    - QED는 NISQ 장난감으로 취급됨
  - 이번 발견:

    - QED가 **스케일 가능한 형태**로 재해석됨
    - 논리 회로가 noise-adaptive하도록 설계 가능
    - QED가 QEC 전체를 대체하지는 않지만
    - → 매우 넓은 클래스의 문제에서 **QEC가 필요 없게 될 수도 있음**
    - 특정 시뮬레이션/양자다체물리 문제에 특화된
    - **practical fault-tolerance substitute** 역할 가능

**💡 이 발견이 실제 양자 컴퓨팅의 미래에 주는 영향**

- - **QEC와 QED의 경계가 흐려짐**

    - QED는 단순한 “버리기 기술”이 아니라 시뮬레이터 구조 일부로 포함될 수 있음.
  - **많은 시뮬레이션에서 full QEC가 필요 없어짐**

    - → 비용 폭감
    - → 더 빠른 scaling
    - → 초기 FTQC에 매우 도움
  - **양자 시뮬레이션 분야의 큰 변곡점**

    - 양자 접촉 과정
    - 비평형 양자 시스템
    - 노이즈 적응적 시뮬레이션
    - 랜덤 회로 연구
  - 등에서 압도적 성능 향상 가능.

**✅ Quantinuum의 “오류를 버리는 대신 Random Reset으로 변환한다”는 말의 의미는?**

- - 오류가 발생하면 샷을 버리는 게 아니라, **해당 큐비트를 0 또는 1로 랜덤하게 초기화**(reset)하고 시뮬레이션을 계속 진행한다.
  - 이 때 reset 이벤트는 **시스템의 동역학을 구성하는 랜덤성의 일부가 된다.**
  - 여기서 핵심이 되는 물리 모델은 Quantum Contact Process(QCP).

    - QCP(양자 접촉 과정)은 원래 다음 규칙을 가짐

      - 어떤 사이트는 확률 p로 감염(infected)
      - 확률 q로 회복(recovery) → reset 상태로 돌아가는 것
      - 주변 사이트와 상호작용하며 entanglement가 퍼짐
    - 즉 원래 모델 자체가 랜덤 reset 연산을 필수로 포함한다.
  - 그런데, Quantinuum팀이 발견한 것이,

    - **하드웨어에서 QED가 감지하는 “오류 패턴”이 QCP의 reset 연산 규칙과 똑같은 구조**라는 사실.
    - QCP 모델은 각 큐비트가 확률적으로 죽었다가(reset) 다시 살아나는(reinfected) 과정을 반복을 하는데,
    - 이 랜덤 reset 과정은 **error detection과 구조적으로 동일한 연산**임.

> 어차피 양자컴퓨터는 확률로 문제를 푸는 컴퓨터니까 한 문제를 푸는데도 10샷 100샷을 돌리니까 충분히 가능한 것 같은데?

**💡****하지만, 문제가 그리 간단하지 않다.**

- - 예를 들어 게이트를 수행하는데 1,000번중 868번(86.8%)의 에러가 난다면, 기존의 .QED는 에러 검출을 한 후 즉각 에러를 폐기하기 때문에 스케일링의 한계가 있다는 것이다.
  - 그럼 이번에는 868번의 에러를 전부 폐기하지 않고 랜덤하게 0 또는 1로 세팅해서 원래 계산에 사용한다고 가정해보자. 여기서는 이해하기 쉽게 50%의 확율로 리셋을 한다고 가정하면, 1000번의 게이트 연산중 운이 너무나도 좋아서 50%의 확율로 1과 0으로 세팅한 값이 에러가 없었을 때의 값과 동일하다면 결과는 퍼펙트 하다. 하지만, 반대로 운이 너무나도 안좋아서, 1이어야 할 값을 0으로, 0이어야 할 값을 1으로 세팅했다면, 우리는 1000번의 게이트 연산중 132번만 제대로된 값을 얻게 되는 것이다.

**💡 핵심 1: 이 프로토콜은 “정답을 찾는 알고리즘”이 아니라 “확률적 양자 다체 시뮬레이션”에서만 유효하다.**

- - **QAOA, Grover, factoring(Shor), VQE처럼 정확한 답을 출력**해야 하는 알고리즘에는 불가능.
  - 왜냐면 말한 것처럼:

    - 오류를 reset으로 바꾸면 원래 알고리즘의 의미가 붕괴되기 때문.
  - **그러나 양자 다체 시스템의 동역학 시뮬레이션에서는 가능하다.**
  - 예: Quantum Contact Process(QCP)

    - 감염 ↔ 회복(reset)
    - 전이 확률
    - 전파 동역학
    - 노이즈/확률적 이벤트 자체가 “현상”의 일부
  - 즉, **정확한 정답이 필요한 알고리즘이 아니라 확률적 진화 자체가 목적**인 “양자 물리 시뮬레이션” 같은 특정 분야에서만 유효하다는 것이다.

**💡핵심 2: “랜덤 reset”은 진짜 완전히 무작위가 아니다.**

- - Quantinuum의 reset 프로토콜은 다음과 같은 구조를 가진다:
  - **(1) error detected**

    - → 이 정확한 qubit에 reset 필요
  - **(2) reset to a well-defined state**

    - **reset은 모델이 요구하는 특정 규칙을 따름**.
  - 아무 값이나 넣는 게 아니라, **시뮬레이션 규칙에 부합하는 형태로 reset**한다.
  - 이 때문에 “운이 나쁘면 86% 다 틀린다” 같은 극단적 상황은 발생하지 않음.

**💡 핵심 3: 확률적 시뮬레이션에서는 “맞는 단일 답”이 없다.**

- - Shor처럼 “정답은 이 수이다.” 가 아님.
  - QCP처럼:

    - “이 시스템의 steady-state 감염률은 0.342이다.”
    - “이 초전도 pairing correlation은 0.27이다.”
  - 같은 집계 통계량(scientific observable)이 출력.
  - 따라서 랜덤 reset은 **통계적 ensemble의 일부**로 포함될 수 있고 전체 분포에 맞춰 평균값이 수렴하면 된다.
  - 즉:

    - reset 노이즈가 모델의 본질적 확률성에 포함됨
    - 많은 샷을 평균하면 **원래 이론 모델에 근접**한다
    - 정확한 단일 정답이 필요한 알고리즘과 달리
    - 통계적 물리량을 구하는 데는 문제 없음

  - **가운데 X자 형태: 정션(Junction)**

    - 이것이 Helios의 핵심 혁신.
    - 이온을 **위/아래/좌/우로 이동시키는 사거리 교차로**

    - 필요한 순간에 메모리에서 이온을 불러옴
    - 병렬 게이트 운영 가능

**💡QCCD 운영 방식**

- - **1) 링에서 캐시를 거쳐 로직존으로 이동(Transport)**

    - 링을 회전시켜 원하는 2개(또는 4개)의 이온을 정션 방향으로 정렬한다.
    - 정션을 통과하여 “상단/하단 다리(top/bottom legs)”로 이동한다.
    - 캐시(zone)에 저장한 뒤, 로직존(logic zones)으로 다시 이동하여 게이트 수행.
  - **2) 병렬 냉각(Parallelized cooling)**

    - 게이팅을 수행한 이온들은 이동 중 열이 쌓이며,
    - 이를 제거하기 위해 Helios는 H1/H2와 달리 **냉각을 공간적으로 분산**했다.
    - 과거: 냉각과 게이트가 동일 존에서 수행 → 병목 발생
    - Helios: 냉각과 게이트 존을 구분 → 더 빠른 운영 속도 달성
  - **3) 병렬 게이팅(Parallelized 1Q/2Q gates)**

    - 각 operation region마다 8개의 로직존이 있어 동시에 여러 개의 게이트(특히 1Q 게이트)를 실행할 수 있다.
    - 2Q 게이트는 동일 로직존의 이온 쌍에 적용된다.
  - **4) 회수(Return) 및 재정렬(Sorting)**

    - 연산을 마친 이온들은 **다시 링으로 돌아가며**, 이동 과정에서의 순서나 위치가 달라지기 때문에
    - 새로운 회로 레이어를 위한 재정렬(slicing and sorting)이 필요하다.

**💡링 구조 덕분에 “유휴 큐비트”를 최소화**

    - 쿨링 중 대기
    - 스왑 경로 확보
    - 연산 중 충돌 방지
    - 때문에 **수많은 물리 큐비트가 비어 있어야 했다.**

    - **병렬 냉각**

      - **“필요한 순간에 필요한 이온만 로직 존으로 가져오는” 구조**
      - → 물리 자원 낭비가 거의 없음.

**💡****Iceberg 코드 기반의 초고효율 오류 정정 인코딩 (2:1 물리:논리 비율) - 위의 QED 참조**

- - **기존 QEC는**

    - 1개의 논리 큐비트를 만들기 위해 **수백~수천 물리 큐비트**가 필요함
    - (예: IBM Surface-17 → 1 LQ 만드는 데 49 PQ 필요)
  - **그러나 Helios는:**

    - Iceberg Code = ancilla가 **2개**만 필요
    - *k 논리 큐비트*를 *k + 2 물리 큐비트*로 인코딩하는 구조임.

      - 98개의 물리 큐비트로 96개의 논리 큐비트 생성가능
    - Code concatenation = 계층적 조합
    - 단 2개의 물리 큐비트가 **1개의 논리 큐비트**로 동작하는 “2:1 인코딩” 가능
    - 실험 결과

      - 폐기율(discard rate) : 86.8 ± 0.7%

        - 폐기율이 높다는 것은 Iceberg가 잘 작동한다는 의미
        - 일반적인 QED라면 1000개의 큐비트 중 868개는 에러가 나서 버리고, 나머지 132개만 사용하는 것임.
        - Random reset을 이용하여 버리지 않고, 전부 다 사용.

          - 에러를 전부 버리면, 스케일의 한계가 발생

            - distance가 2라서 스케일 제한인데, 이를 아래에서 설명하는 Code Concatenation을 사용하게 되면 스케일을 늘릴 수 있지만, 사용할 수 있는 큐비트가 절대적으로 부족해짐.
          - 에러를 랜덤 리셋해서 사용하면, 정확도가 떨어지는 trade-off 발생

            - 정확단 답을 출력해야 하는 알고리즘에서 사용 불가

**💡코드 컨캐티네이션(Code Concatenation)**

- - Helios는 Iceberg 코드 기반으로

    - **1차 코드 + 2차 코드**를 겹쳐서 사용
    - → 매우 높은 오류 탐지 및 수정 가능
  - 이 구조가 **단 2개의 앤실라(Ancilla)로 완전한 오류 보정**을 가능하게 한다.
  - 즉,

    - **각 논리 큐비트 사용 물리 큐비트: 약 2개**
    - → 물리:논리 = **2:1** 비율 성립
  - **Code Concatenation의 단점**

    - 아이스버그(Iceberg)는 **오류** ***검출(QED)*** **기반**이기 때문에 이를 그대로 **2단, 3단으로 “중첩(concatenate)”해서** 사용한다면 폐기율(discard rate)은 **지수적으로 증가한다.**

      - 이를 해결하기 위해,

        - 1차 : Inner layer (Iceberg)는 오류 검출 담당
        - 2차 : outer layer (FEC)는 1차 Iceberg로 부터 받은 블록을 깨끗한 물리 큐비트처럼 취급하고, 오류를 실제로 수정(correct)할 수 있음

**💡그럼에도 불구하고 에러가 발생하면 정정을 어떻게 하나?**

- - 논리 블록 인코딩(Iceberg 또는 concatenated code).
  - 계산 중 정기적 신드롬 측정(중간 측정, reset 가능).
  - 신드롬은 GPU로 스트리밍 → 즉시 디코딩 → Pauli frame 또는 복구 게이트 명령 생성.

    - 디코더 지연 발생 우려
  - 복구는 가능한 경우 Pauli frame으로 처리하여 물리 펄스를 줄이고, 누설 감지 시 즉시 repump 루틴을 호출.
  - 전체 루프가 논리 시계(logical clock)를 크게 늦추지 않도록 병렬화/파이프라인화.

**💡Co-Compilation Framework**

- - Background

    - Iceberg QED 코드는 원래 “오류 검출(error detection)”만 가능한 extremely low-overhead 코드.
    - QEC(정정)보다 훨씬 싸지만 기본적으로 **post-selection 폐기율 문제** 때문에 확장성에 한계.
    - 이 논문은 **Iceberg와 양자 알고리즘을 동시에(compiled together) 최적화하는 전략**을 제안.
  - Iceberg 코드의 보호 동작과 알고리즘 고유 회로(QAOA, random circuits 등)를 **하나의 최적화된 회로로 합성(co-compile)**.

    - 이 연구에서는 Random reset을 사용하지 않아서 QAOA 가능
  - **연구 환경**

    - Quantinuum H2
  - **QAOA 사례**

    - Co-compiled Iceberg 적용 후 **성공률 44% → 65%** 개선.
  - **Algorithm depth 영향**

    - 깊이가 깊을수록 Iceberg 보호 효과가 더 커짐.
  - **Post-selection rate 감소**

    - Iceberg 단독 사용 대비 discard가 크게 감소.
