**✅Classiq란 어떤 기업인가?**

**💡 기업 개요**

- - **Classiq Technologies**는 이스라엘(텔아비브)과 미국(보스턴)을 기반으로 한 **고급 양자 소프트웨어 플랫폼 기업**이다.
  - 한 문장으로 요약하면:

    - “고수준 알고리즘 정의 → 자동 회로 생성 → 최적화 → QPU 실행”까지 전체 양자 SW 스택을 자동화하는 기업
  - 중간 소프트웨어 계층(컴파일러·IDE)을 전문적으로 만든다.

**✅Classiq의 주력 사업 (Core Business)**

Classiq의 사업은 크게 **4개 축**으로 나뉜다:

**1️⃣ 고수준 양자 개발 플랫폼 (IDE + High-Level Language)**

- - **Classiq Quantum IDE : Classiq의 대표 제품**

    - 고수준 추상화 언어 제공
    - 알고리즘의 *수학적 구조만* 입력하면
    - → 자동으로 최적화된 양자 회로로 변환
    - 즉, 다음과 같은 “전문가 공정”을 자동으로 수행한다:

      - 회로 설계
      - 게이트 최적화
      - 얽힘 구조 생성
      - QPU별 매핑 (Hardware-aware mapping)
    - 이 부분이 **Classiq의 절대 핵심 기술(헤자)**.

> **IDE = Integrated Development Environment (통합 개발 환경)**
>
> 코딩, 디버깅, 시각화, 실행까지 한 곳에서 할 수 있는 개발자용 작업 환경 전체를 통합한 소프트웨어
>
> 
>
> Classiq의 IDE는 "**양자 전용 IDE**"이다.

**2️⃣ Algorithmic Quantum Circuit Compiler (회로 자동 생성 엔진)**

- - Classiq의 컴파일러는 “문제 정의 → 회로” 변환을 자동화한다.
  - **기존 방식**

    - 직접 Qiskit 등을 사용해

      - 게이트 하나하나 설계
      - 얽힘 구조 수동 생성
      - 하드웨어 제약 반영
      - → 난이도 매우 높음
  - **Classiq 방식**

    - 변수, 제약조건, 목적함수 →
    - 알고리즘 구조 파악→
    - Classiq 컴파일러가 자동으로 회로 생성→
    - IonQ, QuEra, Rigetti 등 HW별 최적화 버전 출력
    - 이는 타사에서는 아직 제대로 구현하지 못한 부분이며 **Classiq만의 강력한 기술적 차별점**이다.

**3️⃣ Multi-Hardware Platform (HW-Aware Optimization)**

- - Classiq은 전 세계 주요 QPU를 위한 **통합 실행 플랫폼**을 제공한다.
  - 지원 QPU:

    - IonQ
    - Quantinuum
    - IBM
    - Rigetti
    - Orca
    - QuEra
    - Atom Computing
    - Nvidia CUDA-Q 시뮬레이터
  - 즉,
  - **“하나의 문제 정의로 모든 QPU에 실행 가능하게 하는 역할”**

****

**4️⃣ 엔터프라이즈용 Quantum Application 개발 패키지**

- - Classiq은 기업 고객을 위해 도메인 특화 양자 애플리케이션 솔루션을 제공한다.
  - 대표 분야:
  - **금융**

    - 리스크 분석
    - Monte Carlo
    - Derivative Pricing
    - 보험 손실 모델링 → 2024년 NQCC 우승팀도 이 분야 사용
  - **물류/제조**

    - 네트워크 최적화
    - Routing
    - Scheduling
    - Supply chain optimization
  - **헬스케어**

    - NHS 수요 예측
    - 복잡 모델링
  - **에너지**

    - Grid optimization
    - 전력 조정 모델
  - 이들을 위해 Classiq은:

    - 템플릿 라이브러리
    - 문제 구조 패러미터 정의 시스템
    - HW별 최적 회로 생성
    - 을 기업에 제공한다.

**📌 Classiq의 기술 헤자(Competitive Moat)**

Classiq의 기술적 강점은 3가지다.

**🧱 1. Algorithmic Circuit Synthesis 엔진**

- - (회로를 사람이 아닌 **수학적으로 자동 생성하는 엔진**)
  - 이것은 다른 양자 SW 기업이 못 따라오는 부분.
  - “회로 설계 난이도를 100배 낮추는 기술”

**🧱 2. HW-aware Compiler**

- - IonQ의 MS 게이트
  - IBM의 CX 게이트
  - QuEra의 Rydberg blockade
  - Rigetti topology
  - 전부 자동으로 탐지 → 최적 매핑한다.
  - 다른 기업들은 대부분 **Qiskit-like low-level 방식**이어서 이 수준의 자동화가 불가능하다.

**🧱 3. Multi-QPU abstraction layer**

- - 예:
  - 같은 알고리즘 설계

    - → IonQ에서도 실행 가능
    - → IBM에서도 실행 가능
    - → QuEra에서도 실행 가능
  - 이 기능은 **엔터프라이즈 시장에서 매우 큰 장점**이다.

**📌 Classiq의 비즈니스 모델 (BM)**

- - **기업용 SaaS 라이선스**

    - IDE/Compiler 사용료
    - 사용자 수 기반 과금
  - **클라우드 QPU 실행 수수료**

    - IonQ/IBM/Rigetti 등에서 실행할 때
    - → Classiq 플랫폼을 통해 실행하면 수수료 발생
  - **엔터프라이즈 컨설팅**

    - 금융·에너지·제조사 대상
    - 실제 문제 전용 알고리즘 개발
  - **정부 및 국가 프로젝트 참여**

    - 영국 NQCC
    - EU Horizon 프로젝트
    - 이스라엘 국책 프로그램 등

> **📌 Classiq = 양자 개발의 자동화 + 추상화 + 산업화 플랫폼**

**✅HW-aware는 추상화와 관련이 있는데, Xanadu의 Pennylane과 차이점은?**

**💡PennyLane vs Classiq — “겉으로 보기엔 비슷하지만 본질적으로 다른 계층”**

- - PennyLane은 실행 연결 계층(HW abstraction layer)
  - Classiq는 알고리즘 생성 계층(Algorithm synthesis & HW-aware optimization)
  - 즉,

    - **PennyLane = 회로를 가져와 여러 QPU에서 동일하게 실행할 수 있게 해주는 프레임워크**
    - **Classiq = 아예 회로 자체를 만들어주고 최적화하여 QPU별 최적 버전으로 변환해주는 플랫폼**
  - 예를 들어 QAOA 문제를 해결한다면

    - Pennylane은 회로 코딩을 해줘야 하지만,

      - 그래프 → 직접 QAOA 회로 구성 → 파라미터 튜닝 → 실행
      - (회로는 직접 Qiskit 스타일로 작성해야 함)
    - Classiq는 회로 코딩을 필요로 하지 않는다.

      - 그래프, 비용함수, 제약조건 입력 →
      - Classiq가 최적 회로 자동 생성 →
      - IonQ 용, IBM 용, QuEra 용 각각 최적 회로 생성 →
      - 테스트 및 반복

|  |  |  |
| --- | --- | --- |
| **항목** | **PennyLane** | **Classiq** |
| 목적 | 여러 QPU를 단일 인터페이스로 연결 | 고수준 문제 정의 → 자동 회로 생성 및 최적화 |
| 입력 | 사용자가 직접 작성한 회로(Qiskit 스타일) | 문제(수학 모델, 제약, 목적 함수) |
| 출력 | 동일 회로를 여러 QPU에서 실행 | QPU별 최적 형태로 재구성된 회로 |
| 위치 | 런타임 실행 프레임워크 | 설계 + 컴파일 + HW 최적화 |
| 기능 | 미분, QML, back-end switching | 회로 합성, 게이트 최적화, 연결성 매핑 |
| 난이도 | 회로 설계는 여전히 사람이 해야 함 | 회로 설계 필요 없음 (자동 생성) |
| 대상 | 연구자, ML 개발자 | 엔터프라이즈, 산업 프로젝트 |

**✅****IonQ는 왜 Classiq가 필요한가?**

**💡IonQ의 SW팀은 “미들웨어 + QPU 제어 + 에러 억제” 전문가**

- - IonQ 개발자들은 이런 영역을 담당한다:

    - 펄스 제어
    - 레이저 캘리브레이션
    - 스펙트럼 및 cross-talk 억제
    - 게이트 에러 모델링
    - SPAM 보정
    - Clifford Noise Reduction(CliNR)
    - 미들웨어 엔진
  - 👆 IonQ 팀은 **하드웨어에 최대 성능을 내게 만드는 전문가들**

****

**💡Classiq는 “양자 알고리즘 설계 자동화 + 회로 합성 전문가”**

- - Classiq는 아래 영역 전문가다:

    - 산업 문제 → 수학 모델링
    - 알고리즘 ↔ 회로 자동 변환
    - HW-aware 최적 변환
    - Multi-QPU migration
    - 엔터프라이즈 애플리케이션 개발
  - IonQ는 **엔터프라이즈 고객의 비즈니스 문제를 회로로 바꿔주는 팀이 아니다.**
  - 회로 설계는 고객 또는 소프트웨어 계층의 역할이다.

**💡IonQ와 Classiq가 서로 필요한 이유**

|  |  |
| --- | --- |
| **IonQ가 Classiq를 필요로 하는 이유** | **Classiq가 IonQ를 필요로 하는 이유** |
| 산업 고객의 문제를 구현할 인력 부족 | 세계 최고 HW에서 성능을 증명해야 함 |
| 회로 설계 자동화 계층 부족 | IonQ의 전결합 구조 활용이 최적 |
| 고객 진입 장벽 낮춰야 함 | HW 의존성 없는 확장성 확보 |
| 엔터프라이즈 협업 확대 | 공동 판매, 공동 배포 모델 필요 |

**💡인수 대신 투자를 선택한 이유**

- - Classiq의 가장 큰 장점은 **IonQ·IBM·QuEra·Rigetti·Quantinuum·Orca·CUDA-Q 등** 모든 QPU에서 실행·최적화 가능한 범용 플랫폼
  - 만약 IonQ가 Classiq를 인수하면,

    - Classiq는 사실상 IonQ 전용 플랫폼으로 보일 가능성이 커지고
    - 타 하드웨어 업체들이 Classiq 채택을 꺼릴 수 있음
  - IonQ는 HW 중심, Classiq는 SW 및 애플리케이션 중심 회사
  - IonQ가 인수하게 되면 **Classiq의 독립 생태계**(고객·파트너)와 **HW 중립성**을 잃는다
  - 생태계 확장을 위해서라도 Classiq를 소유하면 안됨.
