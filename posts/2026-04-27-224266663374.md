**✅ XIX. Physical Implementation of the Walking Cat Architecture**

**📌 이 챕터의 본질**

- - 지금까지는 “논리 구조”였다면 여기부터는 **“Moving qubit 모델을 실제 trapped-ion(QCCD) 칩 위에서 구현하는 방법”**

****

**📌 물리 플랫폼: Trapped-ion + QCCD**

- - **기본 구조**

    - 이온 = qubit
    - RF field → trapping (가둠)
    - DC electrode → 위치 제어
  - **QCCD 구조**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMTAx/MDAxNzc3MjU2Mzk0NDU3.aBVX2P671_wjNwSJPfdT29odO2TbTbRapOiBE-yoqyUg.4_is1q4uPZzFG6f5yq5Ot8rXqzd837EslSpJk5xA6Wcg.PNG/image.png?type=w800)](#)

- - - 2D grid (junction + linear sections)
    - 이온은 potential well에 위치
    - 전압 조절 → well 이동

|  |  |
| --- | --- |
| **영역** | **역할** |
| transport line | 이동 |
| junction | 경로 변경 |
| well | qubit 저장 |
| gate zone | 연산 |
| optical zone | 측정 |

- - **핵심 차이**

    - **“연산 = 이동 → 정렬 → interaction”**

|  |  |
| --- | --- |
| **기존 QC** | **Walking Cat** |
| qubit 고정 | qubit 이동 |
| gate 전달 | 위치 이동으로 gate |

****

**📌 Potential Well 기반 동작**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMTIz/MDAxNzc3MjU1ODY2MzMz.BkrcqJ0qi9YPLJ0yx9qBthvWRNfUt0He6y9SMOv94vMg.OOKsFrZi7_JmdkifiEKFRIFUm4FkjxCabpXaZVVbGEcg.PNG/image.png?type=w800)](#)

- - **Merge**

    - 두 well → 하나
    - 두 이온 가까워짐
    - 2Q gate 준비
  - **Split**

    - 하나 → 둘
    - 연산 후 분리
  - **Translate**

    - well 자체 이동
    - qubit transport
  - **핵심 직관**

    - **모든 연산 = merge + split + 이동 조합**

****

**📌 Moving Qubit 모델의 현실 제약**

- - 이론 모델 vs 실제 구현
  - **이동은 자유롭지 않다**

    - junction 따라 이동
    - arbitrary 이동 불가능
  - **이동은 단계적이다**

    - 한 번에 이동 ❌
    - 여러 step 필요
  - **이동은 비용이 있다**

    - heating 발생
    - motional excitation 증가
    - fidelity 저하
  - **2Q gate 조건**

    - 반드시:

      - 같은 well
      - 같은 gate zone
  - **결론**

    - **“연산보다 이동이 더 비싸고 어렵다”**

****

**📌 QCCD 칩의 기능 구조 (Section A)**

- - **핵심 아이디어**

    - **“기능별 공간 분리 + 반복 가능한 unit cell”**
  - **구성 요소**

    - **Gate zone**

      - 1Q / 2Q gate 수행
      - RF antenna 존재
    - **Photonic zone**

      - measurement 수행
      - laser + photon detection
    - **Transport network**

      - junction + linear path
      - qubit 이동 경로
  - **중요한 포인트**

    - **연산 / 측정 / 이동이 물리적으로 분리됨**

****

**📌 Electronic Qubit Control (EQC)**

- - **기존 방식**

    - laser 기반 gate
    - 문제:

      - 광학 정렬 어려움
      - scaling 어려움
  - **EQC 방식**

    - RF magnetic field 사용
    - antenna 기반
  - **장점**

    - 병렬 gate 가능
    - wiring 간단
    - 확장성 좋음
  - **단점**

    - field localization 어려움
    - gradient 설계 필요
  - **의미**

    - **“이 구조는 laser scaling 한계를 넘기 위한 설계”**

****

**📌 Ion 내부 상태와 연산**

- - **qubit 정의**

    - 두 internal state 사용
    - metastable state 포함
  - **주요 과정**

    - **State preparation**

      - optical pumping
      - 특정 상태로 초기화
    - **Gate**

      - RF로 상태 변환
      - 2Q는 motional mode coupling
    - **Measurement**

      - laser excitation → fluorescence
      - photon detection
    - **Cooling**

      - phonon 제거
      - heating 보정
  - **핵심**

    - **“논리 연산은 내부 상태, 물리 제약은 motion”**

****

**📌 Transport 비용 모델**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMTA3/MDAxNzc3MjU2NzQzOTY3.XZ_Fe-xEpMCnAIyCdKfdIdqzEOxTOTg2hzVFqB_5Jhkg.vd6RsQ74Qlsm_VvjwlVFsKn3T1almnKPHLSJsZIbqlEg.PNG/image.png?type=w800)](#)

- - **중요한 개념**

    - **transport cost ≠ constant**
  - **이유**

    - 이동 거리
    - heating
    - cooling 필요 여부
  - **최적화 방향**

    - **“가장 적은 이동으로 gate 수행”**

****

**📌 Zonal Operation (중요)**

- - **핵심 제약**

    - 2Q gate는:

      - 특정 gate zone에서만 가능
  - **결과**

    - qubit을 gate zone으로 이동해야 함
    - 모든 쌍이 바로 gate 불가능
  - **의미**

    - **“연산은 공간적으로 제한됨”**

****

**📌 Parallelism (병렬성)**

- - **장점**

    - 여러 gate zone 존재
    - 병렬 실행 가능
  - **하지만**

    - 이동 충돌 가능
    - scheduling 필요
  - **결론**

    - **“병렬성은 있지만, routing이 bottleneck”**

****

**📌 Micro-architecture vs Moving Model 차이**

- - **Moving model (이론)**

    - 자유 이동
    - 모든 pair 가능
    - 비용 단순
  - **Micro-architecture (현실)**

    - 경로 제한
    - 추가 이동 필요
    - 비용 증가
  - **핵심 차이**

    - **현실에서는 항상 더 많은 이동이 필요하다**

****

**📌 최종 핵심 Insight**

- - **bottleneck이 아닌 것**

    - qubit 수
    - gate fidelity
  - **진짜 bottleneck**

    - **Transport + Routing + Scheduling**

****

> ***“Walking Cat은 결국 ‘어디서 연산할지’보다 ‘어떻게 이동시킬지’의 문제다.”***

**✅ XX. Micro-architecture of the Components**

**📌 이 챕터의 본질**

- - **“Memory / Magic / Cat factory를 QCCD 위에 실제로 배치하고 돌리는 방법”**

****

**📌 전체 구조 관점**

- - Walking Cat 전체 구조:

|  |  |
| --- | --- |
| **컴포넌트** | **역할** |
| Memory block | 데이터 저장 |
| Magic factory | T gate 자원 |
| Cat factory | measurement |
| Ancilla | 보조 연산 |

- - 문제:

    - 이걸 **2D ion trap 위에 어떻게 배치하고 연결할 것인가?**

****

**📌 핵심 아이디어: 3-ring 구조**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMTUx/MDAxNzc3MjYxNzQxMTc3.pvJe7ZW-f9UPnVI0jT79oMcna_lfIf_ukagiDdwksIsg.jWDejiW_-c_W3veiJw7RzvNdbFGSGjlZcbAgOSByiI8g.PNG/image.png?type=w800)](#)

- - **3가지 ring**

    - **Long ring**

      - 블록 간 이동
      - 큰 scale routing
    - **Medium ring**

      - ancilla 이동
      - 중간 수준 연결
    - **Short ring**

      - local shift
      - block 내부 재배열
    - **핵심 직관**

      - **“게이트 대신 위치 permutation으로 연산한다”**
  - **실제 ring 동작**

    1. 3,4 번 이온을 vertical leg에 숨김
    2. 1,2번 이온을 이동시켜 lower vertical leg에 저장
    3. 3,4번 이온을 꺼내서 왼쪽으로 이동시킴
    4. 1,2번 이온을 다시 꺼냄.

**📌 Memory & Magic factory 구현**

  - **목표**

    - logical qubit 유지
    - ancilla와 interaction 가능
    - 최소 이동
  - **동작 흐름**

    - **Step 1**

      - ancilla 이동
    - **Step 2**

    - **Step 3**

      - merge → 2Q gate
    - **Step 4**

      - split
    - **Step 5**

      - 원위치 복귀
    - 반복
  - **핵심 문제**

    - **“어떻게 하면 이 이동을 최소화할까?”**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfMjE2/MDAxNzc3MjYyMjA3NzQ3.IXiyxPuL4P6jgWj0eTcdz17X16mbBJJUZ4Ruk4F1kh0g.tsgU3JwtssF48w_Qy1V0y92RupoGSmhUI78baY9s00gg.PNG/image.png?type=w800)](#)

- - **구조**

    - **진한 초록 → data qubit**
    - **연한 초록 → ancilla**
    - **빈 줄 → transport 전용**
  - **핵심 설계**

    - **1. 일부 row는 비워둔다**

      - **→ 이동 전용**
      - **엄청 중요**
    - **2. ancilla 개수 = 5의 배수**

    - **3. vertical leg는 비워둠**

      - **→ long ring transport용**

    - 이건 density 싸움이 아니라 routing capacity 설계다

- - **CH2 Magic factory 기본 구조**

    - **🟣 진한 보라 → data qubit (또는 beacon)**
    - **🟡 노랑 → data qubit (다른 역할/위)**
    - **🟣 연보라 → ancilla qubit**
    - **H state resource**
    - **“두 개의 순환 라인 (loop)” 구조**

      - 위쪽 loop
      - 아래쪽 loop
      - 각각이 하나의 **CH2 processing lane**
  - **핵심 구성 요소**

    - **H state input (왼쪽 H)**

      - **외부에서 공급되는 |H⟩ magic state**
      - **CH2 프로토콜의 “원재료”**
      - **T gate의 씨앗**
    - **Data qubits (보라/노랑)**

      - **실제 정제 대상**
      - **noisy magic state 포함 가능**
    - **Ancilla qubits (연보라)**

      - **stabilizer 측정용**
      - **parity check 수행**
      - **오류를 “보는 센서” 역할**
    - **Loop (보라 점선 경로-핵심)**

      - **“cyclic processing pipeline”**
      - **qubit들이 계속 순환하면서 반복적으로 정제 수행**
  - **동작 흐름 (CH2 직관)**

    - **Step 1 — H state 투입**

      - **왼쪽에서 |H⟩ 들어옴**
    - **Step 2 — entanglement**

      - **data + ancilla 결합**
    - **Step 3 — measurement**

      - **오류 syndrome 측정**
    - **Step 4 — filtering**

      - **좋은 state만 유지**
    - **Step 5 — 순환**

      - **다음 라운드로 이동**

**📌 Cat state routing**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjdfNTAg/MDAxNzc3MjYzMTU0MjYw.81iBZwPr76MXlpIjxxY7-HhRJa1JbSwk0LqRgArTOdwg.lB1wUNsy54VUaTGl0kp-lGli06UjDzrno-Cmyf2bGvEg.PNG/image.png?type=w800)](#)

- - **weight-18 cat state 생성의 실행**

    1. **Initial layout**

       - data qubit (진한 주황)
       - ancilla qubit (연한 주황)
       - **아직 아무것도 안 한 상태**
    2. **Cyclical data shift**

       - qubit들을 loop 형태로 이동
       - “순환 이동 (cyclic shift)”
       - **게이트를 하기 위해 위치를 맞춤**
    3. **Vertical data transport**

       - 위/아래 방향으로 이동
       - 서로 다른 row의 qubit을 정렬
       - **interaction 가능한 위치로 모으는 과정**
    4. **CX gate — 8 pairs**

       - qubit 쌍을 만들어
       - 동시에 CX (2-qubit gate) 수행
       - **특징**

         - **active gate zone에서 “8쌍 병렬 처리”**
         - **여기서 entanglement 생성됨**
    5. **Ancilla-data CX**

       - ancilla ↔ data 연결
       - stabilizer 측정 준비
       - **error detection을 위한 coupling**
    6. **Ancilla measurement**

       - ancilla 측정
       - optical zone 사용 (노란 해칭)
       - **syndrome 생성 (오류 정보)**
  - **특징**

    - 여러 qubit 동시에 처리
    - 파이프라인 구조
    - gate zone과 optical zone은 별도로 배치

      - measurement = fluorescence detection
      - gate는 microwave / RF / laser로 아주 미세하게 상태 조작
      - gate fidelity 붕괴됨.
  - **핵심**

    - **“cat state가 돌아다니면서 연산을 수행한다”**

- - **Cat state를 메모리 블록(Q70)으로 ‘배송’해서 data qubit과 맞춘 다음 한 번에 측정/연산하는 과정**
  - **전체 구조**

    - **왼쪽: Cat factory (w=18)**
    - **오른쪽: Q70 memory block**
    - **주황색 경로: 이온 이동 경로******
  - **핵심 개념**

    - cat state는 여러 qubit이 하나의 측정 리소스
    - 이걸 data qubit 위치에 정확히 정렬해야 함
  - **3단계 이동 (논문 핵심)**

    1. Vertical transport (세로 이동)

       - 목적:

         - 목표 data row 맞추기
       - 그림:

         - 위/아래로 이동
    2. Horizontal shift (가로 이동 + 늘어남)

       - 핵심 키워드:

         - “accordion movement”

           - qubit 간 간격 늘리면서 이동
         - 이유:

           - data qubit 위치와 1:1 매칭
    3. Final merge (마지막 결합)

       - 목적:

         - data qubit과 ancilla(cat qubit) 결합
       - 결과:

         - CX gate 수행 가능
  - **중요한 디테일**

    - w/2만 먼저 이동

      - cat state = 18 qubit
      - 한 번에 다 못 옮김
      - 절반씩 (9개씩) 이동
    - 두 번 반복

      - Batch 1 이동 → 연산
      - Batch 2 이동 → 연산
    - 왜 이렇게 복잡하냐

      - 이유 1 — routing 문제

        - qubit은 고정된 wire 없음
        - 반드시 이동 필요
      - 이유 2 — 충돌 방지

        - 모든 qubit 한 번에 이동 ❌
        - congestion 발생
      - 이유 3 — 병렬성 유지

        - 가능한 한 많은 pair 동시 처리
