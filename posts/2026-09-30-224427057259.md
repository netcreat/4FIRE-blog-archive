**✅ 1. 양자컴퓨팅의 출발점부터 기대치를 낮춘다**

**📌 양자컴퓨터가 모든 어려운 문제를 풀어주는 것은 아니다**

- - Ezratty는 양자컴퓨팅을 소개하는 첫 장부터 상당히 신중한 입장을 취한다.
  - 양자컴퓨터가 의미 있는 가속을 제공하려면 단순히 quantum algorithm이 존재하는 것으로 부족하다.
  - 특정 문제에 적합한 양자 알고리즘이 있어야 하고, **데이터 준비부터 계산과 측정까지 포함한 end-to-end resource scaling**에서도 이점이 남아야 한다.
  - 따라서 고전컴퓨터로 풀기 어려운 문제가 모두 양자컴퓨터로 쉬워지는 것은 아니다.
  - 특히 대량의 고전 데이터를 다루는 문제에서는 기존 컴퓨터가 여전히 매우 강하다.
  - 데이터를 양자 상태로 집어넣는 과정 자체가 병목이 될 수 있기 때문이다.
  - 저자는 **Moore의 법칙 역시 아직 끝났다고 보기 어렵다**고 지적한다.
  - 즉 양자컴퓨터의 경쟁 상대는 지금의 고전컴퓨터가 아니라 **계속 발전하는 미래의 CPU·GPU·AI·HPC 시스템**이다.

**📌 NISQ만 있는 것도 아니다**

- - 보고서는 양자컴퓨팅을 단순히 NISQ와 FTQC 두 단계로만 보지 않는다.
  - NISQ 시스템이 특정 문제에서 실용적인 개선을 가져올 가능성도 남겨두고 있으며, analog quantum computing 역시 특정 문제에서 quantum advantage를 보여줄 가능성을 검토한다.
  - 동시에 superconducting electronics, reversible computing 같은 unconventional computing 기술도 경쟁 또는 보완 기술이 될 수 있다고 본다.

**📌 1차 양자혁명과 2차 양자혁명**

- - Part 1은 Planck, Einstein, de Broglie, Schrödinger, Heisenberg, Born, Dirac으로 이어지는 양자역학의 발전사를 상당히 길게 다룬다.
  - 19세기 고전물리학으로 설명되지 않았던

    - black-body spectrum
    - photoelectric effect
    - atomic spectrum
    - Zeeman effect
  - 등을 해결하면서 현대 양자역학이 만들어졌다.
  - 이후 transistor와 laser처럼 다수의 quantum object가 만들어내는 물리현상을 이용한 기술이 **1차 양자혁명**이었다면,
  - 1980년대 이후에는 개별 atom, electron, photon을 직접 제어하고 superposition과 entanglement를 자원으로 사용하는 **2차 양자혁명**이 시작됐다고 설명한다.
  - Quantum computing뿐 아니라

    - quantum communication
    - quantum cryptography
    - quantum sensing
  - 역시 모두 이 2차 혁명에 포함된다.

**✅ 3. 양자물리를 ‘신비한 현상’이 아니라 공학의 언어로 연결한다**

**📌 Part 1에서 다루는 기본 양자현상**

- - 보고서는 다음을 순서대로 정리한다.

    - quantization
    - wave-particle duality
    - superposition
    - entanglement
    - uncertainty
    - measurement
    - no-cloning
    - tunneling
  - 중요한 것은 이런 현상을 흥미로운 물리학 이야기로 끝내지 않는다는 점이다.
  - 결국 각각이

    - qubit을 어떻게 만드는지
    - 어떻게 gate를 동작시키는지
    - 어떤 noise가 발생하는지
    - measurement가 어떻게 이루어지는지
    - 왜 QEC가 필요한지
  - 로 이어진다.

**📌 ‘양자역학의 정답 책’은 없다**

- - Ezratty가 흥미롭게 강조하는 부분 중 하나다.
  - 양자역학의 postulate를 정리하는 방법은 교재와 연구자에 따라 조금씩 다르다.
  - 해석 역시 Copenhagen, Many Worlds 등 다양한 형태가 존재한다.
  - 하지만 해석이 다양하다는 것과 양자역학 자체의 정확성을 혼동해서는 안 된다.
  - 양자역학은 수많은 실험을 통해 극도로 정밀하게 검증된 이론이라는 점을 분명히 한다.

**✅ 4. 알고리즘과 실제 양자컴퓨터 사이에는 엄청난 층이 존재한다**

**📌 우리가 그리는 quantum circuit이 곧 QPU가 실행하는 회로는 아니다**

- - 논리적으로 생각한 알고리즘과 실제 장비가 실행하는 작업 사이에는 여러 계층이 존재한다.
  - 대략적으로 보면

    - **Algorithm**
    - → **Logical circuit**
    - → **Compilation / transpilation**
    - → **Hardware-native gates**
    - → **Control electronics / photonics**
    - → **Physical QPU**
    - → **Measurement**
    - → **Classical processing**
  - 의 구조가 된다.
  - QEC를 사용한다면 여기에

    - syndrome extraction
    - classical decoder
    - Pauli frame
    - real-time feedback
  - 까지 붙는다.

**📌 양자컴퓨터는 결국 하이브리드 컴퓨터다**

- - 실제 시스템에서는 classical computer가 QPU 주변에서 엄청난 일을 수행한다.
  - HPC가 quantum circuit을 준비하거나 결과를 후처리하고,
  - QPU 내부에서도 classical controller가 gate와 readout을 관리한다.
  - FTQC에서는 classical decoder의 역할이 더 중요해진다.

**✅ 5. 결국 Part 1의 중심으로 들어가면 QEC가 나온다**

**📌 오류는 gate에서만 생기는 것이 아니다**

- - 오류는

    - initialization
    - gate operation
    - idle
    - readout
  - 모든 단계에서 발생한다.
  - noise는 외부에서도 들어오고 내부에서도 발생한다.
  - decoherence는 superposition과 entanglement를 점차 파괴한다.
  - 따라서 physical qubit의 fidelity를 개선하는 것만으로는 매우 긴 회로를 실행하기 어렵다.

**📌 QEM과 QEC는 다르다**

- - Quantum Error Mitigation은 주로 **계산 결과에서 오류의 영향을 줄이는 방법**이다.
  - Quantum Error Correction은 계산이 진행되는 동안 **오류를 지속적으로 탐지하고 처리하는 방법**이다.
  - 장기적인 대형 FTQC에서는 결국 QEC가 필요하다.

**✅ 6. Logical qubit은 ‘오류 없는 큐비트’가 아니다**

**📌 여기서 가장 중요한 오해 하나를 바로잡는다**

- - logical qubit을 만들었다고 해서 오류가 0이 되는 것이 아니다.
  - logical qubit 역시 **residual logical error rate**를 가진다.
  - 필요한 것은 오류가 없도록 만드는 것이 아니라,
  - 실행하려는 algorithm의 크기에 맞게 logical error rate를 충분히 낮추는 것이다.
  - 따라서

    - **1 logical qubit = 고정된 physical qubit 수**
  - 라는 식으로 계산할 수 없다.
  - 필요한 physical qubit 수는

    - physical error rate
    - QEC code
    - code distance
    - connectivity
    - 목표 logical error rate
    - circuit depth
    - logical gate 수
  - 등에 따라 달라진다.

**📌 같은 1,000 logical qubit이라도 전혀 다른 컴퓨터일 수 있다**

- - 실행하려는 회로가 짧다면 비교적 높은 logical error rate를 허용할 수 있다.
  - 반대로 수십억·수조 개의 logical operation을 수행해야 한다면 logical error rate를 훨씬 더 낮춰야 한다.
  - 그러면 code distance 또는 QEC overhead가 증가하고 physical qubit 수도 늘어난다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA5MzBfMjMg/MDAxNzkwNzQzNjQ4NzIx.382eF1DOug6yLV6uyVslV8FyHvOOr0CjppKaJ21mQdgg.rwm0SlxZm8CypoUtEyAexyJFJsM56FajpPJCJ1Pqzckg.PNG/image.png?type=w800)](#)

- - algorithm breadth와 depth부터 logical error target, T gate, QEC code, physical fidelity, connectivity, decoder overhead, gate speed가 모두 physical qubit 수와 실행시간으로 연결되는 그림이다.
  - 개인적으로 Part 1 전체에서 가장 중요한 그림 중 하나라고 본다.

**✅ 7. QEC도 하나의 기술이 아니라 ‘동물원’이다**

**📌 Surface code만 있는 것이 아니다**

- - Ezratty는 QEC를 하나의 code로 설명하지 않고 매우 다양한 code family로 정리한다.
  - 대표적으로

    - surface code
    - color code
    - Bacon-Shor
    - toric code
    - qLDPC
    - quantum Tanner code
    - concatenated code
    - bosonic code
    - cat qubit 계열
  - 등이 존재한다.
  - 각 code는

    - connectivity 요구 조건
    - encoding rate
    - distance
    - syndrome extraction
    - decoder
    - logical gate 구현
  - 에서 서로 다른 trade-off를 가진다.

**📌 qLDPC가 주목받는 이유**

- - qLDPC는 surface code보다 높은 encoding rate를 얻을 가능성이 있다는 점이 매력적이다.
  - 즉 동일한 physical qubit으로 더 많은 logical information을 담을 가능성이 있다.
  - 그러나 더 복잡한 connectivity나 syndrome decoding 등의 문제도 함께 해결해야 한다.
  - 따라서 **높은 encoding rate = 곧바로 더 좋은 FTQC**라는 의미는 아니다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA5MzBfMyAg/MDAxNzkwNzQzNzkxNzM3._673GEuTnHEzsXDW7Z3_glZEcbcNLbeZs-tK1RGQhJMg.HBzQIfS3Rwf1CDFuQ_1h_i6VYSxNJtZbBJit9cUKgekg.PNG/image.png?type=w800)](#)

- - Shor code부터 surface code, qLDPC, bosonic 계열까지 QEC 계보를 한 번에 보여준다.

**✅ 8. QEC와 FTQC는 같은 말이 아니다**

**📌 이 보고서에서 가장 중요하게 봐야 할 문장 중 하나다**

- - FTQC는 단순히 logical qubit을 사용하는 컴퓨터가 아니다.
  - Ezratty가 강조하는 조건은 크게 두 가지다.

    - 첫째,**오류를 수정하는 속도가 오류가 만들어지는 속도보다 빨라야 한다.**
    - 둘째,**logical gate를 수행하는 과정에서 하나의 오류가 시스템 전체로 퍼져서는 안 된다.**
  - 이것이 fault tolerance의 핵심이다.

**📌 그러면 FTQC에 실제로 필요한 것은 훨씬 많다**

- - QEC만 있는 것이 아니라

    - fault-tolerant logical gates
    - logical memory
    - syndrome detection
    - real-time decoder
    - magic-state preparation
    - magic-state distillation/cultivation
    - lattice surgery 또는 다른 logical operation 방식
    - interconnect
    - readout
    - classical control
  - 이 함께 동작해야 한다.

  - 최근 “logical qubit 몇 개냐”만 가지고 FTQC를 비교하는 것이 왜 불완전한지를 보여주기에 매우 좋은 그림이다.

**✅ 9. 그래서 FTQC resource estimation은 굉장히 어렵다**

**📌 Logical qubit 숫자 하나로는 아무것도 결정되지 않는다**

- - 실제 resource estimation에서는

    - logical qubit 수
    - logical error target
    - total gate count
    - T-count
    - T-depth
    - QEC cycle
    - code distance
    - physical error rate
    - decoder latency
    - connectivity
    - gate/readout time
  - 등을 동시에 고려해야 한다.
  - 결국 두 개의 연구가 같은 algorithm을 계산하면서도 서로 크게 다른 physical qubit estimate를 내놓을 수 있다.

**📌 RSA뿐 아니라 ECC resource estimate도 계속 낮아지고 있다**

- - 보고서는 2026년까지의 RSA-2048과 ECC-256 공격 resource estimate 변화도 정리한다.

**✅ 10. Quantum Memory와 qRAM은 같은 것이 아니다**

**📌 이 부분도 자주 섞어서 사용한다**

- - 보고서는 적어도 세 가지를 구분한다.

    - **Quantum-state memory**
    - **qRAM**
    - **QROM**
  - Quantum-state memory는 quantum state를 일정 시간 보존하는 장치다.
  - qRAM은 address 자체를 quantum state로 처리하면서 coherent random access를 구현하려는 개념이다.
  - QROM은 circuit을 통해 데이터를 읽어오는 방식으로 qRAM과 같은 것은 아니다.

**📌 대규모 qRAM은 아직 해결된 기술이 아니다**

- - 제한적인 quantum-state memory는 이미 실험적으로 존재한다.
  - 하지만 대규모 FTQC에서 효율적으로 coherent random access를 제공할 **scalable fault-tolerant qRAM은 현재 존재하지 않는다.**
  - 이는 QML이나 data-heavy quantum algorithm을 이야기할 때 상당히 중요한 제약이다.

**✅ 11. 양자컴퓨터의 전력 문제는 생각보다 훨씬 크다**

**📌 QPU 전력만 보면 안 된다**

- - 양자컴퓨터의 에너지 소비는 QPU 자체만으로 판단할 수 없다.
  - 전체 시스템에는

    - cryogenic cooling
    - room-temperature control
    - cryogenic electronics
    - laser
    - photonics
    - vacuum pump
    - cable
    - FPGA / ASIC
    - classical CPU/GPU
    - QEC decoder
  - 등이 모두 존재한다.

**📌 FTQC가 커지면 고전 부분도 함께 커진다**

- - physical qubit이 늘어나면 syndrome extraction도 늘어난다.
  - 이를 처리하는 classical decoder와 control electronics도 함께 커진다.
  - 따라서 양자컴퓨터가 특정 계산에서 빠르다고 해서 자동으로 **energy advantage**를 가지는 것은 아니다.

**📌 Vendor들의 전망도 엄청난 차이를 보인다**

- - 보고서는 미래 FTQC 시스템의 전력 예측을 여러 vendor roadmap을 기준으로 비교한다.
  - 예측치 사이에 대략 **1 대 100 정도의 범위 차이**가 존재한다.
  - 그만큼 아직 architecture와 technology choice에 따른 불확실성이 크다는 뜻이다.

**✅ 12. Lieb-Robinson bound까지 컴퓨터 구조 문제로 연결한다**

**📌 정보는 무한한 속도로 QPU 안을 이동하지 않는다**

- - 보고서는 이례적으로 Lieb-Robinson bound를 별도의 큰 절로 다룬다.
  - 핵심은 많은 quantum system에서 information과 entanglement의 propagation에 사실상의 속도 한계가 존재한다는 것이다.
  - 이는 단순 이론물리학 이야기가 아니다.
  - 대규모 QPU에서는

    - qubit layout
    - connectivity
    - logical gate
    - compiler
    - QEC
    - distributed quantum computing
  - 의 성능과 연결될 수 있다.
  - 즉 million-qubit system을 만든다고 하더라도 모든 qubit이 즉시 모든 다른 qubit과 상호작용할 수 있는 것은 아니다.

**✅ 13. 저자는 낙관론도 비관론도 그대로 믿지 않는다**

**📌 Quantum computing에는 두 극단이 존재한다**

- - 한쪽에서는 수년 내 FTQC와 quantum advantage가 본격화될 것이라고 주장한다.
  - 반대쪽에서는 scalable quantum computing 자체가 불가능하거나 경제성이 없을 것이라고 주장한다.
  - Ezratty는 이 둘 사이의 **Middle Road**를 택한다.

**📌 중요한 것은 일정이 아니라 남아 있는 문제를 분해하는 것이다**

- - 보고서가 요구하는 질문은 단순하다.

    - physical fidelity가 충분한가?
    - QEC overhead가 현실적인가?
    - logical operation을 충분히 빠르게 할 수 있는가?
    - classical decoding이 따라갈 수 있는가?
    - interconnect가 확장 가능한가?
    - cooling과 control이 확장 가능한가?
    - algorithm speedup이 end-to-end에서도 남아 있는가?
  - 결국 “2030년인가 2040년인가”를 맞히는 것보다 이 각각의 constraint가 실제로 해결되고 있는지를 추적하는 것이 중요하다.

**✅ 15. 결국 Part 1이 말하는 것은 ‘논리 큐비트 숫자를 보지 말라’는 것이다**

**📌 큐비트 숫자는 시작일 뿐이다**

- - Part 1을 450페이지 읽고 나면 오히려 단순한 숫자로 양자컴퓨터를 비교하기가 더 어려워진다.
  - Physical qubit 수만으로도 부족하고,
  - logical qubit 수만으로도 부족하다.
  - 실제 FTQC의 성능을 결정하는 것은

    - **Physical fidelity**
    - × **QEC architecture**
    - × **Logical error rate**
    - × **Logical operation**
    - × **Decoder speed**
    - × **Connectivity**
    - × **Circuit depth**
    - × **Runtime**
    - × **Energy**
  - 이다.

**📌 Logical qubit ≠ FTQC**

- - 이것이 Part 1에서 가장 기억해야 할 부분이라고 본다.
  - logical qubit은 QEC가 적용된 하나의 구성요소일 뿐이다.
  - 실제 fault-tolerant system에서는 **오류 생성보다 빠른 오류 처리**, logical operation 과정에서의 **fault propagation 방지**, QEC와 classical decoding의 실시간 동작까지 필요하다.
  - 따라서 “logical qubit 몇 개를 달성했다”는 발표와 “유용한 FTQC를 구현했다”는 주장은 상당한 거리가 있다.

**✅ 16. 결론 — 양자컴퓨터는 QPU 경쟁에서 시스템 경쟁으로 이동하고 있다**

**📌 이 보고서를 읽고 가장 크게 달라지는 시각**

- - 양자컴퓨터를 보면 자연스럽게

    - **큐비트가 몇 개인가?**
    - **2Q fidelity가 얼마인가?**
  - 를 먼저 보게 된다.
  - 하지만 Ezratty의 Part 1을 따라가면 질문이 바뀐다.

    - **어떤 code를 쓰는가?**
    - **목표 logical error rate는 얼마인가?**
    - **얼마나 많은 hard logical operation을 수행할 수 있는가?**
    - **decoder는 그 속도를 따라갈 수 있는가?**
    - **logical gate와 magic state는 어떻게 구현하는가?**
    - **QPU를 연결할 interconnect가 있는가?**
    - **control과 cooling은 얼마나 확장 가능한가?**
    - **전체 계산 시간과 에너지 소비는 얼마인가?**
  - 결국 FTQC는 **좋은 qubit 하나를 만드는 경쟁이 아니라** **전체 stack을 동시에 최적화하는 경쟁**이다.
