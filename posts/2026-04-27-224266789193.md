**✅ XXI. Compilation & Applications**

**📌 Logical Compiler (핵심 역할)**

- - 역할 한 줄:

    - “알고리즘 → Walking Cat에서 실행 가능한 연산으로 변환”
  - **구조**

    - 입력: high-level 알고리즘 (예: Hamiltonian, Shor)
    - 출력:

      - Pauli measurement
      - Clifford
      - T gate (magic factory 기반)
  - **핵심 방식: Hierarchical synthesis**

    - 큰 연산
    - → 작은 블록
    - → 더 작은 연산
    - → 최종: measurement + Clifford + T
  - 특징:

    - ancilla를 포함한 “spec / def 구조”
    - 병렬 실행 가능한 layer로 재구성

**📌 왜 컴파일이 중요한가**

- - Walking Cat에서는:

    - 연산 = measurement + feedforward
  - 따라서:

    - compile 단계에서 **전체 실행 구조가 결정됨**
    - scheduling / 병렬성 / factory 사용량까지 포함

**📌 Application 1: Hamiltonian Simulation**

- - **목표**

    - Heisenberg model 시뮬레이션
  - **Classical vs Quantum**

    - **Classical (MPS - matrix-product-state)**

      - ~50 qubits 수준
      - 정확도 제한
      - 연결성 증가 시 성능 급락
    - **NISQ**

      - ~100 qubits
      - shallow circuit만 가능
      - error 큼
    - **Walking Cat (FTQC)**

      - 결과:

        - 더 깊은 circuit 가능
        - chemical accuracy (~1e-3) 목표
  - **핵심 기술**

    - **Trotterization**

      - Hamiltonian:

- - - - → exponential 분해:

        - exp(-iHt) ≈ product of simpler terms
  - **중요한 수치**

    - chemical accuracy:

      - ~80 step (2nd order)
      - ~10 step (6th order optimized)
  - **성능 결과 (핵심)**

    - execution time:

      - 수 시간 ~ 수십 시간
    - scaling:

      - magic factory 많을수록 빨라짐
      - 하지만 saturation 존재
    - **일정 수준 이후에는 factory를 늘려도 속도가 안 빨라진다 (그림 68)**
    - **메모리와 Magic Factory간의 trade-off 구조**

      - factory 늘리면

        - compute 빨라지지만 memory 줄어듦 **(그림 69)**
      - memory 늘리면

        - paralleism 증가하지만 factory 부족 **(그림 70)**

**📌 Application 2: Quantum Phase Estimation (QPE)**

- - **목적**

    - observable 측정 (예: magnetization)
  - **특징**

    - 반복적인 controlled-U 필요
    - shot 수:

      - ~30–100회
  - 핵심:

    - measurement cost가 매우 큼

**📌 Application 3: Shor’s Algorithm**

- - **구조**

    - QPE 기반
    - modular multiplication 반복
  - **특징**

    - controlled operations 많음
    - ancilla-heavy 구조
  - **결과 (중요)**

**📌 핵심 병목 분석**

- - **진짜 병목**

    - T gate (magic factory)
    - + routing
    - + measurement latency

**📌 Architecture-level Insight**

- - **Magic factory 영향**

    - 많을수록 병렬성 증가
    - 하지만:

      - 어느 순간 memory / routing이 병목으로 전환
  - **Q54 vs Q70 vs Q102**

    - Q102:

      - 더 적은 memory block 필요
      - 안정적 데이터 저장
    - Q70:

      - 정밀 magic state (MEK)
    - Q54:

      - 빠른 H-state 생산 (CH2)

|  |  |  |
| --- | --- | --- |
| **코드** | **특징** | **용도** |
| Q54 | transversal H 가능 | CH2 |
| Q70 | Clifford 자유 | MEK |
| Q102 | 안정적 memory | 저장용 |

**📌 가장 중요한 결론**

- - 성능 = 알고리즘이 아니라
  - “컴파일 + 리소스 배치 + factory 구성”에 의해 결정됨

> ***Walking Cat에서는 “어떤 알고리즘을 쓰느냐”보다***
>
> ***“어떻게 컴파일하고 리소스를 배치하느냐”가 성능을 결정한다.***

**✅ XXII. Conclusion**

**📌 무엇을 제시했나**

- - 완전한 Fault-Tolerant Quantum Computing 아키텍처
  - 구성 포함:

    - Logical architecture
    - Compiler
    - Micro-architecture
    - Error correction
    - Physical implementation
  - 즉, “아이디어”가 아니라 “전체 시스템 설계도”

**📌 핵심 설계 철학**

- - 가장 중요한 키워드:

    - **단순성 (Simplicity)**

      - 복잡한 gate 대신 단순한 반복 구조 + 이동 + 측정
    - **Measurement 중심 구조**

      - 모든 연산 = cat-based measurement
      - gate가 아니라:

        - measurement
        - Clifford
        - feedforward
    - **이동 기반 연산**
    - 연산 = gate 적용 ❌
    - 연산 = qubit 이동 + 정렬 ✔️

**📌 기술적 핵심 포인트**

- - EQC (RF 기반 control)

    - → laser scaling 문제 해결
  - Cyclic shift

    - → 복잡한 routing 단순화
  - Cat factory

    - → measurement를 factory화

**📌 성능에 대한 입장 (중요)**

- - 논문 stance:

    - “이론적 최고 성능” ❌
    - “실제로 구현 가능한 구조” ✔️
  - 즉, 구현 가능성 중심

**📌 앞으로의 의미**

- - 이 구조는 최적화 여지가 매우 크다
  - 개선 가능 영역:

    - compiler
    - layout
    - error correction
    - hardware co-design

**📌 현실적인 한계 인식**

- - 아직은 초기 단계

    - 수천~수만 qubit scaling 필요
    - 실험적 검증은 제한적

**📌 가장 중요한 철학적 결론**

- - “문제는 계산이 아니라, 그 계산을 실행할 수 있는 구조다”
  - Quantum computing is a systems problem, not a gate problem.

> ***Walking Cat은 “양자 게이트 설계”가 아니라***
>
> ***“전체 컴퓨팅 시스템을 어떻게 구성할 것인가”에 대한 답이다.***

**✅ 맺음말**

- - 처음 이 논문을 펼쳤을 때의 인상은 솔직히 단순했다. “또 하나의 복잡한 양자컴퓨팅 아키텍처겠지.” 하지만 한 장, 한 장 따라가다 보니 이건 단순한 기술 제안이 아니라 **하나의 ‘세계’를 설계한 문서**라는 느낌이 들기 시작했다.
  - 처음에는 모든 것이 낯설었다.

    - cat state를 중심으로 한 연산
    - measurement 기반 계산
  - 이 모든 것이 기존에 익숙했던 “큐비트를 배열하고 게이트를 쌓는다”는 사고방식과는 완전히 달랐다. 그래서 초반에는 이해하려고 하기보다 **“이게 정말 돌아갈까?”라는 의심이 먼저 들었다.**

****

- - 그런데 흥미로운 건, 읽을수록 그 의심이 점점 사라졌다는 점이다. 이 논문은 단순히 아이디어를 던지고 끝내지 않는다.

    - 오류정정 코드 구조
    - 디코딩 알고리즘
    - 물리적 이동 방식
    - 실제 시간(latency)
    - 심지어 transport cost까지
  - 모든 것을 하나씩 연결해 나간다. 그 과정에서 자연스럽게 깨닫게 된다. 이건 “가능성”을 말하는 논문이 아니라 **“이렇게 만들면 된다”를 말하는 논문이다.**
  - 특히 인상 깊었던 부분은 디코더였다. 보통 양자컴퓨팅을 이야기할 때는 게이트 fidelity나 qubit 수에 집중하게 된다. 그런데 이 구조에서는 완전히 다르다.
  - IonQ는 이미 Beam Search로 방향을 제시했고, 이번에는 그것을 streaming으로 연결해 실시간 시스템으로 완성했다.
  - 그때 처음으로 느꼈다. 이건 더 이상 가능성을 이야기하는 분야가 아니라, 이미 동작하기 시작한 시스템이라는 것을.

- - 또 하나 인상 깊었던 건 ‘이동’이라는 개념이었다. 사실 큐비트를 이동시켜 연산을 수행한다는 아이디어 자체는 이미 알고 있었고, 크게 낯선 개념은 아니었다. 이온트랩 기반 구조에서 이동이 필수적이라는 점도 어느 정도는 이해하고 있었다. 하지만 이 논문을 따라가면서 느낀 건, 그동안 내가 이해하고 있던 ‘이동’은 굉장히 단순화된 개념이었다는 점이었다.
  - 여기서의 이동은 단순히 큐비트를 A에서 B로 옮기는 문제가 아니라, 연산의 순서, 병렬성, 오류율, 심지어 전체 시스템의 성능까지 결정짓는 핵심 요소였다. 특히 cyclic shift, batching, 그리고 factory와 memory 간의 분리된 구조를 통해
  - 이동을 최소화하는 것이 아니라, 일정한 패턴으로 반복되도록 만들어 예측 가능하고 제어 가능한 형태로 바꾸고 있다는 점이 인상적이었다.
  - 그제서야 비로소 이해가 됐다. 이 구조에서 이동은 단순한 구현 디테일이 아니라, 전체 아키텍처를 지탱하는 중심 축이라는 것을.

- - 중반 이후로 넘어가면서는 이 논문이 얼마나 집요하게 “현실성”을 붙잡고 있는지가 드러난다.

    - 몇 번의 SEC가 필요한지
    - 몇 ms의 latency가 나오는지
    - 몇 개의 factory가 병목이 되는지
  - 이 모든 수치들이 등장하면서, 처음에는 추상적으로 느껴졌던 구조가 점점 **“실제로 돌아가는 기계”처럼 보이기 시작한다.**

- - 그리고 마지막에 이르러서야 전체 그림이 하나로 이어진다.

    - Cat factory → 연산
    - Magic factory → 비-Clifford 자원
    - Qubit factory → 생존과 보충
    - Decoder → 실시간 판단
    - Enriched architecture → 연산 확장
  - 이 모든 요소가 따로 존재하는 것이 아니라 하나의 흐름으로 연결되어 있다. 그 순간 느껴지는 건 단순한 이해가 아니다.
  - **“아, 이건 진짜 돌아가겠구나”라는 확신**이다.

- - 물론, 여전히 갈 길은 멀다.

    - 수천, 수만 큐비트로의 확장
    - 실제 하드웨어 구현
    - noise와 engineering 문제
  - 이 모든 것들이 남아 있다.
  - 하지만 이 논문을 통해 분명해진 건 하나다. 이제 문제는 “가능한가?”가 아니라 “얼마나 빠르게 만들 수 있는가?”다

> ***이 논문은 양자컴퓨팅을 ‘이론’에서 ‘설계 가능한 시스템’으로 끌어내린 작업이었다.***
