**✅ XI. The Cat Factory**

- - 이 섹션은 walking cat architecture에서 사용하는 cat state 생성 시스템(cat factory)를 설계하는 파트다.
  - 핵심 목적은 logical Pauli measurement를 수행할 때 필요한 cat state를 안정적으로 공급하는 것이다.
  - 여기서 중요한 점은, 이 논문에서 사용하는 cat state는 “완전한 fault-tolerant 상태”가 아니라, 오류가 매우 작고 통제 가능한 상태(quasi-independent)라는 것이다.

**📌 Quasi-independent cat states**

- - cat state는 다음과 같은 형태를 가진다.

    - 여러 큐비트가 동시에 0과 1 상태에 있는 얽힘 상태다.
  - 이 상태는 완벽하지 않고 일부 Pauli error가 포함될 수 있다.
  - 하지만 중요한 조건이 있다.

    - 각 error가 서로 강하게 얽혀서 퍼지는 것이 아니라 거의 독립적으로 발생해야 한다.
    - 이걸 quasi-independent라고 부른다.
  - 핵심 의미는 다음과 같다.

    - 에러가 있어도

      - → 특정 패턴으로 폭발적으로 퍼지지 않고
      - → 제한된 형태로 유지됨
  - 그래서 이 cat state를 사용해도 logical error rate을 크게 증가시키지 않는다.
  - 논문에서는 목표 precision을 설정한다.

    - 예를 들어 ε = 10-10 수준 이하의 에러만 허용한다.
    - 즉, 완벽한 cat state가 아니라 “충분히 안전한 cat state”를 만드는 전략이다.

**📌 Heuristic estimate (대략적 추정값)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMTk2/MDAxNzc3MTgyMzQ4MzUw.cAQtpYlSON4G5MGPjhhvoIQDhjNZQKgibQLt_Xd881Ig.6iDCrEQLZl8z-NwbUQWX15pUnSh8SORaF7DDBt_tYNAg.PNG/image.png?type=w800)](#)

- - **검증 라운드 수 m**

- - - 의미:

      - 정확도 높일수록 m 증가
      - p 작을수록 m 감소
  - **오류율**

    - X error: p/2
    - Z error: 4(m+1)p/15
    - **의미**

      - Z error가 더 큼
  - **rejection rate**

    - error 기반: (2m+1)wp
    - leakage 기반: *p**leak*⋅w(log2w+…)
    - loss 기반: *p**loss*⋅w(log2w+…)
    - **핵심**

      - cat state 크기 w 커질수록 버려지는 비율 증가
  - **생산 시간**

    - POC 기준: log2(w)+3m+3
    - 이동 단계: w/2+m−1

> ***cat factory가 얼마나 빠르고, 얼마나 정확하게, 얼마나 많은 실패를 감수하며 cat state를 만드는지 추정한 성능표***
>
> *크게 만들면 (w ↑) → 더 많은 연산 가능*
>
> *많이 검증하면 (m ↑) → 더 안전*
>
> *하지만 둘 다 하면 → 느려지고 비싸짐*

**📌 Design of the cat factories**

- - cat factory는 두 단계로 동작한다.

    1. Cat state preparation

       - 작은 상태에서 시작해서 점점 키운다.
       - 초기:

         - 하나의 qubit
       - 이후:

         - CX 게이트를 반복해서 cat state 크기를 2배씩 증가
       - 결과:

         - weight w 크기의 cat state 생성
       - 이 과정에서

         - X error, Z error, leakage, loss가 발생할 수 있다.
       - 핵심

         - **단순 체인 ❌**
         - **“shift + CX로 병렬 생성”**
    2. Cat state verification

       - 생성된 cat state가 문제가 없는지 검사한다.
       - 방법:

         - ancilla를 사용해서 ZZ stabilizer 측정 수행
       - 구조:

         - cat qubit ↔ ancilla 연결
         - → parity 체크
       - 검증 과정 특징:

         - 여러 번 반복 (m rounds)
         - 문제 발견 시 즉시 폐기 (rejection)
         - 정상인 것만 통과
       - 이 과정에서 leakage와 loss도 함께 검출된다.
       - 핵심 trade-off:

         - verification 많이 하면
         - → error 감소
         - → 대신 시간 + 리소스 증가
       - 논문에서는 m = 2 정도로 충분하다고 본다.
  - **Cat state preparation 핵심 메커니즘**

    - cat state는 단순히 한 번에 만드는 게 아니라 다음 패턴으로 생성된다.

      - 정렬 → CX → 이동 → 정렬 → CX → 이동
    - 이 구조는 walking cat architecture의 핵심인 “이동 기반 연산”과 동일하다.

      - 즉, cat factory도 동일한 이동-연산 구조를 공유한다.
  - **Error propagation과 verification의 역할**

    - cat state 생성에서 가장 위험한 건 X error다.
    - 이유:

      - 하나의 X error가

        - → 여러 qubit으로 퍼질 수 있음
        - → high-weight error 생성
    - verification이 필요한 이유:

      - 이런 error를 초기에 발견해서 제거하기 위함
    - 결과적으로:

      - verification 이후 남는 error는 독립적인 작은 확률의 error로 제한된다.

**📌 Heuristic error estimates**

- - 논문은 cat factory의 성능을 수식으로 근사한다.
  - 주요 요소:

    - X error rate
    - Z error rate
    - rejection rate
    - loss / leakage 영향
  - 핵심 결과:

    - X error:

      - weight k에 대해
      - 확률 ~ (p\_x)^k 형태로 감소
      - → weight 커질수록 급격히 감소
    - Z error:

      - 선형적으로 증가하지만
      - 전체 영향은 제한적
    - rejection rate:

      - error detection 때문에 일부 cat state는 폐기됨
    - loss:

      - 확률은 작지만 한 번 발생하면 여러 qubit 영향 가능
    - leakage:

      - 검출되면 즉시 제거 → logical error에는 직접 영향 적음
  - 중요한 해석:

    - 이 모델은 보수적 (pessimistic)이다.
    - 실제 시뮬레이션 결과는 더 좋게 나온다.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfNzcg/MDAxNzc3MTgzMzk1MzAz.LuFJsGxfys908EeumCacxIkTEfkNeEMPONgenP6KL9Ag.lmifBeY7dmFk1qDDgfrEJKbH4Yy_HTZjOwJgh1oHF9Mg.PNG/image.png?type=w800)](#)

- - Monte Carlo 시뮬레이션 기반으로 분석한 weight-30 cat state의 검증 과정에서의 X/Z 오류와 rejection rate

    - (a) X error

      - weight k 증가 → 오류 급증
    - (b) Z error

      - 선형 증가
    - (c) rejection rate

      - p 증가 → 거의 선형 증가
    - 핵심 : **물리 error ↑ → cat 품질 급락**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMjM1/MDAxNzc3MTgzNDY1OTU3.udvRkpHmVM5s96PHc4T8rva-x4qKpQ7jarA4l5Acx6Qg.cwyX4aTavrp1JrZ6d6aXWK7D-U-qT4PeTsLFvycrHwgg.PNG/image.png?type=w800)](#)

- - **Weight-50 cat state에서의 오류율과 rejection rate (p = 10⁻⁴, m = 2, Monte Carlo 결과)**

    - X error는 weight가 커질수록 급격히 감소 (weight-2는 거의 무시 수준)
    - Z error는 X보다 훨씬 큼 (주요 잔존 에러)
    - rejection rate는 비교적 높지만 → 오류 제거 과정의 결과
    - 전체적으로 “verification이 high-weight X error를 강하게 억제한다”
  - **Weight-30 cat state에서의 qubit loss 확률 분포**

    - 대부분의 경우: **손실 0~몇 개 (매우 낮은 확률)**
    - 드물게: 여러 개 qubit 손실 (long tail)
    - 분포가 4개 구간으로 나뉨 (1, 2~8, 9~16, 17~60)
    - **“loss는 rare event지만 발생하면 여러 qubit에 퍼질 수 있음”**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfOTIg/MDAxNzc3MTg0MDk3NzA2.6KBWwG70HAw4tFfoJwch89jmapZO9oIUv4RyrnfvHRog.QjXwDe30p2RTPE1apdCOYErFDscCAyi30ZhmJnIaQeIg.PNG/SE-00e4a162-fa47-4969-b83a-165778c10126.png?type=w400)](#)

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA0MjZfMjU1/MDAxNzc3MTg0MDk2NzA4.83zPG1cscr1A6y6RRRi0nqWIDMAvOlRGR8Wtg1UAIXcg.vypx1fCdXey1DQriVI7icv6ItivkgZbDtYEfVR4D-Vgg.PNG/SE-fd4fdde5-f2a2-43cb-ad96-c7505682008f.png?type=w400)](#)

> ***verification은 error를 강하게 억제하고, loss는 드물지만 발생 시 다중 qubit에 영향을 줄 수 있다***

**📌 핵심 정리**

- - cat factory의 본질은 다음이다.

    - 완벽한 cat state를 만드는 것이 아니라
    - → 에러를 통제 가능한 형태로 제한하고
    - → 검증을 통해 불량 상태를 제거하며
    - → 안전한 measurement resource를 공급하는 시스템
  - 즉,

    - cat factory = “measurement용 고품질 entanglement를 안정적으로 생산하는 엔진”
  - 그리고 이 구조 덕분에 walking cat architecture는 large-weight Pauli measurement를 안정적으로 수행할 수 있다.

**✅ XII. The Bell Factories**

- - 이 섹션은 **cat state를 더 크게 만들기 위한 연결(stitching) 기술**과 이를 위한 Bell state 생산 구조를 설명한다.

****

**📌 핵심 개념**

- - Bell factory의 역할은 단순하다.

    - **두 개의 cat state를 하나로 합치는 것**
  - 즉,

    - cat state (크기 w1)
    - cat state (크기 w2)
  - → 합치면 **더 큰 cat state (w = w****1** **+ w****2****)**

****

**📌 왜 필요한가**

- - cat factory만으로는 큰 cat state를 만들기 어려움

    - w가 커질수록
    - → 생성 비용 증가
    - → 오류 증가
  - 그래서 전략은 **작은 cat 여러 개 만들고 나중에 붙인다**

****

**📌 Stitching (핵심 알고리즘)**

- - 구조:

    - 두 cat state C1, C2 준비
    - Bell pair들을 이용해서 연결
    - 여러 개의 ZZ measurement 수행
    - 결과 parity 확인
  - 판단 기준:

    - 모든 parity가 같으면 → 성공
    - 하나라도 다르면 → 실패 (reject)

**📌 중요한 특징**

1. 1. **성공 시 결과**

      - 하나의 큰 cat state 생성
      - 단, parity가 odd면

        - → 전체에 X error가 있는 상태
        - → 하지만 **추적 가능 (frame tracking)**
   2. **실패 조건**

      - 다음 중 하나라도 발생하면 reject:

        - measurement 결과 불일치
        - loss 발생
        - leakage 발생
   3. **오류 전파**

      - stitching 중 오류는 3가지 방식으로 나타남:

        - parity 측정 오류 → global X error
        - 한쪽 cat에만 error → local error
        - 양쪽에 동시에 영향 → correlated error
      - 하지만 대부분은 검증 단계에서 걸러짐

**📌 성능 및 설계 포인트**

- - **Bell state 생성**

    - |00⟩ + |11⟩ 상태 생성
    - 2 POC 정도로 빠름
    - 별도 verification 필요 없음 (바로 사용)
  - **필요한 Bell factory 수**

    - cat factory N개 있으면
    - → 최대 N/2 stitching 필요
    - 각 stitching은 m개의 Bell state 소비
  - 그래서:

    - 총 Bell 필요량 ≈ N·m/2
  - Bell factory 하나는:

    - 약 ⌈3m/2⌉ Bell state 생산
  - 결론:

    - **약 ⌈N/3⌉ Bell factory면 충분**

****

**📌 핵심 trade-off**

- - m (검증 횟수) ↑
  - → 정확도 ↑
  - → Bell 소비 ↑
  - → 속도 ↓

**📌 Cat vs Bell**

|  |  |  |
| --- | --- | --- |
| **항목** | **Cat state** | **Bell state** |
| 크기 | multi-qubit | 2 qubit |
| 역할 | 연산 | 연결 |
| 생성 비용 | 높음 | 낮음 |
| 오류 영향 | 큼 | 작음 |

- - **Bell factory는 “멀리 떨어진 큐비트들을 연결해 하나의 계산 시스템으로 만드는 양자 네트워크 계층”이다.**

    - **Cat factory**

      - 역할: cat state 생성
      - 필요 요소:

        - 2-qubit gate (필수)
        - 이동 (정션존 포함)
      - 이유:

        - → 얽힘 자체를 처음부터 만들어야 함
      - **여기서는 정션존 + 게이트가 핵심**
    - **Bell factory (stitching)**

      - 역할: 이미 있는 cat state 두 개를 연결
      - 방식:

        - Bell pair 준비 (여기서 이미 2-qubit gate 사용됨)
        - ZZ measurement 수행
        - parity로 연결
      - 핵심:

        - **data qubit끼리 직접 게이트 안 함**
        - 대신 → **Bell + measurement로 간접 연결**

**📌 최종 정리**

- - Bell factory의 본질은 다음이다.

    - **작은 cat state들을 연결해서 더 큰 cat state를 만드는 인프라**
  - 그리고 이 구조 덕분에:

    - 큰 weight Pauli measurement 가능
    - cat factory 부담 감소
    - 전체 시스템 확장성 확보

> ***Bell factory = “cat state를 스케일 업하는 연결 엔진”***
