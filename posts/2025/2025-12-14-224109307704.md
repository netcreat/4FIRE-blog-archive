**✅****칩, 패키지, 보드?**

**1️⃣ 칩 내부(Die 내부)란?**

- - **칩 내부 = 하나의 실리콘 다이 안쪽**
  - 예:

    - GPU 다이 내부의

      - SM ↔ SM (Streaming Multiprocessor)
      - L2 ↔ HBM 컨트롤러
    - CPU 내부 코어 ↔ 캐시
  - 특징:

    - 모두 **전기 신호**
    - 나노미터 거리
    - TSV (Through-Silicon Via)

      - 실리콘 웨이퍼를 “위에서 아래로 관통”하는 수직 금속 통로
    - BEOL (Back-End-Of-Line)

      - 트랜지스터 위에서, 신호와 전력을 연결하는 ‘칩 내부 수평 금속 배선층’
    - 금속 배선
    - ❌ **광 사용 거의 없음 (연구 단계)**
  - 정리:
  - “칩 내부” = 실리콘 한 장 안에서 전자가 왔다 갔다 하는 세계

**2️⃣ 패키지(Package)란?**

- - **패키지 = 칩(다이) 여러 개를 하나로 묶는 ‘외장 껍질 + 연결판’**
  - 구성 예:

    - GPU 다이
    - HBM 메모리 스택
    - I/O 다이
    - 광 I/O 다이 (Ayar가 들어가는 위치)
  - 연결 방식:

    - 실리콘 인터포저

      - 칩 아래에 ‘실리콘 판’을 하나 더 깔아서, 그 위에 미세 배선을 만들어 여러 다이를 연결하는 방식
      - 미세 배선 가능 (BEOL급)
      - TSV로 아래 패키지와 연결
      - 대표 사례

        - NVIDIA A100 / H100
        - AMD MI300
        - GPU + HBM 구조
    - EMIB (Embedded Multi-die Interconnect Bridge)

      - “인터포저를 통째로 깔지 말고, 필요한 부분에만 ‘실리콘 다리’를 묻어놓자”는 Intel의 비용 절감형 대안
      - 대표 사례

        - Intel Ponte Vecchio
        - Intel Xe HPC
        - 일부 FPGA
    - Foveros (3D 적층 패키징)

      - 칩을 옆에 놓는 게 아니라, 위아래로 쌓아서 연결하는 3D 패키징
      - 대표 사례

        - Intel Meteor Lake
        - Intel Arrow Lake
        - 향후 AI 가속기
    - UCIe (Universal Chiplet Interconnect Express)

      - “칩렛들이 서로 통신하는 ‘공통 언어(표준)’”
      - 물리 배선 기술이 아니라, 프로토콜/인터페이스 표준
  - 거리:

    - mm ~ cm 단위
  - 정리:
  - “패키지” = 여러 개 칩을 하나의 슈퍼칩처럼 묶는 단계

**3️⃣ 보드(Board)란?**

- - 패키지들이 PCB 위에 올라감
  - 전기 트레이스로 연결
  - 수 cm ~ 수십 cm

**4️⃣ 랙(Rack) / 데이터센터는 완전히 다른 차원**

- - 광모듈
  - DSP
  - 스위치
  - 10m ~ km

**✅****Ayar Labs와 Marvell의 포지션 차이**

**1️⃣Ayar Labs는 “서버 내부 전용”**

- - Ayar Labs의 기술이 아무리 성공해도 적용 영역은:

    - GPU ↔ GPU
    - GPU ↔ 스위치 (같은 랙 내부)
    - 패키지~수십 미터 거리
  - 하지만 **마벨 DSP의 진짜 매출은 여기서 나온다.**

|  |  |
| --- | --- |
| **구간** | **DSP 필요 여부** |
| 랙 내부 1~3m | ❌ Ayar 가능 |
| 랙 ↔ 랙 (수십~수백 m) | ✅ **DSP 필수** |
| 데이터센터 ↔ 데이터센터 (km) | ✅ **DSP 절대 필수** |

- - 📌 **DCI(데이터센터 간 연결)는 Ayar가 구조적으로 못 들어온다.**

****

**2️⃣구체적 사례**

- - Ayar Labs는 “같은 패키지/랙 초단거리”용 기술이고
  - 칩과 칩(랙 간·장거리)은 여전히 DSP가 필수다.
  - 즉,

|  |  |  |
| --- | --- | --- |
| **구간** | **Ayar Labs** | **Marvell DSP** |
| **칩 내부 (Die 내부)** | ❌ 불가능 | ❌ 불필요 |
| **같은 패키지 (Co-packaged)** | **✅ 핵심 적용 영역** | ❌ |
| **같은 보드 (수 cm)** | ⚠️ 일부 가능 | ❌ |
| **같은 랙 (1~3m)** | ⚠️ 조건부 | ❌ 또는 ⚠️ |
| **랙 ↔ 랙 (10~100m)** | ❌ 거의 불가 | **✅** **필수** |
| **데이터센터 ↔ 데이터센터 (km)** | ❌ 불가능 | **✅** **절대 필수** |

- - **왜 “Die 내부 광”이 아직 안 되느냐?**

    - Die 내부는:

      - 수십 GHz ~ 수백 GHz 전기 클록
      - 트랜지스터/배선/캐시/연산 유닛이 **나노미터 간격**
      - 광을 쓰려면:

        - 레이저 소스
        - 변조기
        - 웨이브가이드
        - 광-전기 변환기
      - → 이걸 **GPU 다이 안에 직접 집어넣는 건 현재 공정/열/수율상 거의 불가능**

****

**3️⃣왜 Ayar는 “초단거리”만 가능한가?**

- - Ayar Labs 구조는:

    - **Direct Drive Optical I/O**
    - **DSP 없이 GPU/ASIC에서 광을 직접 변조**
    - **아날로그 신호를 전기→광으로 바로 쏴버림**
  - 문제는 이 구조의 본질적 한계이다.

|  |  |
| --- | --- |
| **한계 요소** | **이유** |
| ❌ 장거리 신호 열화 | DSP 기반 보정 불가 |
| ❌ 분산/왜곡 누적 | FEC, CD 보정 없음 |
| ❌ 온도·노이즈 내성 약함 | 서버 내부 환경에 최적화 |
| ❌ 표준 이더넷 정합 어려움 | CPO 전용 구조 |

- - 📌 **Ayar는 “패키지 내부 광선”이지, “통신용 광”이 아니다.**

**4️⃣그럼 “칩과 칩”이 정확히 어디부터 DSP가 필요하냐?**

- - **DSP 없이 가능한 구간 (Ayar 영역)**

    - GPU 다이 내부
    - CPU–DPU 같은 패키지 내부
    - 같은 PCB 보드
    - 같은 랙의 극초단거리 연결 (≤2~3m, 미래 한정)
  - **DSP 없으면 불가능한 구간 (마벨 영역)**

    - 랙 ↔ 랙 10m 이상
    - 스위치 ↔ 스위치
    - TOR ↔ Spine
    - 데이터센터 간 DCI
    - 통신사 광백본

**1️⃣ 공통점 (Ayar vs POET)**

|  |  |  |
| --- | --- | --- |
| **구분** | **Ayar** | **POET** |
| Die 내부 광? | ❌ | ❌ |
| 패키지 내부 광? | ✅ | ✅ |

| 타겟 | AI 패키지 내부 대역폭 | AI 패키지 + 광엔진 |

- - 둘 다:

    - GPU/ASIC 다이 **“옆에”**
    - **광 I/O 칩을 붙여서**
    - **패키지 내부에서 전기 대신 광으로 연결**
  - 이 관점에서는 **동일한 층위(Level)** 에 있다.

**2️⃣ 하지만 “DSP 존재 여부”에서 완전히 갈림 (핵심 차이)**

- - 여기가 **마벨과의 관계, 그리고 Ayar vs POET의 본질적 차이**이다.

|  |  |  |
| --- | --- | --- |
| **구분** | **Ayar Labs** | **POET** |

| FEC / 보정 | ❌ 없음 | ✅ 있음 |
| 이더넷 호환 | ❌ 전용 링크 | ✅ 표준 이더넷 |
| 마벨 DSP 대체? | ✅ 일부 가능 | ❌ 불가 (오히려 마벨 고객) |

- - 즉:

    - **Ayar = “DSP를 제거하려는 기술”**
    - **POET = “DSP를 더 효율적으로 쓰게 해주는 기술”**

- - Ayar Labs와 POET는 모두 패키지 내부에서 칩 간 연결을 광으로 처리한다는 공통점이 있지만,

**✅광통신–DSP 구조**

**1️⃣DSP는 정확히 “무엇을 하느냐?”**

- - DSP는 “아날로그로 망가진 디지털 정보를 다시 완벽한 디지털로 복구하는 복원 기계”

[ GPU ] → (디지털 전기) → [ DAC ] → (아날로그 전기) → [ 레이저 변조 ]
→ (아날로그 광) → [ 포토다이오드 ]
→ (아날로그 전기) → [ ADC ] → (디지털 전기) → [ DSP ]

**2️⃣ 그럼 Ayar는 왜 “DSP가 필요 없느냐?”**

1. 1. **거리 극단적으로 짧음**

      - 패키지 내부, 보드 내 수 cm~수십 cm 수준
      - 감쇠·분산·반사가 “무시 가능” 수준
   2. **환경 통제 가능**

      - 같은 패키지/보드 → 온도·진동·커넥터 편차가 거의 없음
      - 케이블/커넥터/광소자 전부 자기 설계·자기 스택
   3. **변조 포맷 단순화**

      - 고차 변조(PAM4, QAM) 대신 **단순 OOK/NRZ 또는 그에 준하는 것**

        - **PAM4 (Pulse Amplitude Modulation, 4-level)**

          - → **진폭(Amplitude)** 을 4단계로 나눠서 데이터를 보냄
        - **QAM (Quadrature Amplitude Modulation)**

          - → **진폭(Amplitude) + 위상(Phase)** 을 동시에 써서 데이터를 보냄
      - 즉, **복잡한 Equalization·FEC 없이도 BER를 억제 가능**
   4. **링크 목적이 “패키지 내부 대역폭 증가 + 전력 절감”**

      - 여기서는 1m 이내를 극한으로 최적화하는 게 목표
      - 100m, 1km 같은 건 애초에 자기 스코프가 아님 → 그건 **DSP + 마벨 영역**
   - 이 조건을 만족하면:

     - **채널이 너무 짧고 깨끗해서**
     - ADC로 미친 샘플링을 해서 DSP로 복원할 필요가 거의 없음
     - 대신:

       - 간단한 아날로그 프런트엔드 +
       - 비교적 단순한 클록/데이터 회복(CDR) 정도면 충분
   - ADC→DSP→DAC 과정을 통째로 제거 가능
   - 대신:

     - GPU에서 나온 디지털 신호를 바로 **간단 아날로그 변조기(driver)** 로 광으로 바꿔서 쏘는 구조

**3️⃣그래서 마벨 DSP의 존재 이유는?**

- - 거리 + 속도 + 오류율 + 표준 통신 + 대규모 스위칭
  - → 이 5개를 동시에 만족시키려면
  - → 아날로그 광을 그냥 쓰면 반드시 무너지고,
  - → DSP만이 이것을 디지털 세계로 되돌릴 수 있기 때문

**4️⃣“패키지 내부 광”을 누가 하느냐를 정확히 나누면**

|  |  |  |  |
| --- | --- | --- | --- |
| **회사** | **패키지(CPO/OCI) 내부 광** | **DSP 포함 여부** | **성격** |
| **Ayar Labs** | ✅ 핵심 사업 | ❌ **DSP-less** | 초저전력, 초단거리 전용 |
| **Intel (Silicon Photonics + OCI)** | ✅ 적극 추진 | ✅ **DSP 전제** | 표준 이더넷, 랙/랙간 |
| **POET** | ✅ 가능 (광엔진) | ✅ **DSP 전제** | 광모듈/광엔진 공급 |
| **Marvell** | ❌ OCI 자체는 안 만듦 | ✅ **DSP 본체** | 네트워크/DSP 두뇌 |

- - **Ayar = “패키지 내부 광 + DSP 제거”**
  - **Intel = “패키지 내부 광 + DSP 유지”**
  - **POET = “패키지 내부 광엔진 + DSP와 결합”**

****

**5️⃣구조적으로 누가 더 강하냐는 관점에서 보면**

- - **Ayar**:

    - 서버 내부 전력·지연·밀도에서는 **가장 혁신적**
    - 하지만 **적용 범위가 가장 좁음**
  - **Intel / POET**:

    - 서버 → 랙 → 랙간까지 **연속적으로 확장 가능**
    - 기존 이더넷·데이터센터 표준과 **완전히 호환**
  - **Marvell**:

    - 이 둘을 **밖에서 지배하는 네트워크·DSP의 ‘두뇌’**

**✅왜 NVIDIA는 Ayar를 선택했나?******

**1️⃣** **NVIDIA가 가장 두려워하는 것**

- - GPU 성능보다 더 빨리 망가지는 게 **전력·발열·배선**
  - GPU가 커질수록:

    - 보드 레벨 전기 인터커넥트 → **전력 폭탄**
    - 신호 무결성(SI) → **112G/224G에서 급붕괴**
  - 그래서 NVIDIA의 선택은:

> ***❝ GPU 안에서 쓰는 전기 배선을 ‘광’으로 바꿔버리자 ❞***
>
> ***→ Ayar 같은 DSP-less Direct Drive가 최적*********

**2️⃣** **NVIDIA 입장에서 Ayar는 “GPU 내부 구조적 해답”**

- - GPU ↔ GPU
  - GPU ↔ HBM 컨트롤러
  - GPU ↔ 같은 랙 스위치
  - 이 구간에서:

    - DSP 전력 아예 제거
    - ADC/DAC 제거
    - 레인당 전력 50% 이상 감소
    - GPU 집적도 극대화
  - 👉 **NVIDIA는 ‘GPU 하나당 성능’보다 ‘랙당 FLOPS’를 극단으로 밀어올리는 회사**라서 **Ayar가 전략적으로 완벽히 맞다.**

---

**✅ 왜 Intel은 여전히 DSP 포함 OCI를 고수하나?**

- - Intel의 본질은: CPU는 “범용 표준 컴퓨팅 플랫폼”
  - Intel은 다음을 포기할 수 없다:

    - 표준 이더넷
    - 모든 스위치와 상호운용
    - 랙 간 연결
    - 멀티벤더 생태계
    - 통신 규격(IEEE)
  - 이 요구사항을 만족하려면:

> ***❌ DSP-less 광은 구조적으로 불가능***
>
> ***✅ DSP + PAM4 + FEC + 이더넷이 필수*********

- - 그래서 Intel은:

    - “광은 패키지 안으로 끌어오되”
    - “통신은 끝까지 ‘표준 이더넷’으로 가자”
    - → OCI 안에도 **DSP 전제**

---

**✅ 전력 vs 거리 vs 표준 – 트레이드오프 공식**

- - 이건 물리적으로 항상 성립하는 공식다:

> ***전력↓ → 거리↓ → 비표준화***
>
> ***거리↑ → 전력↑ → 표준화***

- - 그래서:

    - **Ayar** = 전력↓ 끝판왕 → 거리 짧음 → 비표준
    - **Intel+DSP** = 거리↑ + 표준 유지 → 전력↑

---

**✅결론**

**1️⃣ 거시적 관점(Macro / 시스템-네트워크 관점)**

- - 데이터센터 전체 관점에서는 수많은 CPU·GPU·스토리지·스위치·랙·데이터센터가 서로 **표준화된 방식으로 안정적으로 통신해야 한다.**
  - 그래서 이미 전 세계적으로 검증된 IEEE 802.3 이더넷을 고수하는 것이 합리적이고, 그 거리·속도·신뢰성 요건을 만족시키려면 아날로그 광을 반드시 **DSP로 통역·복원**해야 한다.

**2️⃣ 미시적 관점(Micro / 패키지·전력·열 관점)**

- - 반면, GPU 패키지 내부·보드 내부처럼 거리가 **수 cm ~ 수십 cm로 극단적으로 짧고**, 외부 표준과도 직접 연결될 필요가 없는 구간에서는 **프로토콜 호환성보다 전력·발열·밀도·지연이 더 중요하다.**
  - 이 구간에서는 굳이 이더넷/표준을 쓸 필요도 없고, 아날로그 채널도 너무 깨끗하기 때문에 **DSP를 굳이 넣지 않아도 BER를 유지할 수 있다.**
  - 그래서 **Ayar 같은 ‘전용 링크 + DSP-less 광 I/O’가 합리적이다.**

****

**3️⃣ POET는 구조적으로 “마벨이 클수록 같이 커지는 회사”**

- - AI 트래픽 ↑
  - 400G → 800G → 1.6T로 올라감
  - DSP 필요성 ↑
  - 광모듈 수요 ↑
  - **POET 광엔진 수요 ↑**

****

**4️⃣ POET는 ‘Ayar가 성공하면 망하는 회사냐, 아니면 오히려 같이 크는 회사냐?’**

- - Ayar가 성공할수록 전체 광 트래픽이 폭증하므로,

    - Ayar의 성공은 GPU 밀도 ↑

      - 랙당 연산량 ↑
      - 랙당 데이터 이동량 ↑
      - 랙 ↔ 랙 트래픽 ↑
      - Spine 스위치 트래픽 ↑
      - DCI(DC 간) 트래픽 ↑
  - POET는 ‘직접 경쟁’이 아니라 ‘간접 수혜’ 쪽에 가깝다.
