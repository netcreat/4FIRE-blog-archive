**📌1. 핵심 주장**

- - 느린 양자 인터커넥트(예: 원격 Bell pair 생성이 게이트보다 5배 느림)라도, **여러 QPU를 연결한 분산 구조가 단일 거대 QPU보다 더 잘할 수 있음을 증명한다.**
  - 특히, IonQ가 만든 **CliNR(Clifford Noise Reduction)** 기법을 **분산형으로 재설계**하면,

    - **논리 오류율이 더 낮고**,
    - **회로 깊이도 더 짧아진다.**
  - 즉, *“인터커넥트가 느려도 분산 QC는 이득이 있다”* 를 처음으로 이론 + 시뮬레이션으로 보인다.

**📌2. 왜 가능한가? (핵심 직관)**

- - CliNR는 큰 Clifford 회로를 여러 **서브서킷**으로 쪼개고, 각 서브서킷을 **오프라인에서 준비 및 검증(RSP & RSV)** 한 뒤 성공한 리소스 상태만 사용해 회로를 주입(injection)한다.
  - 저자들은 다음을 보여준다:

    - RSP&V 과정은 Bell pair를 필요로 하지 않는다.

      - → **각 QPU가 독립적으로 병렬 수행 가능.**
    - 실제 Bell pair는 **회로를 주입할 때 n개만** 필요하다.

      - → 미리 충분히 만들어 저장해 둠으로써 **대기 시간(stall)** 을 거의 제거할 수 있다.
  - 이 구조 때문에 인터커넥트가 느려도 전체 알고리즘의 깊이가 늘어나지 않는다.

**📌3. 시뮬레이션 결과**

- - n = 85 큐비트 Clifford 회로를 기준으로 해보면:
  - **분산 CliNR의 성능**

    - **논리 오류율**: 단일 QPU에서 실행하는 단일(Monolithic) CliNR과 동일하게 낮춘다.
    - **깊이**: Monolithic보다 훨씬 짧고, 심지어 **직접 실행(direct circuit)** 보다도 짧다.
    - **인터커넥트 지연 τe ≤ 5** 까지는 모두 분산 구조가 우세하다.
  - 즉, **Bell pair 생성이 게이트보다 5배 느려도 문제없다.**

****

**📌4. 이론적 결과(Asymptotic)**

- - 대규모 시스템에서 분산 CLI NR이 stall 없이 동작하려면 각 링크가 **O(T / ln T)** 개의 Bell pair를 병렬 생성할 수 있으면 충분함을 증명한다. (여기서 T는 QPU 개수)

    - → 놀랍게도, **QPU 당 qubit 수와 무관하다.**
  - 이는 **대규모 분산 QC의 실용성**을 강하게 뒷받침한다.

**📌5. 의미 & 응용**

- - **느린 인터커넥트 시대의 유효한 분산 QC 전략**을 처음으로 명확히 제시
  - CliNR 같은 **저비용 에러 감소 기법**이 분산 구조에 이상적으로 결합됨을 입증
  - 향후 **분산형 양자 우월성 실험**(conjugated Clifford circuits) 가능성을 제시
  - IonQ의 **멀티-QPU 로드맵**을 기술적으로 뒷받침하는 연구

**✅****논문의 조건과 결과**

**📌조건**

- - 분산 양자 컴퓨팅 모델을 아래와 같이 고려하여 **현실 하드웨어보다 훨씬 더 나쁜 상황**을 일부러 설정한 것
  1. **각 QPU는 정확히 두 개의 다른 QPU와만 연결된다.**

     - 최저 비용, 최저 연결성의 극단적 환경을 상정한다.
  2. **각 연결은 한 번에 오직 하나의 Bell pair만 생성할 수 있다.**

     - 즉, **병렬 생성 불가.**
     - 이것은 *가장 보수적이고 느린 인터커넥트* 모델이다.
  3. **Bell pair를 생성하는 데 걸리는 시간은 내부 게이트 시간보다 τₑ 배 길다.**

     - Bell pair generation time=τe×gate time
     - 일반적으로 τₑ ≥ 1 인 매우 비관적 환경

**📌결과**

- - **얽힘 생성 시간이 게이트보다 최대 다섯 배(τₑ ≤ 5)까지 느리더라도**, 분산형 CliNR은

    - ▶ **직접 회로를 실행하는 방식(direct implementation)** 과
    - ▶ **단일 QPU에서 수행하는 monolithic CliNR** 보다
  - **더 낮은 논리 오류율(logical error rate)** 과 **더 짧은 회로 깊이(depth)**를 동시에 달성한다.
  - 또한, **대규모 확장(asymptotic regime)** 에서 조건 (2)을 완화하여, 각 연결(link)이 서로 병렬로 **O(T / log****e** **T)** 개의 Bell pair를 생성할 수 있다고 가정하면, QPU 수 T가 증가하더라도 **분산 CliNR이 더 이상 얽힘 생성 때문에 지연(stall)되지 않음을** 증명한다.

    - **T = 10****4** **→ 1,087**
    - **T = 10****5** **→ 8,682**
  - 이 결과는 **QPU 내부의 큐비트 수와 무관하게 성립**한다.

**✅****단일 QPU와 분산형 아키텍처**

**📌1. Monolithic Architecture (단일 QPU 아키텍처)**

- - 단일(monolithic) 아키텍처는 **모든 큐비트를 하나의 QPU 내부에 배치한 구조**를 의미한다.
  - 이 QPU는 다음과 같은 기능을 갖춘 것으로 가정한다:

    - |0⟩ 상태로의 큐비트 초기화
    - 임의의 단일 큐비트 회전 연산
    - CX, CY, CZ와 같은 **임의의 두 큐비트 게이트**
    - 단일 큐비트 파울리 측정
  - 여기서 중요한 점은:

> ***QPU 내부의 모든 큐비트가 서로 완전히 연결되어 있으며,***
>
> ***서로 겹치지 않는 연산들은 동시에 병렬로 수행 가능하다고 가정한다.***

- - 즉, 단일 QPU는 **완전 연결 + 최대 병렬성**을 지원하는 "이상적 메모리+컴퓨팅 장치"로 모델링된다.

**📌2. Distributed Architecture (분산형 아키텍처)**

- - 분산형 아키텍처에서는 하나의 QPU 대신 **여러 개의 QPU가 네트워크로 연결된 구조**를 사용한다.
  - 이 논문에서는 가장 단순하고 제한적인 형태인 **원형(circular) 토폴로지**를 가정한다.
  - **QPU 네트워크 구조**

    - 총 **T개의 QPU**를 사용하며, 각 QPU는 **Q**k로 표시한다.
    - **Q**k는 오직 **두 개의 QPU(**Qk-1, Qk+1**)** 와만 연결된다.
    - 즉, QPU들은 **원형 링 구조**를 이룬다.
  - **QPU 내부 구성**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTEyMTJfMTY1/MDAxNzY1NTQ1MzM2NzQz._Kb5nwnLtqtTZseyhKEkW_UduzIg691b0RJ9WPCh4JQg.lIfJLYY-pEsLLnieJHgk02G5bRDTPWvgqvdZdSW9-EAg.PNG/image.png?type=w800)](#)

- - - 각 QPU는 다음 **3개 모듈**로 구성된다:

      1. **Entanglement generation module (얽힘 생성 모듈)**

         - 인접한 QPU와 **Bell pair를 생성**하는 역할
         - 생성된 Bell pair는 즉시 저장 모듈로 이동된다
         - 한 링크는 한 번에 Bell pair 하나만 생성할 수 있으며, Bell pair 생성에 **τₑ 단위 시간**이 걸린다고 가정한다
         - 링크마다 서로 다른 Bell pair는 동시에 생성할 수 있음 (병렬성은 link 단위)
      2. **Storage module (저장 모듈)**

         - 총 ns개의 저장 큐비트를 포함
         - 생성된 Bell pair의 절반(한 큐비트)을 저장
         - 다른 반쪽은 인접한 QPU의 storage module에 저장됨
         - 이 저장 큐비트들은 **idle noise가 거의 없다고 가정**한다
         - compute module과 제한적으로 상호작용할 수 있음 (예: remote gate 실행 시)
      3. **Compute module (계산 모듈)**

         - 총 nc개의 **완전 연결**된 “계산용 큐비트”
         - monolithic QPU와 동일한 방식으로 단일/이중 큐비트 게이트, 측정 수행
         - 최대 병렬 연산 가능
         - 분산된 리소스 상태 주입(RSI)은 이 compute module에서 실행된다

**📌3. Remote Gate의 개념**

- - 분산 아키텍처에서는 QPU 간에 물리적으로 떨어진 큐비트끼리도 **원격 CX 또는 텔레포테이션 기반 게이트(remote gate)** 를 수행할 수 있다.

    - Remote gate 1회 실행 → **저장 모듈에 미리 저장된 Bell pair 1개를 소비**
    - 저장된 Bell pair가 충분하지 않으면 → **연산이 지연(stall)**
    - 따라서 Bell pair 생성 속도(= τₑ)가 분산 계산의 성능을 결정하는 핵심 요소가 된다.
  - 이 구조에서 분산형 QPU는:

> ***저장 모듈 = Bell pair buffer***
>
> ***계산 모듈 = 연산 실행 지점***
>
> ***얽힘 생성 모듈 = 원격 게이트 “연료” 생산기***

**✅****단일형 CliNR와 분산형 CliNR 방식**

**📌A. Review of CliNR (기존 CliNR 요약)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTEyMTJfNyAg/MDAxNzY1NTQ2MDcwMTI1.Mifc3rRp8ijsVL_b0xud1oGrk7EZP37yOcO3YOOj_6Ag.hMsUZyyZ1pK7-vzyjhHgWs9Ld8SAIrTlmvB0JyHMGgQg.PNG/image.png?type=w800)](#)

- - CliNR는 **Clifford 회로에서 발생하는 논리 오류율을 감소시키기 위한 기법**이다.
  - 핵심 아이디어는 다음과 같다:

    - Clifford 회로 C를 직접 실행하지 않고
    - **오프라인에서 리소스 상태(resource state)** 를 먼저 준비한 뒤 그 리소스 상태가 에러 없이 준비되었는지 **stabilizer 측정으로 검증(RSV)** 한다.
    - 성공적으로 검증된 상태만 회로에 **주입(injection)** 한다.
  - 즉, 회로를 직접 실행하면서 오류가 누적되는 것을 피하기 위해, 회로 일부를 **사전에 오프라인에서 준비·검증**해 두는 방식이다.
  - CliNR의 3단계 구조

    - **RSP**: 리소스 상태 만들기
    - **RSV**: 리소스 상태 검사(검증)
    - **RSI**: 만들어진 리소스 상태를 회로에 “주입”
  - 문제점

    - 검증(RSV)에서 실패하면 처음부터 다시 해야 해서 시간이 오래 걸린다.
    - 큰 회로일수록 실패 확률도 커지고, 반복도 많아짐 → 깊이가 길어짐.

**📌B. Distributed CliNR (분산형 CliNR)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTEyMTJfNjUg/MDAxNzY1NTQ2NDA3ODk0.0FlEeSM3-QQVgX3WQ9I3gYTjG8NNZLpBK2HDFK9vBLIg.-39KZojQI4r6NfVhr0drdDa8N_8a_oJSvsz1wvER8UUg.PNG/image.png?type=w800)](#)

- - 본 연구에서는 위의 CliNR을 **분산 QPU 환경에서 수행할 수 있도록 재설계**한다.
  - 목표:

> ***리소스 상태 준비(RSP)와 검증(RSV)을 여러 QPU에서 병렬로 동시에 수행하여 전체 깊이를 줄이고,***
>
> ***이후 순차적으로 주입(RSI)을 수행하면서 remote gate로 회로를 연결한다.***

- - Step 1: 여러 QPU가 **각자** 동시에 RSP & RSV 실행

    - QPU0는 첫 번째 블록
    - QPU1는 두 번째 블록
    - QPU2는 세 번째 블록
    - … 이런 식으로 **병렬 준비**
    - → 이 단계는 **인터커넥트(Bell pair)를 전혀 안 씀**
    - → 즉, 얽힘이 느려도 문제 없음!
  - **Step 2: 준비된 블록들을 하나씩 주입(RSI)**

    - 여기서 remote gate가 필요해서 Bell pair를 써야 함.
    - 각 RSI에서는 **n개의 Bell pair**가 필요
    - Bell pair가 모자라면 그 부분이 잠시 멈춤(stall)
    - 그래서 τₑ(벨페어 생성 속도)가 중요해짐.
  - Step 3: 최종 결과를 맨 앞 QPU로 텔레포트해서 작업 종료

    - 조건처럼 QPU들이 직접 연결되어 있지 않더라도
    - 체인 텔레포테이션(chain teleportation)으로 최종 상태를 이동가능함

**📌C. Three Implementations (세 가지 구현 모델)**

- - 논문은 Clifford 회로를 실행하는 세 가지 방식을 비교한다:
  1. **Direct implementation**

     - n-qubit monolithic QPU에서 Clifford 회로를 직접 실행
  2. **Monolithic CliNRₜ,ᵣ**

     - 하나의 QPU(3n+1 qubits)에 전체 CliNR을 수행
  3. **Distributed CliNRₜ,ᵣ**

     - t+1개의 QPU에 분산하여 실행
     - 각 QPU는 (2n+1 compute qubits + 2n storage qubits)

    - τₑ = 1(인터커넥트가 게이트랑 동일한 속도)일 때는, 분산형이 monolithic보다 실제 오류가 더 적다.
  - 오른쪽 그래프: 깊이(Depth)

    - 분산 CliNR은 깊이를 단일 CliNR보다 훨씬 줄일 수 있다.
    - (성능은 같거나 더 좋은데, 깊이는 더 작아짐 → 최고의 조합)

**📌n = 85일 때 τₑ(인터커넥트 속도) 변화에 따른 성능**

- - 왼쪽 그래프: 논리 오류율(Logical Error Rate)

    - τₑ ≤ 5일 때 분산 CliNR은 단일 QPU보다 항상 더 낮은 오류율을 달성한다.

      - 초록색선이 파란색과 주황색보다 어 낮은 오류율을 갖는다.
    - 인터커넥트가 게이트보다 **5배 느려도** 분산 구조는 monolithic보다 **더 성능이 좋다**.
  - 오른쪽 그래프: 깊이(Depth)

    - τₑ ≤ 5 까지는 depth 증가가 매우 완만하여 실용적으로 감당 가능하다.

---

**✅****이 논문의 진정한 의미**

- - **이 논문의 결과는** ***CliNR에 특화된 것이지만*****, 핵심 메커니즘은 다른 QEC·오류경감(error mitigation) 기법에도 “일반화될 가능성이 매우 크다.”**
  - 즉, **모든 QEC에 자동 적용되는 것은 아니지만, 구조적 이유 때문에 상당수 기술에 확장될 수 있다.**

**🟦 1. 결론 요약**

|  |  |
| --- | --- |
| **항목** | **적용 여부** |
| **Clifford 기반 오류 억제 / 오류 경감 기법 (CliNR 계열)** | ✔ 강하게 적용됨 |
| **리소스 상태를 만드는 방식의 다른 기법들 (magic-state distillation 등)** | ✔ 원리적으로 적용 가능 |
| **표준 QEC(Surface code, LDPC 등)** | △ 일부만 적용됨 (특정 구조에서만 가능) |
| **회로 병렬화가 중요한 알고리즘(QAOA, VQE 등)** | △ 특정 경우에 적용 가능 |

> ***이 논문의 결과는 “CliNR만 가능한 마법”이 아니라,***
>
> ***“리소스 상태를 분산 병렬로 준비할 수 있는 구조의 QEC·오류 경감 기법에서는 모두 작동”할 가능성이 있다.***

**🟦 2. 왜 이 논문은 CliNR에 집중했나?**

- - CliNR는 Clifford 회로를 다음 방식으로 수행한다:

    1. 리소스 상태 미리 만들기
    2. 검증하고
    3. 성공한 것만 주입(injection)
  - 즉, **RSP&V를 완전히 오프라인으로 병렬화할 수 있는 구조**를 갖고 있다.
  - Distributed CliNR의 성능 향상이 가능한 이유가 바로 여기에 있다:

> ***✔ RSP&V는 Bell pair를 전혀 사용하지 않는다***
>
> ***✔ 즉, “느린 인터커넥트”의 영향을 받지 않는다***
>
> ***✔ 따라서 여러 QPU가 동시에 준비를 하면 병렬 효과가 극대화된다***

- - 즉, **전체 오버헤드를 잡아먹던 가장 큰 병목(RSP&V)을 완전히 병렬화할 수 있다.**
  - 이 구조가 CliNR을 분산에 “아주 잘 맞는 알고리즘”으로 만든다.

**🟦 3. 그렇다면 다른 QEC도 이런 이득을 얻을 수 있을까?**

- - 결론은 **“경우에 따라 다르다.”**
  - 아래는 주요 QEC 계열별로 적용 가능성 분석.
  1. **Magic-State Distillation (T게이트용).**

     - 이건 사실 **CliNR와 매우 비슷한 구조**이다:

       - 오프라인에서 Magic state 준비
       - 여러 라운드를 병렬로 준비
       - 실패하면 다시 만들어야 함
       - 성공한 상태만 회로에 주입
     - 즉, **RSP&V 구조가 CliNR과 거의 동일하다.**

       - ➡ 이 논문의 아이디어는 **magic-state distillation에도 그대로 적용 가능**
       - ➡ 여러 QPU가 동시에 distillation 수행 → 성공률 높아짐 → 시간 단축
       - ➡ remote gate 비용은 distillation 단계에 거의 없음
     - 이건 정말 높은 적용 가능성을 가진다.
  2. **Surface Code + Lattice Surgery**

     - Surface code는 다음 특성이 있다:

       - 대부분의 연산은 **로컬**
       - 원거리 조작은 **lattice surgery** 나 **teleportation** 필요
       - 병목은 **통신 비용(Bell pair)**
     - 즉, 분산 효과는 **일부 상황에서는 가능**하지만:

       - 코드 패치 자체는 분산하기 어려움
       - syndrome extraction은 매우 로컬하고 반복적
       - RSP&V처럼 오프라인 병렬화 가능한 구조가 기본적으로 없다
     - ➡ **완전한 이득은 어렵고, 제한적 이득만 가능**
     - 그러나 “분산 surface-code factory” 같은 아이디어에는 적용 가능.
  3. **LDPC codes (qLDPC, HGP, Cyclic HGP 등)**

     - LDPC 계열은:

       - 검출기(graph)가 매우 sparse
       - 병렬 syndrome extraction 가능
       - 일부 회로를 원격 게이트로 연결하는 구조가 필요함
       - 디코더가 겹치지 않으면 병렬성 증가 가능
     - 따라서:

       - ➡ **일부 구조에서는 분산 RSP가 가능**
       - ➡ 특히 “magic-state factory” 또는 “logical Clifford 준비” 단계에서 큰 이득 가능
       - 클러스터형 fault-tolerance에서는 비교적 높은 적용 가능성을 가진다.
  4. **QAOA, VQE 같은 알고리즘적 구조**

     - 이 경우에도 다음 조건이 맞으면 적용 가능:

       - 각 레이어를 독립 QPU에서 준비 (리소스 상태 방식)
       - 레이어 간 연결만 remote gate 사용
     - 그러나 QAOA는 **Clifford가 아니기 때문에** CliNR 직접 적용은 불가함.

       - 다만:
       - ➡ “parameterized Clifford + magic-state injection” 구조로 재해석하면 일부 적용 가능

**🟦 4. 정리:**

- - **✔ 이 논문의 핵심 메커니즘은 “RSP&V를 분산 QPU에서 병렬화한다”는 아이디어이다.**
  - 이 점은 **CliNR뿐만 아니라, 리소스 기반 QEC·오류 경감 기술에 넓게 확장 가능**하다.
  - 구조적으로 동일한 특징을 가진 경우:

    - 리소스 상태를 미리 만들고
    - 검증하고
    - 성공 시 주입하는 방식이라면
  - → **Distributed CliNR의 원리를 그대로 사용할 수 있다.**

****

**🟩 최종 결론**

> ***논문의 결과는 형식적으로는 CliNR에 대한 것이지만,***
>
> ***동일한 구조를 가진 많은 QEC·오류경감 기법에도 적용되는 “범용 원리”이다.***

- - 특히 다음에는 거의 그대로 적용 가능:

    - Magic-state distillation
    - Clifford-based subroutines
    - Multi-QPU logical state factories
    - LDPC / HGP code 기반 리소스 준비
    - Distributed logical Clifford blocks

> 각각의 QPU에서 수행하는 QEC 성능이 향후 크게 개선된다면,
>
> 이러한 분산 기반 기법이 더 이상 필요하지 않을 가능성도 있다.
>
> 현재는 네트워킹 속도가 연산 속도보다 훨씬 느리기 때문에
>
> 연산을 여러 QPU로 분산시키고, 최종 결과만 네트워크를 통해 전달받는 방식이 유리한 것이다.
>
> 이는 마치 비트코인 채굴에서 여러 GPU를 병렬로 연결하여
>
> 독립적으로 계산을 수행한 뒤, 유효한 해시만 네트워크로 제출하는 구조와도 비슷하다.
>
> 물론 양자 네트워킹 분야에는 아직 해결해야 할 기술적 과제가 많아
>
> 완전한 형태로 구현되기까지는 시간이 더 필요하다.
>
> 그럼에도 불구하고, 다양한 접근을 실험하고
>
> 각 시대의 기술 수준에 적합한 최적의 방법을 찾아가는 일은
>
> 기업과 연구자 모두에게 중요한 과제라고 생각한다.
