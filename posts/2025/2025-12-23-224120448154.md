# AST SpaceMobile의 한계와 사업 모델

Published: 2025-12-23T22:51:01.934000+09:00

Original Naver post: https://blog.naver.com/4-fire/224120448154

---

> ASTS는 500km가 넘는 높은 곳에서 어떻게 서비스를 할까 들여다 보자.

**✅AST SpaceMobile 개념 요약**

- - **LEO 위성 고도**: 약 **500–700 km**
  - **지상 단말**: 일반 스마트폰 (아이폰/안드로이드, 개조 없음)
  - **주파수**: 기존 **LTE/5G 대역 (저주파 중심, <3GHz)**
  - **목표**: 지상 기지국이 없는 지역에서도 **직접 통신**

****

1. 1. **핵심은 거대한 위상 배열 안테나**

      - **BlueWalker 3**:

        - 펼쳤을 때 **약 64~70 m****2**
        - 위성 안테나로는 사실상 **사상 최대급**
      - 수천 개의 소형 안테나 소자를 위상 배열(phased array)로 제어
   2. **아주 좁은 빔포밍 (Beamforming)**

      - 지상 LTE 기지국:

        - 섹터 폭 **60~120°**
      - 위성 빔포밍(ASTS):

        - **수 도(°) 이하**
        - 경우에 따라 **1° 미만**
      - 빔 하나 = 수 km ~ 수십 km
      - 동시에 수천 명을 덮는 구조 ❌
      - **TDMA / FDMA / 빔 스위칭**으로 순차 서비스
      - 📞 음성, SMS, 저속 데이터 → OK
      - 📹 유튜브, 대용량 트래픽 → 구조적으로 불리
   - 👉 결과:

     - 위성 자체 출력은 **법적·물리적 한계 내**
     - 스마트폰에서 나오는 **아주 약한 업링크 신호도 수신 가능**
   - ****📌 쉽게 비유하면

> ***Upstream : 위성의 거대한 배열 안테나***
>
> ***Downstream : 좁은 빔포밍***

**2️⃣ 딜레이(latency)는?**

- - **📍 생각보다 크지 않다**
  - **📏 전파 지연 계산**

    - 고도 500 km → 왕복 약 1,000 km
    - 빛의 속도 기준:

      - **전파 지연 ≈ 3.3 ms (편도)**
      - 왕복(RTT) ≈ **7 ms 내외**
  - **📡 실제 체감 딜레이**

    - 위성 → 지상 게이트웨이 → 코어망 경유
    - **총 RTT**:

      - 약 **30–50 ms**
      - LTE 지상망과 비슷하거나 약간 느린 수준
      - Starlink(위성 인터넷)과 거의 동일한 레벨
  - 📌 **음성 통화, 메시지, 저속 데이터**: 문제 없음
  - 📌 **초저지연 게임/고빈도 트레이딩**: 부적합

**3️⃣ 왜 가능한데, 왜 아무나 못 하냐?**

- - **📍 기술적 진입장벽이 매우 높다**

|  |  |
| --- | --- |
| **요소** | **이유** |
| 초대형 전개형 안테나 | 발사·전개 실패 리스크 |
| 위상 배열 제어 | 위성 전력·열·연산 한계 |
| 셀룰러 표준 연동 | 3GPP/통신사 협력 필수 |
| 링크 버짓 최적화 | 안테나·궤도·주파수 동시 최적화 |

- - 👉 그래서 **ASTS가 유일하게 “직접 스마트폰 연결”을 실증**했다.

**4️⃣ 가능한 서비스 범위 (현실 기준)**

- - **✅ 잘 되는 것**

    - 📞 **음성 통화 (VoLTE)**
    - 💬 **SMS / RCS**
    - 📡 **메신저 텍스트**
    - 📍 **위치 정보, IoT 텔레메트리**
    - 📨 **저속 앱 데이터**

      - WhatsApp 텍스트
      - 이메일(첨부 제외)
      - 간단한 웹 요청
    - 👉 **수 kbps ~ 수십 kbps 수준의 일정한 대역폭 요구사항**
  - **⚠️ 제한적으로 되는 것**

    - 🖼️ 이미지 전송 (저해상도)
    - 📲 앱 알림
    - 🌐 매우 가벼운 웹 페이지
    - 📌 가능은 하지만:

      - 지연 있음
      - 대기시간 길어짐
      - 동시 사용자 많으면 속도 급락
  - **❌ 구조적으로 불가능한 것**

    - 📹 유튜브 / 넷플릭스
    - 🎮 실시간 게임
    - 📥 앱 다운로드 / 업데이트
    - ☁️ 대용량 파일 업로드·다운로드
    - 📡 지상 5G 수준 모바일 데이터

**5️⃣ 왜 데이터가 제한되나?**

- - **한 빔 = 한 셀 (하지만 셀이 너무 크다)**

    - 지상 LTE:

      - 셀 반경 **수백 m ~ 수 km**
      - 섹터 다수
    - ASTS:

      - 위성 1기
      - 셀 반경 **수 km ~ 수십 km**
      - 수십~수백 개 빔을 **시간 분할로 운용**
    - 👉 **동시에 붙을 수 있는 단말 수가 적다**
  - **위성 전력 & 열 한계**

    - 위성은:

      - 수 kW급 태양광
      - 배터리 제한
    - 빔 수 늘리면:

      - 전력 분산
      - 각 빔 SNR 하락
      - → 데이터율 감소
  - **주파수 대역의 한계**

    - ASTS는 **저주파 LTE 대역**(700~900 MHz 중심) 사용

      - 저주파는 커버리지는 좋지만 대역폭이 좁음
    - 중주파(2~3.5 GHz)는 저주파 대비 손실이 크게 증가하여

      - 연결 성공율
      - 통화 유지율
      - 이 낮아서 저주파를 사용하게 됨.

> ***한 빔(한 셀)당 최대 대역폭이*** ***120Mbps***

|  |  |  |
| --- | --- | --- |
| **상황** | **실효 대역폭** | **셀 총 처리량** |
| 베스트 케이스 | 40 MHz | ~120 Mbps |
| 양호 | 20 MHz | ~50–60 Mbps |
| 보통 | 10 MHz | ~20–30 Mbps |
| 혼잡/비상 | 5 MHz | 음성 중심 |

**✅ASTS의 비지니스 모델**

**1️⃣****사용자의 경험**

- - 평소:

    - 📶 데이터 → 지상 LTE/5G
    - 📞 음성 → VoLTE
  - 무인지역/재난:

    - 📞 **ASTS로 자동 폴백**
    - 📡 데이터는:

      - Starlink 단말 있으면 사용
      - 없으면 제한적 메시지 수준

**2️⃣ASTS의 사업 목적**

- - ASTS는 음성과 데이터를 "평소처럼 제공하는 기술”이 아니라 “완전히 끊기지 않게 하는 기술”이다.
  - **지상 LTE/5G 대체하거나** **일반 데이터 요금제 경쟁을 하려는 회사가 아니다**
  - 👉 ASTS는 “모바일 메인망”이 아니라 “모바일 보험망”이다.

**3️⃣ ASTS의 타겟**

- - 사용자 직접 과금 ❌ (보조적)
  - **통신사 도매 계약 ✔**
  - 정부/공공 ✔
  - 재난/의무 커버리지 ✔
  - 📌 ASTS는 **B2C보다 B2B2C**
