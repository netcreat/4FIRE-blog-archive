**✅****알고리즘 종류**

- - **QLBM (Quantum Lattice Bolzmann Method) → 시뮬레이션 기반 CFD 해법 → FTQC**
  - **VQE (Variational Quantum Eigensolver) → 변분 최적화 기본형, 고유값 문제에 특화**
  - **QITE (Quantum Imaginary Time Evolution) → Imaginary-time 진화를 직접 시뮬레이션, 회로 깊이 부담 큼**
  - **cQITE (Compressed QITE) → QITE 최적화 버전, 리소스 효율성↑**
  - **VarQITE (Vatiational QITE) → QITE를 VQE 스타일로 변환, PDE 해법에서 가장 유망**
  - **QAOA (****Quantum Approximate Optimization Algorithm) → 조합최적화 전용, PDE엔 QUBO 변환 필요 → FTQC**
  - **AWQV (Adaptive Weighted QITE-VQE) → QITE+VQE 하이브리드, 샷 절감 + 수렴속도 향상**

    - **문제점**: QITE를 NISQ에서 직접 적용하면 압축(cQITE) 때문에 오차가 누적되어 성능이 떨어짐.
    - **해결책**: VQE의 기울기 정보를 동적으로 섞어주는 **Adaptive Weighted QITE-VQE (AWQV)** 도입.

      - 초반엔 **QITE 업데이트**를 크게 반영 → 빠른 초기 수렴
      - 후반엔 **VQE 기울기 기반**으로 세밀하게 최적화
      - 실험에서 MaxCut 기준 **pgs ≈ 1.0** → 거의 완벽히 최적 상태 도달

- - **VQE는 범용적 알고리즘이지만 “최적화 문제(QUBO)”보다는 “고윳값 문제(Eigenvalue Problem)”에 강점**이 있다.
  - 즉, VQE는 기본적으로 **화학, 재료, 물리계 시뮬레이션**에 더 최적화돼 있고, 조합 최적화(MaxCut, UC, 그래프 파티셔닝)에서는 QAOA·QITE 계열이 주력으로 쓰인다.

|  |  |  |
| --- | --- | --- |
| **비교 항목** | **VQE** | **QAOA/QITE/VarQITE/AWQV** |
| **목적** | 해밀토니안 바닥 상태 에너지 계산 | QUBO 기반 조합 최적화 해 찾기 |
| **적합한 문제** | 화학, 재료, 전자구조, 분자 시뮬레이션 | MaxCut, Unit Commitment, 그래프 파티셔닝 |
| **회로 깊이** | 얕음 → NISQ 친화적 | QITE/VarQITE/AWQV는 얕음, QAOA는 깊음 |
| **샘플 효율** | 낮음 (Expectation 측정 반복 필요) | QITE·AWQV가 VQE보다 샘플 효율 우수 |
| **Blood Pump 적용성** | Fill-in 최소화 직접 매핑 어려움 | VarQITE가 QUBO로 직접 매핑 가능 |
| **UC 문제 적용성** | MILP/QUBO 변환 시 비효율 | QITE 기반 VQA가 훨씬 효율적 |

**💡****유래**

- - **전통 LBM(Lattice Boltzmann Method)**

    - **배경**: 1980년대 후반 ~ 1990년대 초반
    - **목적**: **Navier-Stokes 방정식**을 직접 풀지 않고, **유체역학을 입자 기반 확률 분포로 모델링**
    - **핵심 아이디어**

      - 유체를 미시적 입자들의 집합으로 보고, 격자(lattice) 상에서 분포함수 fi(x,t)를 진화시킴.
      - **충돌(Collision)** + **스트리밍(Streaming)** 두 단계 반복.
      - 계산 단순성 덕분에 병렬성(Parallelism)에 매우 유리.
  - QLBM은 **클래식 LBM → 양자 버전으로 확장한 알고리즘**.
  - 2021년 Budinski가 최초 제안 → 이후 여러 최적화 연구 진행.
  - 2025년 IonQ + Ansys 논문에서 **IonQ Forte**에서 **실제 2D QLBM 시뮬레이션 최초 구현** 성공.
  - CFD, 항공역학, 날씨 예측, 반도체 냉각, 플라즈마 물리 등 **산업적 잠재력**이 매우 큼.
  - 요약

    - Navier-Stokes는 **기본 PDE** 자체를 푸는 전통적 접근.
    - LBM은 이를 확률 기반으로 단순화 → **양자화 가능성 ↑**.
    - VarQITE는 Navier-Stokes를 직접 다루되 **변분적 최적화**를 적용 → 여전히 초기 단계.
    - IonQ 논문이 QLBM을 선택한 이유는 **NISQ에서 실행 가능성**이 가장 높음

**💡****QLBM, VarQITE, QAOA 비교**

|  |  |  |  |
| --- | --- | --- | --- |
| **특징** | **QLBM** | **VarQITE** | **QAOA** |
| **문제 접근** | LBM 확률 분포를 양자 상태로 시뮬레이션 | N-S를 Imaginary Time Evolution으로 변환 | N-S를 QUBO로 변환 |
| **핵심 알고리즘** | 스트리밍 + 충돌 양자회로 | 변분 최적화 | QAOA 파라미터 최적화 |
| **변수 처리** | 연속 변수 직접 다룸 | 연속 변수 직접 다룸 | 이산화 필요(혹은 C-QAOA) |
| **회로 깊이** | 낮음 (MPS + One-hot Encoding) | 중간 | 깊음 (p ≫ 100) |
| **NISQ 적합성** | **매우 높음** (IonQ Forte 실험 성공) | 보통 | 낮음 |
| **주요 장점** | 병렬성, 실제 하드웨어 실험 가능 | VQE 기반, 최적화 안정적 | 전역 최적화 가능성 |
| **적합 문제** | CFD, 열전달, 미시유동 | 저차원 단순 PDE | 설계 최적화, 파라미터 튜닝 |

**💡****PDE와 최적화의 차이**

|  |  |  |
| --- | --- | --- |
| **특징** | **PDE 해석** | **최적화 문제** |
| **목표** | 물리 시스템의 상태(함수)를 예측 | 특정 비용/보상 함수의 최적값 탐색 |
| **출력** | 시간·공간에서 연속 함수 값 | 벡터/스칼라 최적해 |
| **수학적 성격** | 미분방정식 해 | 최소화/최대화 문제 |
| **대표 예시** | Navier-Stokes, Schrödinger, Maxwell | Travelling Salesman, Portfolio Optimization |
| **해공간** | 무한 차원(연속적) | 보통 유한 차원(이산 또는 연속) |
| **양자 알고리즘 접근** | QLBM, VarQITE, VQS, HHL | QAOA, VQE, QML |

- - **최적화**와 **PDE 해석**은 **목적과 방법이 다르다**:

    - 최적화: 어떤 목적함수를 최소화 또는 최대화 하여 최적 점(스칼라)을 찾는 문제
    - PDE 해석: **시간과 공간에서 연속적인 물리 현상을 기술하는 연속 함수**를 구하는 문제
  - 하지만 PDE를 잔차(redidual) 최소화 형태로 바꾸면 **최적화 문제로 재구성** 가능.

    - 잔차란 PDE가 얼마나 만족되니 않는지 측정하는 값
    - QAOA : PDE → QUBO → 최적화
    - QLBM : PDE를 LBM으로 변환 후 양자 시뮬레이션
    - VarQITE : 변분 원리(Variational Principle)를 이용하여 PDE를 Imaginary Time Evolution으로 변환

**💡****QLBM을 사용하는 이유**

- - 기존 CFD에서 사용하는 **Navier–Stokes(N-S) 방정식 직접 해법**은 HPC에서조차 **계산량이 폭발**하는 문제가 있음

|  |  |  |  |
| --- | --- | --- | --- |
| **CFD 접근** | **계산량 복잡도** | **병렬성** | **NISQ 적합성** |
| Navier-Stokes 직접 해석 | O(N^3) | 낮음 | 거의 불가능 |
| LBM (클래식) | O(N) | 높음 | GPU 친화적 |
| **QLBM** | O(log⁡N)~ O(polylog N) | **매우 높음** | **NISQ에서도 가능** |

- - 항공우주 / 자동차 공학
  - 반도체 및 마이크로채널 열관리
  - 에너지 및 기후 모델링
  - 제약, 바이오 / 의료 시뮬레이션
  - 멀티피직스 시뮬레이션

**💡****Accelerating Large-Scale Linear Algebra Using Variational Quantum Imaginary Time Evolution**

- - **연구 개요**

    - 혈액펌프는 HPC(수퍼컴퓨터)업계에서도 악명 높은 난제로 알려져 있기 때문에 이를 양자컴퓨터로 테스트함으로써, 양자컴퓨터 성능을 측정하기 위한 테스트베드로 활용하였다.

      - **비뉴턴 유체**: 혈액은 점도가 일정하지 않음 → 수치해석 어려움.
      - **다중 물리 연성**: FEA(구조), CFD(혈류), FSI(상호작용) 모두 필요.
      - **규모가 큼**: 2.6M 노드, 40M 엣지 → 메모리·연산량 모두 폭발적.
      - **해석 병목**: LS-DYNA에서도 그래프 파티셔닝(GPP) 때문에 병목 발생.
    - Ansys와 협업하여 **대규모 선형대수 문제**(FEA, Finite Element Analysis)에서 발생하는 **희소 행렬 분해(LU, Cholesky) 시 Fill-in 최소화**를 위해, 변분 양자 허수 시간 진화(VarQITE)를 활용하는 **하이브리드 양자-고전 알고리즘**을 제안했다.
    - Ansys **LS-DYNA** 소프트웨어에 VarQITE를 통합.
    - 자동차 충돌 해석, 혈액 펌프 시뮬레이션, 차량 진동 해석 등 **6M 노드급 FEA 문제**에 적용.
    - IonQ **Aria** 및 **Forte** QPU에서 실제 실험 수행.
    - 최대 **12% 시간 단축** 성과 달성.

[**Accelerating large-scale linear algebra using variational quantum imaginary time evolution**

The solution of large sparse linear systems via factorization methods such as LU or Cholesky decomposition, can be computationally expensive due to the introduction of non-zero elements, or ``fill-in.'' Graph partitioning can be used to reduce the ``fill-in,'' thereby speeding up the solution of the...

arxiv.org](https://arxiv.org/abs/2503.13128v2)

- - **LS-DYNA**는 **Ansys**에서 제공하는 **범용 유한요소해석(FEA, Finite Element Analysis) 프로그램**

    - **해석 엔진 전체를 의미**
  - **LS-GPart**는 LS-DYNA에 포함된 **그래프 파티셔닝(Graph Partitioning)** 모듈.

    - 그래프 파티셔닝이란 **초대형 해석 모델의 메시(mesh)를 그래프로 변환한 뒤, 이 그래프를 여러 개의 “서브그래프(subgraph)”로 나누는 과정**
    - LS-DYNA 내부에서 **메시(Graph) 분할을 담당하는 핵심 알고리즘** → 이번 연구에서 LS-GPart를 VarQITE로 대체

      - 결과 : Fill-in 최소화 개선 → 총 실행 시(WCT-Wall Clock Time) 12% 단축
      - Fill-in이란 희소 행렬(Sparse Matrix)을 분해할 때 **원래 0이었던 위치에 새로운 비영(非零) 항이 생기는 현상**으로 LS-GPart대신 VarQITE를 사용함으로써 Fill-in을 최소화하였고, 이로인해 .WCT를 줄일 수 있음.
      - Fill-in 최소화를 위한 그래프 파티셔닝
      - Fill-in을 줄이는 핵심 전략은 노드 순서 최적화(Node Ordering)이다. 즉, **어떤 순서로 행렬을 분해하느냐**에 따라 Fill-in 개수가 크게 달라진다.

        - **LS-DYNA의 기존 방식: LS-GPart**

          - 메시(mesh)를 그래프로 변환 → 노드 연결 관계 기반으로 **그래프 파티셔닝** 수행.
          - **목표**: 서브그래프 간 엣지 최소화 → Fill-in 감소.
          - 한계: Blood Pump처럼 초대형 그래프에서는 LS-GPart 최적화가 충분히 안 됨.
        - **IonQ의 접근: VarQITE 기반 QUBO 최적화**

          - 그래프 파티셔닝을 **QUBO(Quadratic Unconstrained Binary Optimization)** 문제로 변환.
          - IonQ Forte에서 VarQITE로 최적화 → **Fill-in 최소화 효과 극대화**.
          - 결과: LDLᵀ 분해에서 필요했던 메모리·계산량 동시 절감 → **WCT 12% 단축**.
  - **이번 실험에서 증명한 것**

    - **양자컴퓨터가 고전적 방법보다 실질적으로 빠를 수 있음을 입증**

      - 최대 **2.6M 노드**, **40M 엣지** 규모 혈액 펌프 시뮬레이션에서 **최대 12% 해석 시간 단축**.

        - 12% 단축의 의미

          - 혈액 펌프 시뮬레이션을 HPC로 수행할 경우 최대 3 ~ 5일 소요되고 이를 반복 시뮬레이션 할 경우 의료 기기 설계 기간에 지연이 발생됨.

|  |  |  |  |
| --- | --- | --- | --- |
| **해석 규모** | **기존 LS-GPart** | **VarQITE 적용 후** | **단축 시간** |
| **단일 Blood Pump** | 72시간 | **63시간** | **9시간 절감** |
| **디자인 10회 반복** | 720시간(30일) | **630시간(26일)** | **4일 단축** |
| **프로젝트 단위** | 6개월 | **5개월 보름** | **수십만 달러 절감** |

- - - **NISQ 장치에서도 실질적인 산업 문제 해결 가능성을 입증** → FTQC에서의 성능 개선은 이미 예견된 것

      - IonQ Forte QPU(36 큐비트)를 사용해 실제 하드웨어에서 테스트.
      - 시뮬레이터가 아닌 **실제 장치에서 얻은 결과가 산업 문제에 적용 가능**함을 증명.
      - 이는 단순 “알고리즘 검증”을 넘어서, **NISQ 장치가 현실적인 산업 최적화 문제에 기여 가능**함을 보여줌.
    - **VarQITE가 QAOA 대비 유리하다는 사실 검증**

      - 기존 **QAOA**는 회로 깊이가 깊어 노이즈에 취약.
      - VarQITE는:

        - 얕은 회로 (O(log N))
        - 2큐비트 게이트 수 최소화
        - 노이즈 강인성 확보
        - → IonQ Forte 같은 **NISQ 장치에서도 안정적으로 성능 발휘 가능**함을 입증.
  - **적용 분야**

    - FEA (**Finite Element Analysis)** — 유한요소 해석
    - **CFD (Computational Fluid Dynamics)** — 전산 유체역학
    - **FSI (Fluid-Structure Interaction)** — 유체-구조 연성 해석

      - 의료기기 설계
      - 자동차, 항공, 우주 구조 해석
      - 에너지 인프라 및 전력망 최적화
      - 물루 공급망 최적화
      - 금융 및 포트폴리오 최적화

**💡****QITE vs VarQITE 성능 비교**

- - **VarQITE가 QITE보다 항상 뛰어난 건 아니다**.
  - **VarQITE** → NISQ 환경에서 **샷 효율·속도 최적화** 필요할 때 강점.
  - **QITE** → 제약조건 많은 문제나 **전역 수렴**이 필요한 문제에서 강점.
  - UC 문제에서는 QITE가 더 적합했고, Blood Pump 문제에서는 VarQITE가 최적 선택이었던 것.

|  |  |  |
| --- | --- | --- |
| **구분** | **QITE** | **VarQITE** |
| **회로 깊이** | 얕음 | 얕음 |
| **샷 효율** | 낮음 | **높음** ✅ |
| **전역 최적 보장** | **강함** ✅ | 약함 |
| **제약조건 처리** | 강점 | 약점 |
| **지역 최소 문제** | 거의 없음 | 가능성 있음 |
| **적합 문제** | UC, MILP, 제약 최적화 | QUBO, 그래프 파티셔닝, 샷 효율 중요한 문제 |

**✅****고전컴퓨팅 리소스 요구사항**

- - VQE, QAOA, QITE/VarQITE/AWQV 등의 알고리즘은 하이브리드 양자-고전 알고리즘이다.
  - 즉, 양자컴퓨터가 **파라미터화된 양자 회로 실행 및 측정**을 담당하고, **고전 컴퓨터**가 그 결과를 받아 **파라미터 최적화**를 수행한다.
  - 여기서 중요한 건 **고전 컴퓨터의 연산 스펙**

|  |  |  |  |
| --- | --- | --- | --- |
| **알고리즘** | **고전 연산 난이도** | **특징** | **산업 적용성** |
| **QAOA** | **높음** | 파라미터 많음, 샷 수↑, 회로 깊음 → HPC 필요 | FTQC 이후 주력 |
| **VQE** | **중간~높음** | 해밀토니안 항 분해 수에 비례, 화학계는 수천 항 가능 | 분자/재료 분야 |
| **QITE** | **낮음~중간** | 연속적 경사하강 기반, 샘플 효율 좋음 | NISQ 친화적 |
| **VarQITE** | **낮음~중간** | QITE의 변분 근사, QUBO 문제 최적 | Blood Pump 등 |
| **AWQV** | **중간** | 초기 QITE, 후반 VQE Gradient 혼합 → 효율적 | MaxCut, UC 등 |

**✅****현재 상황과 미래**

|  |  |  |
| --- | --- | --- |
| **항목** | **QAOA (Quantum Approximate Optimization Algorithm)** | **VarQITE (Variational Quantum Imaginary Time Evolution)** |
| **원리** | 최적화 문제를 **해밀토니안**으로 인코딩하고, p-레이어 심층 회로로 최적해 탐색 | 허수 시간 진화(Imaginary Time Evolution)를 변분적으로 근사해서 바닥 상태(최적해)에 수렴 |
| **회로 깊이** | 깊음 → **O(p)**, 보통 p=20~100 이상 필요 | 얕음 → **O(log N)** 또는 상수 레벨 회로 |
| **2큐비트**  **게이트 수** | 매우 많음 → 노이즈 취약 | 적음 → 노이즈 강인성 높음 |
| **수렴 속도** | 이상적 하드웨어에서 빠르게 최적해 접근 가능 | 얕은 회로에서 안정적으로 수렴, 하지만 이상적 QAOA보다 느림 |
| **샘플 효율** | 샘플링 비용 큼 (해공간 탐색 중심) | 샘플 효율 높음 (연속적인 경사 하강 기반) |
| **하드웨어**  **요구사항** | **FTQC 필요** (오류보정된 수천~수만 큐비트) | **NISQ 친화적** (수십~수백 큐비트에서 동작 가능) |
| **적합한 문제** | 대규모 조합 최적화, 전역 탐색 | NISQ에서 QUBO, 그래프 파티셔닝, Fill-in 최소화 |

**💡****QAOA가 “이론적으로” 더 좋은 이유**

- - QAOA는 p → ∞일 때 아디아배틱 최적화(Adiabatic Optimization)와 수렴적으로 동치가 된다.

    - 즉, 충분히 깊은 회로(p 수십~수백 이상)와 오류보정(FTQC)만 보장되면, QAOA는 거의 완벽한 최적해를 **보장**할 수 있다.
  - 하지만 문제는:

    - 깊은 회로 → 2큐비트 게이트 수 폭발 → **노이즈 취약**
    - p를 줄이면 → 해 품질 급격히 저하 → **실효성 상실**
  - 즉, **QAOA는 이상적 상황에선 최선, 현실 NISQ에선 사실상 불가능**.

**💡****NISQ 한계 때문에 VarQITE 채택**

- - IonQ와 Ansys가 Blood Pump 실험에서 **VarQITE**를 선택한 이유는 딱 두 가지.
  - **얕은 회로 + 노이즈 강인성**

    - Blood Pump 해석 모델은 **2.6M 노드, 40M 엣지** → 매우 큰 QUBO 문제.
    - IonQ Forte(36큐비트)에서 실행해야 하므로 **회로 깊이 최소화**가 필수.
    - VarQITE는 **얕은 회로**로도 허수 시간 진화를 근사 → **노이즈에 강함**.
  - **Fill-in 최소화 특화**

    - Blood Pump 해석에서 **그래프 파티셔닝(GPP)** 성능이 해석 속도(WCT)를 좌우.
    - VarQITE는 QUBO 문제에서 연속적인 경사하강 기반 최적화를 수행 → **Fill-in 최소화 성능 최적화**에 잘 맞음.
  - 결과적으로 IonQ는 VarQITE를 선택해 **WCT 12% 단축**을 달성했음

**💡****하드웨어가 발전하면? (QAOA 재등장 가능성)**

- - 앞으로 큐비트 수↑, 오류율↓이 되면 상황이 달라진다.

|  |  |  |
| --- | --- | --- |
| **하드웨어 단계** | **VarQITE** | **QAOA** |
| **현재 NISQ (~50논리큐비트)** | ✅ 최적 선택 | ❌ 회로 깊이 제한으로 불가능 |
| **중간 단계 (~500논리큐비트, 오류↓)** | 여전히 유리 | 부분적으로 가능(p=10~20 제한) |
| **FTQC (수천~수만 논리 큐비트)** | 보조적 역할 | ✅ **최강 옵션**으로 부상 |

- - 즉, 현재는 VarQITE가 최선이지만, 오류보정 시대(FTQC)가 오면 QAOA가 다시 주력 후보가 될 가능성이 높다.

|  |  |  |
| --- | --- | --- |
| **문제 유형** | **현재(NISQ)** | **FTQC 시대** |
| **화학·재료·전자구조** | VQE 변종(Adaptive VQE, Hardware-efficient ansatz) | **QPE(Quantum Phase Estimation)** → 정확도 보장 |
| **조합 최적화** | QITE/VarQITE/AWQV 주력 | **깊은 QAOA**로 전환 가능 |
| **산업 해석(FEA, CFD, Blood Pump 등)** | VarQITE 등 얕은 회로 하이브리드 | **양자선형계해법 QLSA(Quantum Linear Solver)** 적용 가능 |

- - 지금 → VQE는 화학·양자물리 문제 중심, QITE 계열이 최적화 문제 중심
  - **FTQC → 화학계는 QPE, 최적화는 QAOA, 선형계는 QLSA, 병렬 유동 시뮬레이션은 QLBM이 주력으로 바뀜**
