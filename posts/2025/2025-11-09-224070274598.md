# 도대체 IonQ의 포부는 얼마나 큰거야? (ESP - Entanglement Service Provider)

Published: 2025-11-09T22:20:36.485000+09:00

**✅ 양자 인탱글먼트 인터넷을 설계한 특허: 2030년 양자 네트워크의 청사진**

- - 오늘은 “인탱글먼트를 인터넷처럼 배포하는 네트워크 아키텍처”를 정의한 특허를 살펴본다.
  - 한마디로 요약하면:

> **이 특허는 양자 인터넷의 ISP 모델 전체를 설계해 놓은 로드맵이다.**

- - 현재 IonQ, Quantinuum, Infleqtion(ColdQuanta), Qunnect, Cisco, Aliro 등이 추진하는 양자 네트워크 전략과 매우 정확하게 맞물린다는 점에서 의미가 크다.

**🎯 왜 이 특허가 중요한가?**

- - 양자 인터넷은 보통 “미래 기술” 정도로만 이야기된다.
  - 하지만 이 특허는 질문을 정반대로 던진다.

> **“양자 인터넷을 진짜 서비스로 팔려면, 어떤 구조를 만들어야 하는가?”**

- - 이런 류의 특허는 매우 드물다.
  - 기초 과학이 아니라 **사업 모델–네트워크 인프라–프로토콜–서비스 모델**이 포함돼 있기 때문이다.
  - 즉, *인탱글먼트 생산 → 백본 전송 → 고객 라우팅 → SLA → QPU 서비스*까지 풀스택으로 정의한 설계도다.

---

**🧩 Part 1. 인탱글먼트 프로바이더(ESP)의 등장**

- - 특허는 명확하게 말한다.

> **향후 인탱글먼트는 “서비스로 전달되는 자원”이 된다.**

- - ISP가 고객에게 IP 패킷을 제공하듯,
  - ESP는 고객에게 EPR Pair를 제공한다.

**💡** **ESP(Entanglement Service Provider)가 제공하는 기본 서비스**

|  |  |
| --- | --- |
| **서비스** | **설명** |
| 인탱글먼트 전송(EPR delivery) | 광자 쌍을 생성해 고객 노드에 전달 |
| 인탱글먼트 라우팅 | 중계 노드를 통해 장거리 얽힘 확장 |
| 인탱글먼트 스와핑 | A↔D 장거리 얽힘 생성의 핵심 |
| 양자 메모리 풀 | 필요 시 entanglement buffer(SR, NR, DR) 제공 |
| 알고리즘 모듈 서비스 | QFT, CNOT, Phase op, BSM 등을 API처럼 제공 |
| 블라인드 양자 계산(BQC) | 고객의 계산 내용을 숨긴 채 연산 |

---

**🧩 Part 2. 네트워크 구조: 인터넷과 거의 동일**

- - 특허에서 가장 놀라운 부분은 구조다. 그냥… 인터넷이다. 네이밍만 다를 뿐.
  - **고객 엔드포인트 (Customer Endpoint)**

    - Fiber Access Modem
    - 인탱글먼트 측정기
    - classical authenticated 채널
    - 고객은 EPR을 받아서:

      - QKD (양자키)
      - distributed QPU
      - BQC(블라인드 계산)
      - secure ID
    - 등을 수행할 수 있다.
  - **중간 노드 (Intermediate Node, IN)**

    - 완전한 양자 라우터.

      - 인탱글먼트 스와핑
      - 메모리
      - classical control plane
      - routing module
    - 특허 문구 그대로다. “IN은 next-hop을 결정한다.”
    - 즉, **양자 라우팅 프로토콜(QRP)의 실제 구조**를 거의 다 설명하고 있다.
  - **리피터 & EPR Source**

    - 광섬유 or free-space 광자
    - dual-frequency 가능
    - 위성·지상국 + fiber 하이브리드 링크
    - 2024년 DARPA·DOE가 추진 중인 장거리 인탱글먼트 체계와 1:1로 대응.

**💡****핵심 포인트 6가지**

1. 1. **서로 다른 Quantum Hardware Provider (210, 212, 214)**

      - IonQ, Quantinuum, Infleqtion, ORCA 같은 업체들이 여기에 해당됨.
   2. **각 Provider가 Intermediate Node(IN)를 포함**

      - 각 IN은 얽힘 스와핑/저장/연결 수행.
   3. **Service Provider Network 내부에 Quantum Endpoint(206)가 존재**

      - 데이터센터 출발점.
   4. **중간 노드를 거쳐 고객에게 얽힘이 전달**

   5. **고객 단에는 두 종류**

      - Fiber-accessible endpoint (226)
      - Quantum device/computer (230, 232)
   6. **Trusted Locations vs Trust-free Region(218)**

      - 고객 IDC, AWS 리전, Telco core는 Trusted
      - ISP backbone이나 서브넷, 케이블은 Trust-free

- - 이 그림은 2A와 거의 동일해 보이지만 **중요한 한 가지가 다르다:**

    - **Trust-Free Region 258/260이 훨씬 더 넓음**
  - 즉:

    - 고객 장비 자체도 trust-free region에 들어갈 수 있음
    - 고객 데이터센터 일부도 trust-free
    - 심지어 intermediate node들이 전부 서로 신뢰 불가능
  - 그럼에도 불구하고 **얽힘 기반 보안으로 end-to-end 신뢰가 유지된다**는 구조를 특허화했다.
  - 이는 일반 QKD가 절대 제공할 수 없는 모델.
  - QKD는 중간 노드를 반드시 신뢰해야 한다.
  - 특허의 혁신은 바로:

> **"Trustless repeater network"**
>
> 즉, **중간 노드를 해킹해도 전체 얽힘 분배가 깨지지 않는 구조**.

**✅ FIG. 3 — “고전 채널을 이용한 얽힘 측정/전송 흐름도”**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMDlfMjYz/MDAxNzYyNjkwOTE1NjM5.K4x_QVfnu1a6b_v-FBE0zJttxLsKnLAB3AVmbOp7JRsg.687fKaQGQAwxAecJs1O8oQDYKZzSRUEvjWxhg-IX7sYg.PNG/SE-cff52bc9-0a7c-4163-b39f-ce6f8e87f67a.png?type=w800)](#)

- - 이 그림은 **얽힘이 고객에게 전달되는 기본 경로(flow) 시나리오**를 보여준다.
  - 특히 신호 흐름은 두 종류:

    - **양자 채널(Entangled Particle)**
    - **고전 채널(Entanglement Measurement Communication)**
  - 두 개가 결합해서 텔레포테이션이나 blind QC가 가능해진다.

**💡 구성 요소 설명**

- - **Entangled Particle Source Node (314, 316)**

    - 얽힌 광자 쌍(EPR Pair) 생성기.
    - 이 장비가 “얽힘 공급자(Entanglement Producer)” 역할.
    - 광자 한쪽은 왼쪽 고객에게, 다른 한쪽은 오른쪽 리피터로 전달.
  - **Fiber Link**

    - 얽힌 광자를 전송하는 물리 경로.
    - 손실이 많기 때문에 리피터가 필요.
  - **Quantum Repeater Blocks (302)**

    - 리피터는 내부에 3개 모듈이 있음:

|  |  |
| --- | --- |
| **모듈** | **기능** |
| **Measurement Communication 304** | Bell-state 측정 결과를 classical channel로 전송 |
| **Entanglement Measurement 306** | joint measurement 수행 (collapse-free 구조 포함) |
| **Quantum Memory 308** | 한쪽 광자를 저장하여 시간 동기화 |

- - 리피터는 얽힘을 "증폭"하는 장치가 아니라 **끊긴 얽힘을 다시 이어 붙이는 장치**다.
  - **Classical Communication Channel (324, 322)**

    - Bell-state measurement 결과를 고객에게 전달.
    - 텔레포테이션에 반드시 필요.
    - 고전 채널은 "동기화 정보" 제공.
  - **Customer Endpoint (312, 320)**

    - 얽힘 광자를 받아 실제 통신/계산에 사용.
    - 고객 쪽 장비는 반드시 양자 장비일 필요 없음
    - (특허는 classical→quantum 변환 장치 포함).

> **얽힘 분배에는 반드시 두 채널이 필요하며, 리피터는 광자를 실제로 “측정하지 않고” 얽힘을 이어 붙일 수 있는 방식으로 동작****한다.**
>
> 이게 이 특허의 중요한 부분:
>
> 기존 이론적 논문에서는 collapse-free repeater가 있었지만 **실용적인 전체 시스템으로 특허화된 것은 매우 드물다.**

- - **Satellite (402)**

    - 우주에서 양자 광자를 보내는 광학 송신기.
    - 현재 NASA, 중국 Micius, CSA, EU Quantum Space가 연구 중인 구조와 동일.

**💡 구성 요소 설명**

- - **Quantum Memory (502)**

    - 얽힌 광자의 한쪽을 저장하는 장치.
    - 여기서는 **rare-earth doped crystal**이나 **NV센터**, **SiV**, **Eu:Y2SiO5** 같은 매질을 암시.
    - 그림의 오른쪽 원(Si)로 표시된 “Single Quantum Memory(510)”는 NV center/SiV center 구조를 의미.
  - **Superposition Particle Storage (506)**

    - 얽힌 광자가 superposition 상태 그대로 보관됨.
    - collapse되지 않음(핵심).
  - **Photonic Interface (508)**

    - 광자 <-> 원자계 변환 인터페이스.
    - QFC(Quantum Frequency Conversion) 포함.
  - **A/B Interface (504)**

    - 외부에서 들어오는 얽힌 광자(A/B)를 받아 내부로 보냄.
  - **Quantum Measurement Device (512)**

    - joint measurement (Bell-state-like) 수행
    - 하지만 특허의 포인트는:
    - **측정 결과를 classical로 보내지만, 얽힘 자체는 collapse되지 않음.**
  - 이는 “non-destructive Bell measurement” 또는 “entanglement swapping without full collapse” 기술을 의미.

**🧩 Part 3. 인탱글먼트 배포 시나리오 (Fig. 6–11)**

- - 도면들은 모두 현실성 높은 3가지 시나리오를 그린다.

**💡 1. 고객 → 서비스 제공자 (Customer → Provider Resource)**

- - 고객이 ESP의 데이터센터 리소스와 얽힘을 공유한다.
  - 즉,

    - 분산 QPU
    - 양자 RNG 서버
    - 양자 인증 서버
    - 보안 모듈
  - 과 연결되는 모델.
  - 👉 **양자 클라우드(Quantum Cloud Connect)의 핵심 구성.**

****

**💡 2. 고객 ↔ 고객 (Customer ↔ Customer)**

- - 양자 VPN / 보안 링크.
  - 예:

    - 고객 A가 고객 B와 QKD 수행
    - 분산 알고리즘에서 원격 노드 간 공유
  - 👉 **기관 간 통신(국방/금융)에 바로 적용 가능.**

****

**💡 3. 원격 고객↔고객 (Remote Distributed Entanglement)**

- - 여기서 위성이 등장한다:

    - 인탱글먼트 위성 소스
    - 지상국(Optical Ground Station)
    - fiber 노드로 hand-off
  - 👉 *유럽의 Eagle-1, 캐나다의 QEYSSat, 미국의 Space Entanglement 프로그램과 구조가 동일.*

**✅ FIG. 9 — Customer → Service Provider Distributed Entanglement (원거리 ↔ DC)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMDlfMTYx/MDAxNzYyNjkyODcwOTMw.1hu97X4LWrdMVyw7f_wzHlINv9uCyYBOEJQcOTtYhIwg.C13wKqeQYgpZ8USJXX_T6AwiBdGJLuW7_1ez8PtSEJcg.PNG/SE-8895cb3b-b26c-4960-a1d3-7f59a08e7a15.png?type=w800)](#)

- - 핵심은:

> **“그 고객이 지역에 있지 않아도, 얽힘을 스왑하여 원거리 DC까지 연결해주는 구조”**

- - 즉 “원거리 고객에게 DC 얽힘 전달”.

**🧩 Part 4. 인탱글먼트 스와핑 (Fig. 12)**

- - Fig. 12는 스와핑 과정을 “초등학생도 이해할 수 있게” 시각화한 도면이다.

**✅ FIG.12 — Entanglement Swapping 동작 원리 (단일 노드 버전)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMDlfNzMg/MDAxNzYyNjkyODczOTA5.N1suYaK1ppvlgr1PFtzUPxc2R2DsA0WlFP5BaBRkky8g.PxrFEApgh172rwpXGmlANCPWMHSX162-H-o89j7GUvgg.PNG/SE-e4f919d4-7d62-4f02-9195-0cf899f18ab9.png?type=w800)](#)

- - FIG.12는 전체 시스템의 “수학적/물리적 핵심 원리”를 보여준다.
  - 즉 **entanglement swapping**.
  - 그림 순서를 정리하면:
  - **Step 1**

    - A-B, C-D
    - 두 쌍(A–B, C–D)이 각각 얽혀 있다.
    - 이 상태에서는 A↔D가 얽혀 있지 않음.
  - **Step 2**

    - 중간 노드가
    - B와 C에 대해 Bell-State-like measurement을 수행한다.
    - 그림에서 “opposite”, “±1”이라고 표시된 곳은
    - 결과가 classical로 전달되어야 한다는 의미.
  - **Step 3**

    - 측정 결과에 따라 (classical correction)
    - A와 D가 얽히게 된다.
  - **Step 4**

    - A ↔ D 쌍이 원래 한 번도 직접 만난 적이 없지만
    - entanglement swapping 덕분에 완전히 얽힘 상태가 된다.
    - 이 원리를
    - 수백 km 지상 광자 패스
    - 위성 + 지상국
    - 다중 데이터센터
    - 고객 ↔ 고객
    - 등에 반복 적용한 것이 특허 전체 네트워크다.
  - **FIG.12의 메시지**

> “중간 노드를 신뢰하지 않고도,
>
> 반복적인 entanglement swapping으로 초장거리 end-to-end 양자 연결을 만들 수 있다.”

**✅ FIG. 14 — Blind Quantum Computation on Distributed Entanglement**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMDlfMTky/MDAxNzYyNjkyODY5NTAz.Pft02d6ZY_c9bVYByKJIycPvmgjhZ7D1HlZOOJS8GoUg.uzwtUsyX16ZKF32Kso8CBsdSobkgHw52MSHAEZ1GuJMg.PNG/SE-32610573-73e4-4a95-ada5-dbe2f47c6a76.png?type=w800)](#)

  - 이 그림은 매우 중요하다.
  - IonQ 특허 전체의 핵심 중 하나:

> **원격 얽힘을 이용한 Blind Quantum Computing(BQC)**

  - **Classical CPU Device 1406**

    - 측정 결과를 로컬에서 처리.
    - Blind QC를 위해 필요한 고전 계산 수행.
  - **U1, U2, …, Uk 계산**

    - 이것은 회로 실행에서 필요한 “대상 게이트”들을 classical로 정리하는 과정.
  - **Classical Network 132**

    - 정제된 연산 명령(U1~Uk)만 클라우드로 보내는 구조.
  - 중요 포인트:

> **클라우드는 고객이 어떤 알고리즘을 수행하는지, 어떤 입력을 사용하는지 알 수 없다.**

- - Quantum Compute Resources 204 안에는:

    - QPU: Generic Blind Quantum Circuit 1402
    - Unitaries U1, U2…Uk
    - Random rotations R1, R2…Rj
  - Blind QC의 핵심은 **클라우드가 “랜덤한 회전 R”을 삽입하기 때문에 고객의 실제 연산을 추정할 수 없게 된다**.

> **얽힘 네트워크 위에서 Blind QC까지 제공할 수 있는 완전한 양자 클라우드**
>
> **원격 고객이 자신의 QPU를 “탈중앙화 / 프라이버시 유지” 상태로 사용할 수 있음**
>
> **고객 장비가 classical device여도 가능**
>
> **클라우드는 신뢰되지 않아도 됨(trust-free quantum computation)**
