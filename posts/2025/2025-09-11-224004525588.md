**✅****Microsoft Quantum 소프트웨어 구성 요소**

**💡****Q# 프로그래밍 언어**

- - Q#는 Microsoft가 개발한 양자 알고리즘 전용 도메인 특화 언어이다. C#·F#·Python에서 영향을 받았으며, 강한 타입 검사 및 정적 타입 시스템을 특징으로 한다
  - Q#는 양자 알고리즘의 작성과 시뮬레이션에 최적화되어 있으며, 양자 게이트, 제어 흐름, 측정 등의 기능을 지원한다 .
  - 2023년에는 QIR(Quantum Intermediate Representation)을 도입하여, 다양한 프로그래밍 언어와 양자 프로세서 간 통합 인터페이스 역할을 한다 .

**💡****Quantum Development Kit (QDK)**

- - QDK는 오픈 소스 기반의 크로스 플랫폼 프레임워크로, 개발자가 Q#로 알고리즘을 작성하고, 시뮬레이터 또는 양자 하드웨어에서 실행·디버그할 수 있게 돕는다 .
  - 시뮬레이터는 최대 40 큐빗까지 시뮬레이션 가능하다는 연구 논문도 있다.

**💡****Azure Quantum 플랫폼**

- - Azure Quantum은 Microsoft가 제공하는 클라우드 기반 양자 컴퓨팅 플랫폼이다. QDK, Q#, 시뮬레이터, 그리고 다양한 파트너의 양자 하드웨어(Quantinuum, IonQ, Atom Computing 등)를 하나로 통합해 제공한다 .
  - Azure Quantum에는 리소스 추정 도구(Resource Estimator), Azure Quantum Elements(화학·재료·제약 분야용 AI + 고성능 컴퓨팅 통합 플랫폼), Generative Chemistry, Accelerated DFT 같은 기능이 포함되어 있다 .

**💡****Azure Quantum Elements**

- - Azure Quantum Elements는 AI, HPC, 양자 도구를 결합해 화학 및 재료 과학, 제약 분야에 적용하는 플랫폼이다. 예: 2024년 배터리 소재 후보 3,200만 건을 스크리닝한 사례.
  - 2024년 7월에는 Generative Chemistry와 Accelerated Density Functional Theory 도구가 공개되었다 .

**💡****Quantum Coding with Copilot**

- - 브라우저 기반의 무료 툴로, 양자 코드를 작성하고 실행·시뮬레이션하며, GPT-4 기반의 Copilot으로부터 기술·가이드 도움을 받을 수 있다.

**✅수퍼컴퓨터와 양자컴퓨터와의 교량 역할**

**💡****QIR(Quantum Intermediate Representation)의 역할**

- - QIR은 **양자 프로그래밍 언어와 하드웨어를 잇는 공통 인터페이스**로 설계한다.
  - LLVM 기반의 오픈소스 중간 표현(intermediate representation, IR)로 개발되어,
  - 다양한 언어(Q#, Python, C++, Qiskit 등)에서 작성된 양자 알고리즘을 지원한다.
  - 서로 다른 양자 하드웨어 및 시뮬레이터에 쉽게 매핑할 수 있게 한다.
  - QIR은 양자·고전 하이브리드 연산을 자연스럽게 표현할 수 있는 것이 특징이다.
  - QIR은 향후 광범위한 소프트웨어 생태계를 구축하는 핵심 기반이 된다.

**💡****DOE 협력 및 NQI(국가 양자 이니셔티브) 프로젝트**

- - Microsoft는 **미국 에너지부(DOE)** 산하 NQI(National Quantum Initiative)와 협력해 QIR을 실제 연구 환경에 적용한다.
  - **PNNL 시뮬레이션 프로젝트**

    - **목표**: 잡음성 큐빗(noisy qubit)이 **VQE(Variational Quantum Eigensolver)** 알고리즘 정확도에 미치는 영향 측정
    - **방법**:

      1. Q#로 VQE 알고리즘을 작성한다.
      2. QIR을 통해 Q# 알고리즘을 초컴퓨터 시뮬레이터용 표현으로 변환한다.
      3. ORNL(오크리지 국립연구소)의 **Summit 슈퍼컴퓨터**에서 시뮬레이션한다.
    - **결과**: 고전 슈퍼컴퓨터에서 대규모 양자 알고리즘을 실행하고 분석하는 데 성공한다.
  - **ORNL 통합 프레임워크**

    - ORNL은 Q#과 QIR을 자체 양자 컴퓨팅 프레임워크에 통합한다.
    - 이를 통해 ORNL 연구원들은 Q# 코드로 작성된 알고리즘을 다양한 타깃(시뮬레이터 및 실험용 양자 하드웨어)에서 실행할 수 있다.
    - ORNL은 QIR 기반 언어 독립적 양자 최적화(quantum optimizations)를 개발 중이다.
    - 예: Q#, Qiskit, Cirq 등 언어와 무관하게 작동하는 컴파일 최적화 기술

**💡****Q# + QIR + 슈퍼컴퓨팅 융합 전략**

- - Microsoft의 비전은 “클래식 HPC + 양자 QPU”의 통합이다.

    - QIR 덕분에 **슈퍼컴퓨터 시뮬레이션**과 **양자 알고리즘**을 매끄럽게 연결할 수 있다.
    - PNNL은 Q# + QIR을 사용해 ORNL Summit 슈퍼컴에서 VQE를 실행했다.
    - ORNL은 QIR을 도입해 양자 시뮬레이터와 실험용 하드웨어를 모두 단일 프레임워크에서 지원한다.
    - DOE 산하 4개 국립연구소, 3개 산업 파트너, 9개 대학이 QIR을 통해 공동 개발 환경을 공유한다.

**💡****QIR의 LLVM 기반 아키텍처 장점**

- - LLVM을 기반으로 하므로 기존 HPC·클래식 최적화 도구와 통합이 쉽다.
  - 기존 컴파일러 최적화 패스(pass)를 재활용할 수 있다.
  - 다양한 백엔드(시뮬레이터, 실제 QPU, 하이브리드 환경)에서 동일한 IR을 사용할 수 있다.
  - 커뮤니티가 오픈소스 생태계에서 QIR 최적화 및 코드 변환을 개발할 수 있다.

**💡****QDK(Q# Development Kit) 시각화 및 툴 혁신**

- - **Quantum Program Visualization**

    - Microsoft는 QDK에 양자 프로그램 시각화 툴을 추가한다.
    - 알고리즘 실행 흐름을 단계별로 시각화해 디버깅을 돕는다.
    - 연구자뿐만 아니라 초보자에게도 교육적 가치가 있다.
  - **Density Matrix Simulator**

    - PNNL 연구진이 **GPU 클러스터 기반 밀도행렬 시뮬레이터**를 개발했다.
    - BSP 기반 가상 머신을 구성하여 병렬성을 극대화한다.
    - 기존 상태벡터(state-vector) 시뮬레이터 대비 **10배 이상 빠른 성능**을 보인다.

**✅****LLVM (Low Level Virtual Machine)이란?**

**💡****LLVM 개념과 철학**

- - LLVM은 원래 “**Low Level Virtual Machine**”의 약자였으나, 현재는 이름 그대로의 의미를 벗어나 **범용 컴파일러 인프라스트럭처 프로젝트**를 의미한다.
  - **1.1 LLVM의 정의**

    - LLVM은 **프로그래밍 언어 → 하드웨어** 사이의 중간 계층(Intermediate Representation, IR)을 제공하는 **컴파일러 프레임워크**이다.
    - 특정 언어(C, C++, Rust, Swift, Q# 등)에 종속되지 않고, 특정 하드웨어(CPU, GPU, FPGA, QPU 등)에도 독립적이다.
    - 따라서, LLVM은 “언어 비종속 + 타깃 비종속”을 핵심 철학으로 한다.
  - **1.2 설계 목표**

    - **언어 중립성(Language-agnostic)** → Q#, Python, C++, Swift 등 다양한 언어를 지원한다.
    - **타깃 중립성(Target-agnostic)** → x86, ARM, GPU, DSP, TPU, QPU 등 하드웨어와 독립적이다.
    - **재사용성(Modularity)** → 프런트엔드(front-end), 백엔드(back-end), 최적화(optimizer) 레이어를 독립적으로 교체 가능하다.
    - **최적화 중심** → 다양한 최적화 패스(pass)를 통해 프로그램 실행 효율을 높인다.

**💡****LLVM 내부 아키텍처**

- - LLVM의 핵심은 **3단계 컴파일 파이프라인**이다.
  - **Frontend (프런트엔드)**

    - **역할**: 고수준 언어 → **LLVM IR** 변환
    - 예시:

      - Clang → C/C++/Objective-C를 LLVM IR로 변환
      - Rustc → Rust를 LLVM IR로 변환
      - Swiftc → Swift를 LLVM IR로 변환
      - Q# Compiler → Q#을 LLVM IR 기반 QIR로 변환
    - 출력물: **LLVM IR(중간 표현)**
  - **LLVM IR (Intermediate Representation)**

    - LLVM IR은 LLVM의 핵심이며, **3가지 형태**로 표현한다.

|  |  |  |
| --- | --- | --- |
| **형태** | **특징** | **용도** |
| **LLVM IR Text** | 사람이 읽기 쉬운 SSA 기반 어셈블리 | 디버깅, 분석 |
| **LLVM IR Bitcode** | 바이너리 포맷 | 컴파일 캐싱, 전송 |
| **LLVM IR In-memory** | 메모리 내 객체 모델 | 컴파일러 내부 연산 |

- - **Optimizer (최적화기)**

    - **역할**: LLVM IR을 분석하고 최적화한다.
    - 특징:

      - 200개 이상의 패스(pass)가 존재한다.
      - 예시: 인라이닝(inlining), 루프 전개(loop unrolling), 데드 코드 제거(DCE), 벡터화(vectorization)
    - 사용자 정의 최적화 패스도 추가 가능하다.
    - **QIR에서 Microsoft가 사용하는 부분**:

      - VQE, QAOA 등 양자 알고리즘의 게이트 수와 노이즈 민감도를 최소화하기 위한 **양자 전용 최적화 패스**를 작성 가능하다.
  - **Backend (백엔드)**

    - **역할**: 최적화된 LLVM IR → 타깃별 기계어 코드 생성
    - 지원 타깃:

      - CPU: x86, ARM, RISC-V, PowerPC 등
      - GPU: NVIDIA PTX, AMD GCN, SPIR-V
      - FPGA, DSP, TPU 등
      - **QPU (양자 프로세서)** → **QIR을 통해 매핑**
    - QIR은 LLVM 백엔드 구조를 그대로 차용하되, QPU 명령 세트에 맞게 확장한다.

**💡****QIR(Quantum Intermediate Representation)과 LLVM의 관계**

- - Microsoft는 LLVM 아키텍처를 그대로 활용해 QIR을 개발했다.
  - 즉, QIR은 LLVM IR 위에 양자 연산 모델을 얹은 **확장 계층**이다.
  - **QIR에서 LLVM의 장점 활용**

    - LLVM의 **SSA 구조** → 큐빗 상태 추적 및 게이트 적용을 최적화 가능
    - LLVM의 **패스 시스템** → QAOA/VQE 등 특정 알고리즘에 맞는 최적화 삽입 가능
    - LLVM의 **멀티 타깃 백엔드** → 동일한 Q# 코드로 여러 하드웨어에 배포 가능
  - **예시: Q# → QIR 변환 과정**

    1. 개발자가 Q#로 VQE 알고리즘 작성
    2. Q# Compiler가 LLVM 프런트엔드 역할 수행
    3. QIR로 변환 → LLVM IR 기반 SSA 구조
    4. 최적화 패스 적용
    5. 백엔드를 통해:

       - 시뮬레이터 실행 (예: Summit 슈퍼컴)
       - 실제 QPU 실행 (예: Quantinuum, IonQ, Azure Quantum)
  - **3.3 Microsoft-DOE 협력 시나리오 예시**

    - **문제**: 잡음성 큐빗이 VQE 결과에 미치는 영향 분석
    - **과정**:
    - Q# 작성 → QIR 변환 → LLVM Pass 기반 최적화
    - Summit 슈퍼컴퓨터에서 시뮬레이션
    - 노이즈 모델과 파라미터 최적화 자동화
    - **결과**: 기존 시뮬레이션 대비 10배 이상 속도 향상

**✅****QIR (Quantum Intermediate Representation)이란?**

**💡****QIR의 정의**

- - QIR은 Microsoft가 개발한 **양자 프로그램을 표현하기 위한 중간 표현(intermediate representation)** 이다.
  - QIR은 오픈소스 LLVM IR 언어를 기반으로 하며, LLVM에 대한 어떠한 확장(extension) 또는 수정(modification)을 요구하지 않는다.
  - QIR은 단지 **양자 구성요소(quantum constructs)** 를 LLVM 상에서 표현하기 위한 규칙(rule set)이다.

**💡****QIR의 목적과 철학**

- - 여러 프로그래밍 언어(source language)들과 다양한 양자 컴퓨팅 플랫폼(target) 사이의 **공통 인터페이스(common interface)** 역할을 한다.
  - 언어 종속이 아니고 Q#에만 한정된 것이 아니다. gate-based quantum computing(게이트 기반 양자 컴퓨팅)이 가능한 어떤 언어도 QIR로 표현할 수 있다.
  - 하드웨어-비종속성(hardware-agnostic)이 핵심이다: QIR은 특정 양자 명령어 집합(gate set)을 미리 정하지 않는다. 타깃 컴퓨팅 환경(target environment)이 정하는 바에 따르게 한다.
  - 양자와 고전(classical) 계산의 통합(integration)을 완전하게 묘사할 수 있도록 설계한다. 즉 양자 알고리즘만이 아니라, 조건 분기(conditionals), 루프, 고전적 제어 흐름(classical control flow) 등이 모두 가능하다.

**💡****QIR 구조 및 예시**

- - QIR은 LLVM IR과 매우 유사하게 보인다. 코드의 구조, 문법, 제어 흐름 등이 LLVM IR의 것과 유사하다.
  - 예시: Q# 코드로 Bell Pair (벨 상태) 만드는 연산(operation)을 작성 → QIR로 변환된 모습.
  - Q# 코드:

operation BellPair(qb1 : Qubit, qb2 : Qubit) : Unit
{
H(qb1);
CNOT(qb1, qb2);
}

- - QIR 코드 예:

define void @BellPair\_\_body(%Qubit\* %qb1, %Qubit\* %qb2) {
entry:
call void @\_\_quantum\_\_qis\_\_h(%Qubit\* %qb1)
call void @\_\_quantum\_\_qis\_\_cnot(%Qubit\* %qb1, %Qubit\* %qb2)
ret void
}
``` :contentReference[oaicite:9]{index=9}

- - 여기서 특징:
  - %Qubit\* 타입은 opaque 구조체(불투명한 구조체) 포인터 타입이다. ‒ 큐빗을 LLVM 타입 시스템 안에서 표현한다.
  - \_\_quantum\_\_qis\_\_h 또는 \_\_quantum\_\_qis\_\_cnot 같은 함수 이름은 **양자 명령어 집합(quantum instruction set, qis)** 을 나타내며, 예약된 네임스페이스(reserved names)로 사용한다.

**💡****QIR로 할 수 있는 것들**

- - QIR은 기존의 **클래식 컴파일러 도구체인(LLVM tool chain)** 과 통합 가능하다. 예를 들어, Clang을 사용하여 QIR을 읽고 처리해서 고전적 타깃(classical target)의 실행 코드(executable)로 변환할 수 있다. 이 경로를 통해 양자 연산 명령어 함수들을 시뮬레이터(such as C/C++)로 구현 가능하다.
  - 표준 LLVM “pass” 인프라를 활용해 **양자-언어 및 양자-하드웨어 독립적 최적화(optimizers and code transformations)** 를 작성할 수 있다.
  - 커뮤니티 및 연구기관과 협력하여, 언어 독립적이고 백엔드 독립적인 최적화나 변환을 체계적으로 개발할 수 있다. 예: ORNL 및 XACC 프레임워크와의 통합 사례 언급됨.

**💡****기술적/생태계 측면의 구현 사항 열린 요구사항(open items)**

- - 현재 QIR은 **초안(draft)** 형식의 명세(specification)가 공개되어 있다. 사용자 의견(issue)을 받아 명세를 개선해 간다.
  - Q# 컴파일러 레포지토리(repository)에 QIR을 생성하는 컴파일러 확장(extension)이 공개되어 있다. 사용 지침도 함께 제공됨.
  - 기여 가이드(contribution guide)가 있으며, QIR 명세 리포지토리에 이슈(issue) 제안 가능하다.

**💡****QIR의 한계와 고려 사항**

- - QIR은 gate-based 양자 컴퓨팅 양식(gate-based quantum computing)에 맞춘 표현이다. 다른 양자 컴퓨팅 모델 (예: 애니힐레이션, 토폴로지컬 양자 컴퓨팅 등)에는 기본적으로 적합하지 않을 수 있다.
  - 특정 하드웨어 명령어 집합(gate set), 노이즈 모델, 하드웨어 제약(hardware constraints) 등은 QIR 명세에 포함되지 않으므로, 하드웨어별 구체적인 확장이나 후처리(post-processing)가 필요하다.
  - QIR을 사용하는 최적화 혹은 백엔드 구현의 품질이 전체 성능 및 정확성에 크게 영향을 준다. 예컨대, 큐빗 수가 많거나 노이즈가 있는 환경에서는 적절한 최적화와 노이즈-에러 모델이 중요하다.

**✅****Q# vs QIR 차이점**

|  |  |  |
| --- | --- | --- |
| **구분** | **Q#** | **QIR** |
| **정의** | Microsoft가 개발한 **양자 프로그래밍 언어** | LLVM 기반의 **양자 프로그램 중간 표현(Intermediate Representation)** |
| **역할** | 사람이 읽고 작성하는 **고수준 언어(High-Level Language)** | Q# 및 다른 언어에서 작성한 코드를 하드웨어·시뮬레이터에서 실행 가능하도록 변환하는 **중간 계층** |
| **표현 수준** | **알고리즘 레벨**: VQE, QAOA, Shor, Grover 등 논리적 연산 설계 | **게이트·연산 레벨**: Q#, Qiskit, Cirq 등에서 작성한 알고리즘을 SSA 기반 명령어 시퀀스로 변환 |
| **언어 종속성** | Q# 전용 | QIR은 Q#뿐 아니라 Qiskit, Cirq, PyQuil 등 **모든 게이트 기반 언어 지원 가능** |
| **하드웨어 종속성** | Azure Quantum과 통합돼 있으나, 다른 플랫폼에는 직접적 매핑 어려움 | **하드웨어 비종속** → QIR 백엔드를 통해 IonQ, Quantinuum, Rigetti, Atom Computing 등 다양한 QPU 지원 가능 |
| **표현 방식** | Q# 전용 문법: 함수, 제어문, 조건문, 루프, 게이트 호출 등 | LLVM IR 기반 SSA(Static Single Assignment) 형식, 명령어 기반 표현 |
| **사용 대상** | 양자 알고리즘 설계자, 개발자 | 컴파일러, 런타임, 최적화 엔진, 시뮬레이터, 하드웨어 드라이버 |
| **목적** | 양자 알고리즘을 쉽게 작성 | Q# 및 다른 언어로 작성된 프로그램을 **하드웨어·시뮬레이터로 매핑** |

**💡****Q# - 고수준 언어(High-Level Quantum Programming Language)**

- - Frontend 역할
  - 마이크로소프트에서 개발한 **양자 알고리즘 전용 언어**이다.
  - C#·F#·Python 영향을 받아 익숙한 구조를 제공한다.
  - 추상화 수준이 높아서 양자 게이트 단위보다는 **알고리즘 단위**로 코드를 작성한다.
  - 개발자가 **논리적 알고리즘**을 Q#으로 직접 작성한다.
  - 하드웨어별 게이트 세부 구현은 신경 쓸 필요 없다.

**💡****QIR - LLVM IR을 확장한 포맷**

- - IR 계층
  - Q#뿐 아니라 Python+Qiskit, CIRQ, PyQuil 등에서도 동일하게 사용 가능하다.
  - **LLVM 기반 IR로 변환해 하드웨어와 연결하는 역할**을 한다.

**💡****Q# → QIR → QPU 제어 과정**

1. 1. Q# 코드 작성 (Application Layer)

      - 개발자는 큐빗, 게이트, 알고리즘 흐름만 정의한다.
      - QPU의 게이트 세트(gate set), 펄스 시퀀스, 타이밍 제어는 알 필요 없다.
   2. Q# 컴파일러 → QIR 생성 (IR Layer)

      - Q# 컴파일러는 위 코드를 QIR(LLVM IR 기반)로 변환한다
      - QIR은 **Q#에서 선언한 추상 명령을 구체적인 게이트 호출로 매핑**한다.
   3. QIR 런타임 + LLVM Pass 최적화 (Middleware Layer)

      - QIR은 단순히 IR만 제공하는 게 아니라, 런타임과 최적화 패스까지 포함한다.
      - QIR 런타임이 하는 일:

        - 큐빗 할당 및 해제
        - 게이트 시퀀스 최적화 (예: 연속 Hadamard 제거)
        - 루프 언롤링, SSA 기반 최적화
        - QPU 드라이버 호출을 위한 낮은 수준의 명령어 변환
   4. 하드웨어 펌웨어로 변환 (Backend Layer)

      - QIR 런타임이 하드웨어별 게이트 세트(gate set)와 **펄스 시퀀싱**으로 매핑한다.
      - QIR은 “게이트 단위의 추상화 계층”이고, 펌웨어는 “하드웨어별 저수준 펄스 제어 계층”이다.

> **Q#** → 소프트웨어 앱 개발자
>
> **QIR** → 운영체제 커널의 **디바이스 드라이버 레이어**
>
> **펌웨어** → QPU별 전자제어 회로를 직접 구동하는 **하드웨어 시퀀서**
>
> 즉, **Q#이 QIR을 “콜”해서 런타임을 통해 QPU를 제어**하는 구조다.

**✅****QIR의 유연성**

**💡****QIR은 오픈 스탠다드**

- - QIR(Quantum Intermediate Representation)은 **LLVM 기반 IR**이므로 LLVM 철학을 따른다.
  - LLVM은 **언어 비종속**, **하드웨어 비종속**, **커뮤니티 주도형** 구조를 가진다.
  - 따라서 QIR도 마이크로소프트가 설계했지만, **표준은 공개되고 누구나 확장 가능**하다.
  - QIR의 specification은 GitHub에 공개되어 있다.

    - Mircosoft와 QIR Alliance가 공동으로 관리하고, 하드웨어 업체 및 국가 산하기관 및 일부 대학 연구소 등이 참여
    - QIR의 사양은 오픈소스로 유지되며, **누구나 Issue, Pull Request를 올려 개선 가능**하다.

      - 하드웨어의 기능이 추가되면, 개발업체에서는 자사 QPU에서 사용되는 게이트 세트(gate set)와 제어 시퀀스(pulse sequence)를 QIR 런타임에 맞게 매핑해야 한다.
      - 보통 벤더가 QIR 런타임 드라이버를 작성하거나, QIR Alliance에 패치를 기여한다.
  - QIR은 개발자가 사용하는 소프트웨어 개발 영역은 아니기 때문에,

    - Q#이외에도, C++이나 Python이용하여 알고리즘을 작성후 QIR API를 호출하면 그만이다.

**💡****QIR이 오픈 스탠다드라서 좋은 점**

|  |  |  |
| --- | --- | --- |
| **항목** | **QIR 오픈 스탠다드** | **비표준 SDK (벤더 전용)** |
| **하드웨어 독립성** | IonQ, Quantinuum, Rigetti 등 모두 지원 | 특정 벤더 SDK에 종속 |
| **언어 독립성** | Q#, Python, C++, Qiskit, Cirq 등 지원 | 보통 SDK 전용 언어 필요 |
| **표준화 방식** | LLVM 기반, QIR Alliance 주도 | 벤더 내부 전용 |
| **업데이트 주체** | Alliance + 벤더 공동 | 벤더 단독 |
| **호환성** | 여러 QPU 백엔드 통합 가능 | 벤더별 코드 재작성 필요 |

**💡****QIR Alliance의 역할**

- - QIR은 단순히 마이크로소프트 혼자 관리하지 않는다.
  - **QIR Alliance**라는 오픈 거버넌스 그룹에서 표준화를 주도한다.
  - **주요 역할**

    - QIR 명세 표준화 및 확장 관리
    - LLVM Pass 기반 최적화 및 코드 생성 아키텍처 표준화
    - QPU 드라이버 및 런타임 ABI 정의
    - 시뮬레이터·슈퍼컴퓨팅 환경 통합 지원
  - **참여자 예시**

    - Microsoft Quantum
    - Quantinuum
    - Rigetti
    - Pasqal
    - DOE 산하 ORNL, PNNL
    - 일부 대학 및 오픈소스 개발자

**💡****주요 업체들 및 QIR 지원 현황**

|  |  |  |
| --- | --- | --- |
| **업체 (Vendor)** | **QIR 프로필 또는**  **지원 수준** | **주요 특징 및 제한사항** |
| **IonQ** | QIR Base 프로필을 지원 | IonQ의 여러 실험용/상업용 QPU와 시뮬레이터가 Azure Quantum에서 QIR Base 프로필로 동작한다. 다만, 측정 결과에 기반한 조건부 흐름(control flow) 같은 중간측정(mid-circuit measurement)이나 측정 결과 조건 비교는 QIR Base 프로필에서 제한된다. 예: QIR Base 프로필은 측정 결과(Result 타입)의 값 비교(equality comparison)나 그 결과를 제어 흐름에 사용하는 것이 허용되지 않는다. |
| **Quantinuum** | QIR Adaptive RI 프로필을 지원 | Quantinuum의 여러 타깃 하드웨어가 **Integrated hybrid circuits**을 포함한 기능들을 포함하여 QIR Adaptive RI 프로필을 충족한다. 즉, 측정 기반 제어 흐름 등을 일부 더 유연하게 지원 가능하다. |
| **Rigetti** | QIR Base 프로필 및 시뮬레이터 쪽 지원됨 | Rigetti의 Quantum Virtual Machine(QVM) 시뮬레이터가 rigetti.qir.v1 데이터 포맷을 지원하고 Azure Quantum을 통해 제공됨. 하지만 실제 하드웨어에 이 모든 기능이 동일 수준으로 구현되었는지는 제한 요소가 있을 수 있다. |
| **PASQAL** | Azure Quantum 타깃으로 존재함 | PASQAL의 중성원자(neutral atom) 기반 프로세서들이 Azure Quantum에 Provider로 등록돼 있으며, QIR 프로파일 중 어떤 수준인지 문서에서 명확히 “Base” 혹은 “Adaptive”인지 지정되는 경우는 제한적이다. 제한 기능 또는 프로필 제약이 있을 수 있음. |
| **Atom Computing** | 공식 프로필 미제공 | Microsoft와 협력 중이며 Azure Quantum Elements 통합 작업 진행 중. **중간측정, 큐빗 재사용, 논리 큐빗** 시연 사례 존재. 다만 QIR 프로필(Base vs Adaptive) 지원 여부는 아직 명확하지 않음. |
| **Microsoft / Azure Quantum** | 여러 QIR 프로필 관리 (Unrestricted / Base / Adaptive RI) | Microsoft와 협력 중이며 Azure Quantum Elements 통합 작업 진행 중. **중간측정, 큐빗 재사용, 논리 큐빗** 시연 사례 존재. 다만 QIR 프로필(Base vs Adaptive) 지원 여부는 아직 명확하지 않음. |

**💡****프로필(Profile) 유형 간단 비교**

- - **QIR Base Profile**

    - 측정 기반 제어 흐름(Measurement-Result로 조건 비교 등)은 지원하지 않음
    - 기본적인 게이트 기반 알고리즘 실행 가능
    - IonQ, Rigetti 등의 많은 QPU/시뮬레이터가 이 수준
  - **QIR Adaptive RI Profile**

    - 중간측정(mid-circuit measurement), 측정 결과 기반 조건문(if-then 등) 등 일부 더 풍부한 흐름을 표현 가능
    - 현재 Quantinuum이 이 프로필을 어느 정도 구현 중임
  - **Unrestricted Profile**

    - 이론상 QIR이 정의하는 모든 기능을 허용하는 프로필
    - 현재 Azure Quantum 하드웨어에서는 제공되지 않음; 다만 시뮬레이터 쪽에서 제한 없이 실행 가능함
