**🖥️양자 컴퓨터 메모리 구조 : 내부 메모리 vs 통신용 메모리**

양자컴퓨터의 메모리는 크게 두가지로 구분할 수 있다. QPU내부에서 연산에 사용하는 메모리와, 얽힘 상태를 유지해 장거리 통신에 사용하는 메모리가 그것이다.

현재 상용이나 연구 단계의 대부분의 양자 컴퓨터는 별도의 전용 메모리를 두지 않고, 큐비트 자체가 연산과 측정을 모두 수행하는 구조이다. 이러한 구조는 하드웨어 구현 난이도를 낮추고, 현재 코히런스 시간 제한 내에서 가능한 가장 간단 설계이기 때문이다. 하지만, 안정적인 장기 저장과 양자 네트워크 연동을 위해 내부 메모리와 통신용 메모리를 구분하는 하이브리드 아키텍처가 활발히 연구되고 있다.

|  |  |  |
| --- | --- | --- |
| **구분** | **양자컴퓨터 내부 메모리** | **양자 통신/네트워크용 메모리** |
| **목적** | 연산 중 임시 저장(레지스터 역할) | 얽힘·양자 상태를 장거리 통신용으로 임시 저장 |
| **광자 필요 여부** | 필요 없음 | 필요 |
| **저장 시간** | ns ~ms (게이트 준비, QEC 전제) | ms~s (네트워크 지연 허용) |
| **위치** | QPU 칩 내부 | 중계기·노드·광자 인터페이스 주변 |
| **연결 대상** | 같은 QPU 내부 큐비트 | 다른 QPU/지상국/위성 등 |
| **기술 구현** | 초전도·이온·스핀 등 QPU 자체 큐비트 | 희토류 결정·원자 집합·QPU 큐비트 메모리화 |
| **주요 기능** | 연산용 큐비트 유지 | 얽힘 분배, 스와핑, 네트워크 동기화 |

**1️⃣하이브리드 설계의 장점**

- 양자 통신을 위해서는 (2025년 기준) 무조건 광자가 필요하다는 것은 이미 증명이 됐고, 어떤 방식으로 QPU내부의 큐비트롤 사용하는 것이 가장 효율적인지 여러 의견이 있지만, 앞서 여러차례 언급했듯이, QPU내부에서 광자를 사용하는 것은 Best가 아니라는 개인적인 의견이다.
- 즉, QPU내부와 외부가 서로 다른 방식의 큐비트를 사용하는 것이고, 그에 따른 메모리 관리도 다른 방식으로 구현되는 것이 매우 합리적이라 할 수 있다.
- 앞으로 더욱 다양한 양자컴퓨터가 개발되겠지만, 이 글을 작성하는 현재, 이온트랩방식이 양자컴퓨터의 철학을 가장 잘 대변한다고 생각하기 때문에 메모리에 대한 설명 또한 **이온트랩방식 위주**로 풀어가겠다.
- 아이온큐가 자신들이 개발하고 고수해오던 레이저 제어방식을 버리고 옥스포드 아이오닉스의 마이크로파 제어방식을 선택했으니, 마이크로파를 기준으로 설명하자면,
- **QPU내부 메모리 → 하이퍼파인상태 또는 메타안정상태**
- **통신/커뮤니케이션 메모리 → 메타안정상태**

  - **단일광자 방출·흡수, 얽힘 분배**
- **→ 결과적으로 레이저/마이크로파 병행이 효율적**

**2️⃣****QPU 내부 메모리의 구분**

- **코히런스 시간(Coherence Time) 차이**

  - 양자 상태는 시간이 지남에 따라 쉽게 붕괴(디코히런스)됨
  - 연산용 큐비트는 μs~ms 단위로도 충분하지만
  - 논리 큐비트/QEC·네트워크 연동에는 **수백 ms~수 s**급 저장 필요
- **용도 차이**

  - **단기 메모리 (short‑term memory)**

    - 연산 중 임시 저장(레지스터·버퍼)
    - 게이트·서킷 동기화 용도
    - 필요 시간: μs~ms (연산 시간 스케일)

|  |  |
| --- | --- |
| **기능** | **설명** |
| **양자 회로 실행 중 임시 레지스터** | 게이트 연산 사이에 상태를 임시 저장 |
| **멀티큐비트 게이트 준비** | 컨트롤/타겟 큐비트를 유지하며 다른 큐비트 연산 동기화 |
| **SWAP/라우팅 버퍼** | 대규모 QPU에서 큐비트 위치 이동 시 임시 저장 |
| **NISQ 알고리즘** | VQE, QAOA 등 연산 동안 유지되는 임시 상태 |
| **내부 QEC 버퍼** | QEC 회로에서 에러 신드롬 추출 시 잠깐 상태 저장 |

- - **장기 메모리 (mid/long‑term memory)**

    - QEC 보조, 얽힘 분배 대기, 논리 큐비트 압축
    - 필요 시간: 수백 ms~수 s (네트워크/복잡 회로 스케일)

|  |  |
| --- | --- |
| **기능** | **설명** |
| **양자 오류 정정(QEC) 보조** | 논리 큐비트 압축·정제 시 긴 시간 유지 필요 |
| **얽힘 정제(Entanglement Purification)** | 여러 쌍의 얽힘을 모아 고신뢰 쌍 생성 |
| **양자 텔레포테이션 준비** | 원거리 통신용 얽힘 상태 대기 |
| **논리 큐비트 스왑 아웃** | 메인 연산 영역에서 장시간 유지해야 하는 상태를 분리 |
| **하이브리드 연산 버퍼** | 연산 속도 <-> 통신/저장 안정성 균형 유지 |

- **엔지니어링 고려**

  - 단기 메모리는 **속도·병렬성·스케일링** 우선
  - 장기 메모리는 **코히런스·안정성** 우선
  - 같은 큐비트라도 **제어·물리 구조·환경 요구가 달라진다**

**1️⃣QPU 내부 메모리**

연산용 메모리는 **QPU 내부 레지스터/보조 큐비트** 개념으로 쓰인다.

특징은 다음과 같다.

- **목적**

  - 연산 중 임시 저장 (레지스터, 버퍼)
  - 논리 큐비트(QEC)용 보조 큐비트
  - 회로 지연/분산 연산 시 로컬 버퍼
- **기술적 특성**

  - 광자 불필요 (연산은 칩 내부에서 이루어짐)
  - 마이크로파/전기장/레이저 중 **플랫폼 맞춤 제어**
  - 저장 시간: μs ~ 수백 ms (동적 디커플링으로 연장 가능)
  - **속도**: ns~μs 단위 접근 가능
  - **통신 인터페이스**: 필요 없음 (광자 불필요)
  - **엔지니어링 우선순위**: 속도, 안정성, 스케일링

- **예시**

|  |  |
| --- | --- |
| **플랫폼** | **연산용 메모리 구현** |
| **이온 트랩** | 하이퍼파인 상태 or 메타 안정 상태를 그대로 사용  → 마이크로파 제어 가능 |
| **초전도 큐비트** | 캐비티 모드(3D 캐비티) 또는 보조 트랜스몬  → 마이크로파 제어 |
| **스핀/SiV 기반** | 전자/핵 스핀 다준위 활용 (qudit) |

**🔑하이퍼파인 상태와 qudit**

- **하이퍼파인 상태**

  - 전자 스핀(𝑆)과 핵 스핀(𝐼)의 상호작용으로 생기는 세분화된 에너지 준위
  - 예:

    - 171Yb+ : F=0,1 상태 → 초대 4준위(큐비트)
    - 137Ba+ : F=1,2 상태 → 최대 8준위(이론상 qudit 가능) → **8‑레벨 qudit 가능** → **3 qubit 메모리 사용 가능**
- **qudit로 활용**

  - 여러 하이퍼파인 준위를 논리 상태 |0⟩, |1⟩, |2⟩ ... 로 매핑
  - 다준위 간 전이를 마이크로파로 직접 구동→광학레이저보다 기술 난이도 낮음
  - 다준위 양자 연산·저장 가능
- **단점**

  - 다준위가 많을수록 주파수 선택성 문제
  - 인접 준위 간 비공진 결합(leakage) 위험
  - **장거리 통신(얽힘·광자 인터페이스)에는 직접 사용 불가**

****

**🔑** **메타안정 상태(Metastable state) 결합형 qudit**

- **바륨 이온의 5D****5/2****, 5D****3/2** **상태를 활용해**

  - **긴 수명 상태 = 보조 메모리 상태**
  - 하이퍼파인 상태와 결합해 **하이브리드 qudit** 구성 가능 : **이론적으로 48개 레벨 가능**

    - 6S1/2 : 8레벨
    - 5D5/2 : 24레벨
    - 5D3/2 : 16레벨
  - 메타안정상태

    - 전자 전이가 전기쌍극자 금지(E1-forbidden)인 경우가 많다

      - 전기 쌍극자 복사가 선택 규칙에 의해 허용되지 않아 전이가 매우 느리게 되고, 이로 인해 메타 안정 상태가 됨.
    - 예: 137Ba+의 5D5/2, 5D3/2 상태
    - 자연 수명: 수백 ms ~ 수십 s
    - 이런 상태 간의 전이는

      - **마이크로파 주파수 영역에 해당하지 않음**
      - **레이저(보통 광학/근적외선)로만 유도 가능**
  - 레이저의 역할

    - **상태 전이(Shelving/Deshelving)**

      - 논리 상태를 메타안정 상태로 올리고 내림
    - **광자 방출·흡수(통신/측정)**

      - 단일광자 생성(QKD, 얽힘 분배)
      - 상태 판독 시 형광 레이저 사용
    - **연산용 보조 메모리**

      - 전자 스핀 ↔ 메타안정 상태 간 매핑
      - 마이크로파만으로는 접근 불가
- **장점**

  - **내부 연산용 장기 저장** 및 **QEC 보조 메모리**에 유리
  - 동적 디커플링 적용 시 수 초~수십 초 코히런스
- **단점**

  - 일부 상태 전이에 여전히 **레이저 필요** (광학적 shelving)

**🔑내부 연산용 단기·고속 메모리에는 마이크로파 제어 하이퍼파인 qudit이 최적이지만, 과제극복해야함**

- **Zeeman 효과 제거 / 억제**

  - **문제**

    - 하이퍼파인 상태는 자기장에 민감 → Zeeman 분할 발생
    - 8개 상태를 동시에 안정적으로 유지하려면

      - 자기장 안정화
      - 지터 및 공간 불균일성 억제 필수
  - **대응 기술**

    - **“Clock state” 선택 - 외부 자기장에 덜 민감한 상**

      - m\_F=0 상태 중심으로 qubit/qudit 구성
      - 1차 Zeeman 민감도 제거
    - **Dynamic Decoupling (DD)**

      - 주기적 또는 최적화된 펄스를 인가해서 **환경잡음에 의한 위상 확산을 억제**
      - 대표적 기법

        - CP(Carr‑Purcell) - 단순 반복 π 펄스 시쿼스
        - UDD(Uhrig DD) - 펄스 간격을 최적화해 **저주파 잡음 억제**
        - multi-tone DD - 최적화된 톤으로 **다양한 잡음 억제**
    - **Magnetic shielding + active field stabilization**

      - 코히런스를 유지하려면 주변 자기장을 nT ~ μT 단위로 정밀 제어해야 함
      - μT 이하 정밀 제어
- **다준위 제어 및 측정 정밀도**

  - **문제**

    - 8‑레벨 qudit은 7개 전이를 제어해야 함
    - 주파수 근접 → **Leakage & Cross‑talk** 문제 심각
    - 측정 시에도 특정 상태만 선택적으로 판독 필요
  - **대응 기술**

    - **멀티톤 마이크로파 제어**

      - 개별 전이 주파수 분리
      - **최적화 펄스**로 leakage 최소화
    - **Sequential shelving/판독**

      - 필요 시 일부 상태를 optically shelve → fluorescence detection
    - **에러 완화**

      - 실시간 error mitigation 적용

****

**🔑 현실적 난이도**

- **2~3레벨 qudit (qutrit)** → 이미 실험적 데모 다수
- **8레벨 qudit** →

  - 제어 가능성은 원리적으로 충분
  - **문제는 안정적·고충실도 동시 제어**
  - Zeeman 억제 + 다중 주파수 제어 + 고정밀 측정 기술이 모두 필요

**2️⃣통신용 메모리**

- **목적**

  - 얽힘 상태 저장 → 장거리 QKD, 양자 네트워크, 중계기
- **특징**

  - **광자를 반드시 사용** (얽힘·단일광자 상태를 주고받아야 함)
  - 저장 시간: **ms ~ s급 필요**
  - 대표 구현:

    - 희토류 도핑 결정(REIC)
    - 원자 집합(DLCZ)
    - 다이아몬드 SiV/NV 색 중심
- **제어 방식**

  - 대부분 **레이저 기반 광자 인터페이스** 필수
  - **마이크로파 단독으로는 네트워크 참여 불가**

****

**🔑통신용 양자 메모리가 필요한 이유**

- **양자 네트워크·인터넷**에서 핵심 기능 수행

  - **얽힘 상태 버퍼링**

    - A↔B↔C 링크를 만들 때, 한쪽 신호가 늦게 도착해도 기다릴 수 있어야 함
  - **Entanglement Swapping**

    - 얽힘을 점프식으로 확장
  - **Entanglement Purification**

    - 품질 낮은 얽힘 여러 쌍 → 고신뢰 얽힘 1쌍으로 정제
- → 저장 시간 수 ms~s급 요구

****

**🔑라이트싱크의 양자 메모리 방식**

1. **다이아몬드 색소 중심 (Color Center in Diamond)**

   - **정의**

     - 다이아몬드 격자 내 결함(예: SiV, NV 중심)의 전자·스핀 상태를 이용

       - 다이아몬드 내부에 존재하는 질소 공공 결함(Nitorgen-vacancy defect)

         - 다이아몬드 결정에 탄소 한 원자가 질소로 치환되고 그 옆 탄소 자리 하나가 공석으로 비어 있는 상태
         - 이 질소-공공 쌍이 NV센터임
         - NV센터는 전자 스핀1 시스템을 형성
       - 양자 컴퓨팅, 양자 센싱 및 양자 통신에 널리 쓰이는 **고체 상태 양자 소자**중 하나.
     - 광자와 직접 상호작용해 **단일광자 흡수·방출 및 상태 저장 가능**
   - **역할**

     - **양자 메모리의 물리적 매질**
     - 들어온 광자 상태(편광/위상)를 전자 스핀 상태로 임시 저장
2. **광자 인터커넥트 (Photonic Interconnect)**

   - **정의**

     - 광 집적 회로(PIC)를 이용해 단일광자·얽힘을

       - QPU ↔ QPU
       - QPU ↔ 중계기
       - 중계기 ↔ 네트워크
       - 로 연결하는 통신 인터페이스
   - **역할**

     - **광자를 칩으로 유도·결합·분배**
     - 다이아몬드 색소 중심과 결합해 **메모리 입출력 통로 역할**
3. **메모리 인핸스드 리피터 (Memory‑Enhanced Quantum Repeater)**

   - **정의**

     - 전통적인 all‑photonic repeater(광자만 이용)와 달리,광자 ↔ 물질 메모리를 결합해 신뢰도 높은 얽힘 분배를 수행하는 중계기
     - 저장(버퍼링) 기능 덕분에 네트워크 지연·동기화 문제 해결
   - **구성**

     - **물리적 메모리** **→ 다이아몬드 색소 중심**
     - **입출력 인터페이스** **→ 광자 인터커넥트**
     - **기능적 구현** **→ 메모리 인핸스드 리피터**

****

**3️⃣결론**

- **독립형 QPU**:

  - **마이크로파 전용 하이퍼파인** qubit 메모리가 가장 단순
  - 레이저 시스템 제거로 엔지니어링 **단순화 극대화**
- **네트워크 연동 QPU**:

  - 양자 네트워크를 위해 레이저 필요 → 하이브리드가 더 합리적

    - 내부 단기 메모리는 하이퍼파인
    - 내부 장기 메모리까지 메타안정 상태
  - 하드웨어 중복 문제보다 **레이저/마이크로파 제어 통합 안정성**이 관건

**🔑 통신 시 레이저·광자 변환 단계**

- **선택된 커뮤니케이션 큐비트만**

  - 마이크로파→레이저 여기→광자 변환
- **포토닉 인터커넥트 수행 후**

  - 필요 시 다시 내부 하이퍼파인 메모리로 매핑
- **결과**

  - 내부: 고속·안정적 마이크로파
  - 외부: 필요한 순간만 광자 변환

**🔑 속도 및 효율 면에서 장점**

- 외부 통신은 **부분적 레이저 사용** → 하이브리드지만 효율적
- 내부 단기 메모리 qudit는 **마이크로파 전용으로 운용**

  - 통신 시만 광자 변환 → 최적의 속도/안정성 확보

> **마이크로파 기반 하이퍼파인 qudit + 필요 시 최소한의 메타안정 상태 접근**
>
> **하지만, 현실은 아직 기술적으로 극복을 해야 한다는 점~~~~~~**
