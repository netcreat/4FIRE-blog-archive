**✅NVLink Fusion, 방어가 아닌 점령을 위한 전략**

**1️⃣ 전제부터 바로잡자: CXL이 이기는 영역은 분명히 있다**

- - NVIDIA도 이걸 **부정하지 않는다**.
  - **CXL이 강한 영역**

    - CPU 중심 서버
    - 메모리 풀링 / 익스팬더
    - 멀티벤더 조달
    - 표준 기반 인프라
    - “GPU가 주연이 아닌” 워크로드
    - 👉 **이 영역은 NVLink가 태생적으로 약하다.**
    - 그래서 NVIDIA는 선택해야 했다.

      - ❌ “CXL 무시하고 GPU 섬에만 머문다”
      - ⭕ “CXL 세계로 들어가되, 중심은 우리가 잡는다”
    - → **NVLink Fusion이 나온 이유**

****

**2️⃣ NVLink Fusion의 진짜 목적 (핵심)**

- - **NVLink Fusion은 이렇게 말한다**

> ***CXL을 쓰든, ASIC을 쓰든, CPU를 쓰든 상관없다.***
>
> ***하지만 AI 팩토리의 중심 패브릭은 NVLink다.***

- - 즉, CXL 흡수·외곽화

**3️⃣ NVIDIA가 본 ‘위험 시나리오’**

- - NVIDIA가 제일 두려워한 건 AI 인프라의 표준 중심이 CXL + 이기종 ASIC으로 굳어지는 것
  - 이 시나리오가 현실화되면:

    - GPU는

      - 하나의 가속 카드
      - 교체 가능한 부품
    - NVIDIA는

      - 가격 결정력 상실
      - 시스템 영향력 상실
  - 👉 **NVLink Fusion은 이 시나리오를 차단하는 장치다.**

****

**4️⃣ 그래서 Fusion은 ‘개방’처럼 보이게 설계되었다**

- - **표면적으로는**

    - MediaTek
    - Marvell
    - Astera Labs
    - Fujitsu
    - Qualcomm
    - Synopsys / Cadence
    - 👉 “개방형 생태계”
  - **하지만 구조적으로는**

    - NVLink PHY
    - NVLink protocol
    - NVSwitch / NVLink Switch System
    - NCCL / CUDA / Mission Control
  - 👉 **핵심 레이어는 전부 NVIDIA 소유**
  - 즉,

> ***NVLink Fusion은***
>
> ***“들어와도 되지만, 룰은 우리가 정한다” 구조***

**5️⃣ 그럼 왜 CXL을 대체하지 않고 병행하나?**

- - 이유는 아주 현실적이다.
  1. **정치 / 조달**

     - 하이퍼스케일러
     - 국가·공공기관
     - 조달 규정
     - → **CXL 없는 시스템은 아예 입찰 불가인 경우 많음**
  2. **범용 워크로드**

     - 스토리지
     - 메모리 확장
     - CPU-heavy 앱
     - → NVLink는 과함
  3. **타이밍**

     - CXL은 이미 퍼짐
     - 없던 일로 만들 수 없음
  - 👉 그래서 NVIDIA는 **대체가 아니라 포위**를 택했다.

**6️⃣ NVLink Fusion이 “이긴다”는 의미의 재정의**

- - 여기서 중요한 관점 전환이 있다.
  - **❌ “NVLink가 CXL을 기술적으로 이긴다”**
  - **⭕ “NVLink가 AI 시스템의 중심이 된다”**
  - 👉 **CXL은 주변, NVLink는 중심**

****

**7️⃣ 만약 NVLink Fusion이 없었다면?**

- - 진짜 중요한 가정이다.

    - 하이퍼스케일러:

      - CXL + 자체 ASIC
    - GPU:

      - 선택적 가속기
    - NVIDIA:

      - “빠른 카드 공급업체”
  - 👉 지금의 **AI 팩토리 독점 구조는 성립 불가**

****

**8️⃣ 그래서 결론은?**

> ***CXL이 NVLink를 ‘대체’하지는 못하지만, NVLink가 ‘고립’될 수는 있기 때문이다.***
>
> ***NVLink Fusion은 그 고립을 막고, AI 인프라의 중심 자리를 고정하기 위한 전략이다.***

---

**✅NVLink Fusion의 개방 범위**

**1️⃣ 공식 스탠스 한 줄 요약**

> ***NVLink Fusion은 타 업체가 ‘쓸 수는 있지만’, NVIDIA가 정한 조건과 위치 안에서만 가능하다.***

- - ❌ PCIe처럼 공개 표준 아님
  - ❌ CXL처럼 컨소시엄 표준 아님
  - ⭕ NVIDIA 승인 하에 **파트너 접근 가능**

****

**2️⃣ 무엇이 “개방”되었고, 무엇이 아닌가?**

- - **✅ 개방된 것 (부분)**

    - **외부 ASIC / 가속기 연결 허용**

      - “NVIDIA GPU가 있는 시스템에”
      - “NVLink 패브릭에 붙는 형태”
    - **NVIDIA가 설계한 NVLink Switch / Fabric 사용**
    - **CUDA / CUDA-X / CUDA-Q 스택 연동**
  - 👉 즉:

> ***“우리 패브릭에 들어오면, 같이 일하게 해줄게”***

- - **❌ 개방되지 않은 것 (핵심)**

    - NVLink **프로토콜 스펙 완전 공개 ❌**
    - NVLink PHY/SerDes 자유 구현 ❌
    - 제3자 간 **독립적 NVLink 네트워크 구축 ❌**
    - NVIDIA GPU 없이 NVLink Fusion 사용 ❌
  - 👉 즉:

> ***“중앙은 항상 GPU(=NVIDIA)다”***

**3️⃣ CXL과의 결정적 차이**

|  |  |  |
| --- | --- | --- |
| **항목** | **CXL** | **NVLink Fusion** |
| 표준 | 개방형 | **비공개(라이선스)** |
| 컨트롤 | 컨소시엄 | **NVIDIA** |
| CPU/GPU 중립 | 있음 | **GPU 중심** |
| 제3자 구현 | 자유 | 제한적 |
| 목표 | 범용 | AI/HPC 독점 성능 |

**4️⃣ 그럼 “타 업체”는 누가 가능한가?**

- - **현실적으로 가능한 타입**

    - **대형 반도체 파트너**

      - Broadcom (SerDes / Switch)
      - Marvell (optical / DSP)
      - 일부 Hyperscaler 전용 ASIC
    - **전략적 가속기 업체**

      - AI inference ASIC
      - 네트워크 가속기
      - (장기적으로) QPU 업체
  - 단, 공통 조건:

    - **NVIDIA와 전략 파트너십**
    - **GPU 중심 시스템 설계 수용**
    - **CUDA 생태계 연동**

****

**5️⃣ QPU 업체 관점에서의 “개방”**

- - **QPU 업체는 “쓸 수는 있다”**

    - IonQ / Oxford Ionics / Quantinuum 등은

      - **직접 NVLink 스펙 구현 ❌**
      - **NVIDIA가 제공하는 인터페이스/브릿지** 사용 ⭕
    - 초기에는:

      - PCIe → CXL → NVLink-class 브릿지
    - 장기적으로:

      - Photonic interconnect + NVLink Fusion adapter
  - 👉 즉:

> ***QPU는 “동등한 패브릭 소유자”가 아니라***
>
> ***GPU에 종속된 가속기 노드***

**6️⃣ 왜 이렇게 애매하게 개방했나?**

- - **NVIDIA의 계산**

    - 완전 폐쇄 ❌ → 반발, 생태계 고립
    - 완전 개방 ❌ → AMD/Intel도 똑같이 씀
    - **부분 개방 ⭕ → 생태계 흡수 + 주도권 유지**
  - 이 구조는 과거와 완전히 같다:

    - CUDA
    - NVLink
    - NVSwitch

**7️⃣ 투자/전략 관점 한 문장**

> ***NVLink Fusion은***
>
> ***‘개방형 표준인 척하는 폐쇄 생태계’다.***

- - 그리고 이게 먹히는 이유는 단 하나:

> ***지금 AI 성능을 이길 대안이 없기 때문***

**1️⃣ 핵심 오해 정리 (중요)**

- - **❌ NVQLink = 새로운 물리 링크 → 아님**
  - **❌ NVLink Fusion = NVLink 차세대 버전 → 전혀 아님**
  - **⭕ NVLink Fusion = NVLink를 포함한 “질서”**
  - **⭕ NVQLink = 그 질서 안에서 QPU가 들어올 자리**

****

**2️⃣NVQLink의 위치**

- - QPU는 NVSwitch Fabric에 직접 연결되지 않음 주의
  - **핵심 이유**

    1. **시간 결정성 보호**

       - NVSwitch는:

         - 초고대역폭
         - 하지만 **비결정적 큐잉**
       - QPU 제어는:

         - **ns~µs 단위 절대 시간 보장**
    2. **패브릭 안정성**

       - QPU는:

         - 불안정
         - 실험 장치 성격
         - 오류 빈번
       - NVSwitch fabric은:

         - 수천 GPU 전체를 묶음
    3. **QPU의 현재 연산 밀도**

       - QPU 데이터량:

         - 작음
         - 이벤트 중심
       - NVLink 패브릭:

         - TB/s급 연속 스트림
  - QPU가 fault-tolerant logical compute node가 되면

    - 패브릭에 **동등한 endpoint로 편입 가능**

**3️⃣ 최종 한 문장 요약**

> ***NVLink는 선이고,***
>
> ***NVSwitch는 판이고,***
>
> ***NVLink-C2C는 온칩 신경이고,***
>
> ***NVLink Fusion은 세계관이고,***
>
> ***NVQLink는 QPU에게 줄 좌석 이름이다.***
