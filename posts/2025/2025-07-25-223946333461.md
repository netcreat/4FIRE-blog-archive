**🧮IonQ의 오류 수정 코드 혁신**

IonQ 연구진은 최근 전통적인 양자 오류 수정보다 훨씬 효율적인 **새로운 방식의 오류 완화 기법**을 발표했다. 완전한 오류 수정을 달성하는 것은 양자 컴퓨팅 커뮤니티의 장기적인 목표로 여겨지지만, 대부분의 오류 수정 방식은 **논리 큐비트 1개당 수많은 물리 큐비트가 필요**해 현재의 하드웨어 수준에서는 비현실적이다. IonQ는 이 문제를 크게 개선하는 **획기적인 방법**을 제시했다.

이 방법은 **CliNR(‘cleaner’로 발음)**, 즉 **Clifford Noise Reduction**의 약자이다. 기존 오류 수정(QEC)은 많은 자원을 소모하고, 오류 완화(QEM)는 샘플링 횟수가 지수적으로 늘어나는 문제가 있었지만, **CliNR은 낮은 오버헤드로 오류율을 절반으로 줄이는 효과**를 보였다.

[![](https://images.ctfassets.net/hqm865gc1xfs/2zumWcg2GfmFspJNsTd9al/c62377de3c6abbab4feea4686cd56d7e/CliNR_Results_Charts_Transparent.png)](#)

**기본 게이트의 충실도(fidelity)에 대한 모델링 가정에 기반하여**, CliNR은 회로 내 오류 발생 확률을 줄일 수 있으며, **회로의 크기와 깊이가 커져도 효율적으로 확장된다.**

**📊 그래프 설명 (왼쪽 / 오른쪽 모두)**

**공통 조건**

- 회로 크기: s≈n2 (큐비트 수 n의 제곱에 비례하는 회로)
- 오류 확률: p2=10p1 (2큐비트 게이트가 1큐비트 게이트보다 10배 더 noisy)

**왼쪽 그래프**

- 오류 확률: p2=10−3
- 큐비트 수 10~35개 범위
- **빨간색 (직접 구현)**: 오류 완화 없이 회로 실행 → 오류율 급증
- **파란색 (CliNR 2×, 4×)**: 회로를 중복하고 오류를 완화함 → **오류율 크게 감소**

**오른쪽 그래프**

- 오류 확률: p2=10−4
- 큐비트 수 **5~85개 범위**
- 기본 오류율이 더 낮은 조건에서도 CliNR 방식이 확연히 낮은 오류 확률 유지
- 큐비트 수가 많아질수록 **직접 구현은 오류율이 급증**, 반면 **CliNR은 완만하게 증가**

****

**오류 처리에서의 가치 격차(Value Gap)**

현재 사용자들은 다음과 같은 문제를 겪고 있다:

- **QEM(오류완화)**: 적은 자원을 사용하지만, 회로가 커질수록 확장성에 문제가 발생.
- **QEC(오류정정)**: 확장성은 좋지만, 구현에 너무 많은 큐비트와 게이트가 필요해 현재 기술로는 실현이 어려움.

⇒ **이 공백을 메우기 위한 현실적인 대안이 바로 CliNR**

|  |  |  |  |
| --- | --- | --- | --- |
| **항목** | **QEM** | **CliNR** | **QEC** |
| 큐비트 수 | 적음 | 적음 (~3:1) | 매우 많음 |
| 게이트 수 | 적음 | 적음 (~2:1) | 매우 많음 |
| 샷(shot) 수 | 많음 (지수적 증가) | 적음 | 안정적 |
| 적용 대상 | 현재 회로 | 클리퍼드 회로 중심 | 논리 큐비트 전체 |
| 확장성 | 낮음 | 중간 (가까운 미래) | 높음 (미래 지향) |

이번 연구는 큐비트 비용, 게이트 비용, 샷 비용이 모두 적은 새로운 부분 오류 수정 방법을 통해 기존의 격차를 해소한다. Clifford 회로(클리퍼드 회로)라 불리는 광범위한 양자 회로 클래스의 노이즈를 줄임으로써, CliNR 기법은 문제 해결을 위한 완전히 새로운 ‘부분 오류 수정(partial error correction)’ 접근법을 가능하게 한다.

이 방식은 **장기적으로 완전한 오류 수정(QEC)을 대체하기 위해 설계된 것은 아니며**, **QEC만큼의 보호 수준을 제공하지는 않는다**. 하지만 단기적으로는 오버헤드가 매우 낮은 대안으로 활용될 수 있다.

또한 장기적인 활용 가능성도 존재한다. 예를 들어, **CliNR을 논리 큐비트에 적용하고 기존 QEC와 결합하면** QEC의 요구사항을 줄일 수 있어 전반적인 리소스 오버헤드 감소로 이어질 수 있다.

현재 IonQ의 양자 컴퓨터인 **Harmony**, **Aria**, **Forte**에는 이미 **QEM(양자 오류 완화)** 기법이 효과적으로 사용되고 있다. QEM은 비교적 적은 수의 **큐비트와 게이트**만을 사용하지만, **큐비트 수가 증가하고 샷 비용(회로 반복 실행 횟수)이 증가함에 따라 확장성이 떨어질 것으로 예상**된다. 회로가 커질수록 QEM은 **효과가 감소하거나**, 또는 **실행 시간이 지수적으로 증가**하는 오버헤드를 유발하게 된다. 따라서 **장기적으로는 다른 해결책이 필요**하다.

이 지점에서 QEC(양자 오류 수정)가 등장한다. QEC는 QEM처럼 **샷 수가 지수적으로 증가하는 문제는 겪지 않기 때문이다**. 그러나 **QEC는 큐비트 수와 게이트 수 측면에서의 비용이 매우 크며**, **현재로서는 실용적으로 사용하기 어려운 상태**이다. 예를 들어, 서피스 코드(surface code)를 사용해 대규모 양자 알고리즘을 실행하려면 **논리 큐비트 1개당 수천 개의 물리 큐비트**가 필요할 수 있다. 최근에는 **양자 저밀도 패리티 검사 코드(qLDPC)** 기반의 돌파구로 인해 QEC에 필요한 큐비트 수가 줄어들긴 했지만, **여전히 논리 큐비트당 20개 이상의 물리 큐비트**를 요구한다. 실제로 올해 초에 IonQ에서 발표한 qLDPC인 BB5도 4개의 논리 큐비트를 얻기 위해 54개의 물리 큐비트가 필요하다.

이러한 상황에서 **CliNR은 QEM과 QEC 사이의 중간 지점**에 위치하며, 중요한 문제를 해결한다. 즉, **QEC보다 낮은 오버헤드로 클리퍼드 회로의 논리 오류를 효율적으로 줄이고**, **QEM보다 더 나은 확장성을 제공**하는 방식이며, **가까운 미래에 실제로 활용 가능**한 접근법이다.

**🧩 CliNR의 고객 가치 활용 방안**

**🔍 단기적으로 알고리즘 정확도 향상**

- 오늘날 IonQ 시스템에서는 **대부분의 노이즈가 2큐비트 게이트**에서 발생한다.
- 따라서 초기에는 **2큐비트 게이트의 오류 보정**에 집중하게 되었고,
- 우리가 개발한 CliNR 기법은 실제로 **CZ, CNOT**, 그리고 IonQ 시스템에서 기본적으로 제공되는 **XX, ZZ** 등
- 모든 클리퍼드 게이트(Clifford gate)를 보정할 수 있다.
- 이들 게이트에서 발생하는 **오류는 회로 깊이가 깊어질수록 누적되기 때문에**,
- CliNR을 적용하면 **더 깊은 회로 실행이 가능**하고, **정확도 또한 향상**될 수 있다.

**🛠 QEC 이전의 프리프로세싱(전처리) 수단으로 활용**

- CliNR은 **오버헤드가 낮기 때문에**,
- **보다 정밀한 입력 게이트가 필요한 QEC(오류 수정) 체계에 앞서 선행적으로 사용**하기에 적합하다.
- 즉, **클리퍼드 게이트의 노이즈를 줄여**,
- QEC가 목표로 하는 논리 오류율(logical error rate)을 더 쉽게 달성할 수 있도록 도와준다.

**🪚 클래식 유추 설명**

**CliNR의 혁신 원리 파헤치기**

오류 수정(error correction)은 양자 컴퓨팅에만 국한된 개념이 아니다. **CliNR**의 핵심 아이디어를 설명하기 위해, 이를 **고전적인(클래식) 사례**에 빗대어 설명할 수 있다.

****

가령, **1%의 오류율을 가진 덧셈기**를 사용해 **1부터 1,000까지의 정수를 모두 더한다**고 가정해 보자.

이 덧셈기는 두 수 x+y=s를 계산할 때, **99% 확률**로 정답 s를 출력하지만, **1% 확률**로 잘못된 값 s+e를 출력한다.

여기서 e는 0부터 s 사이의 **랜덤값**이다.

****

이제 이 덧셈기를 사용해

1+2+3+⋯+1000=(1000×(1000+1))/2=500,500

이라는 결과를 실제로 구해본다.

이 시뮬레이션을 20번 실행한 결과는 다음과 같으며,

각 실행에서 사용된 덧셈기는 평균적으로 약 10번의 오류를 일으킨다.

이는 1,000개의 숫자를 합산하려면 999번의 덧셈이 필요하며, 오류율이 1%만 되어도 그 중 10개 가량은 오류가 발생할 수 있기 때문이다.

[![](https://images.ctfassets.net/hqm865gc1xfs/19KmekRsCL1pB02DNVTvD8/1c5e5853a91b6865e9aebd2b885fecdc/_1__1_000_Integers__20_times__no_error_correction.png)](#)

**"정답이 하나도 없다!"**

이는 **1%의 오류율**이 **1,000개의 숫자를 안정적으로 더하기에는 너무 높기 때문**이다.

실제로 이 계산에서는 **평균적으로 약 10개의 오류가 발생**한다.

짧은 범위의 합산은 훨씬 덜 불안정하다.

예를 들어, **1부터 100까지**의 합을 같은 방식으로 시뮬레이션한 결과는 다음과 같다:

[![](https://images.ctfassets.net/hqm865gc1xfs/26H0hckNjTTN6F325AMtzD/e5d86ef7e03374f8ffa3af2d6851cfe7/_2__100_Integers__20_times__no_error_correction.png)](#)

**정답인 5,050이 6번 등장했다.**

따라서 다수결(majority vote)을 통해 **올바른 결과를 식별할 수 있다.**

많은 수의 합을 **더 안정적으로 계산하기 위해**, 전체 합을 여러 개의 부분합(sub-sum)으로 나눈다.

각 부분합은 **두 번 계산되며**, 두 결과가 **일치하지 않으면 해당 부분합을 다시 계산**한다.

최종 결과는 **이렇게 검증된 모든 부분합을 더해 얻는다**.

[![](https://images.ctfassets.net/hqm865gc1xfs/6lbzZi2AhLRrvFQsW2a6Oj/ebe4efd70c39be0e652ea0ba640a284d/_3__1_000_Integers__20_times__with_error_correction.png)](#)

이번에는 **20번의 시뮬레이션 중 단 3번만 잘못된 합을 산출**했고, 반면 **부분합 검증 없이 실행한 이전 20번의 결과는 모두 오류**였다.

이러한 접근법은 **계산의 노이즈율을 현저히 감소시킨다**.

요약하면, 이 전략의 핵심 요소는 다음과 같다:

- **전체 문제를 더 작고 오류 가능성이 낮은 단위로 분할한다.**
- **각 부분합의 범위는 재실행이 과도하게 발생하지 않도록 충분히 작게 유지한다.**
- **부분합의 개수는 결과의 신뢰성을 확보할 수 있을 만큼 충분히 작게 유지한다.**

논문에서 설명한 CliNR 방식은 이 전략의 양자적 버전(quantum variant)으로 볼 수 있다.

아래 그림은 **CliNR을 활용한 양자 회로의 예시**이며,

그 구조가 앞서 제시한 **고전적인 덧셈기 예제와 매우 유사함**을 보여준다.

[![](https://images.ctfassets.net/hqm865gc1xfs/1qO6UfADgKPcIRJqNoMmhN/8e8e96b97ed7e3a47f69b13843b69206/CliNR_Circuit_Repeated.png)](#)

****

**CliNR 회로는 오류 확률을 줄이기 위해 회로의 하위 구성 요소에 동일한 검증 로직을 반복적으로 적용**한다.

이는 위에서 설명한 **고전적 부분합 전략과 유사한 방식**이다.

양자 설정으로 넘어가면, 가장 큰 문제는 **큐비트의 상태를 측정하면 그 상태를 교란시킬 수 있다는 점**이다.

따라서 **중간 결과를 검증하기 위해 다른 전략이 필요**하며,

이를 위해 **클리퍼드 회로의 구조적인 특성과 게이트 텔레포테이션(gate teleportation)** 기법을 활용한다.

**산업의 진전과 미래의 방향**

지금은 양자 컴퓨팅 커뮤니티에 있어 매우 흥미로운 시기이다.

**Bacon-Shor 코드**, **5큐비트 코드**, **Steane 코드**, 서피스 코드(surface code), **논리적 IQP 회로**, 오류 허용 텔레포테이션(fault-tolerant teleportation), 그리고 논리적 양자 푸리에 변환(logical QFT) 등 **오류 허용 양자 컴퓨팅 아키텍처의 여러 핵심 구성 요소들이 실험적으로 입증**되었다.

이러한 실험들은 **대규모 오류 허용 양자 컴퓨터 구축이라는 장기 목표**에 있어 매우 중요한 통찰을 제공한다.

그러나 QEC(양자 오류 수정)에 대한 실질적인 진전에도 불구하고, 이를 실용화하기 위해서는 **양자 하드웨어의 규모와 품질이 획기적으로 개선**되어야 한다. IonQ는 이러한 하드웨어 문제를 해결하기 위해 노력하는 동시에, **근시일 내에 최대한의 양자 가치를 실현할 수 있는 새로운 방법 — CliNR — 을 개발**했다.

**CliNR은 기존의 양자 오류 수정(QEC)보다 실용적이고 확장 가능한 대안**으로, **리소스 오버헤드는 최소화하면서 오류율을 크게 줄이는 기술**이다.

우리는 CliNR이 단기적으로는 물론, **장기적으로도 유효성을 유지하며 계속해서 가치 있는 성과를 제공할 수 있는 강력하고 지속적인 접근법**이 될 것으로 기대한다. 즉, **오류 허용 양자 컴퓨팅 시대가 도래하더라도, CliNR은 여전히 의미 있는 방식으로 활용될 수 있다.**

**🧩 연구 성과**

IonQ가 이미 **BB5 (********Bivariate** **Bicycle Code** **+ 5)** 수준의 에러 정정(QEC)을 연구하면서도, 여전히 **에러 완화(error mitigation)**, 특히 부분 오류 정정(partial QEC, ex. CliNR)에 집중하는 이유는 **기술적 현실성과 전략적 균형**에 기반한다. 기술적·경제적 이유는 아래와 같다.

**✅ 에러 정정(QEC)과 에러 완화(Mitigation)의 역할 차이**

|  |  |  |
| --- | --- | --- |
| **구분** | **오류 정정 (QEC)** | **오류 완화 (Mitigation / Partial QEC)** |
| 목적 | 논리 큐비트를 영속적으로 보호 | **일시적 연산 정확도 향상** |
| 적용 대상 | 전체 연산 체인 | 특정 게이트 또는 연산만 |
| 리소스 요구 | 매우 큼 (수십~수천 큐비트) | 적음 (3:1 수준도 가능) |
| 계산 시간 | 증가 (디코딩 포함) | 상대적으로 짧음 |
| 적용 시기 | **FTQC 단계** | **NISQ 또는 중간 단계** |

**🧠 IonQ가 에러 완화 및 부분 정정에 계속 투자하는 이유**

**1. 리소스 현실성**

- BB5, Bacon-Shor, LDPC 등은 **물리 큐비트 수가 많아야 의미 있음**.
- 하지만 IonQ의 Tempo/Forte는 아직 수십~수백 큐비트 레벨 → 전체 QEC는 **과잉 설계(over-provisioned)**.
- 반면, CliNR은 **오직 3:1 오버헤드**로 실행 가능 → **현재 QPU 자원에 현실적으로 부합**.

****

**2. 결과 품질 대비 효율**

- 전체 QEC를 쓰지 않아도, 특정 Clifford 구간만 정밀하게 수행하면 **전체 알고리즘 충실도(Fidelity)가 크게 개선됨**.
- 즉, ROI(자원 대비 성능 향상 비율)이 더 높음.

****

**3. 적용 속도와 고객 응용**

- 예: 금융, 물류, 물리 시뮬레이션 등 실제 고객 사례에서는 **시간·정확도 균형**이 중요.
- 완전 오류 정정보다 **빠르고 덜 복잡한 방법**이 현 시점에서 **시장성 높음**.

****

**4. 실험적 확장 경로 확보**

- CliNR은 **정확도 개선**뿐 아니라 **실험적 디버깅 도구**로도 유용:
- 특정 연산만 정밀 측정 → 오류 분포 분석 → 향후 QEC 설계에 반영
- 즉, **QEC 연구에도 간접 기여** 가능.

****

**5. 전략적 전환 단계를 위한 다리 역할**

- **완전 오류 정정은 궁극적인 목표**이지만,
- 그 중간 단계에서 **부분 정정/완화 기술은 기술적으로나 비즈니스적으로 필수 다리** 역할을 함

****

**🧩 BB5와 CliNR은 근본 철학이 다르지만, 상호보완적**

|  |  |  |
| --- | --- | --- |
| **구분** | **BB5 (****Bivariate Bicycle Code** **+ 5, Full QEC)** | **CliNR (Clifford Noise Reduction, Partial QEC)** |
| **기반 이론** | 서브시스템 오류 정정 (Stabilizer code 기반) | Clifford 연산의 구조적 특성 활용 |
| **목표** | **오류 없는 논리 큐비트 생성 및 유지** | **Clifford 연산 구간의 정밀도 향상** |
| **오류 모델** | 임의의 물리적 에러 (X, Z, Y) 대응 | Clifford 연산 중 주로 발생하는 오류 (dephasing, depolarizing) 중심 |
| **적용 범위** | 전체 회로/연산 흐름 | 연산 중 일부 시점 / 구간 |
| **리소스 요구** | 높음 (데이터 + 신드롬 + ancilla 큐비트) | 낮음 (3:1 오버헤드) |
| **활용 시점** | 논리 큐비트 기반의 FTQC 단계 | NISQ 또는 중간 단계 (pre-FTQC) |
