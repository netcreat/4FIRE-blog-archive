**✅ 1. 리타이머(Retimer)가 뭔데?**

- - **리타이머는 전기 신호가 길게 이동할 때 생기는 ‘왜곡·감쇠’를 복구하기 위해 중간에서 신호를 재생성하는 회로.**
  - 전기 신호는 배선을 따라 이동할 때:

    - 감쇠(attenuation)
    - 지터(jitter)
    - ISI(inter-symbol interference)
    - 노이즈
    - 주파수 응답 왜곡
  - 이런 문제 때문에 원래 형태를 잃어버린다.
  - ➡ 그래서 일정 거리마다 **리타이머 칩**을 넣어서
  - 신호를 **다시 깨끗하게** 만들고 다음 구간으로 ‘재송신’해야 한다.
  - **쉽게 말하면:**

> ***고속 전기 신호는 멀리 못 가니, “중간중간 전기 충전소”가 필요하다.***
>
> ***그게 리타이머.***

**📌 예시: PCIe, Ethernet에서 리타이머의 역할**

|  |  |
| --- | --- |
| **연결** | **리타이머 필요 여부** |
| PCIe 5.0 32GT/s | 몇 cm~수십 cm 마다 필요 |
| 400G/800G 전기 인터페이스 | 10~20 cm 마다 필요 |
| GPU ↔ GPU 케이블(Direct Attach Cable) | 최대 1~2m |
| 보드 내부 SerDes | 10~20 cm 넘으면 곧바로 감쇠 발생 |

- - **즉, 메인보드나 패키지 내부에서도 전기신호는 멀리 못 간다.**
  - 그래서 대규모 AI GPU 클러스터는 리타이머가 수백~수천 개 들어간다.

**📌 문제: 리타이머는 “성능”과 “전력”을 많이 먹는다**

- - 800G/1.6T 시대에서는:

    - 1개 포트당 리타이머 ≈ **1~2 W** 전력
    - 스위치 전체 → **수백 W**
    - AI 랙 전체 → **kW 단위**
  - Nvidia/Meta/Google 내부 보고서에서도 나왔듯이 **대규모 AI 클러스터 전력의 30~40%가 “I/O + 리타이머” 전력**이다.
  - 그래서 리타이머는 **AI 시대의 전력 폭탄**.

---

**✅ 2. 전자가 “패키지 크기”에서 제한을 받는 이유**

**✔ 이유 1: 전기 신호는 거리·배선 길이에 극도로 민감**

- - 패키지(패키지 substrate) 안에서도:

    - 배선 길이가 길어지면 감쇠 증가
    - 주파수 응답 저하 → 에러 증가
    - 신호 integrity 확보 어려움
    - 리타이머 or equalizer 필요
  - 즉 **패키지 내부에서도 신호가 멀리 못 간다.**
  - GPU 같은 큰 패키지(100mm2 이상)에서는
  - 멀리 있는 코어끼리 통신할 때 문제가 생긴다.

**✔ 이유 2: 고속 SerDes는 배선 간 간섭(crosstalk)이 크게 증가**

- - 배선을 좁게 만들면:

    - 임피던스 불안정
    - 전력 증가
    - Crosstalk 증가
    - 열 증가
  - 그래서 패키지 안에 배선이 일정 수 이상 밀집되면
  - **속도가 떨어지거나 전력이 폭발**한다.

**✔ 이유 3: 높은 속도 신호일수록 “손실 vs. 거리” 문제 악화**

- - 40 Gbps, 100 Gbps, 200 Gbps 신호는 10cm~20cm 만 가도 원본 신호가 거의 사라짐.
  - GPU 칩 크기 + 기판 길이 + 커넥터 + 케이블을 고려하면 전기 신호는 물리적으로 한계를 갖는다.
  - ➡ **반도체 패키지를 더 크게 만들면 오히려 통신 성능이 떨어짐.**
  - 그래서 Nvidia도 B200·Blackwell 이후:

    - 팬아웃 구조
    - HBM 주변 집중 배치
    - NVLink 도메인 분리
  - 이런 복잡한 구조를 채택하는 이유가 여기 있다.

---

**🔥 3. 그래서 “광자”가 대안으로 떠오른 것**

- - 전자는:

    - 거리 ↑ → 감쇠 ↑
    - 속도 ↑ → 전력 ↑
    - 배선 ↑ → Crosstalk ↑
    - 패키지 ↑ → 손실 ↑
  - 반면 광자는:

    - **거리와 감쇠가 거의 무관**
    - **리타이머 필요 없음**
    - **패키지 크기와 무관**
    - **전력 훨씬 낮음**
  - 그래서 AI 클러스터는 다음과 같은 방향으로 이동 중:

|  |  |
| --- | --- |
| **기술** | **역할** |
| **Co-Packaged Optics (CPO)** | 스위치/가속기 패키지 안에 광학을 직접 넣음 |
| **Optical Interposer (POET 등)** | 광자+전자 집적하여 제조 단순화 |
| **Ayar Labs TeraPHY** | 전기 대신 광링크로 GPU 연결 |
| **Intel Silicon Photonics** | 전기 배선 한계를 광링크로 대체 |

> ***즉 리타이머 폭발 문제 + 패키지 크기 한계가 광자 통신이 필수가 된 핵심 이유.***

---

**✅** **광자의 한계와 경쟁력**

**📌근본적으로 “광자”는 전자처럼 초소형화(scaling)가 안 됨**

1. 1. **파장 제한 (diffraction limit)**

      - 광의 파장은:

        - **1550 nm (1.55 μm)** – 데이터센터용 C-band
        - **1310 nm (1.31 μm)** – 중거리용
      - 반면 전자의 유효 파장은 사실상 **나노미터 이하**, 그리고 금속선·트랜지스터는:

        - **5 nm~3 nm 노드** 수준까지 축소 가능.
      - ➡ **그래서 광소자(레이저, 포토다이오드, 웨이브가이드)가 1~2 μm 수준 아래로 내려가면 손실·산란 증가로 성능이 급격히 악화된다.**
      - **→ 트랜지스터처럼 10배씩 축소하는 스케일링은 불가능.**
   2. **웨이브가이드 폭도 파장 대비 최소 크기 필요**

      - 실리콘 포토닉스 웨이브가이드 폭: **400~600 nm**
      - 금속 배선(전자)은 **20 nm 이하**
      - ➡ 포토닉 회로는 전자 회로보다 **최소 50~100배 넓은 면적을 차지**.
   3. **광자는 “정전용량 감소” 같은 소형화 이점이 거의 없다**

      - 전자회로는:

        - 배선이 짧아지면 정전용량↓
        - 전력↓
        - 속도↑
      - 광자는:

        - 파장이 크기 때문에 규격을 줄여도 손실 증가, 모드 붕괴 발생
        - 더 작게 만들수록 성능 악화
      - ➡ 결국 **광소자는 일정 크기 이하로 줄이면 오히려 손해**.
   - ➡ **칩 사이즈 증가 → 비용 증가**는 장기적 단점.

**📌 그럼에도 불구하고 광자가 필요한 이유**

- - **전자는 더 이상 확장(Scaling)이 안 되고 있기 때문.**
  - AI 데이터센터의 병목은:

    - GPU 간 통신 속도
    - 백플레인 전력 소비
    - 열 처리
    - 100 m 이상 거리 연결
  - 전자 기반 인터커넥트(NVLink, PCIe, SerDes)는:

    - **전력 비용 폭증 (AI 클러스터의 30~40%가 I/O 전력)**
    - **속도 스케일링 둔화**
    - 신호 감쇠 증가 → 리타이머/증폭기 필요
    - 라우팅 복잡성
  - 그래서 GPU·ASIC 회사(Microsoft, Amazon, Intel, Nvidia)는 **전기 → 광자 전환을 선택****할 수밖에 없음.**
  - 광자는:

    - 거리 제한 없음
    - 전력 소비 매우 낮음
    - 주파수 대역폭 매우 넓음
    - 전기신호 재증폭(리타이머)이 필요 없음
    - 병렬 채널 수 증가 용이

> ***즉, 광자는 "더 작게 만드는 기술"이 아니라 "더 멀리, 더 빠르게, 더 적은 전력으로"의 기술.***

**📌 “광자는 작아질 수 없다면 어떻게 경쟁력을 가지나?”**

- - **소형화가 아니라 ‘집적(integration)’으로 해결**

    - 개별 광부품(레이저·PD·모듈레이터)이 작아지지 않아도
    - → 이들을 한 플랫폼 위에 집적하면 전체 부피와 비용을 줄일 수 있다.
    - 예:

      - 구글, MS, Meta → **Co-Packaged Optics (CPO)**
      - POET → **Optical Interposer**
      - Intel → **Silicon Photonics UCIe 광링크**
    - 이 방식은 “모듈 하나의 크기”가 아니라 “패키지 전체의 효율”로 승부하는 전략.
  - **전자처럼 대량 생산 가능한 제조 방식으로 전환**

    - 기존 포토닉 모듈의 문제는:

      - **능숙한 엔지니어가 현미경 보고 레이저를 정렬하는 방식** → 비용·속도 가장 큰 병목
    - POET이 말하는 “Semiconductorization of Photonics”는:

      - 정렬 자동화
      - 웨이퍼 수준 조립
      - pick-and-place 자동화
      - 패시브 alignment
    - 즉,
    - 광자가 작아지지 않아도, 제조 공정이 반도체처럼 자동화되면
    - → 가격과 생산성이 전자 산업 수준으로 진입한다.

**✅광전송 Use Case**

- - **광전송(광인터커넥트, optical I/O)은 앞으로 CPU·GPU·NPU 모두에 들어갈 것이 확실**하고, 이미 여러 회사들이 **프로토타입 또는 초기 상용화 단계**까지 왔다.
  - 즉, 현재는 **데이터센터 네트워크 → 스위치 → NIC** 중심이지만, 미래에는 **CPU/GPU 패키지 내부, 칩-간 직접 연결까지 광자 통신이 확장**될 것이다.

**1. 이미 지금 광전송을 사용하는 곳**

- - **데이터센터 스위치 → 서버 간 연결 (최대 시장)**

    - **→** **이미 전체 데이터센터 트래픽의 90% 이상이 광자 기반 전송****임.**
  - **NIC (Network Interface Card) 내부 전송**
  - **HPC(슈퍼컴퓨터) 인터커넥트 일부**
  - **🔥 결론: 스위치 ↔ 서버 ↔ NIC는 이미 완전한 광자 기반 세계.**

****

**2. 이제 막 시작된 광전송 도입 분야 (GPU, NPU, AI 칩)**

- - **GPU ↔ GPU 직접 광전송 (Ayar Labs + Nvidia, Intel)**
  - **NVIDIA**

    - Blackwell 이후 세대인 **Rubin** 세대부터 NVLink 전기 인터페이스를 **광전송 옵션**으로 확장한다는 오피셜 정보 존재.
    - 스위치 패키지에 **CPO(Co-Packaged Optics)** 채택 중.
    - Nvidia는 이미 Ayar Labs와 여러 번 공동 데모를 한 상태
  - **Intel**

    - **Ayar Labs TeraPHY** = 최초의 완전한 광 I/O 칩
    - Intel Gaudi·Xeon에서 시연
    - 2.5D 패키지 기반으로 **칩 바로 옆에 광 I/O 연결** 가능
    - Intel은 2026~2027 상용화를 목표로 함.
  - **Google / AWS / Meta**

    - 이미 자체 실리콘 포토닉스팀을 운영하며 GPU/TPU에 광전송 통합 준비 중.
  - ➡ **AI 시대에 GPU ↔ GPU 대역폭이 병목이라 광전송이 필수.**

****

**3. 다른 최우선 도입 분야**

- - **메모리 인터커넥트 (HBM 이후 세대)**

    - HBM4/5 이후 대역폭 증가 한계 때문에
    - 광자 기반 메모리 버스가 연구 중 (Samsung, SK Hynix)
  - **칩렛 간 광링크 (UCIe Optical)**

    - 칩렛 구조가 보편화되면서
    - 칩렛 ↔ 칩렛 연결을 광자로 하려는 시도 증가.

      - Intel, AMD, TSMC, GlobalFoundries 모두 연구 중
      - Broadcom도 optical SerDes 발표함
  - ➡ **칩렛 세상에서는 전기 배선이 너무 많은 문제를 일으킴.**

****

**✅광전송 시장의 상황**

**🟩 1) 전환 규모가 너무 크다 (GPU 1개 → 광포트** ***수십 개*****)**

- - GPU·CPU가 광I/O로 바뀌면 구성 방식이 완전히 달라짐
  - 예:

    - 오늘날 800G NIC → 1개
    - 미래 GPU → **광I/O 16~64개 탑재 (Tbps~10Tbps 급)**
  - 즉, **광 포트 수요가 10배~30배 증가**함.
  - 이 시장은 아직 열리지도 않았고, 클라우드 3사+엔비디아만 해도 수백억 달러 규모임
  - ➡ 아직 시작조차 안 했다.

**🟨 2) 진짜 난이도는 “광전송을 칩에 집적하는 것”**

- - 지금까지 우리가 얘기한 건:

    - GPU ↔ GPU 광I/O
    - CPU ↔ 메모리 광I/O
    - 칩렛 ↔ 칩렛 광I/O
    - 패키지 내부 CPO
  - 이런 건 **아직 상용화 안 됐고, 시연/프로토타입 단계**임.
  - 즉, 이런 기업들이 만들어야 하고 해결해야 하는 문제:

|  |  |
| --- | --- |
| **문제** | **해결한 기업** |
| 레이저를 칩 옆에 수동 정렬 없이 붙이는 것 | POET |
| 전력 없이(TIA 없이) 광신호 수신하는 것 | Ayar Labs |
| 대량 생산 가능한 광패키징 | 없음 (시작 단계) |
| GPU 내부에 광 I/O 집적 | 없음 (2026~2028 예상) |

- - ➡ **기술적으로 해결된 부분보다 해결되지 않은 부분이 더 많음.**

****

**🟥 3) 지금은 “Ethernet → Photonics 대전환”의 시작점**

- - 역사로 보면 지금은 2010년의 스마트폰 시장 같은 느낌이다.
  - **2010년 스마트폰 시장이 초기였던 이유:**

    - 이미 Nokia/Blackberry가 “휴대폰”을 만들고 있었지만
    - 진짜 시장은 “모바일 OS + 앱 생태계 + 프로세서 집적화”가 열리면서 시작됨
  - 광I/O도 마찬가지

    - 지금은 “광 모듈” 시대고, 다가오는 건 **“모든 칩이 광 커넥터를 갖는 시대.”**

****

**🟦 4) 시장 규모가 너무 커서 경쟁자 수가 부족할 정도**

- - 업계 분석:

    - **2025 광모듈 시장: $14B**
    - **2030 광I/O + CPO 시장: $100B 이상** (10배 성장)
    - **2040 광 커넥티드 컴퓨팅 전체 시장: $300B 이상**
  - 성장률이 “반도체보다 더 빠름.”
  - 지금 기술을 가진 회사는 너무 적고(3곳), 수요는 Nvidia·Google·Amazon·Meta·Microsoft·Tesla 등 전 세계 모든 AI 기업이 다 필요함.
  - ➡ 공급 부족이 심각해진다는 보고가 이미 나와 있음.

**🟩 5) 비교 기준: 이 시장은 아직** ***전기에서 광으로 전환하는 초입기***

- - 현재 전체 I/O의 95%는 여전히 **전기**임.
  - 광I/O로 이동하는 비중은 **5% 미만**.
  - 전기 → 광 전환은 앞으로 10~15년 동안 계속될 “메가 트렌드.”
  - 즉:

> ***“너무 많은 기업이 구현해서 기회가 없다”가 아니라 지금은 광I/O 시장의 1%만 열린 상태.***
>
> ***나머지 99%가 앞으로 열릴 시장이다.”***
