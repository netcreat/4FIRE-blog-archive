**✅****Relay-BP란 무엇인가?**

"Relay‑BP ('Relay‑ensembling with locally‑averaged memory')"의 이름으로, Tanner Graph 기반의 QEC 디코더다.

**💡****내부 알고리즘 구성 요소 (Relay-BP)**

- **DMem-BP (Disordered Memory Belief Propagation)**

  - 기존의 Belief Propagation(BP)에 메모리 항을 추가해 진동(oscillation)을 줄이고, 균형 잡힌 메시지 흐름을 유지하도록 한다.
  - 특히, 메모리 강도(memory strength)를 노드마다 다르게(disordered) 설정해 수렴성과 정확도를 개선한다.
  - 메모리 강도 값은 양수부터 **음수**까지 허용되며, 이는 동일성(symmetry)으로 인한 고착(trapping set)을 깨뜨리는 역할을 한다.
- **Relay 앙상블 (Relay Ensembling)**

  - 여러 DMem‑BP 실행 단계를 이어 붙여, 각 단계(leg)는 이전 단계의 최종 마지널(marginals)을 초기화(input)로 사용한다.
  - 각 단계는 해(solution)를 찾거나 지정된 최대 반복(iteration) 횟수를 채우면 종료된다.
- **전체 알고리즘 흐름 (Pseudocode 요약)**

  - Relay‑BP는 다음과 같은 인자를 사용해 전체 구조가 정의된다:

    - **찾으려는 해의 수 (stop\_nconv)**
    - **릴레이 단계 수 (num\_sets)**
    - **각 단계별 최대 반복 횟수 (set\_max\_iter 혹은 pre\_iter)**
    - **각 단계의 메모리 강도 설정 (gamma distribution 또는 explicit gammas)**
- **프로세스 요약:**

  - 첫 번째 DMem‑BP 단계 실행 → 초기 marginals + gamma 설정 사용
  - 수렴 또는 반복 제한 도달 시 종료 → 다음 단계로 넘어감 (마지널 전달)
  - 모든 단계 종료 시, 모든 단계에서 찾은 해 중 가장 낮은 weight(에러 확률을 최소화하는 해)를 반환

**💡****요약**

Relay-BP는 메모리 기반의 BP 변형(DMem-BP)과 여러 단계 연계(relay ensemble)를 결합해,

- - **진동과 수렴 문제를 교정하고**
  - **다양한 시작 조건에서 여러 해를 탐색해 정확도를 높이며**,
  - **FPGA 등 실시간 디코딩 하드웨어에 적합한 구조**를 갖는데 초점을 맞춘 알고리즘.

**✅****Tanner 그래프란?**

- **정의**:

  - 부호(코드)의 패리티 검사 행렬 H를 이분 그래프(bipartite graph)로 표현한 것.

    - **변수 노드(Variable Node, VN)**: 코드워드의 각 비트(또는 큐비트)에 해당
    - **검사 노드(Check Node, CN)**: 패리티 검사식(행)에 해당
- **엣지 연결**:

  - H 행렬에서 **1**이 있는 위치 → 해당 변수 노드와 검사 노드를 연결.

**💡****양자 코드에서**

- qLDPC나 서피스 코드도 H(X), H(Z) 두 개의 패리티 행렬을 각각 Tanner 그래프로 표현 가능.
- X 안정자, Z 안정자 각각이 검사 노드 역할.

**💡****Tanner 그래프 기반 디코더**

- **로컬 정보로 전역 오류 추정**: 각 노드가 인접 노드로부터 받은 정보만 가지고 갱신.
- **병렬 처리 가능**: FPGA/ASIC 구현에 적합.
- **코드 구조 직관적 이해**: 연결 관계를 시각적으로 파악 가능.
- 아래는 Tanner 그래프 예시

  - **노드 두 종류**:

    - **Variable Node (VN)**: 코드워드 비트(혹은 큐비트)
    - **Check Node (CN)**: 패리티 검사식(혹은 안정자)
  - **엣지 연결**:

    - H 행렬에서 1인 항목 → 해당 VN과 CN을 연결

**💡****왜 Tanner Graph라고 부르나?**

- **Michael Tanner**라는 캐나다의 전자공학자가 1981년에 처음 제안했고, 제안자의 이름을 붙여서 Tanner Graph라 부른다.
- 그의 논문에서 **LDPC(Low-Density Parity-Check) 코드**의 구조를 시각화하는 수단으로 Tanner 그래프를 도입했다.
- 사실 그래프 자체의 수학적 구조(이분 그래프, bipartite graph)는 이미 존재하던 개념이었지만,
- “코드의 패리티 검사 행렬을 이분 그래프로 나타내는 방법”을 정보이론에 본격적으로 적용한 것이 Tanner의 공로다.

**💡****어디에 쓰이나?**

- **클래식 통신/코딩**

  - **LDPC 코드 디코딩**: Belief Propagation(BP), Min-Sum 등 메시지 전달 알고리즘이 Tanner 그래프 위에서 동작.
  - **Turbo 코드**, **Polar 코드**에서도 내부 구조를 그래프로 표현할 수 있음.
- **양자 오류 정정**

  - **qLDPC 코드**, **CSS 코드**, **서피스 코드** 등에서도 X 안정자, Z 안정자를 각각의 Tanner 그래프로 표현 가능.
  - BP, BP-OSD, Relay-BP 같은 디코더가 Tanner 그래프에서 신드롬을 바탕으로 오류 추정.
- **기타**

  - Constraint Satisfaction 문제(CSP), 예: Sudoku, SAT solver 시각화
  - 신호 처리, 확률 그래프 모델링, AI(예: Factor Graphs와 구조 공유)

> CSS는 **Calderbank–Shor–Steane code**의 약자임
>
> 1990년대 중반에 **Andrew Calderbank, Peter Shor, Andrew Steane**이 각각 독립적으로 제안한 **양자 오류 정정 코드(QECC)** 설계 방식으로서, CSS 코드는 두개의 고전 선형 코드를 이용해 양자 코드를 만드는 방법
>
> 대부분의 dLDPC 계열이 CSS 구조를 가짐

**💡****왜 중요한가?**

- **시각적 이해**: 코드의 구조를 그림으로 표현하니 직관적으로 오류 전파와 검출 과정을 이해 가능.
- **알고리즘 구현 용이**: BP 등은 VN ↔ CN 간 국소(local) 업데이트만 하면 되므로 병렬 처리 및 하드웨어 구현이 쉬움.
- **범용성**: 고전 코드뿐 아니라 양자 코드, AI 확률 모델, 최적화 문제에도 동일한 그래프 구조를 적용 가능.
- **희소성**: LDPC 계열 코드의 경우, H가 희소하므로 Tanner 그래프도 연결 수가 적어서 메시지 전달이 빠름.

**💡****Tanner 그래프 기반 디코더의 공통 특징**

- **로컬 정보로 전역 오류 추정**: 각 노드가 인접 노드로부터 받은 정보만 가지고 갱신.
- **병렬 처리 가능**: FPGA/ASIC 구현에 적합.
- **코드 구조 직관적 이해**: 연결 관계를 시각적으로 파악 가능.

> Tanner 그래프는 LDPC, qLDPC, 서피스 코드 등 희소한 패리티 검사를 갖는 코드들의 “지도” 같은 역할을 하고,
>
> 이 위에서 메시지를 전달하는 알고리즘(BP 계열, Bit-Flipping 계열 등)이 디코딩의 핵심을 이룬다.

  - 신드롬이 주어질 때마다 메시지가 반복 갱신되며 오류 위치를 추론함

**✅****BP, BP-OSD, Relay-BP의 차이**

**1. 기본 BP (Belief Propagation)**

- **개념**

  - Tanner graph(혹은 factor graph) 위에서 **변수 노드 ↔ 검사 노드** 간 메시지를 반복적으로 주고받아 신드롬(syndrome)에 맞는 오류 패턴을 추론.
  - 주로 저밀도 패리티 검사 행렬(LDPC) 기반 디코딩에 사용.
  - 양자 버전은 qLDPC나 서피스 코드에도 적용 가능.
- **특징**

  - **메모리 항 없음**: 이전 반복에서 보낸 메시지의 영향을 제한적으로만 반영 → 진동(oscillation)이나 국소 최소(local minimum) 문제 발생 가능.
  - 구현이 단순하고 빠름.
  - 오류율이 낮으면 잘 작동하지만, **고잡음 환경이나 구조적 trapping set**에서는 성능 저하.

**2. BP-OSD (Belief Propagation + Ordered Statistics Decoding)**

- **개념**

  - BP로 얻은 LLR(Log-Likelihood Ratio) 기반 신뢰도 순위(ordered statistics)를 매겨, 신뢰도가 낮은 비트(큐비트)를 플리핑해 탐색 공간을 줄이는 보정 단계 추가.
  - 기본 BP 후에 후처리(post-processing)를 통해 ML(Maximum Likelihood)에 가까운 성능을 얻음.
- **특징**

  - 성능은 BP보다 훨씬 높음 — ML 근사치에 접근.
  - 하지만 **복잡도 증가**: OSD 단계에서 조합 탐색을 수행하므로 연산량이 많음.
  - 실시간(예: FPGA, ASIC) 환경에는 부적합할 수 있음.
  - 반복회수가 적더라도 OSD가 무겁기 때문에 레이턴시↑.

**3. Relay-BP (Relay-ensembling with Locally-Averaged Memory)**

- **개념**

  - BP에 메모리 항(memory term)을 추가한 변형인 **DMem-BP** 사용.
  - 각 노드마다 메모리 강도(γ)가 다름(disordered) → trapping set 탈출에 유리.
  - 이전 반복 메시지를 부분적으로 유지(averaging) → 진동 억제.
  - **릴레이 앙상블(relay ensemble)**: 여러 DMem-BP 단계를 순차 실행, 이전 단계 결과(marginals)를 다음 단계 초기값으로 전달.
- **특징**

  - **정확도**: 고잡음 환경에서 BP보다 훨씬 안정적, BP-OSD에 근접하거나 상회하는 경우 있음.
  - **연산량**: BP보다 많지만, OSD보다 훨씬 가벼움 → 실시간 하드웨어 구현 가능.
  - **FPGA/ASIC 최적화**: 병렬성 유지, 메모리 강도 파라미터로 성능 조절 용이.

**4. 비교 요약 표**

|  |  |  |  |
| --- | --- | --- | --- |
| **항목** | **기본 BP** | **BP-OSD** | **Relay-BP** |
| **구조** | 반복적 메시지 전달 | BP + 신뢰도 기반 비트 플립 탐색(후처리) | DMem-BP 단계 여러 개를 릴레이 연결 |
| **메모리 항** | 없음 | 없음 (BP 단계에는 없음) | 있음(노드별 γ 값 다름) |
| **성능** | 중간 (저잡음에서 좋음) | 높음 (ML 근접) | 높음 (OSD에 근접, 경우에 따라 상회) |
| **복잡도** | 낮음 | 매우 높음 | 중간 |
| **하드웨어 적합성** | 매우 좋음 | 낮음 | 좋음 |
| **장점** | 단순, 빠름 | 최고 성능, 에러 플로어 낮음 | 성능/복잡도 균형, 실시간 가능 |
| **단점** | trapping set, 진동 문제 | 연산량·메모리 소모 큼 | 구현 복잡도 BP보다 약간 높음 |

**5. 비유**

- **BP(Belief Propagation)이 전달받은 것을 믿고 다시 전파하기, 즉 들은대로 다시 전달하는 방식이라 우리가 잘 알고 있는 "고요속의 외침"과 같다.**
- **다만 듣고 전달하는 과정에서 오류가 발생할 수 있기 때문에**

  - 왁자지껄이 왕자..가 될 가능성이 높음 (Standard BP). 빨리 진행되지만 결과는 그닥.
  - 누군가가 의심 스러운 사람이 누군지 판단하고 게임에서 뺄지 결정하면(BP-OSD) 훨씬 신뢰도가 높지만, 과연 걸러내는 작업을 누가 어떻게 할지가 핵심
  - 기존에 게임을 몇번 해봤으면 대략 누가 구멍인지 감이 오니까 판단하기 훨씬 쉬워진다.(Relay-BP)

- **Standard BP (Belief Propagation) – 기본 버전**

  - 비유: 친구들이 원을 만들어 앉아 있고, 서로 전달 게임을 하는 상황. 각자 들은 소문을 옆 사람한테 전달하며, 점점 정확한 정보를 만들어 가는 게임이에요.
  - 문제점: 어떤 친구들이 계속 서로 같은 말만 반복하거나, 틀린 소문에 갇혀버릴 수 있음. → “진동” 혹은 “덫(trapping set)”에 빠짐.
  - 장점: 간단하고 빠름.
  - 단점: 복잡한 상황(잡음이 심한 경우)에서는 정확도가 떨어짐.
- **BP-OSD (Belief Propagation + Ordered Statistics Decoding)**

  - 비유: BP 게임을 한 다음, “누가 말을 제일 의심스럽게 하고 있는지” 신뢰도 순위를 매겨서, 그 중 의심스러운 몇 명을 골라 다시 확인 조사하는 방식.
  - 효과: BP가 잘못 짚은 부분도 잡아낼 수 있어서 결과가 훨씬 정확해짐.
  - 문제점: 이 확인 조사 과정이 시간도 오래 걸리고, 경우에 따라서는 모든 조합을 다 따져봐야 해서 무거움.
  - 장점: 정확도 최고 수준.
  - 단점: 실시간 게임(즉시 결과)에는 부적합.
- **Relay-BP (Relay-ensembling with Locally-Averaged Memory)**

  - 비유: BP 게임을 하되, 각 친구가 지난번에 무슨 말을 했는지 조금씩 기억해서, 이번에 말할 때 그 기억을 반영함(메모리 항).
  - 그리고 한 번의 게임이 끝나면, 그 결과를 다음 게임에 넘겨주는 릴레이 방식으로 여러 번 진행.
  - 효과: 같은 실수를 반복하지 않고, 잘못된 소문에서 벗어날 가능성이 높아짐.
  - 장점: 정확도가 BP보다 훨씬 좋고, BP-OSD에 거의 근접. 그런데도 속도는 BP-OSD보다 훨씬 빠름.
  - 단점: BP보다는 복잡하고, 구현이 조금 더 어려움.
