**💡Case 1 : 단순한 경우**

- - 원래 비트: 001
  - 오류 발생: 중간 비트가 잘못되어 011이 됨 → 복구 불가 (다수결 판단 불가능)
  - 즉, 단순히 원래 비트만 두고는 오류를 바로 고칠 수 없다.

**💡Case 2 : 3중 반복 코드**

- - **인코딩**:

    - 001 → (000)(000)(111)
    - 즉, 각 비트를 세 번 반복하여 저장
  - **오류 발생**:

    - (000) → (001)
    - (000) → (000)
    - (111) → (011)
  - **디코딩**:

    - (001)은 다수결 → 0
    - (000)은 다수결 → 0
    - (011)은 다수결 → 1
  - 따라서 최종 결과: 001 (원래 값으로 복구 성공)

**💡Case 3. 5중 반복 코드 - 최대 2비트 플립까지 정정 가능**

- - **인코딩**:

    - 001 → (00000)(00000)(11111)
  - **오류 발생**:

    - (00000) → (01100)
    - (00000) → (00001)
    - (11111) → (01100)
  - **디코딩 (추가 설명 필요 부분)**:

    - (01100) → 다수결은 0
    - (00001) → 다수결은 0
    - (01100) → 다수결은 0 - 최대 플립 오류 허용 개수인 2를 넘은 3개의 오류가 생겨서 복원이 불가.
  - 따라서 최종 디코딩 결과는 001이어야 함에도 복원 결과가 000이 나왔다.

**💡****Code distance**

- - 코드 거리는 오류 정정 코드의 **강도**를 나타내는 지표이다.
  - 정의: 서로 다른 두 코드워드(codeword) 사이의 최소 해밍 거리.
  - 반복 코드에서는 d번 반복하면 코드 거리는 d가 된다.
  - 표에 나온 것처럼:

    - d=3 → 최대 1비트 플립 오류 정정 가능
    - d=5 → 최대 2비트 오류 정정 가능
    - d=7 → 최대 3비트 오류 정정 가능
  - 따라서 거리 d인 코드는 최대 **(d−1)/2**개의 오류를 정정할 수 있다.

**💡****패리티 그래프**

- - 비트 노드(위쪽 원)와 검사 노드(아래쪽 사각형)로 구성된 **패리티 검사 그래프**(Parity-check graph)이다.

    - 구조가 이분 그래프(biparitite graph)형태라서 그래프.

      - 한쪽 집합 : 비트 노드들 (데이터)
      - 다른 쪽 집합 : 체크 노드들 (제약조건)
      - 간선(edge) : "이 체크 노드가 어떤 비트들을 검사하는지"를 연결
  - 각 체 노드는 연결된 비트들의 합을 *mod* 2로 계산한다.

    - *mod* 2 란 어떤 수를 2로 나눈 나머지를 취하는 연산
  - 왼쪽: 모든 비트가 0 → 모든 검사 결과도 0 (에러 없음)
  - 오른쪽: 몇몇 비트가 1로 바뀌었음 → 연결된 검사 노드들이 1로 바뀌면서 에러 위치를 감지할 수 있다.
  - 이 구조는 LDPC(Low-Density Parity-Check) 코드나 서페이스 코드 같은 실제 오류 정정 코드의 기본 원리와 연결된다.

- - 여기서는 **실제 오류 수정** 과정이 예시로 나온다.
  - 그래프 위에서 두 개의 비트가 플립되었음(Flip 표시).
  - 검사 노드 값(아래쪽)이 이를 감지하고, 오류 위치를 역추적해 비트를 원래 값으로 복구한다.
  - **주요 포인트**

    - 오류 정정은 논리 비트의 실제 값을 몰라도 가능하다.
    - 하지만 반복 코드는 **단 하나의 논리 비트(logical bit)만 인코딩**할 수 있다 → 이것이 가장 큰 한계이다.

**💡해밍 코드**

- - **해밍 코드**는 단순 반복 코드보다 효율적으로 오류를 정정할 수 있는 고전 오류 정정 코드이다.
  - 원형 노드 = 데이터 비트, 사각형 노드 = 패리티 검사 비트.
  - 예시:

    - 왼쪽 그림: 특정 검사 노드가 bit1 + bit3 + bit5 + bit7 mod 2를 검사하는 구조.
    - 오른쪽 그림: 실제 데이터(0010110)가 주어졌을 때 각 검사 노드가 계산한 패리티 값이 모두 0 → 오류 없음.
  - 장점: 더 적은 오버헤드로 단일 비트 오류를 감지하고 정정 가능하다.

- - 여기서는 한 비트가 플립되었음을 가정한다.
  - 검사 노드 출력(010)이 바뀌어 **특정 패턴**이 형성된다.
  - 이 패턴이 바로 신드롬(syndrome)으로, 어떤 비트가 잘못되었는지 직접 알려준다.
  - 따라서 오류를 찾아내고 원래 값으로 되돌릴 수 있다.

> 지난편에서 언급했듯이 1996년 Andrew Steane이 개발한 **Steane Code**는 **Hamming Code**를 기반으로 만든 양자 에러 코드이다.
