✅ **QEC를 둘러보기 전 이해하고 있어야 할 개념**

**📌** **1. Pauli 연산자 집합 {I,X,Y,Z}**

- - QEC는 오류를 Pauli 연산자의 조합으로 모델링한다.
  - 각 오류는 X (bit flip), Z (phase flip), Y (bit+phase flip)로 환원 가능.
  - 모든 오류는 이들의 선형 조합으로 분해 가능하다는 전제가 stabilizer QEC의 핵심.

****

**📌** **2. Tensor Product Notation**

- - 다중 큐비트를 표현할 때 사용하는 텐서곱 개념.
  - 예: *X*⊗*I*⊗*Z* → 3큐비트 연산에서 첫 번째에 X, 세 번째에 Z 작용.
  - 오류 모델링과 stabilizer 연산자 구성에 필수.

****

**📌** **3. 양자 중첩과 측정의 비가역성**

- - 오류는 측정을 하지 않고 상태를 바꾸는 과정으로 발생한다.
  - 측정을 하면 상태가 붕괴되므로, 측정 없이 오류 탐지가 핵심.
  - "간접 측정"을 위해 ancilla qubit이 도입된다.

****

**📌** **4. 얽힘 (Entanglement)의 역할**

- - 오류를 수정하려면 큐비트 간 얽힘이 있어야 함.
  - 예: 3-qubit bit-flip code에서 오류 위치를 판별하려면 얽힘 구조 필요.
  - QEC는 얽힘을 통해 정보를 분산시켜 보호한다.

****

**📌** **5. Ancilla Qubit (보조 큐비트)**

- - 원래의 논리 큐비트를 손상시키지 않고 오류 여부를 알아내기 위해 사용됨.
  - Syndrome 측정 시 ancilla를 통해 오류 정보를 간접적으로 추출함.
  - ancilla는 QEC 회로에서 측정용 인터페이스 역할.

****

**📌** **6. Quantum Circuit 모델 (gate-based model)**

- - QEC는 양자 회로 내에서 구현되므로, 회로 관점의 이해가 필수.
  - 게이트 적용 순서, 병렬성, 측정 순서가 논리 오류율에 영향을 줌.
  - CNOT, Hadamard, Measurement 연산의 동작을 정확히 이해해야 함.

****

**📌** **7. Noise Model**

- - 현실적인 오류 모델링이 있어야 QEC가 의미를 가짐.
  - 대표 모델:

    - Bit flip: X 오류
    - Phase flip: Z 오류
    - Depolarizing noise: X,Y,Z 오류가 확률적으로 섞임
  - Pauli error channel을 기반으로 설계하는 게 stabilizer 코드의 기본 전략

****

**📌** **8. 클리포드 연산자 (Clifford Group)**

- - 많은 QEC 회로는 Clifford 연산자로 구성됨.
  - X,Z,H,S,CNOT 등은 Clifford 연산자이며, Pauli 연산자를 보존함.
  - Clifford 연산자만으로 오류가 퍼지는 양상을 제어 가능함.

****

**📌** **9. 측정 결과의 해석 (Syndrome)**

- - 오류 자체는 직접 측정하지 않음 → ancilla를 이용해 Syndrome이라는 패턴으로 오류 탐지.
  - 예: "어디에 오류가 났는지는 모르지만, 어떤 종류의 오류가 발생했는지는 앎."
  - Syndrome은 오류를 고치는 단서이지, 정답은 아님 → **디코딩 알고리즘 필요.**

---

✅ **1. [[*****n,k,d*****]] — 양자 오류 정정 코드의 파라미터**

- - **이 표기법은 QEC 코드의 핵심 특성 3가지를 요약한 것**

|  |  |  |
| --- | --- | --- |
| **기호** | **의미** | **설명** |
| **n** | 총 **물리 큐비트 수** (physical qubits) | 오류 정정 코드를 구성하기 위해 사용하는 전체 큐비트 수 |
| **k** | **논리 큐비트 수** (logical qubits) | 오류로부터 보호되는 실질적인 정보량 (논리 정보) |
| **d** | **코드 거리 (minimum distance)** | 최대 몇 개의 오류까지 정정할 수 있는지를 나타내는 지표 |

**📌** **예시:**

- - **[[7,1,3]] Hamming code 기반 QEC:**

    - 7개 물리 큐비트 사용
    - 1개 논리 큐비트 보호
    - 오류 2개까지 검출 가능(d=3 →⌊(d−1)=2)
    - 오류 1개까지 정정 가능 (d=3 →⌊(d−1)/2⌋=1)

---

✅ **2. 코드 거리** ***d*****의 의미**

|  |  |  |
| --- | --- | --- |
| **코드 거리 d** | **정정 가능 오류 수** | **검출 가능 오류 수** |
| 3 | 1개까지 정정 | 2개까지 검출 |
| 5 | 2개까지 정정 | 4개까지 검출 |
| 일반적으로 | ⌊(*d−1)/2*⌋ | *d−1* |

> 거리 *d*는 **얼마나 많은 오류까지 논리 정보를 보호할 수 있는지를 결정**한다.

---

✅ **3. O(⋅) 표기 — 점근적 크기 표현 (빅-오 표기법)**

- - **알고리즘 이론 및 복잡도 분석에서 사용하는 표기법이지만, QEC에서는 확장성, 효율성, 자원 요구량 분석에 자주 사용된다.**

|  |  |  |
| --- | --- | --- |
| **표기** | **의미** | **QEC 내 해석** |
| *O(n)* | 선형 크기 | qubit 수 증가에 따라 논리 큐비트 수 or 거리도 비례 증가 |
| *O(√n)* | 제곱근 증가 | Surface code 등에서 최소 거리 증가 속도 |
| *O(log⁡n)* | 로그 성장 | 매우 효율적인 자원 사용 (거의 존재하지 않음) |

**📌** **예시:**

- - **Surface Code의 최소 거리:**

    - ***O(√n)*** **(거리 증가가 느림)**
  - **Balanced Product Code:**

    - ***k=O(n), d=O(n)*** **(정보량과 보호능력 모두 선형)**

---

✅ **보너스: 좋은 QEC 코드란?**

- - **좋은 양자 오류 정정 코드는 다음 특성을 가진다:**

|  |  |
| --- | --- |
| **목표** | **설명** |
| **높은** ***k/n*** | 더 적은 큐비트로 더 많은 논리 큐비트를 보호 |
| **높은** ***d*** | 더 강한 오류 정정 능력 |
| **낮은 stabilizer weight** | 연산 복잡도 감소, 실험 적용 용이 |
| **LDPC 구조** | 디코딩 효율과 구조 간소화 가능 |

---

**✅ 양자 오류 정정 코드(QEC)의 핵심 구성 요소**

|  |  |  |
| --- | --- | --- |
| **구분** | **구성 요소** | **역할** |
| 📐 **논리 구조** | **QEC Code (e.g. surface, qLDPC, color)** | 물리 큐비트들 위에 논리 큐비트를 인코딩하는 방법을 정의함 |
| 🧩 **상태 유지** | **Stabilizers** | 특정 상태가 유지되도록 강제함 (**오류 감지 및 코드 공간 정의**) |
| 🧪 **오류 감지** | **Syndrome Extraction Circuit** | stabilizer 값을 측정하여 오류의 존재와 위치를 감지함 |
| 🧠 **오류 해석** | **Decoder** | syndrome 값을 바탕으로 어떤 오류가 발생했는지 추정하고 보정함 |
| 🔧 **정정 동작** | **Recovery Operator** | 디코더가 지시한 오류에 맞춰 실제로 역게이트를 적용함 |
| 🔁 **반복 실행** | **QEC Cycle Scheduler** | 주기적으로 syndrome 추출과 디코딩을 반복함 (보통 수백~수천 번) |
| 📥 **초기화** | (Optional) **Encoder** | 초기 상태를 QEC 코드 공간으로 변환 (보통 한 번만 실행) |

✅ **LDPC 코드란?**

- - LDPC (Low-Density Parity-Check) 코드는 희소한(=low-density) 패리티 검사 행렬을 기반으로 한 오류 정정 코드다.
  - 1960년 Robert Gallager에 의해 처음 고안되었고,1990년대 후반 turbo 코드와 함께 재조명되며 오류 정정 분야의 혁신을 이끌었다.

[![](https://upload.wikimedia.org/wikipedia/commons/thumb/9/96/Robert_Gallager.jpg/250px-Robert_Gallager.jpg)](#)

출처 : 위키피디아 Robert G. Gallager

- - **이더넷, Wi-Fi, 5G, 위성TV, 플래시 메모리, SSD** 등 다양한 실용 기술에 널리 사용된다.
  - 기존 오류 정정 코드보다 **성능이 수배 향상**되었으며, **채널 용량 근접** 성능을 실현할 수 있다.
  - **인코더 디코더가 쌍으로 동작**
  - **성능의 핵심: 디코딩**

    - LDPC는 **반복적 추론 기반의 BP 디코딩 알고리즘**과 궁합이 뛰어나다.
    - 잘 설계된 LDPC 코드는:

      - 채널 용량(capacity)에 거의 근접하는 **정확도**
      - **선형 시간 복잡도(linear decoding time)**
      - **블록 길이 증가에 따라 오류 확률이 거의 0에 수렴**
  - **설계 구조: 희소한 Tanner 그래프**

    - LDPC 코드는 보통 Tanner 그래프 형태로 표현된다:

      - '=' 노드: 변수 노드 (정보 비트)
      - '+' 노드: 팩 노드 (패리티 조건)

출처 : 위키피디아 (6,3)LDPC 코드

- - - 각 노드는 소수의 연결선만 가짐 → 회로가 간단하고 연산량이 작음
    - 이 구조는 에러 정정 시 회로 깊이를 줄이고 병렬화 가능성 증가
  - **예시: (6, 3) LDPC 코드**

    - 메시지 비트 3개를 코드워드 6개로 인코딩

      - 즉 오류가 없는 상황에서 보낼 메시지는 3비트로 이루어져 총 23=8개의 메시지가 나오는데,
      - 3비트만 보내면 받는 쪽에서 오류를 검출 할 수 없으니 패리티 비트 3개를 추가해서 총 6비트를 보내는 것이다.
    - 결과적으로 8가지 유효한 코드워드만 존재함
    - 중복을 통해 채널 오류에도 복원 가능성 증가

✅ **qLDPC Code**

- - 고전적인 LDPC의 개념을 **양자 오류 정정 코드**에 확장한 것이 바로 **qLDPC 코드**이다.

****

**📌 qLDPC에서 인코딩과 디코딩**

- - 인코더는 "정보 큐비트를 오류 정정 코드의 논리 상태로 바꾸는 회로"다.
  - 이건 일반적으로 단 한 번만 수행됨

    - 알고리즘 시작 전에 논리 상태를 초기화하거나,
    - T-state, GHZ 상태 등을 증류할 때만 사용됨

**📌 디코딩은 QEC의 핵심**

- - 디코더는 반복적으로 수행된다:

    - 매 QEC 라운드마다 syndrome을 측정하고 → 오류 위치 추정 → 보정
  - 수백~수천 번의 QEC 라운드 동안:

    - 인코딩은 한 번뿐, 디코딩은 수천 번 반복
  - 디코딩이 정확하지 않으면:

    - 오류가 누적되고 → 논리 오류 발생 → 전체 알고리즘 실패

> 디코더가 정확하고 빠르게 동작하는 것이 FTQC에서 가장 중요하다.

- - **Surface Code와 비교해서 더 적은 물리 큐비트로 같은 효과를 낼 수 있지만, 보다 복잡한 디코더가 필요하다.**
  - 먼저 지금까지 알려진 qLDPC 코드는 어떤 것들이 있는지 잠깐 짚고 넘어가자.

****

**📌 qLDPC Code 종류**

- - Homological Codes - 2D 격자 기반, topological 보호, 고전적 surface code의 연장

    - **Surface Code**
    - **Toric Code**
    - Hyperbolic Code
  - Product-Based Codes - 고전 LDPC 부호의 텐서곱 구조 (CSS 형태), 이론상 **확장성 우수**

    - Hypergraph Product
    - Balanced Product
    - Lifted Product
  - Graph-Based Codes - Tanner 그래프, Expander 그래프 기반 → distance와 rate 동시에 확보

    - **Quantum Tanner Code**
    - **Quantum Expander Code**
    - **Good LDPC Codes**
  - Circulant Matrix Codes - 반복 가능한 순환 행렬 기반 구조, BB 계열로 대표됨

    - **BB6 Code**
    - **BB5 Code**
  - 특수 목적/경량 실험 최적화 - 실험 구현 최적화 (소형, 저복잡도) — Gröss가 대표적

    - Gröss Code
  - Optimized Variants - 기존 코드의 구조 변형 (예: stabilizer 방향성 재조정)

    - **XZZX Surface Code**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **코드 종류** | **주요 논문 / 제안자** | **구조적 특징** | **장점** | **단점** |
| **Hypergraph Product Code** | Tillich & Zémor (2009) | - 고전 LDPC 코드 2개를 텐서곱 형태로 결합  - CSS 구조 | - 임계점(threshold) 존재  - 수학적 구조 명확 | - 코드 길이에 비해 최소 거리 작음: *d=O(√n)***** |
| **Balanced Product Code** | Panteleev & Kalachev (2022) | - 비대칭 대신 균형 잡힌 텐서곱 구조  - 모든 stabilizer weight와 variable degree가 일정 | - FT threshold 존재  - 거의 선형 시간 디코딩 가능 | - 설계 복잡도 높음 |
| **Good LDPC Code** | Panteleev & Kalachev (2021–2022) | - 논리 비트 수 k, 최소 거리 d, 큐비트 수 nn  이 동시에 선형 관계 | - 최초의 asymptotically good qLDPC | - practical decoding은 여전히 어려움 |
| **Lifted Product Code** | Breuckmann & Eberhardt (2021) | - hypergraph product의 일반화  - homological code의 확장 | - threshold 개선  - 작은 블록 사이즈에서도 성능 우수 | - 디코딩 복잡성 |
| **Quantum Bicycle Code (BB6)** | Roffe et al. (2023) | - circulant 행렬 기반  - weight-6 stabilizer LDPC 코드 | - 구조가 반복적이고 구현 용이 | - *d*가 상대적으로 낮고 무게가 약간 높음 |
| **BB5 Code** | **Nicolas Delfosse****,**Min Ye  (2024/2025) | - BB6에서 발전된 weight-5 구조  - 이온체인에 최적화 | - 더 낮은 오류율, 더 적은 보조 큐비트(ancilla) | - 구조 설계에 제약 존재 |
| **Homological Code** (Toric/Surface 등) | Kitaev (1997), Bravyi & Kitaev (1998) | - 2D 격자 위에서 정의됨  - local stabilizer, LDPC 구조 만족 | - 매우 강한 실험적 검증  - **단순하고 robust** | - 최소 거리 *d=O(√n)*  - 낮은 logical qubit 수 |
| **2D Hyperbolic Code** | Breuckmann & Terhal (2016) | - 음의 곡률을 가진 2D 격자 기반 | - surface code보다 logical qubit 수 증가 | - 임계점 낮음 |
| **Quantum Tanner Code** | Leverrier et al. (2021) | - 고전적인 Tanner 그래프 기반 qLDPC | - 선형 distance, 선형 rate | - 복잡한 디코딩 요구 |
| **Quantum Expander Code** | Hastings (2021), Leverrier et al. | - expander 그래프 기반  - 빠른 mixing과 오류 확산 방지 | - 빠른 디코딩  - threshold 존재 | - 구현 복잡도 높음 |
| **XZZX Surface Code** | Bonilla Ataides et al. (2021) | - XZ-ZX 형식의 stabilizer  - 비표준 격자 방향성 | - 비대칭 오류에 매우 강함 | - syndrome decoding 복잡 |
| **Gröss Code** | Gröss et al. (2022~)  IBM | - small-size qLDPC  - 낮은 stabilizer weight  - 실험 친화적 구조  - FT 수준에 못미침 | - 실험 구현 쉬움  - 다양한 플랫폼 적용 가능 | - 낮은 거리, 낮은 logical qubit 수  - 확장성 제한  - 최대 30개 큐비트 |

✅ **2025년 4월 IonQ의 연구 성과 요약**

**📌 연구 배경 및 목적**

- - 양자 오류 수정(QEC)은 FTQC(오류 허용 양자 계산)의 핵심 요소.
  - 긴 이온 체인(trapped-ion chain)은 긴 코히런스 시간과 전-쌍 연결성(all-to-all connectivity)이라는 장점이 있어 LDPC 코드에 유리한 하드웨어 구조로 평가됨.
  - **기존 QEC 기법(예: surface code)은 주로 슈퍼컨덕팅 큐비트 아키텍처에 최적화******돼 있음.

****

**📌 Ion Chain Model 정의**

- - IonQ와 같은 이온트랩 장비의 특징을 반영한 모델로, 다음의 제약 조건을 포함함:

    - 전 연산은 순차적(단일 유니터리 게이트만 한 번에 실행 가능)
    - 측정은 느리지만 병렬 가능
    - 게이트 후 노이즈 모델: depolarizing 노이즈 수준

      - 2큐비트 게이트는 오류 확률 p,
      - 1큐비트는 p/10,
      - 유휴 큐비트는 p/100
    - 모든 큐비트 간 2큐비트 게이트 가능 (이온 체인의 핵심 장점)

****

**📌 신드롬 추출 회로(Syndrome Extraction Circuit)**

- - 알고리즘 1: 이온 체인 모델에 맞춘 오류 시그널 추출 회로 설계

    - ancilla 수를 가변적으로 조절
    - 모든 큐비트 연결 가능하므로 하나의 ancilla로 모든 stabilizer 측정 가능 (슈퍼컨덕팅에선 불가)
  - 알고리즘 2: ancilla 수를 최적화하여 논리 오류율과 오버헤드 간의 트레이드오프 조절

****

**📌 BB5 코드 제안 및 성능 비교**

- - 기존의 BB6 코드(weight-6)에서 발전된 BB5 코드(weight 5) 제안

    - Weight란 하나의 stabilizer가 작용하는 물리 큐비트의 개수
    - weight가 작을수록 더욱 효율적
  - 예시:

    - [[30, 4, 5]] BB5 vs [[30, 4, 4]] BB6 → 최소 거리 1 향상
    - [[48, 4, 7]] BB5 vs [[48, 4, 6]] BB6
  - BB5 코드는 적은 큐비트로 같은 또는 더 낮은 논리 오류율을 달성함

    - [[48, 4, 7]] BB5 코드 → 논리 오류율 ≈ [[49, 1, 7]] surface code
    - 그러나 논리 큐비트 수 4배, 전체 큐비트는 더 적음 (54 vs 57)

      - BB5 코드 : [[48, 4, 7]], 48+6=54

        - 논리 큐비트를 4개 보호하면서 총 54개 물리 큐비트 사용
        - 데이터 큐비트 수 n=48
        - 튜닝된 ancilla 수 na=6 (아래 표 참조)
      - Surface 코드 : [[49, 1, 7]], 49 + 8=57

        - 논리 큐비트를 1개 보호하면서 총 57개 물리 큐비트 사용
        - 데이터 큐비트 수 n=49
        - 튜닝된 ancilla 수 na=8 (아래 표 참조)

✅ **BB5 코드란?**

- - BB5 코드는 **기존에 존재하던 알고리즘이 아니라, 새롭게 제안된 코드의 변형 및 확장된 형태**이다.
  - 정확히 말하면, BB5는 기존의 **Bivariate Bicycle (BB) 코드** 계열에서 파생된 **새로운 변형 코드이다.**
  - 기존 연구자들이 찾지 못한 **[[48,4,7]]** 같은 고성능 코드를 체계적인 검색 및 최적화를 통해 발굴하고, BB5라는 이름으로 명명해 제시한 것이다.
  - 이 코드는 특정 하드웨어 모델(긴 이온 체인)에 최적화되어 설계되었기 때문에, 하드웨어 맞춤형 LDPC 코드 설계의 좋은 사례로 평가됨

|  |  |
| --- | --- |
| **항목** | **내용** |
| 기존 | **BB6 코드** (Bivariate Bicycle Code) |
| 정의 | 두 circulant 행렬을 기반으로 생성된 **weight-6 stabilizer**를 가지는 CSS 코드 |
| 출처 | [Panteleev & Kalachev, 2022], [Roffe et al., 2023] 등에서 다룸 |
| 새 제안 | **BB5 코드** (이 논문에서 명명) |
| 특징 | **Weight-5 stabilizer**를 갖도록 수정하여, **논리 오류율 감소와 qubit 절약** 효과 도입 |
| 기여 | BB5는 **기존 BB 코드 구조를 일반화**하여 새로 설계한 것으로, 특정 사례([[30,4,5]])는 예전에 다른 논문에서 부분적으로 발견된 바 있으나, 체계적인 **BB5 설계 및 명명은 본 논문이 최초** |

   3. **Surface Code**

      - **장점**

      - **단점**

        - 오버헤드 (101:1)

      - 논리 큐비트 위에서 **논리 게이트 실행까지 포함한 전 주기 연산**을 시연
   4. **BB5** [**[2503.22071] Quantum error correction for long chains of trapped ions**](https://arxiv.org/abs/2503.22071)

          - ancilla 수 최적화에 한계

✅ **디코더란 무엇인가?**

**📌 역할:**

- - QEC 코드가 주기적으로 syndrome (오류 징후)를 측정함.
  - 디코더는 이 syndrome 값을 받아,

    - 어떤 오류가 발생했는지 추정하고,
    - 어떻게 보정할지 결정한다.

> **"이 시점에서 어떤 Pauli 오류가 있었던 것 같으니, 여기에 맞춰 반대 연산을 해줘"라는 판단**을 내리는 역할이다.

**📌 디코더가 중요한 이유**

|  |  |
| --- | --- |
| **요소** | **영향** |
| 🎯 정확도 | 디코딩 오류가 많으면 정정 실패 → 논리 오류 증가 |
| 🕒 속도 | 실시간 디코딩 지연 시 FTQC 불가 (오류 누적됨) |
| 💻 리소스 | 디코딩 연산이 무겁다면 QPU보다 classical overhead가 병목이 됨 |

| --- | --- | --- | --- | --- |
| **디코더 이름** | **코드 유형 예시** | **특징** | **장점** | **단점** |
| **Minimum Weight Perfect Matching (MWPM)** | Surface Code | 가장 보편적, 실제 실험 사용 | 빠름, 구현 쉬움 | LDPC·복잡한 topology에는 부적합 |
| **Union-Find Decoder** | Surface Code | 구성 간단, 병렬화 쉬움 | 속도 빠름, 구조 단순 | 정확도는 MWPM보다 낮음 |
| **Belief Propagation (BP)** | LDPC, BB5 등 | 확률 기반 추론 | LDPC에 적합, 병렬화 가능 | Loops에 취약함 |
| **BP-OSD (Ordered Statistic Decoding)** | BB5, BB6 | BP에 OSD 후처리 추가 | 매우 높은 정확도 | 느림, 하드웨어 실시간 어려움 |
| **Neural Network Decoder** | Surface, LDPC, etc. | ML 기반, 훈련 필요 | 다양한 noise model 대응 | 훈련 필요, generalization 한계 |
| **Lookup Table** | Small Code (e.g., [[5,1,3]]) | 미리 계산된 오류→수정 맵 | 초고속 | 확장성 없음 |
| **Tensor Network Decoder (e.g., PEPS)** | Color Code 등 | 다차원 상호작용 대응 | 정확도 높음 | 계산량 매우 큼 |
| **Renormalization Group Decoder** | LDPC 등 | multi-scale 구조 사용 | 이론적 성능 좋음 | 실전 구현 어려움 |

**📌 디코더 선택 기준**

|  |  |
| --- | --- |
| **상황** | **적합 디코더** |
| **Surface Code, 실험적** | MWPM, Union-Find |
| **LDPC 계열 (BB5, Tesseract 등)** | BP, BP-OSD |
| **속도가 중요 (실시간 QEC)** | Lookup table, Union-Find |
| **정확도가 중요 (Magic state 정제)** | BP-OSD, PEPS decoder |
| **노이즈 모델이 복잡할 때** | Neural decoder |

> **디코더는 QEC의 뇌 역할**을 하며,
>
> 어떤 QEC 코드를 쓰든지 **얼마나 빠르고 정확하게 오류를 추정하고 보정하느냐**에 따라 시스템의 성공이 갈린다.
>
> BB5 같은 LDPC 계열은 일반 surface code보다 훨씬 정교한 디코더를 필요로 한다.

✅ **FTQC에서의 IonQ의 현재와 미래**

- - 최근 QEC 상용화 우선순위 지표에서 IonQ의 BB5는 상위권에 이름을 올리지 못했다. 반면 Quantinuum은 Carbon Code와 Tesseract Code로 1위와 2위를 차지하며, QEC 기술 개발에 쏟는 집중도와 실험적 완성도를 명확히 보여주었다.
  - 하지만, IonQ는 과거에도 조용히 기술적 전환점을 만들어 온 기업이다. 그리고 지금, 다시 한 번 중대한 전환점을 준비하고 있다.

**📌** **IonQ + Oxford Ionics: 하드웨어 기반의 잠재력**

- - IonQ는 Oxford Ionics와의 통합을 통해 **세계 최고 수준의 게이트 충실도**와 **업계 최상위 집적도를 갖춘 하드웨어 플랫폼**을 구축 중이다.
  - 특히 Oxford Ionincs는 **DARPA QBI 프로그램**을 위한 목적이긴 하지만, 호주의 **Iceberg Quantum**과도 **qLDPC 아키텍처 개발**을 협력하고 있다.

**📌** **연구진의 내력: Delfosse, Muller의 존재감**

- - 현재 IonQ의 수석 연구원인 **Nicolas Delfosse**는 직전까지 **6년간 마이크로소프트 퀀텀**에서 핵심 연구원으로 활동했으며, 그 시절에 **Hypergraph Product Code** 관련 논문을 다수 발표했다. 또한 최근에는 **개인 자격으로 해당 코드 최적화에 대한 연구 논문**도 공개했다.
  - 또한 IonQ는 호주의 Emergence Quantum과 협력한다는 뉴스를 오늘 발표했는데, Emgergence Quantum은 Microsoft Quantum Sydeny에 속해 있던 직원들이 만든 기업으로서, CTO이자 CSO인 Thomas Ohki는 **DARPA** 프로그램에 참여했었던 이력이 있다.
  - 여기에 더해, 최근에는 전 IARPA Director였던 **Rick Muller**가 **Quantum Systems 부문 전무로 IonQ에 합류**했다.
  - 그는 IARPA 이전에는 **미 에너지부(DOE)** 산하 국가 양자 이니셔티브(NQI)의 핵심 기관인 QSA (Quantum Systems Accelerator)의 Director로, **양자 우위를 달성하기 위한 알고리즘, 하드웨어, 공학적 설계의 공동 최적화**를 주도했던 인물이다.
  - 이러한 이력은 그가 단순한 임원이 아닌, **IonQ의 차세대 QEC 기술 전략 수립에 깊숙히 관여할 가능성**을 강하게 시사한다.

**📌** **미래 예측: Hypergraph Product + BP-OSD?**

- - 이러한 기술적 정황과 인물 구성을 종합하면, IonQ와 Oxford는 **Hypergraph Product Code** 혹은 그에 준하는 **Balanced Product Code** 같은 고급 qLDPC 코드를 중심으로, **BP-OSD (Belief Propagation + Ordered Statistics Decoding)** 기반의 디코더 조합을 전략적으로 채택할 가능성이 높아 보인다.
  - 물론, 이들 코드는 **구조 설계가 복잡**하고, BP-OSD는 **디코딩 연산량이 매우 크다**는 단점이 있다.
  - 하지만 Oxford의 마이크로파 기반 이온 트랩 시스템은 **극한의 충실도와 연결성을 제공**하며, IonQ의 시스템 아키텍처는 **복잡한 디코딩까지 감당 가능한 충분한 처리 능력**을 확보해가고 있다.

✅ **결론**

- - IonQ는 지금껏 항상 “조용하지만 결정적인 변화”를 만들어왔다. BB5 이후 다소 정체된 것으로 보일 수 있지만, **Oxford의 하드웨어**, **Iceberg와의 협력**, **Microsoft에서 넘어온 연구진**, 그리고 **IARPA/QSA를 이끌던 리더십**까지 모두 고려하면 그들은 분명히 **qLDPC 시대에 걸맞은 새로운 QEC 전략**을 준비하고 있다.
  - 그리고 그 전략의 핵심에는 **Hypergraph Product Code + BP-OSD**, 그리고 그것을 감당할 수 있는 **최고의 물리적 플랫폼**이 존재할 가능성이 매우 높다.
