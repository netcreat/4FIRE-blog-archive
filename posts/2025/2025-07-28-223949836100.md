# 광자, 光子(mitsuko), Photon

Published: 2025-07-28T14:32:59.785000+09:00

Original Naver post: https://blog.naver.com/4-fire/223949836100

---

이 포스트를 준비하면서 광자라는 단어를 많이 사용하다 보니 옛날 영화 제목이 문득 떠올라서, 오마주 해봤다.

[![](http://file.koreafilm.or.kr/poster/00/03/66/DPK04540B_01.jpg)](#)

출처 : KMDb

양자(quantum)의 성질을 이용하여 컴퓨터 연산을 하려고 하면, 0이기도 하고 1이기도 한 중첩 상태가 있어야 한다.

**이온트랩**의 경우에는 **이온을 찜질방에 가둬놓고 열을 가하면 이온들이 살짝 맛이 가서 0인지 1인지 분간이 안되는 상태**로 만들 수 있다.

이번에는 광자를 이용하여 중첩 상태를 만든다는 포토닉 양자 컴퓨터의 작동 원리를 살펴보겠다.

포토닉(광자 기반) 양자컴퓨터는 **빛의 입자인 광자(Photon)** 를 정보의 기본 단위인 큐비트로 사용하는 방식이다. 일반적인 초전도나 이온트랩과는 다른 방식으로, 빛의 특성을 활용한 매우 독특한 접근이다.

---

**🔄 포토닉 양자의 기본개념**

****

**🧊용어 설명**

|  |  |
| --- | --- |
| **용어** | **의미** |
| **Fusion gate** | 두 광자 큐비트를 간섭시킨 뒤, 일부를 측정하여 나머지 큐비트 간에 **얽힘을 형성**하는 연산 |
| **Cluster state** | 계산이 가능한 얽힌 광자들의 네트워크 (예: 체인, 2D 격자 등) |
| **MBQC** | 미리 준비된 클러스터 상태를 이용해 **측정만으로 계산을 진행**하는 양자계산 방식 |
| **Fusion-based MBQC** | Fusion gate를 사용해 클러스터 상태를 점진적으로 생성하고, 그 위에서 측정 기반 계산 수행 |

> **Fusion-based QC**는 얽힌 클러스터 상태를 효율적으로 생성하기 위해
>
> **두 개 이상의 광자를 beam splitter와 측정을 이용해 얽히게** 만드는 기법임
>
> 이 방식은 **직접적인 2큐비트 게이트 대신**, "**얽힘을 확장하는**" 연산을 측정을 통해 수행하는 것이 핵심임.

**🔄 Fusion gate 작동 원리**

두 광자 ψ₁, ψ₂를 beam splitter로 간섭시킴

- - 한 쪽 또는 양 쪽 출력을 측정
  - 측정 결과에 따라 남은 광자들의 상태가 얽힘 상**태로 전환됨**
  - **예: Bell 상태 또는 GHZ 상태의 일부로 진화**

****

**🔄Fusion Gate가 중요한 이유**

- - **직접 게이트 없이 얽힘 생성 가능** → 선형광학만으로 계산이 가능함
  - 확장성이 높음 → 수천/수만 개 광자 얽힘 구조 형성 가능
  - 오류에 강한 방식 구성 가능 (loss-tolerant fusion network)
  - PsiQuantum이 2023년 발표한 "Fusion-based quantum computing"구조에서

    - **single-photon sources** + **fusion gate** + **adaptive measurement** 조합으로
    - **loss-tolerant 2D 클러스터 상태**를 실시간으로 생성
    - 매우 긴 광자 체인도 안정적으로 얽힘 구성 가능

****

**🧊이온 vs. 광자: 본질적 차이 요약**

|  |  |  |
| --- | --- | --- |
| **항목** | **이온 트랩** | **포토닉 방식** |
| 정보의 물리적 구현 | **가둔 이온**의 에너지 준위 | **날아가는 광자**의 편광, 경로 등 |
| 조작 방식 | 마이크로파/레이저로 **직접 연산** | 빔스플리터·위상편이기 등 **간접 연산** |
| 큐비트 상태 유지 | 이온을 트랩에 **오래 가둘 수 있음** | 광자는 전자기장 없이 **날아가므로 지속 유지 불가** |
| 연산의 시점 | 원할 때 연산 가능 (Gate-based) | **광자 생성 → 즉시 연산해야 함 (Measurement-based)** |
| 큐비트 간 상호작용 | **공진 모드 또는 광자 매개** | 얽힘된 상태를 **미리 준비**해야 함 |

**🧊 그래서, 광자를 "가두지 않고" 어떻게 양자 연산을 하나?**

**▶ 기본 전략: "얽힌 광자 자원 상태(Resource state)"를 미리 만들어두고, 그것을 사용해서 계산**

이것이 바로 **"Measurement-based quantum computing (MBQC)"**, 또는 **"One-way quantum computing"** 이라 불리는 방식이다.

****

**🧠 핵심 아이디어: 광자는 가둘 수 없으니, 계산 전에 다 준비해둔다**

**📦 Step 1: 클러스터 상태(Cluster state) 생성**

- - 얽힌 광자 수십~수백 개를 일단 **한꺼번에 만들어 놓음**
  - 마치 양자 회로의 회선도를 먼저 그려놓는 것처럼

**🔎 Step 2: 측정하면서 연산 진행**

- - 광자 하나씩 측정 (측정 기준 축을 조절)해가며 계산
  - 연산은 "피드포워드" 방식: 이전 측정 결과에 따라 다음 측정 조건 변경

> **PsiQuantum**은 "가둘 수 없는 광자를 CMOS 실리콘 공정으로 정밀하게 타이밍 조절"하는 방식으로 이 문제를 해결하려 하고, **Xanadu**는 위상 공간에서 연속적으로 정의되는 상태를 큐비트로 쓰는 GKP 방식을 개발 중이다.

**🔑 핵심 개념: "동시적(spatially simultaneous)"이 아니라 "순차적(temporally structured)"**

광자 클러스터 상태는 보통 이렇게 구성된다:

- - 빛은 여전히 **날아간다**.
  - 하지만 그것들을 **정해진 시간 간격으로 순서 있게 생성**하고
  - **그 사이에 얽힘 연산(fusion gate)** 을 삽입하여
  - 결과적으로 "**연산이 가능한 얽힌 상태를 시간 순서대로 구성**"하는 것이다.

이 구조를 **“Time-domain cluster state”** 또는 **“Temporal-mode photonic cluster state”** 라고 부른다.

****

**🧬 예시: 시간-도메인 클러스터 상태**

**⏱️ 구조**

- - 각 ψₖ는 서로 다른 시간에 생성된 광자이다.
  - 이들은 **지속적으로 생성되며**, 생성된 직후 **다음 광자와 얽힘 연산**이 수행된다.
  - 결과적으로 이 광자들은 **체인 형태의 클러스터 상태를 형성**한다.

**🧊 정적 vs 동적 클러스터 상태**

|  |  |  |
| --- | --- | --- |
| **구조 방식** | **설명** | **구현 예** |
| **정적 (spatial)** | 광자들이 동시에 존재하며 얽힘 (복잡한 회로 필요) | 이론적 모델, 일부 실험 (소규모) |
| **동적 (temporal)** | 광자들이 시간 순서대로 생성되며 얽힘 | 실용 구현 대부분이 이 방식 (PsiQuantum, Xanadu 등) |

> 이 구조는 “광자는 가둘 수 없다”는 제약을 **시간 도메인에서 구조화**함으로써 극복한 아주 영리한 방식이다

**🧊 기술별 비교**

|  |  |  |  |
| --- | --- | --- | --- |
| **항목** | **Fusion-based 포토닉 (PsiQuantum)** | **이온트랩**  **(IonQ, Oxford)** | **초전도체**  **(IBM, Rigetti)** |
| **큐비트 물리구현** | **광자 (Photon)** | 이온의 **전자 에너지 준위** | **조셉슨 접합** 기반 회로 |
| **큐비트 이동성** | 광자 자체가 이동 (전송에 유리) | 셔틀링 또는 정적 다중존 설계 | 고정 위치 (배선 이동 불가) |
| **중첩 생성** | 광자에 편광/시간-bin 인코딩 → 측정 | 레이저로 이온 상태 회전 | 마이크로파 펄스로 회전 |
| **얽힘 생성** | Fusion gate (간섭 + 측정) | 공동 모드 진동 or 광자 중계 | 커플링 버스 또는 공진기 |
| **연산 모델** | **측정 기반 (MBQC)** | **게이트 기반** | **게이트 기반** |
| **T gate 구현** | 측정 + 피드백 기반 (**간접적**) | 레이저 펄스 직접 연산 | 마이크로파 직접 연산 |
| **오류 정정** | Loss-tolerant cluster + fusion lattice | Surface code 또는 **qLDPC** | **Surface code** 또는 LDPC |
| **확장성** | 시간 도메인 클러스터로 논리적 확장 유리 | 고정된 trap 구조, 포토닉 인터커넥트 필요 | 크기가 커질수록 배선/냉각 부담 |
| **측정 시간/속도** | **빠르지만 광자 손실에 민감** | **느림 (ms 단위)** | **빠름 (ns 단위)** |
| **작동 온도** | 실온 가능 (광자는 냉각 필요 없음) | 저온 (이온은 레이저 냉각) | 극저온 (Dilution fridge, mK) |

**🧠 포토닉 양자컴퓨터 작동 원리 개요**

|  |  |
| --- | --- |
| **단계** | **설명** |
| 1️⃣ 광자 생성 | 큐비트를 나타내기 위해 단일 광자(Single Photon)를 생성함. 보통 SPDC나 마이크로링 공진기 등을 사용. |
| 2️⃣ 큐비트 인코딩 | 광자의 다양한 자유도(Degree of Freedom)를 사용해 큐비트를 표현함. 예: 편광, 경로, 위상, 시간 등 |
| 3️⃣ 양자 논리 게이트 구현 | 선형광학 요소(beam splitter, 위상 편이기 등)로 양자 게이트를 구현하거나, 비선형성 또는 측정 기반 연산 사용 |
| 4️⃣ 얽힘 생성 | 광자들 사이의 얽힘을 만들어 양자 정보처리의 기반을 마련함 |
| 5️⃣ 측정 기반 연산 | 얽힌 광자군을 미리 준비하고, 측정 결과에 따라 연산이 결정되는 "MBQC(Measurement-Based Quantum Computing)" 방식이 일반적 |
| 6️⃣ 측정 및 결과 해석 | 광자를 검출기(APD, SNSPD 등)로 측정하여 결과를 얻고 고전적으로 처리함 |

**🌈 광자 큐비트의 표현 방식**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **인코딩 방식** | **|0⟩ 정의** | **|1⟩ 정의** | **사용 원리 / 설명** | **예시** |
| **편광 (Polarization)** | 수직 편광 (V⟩) | 수평 편광 (H⟩) | 광자의 전기장이 진동하는 방향으로 상태 정의 | HWP(하프 웨이브 플레이트)로 ∣ψ⟩=1/√2  (∣H⟩+∣V⟩) 생성 |
| **경로 (Path)** | 위쪽 경로 (Upper path) | 아래쪽 경로 (Lower path) | 빔스플리터로 경로를 나누고 간섭기로 두 경로 간 위상 조작 가능 | Mach-Zehnder 간섭기로 ∣ψ⟩=1/√2(∣위⟩+eiφ∣아래⟩) |
| **시간 (Time-bin)** | 이른 도착 시간 (Early time) | 늦은 도착 시간 (Late time) | 펄스 두 개를 분리해서 서로 다른 시간에 광자 도착시킴 | 비선형 결정 + 간섭기를 사용해  ∣ψ⟩=1/√2(∣E⟩+∣L⟩) |
| **주파수 (Frequency)** | 낮은 주파수 (예: 적색 광자 ω1) | 높은 주파수 (예: 청색 광자 ω2\omega\_2  ) | SPDC에서 두 광자가 주파수 보존 법칙에 따라 생성됨 | ∣ψ⟩=1/√2(∣ω1⟩+∣ω2⟩) (ω₁ ≠ ω₂) |
| **고차원 (Qudit)** | |0⟩, |1⟩, ..., |d−1⟩ (d ≥ 3) 상태 사용 | 추가 상태 사용 (예: |2⟩, |3⟩ 등) | 편광 + 시간 + 경로 등 여러 자유도를 조합하여 d차원 상태 구현 | 시간 슬롯 4개 사용 → 4-수준 시스템  ∣ψ⟩=1/√2(∣0⟩+∣1⟩+∣2⟩+∣3⟩) |

**💡 각 방식 요약 포인트**

1. **편광**: 가장 직관적인 방식. 광자의 전기장 진동 방향 사용 (H/V 또는 R/L)
2. **경로**: 두 개의 물리 경로로 큐비트 정의 (Interferometer 필수)
3. **시간**: 하나의 광자지만 시간 축에서 구별됨 → fiber delay 또는 unbalanced MZI 사용
4. **주파수**: 다른 에너지 레벨(색상)로 구별. 필터링이 중요
5. **고차원**: 큐비트(2-level)를 넘어 다수의 상태를 사용하는 **qudit**로 일반화. 더 많은 정보 저장 가능

**🔧 광자 기반 양자 게이트 구현**

- **선형광학(Linear Optics)** 사용:

  - Beam splitter, phase shifter, wave plate
  - 대표적인 예: **KLM(Knill-Laflamme-Milburn)** 프로토콜
- **얽힘 및 연산 방식**:

  - 광자 간 직접 상호작용이 어려우므로, 대부분 **얽힌 상태를 미리 준비**하고 **측정 기반 계산**을 수행함
  - 주요 기술: **Cluster state quantum computing**, **fusion gate**

**✔️ 가능한 알고리즘 (이론적으로)**

|  |  |  |
| --- | --- | --- |
| **알고리즘** | **Fusion-based MBQC에서 구현 가능 여부** | **비고** |
| **Shor's algorithm** | ✅ 가능 | T gate (π/8) 수행 시 정확도와 자원 소모 중요 |
| **Grover's algorithm** | ✅ 가능 | 다수의 Hadamard, Oracle 회로 구현 가능 |
| **QAOA** | ✅ 가능 | H, CNOT, Rx 등으로 구성됨 |
| **VQE, QPE** | ✅ 가능 | 복잡도는 증가하지만 구현 가능 |
| **GHZ, Bell state** | ✅ 당연히 가능 | 얽힘 생성이 주 방식이므로 오히려 적합 |
| **Surface code QEC** | ✅ 가능 | 2D 클러스터 상태와 연결됨 |

**🧪 대표 기술 예시**

- **KLM 프로토콜 (2001년) : 게이트 기반**

  - 선형 광학 요소 + 측정 + 고전 피드백만으로 게이트 기반의 양자컴퓨터가 가능함을 증명
  - 성공 확률이 낮아 보정 및 중복이 필요 → **실용적 포토닉 QC들은 대부분 측정 기반 연산 (MBQC) 으로 발전**했음
  - QCI(Quantum Computing Inc.)에서 사용
- **클러스터 상태 연산 (One-way QC)**

  - 얽힌 클러스터 상태를 만든 뒤, 측정을 통해 계산 진행
  - PsiQuantum이 이 방식을 사용
- **GKP 코드 사용 (Xanadu)**

  - 광장의 위상 공간에 격자 형태로 논리 큐비트를 인코딩
  - 잡음에 견딜 수 있어 오류 보정에 유리함
  - Xanadu에서 사용

**🔧실제 동작 원리**

**📍 1. 마이크로링 공진기 = 단일 광자 또는 광자쌍 생성기**

마이크로링 공진기는 실리콘 포토닉 칩 위에서 다음과 같은 방식으로 동작한다:

- **비선형 광학 현상 (예:** **SFWM** **또는 SPDC)** 을 통해

  - 펌프 레이저 → 에너지 보존 법칙을 따라 **광자 2개 생성**
- 이 2개의 광자는:

  - 서로 얽힌 상태로
  - 동일한 주파수/다른 주파수/편광/시간 등의 **자유도**로 구별됨

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTA3MjhfNjkg/MDAxNzUzNjcwNDM3OTIw.Lg_9ZnCQL_hh26G1Wo8gvrIM38ncTJlxugbWAz9a37wg.paUjCN6bI2-uOxZwggCRcxJ2Xy9ZU8l-a7z40mNctrQg.PNG/ChatGPT_Image_2025%EB%85%84_7%EC%9B%94_28%EC%9D%BC_%EC%98%A4%ED%9B%84_12_39_42.png?type=w800)](#)

즉, 마이크로링은 **얽힌 광자쌍 생성기** 역할을 하고, 이 광자들을 **큐비트로 사용하려면 추가 조작이 필요**하다.

****

**📍 2. 광자를 큐비트로 쓰려면? → 인코딩과 중첩**

빛은 스스로 중첩된 상태로 존재하지 않는다. **중첩은 "두 상태의 선형 결합"이므로**, 우리가 **광자의 두 상태를 잘 정의하고, 그 위에 연산을 가해야 중첩이 생다.**

예를 들어:

- - **편광 기반 인코딩**
  - **시간 기반 인코딩 (Time-bin)**
  - **연속 변수 위상 공간**

**📍 3. 마이크로링 + 간섭기로 큐비트 만들기 예시**

1. 마이크로링 공진기에서 **광자쌍 생성**

   - → 두 광자가 서로 **얽힌 상태**로 나옴 (예: 시간-bin 얽힘)
2. 간섭기(예: Mach-Zehnder Interferometer)를 이용해 두 경로를 중첩시킴

   - → 한 광자당 **중첩 상태가 만들어짐**
3. 특정 **위상 시프트**를 추가해 |0⟩과 |1⟩ 간의 위상을 조정함

   - → 일반적인 큐비트 상태 ∣ψ⟩=α∣0⟩+β∣1⟩ 구성 가능

****

**📍 4. 중첩이 생기는 핵심: 간섭 (Interference)**

- **광자는 본질적으로 중첩될 수 있는 파동이다.**
- 간섭기를 통해 두 경로를 겹치게 만들면,

  - 그 경로 위에 있던 광자 상태가 중첩됨
  - 즉, "이 경로에 있었을 수도 있고, 저 경로에 있었을 수도 있는 상태"로 됨

> **마치 이중 슬릿 실험에서 슬릿을 통과한 광자가 어느 슬릿을 지났는지 모를 때 interference pattern이 생기는 것과 같다.**

**🎯 결론**

👉 마이크로링 공진기는 **큐비트의 재료인 광자쌍을 생성**할 뿐이며, **큐비트로 인코딩하고 중첩을 형성**하려면 그 뒤에 **간섭기, 위상 시프터, 편광 필터 등 양자 광학 장치**를 거쳐야 한다.

**🧭 결론**

포토닉 양자컴퓨터는 엄격한 잣대를 들이대면 **게이트 기반 방식이 아니기 때문에**, 게이트 기반 유니버설 양자컴퓨터에서 구현 가능한 **모든 게이트나 알고리즘이 "이론적으로는" 구현 가능하지만**, **공학적 현실에서는 그 실현 가능성이 분명히 다르다**.

**📉"이론적 가능성"과 "실제 구현" 사이의 간극**

|  |  |  |  |
| --- | --- | --- | --- |
| **상태** | **포토닉 (Fusion)** | **이온트랩** | **초전도체** |
| 이론적 유니버설성 | ✅ | ✅ | ✅ |
| 실용 알고리즘 구현 예 | ❌ 없음 | ⚠️ 일부 실험적 구현 | ⚠️ IBM은 ~127 큐비트로 small-scale 시연 |
| 대규모 QEC 적용 | ❌ 연구 단계 | ⚠️ Quantinuum, IonQ 시도중 | ⚠️ IBM이 시도 중 |
| Shor 2048bit 가능? | ❌ 불가능 | ❌ 불가능 | ❌ 불가능 |

위 표에서 보듯이, **아직 상업적으로 완전히 설득력을 갖춘 양자컴퓨터 방식은 없다**.

하지만, **포토닉 기반**은 "유니버설"이라는 이론적 조건 하에서, **그** **존재 가치를 실증적으로 증명해야 하는 중요한 전환점********에 있다.**

그럼에도 불구하고, 포토닉 방식에는 분명한 장점이 존재한다. 이는 **광자를 정보 단위로 사용하는 데서 오는 물리적 이점**에서 비롯된다

|  |  |
| --- | --- |
| **이유** | **설명** |
| 📡 **빛은 상호작용이 적고 멀리 이동 가능** | 전자, 이온과 달리 광자는 진공이나 광섬유를 빠르고 손실 없이 이동 |
| 🔗 **얽힘 상태 전파 가능** | 두 큐비트 간 광자를 이용해 Bell 상태 또는 GHZ 얽힘 생성 가능 |
| 🧊 **극저온 필요 없음** | 광자 자체는 실온에서 동작 가능 (물론 광자 소스나 감지기는 다를 수 있음) |

한마디로 요약하자면, **광자는 실온에서 멀리 이동할 수 있기 때문에** **"통신용"으로 매우 적합**하다.

사용자 또는 투자자의 입장에서는 **굳이 하나의 방식만 고집할 필요는 없다.** 각각의 기술이 가지는 장단점이 뚜렷하다면, **분산 투자를 통해 리스크를 관리할 수 있다.** 또한, 만약 **두 가지 이상의 장점을 절충할 수 있는 기업**이 존재한다면, **그 기업이야말로 가장 우선적으로 주목해야 할 대상**일 것이다.

가장 신뢰있는 양자컴퓨터는:

- - **게이트 기반 유니버설 양자컴퓨터**를 지향하면서,
  - **신뢰도 높은 이온트랩 아키텍처**로 연산을 수행하고,
  - **QPU 간 통신과 확장을 위해 광자 얽힘을** 병행하려 한다.

이는 **계산과 통신 양쪽의 강점을 모두 흡수하려는 전략**으로, 매우 스마트한 접근 방식이라 평가할 수 있겠다.

물론, 아직 위의 조건을 모두 만족시키는 기업은 아직 없다. 따라서, **투자자가 할 수 있는 최선의 전략은**, 각 기술 기업들의 동향을 예의주시하며, **완성 가능성과 시장 점유율 확대 가능성이 가장 높은 곳을 선별해 나가는 일**일 것이다.
