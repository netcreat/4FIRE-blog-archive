**⚛️양자 네트워크란?**

**1️⃣ 양자 네트워크의 핵심 개념**

- **양자 얽힘(Entanglement)**

  - 두 개 이상의 큐비트가 서로 떨어져 있어도 상태가 상관된 상태
  - 얽힌 상태를 분리된 두 노드 간에 공유하면, 한쪽의 상태 측정이 다른 쪽에도 영향을 미침
  - 장거리 양자 통신과 양자 인터넷의 핵심 자원
- **양자 상태 전송(Quantum State Transfer)**

  - 큐비트를 그대로 전송하기보다, 양자 텔레포테이션(Quantum Teleportation)을 통해 상태를 전달
  - 얽힘과 고전 통신(Classical Communication)을 함께 사용
- **양자 중계기(Quantum Repeater)**

  - 얽힘의 거리를 확장하기 위해 중간 지점에서 얽힘을 확장하고 정제
  - 기존 광섬유 통신처럼 신호를 증폭하는 방식이 불가능(양자 상태는 복제 불가, **No-Cloning Theorem**)
- **양자 오류 정정(QEC)**

  - 광섬유 감쇠, 잡음, 위상 불안정 등으로 얽힘과 양자 상태가 쉽게 깨짐
  - 이를 보호하기 위해 양자 오류 정정 코드(QEC)를 사용

**2️⃣ 양자 네트워크의 기본 구성요소**

|  |  |  |
| --- | --- | --- |
| **구성요소** | **역할** | **예시 기술** |
| **양자 노드(Quantum Node)** | 큐비트 생성·저장·처리 | 트랩드 이온, 초전도 큐비트, 광자자 |
| **양자 메모리(Quantum Memory)** | 얽힘을 저장하여 네트워크 지연 허용 | 전통적 희토류/원자 집합 기반 메모리,  QPU 큐비트 기반 메모리,  SiV 다이아몬드 칩 기반의 memory-enhanced interconnect |
| **양자 광원(Quantum Light Source)** | 단일광자·얽힌광자 생성 | SPDC(SPONT. Parametric Down Conversion), QD-based Photon Source |
| **양자 채널(Quantum Channel)** | 얽힘 전송 경로 | 광섬유, 위성 링크 |
| **양자 중계기(Quantum Repeater)** | 얽힘을 단계적으로 연결 및 정제 | DLCZ(Duan-Lukin-Cirac-Zoller) 프로토콜,  하이브리드 메모리-광자 시스템 |
| **고전 통신 채널** | 얽힘 기반 전송의 보조 신호 전송 | 기존 인터넷 |

> **용어 정리**
>
> **DLCZ 프로토콜 (Duan-Lukin-Cirac-Zoller) : 2001년 제안된 장거리 양자 통신 프로토콜**

**3️⃣ 양자 네트워크의 동작 원리**

- **얽힘 분배 (Entanglement Distribution)**

  - 광원에서 얽힌 광자 쌍 생성
  - 각 광자를 다른 노드로 전송
  - 다중 홉인 경우, 중계기에서 **Entanglement Swapping** 수행
- **양자 텔레포테이션 (Quantum Teleportation)**

  - 송신 노드: 전송할 큐비트 상태를 얽힌 쌍과 결합
  - Bell 측정 후 고전 채널로 결과 전송
  - 수신 노드: 측정 결과를 바탕으로 상태 복원
- **얽힘 정제 (Entanglement Purification)**

  - 잡음이 많은 얽힘을 여러 개 모아 높은 신뢰도의 얽힘으로 정제

**4️⃣ 양자 인터넷의 단계적 발전 로드맵**

|  |  |  |
| --- | --- | --- |
| **단계** | **특징** | **예시 기술** |
| **1단계: QKD 네트워크** | BB84, MDI-QKD로 보안 키 공유 | ID Quantique, Toshiba QKD |
| **2단계: 단일 얽힘 분배** | 얽힘 생성·전송 가능 | 중국 묵자 위성 |
| **3단계: 양자 반복기·저장** | 장거리 안정적 얽힘 전송 | DLCZ 기반 메모리 |
| **4단계: 양자 통신+컴퓨팅 통합** | 분산 양자 연산, 클라우드 QPU | IonQ·Quantinuum·QuEra 네트워크 실험 |

**5️⃣ 양자 네트워크의 활용 분야**

- **양자 보안 통신**

  - QKD(Quantum Key Distribution)로 절대 안전 암호화
  - 예: BB84, E91, MDI-QKD
- **분산 양자 컴퓨팅**

  - 여러 QPU를 연결해 논리 큐비트 확장
  - 예: IonQ·Quantinuum의 미래 전략
- **양자 센서 네트워크**

  - GPS 없는 위치 측정, 중력파 탐지 등 초정밀 센싱
  - 얽힘 기반 동기화
- **양자 클라우드·양자 인터넷**

  - 사용자는 로컬 QPU 없이도 원격 양자 연산 활용
  - FTQC 시대에 분산형 양자 슈퍼컴 구축

**6️⃣ 현재 대표적 연구·실험 예시**

- **중국 묵자 위성 (2017~)**

  - 세계 최초 위성 기반 얽힘 분배·QKD 성공
  - 1200 km 거리에서 얽힘 유지
- **DARPA·EU Quantum Internet Alliance**

  - 미국, 유럽에서 양자 인터넷 로드맵 진행 중
  - 하이브리드 광자-메모리 중계기 개발
- **IonQ**

  - FTQC를 염두에 둔 분산 양자 컴퓨팅 연구
  - Photonic interconnect 연구 진행

**🛰️ 양자 통신 위성**

**1️⃣ 묵자의 주요 목적과 용도**

- **장거리 양자 키 분배(QKD) 실험**

  - 1000km 이상의 거리에서 **양자 키 분배**를 수행해
  - 지상망으로는 불가능한 초장거리 보안 통신을 검증한다.
  - 예시: **베이징-빈(오스트리아) 간 7,600km 초광역 QKD** 실험 성공(2017~2018)
- **양자 얽힘 분배 실험**

  - 위성에서 생성한 **얽힌 광자 쌍**을 양쪽 지상국으로 각각 전송해
  - 장거리에서도 얽힘 상태가 유지되는지 확인한다.
  - 최대 1,200 km 거리에서 얽힘 유지 성공
- **양자 텔레포테이션 실험**

  - 지상에서 만든 큐비트 상태를 위성으로 전송(텔레포테이션)
  - 얽힘을 기반으로 상태 전송 가능함을 시연
- **글로벌 양자 통신 네트워크의 초기 검증**

  - 장래에 다수 위성과 지상국을 연결해 **지구 규모 양자 인터넷** 구축을 목표로 한다.
  - 현재는 주로 **과학 실험과 국가 보안 통신** 목적으로 사용한다.

**2️⃣ 묵자 위성에 적용된 핵심 기술**

|  |  |
| --- | --- |
| **기술** | **설명** |
| **단일광자·얽힘 광원** | SPDC(Spontaneous Parametric Down-Conversion) 기반, 얽힌 광자 쌍 생성 |
| **고감도 단일광자 검출기** | 위성과 지상국 간의 **매우 낮은 광자 도달률** 대응 |
| **초정밀 위성-지상 광학 추적** | 레이저 비콘으로 cm 수준의 정밀 추적, 광자 손실 최소화 |
| **양자 키 분배(QKD)** | BB84, E91(얽힘 기반), MDI-QKD 등 다양한 프로토콜 실험 |
| **얽힘 스와핑·정제** | 장거리 얽힘 유지를 위해 얽힘을 중계·정제하는 기술 |

**3️⃣ 현재 활용 현황**

- **중국 국가 보안 통신**

  - 베이징~상하이 구간의 지상 양자망과 연동
  - “중국-오스트리아” 국제 보안 통화 성공 사례 존재
- **글로벌 양자 통신 연구**

  - EU, 미국 등과 비교해 세계 최초로 **위성 기반 얽힘 분배 및 QKD 상용화 가능성**을 실험
- **차세대 양자 인터넷 기초**

  - 다중 위성으로 확장 시 지구 규모의 양자 통신 백본 구축 가능성 탐색

**📡QKD 위성 운용을 위한 과제**

묵자(Micius) 위성은 **저지구 궤도(LEO, Low Earth Orbit)** 위성이다.

묵자가 **LEO를 선택한 이유**는 다음과 같다.

- - 광자 신호 감쇠를 최소화하기 위해 대기권 통과 거리를 짧게 한다.
  - 고정밀 추적·지상국 연동이 용이하다.
  - 위성-지상 레이저 링크에서 높은 신호대잡음비(SNR) 확보가 유리하다

**1️⃣카펠라 스페이스(Capella Space) 위성과 비교**

카펠라 스페이스의 위성들은 **SAR(Synthetic Aperture Radar)** 지구관측 위성으로, 양자 통신과 목적과 설계가 완전히 다르다.

핵심 차이는 **임무 목적**이다.

- **묵자**는 광자를 최대한 손실 없이 보내는 것이 핵심이므로 **광학·양자 통신 장비 중심**이다.
- **카펠라**는 지구 관측이 목적이라 **레이더(SAR) 안테나와 RF 통신** 중심이다.

|  |  |  |
| --- | --- | --- |
| **구분** | **묵자(Micius)** | **카펠라 위성(Capella Space)** |
| **목적** | 양자 통신, QKD, 얽힘 실험 | 지구관측, SAR 영상 |
| **궤도** | LEO (~500-600 km) | LEO (~525 km) |
| **센서** | 단일광자 검출기, 광자 광원 | SAR 레이더 안테나 |
| **데이터 유형** | 양자 상태, 키 분배 | 레이더 영상 데이터 |
| **통신 방식** | 광학/레이저 기반 양자 채널 + 고전 채널 | RF 통신으로 지상국에 이미지 전송 |
| **운영 방식** | 실험적, 특정 시간에만 지상국과 통신 | 상업 서비스, 지속 관측 네트워크 |
| **주요 특징** | 얽힘/단일광자 유지, 신호 감쇠 최소화 | 전천후 관측, 낮/밤·날씨 무관 |

**즉, 둘 다 LEO위성이지만**

- 묵자는 **과학 실험 위성 + 양자 인터넷 전초기지**
- 카펠라는 **상업용 지구관측 위성**

으로 설계 철학과 장비 구성이 완전히 다르다.

**2️⃣SAR위성을 양자 통신 기능으로 사용가능할까?**

위성이라는 물리적인 한계와 각 기능들을 구현하는데 있어서 공통적인 조건이 그리 많지 않아서 한 위성에 두개의 기능을 모두 탑재하기에는 실질적으로는 불가능하리라 예상하는데, 그 이유는 다음과 같다.

**🔑하드웨어 통합 과제**

- - **광학 페이로드 추가 문제**

    - SAR은 **레이더 안테나**가 중심인데, 묵자 기능을 추가하려면 **광학 망원경 + 단일광자 검출기 + SPDC 얽힘 광원**이 필요
    - 문제점:

      - 페이로드 질량과 부피 증가
      - 정밀 진동·열 안정화 필요 (SAR 안테나는 대형 구조물로 진동 발생 가능)
  - **광학 추적·포인팅 시스템**

    - 양자 통신은 **cm 단위 정밀 지향**이 필요하다.
    - SAR 운용 시 위성 자세가 미세하게 변하면 포인팅 안정도 확보가 어렵다.
  - **열·전력·진동 환경**

    - SAR은 대출력 RF 송신으로 인해 열·전력 부하가 크다.
    - 단일광자 검출기는 극저온 혹은 온도 안정이 필요한데,
    - SAR 작동 시 발생하는 진동·온도 변화가 광학 장치에 영향을 줄 수 있다.

**🔑임무 스케줄링 과제**

- - **SAR 임무 vs 양자 통신 임무 시간대 충돌**

    - SAR은 지구관측이므로 주야간 전천후 가능
    - 양자 통신은 **야간·맑은 하늘·지상국 가시선 조건이 필요**
    - 두 임무를 동시에 수행하면 **자세 제어와 지향 조건 충돌 발생** 가능
  - **지상국 가시성과 관측 경로 문제**

    - SAR은 광역 스캔 중심
    - 양자 통신은 **지상국 특정 지점 정밀 포인팅** 필요
    - 위성 궤도 계획과 임무 우선순위 조정 필요

**🔑 환경·신호 간섭 과제**

- - **RF 간섭과 광학 장치 공존**

    - SAR은 고출력 X-band~Ku-band 송신
    - 단일광자 검출기는 극미약 신호를 처리 → **전기적 간섭(EMI)** 위험
    - RF 차폐·광학 장치 전자적 격리 설계 필요
  - **기구적 진동**

    - SAR 안테나 회전 또는 전개 시 발생하는 진동이
    - 양자 광학 정렬에 치명적 영향을 줄 수 있음

**🔑 통신 신뢰도 및 데이터 처리 과제**

- - **얽힘 유지 및 손실 최소화**

    - SAR 위성의 흔들림·온도 변화로 인해 광자 경로 안정성 저하
    - 얽힘 스와핑·정제 필요성 증가
  - **데이터 링크 관리**

    - SAR 데이터는 수백 Mbps~Gbps급
    - 양자 통신은 kbps~Mbps급이지만 **실시간성·손실률**이 더 민감
    - 이중 링크(광학+RF) 운용 및 스케줄링 필요

카펠라 스페이스의 위성을 SAR와 양자통신용 각각 별도로 운용하려고 해도 여전히 해결되지 않은 문제는 있다.

**3️⃣LEO 기반 양자 통신 위성 개발 핵심 과제 및 사례**

**🔑 궤도·운용 설계**

- - **LEO 위성 가시성 제한**

    - 지상국 가시선에서만 통신 가능 → 1회 패스 5~10분
    - 다수 위성 군집·최적 궤도 설계 필요
  - **지상국 네트워크 연동**

    - 글로벌 QKD·얽힘 분배 위해 지상 인프라 연계 필수
    - 예: 중국은 베이징–상하이 QKD망과 위성을 통합 운용
  - **묵자 사례**

    - 하루 수 회 통과 시 QKD 수행
    - 국제 실험 시 오스트리아 빈까지 지상망 연계

**🔑 광학·하드웨어 과제**

- - **정밀 포인팅·추적**

    - 단일광자/얽힘 광자는 cm·mrad 오차도 치명적
    - LEO 고속 이동 환경 → 레이저 비콘 + 포인팅 미러 필요
  - **광자 손실·대기 산란**

    - 대기 산란·흡수 및 태양 배경광으로 신호 약화
    - 야간 통신·좁은 빔 다이버전스 설계 필요
  - **단일광자·얽힘 광원 안정화**

    - SPDC 기반 얽힘 광원은 온도·진동 민감
    - 열제어·진동 감쇠 설계 필요
  - **단일광자 검출기 운용**

    - Si-APD: 상온 운용 가능, 효율·다크카운트 한계
    - SNSPD: 고효율·저노이즈, 극저온 크라이오쿨러 필요
  - **묵자 사례**

    - 3중 추적: GPS/INS → 와이드필드 카메라 → 양방향 레이저 비콘
    - 810 nm SPDC 얽힘 광원, ±0.1℃ 열안정화, 진동 감쇠 설계
    - 야간 통신 + μrad급 빔 다이버전스
    - 협대역 필터 + ns급 시간 동기화로 SNR 개선
    - Si-APD 기반 단일광자 검출기 사용

**🔑 네트워크·서비스 확장**

- - **단일 위성 한계 → 별자리(Starlink형) 확장 필요**

    - 다수 LEO 위성 동기화·스케줄링 SW 개발 과제
  - **지상망 통합 필요**

    - QKD 단계를 넘어 장기적으로 지상 양자망과 완전 통합 필요
    - 중국: “베이징-상하이 QKD 링크 + 묵자 위성” 구조

**5️⃣ 차세대 QKD 네트워크 (****Quantum Satellite Constellation)**

2025년에 중국에서는 Jinan-1이라는 위성을, 독일/이탈리아/싱가포르 컨소시엄이 QUICK3 위성을 발사하였다. 이들은 위에서 언급한 기능 중 일부만 탑재된 소형 위성들이다.

기존의 LEO 위성으로는

- - 5~10분 동안만 QKD 수행을 할 수 있기 때문에,
  - 음영을 최소화 하고, 위험 분산을 위해서 많은 위성이 배치되어야 하는데
  - 비용효율측면에서 완전기능위성과 소형위성 여러대를 조합으로 운영하는 전략이다.
- **완전 기능 대형 위성 (Full-Feature QKD Satellite)**

  - 정밀 포인팅·추적 (μrad급 APT)
  - 단일광자 송신·수신
  - 얽힘 생성·안정화
  - 온보드 단일광자 검출 (SNSPD)
  - 제한적 양자 메모리 (메타안정 상태/색 중심)
  - **역할**

    - 얽힘 기반 QKD, E2E 보안

      - **Entanglement-based QKD**

        - 얽힘 분배 + Bell 측정 필요
        - 링크 손실이 크므로 극저온 SNSPD 필수
        - 다음을 위해서 필요

          - 양자 얽힘분배
          - 양자 중계기 연계
          - 양자 텔레포테이션
          - 다자간/네트워크형 QKD
    - 양자 중계기 역할 가능
    - 글로벌 링크의 **핵심 노드(Hub)**
- **소형 위성 (Mini/Nano QKD Satellite)**

  - 단일광자 송신 (기본 QKD)
  - 제한적 포인팅/추적
  - 온보드 검출기·메모리 없음
  - **역할**

    - 다운링크 Trusted Relay 중심

      - **Trusted Relay 기반 QKD**

        - 위성이 단일광자 키를 양쪽 지상국에 독립적으로 전송하고 두 지상국은 위성을 신뢰할 수 있는 중계자로 인식하면,
        - 위성 내부에서 고전적으로 키를 결합하여 최종 키를 생성하는 방식
        - 묵자를 이용한 중국과 오스트리아 QKD 영상통화
        - **장점**

          - 양자 중계기 불필요
          - 얽힘 기반 양자 메모리와 복잡한 스와핑 과정 생략 가능
          - 상용급 Si-APD로도 충분히 구현 가능
        - **단점**

          - 위성을 반드시 신뢰해야함
          - 정확히 E2E 양자보안은 아님.
    - **커버리지 보강 + 음영 최소화용 Fill‑in Node**
    - 비용 대비 수량 확보 용이
- **기술적 고려**

  - **위성 간 스케줄링 및 키 관리**

    - Trusted Relay와 얽힘 기반 혼합 운용 필요
  - **네트워크 동기화**

    - 수 ns 급 시간 동기화 ( GPS + 원자시계)
  - **양자 메모리 필요 여부**

    - 얽힘 기반 확장에는 필수
    - 다운링크 Trusted Relay만 사용한다면 불필요
- **사례**

  - **중국의 묵자 + Jinan-1/2시리즈 혼합 추진중**
  - **유럽의 Eagle-1 + CubeSat 군집 계획도 동일한 로드맵**

**6️⃣ 카펠라 스페이스의 기본 역량과 도전과제**

- **기본 역량**

  - **소형 SAR 위성 군집 운용 경험**

    - 이미 **30여 기 이상의 LEO 위성**을 **500~600 km 궤도**에서 운용
    - **대형+소형 혼합 운용·군집 관리 노하우 확보**
    - 하루 수회 revisit 가능 → 양자 위성 음영(minimum visibility gap) 최소화에 적합
  - **정밀 포인팅 및 궤도 제어 능력**

    - SAR 위성은 수십 cm 단위 정밀 지상 포인팅 필수
    - **광학 QKD에서 필요한 μrad급 시선 안정화**로 전환 가능성↑
  - **상업용 LEO 위성의 생산·배치 능력**

    - 소형 위성 대량 생산·발사 경험
    - 군집형 QKD 위성 제작·운용에 필요한 **비용/시간 효율성** 확보 가능
  - **지상국·데이터 네트워크 인프라**

    - 글로벌 지상국 네트워크 이미 운영 중
    - 양자 키 전송 시 지상 relay·key management 인프라로 재활용 가능
- **도전 과제**

  - **양자 통신·광자 페이로드 전문성 부족**

    - SAR 레이더는 RF 대역, QKD는 **광학·단일광자·얽힘**
    - **정밀 광학계·광자 인터페이스·온보드 검출기(SNSPD)** 개발 경험 없음

      - IonQ 또는 ID Quantique 와 협력 필요
  - **위성 하드웨어 통합 난이도**

    - 소형 SAR 위성에 **QKD 광학 모듈** 통합 시 전력·열관리·진동 억제 등 공학적 과제
    - 특히 **SNSPD 극저온 유지**는 큐브샛급에 부담
  - **네트워크·시간 동기화**

    - QKD 네트워크는 **ns 단위 시간 동기화** 요구
    - 현재 SAR 시스템의 시간 동기화 정밀도(μs급)는 보완 필요
  - **보안/규제 과제**

    - 국제 QKD 네트워크는 **수출 규제, 보안 규제**에 민감
    - 특히 미국·동맹국 운용 시 **중국 사례와 다른 보안 프레임워크 필요**

**🛰️의미**

양자 네트워크를 구현하기 위해서는 위성 기반 네트워크가 사실상 필수다. 광섬유를 이용한 지상 전송만으로는 100 km마다 양자 중계기를 설치해야 하며, 대륙 간·글로벌 규모로 확장하려면 물리적·경제적 한계에 부딪힌다. 따라서, 위성은 지상과 우주를 연결하는 양자 네트워크의 유일한 우회로이자, 글로벌 스케일의 엔드투엔드(E2E) 양자 보안을 구현하기 위한 핵심 인프라다.

카펠라 스페이스가 가진 기존 소형 SAR 위성 기술에 QKD를 적용하려면 정밀 광학 페이로드, 단일광자 검출, 시간 동기화, 얽힘 안정화 등 넘어야 할 기술적 과제가 상당하다. 그러나 **IonQ 입장에서는 위성 네트워크를 통한 양자 통신은 결코 피할 수 없는 전략적 과제이며**, 그렇기에 카펠라 스페이스를 품은 선택은 양자 네트워크 상용화를 향한 불가피하면서도 최적의 수순으로 보인다.
