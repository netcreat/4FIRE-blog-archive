> 먼저 기본적인 내용을 복습하고 가겠다.

**✅Capella SAR 위성이 사용하는 주파수 대역**

**💡SAR 스캔(레이더 조사) 주파수 = 마이크로파 ‘레이더 밴드’**

- - SAR 위성이 지표를 촬영할 때 쓰는 건 **레이더 신호**다.
  - 이건 전부 마이크로파(수 GHz 대역)이며, 국제적으로 전용 레이더 밴드가 정해져 있다.
  - 대표 SAR 밴드:

|  |  |  |
| --- | --- | --- |
| **밴드** | **주파수** | **대표 위성** |
| **X-band** | 9.65 GHz | Capella, ICEYE, TerraSAR-X |
| **C-band** | 5.405 GHz | Sentinel-1 |
| **L-band** | 1.27 GHz | ALOS PALSAR, NASA NISAR |
| **S-band** | 3.3 GHz | 일부 NASA 실험 위성 |
| **Ku-band** | 12–18 GHz | 군사용 SAR 일부 |

- - SAR 목적은 “지표 반사파를 받을 수 있는 파장 선택”
  - 통신이 아니라 “레이더 조사” 전용
  - 대출력 단발 펄스, 고주파 신호로 구성

**💡SAR 데이터 전송(다운링크) 주파수 = 통신용 ‘다운링크 대역’**

- - SAR 이미지를 지상으로 보내는 건 **통신 링크**이므로 전혀 다른 주파수 대역을 쓴다.
  - 대표적으로:

|  |  |
| --- | --- |
| **용도** | **주파수 대역** |
| **다운링크(X-band)** | 8.0–8.4 GHz (Earth Exploration Satellite Service) |
| **다운링크(Ka-band)** | 25.5–27.0 GHz (고속 전송) |
| **업링크(S-band)** | 2.0–2.3 GHz (명령 uplink) |

- - Capella Space는 실제로 아래와 같이 운용한다.

    - **스캔 = X-band (9.65 GHz)**
    - **데이터 전송 = X-band (8.1–8.4 GHz), 일부 Ka-band**
  - 즉 **같은 “X-band”에 속하는 것처럼 보이지만, 주파수는 서로 다르며 용도도 전혀 다름**.
  - 그리고 규제도 다르다.

**💡왜 ‘같은 안테나’ ‘같은 주파수’를 쓰지 않는 걸까?**

- - 이유는 크게 3가지다.
  - 레이더는 대출력 펄스, 통신은 연속 송신이라 구조가 다름
  1. **✅ 레이더는 대출력 펄스, 통신은 연속 송신이라 구조가 다름**

     - SAR 레이더는:

       - 대출력 펄스
       - 짧은 시간 집중 조사
       - 반사파 수신
       - 고대역폭 RF 프론트엔드
       - 고정된 전용 안테나(위상배열)
     - 통신 링크는:

       - 연속 송신
       - 좁은 대역폭(효율적 인코딩)
       - 복조/부호화 필요
       - S/X/Ka 등 규제된 통신대역을 사용
       - 지상국을 정확히 조준하는 고지향성 안테나
     - 두 기능을 **한 채널에서 같이 쓰면**:

       - 레이더 펄스가 통신 신호를 죽임
       - 통신 송신이 레이더 수신을 방해
       - 안테나 패턴이 서로 다름
       - 국제 전파 규제 위반
     - 그래서 **물리적으로 분리**되어야 한다.
  2. **✅ ITU 국제전파규정에서 “SAR 조사 대역”과 “위성 통신 대역”이 따로 정해져 있다**

     - 국가마다 SAR 관측/과학/탐지용 대역은 허가되고,
     - 통신용 주파수는 완전히 다른 기준으로 할당된다.
     - 예를 들어:

       - X-band SAR(9.65GHz)는 레이더 전용
       - X-band 통신(8.1~8.4GHz)은 Earth Exploration Satellite Service(EESS) 통신용
       - Ka-band는 데이터 전송 고속 링크용
     - **같은 대역을 쓰는 것은 국제법상 불가능**하다.
  3. **✅ 레이더 안테나와 통신 안테나는 물리적 설계가 완전히 다름**

     - SAR 안테나:

       - 길이가 길고(스트립 형태)
       - 위상배열(위상 조절로 촬영)
       - 지표를 스캔하도록 설계
     - 통신 안테나:

       - 지상국을 향해 고정 빔
       - 신호를 집중시키는 접시형(horn/reflector)
       - 추적 및 좁은 빔폭 필요
     - 따라서 **둘을 하나로 통합하는 것은 설계 자체가 불가능에 가까움**.

**💡각 주파수별 대역폭**

- - **원시 스캔 데이터**

    - 통신 대역폭과 달리, SAR 원시 데이터(raw echo)는:

      - I/Q 복소 샘플
      - 수백 MHz~1GHz 대역폭
      - 초고속 ADC
      - 펄스당 수천~수만 샘플
      - 초당 수만 펄스
    - 이걸 그냥 “데이터로 환산”하면 **초당 수십 GB**를 초과한다.
  - **X-band 통신 링크 속도**

    - X-band는 보통 **지구관측(EESS)** 위성의 다운링크 대역이다.

      - **X-band(8.0–8.4 GHz)**
      - 현실적 최대 속도: **300Mbps ~ 1.2Gbps**
      - Capella/ICEYE 같은 SAR 위성: **1.2~2.0Gbps 정도**
    - SAR 원시신호는 **초당 30~50GB**를 만들지만, 전송은 **0.2GB/s 수준**이다.
    - 그래서 **압축·부분처리·저장**이 필수다.
  - **Ka-band 통신 링크 속도**

    - Ka-band는 대역폭이 넓어서 X-band보다 훨씬 빠르다.

      - **Ka-band(25.5–27 GHz)**
      - 상업 위성 기준: **1~5Gbps**
      - 첨단 지상국 + 고출력 기준: **10Gbps 근처까지 가능**
      - NASA/NRO 일부 군사위성: **20+Gbps급 실험 성공 사례 있음**

****

|  |  |  |
| --- | --- | --- |
| **용도** | **대역** | **현실 속도** |
| SAR 레이더(스캔) | X/C/L/S | 내부 처리량은 **수~수십 GB/s** |

**✅현재 Capella Space가 실제로 운영하는 방식**

**💡 1. SAR 원시데이터(RO = Raw Observation) 수집**

- - Capella의 위성은 **X-band** **SAR**를 사용해 지표면을 고해상도로 스캔한다.
  - SAR 원시 데이터는 대략 이런 속성:

    - 초당 수~수십 GB
    - I/Q 신호 기반의 **complex raw data**
    - 매우 높은 시간·위치 정밀도 필요
    - 압축 전에는 지상 링크로 보내기엔 너무 큼
  - 즉, **위성에서 바로 이미지 형태로 처리되지 않음**.

**💡 2. 위성 onboard에서 “프리프로세싱(압축 + 스트리밍 최적화)”**

- - Capella는 완전한 SAR focusing(이미지 생성)을 위성에서 하지 않는다.
  - 대신 다음 작업만 위성 onboard에서 수행한다:
  - **위성 내 처리**

    - Range compression (부분적인 압축) - 20~40% 압축

      - Chirp 신호와 matched filter를 convolution하여 **필요한 정보만 남기고 스펙트럼을 좁힌다.**
      - 샘플 수가 효과적으로 줄어든다.
      - “슬라이스” 형태로 재배치되며, 레이다 반사 정보가 더 구조화됨.
    - 데이터 정렬(formatting) - 4배~10배 압축

      - 불필요한 라인 제거
      - 샘플 감소(decimation)
      - 도플러 보정 후 불필요 성분 제거
      - 데이터 재배열로 효율 증가
      - 중복된 데이터 제거
    - 시간·위치·운동학 metadata tagging - 압축 효과 없음

      - Precise Orbit Determination(POD) 데이터 매핑
      - Sensor motion compensation
      - Doppler centroid annotation
      - Satellite ephemeris tagging
      - Attitude & jitter metadata 삽입
      - Range line time-stamps
      - PRF 기록
      - GPS 시간/위치/속도 삽입
      - IMU(관성센서) 데이터 결합
    - 고속 전송을 위한 **압축 코덱 적용 -** **4~20배 압축**

      - Quantization(비트 깊이 축소)
      - Multi-look reduction
      - Entropy coding (Huffman, arithmetic)
      - Golomb coding
      - Predictive line compression
      - Block floating point compression
      - delta encoding
  - 즉, **완전한 SAR 이미지가 아니라, 가공 가능한 SAR RAW**를 만들어 지상으로 보낸다.

    - **Capella 0.5m 해상도 SAR**

      - Raw echo: 40~50GB
      - Onboard processed: 2~4GB
      - → **약 15~25배 감소**

**💡 3. 전송: X-band 다운링크 + 다수의 지상국 네트워크**

- - Capella는 전송 속도를 위해 **전용 X-band 링크**를 사용하고 있고, 지구 전역에 파트너 지상국을 두고 있다.
  - **활용하는 주요 파트너 지상국 네트워크**

    - AWS **Ground Station**
    - Microsoft Azure Orbital
    - KSAT (Kongsberg Satellite Services)
    - SSC
    - Infostellar
  - 즉, 위성 → 가장 가까운 지상국 → Capella 클라우드 인프라 순으로 데이터가 이동한다.
  - **전송 속도**

    - Capella는 지상 링크 대역폭을 **기존 상업 SAR 대비 5~10배 수준**으로 최적화했다고 발표함.
    - X-band 기준 최대 수 Gbps급.

**💡 4. 지상에서의 SAR Focusing(이미지 생성)**

- - SAR 원시 데이터는 지상으로 내려오면 **Capella의 클라우드 기반 Focusing Pipeline**으로 들어간다.
  - 여기서 진짜 SAR 이미지가 만들어진다.
  - **주요 알고리즘**

    - Range-Doppler Algorithm (RDA)
    - ω–κ algorithm
    - Back-projection (특수 상황)
    - Radiometric Calibration
    - Autofocus (motion compensation)
    - Speckle filtering
    - Geometric correction (지형 기반 원근 보정)
  - **결과**
  - Capella는 다음과 같은 레벨의 SAR 이미지를 생성한다:

|  |  |
| --- | --- |
| **레벨** | **내용** |
| Level 0 | 압축된 원시 수신 신호 |
| Level 1 | 기본 보정된 SAR SLC(single-look complex) |
| Level 2 | 기하 보정된 GeoTIFF 이미지 |

- - 최종 고객이 보는 건 대부분 **Level 1 또는 Level 2**.

**💡 5. 클라우드 기반 저장·처리 시스템**

- - Capella는 아예 SAR 처리 인프라를 전부 클라우드(AWS/Azure)에서 돌린다.
  - **사용 기술**

    - Kubernetes 기반 GPU/FPGA 가속 노드
    - NVIDIA A10/A30 기반 SAR Focusing

      - **Nvidia Ampere 시리즈 데이터센터 GPU**
    - 분산 병렬 파이프라인
    - 대용량 파일 전송용 S3/GridFS
  - **장점**

    - 수분 내 SAR 이미지 생성 가능
    - 고객 요청 시 즉시 tasking (GPS 기반 실시간 촬영 지시)
    - 글로벌 접근성 → 빠른 전달
  - Capella가 실제로 밀고 있는 포인트는 “**SAR 이미지를 몇 시간이나 며칠 기다릴 필요 없이, 30~90분 내 제공**”.

**💡 6. 고객 전달 (API 기반)**

- - Capella는 위성ㆍ지상국ㆍ클라우드 인프라를 전부 API와 연결해 **자동화된 데이터 파이프라인**을 만든 상태.
  - **고객 제공 형태**

    - Capella Console(웹)
    - REST API
    - STAC 기반 catalog(JSON)
    - GeoTIFF 다운로드
    - AWS/Azure 데이터 레이크로 direct ingest

> 수십GB의 Raw data를 전송하기 불가능 하기 때문에 압축, 손실 등을 하여 작게 만들고, 이를 기반으로 최종 이미지를 생성하는 과정인데, 만약 전처리 과정 생략하고 Raw data를 이용해서 직접 최종 이미지를 생성하면 이점이 있을까?

**✅ 전처리 없이 생성되는 이미지의 장점과 현실**

**💡RAW echo(사전 전처리 없이)로 SAR focusing을 하면 얻는 이점**

- - SAR focusing 알고리즘의 이상적 입력은 사실 **전처리 안된 순수 echo**다.

    - 이유는 RAW에는 아래 정보가 **모두 살아있기 때문**이다.
  - **고주파 정보(High-frequency content)가 전부 유지됨**

    - onboard에서 decimation, filtering을 하면 고주파 성분이 일부 제거됨
    - 완전 RAW라면 **최대 해상도와 최대 SNR로 focusing 가능**
    - ➜ **더 좋은 해상도, 더 선명한 이미지** 가능
  - **Multi-looking, quantization에서 버려진 신호 보유**

    - onboard compression에서는:

      - bit depth를 16 → 8bit로 줄이고 look을 줄이기 위해 averaging을 하고 entropy coding으로 희소성을 이용한다
    - 이 과정에서 **잔여 위상 정보가 일부 손실**된다.
    - RAW에서는:

      - **phase history 정보가 100% 보존**
      - RMA(omega-k), BPA(back-projection) 같은 고정밀 포커싱 알고리즘 사용 가능
      - 고급 interferometry(간섭 SAR) 품질 ↑
      - 소규모 기복 분석(DEM)정밀도 ↑
  - **합성 개구 길이를 최대로 활용 가능**

    - onboard trimming 때문에 실제 aperture 길이가 줄어든다.
    - RAW라면:

      - azimuth compression 성능 극대화
      - sub-meter 이하 해상도까지 도달 가능
      - motion compensation을 ground에서 고정밀하게 적용 가능
  - **정확한 motion compensation / 고차 위상 보정 가능**

    - onboard metadata는 coarse한 편이다.
    - RAW echo에는 **위상, 도플러, 경로지연 정보가 직접적으로 보존**되어서…
    - ground에서는:

      - 6차/7차 polynomial motion compensation
      - autofocus(phase gradient autofocus)
      - micro-Doppler 보정
      - time-domain backprojection
    - 을 수행할 수 있다.
    - ➜ **군사용 고정밀 SAR**에서 특히 중요.
  - **압축·코덱에서 생기는 인공물(artifact) 제거**

    - onboard codec은 다음을 만든다.

      - clipping
      - quantization noise
      - block floating point artifact
      - compression streak
      - speckle 패턴 왜곡
    - RAW echo는 이 모든의 **원천 데이터**라서 ground processor가 compression artifact 없이 깨끗한 이미지를 만들어낸다.

> **RAW focusing의 실질적 결과 요약**
>
> 완전 RAW echo로 focusing을 하면:
>
> 해상도 ↑
>
> SNR ↑
>
> phase accuracy ↑
>
> interferometry precision ↑
>
> micro-motion 분석 가능
>
> advanced autofocus 가능
>
> compression artifact 없음
>
> 즉, **과학/군사/정밀지도/지반변위 분석에서는 큰 이점**이 있다.

**💡 그럼 왜 상업 SAR 위성은 RAW를 주지 않을까?**

- - **물리적으로 전송이 불가능**

    - RAW echo는 **초당 10~100GB** 수준.
    - X-band / Ka-band 속도:

      - X-band: 300Mbps~1.2Gbps
      - Ka-band: 1~10Gbps
      - Optical: 10~200Gbps (일부 실험 단계)
    - 즉, **전송가능 속도와 100배 이상 차이**.
  - **Onboard 저장도 불가능**

    - 1초 촬영 = 30~60GB
    - 10초 촬영 = 300~600GB
    - 1분 촬영 = 2~4TB
    - 위성 SSD는 4TB~20TB 수준.
    - 상용 SAR은 하루에 수십 장 촬영하므로
    - **RAW 저장 불가능**.
  - **Ground에서 처리하면 너무 느림**

    - RAW echo focusing은:

      - Backprojection 기반이면 **수백~수천 GPU 코어 필요**
      - aperture 길이가 길수록 계산량 증가
      - 워크로드가 HPC급
    - 상업 SAR(예: Capella)은 “주문 후 수분 내 이미지 제공”이 핵심
    - RAW focusing은 **수 시간~수십 시간** 걸릴 수 있음.
  - **상업 서비스는 이미지를 팔지, 과학 분석을 팔지 않음**

    - 고객 요구사항 대부분은:

      - 빠른 배달
      - 적당히 좋은 품질
      - 예측 가능한 가격
    - RAW는 고객군이 매우 제한적(군, 연구소).
    - 그래서 대부분의 SAR 업체는 RAW echo를 제공하지 않는다.

**💡 그럼 RAW focusing은 어디에 실제로 쓰일까?**

- - **군사/정보기관**

    - 이동물체의 micro-Doppler 분석
    - 지반 미세 변형 분석
    - 초고해상도 감시
    - 정밀 interferometry
  - **우주·지구과학 연구**

    - 지반 침하
    - 빙하 이동
    - 해양 표면 파라미터
    - 지진 후 변위 분석
  - **고해상도 DEM(디지털 고도 모델) 생성**

    - phase-preserving raw echo가 필요함.
  - **위성 기술 테스트**

    - algorithm tuning
    - antenna calibration
    - motion compensation 검증

**✅****우주 데이터센터가 있다면?**

- - **다음과 같은 이점을 갖게 됨에 따라 SAR 성능은 판도가 바뀔 수 있다.**

    - **전력 무제한**
    - **냉각 무제한**
    - **스토리지 무제한**
    - **GPU 클러스터 무제한**
  - **완전 RAW echo 기반 Full Backprojection**

    - 해상도: 현재 0.25m → 이론적 0.05~0.1m급까지 가능
    - 초박사위상(Pa-type) 정확도
  - **영상 품질의 천장 제거**

    - artifact-free SAR
    - ultra-high SNR
    - ultra-high dynamic range
  - **지상국 없이 수천 장 동시처리**

    - SAR → laser crosslink → data center
    - 실시간 또는 대량 저장 → 병렬 batch focusing
  - **SAR “실시간 스트리밍” 가능**

    - “실시간 SAR 감시”가 가능한 세상
    - 영화에서 나오는 위성 라이브 영상 같은 개념

---

**✅맺음말**

- - 현재는 RAW focusing 데이터의 크기 제한 때문에 전처리된 데이터로 이미지를 생성하지만, 만약 기술적·상업적으로 **우주 데이터센터가 가용해지는 시대**가 온다면 SAR의 성능은 지금과 비교할 수 없을 정도로 큰 변혁을 맞게 될 것이다.
  - 물론 이러한 인프라가 실제로 얼마나 현실성이 있는지는 별개의 문제이고, 현재로서는 초정밀 이미지에 대한 수요도 한정적이어서 수익성이 얼마나 있을지도 확실치 않다.
  - 하지만, 누가 알겠는가?
  - 지금은 인프라가 없어서 하지 못하는 것일 뿐, 만약 가능해진다면 활용 가치는 지금 상상하는 것보다 훨씬 클 수 있다.
  - 마치 “휴대용 기기로 영화를 볼 사람이 얼마나 되겠나?”라고 회의적으로 바라보던 시절이 있었던 것처럼,
  - 새로운 환경이 열리면 전혀 새로운 수요가 뒤따르는 법이다.
