**💡Realistic noise**

- - 단순 모델: ∣ψ⟩에만 노이즈가 있다고 가정.
  - 현실:

    - 준비 상태 ∣ψ⟩,∣+⟩에도 노이즈 있음
    - 게이트(H, CX, CZ 등)에서 노이즈
    - 대기 중인 와이어(Idle qubit)에도 노이즈
    - 측정에서도 노이즈 발생
  - 👉 즉, QEC에서는 **모든 과정이 에러 소스**가 된다.

**💡Fault probability in large circuits**

- - 가정: 각 연산이 **1% 확률로 오류**.
  - 수백 개 연산이 있는 큰 회로라면?

    - "적어도 하나의 오류가 발생할 확률" ≈ 79%
    - 👉 따라서 QEC에서는 **확률적 에러 누적을 고려해야 함**.

**💡Fault propagation**

- - CNOT에서 오류 전파 예시:

    - Control qubit에 X 오류가 CNOT 전에 생기면 → CNOT 이후 control+target 모두에 X 퍼짐.
    - 👉 단일 에러가 **여러 큐빗으로 확산**될 수 있어 더 위험해짐.

**💡Fault-tolerant syndrome extraction**

- - 정의:

    - 회로가 fault-tolerant 하려면 **단일 오류가 최대 1개의 코드 큐빗에만 영향을 미쳐야 함**.
  - 그렇지 않으면 단일 에러가 퍼져서 다중 에러처럼 보이게 되고 QEC로 복구 불가능해짐.

**💡Cat-based measurements**

- - Cat state란?

    - 일반적으로 **cat state**는 **GHZ(Greenberger–Horne–Zeilinger) 상태**라고도 불리우고, 다음과 같이 정의한다.

- - 보조 큐빗을 단일 ∣+⟩이 아니라 Cat state (∣0000⟩+∣1111⟩)로 준비해 syndrome 추출.
  - 장점: 오류가 퍼져도 개별 큐빗이 아닌 **cat state 내부에서만 상쇄/억제**됨.
  - 👉 다중 에러 전파를 막는 방식.

**💡Additional complications**

- - Cat state 자체를 만드는 과정에서도 에러가 생길 수 있음.
  - Syndrome 측정 중 bit-flip이 섞일 수도 있음.
  - Shor (1995): 이 문제들을 해결할 수 있는 방법이 존재함을 증명 (Shor code 기초).

**💡Conclusion**

- - **QEC는 실험적으로 동작**하지만,

    - 자원 소모(큐빗 수, 연산 시간)가 너무 커서 아직 비실용적.
  - 현재 연구 핵심: **QEC overhead 줄이기**.
  - IonQ 팀의 집중 포인트:

    - IonQ 하드웨어 맞춤 코드 설계
    - 더 효율적인 코드와 디코더
    - 논리 게이트 설계
