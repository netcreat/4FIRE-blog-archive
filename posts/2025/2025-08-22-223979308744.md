**✅QCCD의 한계와 대처법**

|  |  |  |  |  |
| --- | --- | --- | --- | --- |
| **회사** | **트랩 구조** | **셔틀링** | **연결성** | **스케일링 방식** |
| **Quantinuum** | 1D racetrack QCCD | **O** (배치 셔틀링) | 루프 내 all-to-all | 2D QCCD 전환 검토 |
| **Oxford Ionics** | 2D 정적 타일 | **O** | 타일 내부 한정 | 타일+포토닉 네트워크 |
| **IonQ** | 1D 직선 체인 | **X** | 단일 체인 all-to-all | QPU간 광자 연결 |

**💡QCCD의 한계**

- - 이온을 이동할 때 열이 발생하고,
  - 셔틀링 경로가 복잡할 수록 제어가 훨씬 복잡해지는 단점

**💡QCCD를 대하는 자세**

1. 1. QCCD를 대체할 다른 방법 : IonQ의 포토닉 인터커넥트
   2. 냉각용 보조 이온을 별도로 구성하여 발열을 잡고, 한개의 이온체인을 Race Track 형식으로 구성하고, 2D 형태의 Trap으로 변경을 연구중
   3. 이온트랩의 냉각을 더 낮게 유지하여 발열을 차단하고, 제어는 레이저가 아닌 마이크로파(1GHz→ 8.037GHz : Sideband Transition)를 사용

**💡****옥스포드 아이오닉스가 QCCD 한계를 극복하는 방식**

- 이 위의 3번 방식이다.

  - **기존 QCCD**:

    - 외부 레이저 빔을 각각의 전극 또는 위치에 맞춰 전달해야 하고,
    - 각 전극을 외부 DAC에 연결해야 하는 복잡한 배선 구조와 대규모 I/O가 필요함
  - **Oxford Ionics 접근법**:

    - **공유 AC 드라이브**로 전체 타일/존에 동시에 제어 필드 전달 → **배선 단순화 & 병렬화**
    - 로컬 튜닝 전극(DC 전압)을 통해 **존별 선택적 제어** 실현 → **강한 지역 제어 가능**
    - SPAM은 **공통 레이저 + 단일 로딩 존**으로 처리 → **레이저 빔 분배 시스템 불필요**
    - **DAC 및 전극 제어의 디멀티플렉싱** (간단한 칩 내 스위치)으로 I/O 선 줄임 → **확장성 확보**

      - **WISE (Wiring using Integrated Switching Electronics) 아키텍처** - "Oxford Ionics 설계 철학 분석" 참조
    - 7존 트랩(시험 장치)에서 이미 **99.99916%(single), 99.97%(two‑qubit)** 게이트 충실도 달성
  - **레이저 대신 칩 내부 전류로 게이트를 수행**하고, cryogenic 환경(≈4K)에서 작동함으로써 **발열을 원천적으로 억제**

    - **고발열의 근본 원인인 레이저를 제거함으로써, 바륨 하나로 충분히 모든 역할을 수행할 수 있는 구조를 갖춤**

**✅Oxford Ionics가 QCCD를 사용하는 이유**

**💡****전역 연결성(All-to-All Connectivity) 확보**

- - 현재 대부분의 QPU는 **근접한 큐비트끼리만 게이트 연산**을 수행할 수 있음.
  - Oxford Ionics는 특정 이온을 다른 존(zone) 또는 유닛셀로 **물리적으로 이동**시켜,

    - → 원하는 두 큐비트를 같은 연산 존에 배치
    - → **모든 큐비트 간 논리적 All-to-All 연결성** 구현 가능.
  - 예시:

    - Qubit A(Zone 1) ↔ Qubit B(Zone 5) 연산 필요
    - B를 Zone 1로 셔틀 → 동일 존에서 이중 큐비트 게이트 실행.
  - Photonic Interconnect는 각 이온체인이 커뮤니케이션 큐빗을 통해서만 연결되는 구조라서, all-to-all 의 한계 발생

**💡****병렬 연산(Parallelism) 강화**

- - 특정 존에서는 연산을 수행하고,
  - 다른 존에서는 SPAM(측정/준비), 이온 로딩, 에러 보정 등을 **동시에 수행** 가능.
  - Oxford Ionics의 **멀티존 QPU**에서는 SPAM 존을 몇 개만 두고, 연산 존 대부분을 순수하게 연산에만 활용 → **성능 극대화**.

**💡** **큐비트 재배열(Qubit Reconfiguration) 및 에러 관리**

- - 하드웨어 결함이 있거나 에러가 큰 이온을 특정 존에서 격리하고,
  - → "좋은" 큐비트들만 연산 존으로 재배열 가능.
  - 양자 에러 정정(QEC)에서도 이온 이동은 매우 중요한 역할:
  - 로지컬 큐비트 코드를 구성할 때 필요한 큐비트 간 상대적 배치를 **동적으로 최적화**할 수 있음.
  - 특히 OI는 **전자제어 기반 게이트**라서, 이동 중에도 QEC 루틴과 쉽게 통합 가능.

**✅Oxford Ionics의 이온트랩 배치**

**💡유닛 셀(Unit Cell)**

- - **정의**: 이 칩의 가장 작은 기본 연산 단위.
  - 구성 요소:

    - **트랩된 이온 1개** → 즉, **유닛셀 1개 = 큐비트 1개**.
    - **Local tuning electrodes (국소 튜닝 전극)**:

      - DC 전압을 걸어 이온 위치와 모션을 제어.
    - **Shared drive**:

      - 칩 전체에 공급되는 공통 AC 자기장으로, 게이트 연산에 필요한 제어 필드를 제공.
  - 역할:

    - 같은 칩 위의 모든 유닛셀은 **하나의 공통 AC 제어 필드**를 받음.
    - 특정 유닛셀만 선택하려면, **해당 셀의 로컬 전극 전압을 조절**해 이온 모션 주파수를 바꾸는 방식으로 제어.

**💡존(Zone)**

- - 단일 유닛 셀 또는 복수 유닛 셀이 연결된 구획
  - 로딩, 준비 측정(SPAM) 또는 연산 등을 수행
  - 아래 그림은 옥스포드 아이오닉스의 아키텍처를 실험적으로 검증하기 위한 프로토타팁으로서, **선형 7존 트랩** 장치.
  - 구성:

    - 총 **7개의 Zone** 존재.
    - **Zone 4**: 레이저 접근 영역
    - → 이온 로딩, 상태 준비(State preparation), 측정(SPAM) 수행.
    - **나머지 6개 Zone(1-3, 5-7)**:
    - 공유된 전자기장으로 제어되는 **연산 영역**.
  - 특징:

    - 현재 실험에서는 **Zone 1~7 각각에 유닛셀 1개씩**, 즉 **큐비트 1개씩** 존재.
    - 따라서 **7존 테스트 디바이스 = 7개의 유닛셀 = 최대 7큐비트** 구조.

**✅Multi Zone QCCD**

**💡Junction Zone과 Gate Zone을 분리**

- - **홀수 짝수 패턴으로 교차 배치**

    - 전기장 안정화

      - 정션 존은 이온을 여러 방향으로 셔틀링하기 위한 **전압 포텐셜 교차점**
      - 두 기능을 한 존에서 동시에 처리하면 전기장 패턴이 섞여 **모션 모드 불안정** 발생
      - **게이트 존과 정션 존을 번갈아 배치**해 전기장 간섭을 최소화
    - 셔틀링 효율 최적화

      - 이온을 이동시키려면 포텐셜 경사(전기장 경로)를 부드럽게 유지해야 함
      - 홀수 존 → 짝수 존 → 다음 홀수 존 순서로 경로를 설계하면:
      - 정션 존을 거쳐 이온을 원하는 게이트 존으로 유연하게 분배 가능
    - 멀티큐비트 게이트 충실도 향상

      - 아래 그림에서 k=6, 정션당 6개의 큐비트가 접근이 가능
      - 이때 게이트 존과 정션 존을 번갈아 배치하면 게이트 존에서 필요한 이온만 선택해 연산
      - 연산 후에는 이온을 다시 정션 존을 통해 원래 위치로 복귀

        - 모션 모드 단순화
        - 교차 간섭 최소화
        - 게이트 충실도 증가
    - 병렬 연산 극대화

      - 홀수 게이트 존에서 연산 중일때 짝수 정션 존은 셔틀링 대기 상태로 활용
      - SPAM 존도 정션 존에 붙여 배치해 연산 존과 분리 → 병렬 작업 가능

**💡QCCD에서의 Zone 역할**

- - **Gate Zones (GZ)** → 연산 중심부에 2~4개씩 위치
  - **Junction Zones (JZ)** → 경계에 배치 → **내부 존 이동** + **광학 연결 가능**
  - **Detection Zones (DZ)** → 구석 쪽에 배치 → PI(Photonic Integration) 채택 시 레이저 라우팅 단순화
  - **Loading Zones (LZ)** → 1~2개, 중앙 또는 모서리 근처
  - **Storage Zones (SZ)** → 주변부, 대기 이온 보관

**✅Zone reconfiguration**

- - 멀티존 QCCD 칩에서 특정 큐비트들의 위치를 재배치(rearrangement)하는 과정
  - 필요한 큐비트들을 서로 가까운 게이트 존(gate zone)에 모아놓고 연산을 수행한 뒤,
  - 연산 후 다시 원래의 저장 존(storage zone)으로 되돌리는 동작

**💡멀티큐비트 게이트를 위한 이온 배치 최적화**

- - 멀티큐비트 게이트를 실행하려면 **같은 게이트 존**에 해당 이온들이 있어야 함.
  - 초기 상태에서 큐비트들이 서로 멀리 떨어져 있으면,

    - 게이트 fidelity 저하
    - 게이트 시간 증가
  - 따라서 필요한 큐비트를 **동일 게이트 존으로 이동**시켜 최적 조건에서 연산 수행.

**💡****게이트 존 내 이온 수 제한**

- - 게이트 존에 너무 많은 이온을 두면:

    - 모션 모드가 복잡해지고
    - 발열(heating) 증가
    - 교차 간섭(crosstalk) 심화
  - 그래서 OI 아키텍처에서는:

    1. 게이트 전, 필요한 이온들만 모아 **짧은 체인 구성**
    2. 게이트 후, 다시 분리 → 원래 저장 존으로 복귀

**💡****SPAM(초기화·측정)과 연산 존 분리**

- - SPAM 존(State Prep & Measurement Zone)은 레이저 접근이 필요한데,
  - 레이저를 사용하는 존과 연산 존을 구분해 병렬성을 극대화.
  - 측정이 필요한 이온만 **SPAM 존으로 리컨피규레이션**해서 보내고,
  - 나머지 이온은 연산 존에 남겨둠 → **병렬 동작 최적화**.

**💡****초기 상태**

- - 각 존(zone)에는 작은 이온 체인(2~6개)이 저장돼 있음.
  - **k=6 qubits per junction** → 각 junction zone은 최대 6개의 큐비트 체인을 연결 가능.

**💡****리컨피규레이션 과정**

1. 1. 필요한 이온을 정션 존(junction zone)을 통해 이동 → 목적 게이트 존으로 모음.
   2. 해당 게이트 존에서 **멀티큐비트 게이트 수행**
   3. 연산 후 다시 원래 저장 존(storage zone)으로 되돌림.

**💡** **특징**

- - 이온을 “소환”했다가 다시 “복귀”시키는 개념.
  - 전체 시스템에서 연산 중인 이온 수를 최소화해 **발열과 간섭을 억제**.

**✅QPU(또는 QPU내부의 타일) 간 연결은 광자(Photonic Interconnect)로**

아래 두개의 Oxford University의 웹사이트에서 각각의 이온 트랩 양자 컴퓨터(여기서는 QPU 또는 타일)는 Photonically integrated된다고 언급이 되어 있는데, 여기서 짚고 넘어가야 할 것이 있다.

- Oxford Ionics가 마이크로파를 사용한다고 해서, 레이저를 더이상 사용하지 않는다는 의미가 아님

  - 마이크로파 (1GHz) - 게이트 수행에 사용
  - DC 전압 (수백 mv) - 트랩 전위 형성, 이온 위치 조정, 게이트 on/off
  - 광신호 (493nm, 650nm) - 광학 정렬(이온 냉각, 상태 준비, 측정)에 사용
- 즉, QPU간에 사용되는 Photonic Interconnect 용 레이저와 QPU내부에서 큐비트 준비 및 측정에 사용되는 레이저가 각각 필요하다는 것을 인지해야 한다.

**💡 하나의 QPU 내부에 10,000 큐비트가 동시에 구동 가능할까?**

- QPU안에 멀티 타일(마치 멀티 코어처럼)로 구성해서 10,000큐비트를 구현할지, 싱글 타일로 구현할지에 대한 정확한 자료 없음

  - 이론상으로 싱글 타일로 구현하는 것이 불가능한 건 아니지만, 아래와 같은 기술적, 물리적 제약 때문에 멀티 타일 아키텍처로 가지 않을까 추측한다.

    - 전극 수 증가 - WISE 아키텍처로 일정 수준 해결 가능
    - 레이저 광학 제어 - 미해결
    - 전기장 균일성 - WISE 아키텍처로 일정 수준 해결 가능
    - 진동 모드 수 증가 - 미해결
    - 열 발생 - Cryogen 냉각으로 일정 수준 해결 가능하지만, 이미 QCCD의 셔틀링으로 인해 발열 문제가 있기 때문에 일정 규모 이상에서 다시 발열 문제 발생
    - 신호 라우팅 - WISE 아키텍처로 일정 수준 해결 가능
  - 규모의 차이는 있겠지만, 대략 256 큐비트 근처를 기준으로 그 이상일 경우에는 멀티 타일로 구성하고, 타일간의 연결은 Photonic Interconnect를 통해 연결이 될 것으로 보인다.

    - 최근에 NQCC에 납품한 **QUARTET**(QUantum Advantage-Ready Trapped-ion Exploration Testbed)은 싱글 타일을 사용했을 것이라 추측.
