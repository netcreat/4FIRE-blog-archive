**✅****Distributed Quantum Memory with Flying Qubits and Sparse Cyclic Layout**

**💡****연구 배경**

- **대규모 양자컴퓨터**는 오류 정정(QEC)과 내결함성 구현으로 인해 수백만 개의 물리 큐비트를 요구
- **모듈형 설계**는 제조·검증·특성 분석을 단순화하고, 플랫폼별 물리적 제약(이온 스펙트럼 혼잡, 칩 수율 저하, 레이저 출력 한계, 극저온 확장 문제)을 완화
- 과제:

  - 모듈 간 연결 방식
  - 모듈형 분산 아키텍처에서의 **효율적인 QEC 설계**

****

**💡****기본 개념**

- **Flying qubits**(이온, 원자, 전자, 광자 등) 이용 → 모듈 간 물리적 이동으로 연결
- **2×L 모듈 배열**:

  - **고정 행(fixed row)**: 데이터 모듈
  - **이동 행(moving row)**: 안실라 모듈
  - 사이클릭 시프트(cyclic shift)로 이동 행 모듈을 회전 이동시켜 필요한 상호작용 구현
- 모듈당 n개의 큐비트, 인접 모듈 간 2큐비트 게이트 가능

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTA4MDlfMjc4/MDAxNzU0NzE0OTU0NTcz.v4zQYaP80oAjjcm5bT4Hlx-ueVAPLCzOROoljoWn3AUg.jOtTIfUMyWoFccGFt9xzo8Yig8kDasg9ED7TuBZ7h5gg.PNG/image.png?type=w800)](#)

- 2 × 3 모듈 배열(총 6개 모듈)의 그림

  - 각 모듈(module)에는 **5개의 큐비트**가 들어 있음.
  - 2개의 행(row) 중 하나는 **고정된 행(fixed row)**, 다른 하나는 이동하는 행(moving row).
  - 그림에서 점선 박스(dashed boxes)로 표시된 부분은 **서로 맞춰진(aligned)** 모듈 쌍을 나타냄
  - 실제 구현에서는 이 2D 배열을 **일렬(1D)로 재배치한 형태**로 생각하며, 각 모듈은 그 안에 포함된 5개의 큐비트를 포함.
  - **사이클릭 시프트(cyclic shift)** — 즉, 모듈의 상대적인 위치를 주기적으로 바꾸는 동작 — 는 **플라잉 큐비트(flying qubit)** 를 이용해서 구현.
  - 플라잉 큐비트란 물리적으로 이동할 수 있는 큐비트로, 예: **광자(photons)**, **전자(electrons)**, **이온(ions)**, **중성 원자(neutral atoms)** 등이 가능.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTA4MDlfMjM1/MDAxNzU0NzE1MTYyODYz.ABXTvKK6WKatMDZZwXWgqT1WTeVB8FDo9zqOPFHwF8Eg.I1oaDQJcQyB9DlRgo3E0NnUFRp9RvgdXkwwWY4lUMi4g.PNG/image.png?type=w800)](#)

- **2×3 모듈 배열**에서 이동 행(moving row)을 **1칸(s=1) 오른쪽으로 순환 이동(cyclic shift)** 시키는 과정을

**Primary zone**(기본 저장 구역)과 **Secondary zone**(임시 저장 구역)을 이용해 3단계로 표현한 그림

- - **Primary zone / Secondary zone**
  - **Primary zone**: 1D로 배열된 모든 모듈이 기본적으로 위치하는 구간
  - **Secondary zone**: 사이클릭 시프트 시 모듈을 임시 보관하는 평행한 구간
  - **s-shift 구현 3단계 (예: s=1)**

    1. **마지막 s개의 이동 행 모듈**을 Secondary zone으로 이동

       - 그림 (a)에서 맨 오른쪽에 있는 이동행 모듈(1,2)를 윗칸(secondary zone)의 맨 왼쪽으로 이동시킴
       - 그럼 원래 (1,2)가 있던 곳(아랫칸 맨 오른쪽)이 비어 있게 됨
    2. **나머지 (L−s)개의 이동 행 모듈**을 Primary zone 안에서 **2s 칸 앞으로** 이동

       - → 여기서 “앞으로”란, 모듈 위치를 주기적으로 바꾸는 방향
       - → 구현 시, 모듈을 Secondary zone으로 잠시 옮겼다가 다시 Primary zone으로 되돌려 배치하는 방식 사용
       - → 스왑 연산 대신 전체 이동이 더 효율적 (스왑은 s에 비례해 연산 수 증가)
       - 그림 (b)에서 이동행 모듈(1,0)과 (1,1)을 각각 오른쪽 모듈로 이동시킴

         - (1,1)은 (1,2)가 있었던, 지금은 비어 있는 아랫칸 맨오른쪽으로 이동
         - (1,0)은 (1,1)이 있었던 중간 모듈로 이동
         - 각 이동행이 모듈을 이동할 때에는 윗칸(secondary zone)을 통해서 건너감.
    3. Secondary zone에 있던 s개의 모듈을 Primary zone의 **첫 s 위치**에 재배치

       - 그림 (c)은 윗칸 맨 오를쪽에 임시로 위치(잠시 파킹)하고 있던 (1,2)는 원래 (1,0)이 있던 왼쪽 모듈로 이동
  - 그림 간단 요약

    - 원래 이동 행: M1 M2 M3
    - Step (i): M3 → Secondary zone
    - Step (ii): M1, M2를 앞으로 2칸 이동
    - Step (iii): M3를 Primary zone 첫 칸에 복귀
    - → 결과: M3 M1 M2

**💡****사이클릭 레이아웃(Cyclic Layout, Algorithm 1)**

- 모든 **안정자 코드**의 신드롬 추출 회로 구현 가능
- 안실라 모듈이 순차적으로 모든 데이터 모듈과 상호작용
- 깊이 상한:

- r: 측정할 Pauli 연산자 수
- **장점**: 범용성
- **한계**: 안정자 수가 많아지면 깊이 증가 → 성능 저하

**💡****희소 사이클릭 레이아웃(Sparse Cyclic Layout, Algorithm 2) -aka** **"띄엄띄엄"**

- **BB 코드**에 특화된 상수 깊이(constant depth) 신드롬 추출 회로
- BB 코드 구조(A,B∈F2[x,y])를 활용
- 데이터·안실라 모듈을 Zℓ×Zm 격자에 매핑 → 병렬 CX 게이트 실행
- **성능**:
- X/Z 안정자 추출 깊이:

- ω: 안정자 weight
- 모든 BB 코드에서 깊이 12 달성
- 일반 레이아웃보다 대규모 코드에 효율적

**💡****물리적 구현 (Trapped-ion 예시)**

- 1D **primary zone**: 고정·이동 모듈 교차 배치
- **secondary zone**: 사이클릭 시프트 시 임시 저장
- s-시프트 절차:

  - 마지막 s개 모듈 → secondary zone
  - 나머지 모듈 → 1차 영역에서 2s 전진
  - secondary zone → 첫 s 위치 복귀
- 깊이 1 시프트 가정: 이동 거리와 무관, 주로 고정 시간 과정이 지배
- **시뮬레이션 결과**:

  - 144-큐비트 BB 코드 (12 모듈, 각 모듈 = 긴 이온 체인)
  - 물리 오류율 10−3 → 논리 오류율 <2×10−6
  - **500배 향상 (Sparse Cyclic Shift 기준)**

**💡****결론 및 전망**

- 제안 아키텍처 = **평면 이동 가능(movable)** flying qubits 기반
- 전자, 이온, 중성 원자 구현에 적합
- 다른 코드(서피스, generalized bicycle 등)로 확장 가능
- **이론적 함의**:

  - LDPC 코드의 그래프 확장성 제약 완화 가능성
  - cyclic shift / flying qubits가 코드 매개변수·논리 연산 한계에 미치는 영향 연구 필요

**✅****논문 분석**

**기존 이온트랩방식에서 ion-chain 한계점**

- 이온트랩 방식은 all-to-all을 지향한다.

  - 소규모 단일 모듈(ion chain)기준에서만 사실상 all-to-all 연결이 가능 - **35개 큐비트 이하**
  - **체인이 길어질수록:**

    - 스펙트럼 혼잡(spectral crowding) → 게이트 속도·정확도 저하
    - 제어 레이저 파워 한계
    - 동시 게이트 실행 병렬성 감소
  - 확장 방법

    - **포토닉 인터커넥트**

      - 여러 모듈(ion chain)을 광자 링크로 연결 (네트워크형 QPU)

        - 물리적으로 떨어진 모듈간 연결에 적합
      - **엔탱글먼트 정제 + 원격 게이트**를 사용했는데, 레이턴시·오류율이 높음
      - 특히 **qLDPC** 같은 고확장성 코드에서는 필요한 연결 패턴을 모듈 간 링크로 만들기 어렵거나 매우 비효율적
      - **기술 구현이 굉장히 난해함.**

**💡****이번 발표의 핵심**

- **핵심 아이디어**:

  - 모듈 간 연결을 광자 링크 대신 **모듈(혹은 일부 큐비트)을 물리적으로 이동**해서 직접 구현
  - 이동을 **사이클릭 시프트**라는 단순 규칙으로 수행 → 복잡한 연결 패턴도 짧은 깊이로 해결
- **이점**:

  1. **확장성**: 모듈 수 L이 커져도 연결 패턴이 단순 → 제어 로직, 경로 설계 쉬움
  2. **병렬성 유지**: 동시에 여러 쌍의 모듈이 게이트 수행 가능
  3. **엔탱글먼트 정제 불필요**: 원격 링크 품질 문제 회피
  4. **qLDPC 적용 가능**: 기존에 분산 환경에서 어려웠던 BB/Gross 코드 같은 고확장성 LDPC 코드의 신드롬 추출 가능

> **발표 이전**: 이온트랩은 한 체인 안에서는 all-to-all, 하지만 모듈 간 연결은 광자 링크 + 엔탱글먼트 정제 필요 → qLDPC 분산 QEC엔 부적합
>
> **발표 이후**: 사이클릭 시프트로 모듈 간 직접 연결 → 하드웨어 단순, 깊이 일정, qLDPC 분산 QEC 실현 가능

**💡****모듈 시프팅 방법**

- QCCD의 구조와 같이 이동행의 모듈만 전극 제어로 다른 구역으로 이동시키는 방법과 유사할 가능성이 매우 큼

  - qLDPC 같은 고확장성 코드의 신드롬 추출은 **특정한 쌍 연결 패턴**이 반복적으로 필요
  - 한 번 시프트할 때 여러 쌍의 데이터/앤실라 연결이 동시에 만들어짐
  - 경로가 규칙적(사이클릭 시프트) → 제어 간단
  - 각 모듈(체인)을 하나의 zone 그룹으로 취급
  - 전극 제어로 모듈 전체를 인접 Zone으로 이동

- 이번 발표는 IonQ에서 발표한 것이기 때문에, 연구의 의도가 기존의 IonQ의 설계에 맞췄을 것인데, 과연 Oxford Ionics의 구조에도 적용 가능할지를 살펴보면,

  - Oxford Ionics의 타일 기반 설계도 **모듈 레벨 구조**이므로, 모듈 ↔ 모듈 간 물리 이동 개념을 적용 가능
  - 광자 링크 대신, 일부 환경에서는 **타일 자체를 인접 타일로 이동**시켜 체인 내부 게이트 품질로 QEC 수행 가능
  - BB 코드처럼 **연결성이 넓은 qLDPC 코드**에도 적용 가능 → 기존 광자 링크 방식보다 더 낮은 대역폭/레이턴시 가능성
- 조정이 필요한 부분

  - **저이동 철학과의 충돌**

    - Oxford Ionics는 이동 최소화를 철학으로 함 → 사이클릭 시프트는 주기적으로 이동하므로 이 점은 재검토 필요
    - 타일의 일부만 이동하거나, 이동 주기를 줄이는 방식으로 타협 가능
  - **마이크로파 제어 환경**

    - 모듈 이동 시 마이크로파 필드 균일성 유지 필요
    - 이동 경로와 전극 설계가 밀접하게 연계돼야 함
  - **포토닉 인터커넥트 전략과의 병행 (하이브리드??)**

    - 장거리(모듈 간 멀리 떨어진) 연결은 여전히 광자 링크 사용

- **이온트랩의 기술 진보**

  - 크리스 먼로 교수가 반도체 칩을 통해서 이온트랩을 최초로 구현한 이후 이온트랩에는 상당히 많은 기술적인 진보가 있었다.

    - 칼슘 → 이테르븀 → 바륨
    - 레이저 → 마이크로파
    - 큐비트 → 큐디트
    - 이온단위의 이동 → 체인 단위의 이동 ?? (QCCD의 셔틀링 개념을 모듈 스케일로 확장)
  - 예전에는 **하드웨어로 모듈을 움직이는 것보다 레이저로 "닿게 하는" 게 훨씬 쉽고 안정적**이었기 때문에 광학 연결이 우선 선택됐던 것이지만,
  - 지금은 **이동식 아키텍처 + 분산 QEC**가 맞물리면서, "굳이 모든 걸 레이저로 연결할 필요 없다"는 방향으로 바뀔 수도 있다.
- 옥스포드 아이오닉스의 **설계 철학의 과제**

  - 타일 구조를 사용하여, 타일 내부에서는 이온의 셔틀링을 최소화
  - **타일 간의 연결은** **포토닉 인터커넥트로 연결**이 목표이지만, 이것을 아직 실현하지 못하여 현재 판매한 양자컴퓨터도 16 ~ 64 큐비트 수준에 머물고 있다.

        - 파장 변환 - Intra QPU(optional), Inter QPU
