일단, 8월의 논문에서 다룬 새로운 개념이 무엇인지 짧게 복습하고 넘어가겠다.

**🧩 1. Cyclic layout (Algorithm 1)**

**기본 개념:**

- - 모든 안실라 모듈이 전체적으로 움직이며, 각 사이클마다 데이터 모듈들과 정렬(alignment)된 상태에서 필요한 2-큐빗 게이트(CX, CZ 등)를 수행한다.

    - 구조: 2×L 모듈 배열 (위 행 = 데이터, 아래 행 = 안실라)
    - 실행: “1-shift”로 전체 모듈이 한 칸씩 순환 이동
    - 목적: 모든 안정자(stabilizer)를 순차적으로 측정
    - 장점: **임의의 stabilizer code**에 적용 가능 (BB 코드뿐 아니라 surface, color code 등)
    - 단점: **깊이가 큼** — 매 스텝마다 전 모듈 이동 + 측정 + 리셋 → 대규모 코드에서는 너무 느림
  - 즉, “모든 안실라가 동일하게 이동하는 전체-이동(full shift)” 모델이라 비효율적이다.
  - 아래의 슬라이딩 퍼즐 또는 컴비네이션 퍼즐처럼, 특정 위치의 모듈을 옮기기 위해선 해당 라인의 모듈들을 차례로 옮기는 것과 유사하다.

**🧮 2. Sparse cyclic layout (Algorithm 2)**

**개선 아이디어:**

- - 모든 안실라를 돌리지 말고, **BB 코드의 구조적 희소성(sparsity)** 을 이용해 “필요한 안실라만” 이동시키는 방식이다.

    - 한 번의 사이클 시프트로 여러 안정자를 동시에 측정 가능.
    - 깊이 = |J(A) ∪ J(B)| + ω + 2 (ω = stabilizer weight)
    - 장점: **필요한 안실라만 움직이므로 훨씬 짧은 depth**, 불필요한 transport 감소.
    - 단점: 여전히 “모듈 단위 이동” 이 필요하므로 transport 노이즈 (τₛ ≈ 30 rounds idle noise) 가 남음.

나는 9월에 우연히 Nicolas Delfosse한테 질문을 할 수 있는 기회가 생겨서 여러 질문을 했었는데, 내가 질문 한 내용외에 흥미로운 내용을 알려줬다.

해당 논문의 Appendix에 언급한 추가 알고리즘이 Oxford Ionics의 아키텍쳐를 위한 내용이라고 한다. 논문을 검토할 당시 Acknowledgement 하위에 있는 Appendix라서 주의 깊게 살펴보지 않았는데, 질문했던 내용외에 뜻밖의 소식을 듣고 놀라지 않을 수 없었다.

공식적으로 IonQ의 인수 승인 발표는 9월 12일이었고, 인수 발표는 6월 9일에 났었는데, 8월에 발표한 IonQ의 논문에 Oxford Ionics의 아키텍처를 위한 내용이 포함되었다는 것은, 이보다 훨씬 오래전부터 인수 준비를 해왔다는 것으로 해석이 된다.

**🧱 3. Flat implementation (Appendix A, Algorithm 3)**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTEwMTJfMjQ3/MDAxNzYwMjYxNTI1NDMy.gRVfRP2xjp1sr9-bvZjZs13ExvxJTBbJYFrE7u87OgIg.4ILI316YWh35WaqhZZccdwzAWYiJ3gLQPBG5dnpyejkg.PNG/image.png?type=w800)](#)

[**[2508.01879v1] Distributed fault-tolerant quantum memories over a 2xL array of qubit modules**](https://arxiv.org/abs/2508.01879v1)

- - 이건 **sparse cyclic layout의 물리적 대안** 이다.

    - 즉, “긴 이온 체인(한 모듈에 다수 큐빗)” 이 아닌, **각 모듈을 짧고 평면적인 1D 큐빗 열로 나눈** 형태이다.
    - **Flat implementation은 sparse cyclic의 논리 구조는 그대로 두되, 물리 적용 단위를 더 잘게 쪼개고 intra-module 병렬성을 활용** 하는 방법이다.
  - 핵심 차이는 다음과 같다.

|  |  |  |  |
| --- | --- | --- | --- |
| **구분** | **Cyclic** | **Sparse Cyclic** | **Flat Cyclic** |
| 이동 단위 | 모든 안실라 **모듈** | 필요한 안실라 **모듈만** | 모듈 + 모듈 내 **큐빗** 동시 |
| 코드 적용 범위 | 모든 stabilizer code | BB code (특화) | BB code (물리 최적화) |
| 회로 깊이 | 가장 깊음 | 중간 | 가장 얕음 |
| 노이즈 영향 | 높음 (전 모듈 이동) | 중간 | 낮음 (짧은 이동) |
| 특징 | 보편성 | 효율성 ↑ | 실행 속도 ↑ + 병렬성 ↑ |

**🧩 Cyclic layout / Sparse cyclic layout — “체인(모듈) 단위 이동”**

- - 여기서 “module”은 **하나의 긴 이온 체인(ion chain)** 으로 구성된 것을 의미함

    - 예: 한 모듈 안에 50~100개의 이온이 일렬로 배열된 구조.
  - “cyclic shift” 명령은 이 **전체 모듈(체인) 자체를 한 칸 오른쪽으로 이동**시키는 것을 의미함.

    - 즉, **체인 전체가 통째로 움직이는 구조**.
  - cyclic layout: 모든 체인을 한 번에 순환 이동 (전 안실라 이동)
  - sparse cyclic layout: 필요한 체인(안실라가 들어있는 모듈)만 선택적으로 이동
  - 💡 여기서의 이동은 “모듈 간 정렬(alignment)”을 바꾸는 데 목적이 있다 —

    - 즉, 아래 행(안실라 체인)을 오른쪽으로 한 칸 이동시켜 위 행(데이터 체인)과 서로 다른 부분이 정렬되도록 하는 원리
  - 이동 단위 = **module (즉, 이온 체인)**

****

**🧱Flat cyclic layout (Appendix A) — “모듈 내부 이동 (intra-module shift)”**

- - 여전히 2×L 구조이지만,
  - 각 “module”이 이제 “짧은 1D 배열(작은 체인)” 형태로 구성됨.
  - 예: 모듈당 5~10개의 이온 정도.
  - 각 모듈 안에서 이온들을 재배열할 수 있음
  - 이게 논문에서 말하는 “intra-module cyclic shift”이다.
  - 즉, 체인 전체를 이동하는 게 아니라 **체인 내부에서 위치만 바꾸는** 것임.
  - 동시에, 모듈 간(global) cyclic shift도 가능하긴 하지만,

    - Flat layout은 **이 모듈 내부(intra-module) 이동을 활용해 대부분의 정렬을 해결**함.
    - 즉, **체인 전체를 옮기지 않고도 원하는 큐빗끼리 맞물리게 만들 수 있는 구조**임
  - 이동 단위 = **module 내부의 개별 이온(혹은 서브모듈)**
