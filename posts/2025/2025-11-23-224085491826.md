**✅Reimagining Error Correction for Modular Quantum Computing**

- - IonQ는 **NISQ 시대에서도 실용적 가치 제공**과 동시에 **가장 빠른 경로의 Fault-Tolerance** 확보를 목표로 하고 있다. 이를 위해 **효율적인 Quantum Error Correction(QEC)** 과 **모듈형(Modular) 아키텍처**를 함께 추구한다.

**💡** **QEC 코드 효율 비교**

|  |  |  |
| --- | --- | --- |
| **항목** | **Surface Code** | **qLDPC / BB Code** |
| 구조 | 단순한 2D Grid | 복잡한 연결 패턴(Tanner graph) |
| 효율 | Logical 1 qubit 보호에 약 100 physical qubit 필요 (distance=10) | Logical 8 qubits 보호에 90 physical qubit (distance=10) |
| 장점 | 하드웨어 매핑 쉬움 | 매우 높은 효율, 적은 오버헤드 |
| 단점 | 물리적 자원 소모 큼 | 복잡한 레이아웃 필요 |

- - BB(Bivariate-Bicycle) 코드는 **표면코드 대비 압도적 효율**을 제공하지만 **모듈 간 연결이 매우 복잡**해지는 문제가 있음.

**💡** **Modular Layout 문제**

- - qLDPC / BB 코드의 Tanner graph는 **Edge-Expansion**이 큼.
  - 모듈을 나누면 **모듈 간 연산이 많아져 속도·정확도 저하**.
  - 즉, 효율성은 좋지만 **하드웨어 배치가 매우 어려움**.

**💡** **Flying Qubits가 제공하는 해결책**

- - 이온트랩 시스템은:

    - **이온 재배열, 셔틀링 가능**
    - **광자 링크로 장거리 연결 가능**
  - 즉, **하드웨어 연결성을 동적으로 변경해 복잡한 qLDPC도 구현 가능**.

**💡** **Cyclic Layout**

- - Qubits를 module(=parcel) 단위로 두 줄로 배열.
  - Ancilla 모듈이 오른쪽으로 한 칸씩 **Cyclic Shift**하며 모든 Data 모듈과 순차적으로 상호작용.
  - 이 방식으로 **모든 stabilizer code의 syndrome extraction 가능**.

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMjNfMTQ0/MDAxNzYzODcxMzIwMzcx.jj2rd6g1OokpZjOjSWyC1S_aqjVUR5QRTBdIOYvBlOIg.kywcdry12iPZmrAYvqH6CqRbNP7fTgO5hRiaXe0KAAog.PNG/image.png?type=w800)](#)

**💡** **Sparse Cyclic Layout (최적 해법)**

- - BB 코드의 **자연적 cyclic 구조**를 활용하여 **불필요한 shift를 제거**.
  - 예: 288 코드 길이의 BB 코드 → 단 **4번의 cyclic shift만 필요**
  - Shift 횟수가 코드 크기 L과 무관 → **확장 시 오버헤드 거의 없음**

|  |  |
| --- | --- |
| **Layout** | **비용 특성** |
| 2D Grid | 사실상 불가능 또는 극도로 비효율적 |
| 일반 Cyclic | 코드 크기 증가 시 Shift 횟수 증가 |
| **Sparse Cyclic (최적)** | **Shift 횟수 고정 → 대규모 BB 코드에 최적** |

**💡결론**

- - IonQ는 **이동 가능한 이온 트랩 큐비트(=Flying Qubits)** 의 유연성과 **Sparse Cyclic Layout**을 결합하여:

    - 효율적인 qLDPC / BB QEC 구현
    - 모듈형 아키텍처와 병렬성 확보
    - 확장성이 뛰어난 **Fault-Tolerant Quantum Computer**로 가는 핵심 기술 기반 확보
  - 즉, **“모듈형 + 고효율 QEC + 동적 연결성” = 타 플랫폼 대비 독보적 스케일링 전략**

**✅Tanner Graph란 무엇인가?**

- - Michael Tanner (MIT 출신 정보이론 연구자)가 1981년에 발표한 논문에서 처음 제안한 이후 지금까지 널리 사용되는 개념으로서, graph는 **“코드의 패리티 제약 구조”를 그래프로 그린 것**이라고 보면 된다.
  - 자세한 내용은 위의 링크를 참고하자.

**💡****Surface Code의 Tanner Graph**

- - Surface code는 2D 격자 상에서:

    - 각 큐비트가 딱 **주변 4개 정도의 체크에만 연결**되고,
    - 그 배치가 2D 평면 위에서 깔끔히 표현된다.
  - 따라서 Tanner graph의 간선을 적절히 “펴서” 배치하면
  - **자연스럽게 2D 그리드 구조로 매핑**할 수 있다.

    - → 초전도 qubit 같이 **근접 이웃(nearest neighbor)** 만 허용되는 하드웨어에 잘 맞음
    - → 하지만 효율은 낮아서, logical 1 qubit 보호에 수십~수백 physical 필요

**💡****qLDPC / BB 코드의 Tanner Graph**

- - qLDPC / BB 코드에서는:

    - 각 체크 노드가 연결하는 큐비트 수가 상대적으로 적다(**Low-Density**),
    - 하지만 전체적으로 보면 **연결 패턴이 훨씬 더 복잡하고 “멀리” 뛰어다님**.
  - 즉,

    - **각 노드의 차수(degree)는 작지만**,
    - 그래프 전체는 **멀리 있는 노드들끼리도 촘촘히 엮여 있는 구조**를 가진다.
  - 이건 **에러정정 성능과 한계 길이, 거리(distance), logical qubit 수 측면에서 매우 좋다.**
  - 하지만, 이걸 **실제 하드웨어에서 모듈로 잘라서 배치하는 순간** 문제가 터진다.
  - 그게 바로 **edge-expansion**과 연결된다.

---

**✅Edge-Expansion이란 무엇인가?**

**💡****개념 직감 버전**

- - 그래프 이론에서 **edge-expansion(엣지 확장)** 은 대충 이런 느낌이다:

> **“어떤 노드 묶음 S 을 떼어냈을 때, 그 묶음 S밖으로 나가는 간선이 얼마나 많이 튀어나오는가?”**

- - 즉, **큐비트 한 개당 “밖으로 나가는 연결 수”가 얼마나 많은지**를 보는 지표다.
  - 이 값이 **크다**는 말은:

    - “어느 정도 크기의 덩어리 S를 잡아도,
    - 그 덩어리 밖과 연결된 간선이 어마어마하게 많다”
    - 즉, **모듈로 쪼개도 모듈 간 연결이 엄청 많다**는 뜻.

**💡****모듈형 양자컴퓨터에서 왜 문제인가?**

- - 모듈형 아키텍처를 생각해 보자.

    - 하나의 **모듈 = 특정 개수의 큐비트 + 그 안에서의 고속 게이트**
    - 모듈 간 게이트/통신은 **느리고 오류율이 더 크고, 자원도 많이 든다**
    - (이온 셔틀링, 광자 링크, 버스 모드 등…)
  - 이때, 만약 어떤 코드의 Tanner graph가 **edge-expansion이 큰 그래프**라면:

    - 모듈 하나에 해당하는 큐비트 집합 S를 대응시키면,
    - 그 S 밖으로 나가는 간선이 **무지막지하게 많다** →
    - = “모듈 간 게이트가 엄청 많이 필요함”

> **코드의 오류 정정 구조 자체가 “모듈 경계를 무시하고 다리(간선)를 많이 걸어놓은 상태”라서,**
>
> **하드웨어 입장에서는 모듈 간 연산이 폭발적으로 증가.**

- - 그래서 BB 같은 고성능 qLDPC 코드는 **오류정정 관점에서는 최고지만,**
  - **모듈형 HW에서는 그대로 쓰면 통신 지옥**이 되는 것이다.

**💡그림 1. Tanner Graph의 모듈 분리**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMjNfMjMx/MDAxNzYzODcxMTk3MzQx.Ih8xSjDoxoI2rlyWgItKkwGed0GcMQr_j4qEFYZHJKsg.TfkOTtg-KxLo7hpihdJxoiTkaOi34Qobi_0BMp14PgIg.PNG/image.png?type=w800)](#)

- - - **Surface code Tanner Graph**

      - 2D 격자(grid lattice)
      - **각 qubit는 주변 이웃(qubit 또는 stabilizer)과만 연결**
      - 연결 구조가 **Local / Nearest-neighbor**
      - **Module 1과 Module 2 사이에는 연결이 거의 없음**
      - 즉, 모듈 분할 시 **연결(edge) 단절 → 병목 발생**
      - 모듈형 아키텍처(MQC)로 확장할 때 **확장성(scalability) 한계**
    - **qLDPC Tanner Graph**

      - 바깥 원: **variable nodes (data qubits)**
      - 중간 원/안쪽 원: **stabilizer check nodes (X-check, Z-check)**
      - 선(edge): **parity-check constraint connections**
      - 각 qubit는 **long-range, sparse, 다수의 stabilizer와 연결**
      - 모듈 1 ↔ 모듈 2 사이 연결(edge) **엄청나게 많이 존재**

        - **Edge Expansion 문제로 인해, 통신 지옥이 된다는 의미임.**
      - **Local layout이 아니라 글로벌 geometry**

****

**💡****“좋은 코드” vs “힘든 레이아웃”의 역설**

- - 코드이론 관점에서:

    - Edge-expansion이 큰 그래프 = **좋은 LDPC 코드**
    - 랜덤한 에러 패턴이 흩어져도 잘 잡아낸다
    - 최소 거리, 스펙트럼, 디코딩 성능 등에서 유리
  - 하지만 **하드웨어/레이아웃 관점**에서는:

    - Edge-expansion이 크다 = “어느 부분을 잘라 모듈 하나로 만들어도 **밖으로 나가는 에지(=모듈 간 게이트)가 엄청 많다**”
    - 특히 BB 코드처럼 **여러 논리 큐비트를 동시에 고효율로 보호**하는 코드일수록 **모든 논리/체크 구조가 전체에 걸쳐 강하게 섞여 있음**

> **edge-expansion이 크다 = BB 코드가 강력하다 + 모듈형 배치에선 난이도 극상**
>
> 이 두 가지가 동시에 성립한다.

**💡IonQ가 제시하는 해법과 edge-expansion의 관계**

- - 여기서 **Sparse Cyclic Layout**이 등장한다.

    - 일반적으로 qLDPC/BB Tanner graph의 큰 edge-expansion 때문에 어떤 식으로 모듈을 나누어도 **모듈 간 연결이 많이 생기는 것이 원래 구조**
    - 그런데 IonQ는:

      - **큐비트를 실제로 이동시킬 수 있는 이온트랩 특성** +
      - **cyclic shift 기반 레이아웃** +
      - **BB 코드의 “순환 구조(cyclic structure)”** 를 이용해서

> “그래프의 복잡한 edge-expansion 구조를
>
> 하드웨어 상에서는 **소수의 ‘패턴화된 cyclic shift’로 흡수**해버린다”

- - - 즉, 논리적으로는 edge-expansion이 큰 qLDPC / BB 코드를 쓰지만,
    - 물리 레이아웃에서는:

      - ancilla 모듈을 몇 번만 특정 규칙으로 순환 이동시키면
      - 필요한 모든 체크를 **순차적으로** 구현할 수 있도록 바꾼 것.

> **BB 코드의 큰 edge-expansion이라는 “이론적으로 좋은 성질”을 그대로 유지하면서도,**
>
> **하드웨어 측 부담(모듈 간 연결 폭발)을 “flying qubits + sparse cyclic layout”으로 상쇄한 것이 IonQ의 포인트.******

**✅****General Cyclic Shift 와 Sparse Cyclic Shift의 차이점.**

**🔁 General Cyclic Shift (일반 Cyclic Shift)**

- - **모든 ancilla parcel(ancilla 모듈)을 한 칸씩 오른쪽으로 이동시키는 동작을 일정한 순서로 반복**
  - 그 결과, **각 ancilla가 모든 data parcel을 순차적으로 만나게 해서** 모든 stabilizer 측정을 수행함

[![](https://mblogthumb-phinf.pstatic.net/MjAyNTExMjNfMTAw/MDAxNzYzODcxMzU3MzE2.i2wgIH6JvuiySgCHnFMAsDL6e60SkWONjh45z3-eCX4g.8y5zOxmBay33TZrwCpWL6E3itVV_y2YKYci7rmJqQHQg.PNG/image.png?type=w800)](#)

**🌟 Sparse Cyclic Shift (희소 Cyclic Shift)**

- - **Shift를 매번 1칸씩 하는 일반 Cyclic과 달리,**
  - **특정 코드 구조(BB code의 polynomial/circulant 구조)에 맞춘 “필요한 Shift만 선택적으로 수행”**
  - **288 큐비트 경우 4번의 쉬프트 만으로 충분**

**🆚 비교 요약**

|  |  |  |
| --- | --- | --- |
| **항목** | **Cyclic Shift (일반)** | **Sparse Cyclic Shift** |
| 목적 | 모든 ancilla가 모든 data와 만남 | 필요한 pairing만 수행 |
| shift 횟수 | 코드 크기 L에 비례 | **작고 고정된 수 (O(1))** |
| Latency | 큼, 커질수록 증가 | **극도로 작아짐** |
| 효율 | 단순하지만 비효율 | **최적화되어 FT scaling 핵심** |
| 적용 코드 | 모든 stabilizer 코드 | **BB(qLDPC)처럼 circulant 구조를 가진 코드에 최적** |

> **General Cyclic = 마을버스**
>
> 모든 정류장을 일일이 하나씩 순서대로 들러야 함
>
> 전체 이동 시간 = 정류장 수에 비례 → **O(N)**
>

**🔢 수학적 구조**

- - BB 코드는 다음 형태의 **polynomial parity-check matrix**를 가진다:

- - 여기서

    - A(x),B(x)는 **다항식(polynomials)**
    - 항(terms)들은 **순환 행렬(circulant matrices)** 에 대응됨
    - 항의 degree들이 **shift amount**가 됨
  - 예시 (설명용 단순화):

- - 그러면,

    - nonzero 항의 위치 = **연결되는 데이터 parcel index**
    - exponent = **shift 거리**

      - Shift 0
      - Shift 37
      - Shift 101
      - Shift 203
    - 이 네 개의 이동이 만들어 내는 edge 패턴만으로 전체 Tanner graph 구성이 된다.

      - 실제로 이 4가지 수는 288과 서로소(공약수가 1인수)라서,

        - cyclic group에서 “잘 섞이는” 역할을 할 수 있고
        - sparse cyclic shift에서 소수 차수처럼 “좋은 궤도(orbit)”를 만들어 줌

**🧠****Logical qubit(논리 큐비트)란?**

- - 여러 **물리 큐비트**를 묶어서 **오류에 강한 안정적인 큐비트(software-defined qubit)** 를 만든 것
  - 개념은 **Peter Shor(1995)** 의 QEC 연구에서 시작됨
  - **Fault tolerance(결함 허용)** 와 함께 대규모 실용 양자컴퓨터의 필수 구성요소

**❗ 하지만 오해가 많다**

- - “논리 큐비트 = 항상 더 좋다”는 잘못된 생각
  - 실제로 많은 초기 논리 큐비트 데모는 **느리고**, **불안정하고**, **사용 가능한 게이트 세트가 제한적**
  - 좋은 논리 큐비트를 만들려면 **높은 품질의 물리 큐비트**가 필수

**🧾 논리 큐비트 평가 기준 5가지**

|  |  |
| --- | --- |
| **항목** | **의미** |
| Overhead | 물리→논리 변환 효율 |
| Idle logical error rate | 저장 중 오류 가능성 |
| Logical gate fidelity | 논리 게이트 정확도 |
| Logical gate speed | 연산 속도 |
| Gate universality | 모든 알고리즘 지원 여부 |

**🔧 Fault tolerance는 On/Off 스위치가 아니다**

- - **완전한 FT는 하나의 점이 아니라 연속적인 스펙트럼**
  - 각 응용마다 **요구되는 logical error rate** 가 다름
  - 요구 정확도(ex: 10-15) 를 충족하는 **noise budget** 관점으로 봐야 함
