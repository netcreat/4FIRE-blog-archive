**✅Distributed, Network-Aware Quantum Compiler란?**

- - “여러 개의 QPU를 하나의 거대한 QPU처럼 쓰기 위해, 회로를 자동으로 쪼개고 배치하고, 네트워크와 엔탱글먼트 상태까지 감안해서 스케줄링하는 컴파일러”

    - 두 가지를 동시에 고려한다는 것이 포인트

      - **Distributed**
      - **Network-aware**

****

**💡****Distributed Compiler의 역할**

- - Distributed compiler는 처음부터 “이 회로를 QPU A, QPU B, QPU C에 나누어 돌린다”를 전제로 설계됨.
  - 그래서 해야 할 일이 많아진다:

    1. **회로 분할 (Partitioning)**

       - 전체 알고리즘을 서브 회로(서브프로그램)로 나눔
       - 어떤 큐비트 집합은 QPU-A, 어떤 집합은 QPU-B에 배치
       - 통신(teleportation, entanglement) 비용이 최소가 되도록 분할
    2. **논리–물리 매핑 (Logical to Physical mapping across devices)**

       - QPU별 토폴로지, 에러율, 사용 가능한 논리 큐비트 수 고려
       - “어떤 서브회로를 어느 QPU에 올릴지” 결정
    3. **인탱글먼트 자원 스케줄링**

       - QPU 간 CNOT이나 CZ 같은 cross-device 연산이 필요할 때
       - 실제로는 **teleportation + classical feed-forward**로 구현
       - 이때 필요한 **entangled pair(EPR pair)** 를 **언제, 어디서, 얼마나 준비할지** 미리 계산하고 요청
    4. **네트워크 지연/대역폭 고려**

       - classical network처럼 **latency, bandwidth**가 존재
       - 너무 자주 cross-QPU 연산을 하면 오버헤드 폭발
       - → 가능한 한 **local 연산을 많이, remote 연산은 적게** 사용하도록 알고리즘 재구성
    5. **Distributed Error Correction-aware**

       - 각 QPU는 각각 FT 코드를 돌리고 있지만
       - **논리 큐비트가 다른 QPU로 teleport될 때의 cost**,
       - syndrome 교환, recovery time까지 **컴파일 단계에서 고려**

****

**💡****Network-Aware의 “진짜 의미”**

- - 단순히 “네트워크가 있다는 것을 안다” 수준이 아니라:

    - **네트워크 상태(available entanglement, link noise, congestion)를 실시간 반영**
    - classical SDN(Software-Defined Networking)처럼 “지금 이 링크는 얽힘 품질이 좋다 / 얘는 지연이 길다 / 이쪽 경로는 바쁘다” 같은 정보를 **컴파일러 / 런타임이 함께 사용**

> **Network-aware Quantum Compiler = SDN + Distributed QEC + Quantum Compiler의 결합체**

**💡Cisco가 제안하는 전체 구성/기술 스택**

- - Cisco 쪽 발표를 네가 준 텍스트까지 포함해서 정리하면, 크게 네 계층으로 나눌 수 있어:

    1. **물리 계층 (Entanglement Chip, Photonics)**

       - 초당 2억(200M) 쌍 이상의 얽힌 광자 생성
       - 99% fidelity 수준
       - 텔레콤 파장대(1.3/1.5μm)에서 동작 → 기존 광섬유와 호환
       - 실온에서 동작 가능 (QPU는 냉동, 광 네트워크는 상온)
    2. **링크 & 라우팅 계층 (Quantum Network Nodes)**

       - Quantum Router / Switch
       - ELP (Elementary Link Protocol)
       - EDP (Entanglement Distribution Protocols)
       - QRP (Quantum Routing Protocol)
    3. **컴파일러 & 런타임 계층 (Network-aware Compiler)**

       - Quantum Controller는 Quantum Routing을 위해 필요한 핵심 구성 요소
       - 중앙 컨트롤 서버에서 Distributed Compiler + Runtime + Entanglement Resource Manager + Scheduling을 맡는 구조
    4. **데이터센터/애플리케이션 계층 (Quantum Datacenter Vision)**

       - Cisco가 그리는 큰 그림
       - “여러 개의 Cryostat 속 QPU들을 하나의 데이터센터 네트워크로 묶고, 이 데이터센터를 다시 여러 지역/국가 간에 연결하는 Quantum Datacenter–Quantum Internet 아키텍처”
