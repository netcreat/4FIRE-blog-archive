**🧮****플래시 셀에서 큐비트까지: IonQ가 양자 오류 정정을 발전시키기 위해 고전 플래시 메모리에서 영감을 얻는 방법**

**🔬연구 배경**

- IonQ는 상업 고객 지원과 동시에 미래형 양자 컴퓨터를 위한 **오류 정정 기술**을 개발한다.
- 이번 연구는 **고전 플래시 메모리의 멀티 레벨 셀**에서 영감을 얻어, **적층형(Stacked) 양자 메모리**와 **양자 Gabidulin 코드**를 제안한다.

**💾고전 플래시 메모리에서의 교훈**

- 플래시 메모리는 전자 수에 따라 비트를 저장하며, **멀티 레벨 셀**을 통해 한 셀에 여러 비트를 저장한다.

  - 2비트를 저장하면 멀티레벨셀(MLC)라고 부르며,
  - 오늘날의 기술은 3~4비트 저장 셀을 사용하고, 5비트 저장 셀도 개발중이다.
  - 장점

    - **정보 밀도 증가** → 동일한 면적에 더 많은 정보를 저장 가능
    - **제조 비용 절감** → 더 적은 셀로 동일 용량 확보 가능
  - 단점

    - 셀은 수명 동안 **여러 번 충방전**을 반복한다.
    - 이 과정에서 셀 벽이 마모되어 전자를 유지하기 어려워진다.
    - 결과적으로 전압이 서서히 드리프트(drift)되어 읽기 오류(readout error)가 발생한다.
    - 특히 **멀티 비트 저장 셀**에서는 하나의 오류가 **모든 비트**에 영향을 줄 수 있다.
    - **→ 강력한 오류 정정 코드**가 필수적이다.

**🧩스택드 양자 메모리 개념**

- IonQ는 고전 플래시 메모리에서 영감을 얻어 **한 원자(셀)에 여러 큐비트**를 저장하는 방식을 제안한다.
- 예를 들어 3큐비트 셀은 8개의 전자 궤도로 상태를 표현하며, 이를 여러 층으로 쌓아 **스택드 메모리**를 구성한다.

  - 여기서 셀은 원자 하나다.
  - 전자는 두 궤도의 중첩 상태에 있기 때문에, 한개의 큐비트를 저장한다.
  - 2큐비트를 한 원자에 저장하려면 4개의 궤도가, 3 큐비트를 저장하려면 8개의 궤도가 필요하다.

- 동일한 양자 회로를 층마다 병렬 실행해 **처리량을 3배 이상 높이는 효과**를 기대한다.

**🔐양자 Gabidulin 코드**

- 멀티 큐비트 셀에서는 한 큐비트 오류가 다른 큐비트로 확산한다.
- IonQ는 **클래식 네트워크 코딩의 Gabidulin 코드**를 양자에 적용해 새로운 방식의 오류 정정을 제시한다.

[![](https://images.ctfassets.net/hqm865gc1xfs/2fizKrf0N1qmiPYsEzjfD7/9e588cea22a56bc52e32b4efc3705121/Network_Encoding_with_Fault.png)](#)

출처 : 아이온큐 홈페이지 - 중간 노드에 에러가 생기고, 에러가 수정이 안되면 이후 모든 단계에 영향을 끼치게 된다.

- - 네트워크 상의 오류전파와 멀티 큐비트 셀의 오류 전이는 동일한 현상임.

**🌟연구 의의**

- **큐비트 효율적인 오류 정정** 가능성을 제시한다.
- **스택드 메모리 병렬 실행**으로 처리량과 속도를 높인다.
- 변분 양자 알고리즘(VQA)과 **논리 큐비트 리소스 생성** 등 실제 응용에도 기여할 수 있다.

IonQ는 이 접근법이 **확장성**과 **오류 정정**이라는 양자 컴퓨터의 핵심 과제를 동시에 진전시키는 기반이 된다고 본다.

**⚡핵심 요약: 장기적 양자 오류 정정과 확장성의 잠재적 해법**

- **새로운 오류 정정 접근법**

  - 회로 오류를 저랭크 행렬로 취급
  - 기존 대비 큐비트 효율적인 양자 오류 정정 가능성
- **처리량 증가 및 실행 속도 향상**

  - 스택드 메모리에서 동일 회로를 다층 병렬 실행
  - 클리포드 회로 중심 작업의 처리량 최대 3배
- **실제 응용 잠재력**

  - 변분 양자 알고리즘(VQA) 및 최적화 가속

- **이번 연구는 아직 초기 단계지만, 확장성(Scalability) 오류 정정(Error Correction) 양대 과제를 동시에 진전시키는 중요한 발걸음이다.**

**1️⃣ 퀀텀 메모리란 무엇인가?**

- **클래식 메모리**

  - RAM, SSD, HDD 등
  - **0/1 비트 상태를 안정적으로 유지**
  - 읽기/쓰기 후 상태가 변하지 않음 (논리적 비가역 연산 없음)
- **양자 메모리**

  - **큐비트의 상태(중첩·얽힘 포함)를 일정 시간 유지**
  - decoherence(디코히런스) 없이 **계산·통신에 재사용 가능**
  - 예:

    - 계산 중간 결과(양자 상태)를 임시 저장
    - 매직 스테이트, 스태빌라이저 상태를 안정화해 로직에 공급
    - 양자 네트워크에서 **큐비트를 보관 후 전송** (큐비트 버퍼 역할)

****

**🔹 기존 양자컴퓨터의 “메모리” 사용 방식**

- **연산용 큐비트 = 저장소**

  - 초전도체, 이온트랩, 포토닉 등 어떤 하드웨어든 **큐비트를 계산에 쓰면서 동시에 상태를 유지**
  - 예: IBM이나 IonQ QPU에서 **논리/보조 큐비트**가 계산 중간 상태를 그대로 유지 (RAM 같은 역할)
- **중간 상태를 따로 보관하는 장치 없음**

  - 클래식처럼 DRAM·SSD 같은 계층 구조 없음
  - 계산 과정에서 필요한 상태는 전부 **레지스터처럼 존재하는 큐비트**에만 보관
  - 상태를 오래 유지해야 하면 QEC(오류 보정)로만 버팀
- **실제 동작 흐름 예시**

  - **QAOA / VQE 같은 NISQ 알고리즘**:

    - 초기 상태 준비
    - 파라미터 회로 적용
    - 측정 → 결과를 클래식으로 전송
    - 중간 상태를 장기 보관하지 않고 바로 측정/폐기
  - **FTQC 로드맵**에서는

    - 논리 큐비트를 계속 유지하기 위해
    - **Surface code / LDPC code** 기반 **지속적 오류 보정** 사용 → 사실상 이것이 임시 메모리 역할

****

**🔹 기존 접근의 한계**

- **메모리 계층 부재**

  - 모든 큐비트를 같은 수준에서 유지해야 하므로
  - **비용 ↑, 확장성 ↓**
- **상관 오류(correlated error) 취약**

  - 장기간 상태 유지 시

    - 환경 잡음이나 하드웨어 cross-talk 때문에
    - **여러 큐비트가 동시에 깨짐** (i.i.d. 가정 붕괴)
- **Magic State Factory·Stabilizer 준비의 병목**

  - FTQC에서는

    - 비클리포드 연산용 매직 스테이트를 대량 생산/저장 필요
    - 별도 안정적 메모리 없으면 **계산과 저장이 충돌** → 병목

****

**🔹 IonQ의 접근(스택형 메모리)**

- **기존:** 모든 큐비트를 연산용+저장용으로 다같이 쓰고, **Surface code** 등으로만 보호
- **IonQ 제안:**

  - 계산용 큐비트와 **계층적 저장용 큐비트 분리**

    - 여기서 **Qudit(5,7 또는 13레벨)**를 이용하거나 포토닉 인터커넥트를 언급함.

        - 메타안정상태인 **5D****3/2** **준위**는

바륨을 이용한 13레벨 다준위 큐비트 제어 및 측정

- - - 저장하는 대상: **양자 상태**(중첩·얽힘 포함)
    - 목표: **장시간 유지 + 필요 시 읽기/쓰기**
  - 저장 계층에는 **멀티큐비트 셀+Rank-metric QEC** 적용

**2️⃣ Gabidulin 코드란 무엇인가?**

지난 2개의 포스팅에서 언급하길, IonQ는 qLDPC 코드를 개발중이고(이미 BB5를 발표했었다), 동시에 CliNR를 수정하여 오류완화의 투트랙으로 간다고 했었는데, 왜 새로운 코드가 발표되었는가?

**일반적인 오류 정정 코드**

- - 우리가 흔히 아는 해밍 코드, LDPC 코드 등은 해밍 거리(Hamming distance) 기반으로 설계된다.
  - 해밍 거리는 “서로 다른 위치의 비트 개수”를 세는 방식이다.
  - 예: 1011과 1001의 해밍 거리는 1

**Rank-metric 코드**

- - 랭크 거리(rank distance)를 사용한다.
  - **행렬 형태의 데이터**에서 오류가 특정 행/열에 모여 있을 때 유용하다.
  - 메시지를 **행렬 형태로 표현**하고, **오류도 행렬로 모델링**한다.

    - 예: 데이터 행렬 A, 오류 행렬 E
    - **랭크 거리 = 오류 행렬 E의 랭크(선형 독립 행 개수)**
  - 즉, 비트 몇 개가 바뀌었는지가 아니라, **오류가 차지하는 선형 독립 방향 수로 판단**한다.

**💡 장점**

- - 네트워크 코딩이나 메모리 오류처럼 **국소적인 오류가 확산되는 환경에서 강력**하다.
  - 예: 한 열(Column)에만 오류가 나도, 여러 비트가 동시에 잘못되지만 랭크는 1일 수 있다.

****

**Gabidulin 코드 (클래식)**

- - **Rank-Metric 코드**의 대표격
  - 행렬에서 **랭크 오류**(예: 버스트 오류, 패킷 손실)를 복구하는 데 강함
  - **네트워크 코딩**이나 **스토리지**에서 쓰임

**양자 일반화 (Quantum Gabidulin Codes)**

- - IonQ+Zémor 연구의 핵심
  - **클리포드 회로에서 발생하는 다중 큐비트 오류**를 효율적으로 복구
  - 일반적인 QEC 코드(예: Surface code)는 **독립적 단일 큐비트 오류**에 강하지만
  - **버스트성/상관 오류(correlated error)에는 취약 → 여기서 Gabidulin 계열이 빛을 발함**

**주요 QEC 코드 비교**

|  |  |  |  |
| --- | --- | --- | --- |
| **코드 유형** | **오류 모델에 대한 강점** | **약점 / 한계** | **하드웨어 적합성** |
| **Surface code** | - 단일 큐비트 오류 및 인접 2큐비트 오류에 강함  - 평면 격자 기반으로 구현 단순 | - **버스트성/상관 오류에 취약**  - 높은 물리 큐비트 오버헤드 | 초전도체, 실리콘 스핀 |
| **qLDPC** | - 낮은 오버헤드로 고코드 거리 확보 가능  - **멀리 떨어진 오류도 잡음 가능**  **- 표준적인 독립 오류 모델 대응**  - **FTQC를 위한 논리 큐비트에 적합** | - 구현 난이도 높음  - 디코딩 복잡도 ↑ | 대규모 모듈러 QPU |
| **Gabidulin 기반 QEC** | - Rank-metric 기반 양자 코드  - **상관/버스트 오류에 강함**  **- Staked quantum memory에 적합**  **- 클리포드 회로 & Magic state factory 보호에 최적화** | - 일반화 초기 단계  - 대규모 실증 없음 | 이온트랩 QCCD, 스택드 메모리형 QPU |

**저랭크 오류 정정 (Low-rank error correction)**

- 저랭크 오류란, 오류 행렬의 랭크가 낮은 상태를 의미한다.

  - 예: 적층형 양자 메모리에서 한 셀(여러 큐비트)에만 오류가 발생하면
  - 여러 큐비트 값이 틀려도
  - 그 오류는 하나의 원인(셀 단위)에서 비롯되어 랭크 1에 해당할 수 있다.

저랭크 오류 정정이란

- 이런 **낮은 랭크의 오류를 타깃**으로 하는 정정 기법이다.
- 해밍 기반 코드보다 효율적일 수 있다.

  - 왜냐하면 기존 코드는 “바뀐 비트 수”에 비례해 많은 패리티 비트를 필요로 하지만,
  - 랭크 기반 코드는 “오류의 독립적 원인 수”만 신경 쓰면 되기 때문이다.

****

**3️⃣ 이번 IonQ 논문과의 연결**

- **적층형 양자 메모리**에서는

  - 한 큐비트 오류가 같은 셀의 다른 큐비트로 확산됨 → 여러 비트 동시 오류
  - 해밍 코드로는 다중 비트 오류처럼 보임
  - 하지만 실제로는 원인(셀 단위)은 1개 → 랭크 낮음
- IonQ는 이를 활용해

  - 오류를 저랭크 행렬로 모델링
  - 양자 Gabidulin 코드(랭크-메트릭 코드)로 효율적 오류 정정을 제안함

**4️⃣적용 대상 기술**

**Stacked Quantum Memory와 Rank-Metric코드의 결합 기술**은 아래와 같이 **연산회수(깊이, depth)가 많고**, **오류가 누적되기 쉬운 과정** 및 **중간 상태를 오래 유지해야 하는 과정**에 적용되면 획기적인 성능향상을 기대할 수 있다.

- **Stabilizer State 준비**

  - 표준적인 양자 오류 보정 및 로직 게이트 준비 과정에서 안정성을 크게 향상
- **Magic State Factory**

  - T 게이트와 같은 비클리포드 연산을 위해 필요한 고품질 매직 스테이트 생산 효율 개선
- **스케일러블 QPU 아키텍처**

  - 모듈러/타일 기반 QPU 설계 시 계층적 양자 메모리 구조 적용 가능
- **Clifford Noise Reduction(CliNR)** 같은 저오버헤드 오류 완화 기법과 시너지 가능

**5️⃣요약하면**

- 이 연구는 **양자 스토리지 및 오류 보정의 새로운 계층 모델**을 제안하며,

  - **클리포드 회로 오류 보정 → 안정적 매직 스테이트 → FTQC 확장성**을 노리는 기술이다.
- **IonQ의 하드웨어 로드맵**에서 보면,

  - 현재 **Forte II / 타일 기반 QCCD**와 **Oxford Ionics의 마이크로웨이브 제어 기술**
  - 여기에 **스택형 양자 메모리 + Gabidulin 기반 오류 보정**을 얹어 **저오버헤드 FTQC**를 목표로 하는 그림.
- **당면 과제**

  - 이론 모델과 수학적 검증 단계이기 때문에 아래와 같은 당면과제를 해결해야만 한다.
  - **멀티-큐비트 셀 하드웨어 실현**

    - **메타안정상태+하이퍼파인 준위 조합 →** **마이크로파 기반의 옥스포드 아이오닉스 칩에서 메타안정상태 구현 불가**

      - **메타 안정을 위해서는 1762nm 레이저 필요함**
      - **137****Ba****+** **이온의 경우 이론적으로 8개의 하이퍼파인구조 가능(3큐비트)하지만,** **제이만 효과로 인해 디코히어런스가 빠르고, 단일 마이크로파로 선택적 제어는 거의 불가능함.**
    - 포토닉 인터커넥트를 통한 다중 QPU를 통한 멀티 메모리 구현이 대안이라 생각됨
  - **셀 간 크로스토크 억제**

    - 제어 신호가 인접 셀에 간섭하면 저랭크 오류 모델이 깨짐
  - **랭크-메트릭 전용 신드롬/디코더 개발**

    - 저랭크 행렬 기반 오류 측정이 필요하기 때문에 전용 신드롬과 디코더가 필요함
  - **실제 FTQC 응용과의 통합 검증**

    - Magic state factory, stabilizer factory, VQA에서 성능 이점 검증 필요
    - 실제 하드웨어에서 병렬 실행을 안정적으로 유지하는 것이 과제
