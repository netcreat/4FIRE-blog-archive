# AI 인프라 병목, 메모리 3사 다음에 준비해야 할 기술과 기업

Published: 2026-06-25T17:24:26.757000+09:00

Original Naver post: https://blog.naver.com/4-fire/224327133028

---

**✅ 핵심 요약**

- - 지난 몇 년 동안 AI 인프라의 1차 병목은 GPU 연산 성능에서 HBM과 고성능 DRAM으로 이동했다. 그 결과 SK하이닉스, Micron, Samsung Electronics 같은 메모리 3사는 이미 강한 주가 재평가를 받았다.
  - 따라서 지금부터 중요한 질문은 “메모리 3사가 더 오를 것인가”가 아니다. 더 중요한 질문은 다음과 같다.

    - **HBM 병목이 이미 시장에 반영된 이후, 다음 병목은 어디로 이동할 것인가?**
  - 이 보고서는 그 다음 병목을 다섯 가지로 본다.

    - 첫째, **CXL과 memory fabric**이다.

      - HBM과 DRAM을 더 많이 만드는 것만으로는 부족하다. 앞으로는 메모리를 어디에 두고, 어떻게 공유하고, 어떻게 풀링할지가 중요해진다.
    - 둘째, **UALink와 accelerator scale-up fabric**이다.

      - AI 모델이 커질수록 단일 GPU로는 부족하다. 여러 GPU 또는 AI accelerator를 하나의 거대한 accelerator complex처럼 묶는 기술이 중요해진다.
    - 셋째, **Ethernet/RoCE, InfiniBand, Ultra Ethernet 같은 서버 간 scale-out network**다.

      - GPU와 메모리가 충분해질수록, 다음 병목은 서버와 서버 사이의 데이터 이동으로 넘어간다.
    - 넷째, **optical interconnect, CPO, SerDes**다.

      - 전기 신호 기반 연결은 전력, 거리, 발열에서 한계를 맞기 때문에 광통신 기반 데이터 이동이 점점 중요해진다.
    - 다섯째, **전력과 냉각 인프라**다.

      - AI 클러스터가 커질수록 최종 병목은 반도체 성능이 아니라 전력 공급과 열 관리가 될 가능성이 높다.
  - 따라서 HBM 이후의 핵심 수혜 기업은 메모리 3사보다 **Astera Labs, Marvell, Broadcom, Arista, Cisco, NVIDIA Networking, AMD, Coherent, Lumentum, Credo, Vertiv, Schneider Electric, Eaton** 같은 **연결·네트워크·광·전력 인프라 기업**으로 확장된다.

---

**✅ 메모리 3사는 왜 비중을 낮춰야 하는가**

- - SK하이닉스, Micron, Samsung Electronics는 여전히 중요하다.
  - HBM, DDR5, MRDIMM, CXL DRAM, NAND, HBF 모두 결국 메모리 제조사의 제품이기 때문이다.
  - 그러나 투자 관점에서는 이들이 이미 **1차 병목의 대표 수혜자**라는 점이 중요하다. HBM 부족은 더 이상 숨겨진 테마가 아니다. AI GPU 수요가 HBM 수요를 끌어올리고, HBM 공급 부족이 DRAM 가격과 고성능 NAND 수요까지 밀어 올리는 구조는 이미 시장의 중심 스토리가 되었다.
  - 따라서 이 보고서에서 메모리 3사는 중심이 아니라 **기준점**이다.
  - 즉 이들은 다음과 같이 봐야 한다.

    - **메모리 3사 = 이미 확인된 1차 병목 수혜자**
    - **CXL·UALink·Ethernet·Optical·Power 기업 = 병목이 다음 단계로 전이될 때의 잠재 수혜자**
  - HBM 랠리가 “GPU에 붙는 메모리가 부족하다”는 문제에 대한 시장의 반응이었다면, 다음 랠리는 “그 메모리를 어떻게 연결하고, 공유하고, 이동시키며, 전력을 공급할 것인가”에서 나올 가능성이 높다.

**✅ 첫 번째 다음 병목: CXL과 Memory Fabric**

[![](https://mblogthumb-phinf.pstatic.net/MjAyNjA2MjVfMjc0/MDAxNzgyMzc1MTgyNTEx.ijhsyMQkTbR9z7aE3tSP8me5f0HgyUDC2l7w-ySMeHwg.kQnXSf208AMFewswKOnJlNgqkv5NbQCKDtcLlYYgzLQg.PNG/image.png?type=w800)](#)

- - HBM은 빠르지만 비싸고 용량이 제한적이다. DDR은 싸고 용량을 키우기 쉽지만, GPU의 hot path를 감당할 만큼 빠르지 않다. 이 사이에서 CXL은 “더 빠른 메모리”가 아니라 **더 유연한 메모리 구조**를 만드는 기술로 주목받는다.
  - CXL의 핵심은 CPU가 외부 메모리 장치를 더 자연스럽게 접근하고, 장기적으로는 메모리를 서버에 고정하지 않고 풀링하는 것이다.
  - 기존 구조에서는 서버마다 메모리가 고정되어 있다.

    - 서버 A는 메모리가 부족하고 CPU는 놀고 있을 수 있다.
    - 서버 B는 메모리가 남지만 다른 서버가 쓸 수 없다.
    - CXL memory pooling이 성숙하면 이런 구조가 바뀔 수 있다.
  - 각 서버가 고정된 DRAM만 쓰는 것이 아니라, CXL fabric을 통해 외부 DRAM 또는 memory pool을 필요에 따라 할당받는 구조가 가능해진다.
  - 이것은 스토리지가 로컬 디스크에서 SAN, NAS, NVMe-oF로 진화한 것과 비슷한 방향이다. 다만 CXL은 스토리지가 아니라 메모리 계층이다.

**📌 CXL이란?**

- - CXL은 크게 세 타입이 있다.

    - Type 1: “메모리 없는 coherent accelerator”

      - CPU가 CXL.mem으로 접근할 수 있는 대용량 로컬 메모리를 제공하지 않는다는 뜻에 가까움
    - Type 2: “자체 메모리를 가진 coherent accelerator”

      - Type 2는 가장 복잡하고 강력한 형태. GPU, FPGA, AI accelerator처럼 자체 HBM/GDDR/DRAM을 가진 가속기가 여기에 해당한다.
      - 양방향 성격이 있음

        - 첫째, 디바이스가 CXL.cache로 **CPU 메모리를 coherent하게 접근**할 수 있다.
        - 둘째, CPU가 CXL.mem으로 **디바이스의 로컬 메모리, 예를 들면 HBM/GDDR, 에 접근**할 수 있다.
    - Type 3: “메모리 버퍼/확장기”

      - Type 3는 계산 가속기가 아니다. 핵심 기능은 CPU에게 추가 메모리를 제공하는 것이다.

> ***비유***
>
> ***Type 2 : 네트워크상에 있는 다른 장치의 리소스를 내가 접근해서 쓰는 느낌***
>
> ***Type 3 : NAS/SAN처럼 여러 주체에게 공용 리소스를 제공하는 느낌***
>
> ***각자의 컴퓨터를 사용하다가 옆 사람 컴퓨터의 파일을 엑세스 하려면, USB로 카피해달라고 해야 겨우 엑세스 할 수 있었는데, 컴퓨터를 LAN으로 연결하고, 네트워크에 NAS를 연결해 놓으면 모든 사용자들이 NAS에 파일을 올리고, 내려받기 쉬워지는 이치와 비슷할 수 있겠다.***

**✅ 두 번째 다음 병목: UALink와 Accelerator Scale-up**

- - AI 모델이 커질수록 단일 GPU로는 부족하다.
  - 그래서 여러 GPU 또는 AI accelerator를 하나의 큰 accelerator complex처럼 묶는 scale-up fabric이 중요해진다.
  - 현재 이 영역의 최강자는 NVIDIA다.

    - NVIDIA는 GPU, HBM, NVLink, NVSwitch, InfiniBand, CUDA를 수직 통합했다. 이 구조 덕분에 NVIDIA GPU 서버는 단순 GPU 묶음이 아니라 하나의 거대한 AI 시스템처럼 동작한다.
  - 그러나 이 강점은 동시에 hyperscaler와 경쟁사 입장에서는 부담이다. NVIDIA 생태계에 지나치게 종속되기 때문이다.

    - 여기서 등장한 것이 **UALink**다.
  - UALink는 CXL의 경쟁자가 아니다.
  - CXL은 CPU와 memory, CPU와 accelerator를 연결하는 기술에 가깝다.
  - UALink는 accelerator와 accelerator를 직접 연결하는 기술이다.
  - 즉 UALink는 CXL보다 **NVLink/NVSwitch의 오픈 대안**에 가깝다.

**📌 NVLink / NVSwitch / UALink**

|  |  |  |
| --- | --- | --- |
| **구분** | **주 대상** | **성격** |
| **NVLink / NVSwitch** | GPU ↔ GPU | NVIDIA GPU들을 하나의 큰 GPU complex처럼 묶는 scale-up fabric |
| **NVLink-C2C** | CPU ↔ GPU, chip ↔ chip | NVIDIA의 cache-coherent chip-to-chip interconnect |
| **CXL Type 1** | CPU ↔ 메모리 없는 accelerator | accelerator가 host memory를 coherent하게 접근 |
| **CXL Type 2** | CPU ↔ 자체 메모리 가진 accelerator | GPU/FPGA/AI ASIC 같은 장치와 host memory/device memory 공유 |
| **CXL Type 3** | CPU ↔ memory expander | CPU에 외부 DRAM/PMEM/CXL memory 제공 |

**📌** **주목할 기업**

- - **NVIDIA**

    - NVIDIA는 이 영역의 현재 지배자다. NVLink와 NVSwitch는 이미 AI scale-up의 사실상 표준처럼 쓰이고 있다.
    - 다만 투자 관점에서는 NVIDIA가 너무 명확한 수혜주라는 점이 문제다. 이미 GPU, 네트워킹, 소프트웨어, AI factory 기대가 주가에 상당히 반영되어 있다.
    - NVIDIA는 여전히 가장 강하지만, 이 보고서의 목적이 “다음 준비 대상”이라면 NVIDIA는 신규 발견 종목이라기보다 비교 기준이다.
  - **AMD**

    - AMD는 UALink 진영에서 가장 중요한 상장 대항축이다. EPYC CPU, Instinct GPU, Infinity Fabric/XGMI, Pensando networking, Helios rack 전략을 통해 NVIDIA의 수직 통합에 도전하고 있다.
    - AMD의 투자 포인트는 단순히 GPU 점유율 확대가 아니다. 더 중요한 것은 AMD가 NVIDIA 독점적인 scale-up architecture에 대한 **오픈 생태계의 중심축**이 될 수 있느냐이다.
    - 리스크는 소프트웨어와 생태계다. NVIDIA CUDA와 NVLink/NVSwitch의 완성도에 비해 AMD는 아직 시스템 레벨에서 증명해야 할 부분이 많다.
  - **Broadcom**

    - Broadcom은 UALink 자체보다 더 넓게 봐야 한다. 이 회사는 Ethernet switch ASIC, custom AI ASIC, SerDes, NIC, optical connectivity에 걸쳐 있다.
    - 특히 hyperscaler들이 자체 AI accelerator를 키우고 NVIDIA 의존도를 줄이려 할수록, Broadcom의 custom ASIC과 scale-up/scale-out fabric 역할이 커질 수 있다.
    - Broadcom은 이미 대형주이고 AI 기대가 많이 반영되어 있지만, HBM 이후의 데이터 이동 병목을 보면 여전히 가장 중요한 기업 중 하나다.

**✅ 세 번째 다음 병목: 서버 간 Scale-out Network**

- - 메모리가 충분해지고 GPU가 더 많이 묶이면 다음 병목은 서버와 서버 사이로 이동한다.
  - 대규모 학습에서는 all-reduce, all-to-all, parameter shard 이동이 중요하다.
  - 분산 추론에서는 prefill과 decode를 분리하거나, KV cache를 여러 노드에서 관리해야 할 수 있다.
  - Agentic AI에서는 여러 모델, tool, memory store, vector DB가 계속 통신한다.
  - 결국 AI 인프라는 GPU만 빠르다고 되는 것이 아니라, **서버 간 네트워크가 얼마나 빠르고 안정적이며 예측 가능하냐**가 중요해진다.
  - 현재 premium AI/HPC 네트워크에서는 **NVIDIA InfiniBand**가 강하다. Mellanox 인수 이후 NVIDIA는 InfiniBand switch, HCA, software stack을 모두 갖고 있다.
  - 하지만 더 넓게 커지는 시장은 **Ethernet**일 가능성이 높다.
  - Hyperscaler들은 비용, 운영성, 멀티벤더 공급망, 기존 데이터센터 네트워크와의 통합 때문에 Ethernet/RoCE와 Ultra Ethernet을 선호한다.
  - 따라서 다음 구도는 이렇게 봐야 한다.

    - **Premium AI/HPC = NVIDIA InfiniBand**
    - **대규모 hyperscale AI fabric = Ethernet/RoCE, Ultra Ethernet, Spectrum-X**
  - 중요한 점은 NVIDIA도 Ethernet을 한다는 것이다. NVIDIA는 InfiniBand만 하는 회사가 아니다. Spectrum-X Ethernet을 통해 AI Ethernet 시장도 가져가려 한다.4

**📌 RDMA / RoCE and InfiniBand**

- - RDMA는 NIC가 한 서버의 등록된 메모리 영역에서 다른 서버의 등록된 메모리 영역으로 데이터를 직접 옮기게 해주는 기술이다.

    - 여기서 “CPU 관여 없이”라는 말은 데이터 전송 경로에서 CPU가 복사 작업을 하지 않는다는 뜻이다.
    - 실제 데이터 복사는 CPU가 memcpy()로 하는 게 아니라 NIC가 DMA로 처리한다.
    - RDMA는 네트워크 어댑터가 wire에서 application memory로, 또는 application memory에서 wire로 직접 데이터를 옮겨 zero-copy networking을 가능하게 한다.
  - RoCE와 InfiniBand는 둘 다 RDMA를 구현/제공하는 대표적인 전송 기술이다.
  - 하지만 “근본이 RDMA”라기보다는, RDMA라는 기능을 제공하는 fabric/protocol 계열이라고 보는 게 더 정확하다.

    - RoCE는 이름 그대로 RDMA over Converged Ethernet, 즉 Ethernet 네트워크 위에서 RDMA를 가능하게 하는 프로토콜이다.
    - InfiniBand도 메시지 형태로 RDMA read/write, send/receive, atomic operation 등을 지원하는 고성능 switched fabric이다.

| **InfiniBand** | HPC/AI 클러스터용 전용 고성능 fabric. RDMA를 native하게 지원 |

**📌 CXL과 RDMA의 차이**

|  |  |  |
| --- | --- | --- |
| **구분** | **CXL** | **RDMA** |
| 기본 성격 | 메모리/캐시 coherent interconnect | 네트워크 기반 remote memory access |
| 주 사용 범위 | CPU ↔ device, CPU ↔ CXL memory, rack-scale memory | 서버 ↔ 서버, GPU cluster, storage, distributed systems |
| 접근 방식 | load/store, cacheline 중심 | NIC work queue, RDMA read/write/send |
| coherence | 핵심 기능 | 기본적으로 cache coherent 아님 |
| CPU 역할 | CPU load/store와 cache coherence 체계에 통합 | CPU는 설정/요청 제출, 데이터 이동은 NIC가 처리 |
| 대표 연결 | PCIe/CXL link, CXL switch/fabric | InfiniBand, RoCE Ethernet |
| 주 용도 | memory expansion, accelerator coherence, memory pooling | cluster communication, distributed storage, GPU-to-GPU/network transfer |

> ***비유***
>
> ***RDMA : 서버 A의 NIC가 서버 B의 허락된 메모리 창문으로 직접 택배를 밀어 넣는 것***
>
> ***CXL Type 3 : 서버 옆에 외부 메모리 책장을 붙여서, CPU가 자기 메모리처럼 주소로 읽고 쓰는 것***
>
> ***CXL Type 2 : CPU와 accelerator가 서로의 허용된 메모리/캐시 상태를 일관성 있게 맞추며 협업하는 것***

**📌** **주목할 기업**

- - **Broadcom**

    - Broadcom은 AI Ethernet의 핵심 기업이다. Tomahawk, Jericho, Thor 계열의 switch/NIC silicon은 대규모 Ethernet AI fabric에서 중요하다.
    - Ethernet이 InfiniBand보다 더 넓은 시장으로 커진다면 Broadcom은 가장 직접적인 수혜 기업 중 하나다.
    - 재무적으로 Broadcom은 이미 대형 고수익 기업이며, VMware 인수 이후 소프트웨어 매출도 섞여 있다. 이 때문에 순수 네트워크 반도체 기업으로만 보기는 어렵지만, AI Ethernet과 custom ASIC 양쪽에 노출되어 있다는 점이 강점이다.
    - 밸류에이션은 낮은 편은 아니다. 하지만 NVIDIA 대비 “AI 인프라의 다음 층”에 더 넓게 노출된 기업으로 볼 수 있다.
  - **Arista Networks**

    - Arista는 AI Ethernet switch system의 대표 수혜주다. Broadcom이 칩을 공급한다면, Arista는 그 칩을 기반으로 hyperscaler 데이터센터에서 실제 네트워크 시스템과 운영 소프트웨어를 제공한다.
    - Arista의 강점은 hyperscaler 고객 기반과 데이터센터 Ethernet 운영 역량이다. AI back-end network가 Ethernet으로 커질수록 Arista의 TAM도 커질 수 있다.
    - 리스크는 고객 집중도와 밸류에이션이다. Microsoft, Meta 같은 대형 고객 비중이 크고, AI Ethernet 기대가 이미 주가에 상당 부분 반영되어 있다.
  - **Cisco**

    - Cisco는 전통적인 네트워크 강자지만, AI 데이터센터에서는 Arista와 Broadcom, NVIDIA에 비해 다소 낮게 평가받아왔다.
    - 그러나 Silicon One, optical, 보안, 엔터프라이즈·통신사 고객 기반을 감안하면 Cisco도 AI networking 재평가 가능성이 있다.
    - Cisco의 장점은 안정적인 현금흐름과 상대적으로 낮은 밸류에이션이다. 단점은 순수 AI 성장주로 보기는 어렵고, hyperscale AI back-end에서 Arista만큼 강한 인식을 아직 완전히 확보하지 못했다는 점이다.
  - **NVIDIA Networking**

    - NVIDIA는 InfiniBand와 Spectrum-X Ethernet을 모두 갖고 있다. 따라서 서버 간 네트워크 병목이 커질수록 NVIDIA도 계속 수혜를 받을 수 있다.
    - 다만 이 보고서에서는 NVIDIA를 “다음 발굴 대상”이라기보다 현재 전체 AI 인프라 stack을 장악한 기준 기업으로 둔다. 새로운 알파를 찾는다면 NVIDIA 자체보다 NVIDIA에 맞서거나 보완하는 기업들을 더 봐야 한다.

  - Optical, SerDes, CPO, 전력, 냉각은 시간이 갈수록 중요해질 가능성이 높다.

**📌** **별도 관리: 이미 확인된 1차 수혜자**

- - **SK하이닉스, Micron, Samsung Electronics**
  - 이들은 여전히 AI memory cycle의 핵심 기업이다. 그러나 이 보고서에서는 중심이 아니라 배경이다.
  - 즉 “HBM 병목이 이미 가격에 반영됐다면, 그 다음은 어디인가?”라는 질문에 대한 비교 기준으로만 둔다.

---

**✅ 최종 결론**

- - HBM 랠리는 AI 메모리 병목의 1차 수혜였다.
  - 그러나 다음 기회는 단순히 메모리를 더 많이 만드는 곳이 아니라, 그 메모리를 **연결하고, 공유하고, 이동시키고****, 전력을 공급하고, 냉각하는 기업**에서 나올 가능성이 높다.
  - AI 인프라의 경쟁은 이제 GPU 단품 경쟁에서 다음 단계로 이동하고 있다.

    - 첫째, 메모리를 어떻게 풀링할 것인가.
    - 둘째, GPU와 accelerator를 어떻게 scale-up할 것인가.
    - 셋째, 서버와 서버를 어떻게 scale-out할 것인가.
    - 넷째, 데이터를 전기에서 빛으로 어떻게 이동시킬 것인가.
    - 다섯째, 이 모든 시스템에 전력과 냉각을 어떻게 제공할 것인가.
  - 따라서 HBM 이후의 핵심 기술은 CXL, memory fabric, UALink, Ethernet/RoCE, Ultra Ethernet, InfiniBand, optical interconnect, CPO, SerDes, power/cooling이다.
  - 투자 관점에서 한 줄로 정리하면 다음과 같다.

    - **메모리 3사는 이미 확인된 1차 수혜자이고, 다음 준비 대상은 CXL·UALink·Ethernet·Optical·Power/Cooling 인프라 기업이다.**
  - HBM 랠리가 “메모리가 부족하다”는 문제의 반응이었다면, 다음 랠리는 “데이터를 어디에 두고, 어떻게 움직이고, 어떻게 연결할 것인가”라는 문제에서 나올 가능성이 높다.
  - 흥미로운 것은 NVIDIA, Marvell, Broadcom은 위 항목에서 각각 3분야에 랭크가 되어 있으며, Broadcom과 Marvell은 메모리 병목과 별개로 광통신, 양자통신 또는 우주 통신 분야에도 수혜를 받을 수 있는 업체이기도 하다.
