# IonQ, 새로운 이온을 사용하게 될까?

Published: 2025-08-29T18:54:29.834000+09:00

Original Naver post: https://blog.naver.com/4-fire/223988118189

---

2025년 3월 5일 발표된 글이지만 지금까지 별다른 관심을 받지 못한 상황이다. 해당 연구는 내부 시스템 아키텍처에 상당한 변화를 가져올 수 있는 중대한 내용임에도 불구하고, **Investor Update**나 **Technology Webinar**에서도 소개된 바가 없다. 처음에는 Oxford Ionics에서 사용하는 마이크로파 제어 방식과의 호환성 문제로 인해 활용도가 낮아 묻힌 기술일 가능성을 의심했으나, 관련 개연성을 뒷받침할 만한 근거는 발견하지 못했다. 따라서 현 시점에서는 **아직 기술 개발 단계에 머물러 있어 시장과 업계의 주목을 받지 못하고 있는 것**이라는 잠정적 결론에 이른다.

**✅양자 컴퓨팅의 진보: 트랩형 이온 양자 네트워킹을 위한 더 빠른 혼합종 게이트**

**💡****혼합 종(mixed-species) 게이트의 필요성**

- - 트랩 이온 방식은 동일한 종의 이온을 사용하여 게이트 조작을 수행해 왔지만,
  - 혼합 종 이온 게이트는 진정한 대규모 양자 시스템 아키텍처 구축에 있어 더 유연하고 확장 가능하다.
  - 예로, **Barium, Calcium, Ytterbium, Beryllium** 등의 다양한 이온을 조합해 사용한다.

    - **133****Ba****+** **–** **138****Ba****+**
    - **43****Ca****+** **–** **88****Sr****+**

****

**💡****속도 향상을 위한 혁신: SDK 기반 접근법**

- - 기존에는 Lamb‑Dicke 영역에서의 구현 방식이 약 **10 kHz** 수준의 속도가 한계였다.
  - IonQ는 **ultrafast state‑dependent kicks (****SDK****s)** 방식을 도입해, **나노초 단위** 레이저 펄스로 훨씬 더 빠른 **MHz** 속도 게이트를 제안한다.
  - 즉, 수십에서 수백 마이크로초가 아닌, **수백 나노초 이하** 게이트 시간을 가능하게 한다.

**💡****기술의 핵심 요소**

- - **정밀한 펄스 시퀀스 설계**를 통해 모션 잡음이나 오류를 효과적으로 제어한다.
  - 시뮬레이션 결과, 게이트 오류율(infidelity)을 **10****-4** 수준으로 낮출 수 있음을 확인했다.

**💡****기대 효과**

1. 1. **더 빠른 문제 해결 시간**: 게이트 속도가 빨라지면 전체 문제 해결도 빨라진다.

      - 지금까지 이온트랩의 가장 큰 두 난제중 하나인 속도 문제가 해결될 말그대로 Kick이 될 것으로 기대됨.
   2. **높은 신뢰도**: 낮은 오류율을 통해 대형 회로 실행과 오류 보정 효율이 향상된다.
   3. **확장성**: 더 빠른 게이트는 깊은 회로를 가능하게 하고, 시스템 성능을 전반적으로 높인다.
   4. **분산 컴퓨팅 & 네트워킹**: 네트워크 노드 간 정보 전송이 매우 빠르고 정확해져, **고속 양자 인터넷** 구축이 한층 가까워진다.

****

**💡****앞으로의 방향**

- - 이 연구는 현재는 **이론적 단계**이나, IonQ는 이미 **특허 출원(Provisional Patent) 완료**했고, 곧 **실험적 검증**을 진행할 계획이다.

    - 아직까지는 특허 검색에서 확인은 되지 않고 있다.

**✅****이번 발표의 의미**

혼합종 이온은 이미 Quantinuum에서 사용중인데, 그 사용 목적이 전혀 다르다.

간단하, Quantinuum에서는 QCCD를 사용하는 데 있어서 발열 및 노이즈 억제를 위해 기존 연산용 큐비트인 이테르븀에 냉각의 목적으로 바륨이온을 사용하였지만, 이번에 발표한 IonQ의 혼합종은 나노초 펄스 기반 상태 의존 변위를 위한 것이다.

****

**💡****IonQ 특허의 핵심: SDK(Ultrafast State-Dependent Kicks)**

- - IonQ가 출원한 특허는 **혼합종 자체**가 아니라 **게이트 동작 메커니즘**에 대한 것이다.
  - **Quantinuum 방식**

    - 전통적인 **Lamb-Dicke 영역**에서 작동
    - 광학 펄스를 이용해 **모션 모드에 작은 진동을 유도** → MS 게이트를 통해 얽힘 생성
    - 속도는 제한적(약 10kHz 수준)
    - **많은 냉각 단계와 오류 보정 오버헤드 필요**
  - **IonQ 방식 (이번 특허 출원)**

    - SDKs(초고속 상태 의존 킥) 도입
    - **나노초 단위 레이저 펄스**로 **이온 모션 상태를 순간적으로 변위시키고 다시 복귀**
    - **펄스 시퀀스 최적화**로 모션 가열을 최소화
    - 시뮬레이션상 **100ns~300ns** **수준의 게이트 시간 달성 가능**
    - 결과적으로, **MHz급 초고속 혼합종 게이트** 실현 가능성 확보

**💡****특허 전략의 숨은 의도**

- - IonQ가 이번 SDK 기반 혼합종 게이트 특허를 서두르는 이유는 두 가지로 해석된다.
  - **Photonic Interconnect(PI) 네트워킹 전략**

    - IonQ의 4단계 로드맵 중
    - **3단계**: 데이터 큐비트 ↔ 네트워크 큐비트 간 초고속 얽힘 전송
    - **4단계**: 멀티-QPU 분산 네트워크 구축
    - 혼합종 SDK 게이트가 **네트워크 대역폭**을 높이는 핵심 기술로 작용
  - **표준화 경쟁 선점**

    - Quantinuum은 이미 혼합종 특허 포트폴리오를 상당히 구축한 상태
    - IonQ는 **"속도 우위"와 "네트워크 최적화"라는 새로운 기술 축**을 잡고 시장에서 특허 영역을 확보하려는 전략

**💡****133****Ba****+** **–** **138****Ba****+**

- - 왜 137Ba+은 사용안하는가?
  - 여러 조합이 있을 수 있지만 바륨계열을 사용한다면 1**37****Ba****+******는 사용하지 않는다.

    - **133****Ba****+** **–** **138****Ba****+**
    - **43****Ca****+** **–** **88****Sr****+**
    - **138****Ba****+** **–** **171****Yb****+**
    - **138****Ba****+** **–** **9****Be****+**
  - 그 이유는

    - 1**37****Ba****+**는 **핵스핀 값이 (I=3/2)**
    - **133****Ba****+** **는 핵스핀 값이(I=1/2) 이라서 하이퍼파인 값이 더욱 단순해진다.**
    - **138****Ba****+** **은 핵스핀 값이(I=0) 이라서 더욱 단순해지기 때문에 네트워크용 큐비트로 훨씬 적합하다.**

****

**💡****하이퍼파인 결합 기본 원리**

- - 전체 각운동량:

    - F=I+J
  - 여기서

    - I = 핵스핀
    - J = 전자 껍질의 전자각운동량(궤도+스핀 합성)
  - 가능한 F 값의 범위:
  - F=∣I−J∣,∣I−J∣+1,…,I+J
  - 따라서, 같은 핵스핀을 가진 동위원소라도, **전자 준위의 J 값**에 따라 F 값의 개수가 달라집니다.

**💡****137****Ba****+** **(I = 3/2) vs** **133****Ba****+** **(I = 1/2) 비교**

- - **6S****1/2** **상태 (J=1/2)**

    - **137****Ba****+**:

      - F=∣3/2−1/2∣…3/2+1/2=1,2
      - → **F=1,2 두 개**
    - **133****Ba****+**:

      - F=∣1/2−1/2∣…1/2+1/2=0,1
      - → **F=0,1 두 개**
    - 즉, 6S1/2 바닥 상태에서는 두 동위원소 모두 F 값이 두 개뿐임.
  - **5D****3/2** **상태 (J=3/2)**

    - 여기가 차이가 크게 남.
    - **137****Ba****+** **(I=3/2)**:

      - F=∣3/2−3/2∣…3/2+3/2=0,1,2,3
      - → **F=0,1,2,3 총 네 개**
    - **133****Ba****+** **(I=1/2)**:

      - F=∣1/2−3/2∣…1/2+3/2=1,2
      - → **F=1,2 두 개만 존재**
  - **6P****1/2** **상태 (J=1/2)**

    - **137****Ba****+** → F=1,2
    - **133****Ba****+** → F=0,1
    - → 여기서도 두 개씩만 존재.
  - 결과적으로 **137****Ba****+**에서는 **650nm 채널에 여러 개의 EOM 사이드밴드**가 필요하고, 레이저 파워가 분산돼서 원하는 전이에 충분한 세기를 몰아주기 어려워진다.
  - 반대로 **133****Ba****+**는 전이선이 단순해 **펌프 사이클과 재펌프 효율**이 좋아지고, 따라서 **493nm 광자 산란률**과 **포토닉 인터페이스 효율**이 높아진다

**💡****SDK가 Photonic InterconnectI에 미치는 영향**

- - **IonQ의 Photonic Interconnect 4단계 로드맵에서 SDK가 중요한 위치를 차지할 것으로 예상된다.**

|  |  |  |
| --- | --- | --- |
| **PI 단계** | **목표** | **SDK 역할** |
| **1단계** | Ion ↔ Photon 얽힘 생성 | SDK 필요 없음 |
| **2단계** | Photon ↔ Photon 얽힘 | SDK 필요 없음 |
| **3단계** | **Photon 얽힘 → 데이터 큐비트 전환** | **SDK 필요** (혼합종 얽힘을 초고속으로 생성) |
| **4단계** | 멀티-QPU 네트워크 구축 | SDK가 네트워크 대역폭을 사실상 결정 |

- - **따라서 SDK는 PI 3단계 이후에서 매우 중요한 핵심 기술이 될 것이다.**
  - **SDK 없이는 네트워크 속도가 PI 광자 인터페이스보다 훨씬 느려져 멀티-QPU 병렬화가 어려워 질 수 있기 때문이다.**

**✅질문 1.** **그럼 왜 지금까지** **133****Ba****+** **를 사용하지 않고,** **137****Ba****+** **을 사용 했을까?**

Quantinuum, IonQ, NIST 등 대부분의 초기 트랩 이온 연구에서 **137****Ba****+**를 선호한 이유는 **133****Ba****+** **동위원소의 확보 난이도**와 **실험 인프라** 때문이다.

- **137****Ba****+****가 주류였던 이유**

  - **핵스핀(I=3/2)** → 하이퍼파인 구조가 있어서
  - "clock transition"이라는 **자기장 민감도가 낮은 안정적인 전이**를 구현할 수 있었음.
  - **풍부한 동위원소 공급**: 자연계에서 **137****Ba** **비율이 약 11.2%** → 쉽게 확보 가능.
  - 레이저 파장 493nm, 650nm 등 기존 바륨 실험 장비와 호환성 높음.
  - Quantinuum이 **171****Yb****+****,** **137****Ba****+** **혼합종**을 선택한 것도 같은 이유.
- **133****Ba****+****를 쓰기 어려웠던 이유**

  - 자연계에서 **133****Ba** **비율 ≈ 0%** → **핵반응을 통해 합성**해야 함.
  - 매우 희귀해서 동위원소 공급망이 거의 없었음.
  - 방사성 반감기(약 **10.5년**) 때문에 실험실에서 쓰려면 엄격한 방사선 관리 필요.
  - NIST에서도 2018년 이전까지는 **133****Ba** 양자 실험 보고가 거의 없었음.
- **IonQ가** **133****Ba****+****를 사용하려는 이유**

  - **포토닉 인터커넥트 최적화**:

    - **133****Ba****+**는 광학 전이선이 통신 파장(493nm, 650nm)과 가장 잘 맞아 **광자 기반 얽힘 생성률**을 높이기에 유리.
  - **하이퍼파인 구조 단순화**:

    - **133****Ba****+**는 **핵스핀 I=1/2** → 에너지 준위 단순, 펄스 최적화가 쉬움.

**💡****133****Ba****+** **vs** **137****Ba****+****: 하이퍼파인 “선 개수”와 “간격” 비교**

- - **핵스핀 I 차이**

    - **137****Ba****+**: **I=3/2** → 특히 5D3/2 상태의 하이퍼파인 다중도 F=0,1,2,3로 **4개** (하위 m\_F까지 합치면 더 많음).
    - **133****Ba****+**: **I=1/2** → 5D3/2는 F=1,2 **2개**만 존재. → **주소해야 할 선이 절반 수준**.
  - **하이퍼파인 ‘간격’(분할 값)**

    - **133****Ba****+**:

      - 6S1/2 분할: **9.931 GHz**
      - 6P1/2 분할: **1.840 GHz**
      - 5D3/2 분할: **0.937 GHz**.
    - **137****Ba****+**:

      - 6S1/2 분할: 약 **8.037 GHz**(실험에서 493 nm 빔 EOM을 **8.037 GHz**로 모듈레이션해 모든 하이퍼파인 성분을 커버)
      - 6P1/2 분할: 약 **0.74 GHz**.
  - 요약하면, **133****Ba****+****는**

    - **필요한 선 개수가 적고,**
    - **특히 여기 상태 6P1/2의 분할이** **137****Ba****+****(0.74 GHz)보다 훨씬 큼(1.84 GHz)**
    - → 스펙트럼이 **더 성긴(=밀도 낮은)** 구조다.
    - 그래서 특정 하이퍼파인 전이만 **깨끗이 골라 때리기**가 쉽다.

**💡****“밀도가 낮으면” 왜 광자 수율이 좋아지나?**

- - 여기서 말하는 “광자 수율”은 렌즈 NA/검출기 QE로 정해지는 ‘기하학적 수집 효율’이 아니라, 보통 실험 맥락에서 쓰는 실제 유효 산란률/시도당 성공률(=단위 시간당 검출되는 ‘원하는’ 493 nm 광자 수)을 뜻한다고 이해하면 된다.
  - **메커니즘은 두 가지다.**

    - **오프-레조넌트(Off-Resonant) 누설 감소 → 원하는 선에 ‘전력 집중’**

      - 특정 이온상태 전이의 에너지 차이에 정확히 맞춘 주파수를 사용하는 경우를 공명(Resonant)라고 하는데, 의도한 전이와는 다른 에너지도 준위도 같이 동작하는 "살짝 같이 들썩이는 현상"을 오프 레조넌트라고 함.
      - 실험에서는 한 하이퍼파인 전이(예: F→F′)만 선택적으로 구동하고 싶다.
      - 하지만 이웃한 하이퍼파인 선까지의 여유 detuning(Δ)이 작으면(=선이 빽빽하면) **오프-레조넌트 산란률**이∝(Ω/Δ)2로 커져서 **원치 않는 상태로 새어나감**(dark state 생성, 잘못된 편광/주파수의 광자 방출 등).
      - **133****Ba****+**는 6P1/2 분할이 **1.84 GHz**로 커서, 같은 구동 세기(Ω)에서 (Ω/Δ)2가 **137****Ba****+****(0.74 GHz)** 대비 **약 (0.74/1.84)² ≈ 1/6** 수준으로 줄어든다 → **누설/혼선이 크게 감소**.
      - 결과: 같은 총 레이저 파워로 **원하는 한 개 전이에 더 과감히 전력 집중** 가능 → **목표 전이의 포화도(s)↑ → 단위 시간당 원하는 493 nm 산란 광자 수↑**.
    - **필요한 “사이드밴드/재펌프 채널” 수 자체가 줄어듦**

      - **137****Ba****+**는 “**하이퍼파인 레벨이 많아** 모든 레벨을 커버하려면 **493 nm/650 nm 레이저에 여러 EOM 사이드밴드**를 얹어야 한다”는 것이 실험 표준. 그만큼 **레이저 파워가 분산**되고, **어느 한 선의 구동 세기**가 상대적으로 약해진다.
      - **133****Ba****+**는 D3/2가 F=1,2 **두 개뿐**이라 650 nm 재펌프도 단순하고, 전체 **광학 펌프 사이클이 짧고 깨끗**해져 시도 속도(초당 시퀀스 반복률)가 올라간다.

**✅질문 2.** **133****Ba****+** **단일종을 사용하지 않고, 굳이** **138****Ba****+****혼합종을 사용하는 이유는?**

**💡단일종(****133****Ba****+** **또는** **138****Ba****+****)만 사용하는 경우**

- - **133****Ba****+** 또는 **138****Ba****+** 단일종만 사용하면 설계가 단순해지고 다음 장점이 있다:

    - **레이저 세트 단순화** → 493 nm / 650 nm 이중 파장만 관리하면 됨
    - **하이퍼파인 구조 단순성** → **133****Ba****+**(I=1/2)는 2개(F=0,1), **138****Ba****+** (I=0)는 하이퍼파인 분할이 없으므로 제어 단순
    - **게이트 설계 쉬움** → SDK(나노초 펄스)도 동종 제어에서 최적화 가능
  - 하지만 단점도 있다:

    - **네트워킹 최적화 불리** → 포토닉 인터커넥트(Photonic Interconnect)용 파장과 내부 연산용 파장이 충돌
    - **쿨링과 메모리 문제** → 연산 중 모션 노이즈가 쌓이면 냉각을 해야 하는데, 같은 종을 쓰면 데이터 손상 위험 증가
    - **역할 분리 어려움** → 연산·메모리·네트워킹을 하나의 종으로만 처리하면 병렬 동작 속도가 제한됨
  - 즉, **단일종만 사용하면 QPU 설계는 단순하지만, 확장성과 네트워킹 측면에서 한계 발생.**

****

**💡혼합종(Mixed-Species) 설계가 필요한 이유**

- - IonQ가 SDK 논문에서 **133****Ba****+** **,** **138****Ba****+****,****43****Ca****+** **,** **88****Sr****+****,****171****Yb****+**등 다양한 조합을 언급한 이유는 **역할별 최적화** 때문.
  - **연산(Computation) 최적화**

    - **133****Ba****+** → 하이퍼파인 단순, 내구성 강함, SDK 제어에 유리
    - **43****Ca****+** 또는**171****Yb****+** → 초고충실도 연산용, 마이크로파 또는 Raman 제어 가능
    - **혼합하면** 연산 전용 Qubit에서 더 빠른 게이트 시간 확보 가능
  - **메모리/네트워킹 역할 분리**

    - 네트워킹 Qubit은 포토닉 인터커넥트용 → **138****Ba****+**처럼 650 nm와 493 nm 모두 지원하는 종이 유리
    - 연산 Qubit은 고충실도 SDK 게이트 최적화용 → **43****Ca****+** **,** **88****Sr****+****,****171****Yb****+**등 사용 가능
    - 메모리 Qubit은 **T₁** 시간(초 단위 유지) 최적화 → **138****Ba****+****,****43****Ca****+** 같은 단순 핵스핀 종 유리
  - 즉, **같은 QPU 안에서도 각 Qubit의 역할을 최적화하기 위해 종을 나누는 게 핵심 전략**.

**✅향후 전망**

**💡SDK의** **단점**

- - 장기적으로 **qudit(다준위 큐비트) 아키텍처**로 갈 경우 **137****Ba****+**가 **133****Ba****+**보다 훨씬 유리해질 가능성이 높다.
  - 현재 IonQ가 **133****Ba****+**를 고려하는 가장 큰 이유는 **SDK + 포토닉 인터페이스 최적화** 때문이지만,
  - **장기적으로 멀티레벨 코딩, QEC, qudit 기반 논리 게이트**를 고려하면 **137****Ba****+** 같은 **핵스핀 큰 동위원소**의 잠재력이 더 크다는 Trade-off가 있다.

**💡****IonQ SDK + PI 전략 vs Qudit 활용성**

|  |  |  |
| --- | --- | --- |
| **항목** | **133Ba⁺** | **137Ba⁺** |
| **현재 IonQ SDK/PI 전략** | 최적화 대상 | 비적합 |
| **포토닉 얽힘 효율** | 높음(스펙트럼 단순) | 상대적으로 낮음 |
| **SDK 초고속 게이트 최적화** | 유리(단순한 펄스 시퀀스) | 상대적으로 불리(복잡한 시퀀스) |
| **멀티레벨(Qudit) 코딩** | 거의 불가능 | 매우 유리 |
| **미래 QEC 확장성** | Surface code, BB5/BB6 같은 전통적 QEC에 적합 | qLDPC, GKP, Qudit-QEC에 적합 |

즉, IonQ가 최종적으로 **133****Ba****+**를 선택할지, 아니면 **멀티레벨 QEC**나 **Qudit 기반 알고리즘을 고려해서** **137****Ba****+**를 고수할지 지켜봐야 할 것이다.

**💡****Oxford Ionics에서도 사용가능한가?**

- - **Oxford Ionics 방식을 선택한다는 것은 제어 방식** 자체를 레이저에서 마이크로파로 바꾸는 것이고,
  - IonQ SDK의 접근은 **게이트 동작 원리** 자체를 바꾸는 것이다.
  - **두 기술은 원리적으로 충돌하지 않음으로 사용가능할 것으로 보임**

**✅****IonQ 로드맵에서 SDK 접근의 미래**

IonQ가 Oxford Ionics를 인수한 후의 전략을 보면, SDK 연구 자체를 버리지는 않을 것이고, **우선순위가 달라질 가능성**이 있다.

- - **단기 (~2026)**

    - **IonQ QPU 라인업**(Forte, Tempo) → SDK 연구 계속 반영
    - 이유: 기존 IonQ 하드웨어는 레이저 기반이므로, 현재 발표된 SDK 논문 그대로 적용 가능
  - **중기 (****2027** **~ 2029)**

    - Oxford Ionics의 Cryo-CMOS 마이크로파 제어를 IonQ 하드웨어에 통합 시작
    - SDK 기반 초고속 게이트 알고리즘은 유지하되,
    - **"나노초 레이저 펄스"가 아닌 "나노초 마이크로파 펄스"로 구현** 가능성 높음
    - 즉, SDK의 수학적 원리와 특허는 그대로 살아남음
  - **장기 (~2030 이후)**

    - **포토닉 인터커넥트(PI) 기반 멀티 - QPU 네트워크** 완성
    - 이 단계에서는 네트워크 큐비트 ↔ 메모리 큐비트 간 혼합종 게이트를
    - **마이크로파 제어 + 포토닉 인터페이스** 방식으로 최적화할 가능성이 큼

  - **핵심 포인트**
